# Studio Generator 重构计划

## 1. 重构目标

基于 Bone-Blueprint DDD UseCase 规范 v1.0 和前端设计规范，重构 Studio Generator 模块，使其符合企业级 DDD + 分级 CQRS + 双模式 UseCase + 六边形架构 + Bone 元数据驱动框架的标准。

### 2.2 核心重构内容

1. **领域模型重构**：
   - 聚合根直接放在 `domain.{aggregate}` 下
   - 同包放实体、值对象、事件
   - 实体使用 `@Table` 注解显式绑定数据库表名
   - 仅使用 `@Getter` 和私有构造器

2. **仓储接口重构**：
   - 继承 `bone-metadata-sdk` 的 `Repository`
   - 空接口，不添加任何自定义方法
   - 所有查询使用 `Criteria` 或 `QueryBuilder`

3. **应用层重构**：
   - 实现双模式 UseCase 策略
   - Mode A（简单模式）：UseCase 直写，逻辑内联
   - Mode B（企业模式）：UseCase 编排 + Handler 原子化
   - 命令处理器使用 `@Transactional` 注解
   - 查询处理器使用 `@Transactional(readOnly = true)` 注解

4. **AI 能力实现**：
   - 使用 `@Capability` 注解标记需要暴露给 AI 的能力
   - 实现 Handler Registry 自动扫描和注册能力

5. **适配器层重构**：
   - Controller 只依赖 UseCase，不直接依赖 Handler
   - 使用 assembler 进行 DTO 转换

### 2.3 关键类重构

1. **领域模型**：
   - `CodeTemplate.java`：聚合根，添加 `@Table` 注解
   - `DataSource.java`：聚合根，添加 `@Table` 注解
   - `CodeGenerationHistory.java`：聚合根，添加 `@Table` 注解

2. **仓储接口**：
   - `CodeTemplateRepository.java`：空接口，继承 `Repository`
   - `DataSourceRepository.java`：空接口，继承 `Repository`
   - `CodeGenerationHistoryRepository.java`：空接口，继承 `Repository`

3. **UseCase**：
   - `GenerateCodeUseCase.java`：Mode B，编排多个 Handler
   - `PreviewTemplateUseCase.java`：Mode A，直接实现
   - `ValidateTemplateUseCase.java`：Mode A，直接实现

4. **Handler**：
   - `GenerateCodeHandler.java`：使用 `@Capability` 注解
   - `TestConnectionHandler.java`：数据源连接测试
   - `LoadTablesHandler.java`：加载表结构

5. **控制器**：
   - `DataSourceController.java`：管理数据源相关 API
   - `CodeGeneratorController.java`：管理代码生成相关 API
   - `TemplateController.java`：管理模板相关 API
   - `HistoryController.java`：管理生成历史相关 API
   - `CapabilityController.java`：管理能力相关 API
