


          
# 扩展引擎注解优化方案与使用最佳实践

## 优化建议完善

### 1. 注解体系明确划分

**核心职责划分**：
- **ExtPoint**：运行时配置中心，专注于扩展点注册和行为控制
- **Extension**：实现识别和路由控制，负责匹配和选择
- **ExtPointDoc**：接口文档生成，提供使用指导
- **ExtensionDoc**：实现类文档，描述适配场景和实现细节

### 2. 保留策略优化细节

| 注解名称 | 保留策略 | 作用时机 | 内存开销 |
|---------|---------|---------|--------|
| ExtPoint | RUNTIME | 运行时解析配置 | 中 |
| Extension | RUNTIME | 运行时路由匹配 | 中 |
| ExtPointDoc | SOURCE | 编译时文档生成 | 无 |
| ExtensionDoc | SOURCE | 编译时文档生成 | 无 |

### 3. 字段精简原则

- **运行时必需字段**：保留在ExtPoint/Extension中
- **文档相关字段**：移至ExtPointDoc/ExtensionDoc中
- **重叠字段**：统一归属到运行时注解中

## 使用最佳实践案例

### 案例1：基础扩展点定义与实现

**1. 定义扩展点接口**

```java
package com.example.order.ext;

import com.bone.engine.extension.ExtPoint;
import com.bone.engine.extension.annotation.ExtPointDoc;

// 运行时配置
@ExtPoint(
    name = "订单价格计算扩展点",
    description = "计算订单最终价格的扩展接口",
    domain = "订单",
    category = "计算",
    version = "1.0.0",
    enabled = true,
    priority = 100,
    enableCache = true,
    timeout = 500
)

// 接口文档（可选，仅编译时使用）
@ExtPointDoc(
    description = "用于计算订单最终价格的扩展接口，支持多种促销策略和价格规则",
    usage = "1. 实现接口并添加@Extension注解\n2. 配置路由条件和优先级\n3. 注入到服务层使用",
    bestPractices = "建议实现保持幂等性，避免性能瓶颈",
    params = {
        @ExtPointDoc.Param(
            name = "order",
            type = "OrderContext",
            description = "订单上下文信息",
            required = true,
            example = "OrderContext.builder().orderId(\"123\").items(Collections.singletonList(item)).build()"
        )
    },
    returnInfo = @ExtPointDoc.Return(
        type = "PriceResult",
        description = "价格计算结果",
        successExample = "PriceResult.builder().finalPrice(new BigDecimal(99.99)).discount(new BigDecimal(10)).build()",
        errorCodes = {
            @ExtPointDoc.ErrorCode(code = "PRICE_CALC_FAILED", description = "价格计算失败", solution = "检查订单数据完整性")
        }
    ),
    notes = "计算结果会被缓存，避免重复计算"
)
public interface OrderPriceExtPoint {
    PriceResult calculate(OrderContext order);
}
```

**2. 实现扩展点**

```java
package com.example.order.ext.impl;

import com.bone.engine.extension.Extension;
import com.bone.engine.extension.annotation.ExtensionDoc;
import com.example.order.ext.OrderPriceExtPoint;
import com.example.order.ext.OrderContext;
import com.example.order.ext.PriceResult;

// 运行时路由配置
@Extension(
    name = "普通订单价格计算实现",
    description = "标准价格计算实现",
    tenantCode = {"*"},
    bizCode = {"STANDARD"},
    useCase = {"NORMAL_ORDER"},
    env = {"*"},
    priority = 100,
    version = "1.0.0"
)

// 实现类文档（可选，仅编译时使用）
@ExtensionDoc(
    description = "标准订单价格计算实现，支持基础折扣计算",
    scenarios = "适用于常规商品订单计算",
    implementationDetails = "基于商品原始价格计算，应用基础折扣规则",
    performance = "单次计算平均耗时<10ms，支持高并发场景",
    notes = "不支持特殊商品（如预售、团购）的价格计算",
    author = "张三",
    createDate = "2023-07-15"
)
public class StandardOrderPriceImpl implements OrderPriceExtPoint {
    @Override
    public PriceResult calculate(OrderContext order) {
        // 实现逻辑
        return PriceResult.builder()
            .finalPrice(order.getTotalPrice())
            .discount(new BigDecimal(0))
            .build();
    }
}
```

### 案例2：多版本与条件路由

**高级折扣实现**

```java
@Extension(
    name = "会员折扣价格计算实现",
    description = "针对会员的特殊折扣计算",

)

@ExtensionDoc(
    description = "会员专享价格计算实现，提供会员折扣",
    scenarios = "适用于VIP会员订单场景",
    implementationDetails = "根据会员等级提供阶梯式折扣",
    differences = "相比标准实现增加了会员等级判断和折扣计算",
    performance = "平均耗时15-20ms，包含会员数据查询",
    author = "李四",
    createDate = "2023-07-20"
)
public class VipOrderPriceImpl implements OrderPriceExtPoint {
    @Override
    public PriceResult calculate(OrderContext order) {
        // 会员折扣逻辑
        BigDecimal originalPrice = order.getTotalPrice();
        BigDecimal discount = calculateMemberDiscount(order.getUserId(), originalPrice);
        return PriceResult.builder()
            .finalPrice(originalPrice.subtract(discount))
            .discount(discount)
            .build();
    }
}
```

## 使用最佳实践建议

### 1. 扩展点设计建议

- **接口设计简洁**：每个扩展点专注于单一职责
- **参数封装合理**：使用上下文对象封装参数，便于扩展
- **版本管理规范**：遵循语义化版本规范
- **优先级设置清晰**：明确多实现的优先级规则

### 2. 注解使用规范

- **必填字段完整**：ExtPoint必须填写name、description、domain
- **路由条件精确**：根据业务场景精确设置匹配条件
- **文档信息详尽**：核心扩展点应提供完整文档
- **避免重复配置**：不要在不同注解中重复配置相同信息

### 3. 性能优化建议

- **缓存策略合理**：对计算密集型扩展点启用缓存
- **超时设置科学**：合理设置超时时间，避免长时间阻塞
- **熔断机制配置**：生产环境配置适当的熔断阈值
- **灰度策略谨慎**：新功能使用灰度发布，逐步放量

### 4. 开发流程建议

1. **接口设计**：先定义清晰的ExtPoint接口
2. **文档先行**：补充ExtPointDoc文档
3. **实现开发**：开发实现类，配置Extension
4. **实现文档**：补充ExtensionDoc文档
5. **测试验证**：验证路由规则和计算结果
6. **灰度发布**：使用weight参数控制发布流量

通过遵循以上最佳实践，可以构建出清晰、高效、可维护的扩展引擎使用体系，充分发挥扩展点机制的灵活性，同时保证系统的稳定性和性能。
