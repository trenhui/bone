# Bone Extension SDK 使用指南

> **产品定位与模块边界**：见 [`../README.md`](../README.md)（摘要）。  
> **注解/API 手册**：见 [`../bone-extension-sdk/README.md`](../bone-extension-sdk/README.md)。  
> **事实来源**：类名、配置以 **`bone-extension-sdk/src/main/java`** 为准；本文为接入与运维主路径。

---

## 1. 环境与依赖

| 项 | 要求 |
|----|------|
| JDK | **17+**（与当前模块 `pom.xml` 一致） |
| Spring Boot | **3.x**（与 Bone 平台主线一致） |
| Maven 坐标 | `com.bone:bone-extension-sdk`（版本继承根工程 / `bone-parent` BOM） |

```xml
<dependency>
    <groupId>com.bone</groupId>
    <artifactId>bone-extension-sdk</artifactId>
</dependency>
```

自动配置由 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 注册；可用 `bone.extension.enabled=false` 关闭。

## 2. 五分钟上手

### 2.1 启用扫描

在启动类或配置类上使用 **`@EnableExtensionPoints`**（见 `api.annotation.EnableExtensionPoints`），并配置 `basePackages` 扫描扩展实现所在包。

```java
@SpringBootApplication
@EnableExtensionPoints(basePackages = "com.yourcompany.ext")
public class Application {
    public static void main(String[] args) {
        SpringApplication.run(Application.class, args);
    }
}
```

### 2.2 定义扩展点接口

使用 **`@ExtensionPoint`** 标注接口（框架会注册 `FactoryBean` + JDK 动态代理）。

### 2.3 编写实现

使用 **`@Extension`** 标注实现类，并注册为 Spring Bean（`@Component` / `@Service` 等）；通过 `tenant`、`bizCode`、`scenario`、`condition`（SpEL）等控制路由。

### 2.4 调用前准备上下文

在调用扩展点接口方法前，通过 **`ExtensionContextManager`** 或 **`ExtensionScope`（try-with-resources）** 绑定 **`BizContext`**；或在路由支持的前提下从参数解析（以当前 `ExtensionPointProxy` 行为为准）。

### 2.5 注入并调用

将**扩展点接口**按普通 Spring Bean 注入，调用接口方法即可触发路由与实现执行。

**完整可编译示例**：见 `bone-extension-sdk/src/test/java/com/bone/example/extension/`（支付、促销、理赔等）。

## 3. 核心注解速查

### `@EnableExtensionPoints`（节选）

| 属性 | 含义 |
|------|------|
| `basePackages` | 扫描 `@Extension` 实现的根包 |
| `extensionRepository` / `extensionPointRouter` | 替换默认仓库 / 路由器实现 |
| `cacheEnabled` / `strictMode` / `routingStrategy` / `timeout` | 路由缓存、未命中是否抛错、策略、超时 |

完整列表以 **`EnableExtensionPoints.java`** 为准。

### `@ExtensionPoint`

常用：`name`、`description`、`version`、`transactional`、`timeout`、`singleton` — 见 **`ExtensionPoint.java`**。

### `@Extension`（路由维度与条件）

| 分类 | 属性示例 |
|------|----------|
| 维度 | `tenant`、`bizCode`、`useCase`、`scenario`、`env`、`userGroup` |
| 控制 | `order`（越小越优先）、`weight`、`traffic`、`enabled` |
| 条件 | `condition`（SpEL）、`tags`、`async`、`timeout`、`startTime` / `endTime` |

完整列表以 **`Extension.java`** 为准。

### 文档注解

`@ExtensionPointDoc`、`@ExtensionDoc` — 用于文档生成，**不参与路由**。

## 4. 调用链与路由算法

1. 业务注入扩展点接口（代理 Bean）。  
2. `ExtensionPointProxy` 解析 **`BizContext`**（ThreadLocal 或参数）。  
3. **`ExtensionPointRouter#route`**（默认 `DefaultExtensionPointRouter`）选择实现。  
4. **`ExtPointInvocationHandler`** 使用已解析的 `Method.invoke` 调用实现。

### 4.1 默认四级路由（`DefaultExtensionPointRouter`）

| 顺序 | 层级 | 说明 |
|------|------|------|
| 1 | **条件（SpEL）** | 有 `@Extension.condition` 的实现；注册期预编译，运行时优先走 `conditionPredicate` |
| 2 | **精确维度** | 无 condition；规则为 `BizContext` 维度的**子集**且值相等 |
| 3 | **模糊维度** | 无 condition；规则含 `*` 通配 |
| 4 | **默认实现** | `defaultImpl`（全 `*` 且无 condition 的注解实现） |

同级多条命中时，按 `ExtensionDefinition.compareTo`：**matchScore → priority（order）→ weight** 择优。

### 4.2 严格模式与兜底

| `bone.extension.router.strict-mode` | 行为 |
|-------------------------------------|------|
| **`true`** | 上述四级均无匹配 → 抛 `RouterException`（`NO_MATCH`） |
| **`false`**（默认） | 再尝试 **最宽泛** 的启用实现（matchScore 最低且通过 `traffic`） |

### 4.3 路由结果缓存

- 开关：`bone.extension.router.cache-enabled` 且 `bone.extension.cache.enabled`  
- 缓存值为 **`extensionCode`**（非 Bean 实例），键 = 扩展点类名 + 排序维度 + **`data/params` 指纹**  
- 注册/下线后调用 `router.clearCache(ExtPoint.class)` 或监听注册事件失效

### 4.4 灰度 `traffic`

`@Extension.traffic = 50` 表示约 50% 请求命中（稳定分桶：`requestId + 扩展点 + code`）。`100` 为全量。

### 4.5 路由策略 `routingStrategy`

配置：`bone.extension.router.strategy` 或 `@EnableExtensionPoints.routingStrategy`。

| 值 | 行为 |
|----|------|
| **`score`**（默认） | §4.1 四级：条件 → 精确维度 → 模糊 → 默认 |
| **`first`** | 在已排序列表上按顺序取**首个**维度/条件命中（不按四级分层） |
| **`priority`** | 在所有「条件或维度可命中」候选中，按 `compareTo`（matchScore / priority / weight）择优 |

别名：`default`、`weight` 等同 `score`。

### 4.6 Studio → 运行时元数据同步

控制面（Studio）只下发**路由元数据**（无 Spring Bean）；业务进程本地仍由 `@Extension` 扫描注册实例，运行时通过 **`MetadataOverlayExtensionRepository`**（**copy-on-read**，不污染本地注册表）叠加路由字段。

| 侧 | 配置 | 说明 |
|----|------|------|
| **业务** | `bone.extension.sync.enabled=true` | 启用元数据叠加 + Pub/Sub 刷新路由缓存 |
| **业务** | `bone.extension.sync.refresh-channel` | 与 Studio 一致（默认 `bone:ext:metadata:refresh`） |
| **Studio** | `bone.extension.studio.runtime-sync.enabled=true` | CRUD 后 `save` + `publishRefresh` |
| **Studio** | `bone.extension.studio.persistence.mode=metadata` | 默认 **Metadata 表**（`ext_studio_extension_point` / `ext_studio_extension_impl`）；`in-memory` 可切换 |
| **Studio** | `spring.sql.init.schema-locations` | H2：`classpath:db/schema-h2.sql`；MySQL：`schema-mysql.sql` |
| **共享** | Redis + `extensionMetadataRedisTemplate` | Jackson 序列化 `ExtensionRoutingMetadata`；Key `bone:ext:meta:{扩展点}:{code}` |

**扩展 `code` 对齐**：Studio `name` 或 `config.code` 须与运行时 `@Extension.name()` 或 `EXT_{类简单名}` 一致（见 `ExtensionCodeResolver`）。

**`Extension.config` JSON（路由字段）**：

```json
{
  "code": "可选，覆盖 code",
  "condition": "#data.type == 'VIP'",
  "traffic": 50,
  "weight": 80,
  "defaultImpl": false,
  "env": "prod"
}
```

手动推送：`POST /api/extensions/{id}/publish-runtime`。

> 勿再使用整 Bean 的 `RedisExtensionRepository` 做控制面同步；已标记 `@Deprecated`，请使用「本地仓库 + 元数据叠加」模型。

## 5. 配置要点（`bone.extension`）

配置类为 **`ExtensionProperties`**，前缀 **`bone.extension`**。以下为常用嵌套路径（Relax Binding 支持下划线/中划线混写）：

| 路径 | 作用 |
|------|------|
| `bone.extension.enabled` | 总开关 |
| `bone.extension.cache.*` | 本地缓存：是否启用、`max-size`、分布式缓存开关等 |
| `bone.extension.router.*` | 路由：`strategy`、`cache-enabled`、`strict-mode`（见 §4.2、§4.5） |
| `bone.extension.sync.*` | 控制面元数据同步：`enabled`（见 §4.6） |
| `bone.extension.scan.fail-fast` | 注册失败是否阻断启动（默认 `true`）；含 SpEL 语法错误 |
| `bone.extension.monitor.*` | 指标与健康检查开关 |
| `bone.extension.async.*` | 异步线程池（若启用异步扩展） |
| `bone.extension.sandbox.enabled` | **`true`** 才注册 `ExtensionSandbox` Bean；**不再使用全局 SecurityManager**（见类注释） |

**Studio**：`bone-extension-studio` 使用 **`prod` profile** 时安全策略收紧，生产需自行接入 JWT/OAuth2 等（见 `studio/config/SecurityConfig`）。

## 6. SpEL 条件（`@Extension.condition`）

- 根对象为 **`BizContext`**；可用 `#context` / `#ctx`、`#data`（载荷）、维度字段。  
- **注册期**：`compile()` 语法错误 → 默认 **`fail-fast` 抛错**（`ExtensionRegistrationException`）。  
- **运行期**：属性缺失/条件不满足 → 视为 **false**（换下一候选）；语法级错误 → `ExpressionEvaluationException` / `RouterException`。  
- 枚举比较请用 `#data.claimType.name() == 'INPATIENT'`，勿与字符串字面量直接 `==`。

**实践**：条件宜短、可单测；复杂规则可下沉到实现内并配合 `order` / `weight` 分档。

---

## 7. 最佳实践（摘要）

1. **扩展点接口稳定**：参数优先使用 `BizContext<T>` 携带领域载荷，避免接口随活动频繁改签名。  
2. **上下文生命周期**：异步/线程池场景务必传递或复制上下文（可用 **`ContextCopier`** 等工具类，以源码为准）。  
3. **默认实现**：为 `strictMode=false` 时准备兜底 `@Extension`，避免路由空命中。  
4. **可观测**：生产打开指标与结构化日志；成功路径日志级别勿过高（见 `ExtPointInvocationHandler`）。  
5. **安全**：敏感逻辑不要依赖进程内「沙箱」；插件隔离优先进程/容器级方案。

## 8. 故障排查清单

| 现象 | 常见原因 | 处理 |
|------|----------|------|
| `BizContext 未找到` | 未 `setCurrentContext` / 未使用 `ExtensionScope` / 异步丢上下文 | 在调用栈入口绑定；异步用 TTL 或显式传参 |
| 路由不到实现 | 维度不匹配 / `condition` 失败 / 实现未扫描进 Spring | 查 `@EnableExtensionPoints` 包路径与 `@Extension` 维度 |
| 注入的接口为 null | 未启用自动配置 / 未 `@EnableExtensionPoints` / 接口未标 `@ExtensionPoint` | 对照自动配置与注册日志 |
| 命中错误实现 | `order`/`weight`/`traffic` 配置与预期不符 | 调小 `order`、检查表达式与缓存 |

调试可临时提高 `logging.level.com.bone.engine.extension=DEBUG`。
