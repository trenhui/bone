


          
# 极简侵入式多数据源最佳实践方案

基于业界最佳实践和项目现状，我设计了一套真正低侵入性、零配置默认支持的多数据源解决方案，确保接入方使用简单，几乎零学习成本。

## 核心设计理念

- **零侵入原则**：默认单数据库模式，现有代码无需任何修改
- **约定优于配置**：提供合理默认值，仅在需要时配置
- **透明化处理**：对开发者隐藏数据源路由和分片复杂性
- **渐进式增强**：从单库到分表分库可平滑过渡

## 二、核心实现组件

### 1. 自动路由数据源

```java
package com.bone.metadata.sdk.support.dataSource;

import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.context.annotation.Configuration;
import org.springframework.jdbc.datasource.lookup.AbstractRoutingDataSource;

import javax.sql.DataSource;
import java.util.HashMap;
import java.util.Map;

// 1. 自动配置类
@Configuration
@ConditionalOnProperty(name = "metadata.sdk.sql.multi-datasource.enabled", havingValue = "true", matchIfMissing = false)
public class MultiDataSourceAutoConfiguration {
    
    @Bean
    @Primary
    public DataSource routingDataSource(
            DataSource defaultDataSource,
            MultiDataSourceProperties properties,
            ObjectProvider<List<DataSource>> customDataSources) {
        
        AutoRoutingDataSource routingDataSource = new AutoRoutingDataSource(properties);
        Map<Object, Object> targetDataSources = new HashMap<>();
        
        // 注册默认数据源
        targetDataSources.put("default", defaultDataSource);
        
        // 注册自定义数据源（如果有）
        customDataSources.ifAvailable(sources -> {
            for (int i = 0; i < sources.size(); i++) {
                targetDataSources.put("custom" + i, sources.get(i));
            }
        });
        
        routingDataSource.setTargetDataSources(targetDataSources);
        routingDataSource.setDefaultTargetDataSource(defaultDataSource);
        return routingDataSource;
    }
}

// 2. 自动路由数据源实现
class AutoRoutingDataSource extends AbstractRoutingDataSource {
    private final MultiDataSourceProperties properties;
    private static final ThreadLocal<DataSourceContext> CONTEXT = 
            ThreadLocal.withInitial(DataSourceContext::new);
    
    public AutoRoutingDataSource(MultiDataSourceProperties properties) {
        this.properties = properties;
    }
    
    @Override
    protected Object determineCurrentLookupKey() {
        DataSourceContext context = CONTEXT.get();
        
        // 优先使用手动指定的数据源
        if (context.getDataSourceName() != null) {
            return context.getDataSourceName();
        }
        
        // 根据SQL类型自动判断读写（通过ThreadLocal传递SQL信息）
        String sql = context.getCurrentSql();
        if (sql != null && properties.isReadWriteSeparationEnabled()) {
            // 自动识别写操作
            if (isWriteOperation(sql)) {
                return "master";
            }
            // 读操作使用从库
            if ("slave".equals(properties.getDefaultRead())) {
                return selectSlaveDataSource();
            }
        }
        
        // 默认返回
        return "default";
    }
    
    private boolean isWriteOperation(String sql) {
        String upperSql = sql.trim().toUpperCase();
        return upperSql.startsWith("INSERT ") || 
               upperSql.startsWith("UPDATE ") || 
               upperSql.startsWith("DELETE ") || 
               upperSql.startsWith("CREATE ") || 
               upperSql.contains("FOR UPDATE");
    }
    
    private String selectSlaveDataSource() {
        // 简化实现，实际使用轮询或随机策略
        return "slave1"; // 实际可根据配置和负载均衡策略选择
    }
    
    // 静态方法供外部使用
    public static void useDataSource(String dataSourceName) {
        CONTEXT.get().setDataSourceName(dataSourceName);
    }
    
    public static void clear() {
        CONTEXT.remove();
    }
    
    public static void setCurrentSql(String sql) {
        CONTEXT.get().setCurrentSql(sql);
    }
    
    // 内部上下文类
    static class DataSourceContext {
        private String dataSourceName;
        private String currentSql;
        private Map<String, String> shardingInfo = new HashMap<>();
        
        // getters and setters
    }
}

// 3. 配置属性类
@Configuration
@ConfigurationProperties(prefix = "metadata.sdk.sql.multi-datasource")
@Data
class MultiDataSourceProperties {
    private boolean enabled = false;
    private ReadWriteSeparationProperties readWriteSeparation = new ReadWriteSeparationProperties();
    private ShardingProperties sharding = new ShardingProperties();
    private Map<String, DataSourceConfig> datasources = new HashMap<>();
    
    public boolean isReadWriteSeparationEnabled() {
        return enabled && readWriteSeparation.isEnabled();
    }
    
    @Data
    static class ReadWriteSeparationProperties {
        private boolean enabled = false;
        private String loadBalance = "round-robin";
        private String defaultRead = "slave";
    }
    
    @Data
    static class ShardingProperties {
        private boolean enabled = false;
        private Map<String, TableShardingRule> tables = new HashMap<>();
        
        @Data
        static class TableShardingRule {
            private String column;
            private String strategy;
            private int count = 1;
        }
    }
    
    @Data
    static class DataSourceConfig {
        private String url;
        private String username;
        private String password;
        private String driverClassName;
    }
}
```

### 2. 自动SQL处理拦截器

```java
// 自动SQL处理拦截器，无需手动标注
@Component
@ConditionalOnProperty(name = "metadata.sdk.sql.multi-datasource.enabled", havingValue = "true", matchIfMissing = false)
public class SqlInterceptor implements StatementInspector {
    
    @Autowired
    private MultiDataSourceProperties properties;
    
    @Override
    public String inspect(String sql) {
        // 1. 传递SQL到数据源路由上下文，用于自动读写分离判断
        AutoRoutingDataSource.setCurrentSql(sql);
        
        // 2. 如果启用了分表，进行表名替换
        if (properties.isEnabled() && properties.getSharding().isEnabled()) {
            return processSharding(sql);
        }
        
        return sql;
    }
    
    private String processSharding(String sql) {
        // 简化实现：实际需要解析SQL，识别表名并应用分片规则
        // 这里提供核心思路，实际需要更复杂的SQL解析逻辑
        
        for (Map.Entry<String, MultiDataSourceProperties.ShardingProperties.TableShardingRule> entry : 
             properties.getSharding().getTables().entrySet()) {
            String tableName = entry.getKey();
            MultiDataSourceProperties.ShardingProperties.TableShardingRule rule = entry.getValue();
            
            // 模拟从ThreadLocal中获取分片键值（实际需要从参数中提取）
            String shardValue = getCurrentShardValue(rule.getColumn());
            if (shardValue != null) {
                int shardIndex = calculateShardIndex(shardValue, rule.getCount(), rule.getStrategy());
                sql = sql.replaceAll("\\b" + tableName + "\\b", tableName + "_" + shardIndex);
            }
        }
        
        return sql;
    }
    
    private int calculateShardIndex(String value, int count, String strategy) {
        switch (strategy) {
            case "hash":
                return Math.abs(value.hashCode() % count);
            case "mod":
                try {
                    return Integer.parseInt(value) % count;
                } catch (NumberFormatException e) {
                    return Math.abs(value.hashCode() % count);
                }
            default:
                return 0;
        }
    }
}
```

### 3. 简化的注解支持

```java
// 极简注解设计，只提供最常用功能
@Target({ElementType.METHOD, ElementType.TYPE})
@Retention(RetentionPolicy.RUNTIME)
public @interface UseDataSource {
    // 数据源名称：master/slave/customName
    String value() default "";
}

// 自动处理注解的AOP切面
@Aspect
@Component
@ConditionalOnProperty(name = "metadata.sdk.sql.multi-datasource.enabled", havingValue = "true", matchIfMissing = false)
public class DataSourceAspect {
    
    @Around("@annotation(useDataSource) || @within(useDataSource)")
    public Object around(ProceedingJoinPoint point, UseDataSource useDataSource) throws Throwable {
        try {
            if (StringUtils.hasText(useDataSource.value())) {
                AutoRoutingDataSource.useDataSource(useDataSource.value());
            }
            return point.proceed();
        } finally {
            AutoRoutingDataSource.clear();
        }
    }
}
```

## 三、使用示例（极简接入）

### 1. 默认模式（零配置）

```java
// 现有代码无需任何修改，完全兼容
@Service
public class MetadataService {
    
    @Autowired
    private MetadataRepository repository;
    
    // 自动使用默认数据源
    public Metadata findById(Long id) {
        return repository.findById(id).orElse(null);
    }
    
    // 自动使用默认数据源
    @Transactional
    public Metadata save(Metadata metadata) {
        return repository.save(metadata);
```

## 四、最佳实践建议

### 1. 零侵入接入策略

- **默认单库优先**：保持默认使用单数据库，确保现有代码完全兼容
- **配置驱动升级**：通过配置文件启用高级特性，无需修改代码
- **渐进式采用**：先启用读写分离，稳定后再考虑分表分库

### 2. 简化配置原则

- **最小配置集**：提供最简洁的配置项，合理设置默认值
- **分组配置**：按功能模块组织配置（读写分离、分表、数据源）
- **智能默认值**：根据环境自动推断合理配置

### 3. 性能优化建议

- **连接池隔离**：为主从数据库配置独立的连接池参数
  ```yaml
  metadata:
    sdk:
      sql:
        multi-datasource:
          datasources:
            master:
              pool:
                max-connections: 50
            slave1:
              pool:
                max-connections: 100
  ```

- **智能负载均衡**：基于响应时间动态调整从库选择策略
- **预热机制**：应用启动时预热数据库连接

### 4. 监控与可观测性

- **数据源指标**：暴露数据源使用情况、连接池状态等指标
- **切换日志**：生产环境可配置详细日志，便于排查问题
- **健康检查**：自动检测数据源可用性，支持故障转移

### 5. 部署与运维建议

- **环境一致性**：开发/测试/生产环境使用相同的配置结构
- **灰度发布**：支持按服务实例逐步启用新功能
- **配置热更新**：支持运行时更新数据源配置（无需重启）

## 总结

这套方案真正实现了"零侵入、零学习成本"的多数据源支持：

1. **默认单库模式**：现有代码无需任何修改，完全兼容
2. **配置驱动特性**：通过简单配置文件启用高级功能
3. **自动SQL识别**：自动区分读写操作，无需手动标注
4. **透明分表处理**：分表逻辑对业务代码完全透明
5. **极简API设计**：提供最简洁的注解和编程接口

这种设计遵循了"约定优于配置"和"渐进式增强"的原则，让开发者可以专注于业务逻辑，而将复杂的数据源管理交给框架处理。对于接入方来说，使用成本极低，同时又提供了强大的扩展性，满足从单数据库到复杂分表分库场景的各种需求。
