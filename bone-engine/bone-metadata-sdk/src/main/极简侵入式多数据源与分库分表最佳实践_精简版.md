# 极简侵入式多数据源与分库分表最佳实践

## 一、方案概述

本方案提供一套极低侵入性的多数据源管理解决方案，通过声明式配置和轻量级组件，实现读写分离、多租户隔离和分库分表，几乎不影响业务代码结构。

### 1.1 核心优势
- **极低侵入性**：通过注解驱动，业务代码几乎无需修改
- **声明式配置**：简洁的配置文件和注解即可完成数据源管理
- **透明切换**：数据源切换对业务层完全透明
- **高性能设计**：优化连接池管理，避免不必要的上下文切换

### 3.2 分库分表配置（可选）

```yaml
spring:
  shardingsphere:
    datasource:
      names: ds0,ds1
      ds0:
        type: com.zaxxer.hikari.HikariDataSource
        url: jdbc:mysql://localhost:3306/db_0?useSSL=false&serverTimezone=UTC
        username: root
        password: your-password
        driver-class-name: com.mysql.cj.jdbc.Driver
      ds1:
        type: com.zaxxer.hikari.HikariDataSource
        url: jdbc:mysql://localhost:3306/db_1?useSSL=false&serverTimezone=UTC
        username: root
        password: your-password
        driver-class-name: com.mysql.cj.jdbc.Driver
    rules:
      sharding:
        tables:
          user:
            actual-data-nodes: ds${0..1}.user_${0..1}
            database-strategy:
              standard:
                sharding-column: user_id
                sharding-algorithm-name: database-inline
            table-strategy:
              standard:
                sharding-column: user_id
                sharding-algorithm-name: table-inline
        sharding-algorithms:
          database-inline:
            type: INLINE
            props:
              algorithm-expression: ds${user_id % 2}
          table-inline:
            type: INLINE
            props:
              algorithm-expression: user_${user_id % 2}
```

## 四、业务使用示例

### 4.1 读写分离场景（注解方式）

```java
/**
 * 读写分离示例服务
 */
@Service
public class UserServiceImpl implements UserService {
    
    @Autowired
    private UserMapper userMapper;

    /**
     * 读操作：自动路由到从库
     */
    @DS("slave")
    @Override
    public User getUserById(Long userId) {
        return userMapper.selectById(userId);
    }

    /**
     * 写操作：使用主库
     */
    @DS("master")
    @Transactional(rollbackFor = Exception.class)
    @Override
    public Long saveUser(User user) {
        userMapper.insert(user);
        return user.getId();
    }

    /**
     * 写入后立即读取：使用主库避免延迟问题
     */
    @DS("master")
    @Transactional(rollbackFor = Exception.class)
    @Override
    public User updateAndGetLatest(User user) {
        userMapper.updateById(user);
        // 同一事务中直接读取，无需切换数据源
        return userMapper.selectById(user.getId());
    }
}
```

### 4.2 多租户场景（AOP自动路由）

```java
/**
 * 多租户自动路由配置
 */
@Configuration
public class TenantAutoConfiguration {

    /**
     * 多租户请求拦截器
     */
    @Component
    public static class TenantInterceptor implements HandlerInterceptor {
        @Override
        public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) {
            String tenantId = request.getHeader("X-Tenant-ID");
            if (tenantId != null) {
                DynamicDataSourceContextHolder.push("tenant_" + tenantId);
            }
            return true;
        }

        @Override
        public void afterCompletion(HttpServletRequest request, HttpServletResponse response, 
                                   Object handler, Exception ex) {
            DynamicDataSourceContextHolder.poll();
        }
    }

    @Bean
    public WebMvcConfigurer tenantConfigurer(TenantInterceptor tenantInterceptor) {
        return new WebMvcConfigurer() {
            @Override
            public void addInterceptors(InterceptorRegistry registry) {
                registry.addInterceptor(tenantInterceptor).addPathPatterns("/**");
            }
        };
    }
}
```

### 4.3 分库分表场景（透明使用）

```java
@Service
public class ShardingUserServiceImpl implements ShardingUserService {
    
    @Autowired
    private UserMapper userMapper;

    /**
     * 自动分片路由，对业务透明
     */
    @Override
    public User getUserById(Long userId) {
        // ShardingSphere自动根据分片键路由到正确的库表
        return userMapper.selectById(userId);
    }

    @Transactional(rollbackFor = Exception.class)
    @Override
    public Long insertUser(User user) {
        // 只需设置分片键，其余交给框架处理
        if (user.getId() == null) {
            user.setId(IdGenerator.nextId());
        }
        userMapper.insert(user);
        return user.getId();
    }
}
```

## 五、最佳实践建议

### 5.1 降低侵入性原则
- **优先使用注解**：@DS注解是最简单直观的数据源切换方式
- **避免硬编码**：数据源名称应通过配置管理，避免硬编码在业务代码中
- **集中处理**：使用AOP或拦截器集中处理通用逻辑，减少重复代码

### 5.2 性能优化建议
- 读操作默认使用从库，写操作强制使用主库
- 写入后立即读取的场景使用主库，避免主从延迟问题
- 为不同业务场景配置合理的连接池参数
- 实现基本的数据源健康检查

### 5.3 安全建议
- 多租户场景下，确保拦截器正确清理线程上下文
- 生产环境中使用环境变量或配置中心管理敏感信息
- 实现必要的数据访问权限验证

## 六、常见问题与解决方案

1. **主从延迟问题**
   - 解决方案：写入后立即读取的场景统一使用主库

2. **数据源切换异常**
   - 解决方案：确保异常情况下正确清理数据源上下文

3. **性能监控**
   - 解决方案：集成Spring Boot Actuator监控数据源状态

通过以上方案，可以实现对业务代码几乎零侵入的多数据源管理，同时保证系统的性能和可维护性。
