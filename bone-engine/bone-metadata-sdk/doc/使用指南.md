# Bone Metadata SDK 使用指南

> **架构、接入规范与演进路线**（唯一权威）：[Bone-Metadata-SDK-最佳实践方案.md](./Bone-Metadata-SDK-最佳实践方案.md)

本文档说明日常开发中的 API 用法（仓储、Criteria、DSL、多数据源、配置与排错）。依赖与最小示例见模块根目录 [README.md](../README.md)。

---

## 1. 核心概念

| 组件 | 说明 |
|------|------|
| `Repository<T, ID>` | 领域仓储接口；通用 CRUD 由框架代理提供 |
| `BaseRepository` | 框架内部实现，**业务侧不要继承** |
| `Criteria` | 读侧条件对象，配合 `findByCriteria` / `pageByCriteria` |
| `FluentQuery` / `repository.where()` | DSL 链式查询（类型安全 Lambda） |
| `SqlTemplate` | 仓储自定义方法的 SQL/YAML 模板 |
| `MetadataService` | 表/字段元数据（嵌入式或远程） |

---

## 2. 定义仓储

### 2.1 接口（推荐）

```java
// domain/repository/UserRepository.java
public interface UserRepository extends Repository<User, Long> {
    List<User> findByDepartment(@Param("dept") String department);
}
```

```java
// 启动类或 @Configuration
@EnableSqlRepositories(basePackages = "com.bone.yourmodule.domain.repository")
@SpringBootApplication
public class Application { }
```

实体使用 **bone-metadata-sdk D1 注解**（`@Table`、`@Id` 等），详见最佳实践方案 §4.2。

### 2.2 CRUD 示例

```java
// 按 ID
User user = userRepository.findById(1L);

// 条件查询（优先 Lambda）
Criteria<User> criteria = Criteria.<User>create()
    .eq(User::getStatus, 1)
    .gt(User::getAge, 18)
    .page(1, 20);
List<User> rows = userRepository.findByCriteria(criteria);

// 插入 / 更新 / 删除
userRepository.insert(newUser);
userRepository.update(user);
userRepository.deleteById(1L);
```

## 3. Criteria 查询

```java
Criteria<User> c = Criteria.<User>create()
    .eq(User::getStatus, "ACTIVE")
    .like(User::getUserName, "张")
    .between(User::getAge, 18, 60)
    .in(User::getId, idList)
    .orderByDesc(User::getCreatedAt)
    .page(pageNo, pageSize);

List<User> list = userRepository.findByCriteria(c);
long total = userRepository.countByCriteria(c);
```

**注意**：务必显式 `page(pageNo, pageSize)`；优先 `SFunction` 字段引用，避免不可信来源的字符串列名。

## 4. DSL 查询（FluentQuery）

DSL 能力集成在 `Repository` 默认方法中，与 Criteria 可并存。

### 4.1 设计理念

- 类型安全：Lambda 字段引用
- 链式 API：可读的条件组合
- 底层仍走 `SqlExecutor` / 现有 SQL 编译，与 Criteria 路径一致

### 4.2 入口

```java
// 方式 1：从条件开始
List<User> users = userRepository.where(User::getStatus).eq("ACTIVE").list();

// 方式 2：先取 FluentQuery
FluentQuery<User> q = userRepository.query();
```

### 4.3 条件、排序、分页

```java
List<User> activeUsers = userRepository.where(User::getStatus).eq("ACTIVE")
    .and(User::getCreatedAt).gt(startDate)
    .and(User::getUserName).like("%test%")
    .orderByDesc(User::getCreatedAt)
    .limit(100)
    .list();

// page(int, int) 直接返回 PageResult，不再链式调用无参 page()
PageResult<User> page = userRepository.where(User::getDepartment).eq("技术部")
    .orderBy(User::getUserName, true)
    .page(1, 20);

long count = userRepository.where(User::getStatus).eq("ACTIVE").count();
boolean exists = userRepository.where(User::getUserName).eq("admin").exists();
Optional<User> one = userRepository.where(User::getId).eq(1L).singleOpt();
```

**终端方法只有这些**（`query.dsl.FluentQuery`）：

| 方法 | 返回 |
|------|------|
| `list()` | `List<T>` |
| `count()` | `long` |
| `page(int pageNum, int pageSize)` | `PageResult<T>` |
| `exists()` | `boolean` |
| `singleOpt()` | `Optional<T>`；多于 1 行抛 `IncorrectResultSizeDataAccessException` |
| `first()` | `Optional<T>`，等价于 `limit(1).singleOpt()` |

排序为 `orderBy(SFunction, boolean isAsc)` / `orderByDesc(SFunction)`；**没有**单参 `orderBy(Lambda)`、
**没有** `findOne()`、**没有** `list(Class)` 投影重载。需要 DTO 投影请用 `@Sql` 自定义方法（见 §6.3）。

### 4.4 复杂示例

```java
List<User> users = userRepository.where(User::getStatus).eq("ACTIVE")
    .and(User::getAge).gt(18)
    .and(User::getAge).lt(60)
    .and(User::getUserName).like("张%")
    .orderByDesc(User::getCreatedAt)
    .list();
```

### 4.5 DSL 使用建议

| 场景 | 建议 |
|------|------|
| 简单过滤 + 列表 | `where(Lambda).eq(...).list()` |
| 分页列表 | `.page(n, size)` |
| 复杂多表 JOIN | SQL 模板或 `infrastructure` 读侧查询 |
| 新功能 | 优先 DSL 或 Criteria Lambda，避免裸字符串字段名 |

链式调用不宜过长（建议 ≤ 7 步）；复杂逻辑封装为仓储方法 + 模板 SQL。

## 5. 多数据源

### 5.1 注解切换

支持 `@DS("slave")`（`com.bone.metadata.sdk.support.dataSource.annotation.DS`）及 `@DataSourceSwitch`：

```java
@Service
public class UserService {

    @DS("slave")
    public User getUserById(Long id) {
        return userRepository.findById(id);
    }
}
```

写操作走主库；只读查询再切从库；**同一事务内避免切换数据源**。

### 5.2 编程式切换

```java
try {
    DataSourceContextHolder.setDataSource("slave1");
    return userRepository.findById(id);
} finally {
    DataSourceContextHolder.clearDataSource();
}

// 或
return dataSourceManager.executeWithDataSource("slave1",
    () -> userRepository.findById(id));
```

配置：`bone.metadata.datasource.enabled=true`，详见 §7。

## 6. 高级功能

### 6.1 分页

```java
Criteria<User> criteria = Criteria.<User>create()
    .eq(User::getStatus, 1)
    .page(1, 10);
PageResult<User> pageResult = userRepository.pageByCriteria(criteria);
```

另有 `queryPage(PageParam)` 与 `queryByCondition(List<QueryParam>, List<SortingField>, pageNo, pageSize, bizIdentityCode)`
两个通用入口。**不存在** `findByCriteriaWithPage`。

### 6.2 批量操作

```java
userRepository.batchInsert(userList);
userRepository.batchSave(userList);
```

### 6.3 自定义 SQL（`@Sql` 仓储方法）

多表 JOIN、扁平投影、报表、全租户扫描都走这条通道。接口方法由 `SqlMethodHandler` +
`UnifiedSqlTemplateLoader` + `SqlProcessor` 解析，最终仍经 `SqlExecutor` 执行。

```java
@SqlFragment(id = "userCols", value = "u.id, u.name, u.role_id, u.created_at")
public interface UserRepository extends Repository<User, Long> {

  @Sql("""
       SELECT <include refid="userCols"/>
       FROM users u
       WHERE u.deleted = 0
         <if test="name != null and name != ''">
           AND u.name LIKE CONCAT('%', #{name}, '%')
         </if>
         <if test="roleIds != null and !roleIds.isEmpty()">
           AND u.role_id IN
           <foreach collection="roleIds" item="item" open="(" close=")" separator=",">
             #{item}
           </foreach>
         </if>
       ORDER BY u.created_at DESC
       """)
  List<User> searchUsers(@Param("name") String name, @Param("roleIds") List<Long> roleIds);
}
```

**模板来源与优先级**（`UnifiedSqlTemplateLoader`）：默认 `annotation-first`，找不到再回退 classpath；
由 `metadata.sdk.sql.template.load-priority` 切换。

| 来源 | 位置 | 格式 |
|------|------|------|
| 方法 `@Sql` 注解 | 接口方法上 | MYBATIS |
| `classpath:/sql/<包路径>/<接口简名>/<方法名>.sql` | `resources/sql/` | MYBATIS |
| `classpath:/sql-templates/<接口简名><方法名>.yaml` | `resources/sql-templates/` | YAML_SQL |

模板 ID 固定为 `{Repository 接口全限定名}.{方法名}`。

**动态标签**：`if` / `where` / `foreach` / `choose` / `when` / `otherwise` / `set` / `trim` / `bind`；
片段用 `@SqlFragment(id=...)` + `<include refid="..."/>`，或 `<sql id="...">`。
未知标签会被**原样输出为文本**，不会报错——写完务必核对。

**占位符**：

- `#{expr}`：SpEL 求值后绑定为命名参数（`a.b` → 参数名 `a_b`）；**求值为 null 会抛异常**，可选条件必须用 `<if test="x != null">` 包住。
- `${expr}`：直接字符串拼接，值必须匹配 `^[a-zA-Z0-9_]+$`，仅用于白名单化的表名/列名。

**返回类型映射**（`RepositoryFactoryBean#handleSelect`）：

| 返回类型 | 行为 |
|----------|------|
| `List<T>` | `sqlExecutor.query(...)` 逐行映射 |
| `Optional<T>` | 0 行 `empty`；>1 行抛 `IncorrectResultSizeDataAccessException` |
| 简单类型（`Long`/`String`/…） | `queryForObject` |
| 其它（`PageResult` 等） | 按单行映射处理 —— **`PageResult` 无专用分支**，见下 |

> **`PageResult` 不要作为 `@Sql` 方法的返回类型**：代理没有分页分支，不会自动 count。
> 需要分页时写成两个方法（`countXxx` + `selectXxx limit/offset`），在调用方用 `PageResult.of(...)` 组装。

**结果映射**：走 `SmartRowMapper`，用 `BeanUtils.instantiateClass` 创建实例后反射填字段。
因此 **DTO 必须有可访问的无参构造器**（不需要 setter），且列标签要能映射到字段名——
SQL 里请写显式别名（如 `u.id AS order_id` → 字段 `orderId`）。

**`@Sql` 不注入租户、不注入软删条件**：SQL 所见即所得。租户内查询要自己写
`AND tenant_id = #{tenantId}`；跨租户场景（Outbox 中继、定时任务扫描）不写即可，但必须在应用层登记授权与审计。

完整的坑位清单与决策树见 [AGENT-持久化速查手册](./AGENT-持久化速查手册.md)。

## 7. 配置参考

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/bone
    username: root
    password: ${DB_PASSWORD}
    driver-class-name: com.mysql.cj.jdbc.Driver

metadata:
  sdk:
    deploymentMode: EMBEDDED   # 或 REMOTE

bone:
  metadata:
    datasource:
      enabled: true
```

**主要自动配置类**（Boot 3 `AutoConfiguration.imports`）：

| 类 | 作用 |
|----|------|
| `MetadataAutoConfiguration` | 元数据服务、上下文 |
| `SqlRepositoryAutoConfiguration` | SqlExecutor、模板加载、SqlBuilder |
| `UnifiedDataSourceAutoConfiguration` | 动态数据源 |
| `InterceptorAutoConfiguration` | 拦截器 |

## 8. 故障排除

| 现象 | 排查 |
|------|------|
| 仓储 Bean 未注册 | 是否添加 `@EnableSqlRepositories` 且 `basePackages` 正确 |
| 数据源切换无效 | 数据源名是否与配置一致；`finally` 中 `clearDataSource` |
| 查询过慢 / OOM | 是否显式分页；SQL 与索引；避免 N+1 |
| 自定义方法 SQL 找不到 | 模板路径与 `{接口}.{方法}` ID 是否一致 |

规范性问题（禁止 JPA 主路径、仓储命名、读写分层）以 [最佳实践方案](./Bone-Metadata-SDK-最佳实践方案.md) 为准。
