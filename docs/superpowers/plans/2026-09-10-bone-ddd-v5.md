# Bone DDD v5.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 Bone DDD v4.9 重写为概念准确、内部一致、可执行且可维护的 v5.0 规范体系。

**Architecture:** 主文档作为稳定规范入口，业务 Context Map、应用与一致性、机器门禁、迁移台账、版本历史分别进入专用分册。保留仓内已引用标题的兼容入口；本轮只改文档，不修改 Java 门禁实现或业务代码。

**Tech Stack:** Markdown、ADR、Mermaid/ASCII 架构图、ripgrep、仓库 Docs-as-Code 脚本。

## Global Constraints

- `doc/architecture/Bone-DDD-最终实践方案.md` 仍是 DDD 与分层规范入口。
- 领域持久化仍只允许 `bone-metadata-sdk`，不引入其他 ORM。
- 本轮不修改 Java、DDL、OpenAPI、CI 脚本和 AI 自主权等级。
- ADR-0024 状态为“已接受”，本次对话代表架构师批准。
- 当前工作区有大量用户改动，只修改计划列出的文档。
- 不创建 Git commit，由用户统一审查和提交。

**Files:**

**Interfaces:**

- Produces: 主文档可链接的稳定专题真源。

- [ ] **Step 1: 编写纯业务 Context Map**

`context-map.md` 必须包含：

```markdown
# Bone 限界上下文与上下文映射

## 1. 战略分类
## 2. 业务限界上下文
## 3. 上下文关系
## 4. 数据所有权与发布契约
## 5. 技术模块依赖图（非 Context Map）
```

约束：

- Context Map 只画 Metadata、IAM、MasterData、Integration、Extension、System、Notification、Generator 和 Payment 样板。
- framework、SDK、Gateway 仅进入第 5 节技术依赖图。
- Metadata 表述为 Bone 当前唯一已认定核心域，不表述为 DDD 行业限制。
- Shared Kernel 仅用于真正共同拥有的领域模型；普通公共库使用 Shared Library/Platform Kernel。

- [ ] **Step 2: 编写应用与一致性分册**

`application-and-consistency.md` 必须包含：

```markdown
# Bone 应用架构与一致性

## 1. 应用用例边界
## 2. CQRS 与端口位置
## 3. 聚合与事务策略
## 4. 可靠事件发布
## 5. 并发与幂等
## 6. 错误模型
## 7. 持久化模型决策
```

必须明确：

- Handler 或 ApplicationService 二选一作为用例边界，禁止套娃。
- QueryPort 位于 application，QueryBuilder 位于 infrastructure。
- 一个事务默认修改一个聚合实例，R9 扫描为启发式提示。
- Outbox、乐观锁为默认参考实现，不是唯一实现。
- 允许三根异常的语义子类。
- 跨聚合 ID 不触发 PO 分离。

- [ ] **Step 3: 编写门禁分册**

`enforcement.md` 将规则分为：

```markdown
## Hard gate
## Semantic review
## Advisory
## Planned
## 当前 ArchUnit 实现映射
```

`oneAggregatePerTransaction` 和 `AggregatePureUnitTestGuard` 必须标注证明边界，不得宣称能证明领域语义。

- [ ] **Step 4: 迁出迁移台账与版本历史**

`migration-ledger.md` 承接 v4.9 附录 B.2/B.3.1；`CHANGELOG.md` 承接开头 v4.5–v4.9 摘要。不得在分册中虚报 CI 已实现。

- [ ] **Step 5: 验证分册无相互矛盾**

Run:

```bash
rg -n '必须 Outbox|唯一实现|一事务一聚合根|Controller.*只能.*Handler|70/20/10' \
  doc/architecture/ddd --glob '*.md'
```

Expected: 只出现历史 changelog 或明确说明“旧规则已修订”的位置。
