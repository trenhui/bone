# 理赔作业台融合增强 —— 深度分析报告

> 2026-11-13 ｜ change: synapclaim-workbench-assignment-review-quality ｜ 证据口径：worktree `comet/synapclaim-workbench-assignment-review-quality`（基于 `dev@6f0ea427f`）实测，结论均带 `文件:行号`。

## 一、一页结论

**问题不是「菜单没分类」，而是四件事同时缺位：没有归属（案件不认人）、没有队列（工位靠 ID 找活）、没有兜底（请假就卡案）、AI 在后台不在屏上。**

| 用户感受 | 代码层事实 | 证据 |
|---|---|---|
| 初审只有状态可筛，找不到案 | 页面仅 1 个 `Select`（状态），无关键词/时间/金额/渠道/处理人 | `PreExamWorkbenchPage.tsx:209-219` |
| 待办永远翻不全 | 核赔页固定拉 50 条、前端切 20/页，第 3 页即空 | `ReviewWorkbenchPage.tsx:199,343` |
| 案件不认人 | 案件表只有两个复核人字段，无 assignee/队列/优先级；「分配」只改状态不记人 | `bone-init.sql:2745-2746`、`ClaimCase.java:408-411` |
| 请假就停摆 | IAM 无代理人模型；工作流 `transferTask` 未接入理赔 | `bone-init.sql:80,98`、`WorkflowEngineImpl.java:289` |
| AI 帮不上忙 | 决策图与阈值已实现，但 `AUTO_APPROVE` 默认关闭、阈值只能手写 JSON、前端 0 触点 | `AutoApprovalApplicationService.java:52-57`、`TriageLimits.java:48-60` |
| 质检查了也白查 | 结论「只登记不执行」，无打回、无列表 | `InspectionRecord.java:30-31`、`InspectionController.java:41` |

## 五、优化建议（按真实场景，逐条给依据与成本）

### 5.1 查询与检索（批 1，成本低）

- **建议**：三工作台统一 `ClaimQuery`（关键词 / 状态集 / 任务类型 / 处理人 / 作业组 / 渠道 / 金额区间 / 时间 / SLA 分桶），服务端分页返回真实 `total`。
- **依据**：核赔页第 3 页即空（固定 50 条）不是"条件少"，是分页契约错误——用户丢掉了 2/3 待办。
- **真实场景**：客服拿着报案号找案、主管按组看积压、理赔员按金额段捞大额。

### 5.2 归属与分配（批 1，成本中）

- **建议**：`t_claim_task` + `t_claim_assign_rule` + 候选集打分 + 超时回池；默认视图「我的待办」，可切「全部」。
- **依据**：现状主管只能看着案件堆着，没有任何干预手段；规则只表达"派给哪群人"，负载要靠打分。
- **真实场景**：大额派高技能组、小额摊平、峰值允许自领兜底。

### 5.3 请假 / 转交 / 代理（批 4，成本中）

- **建议**：转交（单案） + 代理（时间窗） + 不可用（跳过并回池）三层；不自建 HR。
- **依据**：请假一天＝一批案件静默过期，这是理赔部最常见的运营事故。
- **真实场景**：年假前把 20 件在办移交同事；病假期间代理人接手新派单。

### 5.4 AI 自动初审的配置面（批 2，成本低-中）

- **建议**：三层配置（L1 代码规则 / L2 租户策略 / L3 作业参数） + 受控 API + 治理页可写（只收紧） + 初审页 AI 建议与采纳回流。
- **依据**：能力已在，运营为零——`AUTO_APPROVE` 默认关闭、阈值只能手写 JSON。
- **回答用户原问**：「自动初审的规则在哪里配置」→ 确定性规则在代码（不可配），自动化策略在 `t_feature_toggle`（可配但只能收紧），作业参数在规则表/SLA 配置。

### 5.5 复核与复审（批 3，成本中高）

- **建议**：复审独立成段（43/46 + 独立权限码），与「≥1 万双人复核（44）」并列。
- **依据**：金额闸门与质量闸门的队列、度量、责任人完全不同，合并即无法分别治理。
- **真实场景**：大额案两人签；抽查案由质检组按比例复核，发现问题打回核赔。

### 5.6 质检闭环（批 4，成本中）

- **建议**：结论可执行（打回/重算/追偿），已支付必须先冲正；抽检单接入队列与比例配置。
- **依据**：只登记不处置＝质检无效；已支付直接改状态＝账实不一致。

## 六、分批路线

| 批 | 范围 | 依赖 | 回退开关 |
|---|---|---|---|
| 1 | 任务表 + 规则表 + 分配器 + 我的待办 + 统一查询 | 无 | `AUTO_ASSIGN` |
| 2 | AI 配置 API + 治理页可写 + AI 建议与采纳回流 | 批 1 | 关闭 PUT |
| 3 | 独立复审（43/46 + 权限码 + 队列） | 批 1 | `RE_REVIEW` |
| 4 | 抽检打回 + 请假/转交/代理 + 文档一致性门禁 | 批 1、批 3 | `INSPECTION_ACTION` |

## 七、本报告不做的判断

- 不给自动化率/时效承诺值：行业数字均为方向性依据，目标值应以自有埋点基线为准。
- 不建议把拒赔做成自动：监管与资金安全优先。
- 不建议重做菜单/导航：v2.2 已收口，重复设计会推翻已验证的单导航探针 122/122。
