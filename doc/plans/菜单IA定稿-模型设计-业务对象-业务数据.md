## 1. 定稿结构（目标态）

```
业务建模                      （一级分组，名称保留）
 ├─ 模型设计   /metadata#/apps      order=1   metadata:model:read
 ├─ 业务对象   /metadata#/entities  order=2   metadata:model:read
```

- **不动**：分组名「业务建模」、全部 path/路由、权限码、菜单可见性、order（业务数据维持 0027 降级后的末位语义）。
- **语义链**：在哪建（模型设计）→ 建什么（业务对象）→ 看数据（业务数据）。

## 2. 命名映射与依据

| 现名 | 定名 | 一句话理由 |
|---|---|---|
| 建模工作台 | **模型设计** | 页面核心是"创建/校验/发布模型"的设计活动；去掉宽泛的"工作台"；消除与父级「业务建模」的父子重名 |
| 实体 | **业务对象** | 对齐 `glossary.md` 已有定义 `MetaEntity = 业务对象定义`；对业务人员可读，对研发无损（文档内继续用 Entity）；业界同位词 Salesforce Objects / Dataverse Tables |
| 运行时数据 | **业务数据** | 去掉工程黑话 Runtime；对齐 glossary「按模型读写业务数据」；直接表达"这里是实际业务记录" |

三条命名原则（拍板原文，纳入ADR）：
1. **用户语言优先**：名称表达"用户要做什么/管什么"，不暴露底层实现。
2. **同一抽象层次**：设计活动 / 业务定义 / 业务记录，三层关系清晰。
3. **避免过度专业化**：不要求用户理解 Entity/Runtime 等概念。

**术语表同步**（glossary.md 增补一行对照，避免文档词与 UI 词漂移）：
- 「模型设计 / 业务对象 / 业务数据」= 菜单 UI 名；「Modeling Workspace(App导航) / MetaEntity / Metadata Runtime」= 领域/代码名。「运行时」保留为**架构文档词**，不再出现在用户界面。

## 3. 功能边界（拍板 + 实证校准）

### 3.1 模型设计（现 ModelingWorkspace 页，`/apps`）
- **回答**：如何定义和发布一套业务模型？
- 载荷：创建 CTA（场景模板 / 空白建模 / 存量表导入）+ 我的应用/模块导航 + 待发布实体看板 + 发布动作。
- **诚实标注**：本页当前是"应用导航 + 创建入口 + 发布看板"，**尚不是完整可视化设计器**；设计器界面由 PRD v0.46（P1 可视化建模 UI）演进承接。命名先行、能力按 PRD 路线走，不因改名虚构能力。

### 3.2 业务对象（现 EntityManagement/EntityDetail 页，`/entities`）
- **回答**：系统中有哪些业务对象，它们如何定义？
- 载荷：对象定义清单（**唯一真源**：搜索/筛选/批量发布/复制/导出）+ 对象详情四 Tab（字段/关系/界面/数据）。
- **防止双设计器**：复杂字段与关系编辑**只在**对象详情（EntityDetail）完成；「模型设计」页不重复实现设计器，仅做创建入口与跳转（CTA 直达"选应用→选模块→新建对象"动线）。这正是拍板要求的"清单 + 详情 + 快捷编辑，复杂修改跳设计器"的现有形态。

### 3.3 业务数据（现 RuntimeDataManagement 页，`/runtime`）
- **回答**：系统实际有哪些业务记录？
- 载荷：跨对象记录查询/筛选/CRUD/归档/恢复（回收站）。
- **主路径声明**：单对象日常录数走「对象详情 → 数据 Tab」（上下文已锁定，无"先选实体"空转）；顶层「业务数据」定位为**跨对象运营台**，页头副标题必须写明，消除第三个数据入口的困惑。
- **不扩容**：工作流实例、Agent 执行记录**不进**本菜单；若后续扩展，另设「运行实例 / 执行记录」（拍板明确）。

## 4. 明确不做（本轮划界）

| 事项 | 判定 | 理由 |
|---|---|---|
| 合并「模型设计 + 业务对象」 | 暂不 | 用户任务独立（管理对象定义可直达），且当前两页职责不重叠；若后续数据显示维护频率极低，按拍板"场景表"再议合并 |
| 数据管理页改名 | — | 拍板定名「业务数据」（非"数据管理"），与记录语义更贴 |
| 母组改名（数据建模/应用建模等） | 否 | 拍板保留「业务建模」；候选词留存本节备查，v1.1 再议 |
| 改 path / 权限码 / 路由 / E2E | 否 | 名称层变更零路由影响；`check-menu-single-entry.py`(G35) 只校验单入口与死链，不依赖命名 |
| 第二套对象设计器 | 禁止 | 单一真源在对象详情；见 3.2 |
