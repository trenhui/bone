# 08 部署运维手册（MVP → 试点）

> 用途：试点/客户环境部署与运维的可执行手册（FDE §五"部署包+运维手册"产物的成文版）。分三部分：部署、日常运维、应急。

---

## 一、部署

### 1.1 部署形态（两档）

|**档位**|**适用**|**拓扑**|**资源要求**|
|---|---|---|---|
|轻量（试点/Demo）|Shadow 旁路、单客户试点|Docker Compose 单机：Gateway+Core+TiDB+vLLM(可选)|8C16G + 显存 ≥16G（vLLM 本地推理）|
|标准（生产）|Phase B/C|K8s 集群：Gateway×2 / Core×2 / TiDB×3 / vLLM 独立节点|按案件量横向扩展|

### 1.2 部署步骤（轻量档）

```bash
# 1. 环境准备：Docker 24+；检查端口 8080(API)/2379(TiDB)/8000(vLLM)
# 2. 拉取部署包
git clone <repo> deploy && cd deploy
# 3. 配置（config.yaml）：租户、密钥、目录库版本、规则版本、三态开关
vi config.yaml
# 4. 启动
docker compose up -d
# 5. 验证
curl -s http://localhost:8080/api/v1/health   # 期望 {"status":"ok","mode":"shadow"}
# 6. 数据初始化：目录库导入 + 规则导入 + 评测集导入
./scripts/init-data.sh
```

### 1.3 三态开关（Shadow / Assisted / Automated）

|**模式**|**行为**|**切换方式**|**回退**|
|---|---|---|---|
|shadow|只读同步+旁路出建议+对照评测|config.yaml `mode: shadow`|关同步即可|
|assisted|工作台嵌入，人工终审|`mode: assisted`|关闭建议开关|
|automated|低风险自动通过+支付|`mode: automated` + `autoRatio: 0.05` 灰度|按比例回退|

**切换纪律**：一次只切一个开关；灰度从 5% 开始；切换后 24h 观察三指标（自动化完成率/介入率/结案时效）。

## 二、日常运维

### 2.1 监控与告警（SLO）

|**SLO**|**指标**|**告警阈值**|**告警通道**|
|---|---|---|---|
|可用性 99.99%|探活/错误率|5 分钟错误率 >1%|钉钉+邮件|
|决策 P95 ≤30s|决策链路耗时|P95 >30s 连续 10 分钟|钉钉|
|资金零差错|对账差异|任一差异订单|紧急电话+邮件|
|评测回归|五指标|任一指标下降 >1pp|钉钉|
|数据同步（Shadow）|同步延迟|延迟 >15 分钟|钉钉|

### 2.2 备份与恢复

|**对象**|**策略**|**RPO/RTO**|
|---|---|---|
|TiDB（业务数据）|每日全量 + binlog 实时|RPO ≤5min / RTO ≤1h|
|目录库/规则库（资产）|版本库（Git）|即取即用|
|评测集/标注|版本库 + 对象存储双份|—|
|审计日志|追加式独立存储（7 年）|—|

**恢复演练**：季度一次恢复演练（备份→恢复→校验数据完整性），演练记录存档。

### 2.3 数据保留与删除 SOP（合规）

|**数据**|**保留期**|**到期处理**|
|---|---|---|
|资金/决策日志|≥7 年（监管）|归档存储，只增不改|
|普通操作日志|≥180 天|自动清理|
|案件业务数据|合同约定（试点终止 30 日内删除/返还）|删除+销毁证书|
|评测集脱敏数据|项目存续期|删除脚本+审计留痕|

## 三、应急手册

### 3.1 故障分级与响应

|**级别**|**场景**|**响应**|**目标**|
|---|---|---|---|
|P0|资金异常/全站不可用|立即响应（值班+CEO）|15 分钟内恢复或降级（符合 US-09）|
|P1|决策 P95 超时/数据同步中断|30 分钟内响应|4 小时内恢复|
|P2|功能缺陷/告警噪声|48 小时内修复|—|

### 3.2 典型故障处置

|**故障**|**判断**|**处置**|
|---|---|---|
|决策超时|vLLM 卡顿/OCR 慢|切规则兜底路径（AI 降级）；扩 vLLM 并发|
|资金重复支付风险|对账差异单|立即冻结该案件支付 → 查幂等键 → 人工核对 → 冲正|
|数据同步中断|Shadow 同步延迟告警|检查源系统接口/文件通道 → 断点续传恢复 → 补齐期间数据|
|评测指标下滑|发布后回归失败|回滚最近规则/模型版本（版本绑定记录）→ 复盘失败案例|
|安全事件|泄露/越权告警|按 02 方案：24h 内通知客户 → 隔离 → 取证 → 整改|

### 3.3 值班与交接

- 值班表：CEO/底座/理赔轮值（试点期 7×12 覆盖）
- 交接：值班日志（事件、处理、遗留项）每日同步
- 演练：季度切换演练（三态回退演练 + 备份恢复演练）
