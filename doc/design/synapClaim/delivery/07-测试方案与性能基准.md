# 07 测试方案与性能基准

> 用途：把 PRD §13 的承诺（99.99% 可用性、30 秒 SLA、零资金差错）变成**可执行、可验收**的测试计划。性能实测结果以"待实测"标注（需真实环境），测试方法论与指标口径先行定稿。

---

## 一、测试分层与范围（MVP）

|**层**|**范围**|**工具**|**责任人**|**门禁**|
|---|---|---|---|---|
|单元测试|规则引擎（理算公式）、状态机、幂等逻辑|JUnit|理赔负责人|核心模块覆盖 ≥80%，0 失败|
|集成测试|存储/事件/AI 调用链|Testcontainers|底座负责人|0 失败|
|接口测试|05 契约逐接口（含错误码、幂等）|RestAssured|后端|契约用例 100% 通过|
|端到端测试|4 类案件全链路（自动通过/拒赔/转人工/补件）|Playwright|全员|主路径全绿|
|评测回归|基准测试集五指标（字段/规则/复核率/时长/错误率）|评测脚本|理赔负责人|**发布门禁**：五指标不下降|
|性能测试|见 §三|JMeter/k6|底座负责人|见 §三 通过标准|
|安全测试|越权/注入/敏感数据泄露|OWASP ZAP|CEO/底座|高危 0，中危整改|

## 二、评测集与标注规范（测试可信度保障）

1. **样本量**：MVP 基准集 ≥300 条（覆盖 §四规则书第十节的边界样本要求）
2. **标注规范**：双人独立标注 + 不一致讨论裁决；标注指南（含典型误判案例）成文
3. **标注一致性**：抽 10% 双人复标，一致性 ≥95%（Cohen's Kappa ≥0.85）
4. **测试集/训练集分离**：评估只用测试集；失败案例回收用于规则修正（不入测试集，防过拟合）
5. **报告口径**：每次评测输出五指标报告（字段/规则/复核率/时长/错误率）+ 失败案例回放（区分模型层 vs 规则层 vs 接口层问题）

## 三、性能基准（指标口径 + 待实测项）

### 3.1 指标定义

|**指标**|**定义**|**目标**|**口径**|
|---|---|---|---|
|决策 P95 延迟|提交到返回结果（自动路径）|≤30 秒（P95）|不含人工环节；含 OCR+规则+理算（AI 可选）|

## 四、安全测试要点（金融敏感）

- 越权：跨租户读取（TenantId 隔离）、水平越权（他人案件）——强制用例
- 注入：SQL/NoSQL/命令注入——规则引擎输入面
- 敏感数据：接口响应是否泄露明文身份证/病历（脱敏检查）；日志是否打印敏感字段
- 传输与存储：TLS、AES-256 静态加密验证
- 模型接口：LLM 输出注入（prompt injection 样本 10 条）

## 五、发布门禁（CI 集成，借鉴 Bone 门禁）

```plaintext
静态检查(0违规) → 单元测试(0失败) → 契约测试(100%) → 评测回归(五指标不下降)
→ 安全扫描(高危0) → 性能冒烟(关键场景) → 发布
```

**不 freeze 原则**：门禁全部自动化，任何提交必须过门禁，不靠"冻结版本"保质量。
