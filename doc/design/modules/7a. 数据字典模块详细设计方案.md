## 1. 模型选型：为什么不是「同一模型父子结构」

「值域」和「值」要不要放进同一张自引用树？这是字典建模的第一个分叉口，先把三个候选摆在一起：

| 模型 | 结构 | 业界代表 | 结论 |
|---|---|---|---|
| **A** 单表父子树（值域 = 根节点） | `sys_dict_node(id, parent_id, code, label, value, …)`，深度 0 即值域 | 国内若依系改造版、「省市区一张表」 | ❌ 否掉 |
| **B** 两级 + 父指针内联 | `sys_dict_type` + `sys_dict_item(parent_code)` | Oracle `FND_FLEX_VALUE_SETS` + `FND_FLEX_VALUES.PARENT_FLEX_VALUE`；ISO 11179 值域 + 允许值 | ◐ 可用，但层级被焊死 |
| **C** 两级 + 层级关系独立 | `sys_dict_type` + **扁平** `sys_dict_item` + `sys_dict_hierarchy(hierarchy_code, code, parent_code, path, level)` | **SAP**（值表扁平 + HANA hierarchy 表 / `SETHEADER`·`SETLEAF` 集合）、**W3C SKOS**（ConceptScheme + Concept + `skos:broader`，可多套层级）、Oracle EBS「值集层次」作为独立可编译对象 | ✅ 采用 |

### 1.1 为什么否掉 A（单表父子树）

1. **不变量不同却共用一行**。类型有 `category / enumClass / builtin / editable / maxDepth`，项有 `code / label / value / tagType / isDefault`。同表 ⇒ 要么稀疏列（一半字段对另一半行无意义），要么加 `node_type` 判别列 ⇒ **每个查询都要带判别条件**，且约束无法落到数据库。
2. **丢掉数据库级唯一约束**。值域编码唯一（`(tenant_id, code)`）只对根节点成立；MySQL 没有部分唯一索引，只能退回应用层校验——并发下必然产生重复值域（v1 正是因为唯一键缺失踩过）。
3. **高频查询退化**。下拉是最高频操作：C 模型是 `WHERE type_code = ?` 单列等值命中索引；单表树要先定位根、再按 path 前缀或递归取子树，深度越大越慢。
4. **语义混淆**。删除「一个有子的类型」= 删掉整个值域；删除「一个有子的项」= 删掉一个选项。单表里两者形状完全一致，只能运行时判 depth，**护栏写不进模型**。
5. **事务与并发**。类型与项生命周期不同（类型改一次、项改很多次）；塞进同一行/同一聚合后，「改一个选项」会与「改值域定义」互相阻塞，也破坏 R9「一事务一聚合」。

### 1.2 为什么 B 不够（层级焊在值上）

- **单归属**：`parent_code` 一列 ⇒ 一个值只能有一个父，表达不了「广州既属于广东省，也属于一线城市」。
- **单视图**：同一值域无法并存多套层级（SAP 的 hierarchy variant：成本中心在「组织架构树」和「报表汇总树」里位置不同）。
- **Oracle 自己也不是这么做的**：EBS 把「值集层次」作为**独立可编译对象**（`FND_FLEX_VALUE_HIERARCHIES`），父指针只是其中一种投影，不是值的固有属性。

### 1.3 v3 采用 C，并补上 Oracle / SAP 的另外四项能力

| # | 能力 | 业界出处 | 解决的真实问题 |
|---|---|---|---|
| 1 | **层级关系独立**（`hierarchy_code` + `path` + `level`） | SAP 值表扁平 + 独立 hierarchy 表；SKOS `skos:broader` | 多层级视图、多归属、层级变更不触碰值本身 |
| 2 | **时间有效性** `effective_from` / `effective_to` | Oracle `FND_LOOKUP_VALUES.START_DATE_ACTIVE / END_DATE_ACTIVE` | 「历史单据按旧口径展示、新单据用新口径」——只有启停开关做不到 |
| 3 | **多语言文本表** `sys_dict_item_text` | SAP `T005` / `T005T` 文本表；Oracle `FND_LOOKUP_VALUES_TL` | 值语言无关、译文按 `(code, language)` 存；`/options?lang=` 服务端下发，运营可改、不依赖前端发版 |
| 4 | **外部标准码** `external_code` | SAP check table / 集成场景 | 内部码是平台契约、外部码是对接契约（GB/T 2260、ISO 4217）；v1 把 code 与 value 混用正是这个坑 |
| 5 | **值类型与格式校验** `value_type` + `value_regex` | **SAP Domain**：Domain 定技术属性（类型/长度/小数位/取值范围），Data Element 定语义，值域定取值范围——三层分工 | 把「值必须是什么形状」写进模型，而不是散在前端表单 |
| 6 | **编码分段推导层级** `code_segments` | GB/T 2260 行政区划、UNSPSC、ICD-10、HS 编码 | 层级由**编码前缀**表达（4401 00 → 广东省/广州市），导入时自动补齐父子，无需人工点选 |

> 保留 `i18n_key` 但明确分工：它服务「前端静态语言包」，`sys_dict_item_text` 服务「服务端下发的运营可编辑译文」——两条消费路径、两个真源，不重叠（同 SAP 既有 `T005T` 可编辑文本、也有前端资源文件）。

## 2. 目标与非目标

**目标（v3）**
- G1 两级模型：**字典类型**（定义）+ **字典项**（值）。
- G2 三类值域：**ENUM**（绑定代码枚举）/ **LIST**（扁平）/ **CASCADE**（可挂层级）。
- G3 枚举与字典**单一真源**：同步 + 双向漂移检查。
- G4 **可插拔层级**：默认 `DEFAULT` 层级，可并存多套视图；`path` 物化路径 + `level` 深度，避免递归查询。
- G5 内置保护 + 租户覆盖：平台只读，租户覆盖文案/排序/启停。
- G6 时间有效性、多语言译文、外部标准码、值类型校验。
- G7 进程内缓存 + 写失效。
- G8 前端消费标准化：`useDict` / `<DictSelect>` / `<DictTag>`。

**非目标**
- 不做跨服务字典 RPC/SDK（其他服务走 HTTP；`mdm_reference_*` 收敛另立 change）。
- 不做字典变更历史流水（同 `sys_config` 现状，属 [Target]）。
- 不做「层级版本」（同一层级的历史版本回溯），需要时另立对象。

## 3. 概念模型（v3）

```
DictType（字典类型 · 定义层）
 ├── code / name / category(ENUM|LIST|CASCADE)
 ├── valueType + valueRegex   ── SAP Domain：值的技术形状
 ├── enumClass                ── category=ENUM 绑定 Java 枚举
 ├── codeSegments             ── 可选：由编码前缀推导层级（GB/T 2260）
 ├── builtin / editable / maxDepth
 ├── items        ──► DictItem（值 · 扁平，不含父指针）
 │                     ├── code / label / value
 │                     ├── effectiveFrom / effectiveTo   时间有效性
 │                     ├── externalCode                  外部标准码
 │                     ├── enumName / tagType / i18nKey / isDefault / sort / status
 │                     ├── texts   ──► DictItemText(code, language, label)   多语言
 │                     └── hierarchies ──► DictHierarchy(hierarchyCode, parentCode, path, level)
 └── hierarchies  ──► 同一值域可有多套层级视图（DEFAULT / 报表树 / …）
```

**不变量**
- 值是扁平的：一个值属于一个值域，**不属于某棵树**。
- 层级是关系：`(hierarchy_code, code)` 唯一 ⇒ 一个值在**同一套层级里**只有一个父，但在**不同层级视图里**可以有不同父（多视图），同一视图内不允许多归属（保持树形，避免环路）。
- `path` 与 `parent_code` 由服务端计算并冗余存储：读树/读子树是前缀匹配（`path LIKE '/GD/%'`），不做递归。

## 4. 数据模型

### 4.1 `sys_dict_type`（字典类型）

在 v2 基础上新增 3 列（`valueType` / `valueRegex` / `codeSegments`）：

| 列 | 说明 |
|---|---|
| `value_type` | `STRING`(默认) / `INT` / `DECIMAL` / `BOOLEAN` —— SAP Domain 的数据类型口径 |
| `value_regex` | 值格式正则（如 `^\d{6}$`）；为空不校验 |
| `code_segments` | 层级编码分段，如 `2,2,2`；非空时导入可按前缀自动推导父级（GB/T 2260 风格） |
| `code / name / category / module_code / enum_class / max_depth / builtin / editable / sort / status / description` | 同 v2 |

### 4.2 `sys_dict_item`（字典项 · **扁平**）

移出 `parent_code`（迁至 `sys_dict_hierarchy`），新增 3 列：

| 列 | 说明 |
|---|---|
| `effective_from` / `effective_to` | 生效区间（Oracle 时间有效性）；为空表示始终生效 |
| `external_code` | 外部标准码（GB/T 2260 / ISO 4217…），仅用于对接，不参与内部引用 |
| `code / label / value / enum_name / tag_type / i18n_key / is_default / sort / status / description` | 同 v2 |

约束：`UNIQUE KEY uk_dict_item (tenant_id, type_code, code)`

### 4.3 `sys_dict_hierarchy`（层级关系 · 新增）

| 列 | 说明 |
|---|---|
| `tenant_id` | 0=平台层级；>0=租户自有/覆盖 |
| `type_code` / `hierarchy_code` | 值域 + 层级视图编码（`DEFAULT` 为默认视图） |
| `code` | 子节点编码（引用 `sys_dict_item.code`） |
| `parent_code` | 父节点编码，`NULL`=根 |
| `path` | 物化路径 `/GD/GZ/`，子树查询按前缀匹配 |
| `level` | 深度（根=1），供 `max_depth` 校验与前端缩进 |
| `sort` | 同级排序 |

约束：
- `UNIQUE KEY uk_dict_hierarchy (tenant_id, type_code, hierarchy_code, code)` —— 保证同一视图内是**树**而非图
- `KEY idx_dict_hierarchy_parent (tenant_id, type_code, hierarchy_code, parent_code)`
- `KEY idx_dict_hierarchy_path (tenant_id, type_code, hierarchy_code, path)`

### 4.4 `sys_dict_item_text`（多语言译文 · 新增）

| 列 | 说明 |
|---|---|
| `type_code` / `code` | 指向字典项 |
| `language` | `zh-CN` / `en-US` … |
| `label` / `description` | 该语言下的显示名与说明 |

约束：`UNIQUE KEY uk_dict_item_text (tenant_id, type_code, code, language)`

### 4.5 租户模型（沿用 v2）

```
平台字典   tenant_id = 0    全租户可见，builtin=1，禁删
租户覆盖   tenant_id = T    与平台项同 (type_code, code) 时租户行胜出
租户自有   tenant_id = T    平台无同 code 类型
```

读取合并算法：平台行 + 租户行 → 按 `code` 用租户行覆盖 → 过滤 `status=1` 与「当前时间落在生效区间内」→ 按 `sort` 升序。
**不变量**：删除租户覆盖项只会「回落到平台项」，不会让值域缺项。

### 4.6 实体落位

- `SysDictType` / `SysDictItem` / `SysDictHierarchy` / `SysDictItemText` 均继承 `TenantAggregateRoot<Long>`（HC-008）。
- 持久化唯一通道 `bone-metadata-sdk`（HC-001）：仓储只写接口 + `default` 方法。
- 全租户入口按 E-4.4 命名 `*AllTenants`，并在 `ArchitectureTest` 登记调用方 `DictApplicationService`。

## 5. 关键能力设计

### 5.1 可插拔层级（替代 v2 的内联父指针）

- 写入：新建/移动项时写 `sys_dict_hierarchy`（`hierarchy_code` 缺省 `DEFAULT`）。
- 环检测：沿 `path` 判断——若目标父节点的 `path` 以 `/<自身 code>/` 开头即拒绝（`SYS_DICT_CYCLE_DETECTED`）。
- 深度：`level(父) + 1 > max_depth` 即拒绝（`SYS_DICT_CASCADE_DEPTH_EXCEEDED`）。
- 删除保护：某层级视图内存在子节点则拒绝删项（`SYS_DICT_ITEM_HAS_CHILDREN`），先删叶子。
- 子树查询：`path LIKE '{parentPath}%'` 一次命中，不做递归/CTE。
- 多视图：`GET /dict/types/{code}/hierarchies` 列出该值域全部层级视图；`GET /dict/items/tree?typeCode=&hierarchyCode=` 取指定视图的树。
- **兼容**：默认视图 `DEFAULT` 的行为与 v2 完全一致，前端不传 `hierarchyCode` 时无需感知。

### 5.2 编码分段推导层级（GB/T 2260 风格）

类型配置 `code_segments = "2,2,2"` 后，导入/新建时若未显式指定父级，按编码前缀推导：
`440100` → 父 `440000`；`440000`（前缀为空）→ 根。
推导失败（父编码不存在）时不阻断导入，记为「待补层级」，由人工点选父级补齐——**编码规则是提示不是硬约束**，避免一批数据因个别脏码整批失败。

### 5.3 时间有效性（Oracle）

- `effective_from` / `effective_to` 可空；为空的一端表示不限。
- 读侧（`/options`、树、分页）默认只返回**当前有效**项；管理端列表默认显示全部并标注「未生效 / 已过期」。
- 写入校验 `from <= to`，否则 `SYS_DICT_EFFECTIVE_RANGE_INVALID`。

### 5.4 多语言（SAP 文本表 / Oracle _TL）

- 值本身语言无关；译文落在 `sys_dict_item_text`，按 `(code, language)` 唯一。
- `/options?lang=zh-CN` 命中译文即用译文标签，未命中回退 `label`。
- 与 `i18n_key` 分工：前者服务服务端下发的运营可编辑文案，后者服务前端静态语言包。

### 5.5 值类型与格式校验（SAP Domain）

- 类型上定义 `value_type`（STRING/INT/DECIMAL/BOOLEAN）+ `value_regex`。
- 项写入时校验 `value`：类型不符或正则不匹配 → `SYS_DICT_VALUE_INVALID`。
- 前端据此选择控件口径（数值/布尔/文本），不再每个页面各写一遍。

### 5.6 枚举绑定（ENUM）

- 类型登记 `enum_class`；同步时反射枚举常量生成/刷新项：`code = name()`、`value = ordinal()`。
- **同步幂等**：只补缺失项、刷新 `value`，不覆盖人工润色的 `label`。
- **漂移检查** `/enum-diff` 返回 `missingInDict` / `missingInEnum`（代码已删而字典未清，危险）/ `valueDrift`。
- 反射走 `domain/service/DictEnumScanner` 端口，`infrastructure` 提供实现（限制 `com.bone.*`，防任意类加载）。

### 5.7 内置保护、缓存、导入导出

- `builtin=1`：禁删、禁改 `code`；`editable=0`：项对租户只读。
- 缓存：`DictOptionsCache`（`ConcurrentHashMap`，按 `(tenantId, typeCode, parentCode, lang)` 键，写操作按类型失效）。不引 Caffeine/Spring Cache——字典量级千级，避免为支撑域引入依赖（L3）。
- 导入导出：快照含 `type + items + hierarchies + texts`；导入按 `code` upsert，单批上限 1000。

## 6. API 设计

基础路径 `/api/v1/system/dict`。

### 6.1 字典类型 `/types`

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| POST/PUT/DELETE | `/types`、`/types/{id}` | 类型增删改（内置仅允许改运营态字段） | write |
| GET | `/types/page` | 分页（keyword/category/moduleCode/status） | 开放 |
| GET | `/types/{code}` | 按编码读取 | 开放 |
| GET | `/types/{code}/hierarchies` | 该值域的层级视图清单 | 开放 |
| GET/POST | `/types/{code}/enum-diff`、`/types/{code}/enum-sync` | 漂移检查 / 同步 | read / write |
| GET/POST | `/types/{code}/export`、`/types/{code}/import` | 导出 / 导入快照 | 开放 / write |

### 6.2 字典项 `/items`

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| POST | `/items` | 新建项（可带 `parentCode` + `hierarchyCode`） | write |
| PUT/DELETE | `/items/{id}` | 更新 / 删除（有子节点拒绝） | write |
| PUT | `/items/{id}/move` | 换父级 / 调排序（含环与深度校验） | write |
| PUT | `/items/{id}/default` | 设为默认项 | write |
| GET | `/items/page` | 分页（typeCode/parentCode/keyword/status） | 开放 |
| GET | `/items/tree?typeCode=&hierarchyCode=` | 指定层级视图的树 | 开放 |
| GET | `/items/{typeCode}/{code}` | 按业务键读取 | 开放 |
| GET/PUT | `/items/{typeCode}/{code}/texts` | 多语言译文读写 | 开放 / write |
| GET | `/options?type=&parent=&lang=` | **下拉数据源**（合并 + 生效过滤 + 本地化 + 缓存） | 开放 |

> 读接口不加 `@PreAuthorize`：权限目录只登记了 `sys:dict:write`，挂未登记的读码会让全平台消费方 403（同 `ConfigController` 现状，多租户方案 §F2 已记录欠账）。

## 9. 前端设计

- **字典管理页**：左侧类型列表（搜索 / 分类筛选）→ 右侧项管理。
  - 顶部「层级视图」选择器（来自 `/hierarchies`），CASCADE 值域切换视图即切换树。
