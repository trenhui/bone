> **DDL**：`meta_*` 五表见 [`bone-init.sql`](../../../bone-init.sql) §4 · [数据库开发规范.md](../../architecture/数据库开发规范.md)

## 0. 实现映射（产品能力包）

| 能力 | 模块 | As-Is |
|------|------|-------|
| 平台持久化、扩展字段 EAV | `bone-metadata-sdk` | ✅ 全平台 |
| 扩展字段集中 REST | `bone-metadata-server` :9001 | ✅ `/v1/metadata/fields:*` |
| 规则 / 表达式 / SmartQL | `bone-metadata-engine` | ⚠️ 未接平台 |
| 业务实体 `meta_*` 建模 API | 管理面 + SDK 持久化 | 🔶 DDL 在 init；REST **[Vision]** |
| 代码生成 / 模板 | `studio-generator`、`bone-codegen` | 🔶 见 [§8](./8.Studio%20Generator%20详细设计方案.md) |
| 建模 UI | `bone-metadata-app` :3004 | 🔶 与后端未完全对齐 |

**协作原则**：引擎 **不替代** 代码生成（DDD 源码交付）；SDK **不** 等同于控制台全套建模 API。详见 [元数据能力-实现映射与竞品对照.md](./元数据能力-实现映射与竞品对照.md) §3。

**术语**：**扩展字段 EAV**（server `/v1/metadata/fields:*`）与 **建模字段 `meta_field`**（catalog）不同，见对照文档 **§1.1**。与 **bone-masterdata** 边界见对照文档 **§8**。

## 1. 模块概述

元数据管理是 BONE **应用生成**能力的产品模块，涵盖业务建模、扩展字段、智能规则与代码生成；工程上由 **sdk + server + engine + generator + 前端** 协作实现（非单一 `bone-metadata-server` Jar）。

**核心目标**：
- 提供可视化的业务实体建模能力
- 支持实体字段和关系的管理
- 实现基于元数据的代码自动生成
- 支持代码模板的管理和定制
- 提供实体版本管理和变更追踪

## 2. 功能设计

> 下列 §2.1～§2.3 为 **产品目标态**；实现落点见 §0 与 [实现映射文档](./元数据能力-实现映射与竞品对照.md) §7。

### 2.1 业务实体管理 **[Vision · 主责 meta_* + 管理 API]**

**功能描述**：支持业务实体的创建、编辑、删除和发布，管理实体的字段和关系。

**详细功能**：
- **实体创建**：创建业务实体，设置名称、描述、类型等基本信息
- **字段管理**：添加、编辑、删除实体字段，设置字段类型、长度、约束等
- **关系管理**：定义实体之间的关系，支持一对一、一对多、多对多关系
- **验证规则**：为字段添加验证规则，如必填、唯一、格式验证等
- **实体版本**：管理实体的版本历史，支持版本对比和回滚
- **实体发布**：将实体从草稿状态发布为可用状态

**用户故事**：
> 作为开发人员，我希望创建业务实体并定义字段和关系，以便快速构建业务模型。

### 2.2 代码生成 **[Hybrid · 主责 studio-generator]**

**功能描述**：基于业务实体自动生成前后端代码，支持多种模板和生成配置。

**详细功能**：
- **模板选择**：选择代码生成模板，如 React+Spring Boot、Vue+Spring Boot 等
- **生成配置**：设置代码生成的配置参数，如包名、模块名等
- **代码预览**：预览生成的代码结构和内容
- **批量生成**：支持多个实体的批量代码生成
- **生成历史**：查看代码生成的历史记录
- **异步生成**：支持异步生成代码，通过 WebSocket 推送进度

**用户故事**：
> 作为开发人员，我希望基于业务实体生成前后端代码，支持多种模板，以减少重复编码工作。

### 2.3 模板管理 **[Vision · 与 §2.2 / generator 协同]**

**功能描述**：管理代码生成模板，支持模板的创建、编辑、发布和版本管理。

**详细功能**：
- **模板创建**：创建新的代码生成模板
- **模板编辑**：编辑模板内容，支持 FreeMarker 语法
- **模板预览**：预览模板渲染效果
- **模板发布**：将模板从草稿状态发布为可用状态
- **模板版本**：管理模板的版本历史
- **模板导入导出**：支持模板的导入和导出

**用户故事**：
> 作为开发人员，我希望管理代码生成模板，支持自定义模板，以满足不同项目的需求。

### 3.3 关键实现

#### 3.3.1 业务实体管理

```java
package com.bone.metadata.application.command.handler;

import com.bone.metadata.application.command.cmd.CreateEntityCmd;
import com.bone.metadata.domain.model.entity.Entity;
import com.bone.metadata.domain.model.entity.vo.EntityName;
import com.bone.metadata.domain.repository.EntityRepository;
import com.bone.metadata.common.exception.BusinessException;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Component;
import org.springframework.transaction.annotation.Transactional;

@Component
@RequiredArgsConstructor
public class CreateEntityHandler {
    private final EntityRepository entityRepository;
    
    @Transactional
    public Long handle(CreateEntityCmd cmd) {
        EntityName entityName = new EntityName(cmd.getName());
        
        // 检查实体名称是否已存在
        if (entityRepository.existsByName(cmd.getName())) {
            throw new BusinessException("实体名称已存在");
        }
        
        Entity entity = Entity.create(
            entityName,
            cmd.getDescription(),
            cmd.getType()
        );
        
        entityRepository.save(entity);
        
        return entity.getId().getValue();
    }
}
```

#### 3.3.2 代码生成

```java
package com.bone.metadata.application.command.handler;

import com.bone.metadata.application.command.cmd.GenerateCodeCmd;
import com.bone.metadata.domain.model.codegen.CodeGeneration;
import com.bone.metadata.domain.model.codegen.Template;
import com.bone.metadata.domain.repository.CodeGenerationRepository;
import com.bone.metadata.domain.repository.EntityRepository;
import com.bone.metadata.domain.repository.TemplateRepository;
import com.bone.metadata.common.exception.BusinessException;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Component;
import org.springframework.transaction.annotation.Transactional;

@Component
@RequiredArgsConstructor
public class GenerateCodeHandler {
    private final CodeGenerationRepository codeGenerationRepository;
    private final EntityRepository entityRepository;
    private final TemplateRepository templateRepository;
    
    @Transactional
    public Long handle(GenerateCodeCmd cmd) {
        // 验证实体存在
        var entity = entityRepository.findById(cmd.getEntityId())
                .orElseThrow(() -> new BusinessException("实体不存在"));
        
        // 验证模板存在
        Template template = templateRepository.findById(cmd.getTemplateId())
                .orElseThrow(() -> new BusinessException("模板不存在"));
        
        // 创建代码生成任务
        CodeGeneration task = CodeGeneration.create(
            entity.getId(),
            template.getId(),
            cmd.getConfig()
        );
        
        codeGenerationRepository.save(task);
        
        // 异步处理代码生成
        // TODO: 发送消息到消息队列
        
        return task.getId().getValue();
    }
}
```

#### 3.3.3 模板管理

```java
package com.bone.metadata.application.command.handler;

import com.bone.metadata.application.command.cmd.CreateTemplateCmd;
import com.bone.metadata.domain.model.codegen.Template;
import com.bone.metadata.domain.model.codegen.vo.TemplateName;
import com.bone.metadata.domain.model.codegen.vo.TemplateType;
import com.bone.metadata.domain.repository.TemplateRepository;
import com.bone.metadata.common.exception.BusinessException;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Component;
import org.springframework.transaction.annotation.Transactional;

@Component
@RequiredArgsConstructor
public class CreateTemplateHandler {
    private final TemplateRepository templateRepository;
    
    @Transactional
    public Long handle(CreateTemplateCmd cmd) {
        TemplateName templateName = new TemplateName(cmd.getName());
        TemplateType templateType = new TemplateType(cmd.getType());
        
        // 检查模板名称是否已存在
        if (templateRepository.existsByName(cmd.getName())) {
            throw new BusinessException("模板名称已存在");
        }
        
        Template template = Template.create(
            templateName,
            templateType,
            cmd.getContent()
        );
        
        templateRepository.save(template);
        
        return template.getId().getValue();
    }
}
```

## 7. 性能与安全

### 7.1 性能优化

- **缓存策略**：使用 Redis 缓存元数据和模板，减少数据库查询
- **异步处理**：代码生成任务异步执行，避免阻塞主线程
- **批处理**：批量操作实体和字段，减少数据库操作次数
- **索引优化**：为常用查询字段创建索引
- **模板预编译**：预编译 FreeMarker 模板，提高渲染速度

### 7.2 安全措施

- **权限控制**：基于 RBAC 的细粒度权限控制
- **数据验证**：严格的输入验证，防止注入攻击
- **代码安全**：生成的代码包含安全最佳实践
- **审计日志**：记录所有元数据操作，支持审计追踪
- **模板安全**：模板内容安全检查，防止恶意代码注入

## 10. 微服务与Java工程结构

### 10.1 微服务设计

> **[Vision]** 目标态「元数据管理」微服务职责；**As-Is** 见 [元数据能力-实现映射与竞品对照.md](./元数据能力-实现映射与竞品对照.md) §2～§5。

**微服务名称（规划）**：metadata-service

**服务职责（目标态全集）**：
- 业务实体建模和管理 → **[Vision]**，持久化走 **bone-metadata-sdk**
- 扩展字段元数据 API → **As-Is**：**bone-metadata-server**（`:9001`，`/v1/metadata/fields:*`）
- 代码模板与代码生成 → **studio-generator** / **bone-codegen**，非 server 主责
- 规则 / 表达式 / SmartQL → **bone-metadata-engine**（可选嵌入宿主）

**API 前缀（规划）**：`/api/v1/metadata`（实体/生成等）；**已实现**扩展字段 API 为 `/v1/metadata/fields:*`。

**端口（As-Is）**：扩展字段服务 **9001**（`bone-metadata-server`）。历史 8084/8082 已废止；[wiki/03](../../wiki/03-本地开发与构建.md)。

### 10.5 与其他微服务集成

**服务依赖**：

- **file-service**：用于存储生成的代码文件
- **admin-service**：用于提供系统概览数据

**集成方式**：
- **Gateway**：通过 `domain/gateway/` 目录下的网关接口调用其他微服务
- **消息队列**：通过领域事件机制接收其他服务的事件
- **共享缓存**：通过Redis共享跨服务数据
- **API网关**：通过API网关统一调用其他微服务

**集成流程**：
1. **权限验证**：调用authz-service进行用户认证和权限检查
2. **文件存储**：调用file-service存储生成的代码文件
3. **数据同步**：通过消息队列向admin-service发送元数据更新事件
4. **服务发现**：通过Nacos服务发现机制找到其他微服务

## 11. 总结

元数据管理是 BONE **应用生成**的产品能力包：目标态含可视化建模、模板与生成；**As-Is** 已落地扩展字段（sdk + server :9001）与全平台持久化，实体 REST / 生成闭环与 **engine** 接入仍在演进。定义与竞品路线见 [元数据能力-实现映射与竞品对照.md](./元数据能力-实现映射与竞品对照.md)。

**关键成功因素**：
- 清晰的三层分工：**数据面（sdk）· 控制面（server）· 计算面（engine）** + **生成（generator）**
- 灵活、直观的实体建模界面（Vision）
- 高效、可靠的代码生成能力（generator + 模板）
- 混合路线：引擎管运行时规则，生成管 DDD 可交付源码

**符合规范**：
- 遵循《Bone-DDD》分层与 CQRS Handler 约定
- 应用层以 CommandHandler / QueryHandler 为入口（《Bone-DDD》§14、§20）
- 采用六边形架构，依赖方向正确
- 领域层纯净，仅使用 `@Getter` 和私有构造器
- 仓储接口为空接口，继承 `bone-metadata-sdk` 的 `Repository`
- 数据库表结构符合数据库规范，包含完整的中文注释
- 命名规范符合最新标准
- 集成AI能力定义（@Capability）
- 提供扩展点机制（Calculator命名）
