## 1. Maven 模块（真相源：`bone-engine/bone-metadata-engine/pom.xml`）

> **物理拆分已完成（change `metadata-engine-deep-refactor`，2026-08-26）**：原 `bone-metadata-engine-core` 已删除，源码按 DDD 边界分配到 4 个 Maven 子模块。

| 模块 | Artifact | 包前缀 | 说明 |
|------|----------|--------|------|
| 领域 | `bone-metadata-engine-domain` | `com.bone.metadata.engine.domain.*` | 纯净领域模型与算法（零 Spring/SDK），含 `model`/`metadata`/`core`/`common`/`annotation`/`exception`/`multi`/`impact` |

依赖方向：`domain ← ports ← runtime ← starter`，由各模块 `ArchitectureTest` 固化。

## 2. 根包与分层思想

引擎源码根包（已按 4 模块拆分，见 §1）：

- `domain`（`com.bone.metadata.engine.domain.*`）：实体、字段、操作、工作流等元数据定义与注册表抽象、规则结果、动态实体模型（`model`/`metadata`/`core`/`common`/`annotation`/`exception`/`multi`/`impact`）。
- `ports`（`com.bone.metadata.engine.ports.*`）：读侧端口 `MetadataRepositoryPort`、平台桥接 `MetadataPlatformBridge`、注册表与仓储接口，仅依赖 domain。
- `runtime`（`com.bone.metadata.engine.runtime.*`）：
  - `adapter`：`SdkMetadataRepository`（基于 `bone-metadata-sdk` 的 `Repository<MetaEntityPo, Long>` 读已发布 `meta_entity`/`meta_field`）、`MetaEntityConverter`（防腐层 ACL）、`IamMetadataBridge`（`currentTenantId()` 接 `TenantContext`、`publishEvent()` 接 `ApplicationEventPublisher`）、`InMemoryMetadataRepositoryPort`（内存回退）。
  - 根包引擎类：`MetadataEngine`、`ExpressionEngine`、`RuleEngine`、`ValidationEngine`、`DefaultBusinessRuleEngine` 等。
  - `service`/`query`/`rule`/`expression`/`validation`/`security`/`cache`/`util`/`context`/`event`/`analysis`/`version`/`repository` 实现。
  - 数据面 `runtime.*`：`JdbcRuntimeRecordService`（模式 B 动态行读写，由宿主如 `bone-metadata-server` 装配）。
- `starter`（`com.bone.metadata.engine.starter.*`）：`config`/`autoconfigure`/`platform` Spring 装配（`MetadataEngineAutoConfiguration` 等）。

**依赖建议（阅读代码时）**：从 `MetadataEngine`、`GenericOperationService`、`DynamicDataService` 入口向下追踪，比死记虚构包树更有效。

### 2.1 边界固化（change `metadata-engine-deep-refactor`，物理拆分完成）

按 DDD 端口-适配器物理拆 4 模块，依赖方向：`domain（零依赖）← ports（仅接口，依赖 domain）← runtime（依赖 domain+ports+SDK/Spring）← starter（依赖 runtime，Spring 装配）`：

- **`ports.spi`**：`MetadataRepositoryPort`（读侧契约）、`MetadataPlatformBridge`（租户/事件/已发布实体加载）。**零 `org.springframework.*` / `com.bone.metadata.sdk.*` 依赖**。
- **`runtime.adapter`**：`SdkMetadataRepository`、`MetaEntityConverter`（防腐层 ACL）、`IamMetadataBridge`、`InMemoryMetadataRepositoryPort`。
- 各模块 `ArchitectureTest` 固化依赖方向（domain 不依赖外层 / ports 不依赖 runtime/starter / runtime 不依赖 starter）。

## 3. 子包职责速查（与当前目录一致）

下列为按模块划分的常见子包及职责摘要（随版本演进以 `bone-engine/bone-metadata-engine/` 下各模块源码为准）：

| 模块 / 子包 | 职责摘要 |
|------|----------|
| `domain.metadata` | 元数据定义类、操作与工作流元数据、处理器协作 |
| `domain.model` | 注册表模型、动态实体、规则结果等运行期模型 |
| `domain.annotation` | 实体/字段/规则等注解与类型枚举 |
| `domain.exception` / `domain.common` | 异常体系与公共常量 |
| `domain.impact` | 影响分析领域模型 |
| `ports.spi` | 端口（ports）：`MetadataRepositoryPort` / `MetadataPlatformBridge`，仅接口，零 spring/sdk 依赖 |
| `ports.registry` / `ports.repository` | 注册表与仓储接口 |
| `runtime.adapter` | 运行时：`SdkMetadataRepository` / `IamMetadataBridge` / `MetaEntityConverter` / `InMemoryMetadataRepositoryPort`（防腐层 ACL） |
| `runtime.service` / `service.impl` | 通用操作、动态数据、规则引擎实现等 |
| `runtime.query` / `query.ast` | SmartQL、AST、SQL 生成、执行与缓存 |
| `runtime.expression` | 表达式求值 |
| `runtime.validation` / `validation.strategy` | 元数据与字段校验策略 |
| `runtime.rule` | 规则注册、求值上下文工厂等 |
| `runtime.security` | 权限、字段级安全、脱敏等 |
| `runtime.cache` | 元数据缓存与统计 |
| `runtime.metadata` / `metadata.processor` | 元数据变更事件、注册表与处理器协作（Spring 实现） |
| `runtime.context` / `event` | 用户上下文、元数据变更事件发布实现 |
| `runtime.util` / `analysis` / `version` | 工具、影响分析、版本控制等横切能力 |
| `runtime.repository` | 仓储实现（含 `InMemoryMetadataRepository`） |
| `starter.config` / `autoconfigure` / `platform` | 自动配置与引擎初始化、平台桥接 Bean |
