# 控制台与仪表盘模块详细设计方案

## 1. 模块概述

控制台与仪表盘模块是 BONE 平台的统一入口，提供系统概览、快速导航和关键指标展示功能，帮助用户快速了解系统运行状态和执行常用操作。

**核心目标**：
- 提供系统健康状态实时监控
- 展示关键业务指标
- 提供常用功能的快速入口
- 支持用户待办事项管理
- 实现定制化仪表板

## 2. 功能设计

### 2.1 系统概览

**功能描述**：展示 BONE 平台监控指标、框架相关指标和最近操作记录。

**详细功能**：
- **BONE 监控指标**：实体创建数量、代码生成次数、集成流程执行次数、插件部署数量等平台核心指标
- **框架相关指标**：API 响应时间、错误率、QPS、服务调用次数等框架运行指标
- **最近操作记录**：用户登录、实体创建、代码生成、流程执行等操作的时间线
- **实时数据更新**：支持自动刷新（默认 30 秒）和手动刷新

**用户故事**：
> 作为系统管理员，我希望查看 BONE 平台监控指标、框架相关指标和最近操作，以便快速了解系统运行情况。

### 2.2 快速入口

**功能描述**：提供常用功能的快速导航入口，支持自定义配置。

**详细功能**：
- **功能快捷方式**：创建实体、生成代码、设计流程、管理用户等常用功能
- **待办事项**：审批任务、待处理的质量问题、系统告警等
- **自定义配置**：支持拖拽排序、添加/移除快捷方式
- **智能推荐**：根据用户角色和使用频率推荐常用功能

**用户故事**：
> 作为用户，我希望通过快速入口访问常用功能，查看待办事项，以提高工作效率。

### 2.3 定制化仪表板

**功能描述**：允许用户创建和定制个人或团队仪表板。

**详细功能**：
- **仪表板创建**：支持创建多个仪表板，用于不同场景
- ** widget 添加**：支持添加各种类型的 widget，如图表、列表、指标卡等
- **数据来源**：支持从系统各模块获取数据
- **布局管理**：支持拖拽调整 widget 位置和大小
- **权限控制**：支持设置仪表板的查看和编辑权限

**用户故事**：
> 作为业务分析师，我希望创建自定义仪表板，展示与我工作相关的关键指标，以便快速了解业务状态。

#### 3.3.1 BONE 指标收集

```java
@Service
public class MetricsService {
    
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    
    @Autowired
    private EntityRepository entityRepository;
    
    @Autowired
    private CodeGenerationRepository codeGenerationRepository;
    
    @Autowired
    private IntegrationFlowRepository integrationFlowRepository;
    
    @Autowired
    private PluginRepository pluginRepository;
    
    @Autowired
    private ApiMetricsRepository apiMetricsRepository;
    
    public BoneMetrics getBoneMetrics() {
        BoneMetrics metrics = new BoneMetrics();
        
        // 收集 BONE 监控指标
        metrics.setEntityCount(entityRepository.count());
        metrics.setCodeGenerationCount(codeGenerationRepository.countToday());
        metrics.setIntegrationFlowCount(integrationFlowRepository.countExecutionsToday());
        metrics.setPluginCount(pluginRepository.countDeployed());
        
        // 收集框架相关指标
        metrics.setApiResponseTime(apiMetricsRepository.getAverageResponseTime());
        metrics.setApiErrorRate(apiMetricsRepository.getErrorRate());
        metrics.setApiQps(apiMetricsRepository.getQps());
        metrics.setServiceCallCount(apiMetricsRepository.getServiceCallCount());
        
        return metrics;
    }
    
    // 其他方法...
}
```

#### 3.3.2 实时数据更新

```javascript
// 前端实时数据更新
const useBoneMetrics = () => {
  const [metrics, setMetrics] = useState({});
  const [loading, setLoading] = useState(true);
  
  useEffect(() => {
    const fetchMetrics = async () => {
      try {
        const response = await axios.get('/api/dashboard/metrics');
        setMetrics(response.data);
      } catch (error) {
        console.error('Failed to fetch metrics:', error);
      } finally {
        setLoading(false);
      }
    };
    
    fetchMetrics();
    const interval = setInterval(fetchMetrics, 30000); // 30秒刷新一次
    
    return () => clearInterval(interval);
  }, []);
  
  return { metrics, loading };
};
```

#### 3.3.3 仪表板配置管理

```java
@Service
public class DashboardService {
    
    @Autowired
    private DashboardRepository dashboardRepository;
    
    @Autowired
    private WidgetRepository widgetRepository;
    
    public Dashboard createDashboard(DashboardCreateRequest request) {
        Dashboard dashboard = new Dashboard();
        dashboard.setName(request.getName());
        dashboard.setDescription(request.getDescription());
        dashboard.setUserId(request.getUserId());
        dashboard.setIsPublic(request.isPublic());
        
        return dashboardRepository.save(dashboard);
    }
    
    public void addWidget(Long dashboardId, WidgetCreateRequest request) {
        Widget widget = new Widget();
        widget.setDashboardId(dashboardId);
        widget.setTitle(request.getTitle());
        widget.setType(request.getType());
        widget.setConfig(request.getConfig());
        widget.setPositionX(request.getPositionX());
        widget.setPositionY(request.getPositionY());
        widget.setWidth(request.getWidth());
        widget.setHeight(request.getHeight());
        
        widgetRepository.save(widget);
    }

}
```

## 6. 部署与集成

### 6.1 部署方式

- **容器化部署**：使用 Docker 容器部署，通过 Kubernetes 进行编排
- **资源需求**：
  - CPU：1 核
  - 内存：1GB
  - 存储：10GB

### 6.2 集成点

- **与监控系统集成**：从 Prometheus 获取系统指标
- **与业务系统集成**：从各业务模块获取业务指标
- **与认证系统集成**：使用 IAM 服务进行权限控制
- **与配置系统集成**：通过 Nacos 管理配置

### 6.3 配置项

| 配置项 | 类型 | 默认值 | 描述 |
|--------|------|--------|------|
| `dashboard.metrics.refresh.interval` | Integer | 30 | 指标刷新间隔（秒） |
| `dashboard.operations.max.count` | Integer | 50 | 最近操作记录最大数量 |
| `dashboard.widgets.max.per.dashboard` | Integer | 20 | 每个仪表板最大组件数 |
| `dashboard.quick.access.max.count` | Integer | 8 | 快速入口最大数量 |
| `dashboard.todo.max.count` | Integer | 10 | 待办事项最大数量 |

## 7. 性能与安全

### 7.1 性能优化

- **缓存策略**：使用 Redis 缓存系统和业务指标，减少数据库查询
- **异步处理**：指标收集和更新采用异步方式，避免阻塞主线程
- **数据聚合**：对历史数据进行聚合存储，减少存储和查询压力
- **前端优化**：使用 React.memo、useMemo 等优化渲染性能

### 7.2 安全措施

- **权限控制**：基于 RBAC 的细粒度权限控制
- **数据脱敏**：敏感操作记录中的敏感信息脱敏处理
- **审计日志**：记录所有仪表板操作，支持审计追踪
- **XSS 防护**：对用户输入进行过滤和转义
- **CSRF 防护**：使用 CSRF token 保护 API

  - 仪表板加载失败

### 10.4 与其他微服务集成

**服务依赖**：
- **authz-service**：用于权限验证和用户认证
- **metadata-service**：获取元数据相关指标
- **integration-service**：获取集成流程相关指标
- **extension-service**：获取插件相关指标

**集成方式**：
- **Feign客户端**：通过 `infrastructure/client/` 目录下的客户端类调用其他微服务
- **消息队列**：通过领域事件机制接收其他服务的事件
- **共享缓存**：通过Redis共享跨服务数据
- **API网关**：通过API网关统一调用其他微服务

**集成流程**：
1. **权限验证**：调用authz-service进行用户认证和权限检查
2. **指标收集**：调用metadata-service、integration-service和extension-service获取相关指标
3. **数据同步**：通过消息队列接收其他服务的事件，更新本地缓存
4. **服务发现**：通过Nacos服务发现机制找到其他微服务

- 快速、便捷的功能导航
