# 控制台与仪表盘模块详细设计方案

> **范围声明（务实定位）**：本模块当前阶段是「**平台首页 + 概览聚合**（Dashboard Aggregator MVP）」，**不是**完整的"可配置仪表盘产品"。可配置 Widget、AI 布局、独立服务等均为 **[Vision]**。
>
> **仓库对照（As-Is）**：无独立 `bone-console` 服务；**`bone-system`** 提供 `/api/v1/console/*`，**`bone-shell`** 首页对接概览与快捷操作（30s 刷新）。  
> **HTTP 真源（唯一）**：[`bone-platform/bone-system/.../adapter/web/controller/ConsoleController.java`](../../../bone-platform/bone-system/src/main/java/com/bone/system/adapter/web/controller/ConsoleController.java)（路径常量 `PlatformApiPaths.CONSOLE_V1`）。`bone-iam` 历史副本已删除（v2.0）。  
> **DDL（占位）**：[`bone-init.sql`](../../../bone-init.sql) **§7** 含 **`cnsl_*`** 三表，但运行时未对接（见 §4 DDL-only 标注）。  
> **权限码（真源）**：`sys:console:read`（DDL `id=18`、`DefaultPermissionCodes.ADMIN_FALLBACK`、`bonePermissionCodes.SYS_CONSOLE_READ`）。  
> **错误码前缀**：`SYS_`（控制台聚合归属系统域）。

## 1. 模块概述

控制台与仪表盘模块是 BONE 平台的核心入口，负责系统概览、数据可视化、快速导航和操作中心，为用户提供直观的系统状态展示和快捷操作入口。

**核心目标**：
- 提供系统全局概览和健康状态监控
- 展示关键业务指标和数据趋势
- 提供快速导航和常用操作入口
- 支持自定义仪表盘和数据展示
- 实现多租户隔离的数据视图

## 2. 功能设计

> 所有子节均按**最终能力**描述，在标题加 **[As-Is] / [Target] / [Vision]** 标记表达交付阶段；详见 §1.4 能力矩阵。

### 2.1 系统概览 **[As-Is + Target]**

**功能描述**：展示系统的整体运行状态和健康情况，包括服务状态、资源使用、关键指标等。

**详细功能**：
- **[As-Is]** **服务健康状态**：本进程 Actuator `UP/DOWN`；远端服务返回 `UNKNOWN`。**[Target]** 接入服务注册中心后给真探活与响应时间、错误率。
- **[As-Is]** **资源使用情况**：JVM 堆 `memory.used / memory.max`。**[Target]** CPU / 磁盘占用，对接 `node_exporter` 或 Spring `OperatingSystemMXBean`。
- **[As-Is]** **关键业务指标**：`iam_account / meta_entity / int_flow / exts_plugin_version` 的 `COUNT`；单表查询失败容错为 0（graceful degradation）。**[Target]** 订单数、交易金额等业务侧指标。
- **[Target]** **系统告警**：`alerts[]` 占位为空；待接入 `sys_alert_event` 表与 `AlertController`（已存在）。
- **[As-Is]** **快速导航**：6 个固定入口（iam / metadata / masterdata / integration / system / extension）。**[Target]** 按租户/角色过滤后改 `cnsl_quick_action` 表驱动。

**用户故事**：
> 作为系统管理员，我希望通过系统概览了解系统的整体运行状态，以便及时发现和解决问题。

### 2.2 数据仪表盘 **[Vision]**

**功能描述**：提供可自定义的数据可视化仪表盘，支持多种图表类型和数据来源。**当前阶段未实现**，详设示例代码（§10.4 / §10.5）为 [Vision] 蓝图。

**[Vision] 功能（不在 MVP）**：
- 折线 / 柱 / 饼 / Gauge 图表
- 从系统指标 / 业务数据 / 外部数据源获取数据
- 拖拽自定义布局；时间范围；导出 PDF/Excel

**用户故事**：
> 作为业务分析师，我希望创建自定义的数据仪表盘，以便直观地分析业务数据和趋势。

### 2.3 快速操作中心 **[As-Is（静态） + Target（表驱动）]**

**功能描述**：提供常用操作的快捷入口，简化用户操作流程。

- **[As-Is]** **常用功能**：与 `bone-shell` 路由对齐的 6 个静态快捷入口（`/iam`、`/metadata`、`/masterdata`、`/integration`、`/system`、`/extension`）。
- **[Target]** **最近操作**：表 `cnsl_recent_access` 已在 DDL 预留，待 `RecentAccessRecorder` 拦截器接入。
- **[Vision]** **快捷命令**（CLI 入口）、**任务管理**（长事务可视化）。

**用户故事**：
> 作为普通用户，我希望通过快速操作中心快速访问常用功能，提高工作效率。

### 2.4 租户管理 **[由 IAM 模块承接]**

> **设计决策（v2.0）**：避免功能重复，租户管理统一归属 **bone-iam**（IAM 详设 §5.6）。本模块不直接提供租户 CRUD；首页只读展示当前租户上下文（来自 JWT claim）。

- **[As-Is]** **当前租户上下文**：通过 IAM `/me` 获取当前用户 tenantId 与名称
- **[Target]** **租户切换**：仅平台超管可见，调用 IAM `/tenants` 列表 + 前端切换 `X-Tenant-Id`
- **租户创建 / 删除 / 配额**：参见 IAM 详设 §5.6 与 `TenantController`（**不在本模块**）

#### 3.3.1 控制台聚合 Controller（thin）

控制台仅暴露 **5 个 GET 端点**，全部委派给 `application.query.handler.*`，零业务逻辑。

```33:73:bone-platform/bone-system/src/main/java/com/bone/system/adapter/web/controller/ConsoleController.java
@Tag(name = "控制台", description = "系统概览、服务状态、资源使用、关键指标、快捷操作")
@RestController
@RequestMapping(PlatformApiPaths.CONSOLE_V1)
@RequiredArgsConstructor
public class ConsoleController {

    private final ConsoleOverviewQueryHandler consoleOverviewQueryHandler;
    private final QuickActionsQueryHandler quickActionsQueryHandler;

    @Operation(summary = "获取系统概览（聚合服务、资源、关键指标）",
```

#### 3.3.2 概览聚合 QueryHandler（CQRS / readOnly）

`ConsoleOverviewQueryHandler` 编排三类 outbound port，单次组装；同时落 Micrometer 计数器 `bone_console_overview_refresh_total`（SLO 真源）。

```26:65:bone-platform/bone-system/src/main/java/com/bone/system/application/query/handler/ConsoleOverviewQueryHandler.java
@Component
@RequiredArgsConstructor
public class ConsoleOverviewQueryHandler {

    private final ServiceHealthGateway serviceHealthGateway;
    private final ResourceUsageGateway resourceUsageGateway;
    private final KeyMetricsGateway keyMetricsGateway;
    private final MeterRegistry meterRegistry;

    @Transactional(readOnly = true)
    public ConsoleOverview handle() {
        meterRegistry.counter("bone_console_overview_refresh_total").increment();
        List<ServiceStatus> services = serviceHealthGateway.listServiceStatuses();
        ResourceUsage usage = resourceUsageGateway.snapshot();
        KeyMetrics metrics = keyMetricsGateway.collect();
        return ConsoleOverview.builder()
                .services(services)
                .resourceUsage(usage)
                .keyMetrics(metrics)
                .alerts(List.of())
                .updatedAt(Instant.now())
                .build();
    }
```

#### 3.3.3 业务指标 Gateway（graceful degradation）

`JdbcKeyMetricsGatewayAdapter` 直接对核心表做 `COUNT`；任一表缺失/异常时该字段计 0，绝不让概览整体失败（业界 Operational Dashboard 标准模式）。

```37:64:bone-platform/bone-system/src/main/java/com/bone/system/infrastructure/gateway/JdbcKeyMetricsGatewayAdapter.java
    @Override
    public KeyMetrics collect() {
        return KeyMetrics.builder()
                .userCount(safeCount("SELECT COUNT(*) FROM iam_account WHERE deleted = 0", "iam_account"))
                .entityCount(safeCount("SELECT COUNT(*) FROM meta_entity WHERE deleted = 0", "meta_entity"))
                .integrationFlowCount(
                        safeCount("SELECT COUNT(*) FROM int_flow WHERE deleted = 0", "int_flow"))
                .extensionPluginCount(safeCount(
                        "SELECT COUNT(*) FROM exts_plugin_version WHERE is_active = 1", "exts_plugin_version"))
                .orderCount(0)
                .transactionAmount(0)
                .jvmThreadsLive((long) gauge("jvm.threads.live"))
                .jvmThreadsDaemon((long) gauge("jvm.threads.daemon"))
                .updatedAt(Instant.now())
                .build();
    }

    private long safeCount(String sql, String tableHint) {
        try {
            Long v = jdbcTemplate.queryForObject(sql, Long.class);
            return v == null ? 0 : v;
        } catch (Exception e) {
            log.debug("[console.keyMetrics] count failed on {}: {}", tableHint, e.getMessage());
            return 0;
        }
    }
```

### 5.0 权限码与鉴权（统一锚点）

> **OpenAPI 契约真源（v2.0）**：[`doc/architecture/openapi/console-v1.yaml`](../../architecture/openapi/console-v1.yaml)（设计侧骨架，与 §5.1 1:1）；运行时 SpringDoc `/api-docs` 由 `ConsoleController` 注解派生，**变更 API 时须同步 yaml**。

| 权限码 | 名称 | 域 | DDL | 前端常量 | 状态 |
|--------|------|----|----|---------|------|
| `sys:console:read` | SYS-控制台查看 | system | `iam_permission.id=18`（[`bone-init.sql`](../../../bone-init.sql)） | `BonePermissionCodes.SYS_CONSOLE_READ` | **As-Is**（已分发） |

**鉴权落地状态**：
- **[As-Is]** OpenAPI / Swagger 描述与 Controller `@Operation` 已锚定 `sys:console:read`；权限码已写入 DDL 并默认绑定到 `SUPER_ADMIN`（详设 §1.4）。
- **[As-Is]** **方法级 `@PreAuthorize("hasAuthority('sys:console:read')")`**：`bone-system` 已引入 `spring-boot-starter-security`，`ConsoleController` 类级注解；`JwtAuthenticationFilter` 解析 IAM 签发的 JWT `scopes` claim → `GrantedAuthority`；未认证 **401**、缺权限 **403**（`ConsoleSecurityTest`）。
- **[As-Is]** **前端路由守卫**：`bone-shell` 首页路由 `<Authorized required={SYS_CONSOLE_READ}>`；`auth/jwt.ts` 解析 token scopes（**无验签**，仅 UX）；`axios` 请求自动附加 `Authorization: Bearer`。
- **[Target]** 网关统一 JWT + RBAC 后，下游可切换为「网关信任」模式，减少各服务重复验签（可选演进）。
- **CI**：`scripts/ci/test-console-security.sh`（`ConsoleSecurityTest`）、`validate-console-openapi.sh`；本地 E2E：`verify-three-modules-e2e.sh`（先 IAM 登录再带 Bearer 调控制台）。

### 10.5 与其他微服务集成

**服务依赖**：
- **bone-iam**：用于权限验证和用户认证（`:8081`）
- **monitoring-service**：用于获取系统监控数据
- **business-services**：用于获取业务指标数据

**集成方式**：
- **Gateway**：通过 `domain/gateway/` 目录下的网关接口调用其他微服务
- **消息队列**：通过领域事件机制接收其他服务的事件
- **共享缓存**：通过Redis共享跨服务数据
- **API网关**：通过API网关统一调用其他微服务

**集成流程**：
1. **权限验证**：经网关调用 **bone-iam** 进行用户认证和权限检查
2. **数据获取**：调用monitoring-service获取系统监控数据
3. **业务数据**：调用business-services获取业务指标数据

## 11. 总结

控制台与仪表盘模块是 BONE 平台的**首页入口与概览聚合层**。**当前阶段（v2.0）定位务实地收口为 "Dashboard Aggregator MVP"**：以最小代价聚合服务健康、JVM 资源、关键业务计数与快捷导航，避免与现有 `bone-system` / `bone-iam` / `bone-extension-studio` 形成功能重叠，并为未来的可配置仪表盘留下 schema（`cnsl_*`）与端口（`/api/v1/console/*`）。

### 11.1 当前能力（As-Is · v2.0）

- 5 个 `GET` 概览端点（overview / services / resources / metrics / quick-actions）
- CQRS handler-only：`ConsoleOverviewQueryHandler` + `QuickActionsQueryHandler`
- 3 个出站端口 + 实现：`ServiceHealth`（Actuator）/ `ResourceUsage`（Micrometer JVM）/ `KeyMetrics`（JdbcTemplate COUNT）
- 关键指标 graceful degradation（单表故障容错为 0）
- 权限码契约 `sys:console:read`（DDL / 后端常量 / 前端常量 三处对齐）
- 方法级 `@PreAuthorize('sys:console:read')` + JWT Filter（与 IAM 同密钥）
- 前端首页 `Authorized` 路由守卫 + axios Bearer 注入
- Micrometer 计数器 `bone_console_overview_refresh_total` 作为 SLO 真源
- Single Source of Truth：仅 `bone-system` 一个 `ConsoleController`

### 11.2 已识别的工程债与 [Target] 路线

按业界 Operational Dashboard 最佳实践分级演进（先信号面、再可配置面、最后产品化）：

| 优先级 | 工程债 / [Target] | 推进路径 |
|-------|-------------------|---------|
| P0 | 远端服务真探活（services 现给 UNKNOWN） | 接入服务注册中心 / Gateway 主动探活 |
| P0 | **prod 分库时 `keyMetrics` 跨表 COUNT 失效**（退化为 0） | `application*.yml` 默认连共享库 `bone`；如运维分库需改 Gateway/Feign 调各服务只读 API 聚合 |
| P1 | CPU / 磁盘指标 | 接 `OperatingSystemMXBean` 或 `node_exporter` |
| P1 | `alerts[]` 填充 | 接 `sys_alert_event` + `AlertController` |
| P1 | `cnsl_recent_access` 写入 | 新增 `RecentAccessRecorder` Web 拦截器 |
| P2 | quick-actions 表驱动 | 新增 `cnsl_quick_action` 表 + Handler |

### 11.3 不在 MVP（[Vision]）

- 拖拽 Widget / 多图表类型 / 自定义布局
- AI 智能布局 / Widget 异常检测
- 独立 `bone-console` 微服务与独立数据库
- Prometheus / Grafana 全链路接入

### 11.4 符合规范

- 《Bone-DDD》分层与 CQRS Handler 约定（§14、§20）
- ArchUnit 全部 18 条规则通过（无 freeze 增量，新增 0 违规）
- 仓储 / Gateway / Handler 命名与 transactional 标注满足 P0-* 规则
- 错误码统一 `SYS_` 前缀，禁止自建 `BusinessException`
- 权限码 / OpenAPI / DDL / 前端常量 四处单源对齐（详设 §1.4 / §5.0）
