# 控制台与仪表盘模块详细设计方案

> **仓库对照（As-Is）**：无独立 `bone-console` 服务；**`bone-system`** 提供 `/api/v1/console/*`，**`bone-shell`** 首页对接概览与快捷操作（30s 刷新）。  
> **DDL**：[`bone-init.sql`](../../../bone-init.sql) **§7** 已含 **`cnsl_*`** 三表；无独立 `bone-console` 后端服务。  
> **HTTP 真源**：`bone-platform/bone-system/.../adapter/web/controller/ConsoleController.java`（+ 联调期 `bone-iam/.../ConsoleController.java`）· 路径常量 `PlatformApiPaths.CONSOLE_V1`。  
> **错误码前缀**：复用 `SYS_`（控制台聚合归属系统域）。

## 0. 可观测性契约（SLI/SLO · 与 README「企业级能力」对齐）

| SLI | 目标（**[Target]**） | As-Is 度量来源 |

| 数据新鲜度 | `keyMetrics` 滞后 ≤ 60s | `bone-shell` 30s 轮询 + 服务端缓存 |
| 跨租户隔离失败 | 0 起 / 年 | `TenantContext` + 网关审计 |

> 接入真指标（Prometheus / OpenTelemetry）为 **[Vision]**；当前阶段不对外承诺 SLO，仅供研发自查。

## 1. 模块概述

控制台与仪表盘模块是 BONE 平台的核心入口，负责系统概览、数据可视化、快速导航和操作中心，为用户提供直观的系统状态展示和快捷操作入口。

**核心目标**：
- 提供系统全局概览和健康状态监控
- 展示关键业务指标和数据趋势
- 提供快速导航和常用操作入口
- 支持自定义仪表盘和数据展示
- 实现多租户隔离的数据视图

## 2. 功能设计

### 2.1 系统概览

**功能描述**：展示系统的整体运行状态和健康情况，包括服务状态、资源使用、关键指标等。

**详细功能**：
- **服务健康状态**：显示各微服务的运行状态，包括在线状态、响应时间、错误率等
- **资源使用情况**：CPU、内存、磁盘等系统资源的使用情况
- **关键业务指标**：核心业务指标的实时展示，如订单数、用户数、交易金额等
- **系统告警**：显示最近的系统告警信息
- **快速导航**：提供常用功能的快速访问入口

**用户故事**：
> 作为系统管理员，我希望通过系统概览了解系统的整体运行状态，以便及时发现和解决问题。

### 2.2 数据仪表盘

**功能描述**：提供可自定义的数据可视化仪表盘，支持多种图表类型和数据来源。

**详细功能**：
- **图表类型**：支持折线图、柱状图、饼图、仪表盘等多种图表类型
- **数据来源**：支持从系统指标、业务数据、外部数据源等获取数据
- **自定义布局**：支持拖拽式自定义仪表盘布局
- **时间范围**：支持选择不同的时间范围查看数据
- **数据导出**：支持将仪表盘数据导出为PDF、Excel等格式

**用户故事**：
> 作为业务分析师，我希望创建自定义的数据仪表盘，以便直观地分析业务数据和趋势。

### 2.3 快速操作中心

**功能描述**：提供常用操作的快捷入口，简化用户操作流程。

**详细功能**：
- **常用功能**：提供系统中最常用功能的快速访问
- **最近操作**：显示用户最近的操作记录
- **快捷命令**：支持通过命令行方式执行常用操作
- **任务管理**：显示和管理当前正在执行的任务

**用户故事**：
> 作为普通用户，我希望通过快速操作中心快速访问常用功能，提高工作效率。

### 2.4 租户管理

**功能描述**：为多租户场景提供租户管理功能，包括租户概览、租户切换等。

**详细功能**：
- **租户概览**：显示当前租户的基本信息和资源使用情况
- **租户切换**：支持在不同租户之间快速切换
- **租户创建**：支持创建新的租户
- **租户配置**：管理租户的基本配置和权限

**用户故事**：
> 作为多租户管理员，我希望通过租户管理功能查看和管理不同租户的信息，以便更好地为租户提供服务。

### 3.3 关键实现

#### 3.3.1 系统概览实现

```java
package com.bone.console.application.query.handler;

import com.bone.console.application.query.qry.SystemOverviewQry;
import com.bone.console.application.query.dto.SystemOverviewDTO;
import com.bone.console.application.query.dto.ServiceStatusDTO;
import com.bone.console.application.query.dto.ResourceUsageDTO;
import com.bone.console.domain.gateway.MonitoringGateway;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Component;
import org.springframework.transaction.annotation.Transactional;

import java.util.List;

@Component
@RequiredArgsConstructor
public class SystemOverviewQueryHandler {
    private final MonitoringGateway monitoringGateway;
    
    @Transactional(readOnly = true)
    public SystemOverviewDTO handle(SystemOverviewQry qry) {
        List<ServiceStatusDTO> serviceStatuses = monitoringGateway.getServiceStatuses();
        ResourceUsageDTO resourceUsage = monitoringGateway.getResourceUsage();
        
        SystemOverviewDTO overview = new SystemOverviewDTO();
        overview.setServiceStatuses(serviceStatuses);
        overview.setResourceUsage(resourceUsage);
        
        return overview;
    }
}
```

#### 3.3.2 仪表盘实现

```java
package com.bone.console.application.command.handler;

import com.bone.console.application.command.cmd.CreateDashboardCmd;
import com.bone.console.domain.model.Dashboard;
import com.bone.console.domain.model.widget.Widget;
import com.bone.console.domain.repository.DashboardRepository;
import com.bone.console.common.exception.BusinessException;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Component;
import org.springframework.transaction.annotation.Transactional;

import java.util.List;

@Component
@RequiredArgsConstructor
public class CreateDashboardHandler {
    private final DashboardRepository dashboardRepository;
    
    @Transactional
    public Long handle(CreateDashboardCmd cmd) {
        // 验证仪表盘名称是否已存在
        if (dashboardRepository.existsByName(cmd.getName())) {
            throw new BusinessException("仪表盘名称已存在");
        }
        
        Dashboard dashboard = Dashboard.create(
            cmd.getId(),
            cmd.getTenantId(),
            cmd.getName(),
            cmd.getDescription(),
            cmd.getWidgets()
        );
        
        dashboardRepository.save(dashboard);
        
        return dashboard.getId().getValue();
    }
}
```

## 7. 性能与安全

> 通用横切（缓存策略、TLS、租户隔离、审计、输入验证）统一参考 [`Bone-API-规范.md`](../../architecture/Bone-API-规范.md)、[`Bone-多租户规范.md`](../../architecture/Bone-多租户规范.md) 与 IAM §7.2。本节仅列控制台特有项。

- **概览数据缓存**：Redis 缓存 `keyMetrics`、服务状态聚合结果（TTL 30s ~ 60s，与前端轮询节奏对齐）
- **异步刷新**：组件数据刷新走 `@Async`，避免阻塞概览页主线程
- **数据隔离**：`tenant_id` 透传见 `TenantContext`；多租户视图仅在 JWT claim 校验后渲染

### 10.3 核心类设计

> **命名与分层规范**统一参考 [`doc/architecture/Bone-DDD-最终实践方案.md`](../../architecture/Bone-DDD-最终实践方案.md) §14（标准包结构）与 `bone-blueprint` 示例工程。下表仅列模块特有的关键类，不再重复通用"命名规范"等约定。

| 层级 | 关键类（规划） | 职责 / 备注 |
|------|----------------|-------------|
| Adapter | `SystemOverviewController` / `DashboardController` / `WidgetController` / `PreferenceController` / `QuickActionController` | **As-Is** 由 `bone-system/ConsoleController` 单类聚合 |
| Application | `CreateDashboardHandler` / `RefreshWidgetDataHandler` / `SystemOverviewQueryHandler` | 命令处理器 `@Transactional`；查询处理器 `@Transactional(readOnly=true)` |
| Domain · 聚合根 | `Dashboard` / `Widget` / `UserPreference` | 继承 `bone-core` `AggregateRoot`；`@Getter` + 私有构造器 |
| Domain · 仓储 | `DashboardRepository` / `WidgetRepository` / `UserPreferenceRepository` | 继承 `bone-metadata-sdk` `Repository`，**空接口** |
| Domain · 防腐层 Gateway | `MonitoringGateway`（Prometheus）/ `BusinessDataGateway` / `ExternalDataSourceGateway` | 控制台特有：监控/业务/外部数据源的统一抽象 |
| Infrastructure | `PrometheusMonitoringGatewayImpl` / `BusinessDataGatewayImpl` / `RestDataSourceGatewayImpl` | Gateway 实现，**[Vision]** |

### 10.5 与其他微服务集成

**服务依赖**：
- **bone-iam**：用于权限验证和用户认证（`:8081`）
- **monitoring-service**：用于获取系统监控数据
- **business-services**：用于获取业务指标数据

**集成方式**：
- **Gateway**：通过 `domain/gateway/` 目录下的网关接口调用其他微服务
- **消息队列**：通过领域事件机制接收其他服务的事件
- **共享缓存**：通过Redis共享跨服务数据
- **API网关**：通过API网关统一调用其他微服务

**集成流程**：
1. **权限验证**：经网关调用 **bone-iam** 进行用户认证和权限检查
2. **数据获取**：调用monitoring-service获取系统监控数据
3. **业务数据**：调用business-services获取业务指标数据
4. **服务发现**：通过Nacos服务发现机制找到其他微服务

## 11. 总结

控制台与仪表盘模块是 BONE 平台的核心入口，通过提供系统概览、数据可视化、快速操作和租户管理等功能，为用户提供了直观、高效的系统管理体验。该模块采用了先进的技术栈和架构设计，支持复杂的仪表盘和组件管理需求。

**核心优势**：
- **直观的系统概览**：实时展示系统运行状态和健康情况
- **灵活的仪表盘**：支持自定义仪表盘和多种图表类型
- **高效的快速操作**：提供常用功能的快捷访问
- **多租户支持**：实现租户隔离的数据视图
- **智能布局**：AI 辅助的仪表盘布局和组件推荐

**应用场景**：
- 系统运维：监控系统运行状态，及时发现和解决问题
- 业务分析：通过数据可视化分析业务趋势
- 快速操作：通过快捷入口提高工作效率
- 租户管理：管理多租户环境下的系统资源

控制台与仪表盘模块的设计充分考虑了用户体验、性能和可扩展性，为 BONE 平台提供了强大的系统管理能力，使平台能够更加直观、高效地运行和管理。

**符合规范**：
- 遵循《Bone-DDD》分层与 CQRS Handler 约定
- 应用层以 CommandHandler / QueryHandler 为入口（《Bone-DDD》§14、§20）
- 采用六边形架构，依赖方向正确
- 领域层纯净，仅使用 `@Getter` 和私有构造器
- 仓储接口为空接口，继承 `bone-metadata-sdk` 的 `Repository`
- 数据库表结构符合数据库规范，包含完整的中文注释
- 命名规范符合最新标准
- 集成AI能力定义（@Capability）
- 提供扩展点机制（Calculator命名）
