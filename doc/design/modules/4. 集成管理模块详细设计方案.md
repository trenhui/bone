## 1. 模块概述

集成管理模块是 BONE 平台的核心能力之一，负责系统间的集成和流程编排，是实现企业集成能力的关键模块。

### 1.0 As-Is（与 [README](../../../README.md) 一致）

| 维度 | 当前仓库 |
|------|----------|
| **唯一服务** | `bone-platform/bone-integration`（`:8085`，`context-path` `/api`） |
| **默认运行时** | **INT-09** `LinearSyncFlowRuntime`（START → HTTP → END **线性同步**） |
| **连接器** | CRUD + 连接测试；非 REST/HTTP 部分类型可能 **501** |
| **对外 URL** | `http://host:8085/api/v1/integration/**`（= context-path + `PlatformApiPaths.INTEGRATION_V1`） |
| **演进** | INT-10 MQ Outbox、INT-11 Camel 图编排见 [P0 看板](../../wiki/07-P0-TODO看板.md) |

**核心目标**：
- 提供连接器管理能力，支持与外部系统的连接
- 实现可视化的流程编排，支持系统间的数据流转
- 提供流程监控和执行日志，确保集成流程的可靠性
- 支持场景化的集成模板，提高集成开发效率
- 提供集成流程的版本管理和生命周期管理

## 2. 功能设计

### 2.1 连接器管理

**功能描述**：管理与外部系统的连接器，支持连接器的创建、配置、测试和监控。

**详细功能**：
- **连接器创建**：创建各种类型的连接器，如 REST、SOAP、JDBC、FTP、MQ 等
- **连接器配置**：配置连接器的连接参数，如 URL、用户名、密码等
- **连接器测试**：测试连接器的连接状态和可用性
- **连接器监控**：监控连接器的连接状态和使用情况
- **连接器模板**：提供常用连接器的模板，如数据库、API 等

**用户故事**：
> 作为集成工程师，我希望配置与外部系统的连接器，测试连接状态，以实现系统集成。

**连接器演进红线（INT-CON-01）**：在 HTTP 连接器成熟（超时、重试、熔断、幂等、链路追踪、指标、DLQ、回放）之前，**禁止新增** FTP / JDBC / MQ / Kafka / SOAP 等协议连接器。未实现协议保持显式 501，不得以「部分可用」状态交付。新协议需求先立项、后设计，避免多协议「各 60% 完成」的浅层覆盖。

### 2.2 流程编排

**功能描述**：使用可视化工具设计和管理集成流程，支持流程的创建、编辑、测试和激活。

> **[As-Is]** 画布可保存复杂拓扑，但 **INT-09 运行时仅保证线性路径**（START → HTTP → END）；分支/并行/循环、完整 Camel 图执行为 **INT-11 [Vision]**。

**详细功能**：
- **流程创建**：创建集成流程，设置流程名称、描述等基本信息
- **可视化设计**：使用拖拽式界面设计流程，添加和配置流程节点
- **节点配置**：配置流程节点的参数和属性
- **流程测试**：测试流程的执行效果（**[Vision]**，`/flows/{id}/test` 未实现）
- **流程激活**：激活流程，使其正式运行
- **流程版本**：管理流程的版本历史，支持版本对比和回滚（**[Vision]**，`/flows/{id}/versions` 未实现）

**用户故事**：
> 作为集成工程师，我希望使用可视化工具设计集成流程，配置流程节点和连接关系，以实现系统间的数据流转。

### 2.3 流程监控

**功能描述**：监控集成流程的执行状态，查看执行日志，处理错误。

**详细功能**：
- **执行状态监控**：监控流程的执行状态，如运行中、成功、失败等
- **执行日志查看**：查看流程的详细执行日志，包括每个节点的执行状态和输入输出数据
- **错误处理**：处理流程执行过程中的错误，支持手动重试和错误修复
- **执行统计**：统计流程的执行次数、成功率、平均执行时间等指标
- **告警通知**：当流程执行失败时，发送告警通知

**用户故事**：
> 作为集成工程师，我希望监控集成流程的执行状态，查看执行日志，处理错误，以确保流程正常运行。

- 当前默认运行时为 **`LinearSyncFlowRuntime`**（INT-09 线性同步）；`CamelFlowRuntime`、`FlowNodeExecutor`、`CamelFlowCompiler`、`FlowGraph` 为 **INT-11** 演进路径。
- 通用响应 `ApiResponse` / `PageResult` 不在本模块 `common/`，统一来自 `bone-core`，详设勿再列副本。
- 异常统一使用 `com.bone.core.exception.BizException`（业务失败）、`DomainException`（聚合不变量）、`NotFoundException`（资源不存在）；**禁止**模块自建 `BusinessException` / `*BusinessException`（ArchUnit `noCustomBusinessException` 拦截）。

### 3.4 关键实现

#### 3.4.1 连接器管理

```java
package com.bone.integration.application.command.handler;

import com.bone.integration.application.command.cmd.CreateConnectorCommand;
import com.bone.integration.domain.model.connector.Connector;
import com.bone.integration.domain.model.connector.vo.ConnectorName;
import com.bone.integration.domain.model.connector.vo.ConnectorType;
import com.bone.integration.domain.repository.ConnectorRepository;
import com.bone.core.exception.BizException;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Component;
import org.springframework.transaction.annotation.Transactional;

@Component
@RequiredArgsConstructor
public class CreateConnectorCommandHandler {
    private final ConnectorRepository connectorRepository;

    @Transactional
    public Long handle(CreateConnectorCommand command) {
        ConnectorName connectorName = new ConnectorName(command.getName());
        ConnectorType connectorType = new ConnectorType(command.getType());

        if (connectorRepository.existsByName(command.getName())) {
            throw new BizException("INT_CONNECTOR_NAME_DUPLICATED", "连接器名称已存在");
        }
        
        Connector connector = Connector.create(
            connectorName,
            connectorType,
            command.getConfig()
        );
        
        connectorRepository.save(connector);
        
        return connector.getId().getValue();
    }
}
```

#### 3.4.2 流程编排

```java
package com.bone.integration.application.command.handler;

import com.bone.integration.application.command.cmd.CreateFlowCommand;
import com.bone.integration.domain.model.flow.IntegrationFlow;
import com.bone.integration.domain.model.flow.FlowNode;
import com.bone.integration.domain.model.flow.FlowConnection;
import com.bone.integration.domain.model.flow.vo.FlowName;
import com.bone.integration.domain.repository.IntegrationFlowRepository;
import com.bone.integration.domain.repository.FlowNodeRepository;
import com.bone.integration.domain.repository.FlowConnectionRepository;
import com.bone.core.exception.BizException;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Component;
import org.springframework.transaction.annotation.Transactional;

import java.util.List;

@Component
@RequiredArgsConstructor
public class CreateFlowCommandHandler {
    private final IntegrationFlowRepository flowRepository;
    private final FlowNodeRepository nodeRepository;
    private final FlowConnectionRepository connectionRepository;
    
    @Transactional
    public Long handle(CreateFlowCommand command) {
        FlowName flowName = new FlowName(command.getName());

        if (flowRepository.existsByName(command.getName())) {
            throw new BizException("INT_FLOW_NAME_DUPLICATED", "流程名称已存在");
        }
        
        IntegrationFlow flow = IntegrationFlow.create(
            flowName,
            command.getDescription()
        );
        
        IntegrationFlow savedFlow = flowRepository.save(flow);
        
        // 保存流程节点
        List<FlowNode> nodes = command.getNodes().stream()
                .map(nodeCmd -> FlowNode.create(
                    savedFlow.getId(),
                    nodeCmd.getName(),
                    nodeCmd.getType(),
                    nodeCmd.getConfig(),
                    nodeCmd.getPositionX(),
                    nodeCmd.getPositionY()
                ))
                .toList();
        nodeRepository.saveAll(nodes);
        
        // 保存流程连接
        List<FlowConnection> connections = command.getConnections().stream()
                .map(connCmd -> FlowConnection.create(
                    savedFlow.getId(),
                    connCmd.getSourceNodeId(),
                    connCmd.getTargetNodeId(),
                    connCmd.getCondition()
                ))
                .toList();
        connectionRepository.saveAll(connections);
        
        return savedFlow.getId().getValue();
    }
}
```

### 5.0 横切约定（对齐扩展 §7.1）

| topic | As-Is | [Target] |
|--------|-------|----------|
| 成功信封 | `ApiResponse` + `PageResult.records` | — |
| 失败 | `ProblemDetail` + `INT_*` 错误码 | — |

| 多租户 | `X-Tenant-Id` 或 JWT；`TenantContext` 透传 | 行级隔离 + 配额（连接器并发） |

## 6. 部署与集成

### 6.1 部署方式

> **As-Is**：`bone-platform/bone-integration` 默认 :8085，`context-path` `/api`。下列资源/容器化为 **[Vision]**。

## 7. 性能与安全

> 通用横切（缓存、TLS、租户隔离、审计、输入验证）见 [`Bone-API-规范.md`](../../architecture/Bone-API-规范.md)、IAM §7.2。本节仅列集成特有项。

- **连接器配置缓存**：Redis 缓存 `int_connector.config`（含解密后凭据），TTL 与租户密钥轮换对齐
- **连接器凭据加密**：`config_json` 中的密码/Token 走 AES-256，密钥外置（KMS / K8s Secret）
- **死信幂等**：`int_dead_letter` 配合 `Idempotency-Key` 重试，确保 at-least-once 不重复副作用
- **流程并发隔离**：每租户连接器并发上限（**[Target]** 配额），防止外部接口被打爆

## 10. 总结

集成管理模块是 BONE 平台的核心能力之一，通过提供连接器管理、流程编排和流程监控功能，实现了企业级的系统集成能力。该模块采用了先进的技术栈和架构设计，支持复杂的集成场景和流程需求。

**关键成功因素**：
- 灵活、可扩展的连接器体系
- 直观、易用的可视化流程设计器
- 可靠、高效的流程执行引擎
- 全面、详细的流程监控和日志
- 高性能、可扩展的系统架构

该模块的实现将为 BONE 平台的企业集成能力提供重要支撑，帮助企业实现系统间的无缝集成和数据流转。
