# 11. 枚举选项源统一设计方案（界面设计器字典 × 系统字典 × 主数据 × 外部服务）

> 归属：跨模块（元数据 × 系统管理 × 主数据 × 集成）｜状态：**待评审（设计稿）**
> 触发场景：界面设计器（`bone-metadata-app` · UI Schema Tab · 字典面板）的码表配置与系统管理字典、主数据参考数据、外部服务接口的打通
> 对齐：[BONE-业务对象界面JSON协议设计.md](../lowcode/ui/ui-protocol/BONE-业务对象界面JSON协议设计.md) §3.1/§13.3 · [7a. 数据字典模块详细设计方案.md](./7a.%20数据字典模块详细设计方案.md)（v3）· [3. 主数据管理模块详细设计方案.md](./3.%20主数据管理模块详细设计方案.md)（G15）· [4. 集成管理模块详细设计方案.md](./4.%20集成管理模块详细设计方案.md)（INT-CON-01）· [Bone-DDD-最终实践方案.md](../architecture/Bone-DDD-最终实践方案.md)（HC-001/003/008）· [数据库开发规范.md](../architecture/数据库开发规范.md)

## 1. 结论

| 问题 | 结论 |
|---|---|
| 是否建议打通 | **建议**。作为元数据域的一等能力建设，不是 UI 层功能叠加 |
| 打通点 | 「选项源（Option Source）」下沉到 `meta_field`；界面设计器字典面板保持「只引用 + 可覆写」纪律不变 |
| 三个对象的角色 | 系统字典 = 共享码表真源（L1）；主数据参考数据 = 有治理值域真源（L2）；外部服务 = 权威在外部时的只读接入（L3） |
| 最低成本路径 | P0 只加 `meta_field.enum_source` 一列 + 发布时物化；UI Schema 协议零变更、运行时写校验零变更 |

三条依据：

1. **现状三缺**：`meta_field.enum_values` 是字段私有文本 JSON——不能跨字段共享（同码表复制粘贴漂移）、不能运营维护（改选项 = 改元数据模型 + 重新发布）、不能对接外部标准码（GB/T 2260 / ISO 4217）。
2. **平台已有成熟设施**：`sys_dict_*`（两级 + 层级 + i18n + 时间有效性 + 租户覆盖）与 `mdm_reference_*`（平台值 + 租户私有并集）均已落地，另造第三套违反单真源。
3. **业界一致形态**：选项源是字段（列）属性而非视图属性，UI 只引用不复制（见 §3）。

## 2. 现状（As-Is）与缺口

| 面 | 现状 | 证据 | 缺口 |
|---|---|---|---|
| 界面设计器字典面板 | 只读引用字段 `enumValues`，仅允许 `labelOverride` / `hidden` 覆写 | `DictionaryPanel.tsx`；协议 §13.3 | 码表只能来自字段私有文本；运营改码表必须改元数据并重新发布 |
| 元数据字段 | ENUM 存 `enum_values` JSON（`[{"code","label"}]`），建模向导结构化编辑 | `bone-init.sql:1257`；`FieldWizardModal.tsx` | 无「来源」概念；同码表多字段复制；无外部标准码映射 |
| 运行时写校验 | `RuntimeWriteValidator` 按 `enumValues` 校验 ENUM 越界 | `RuntimeWriteValidator.java`（`validateRules`） | 只认字面量；外部真源变更不同步 |
| 系统字典 | `sys_dict_type/item/hierarchy/item_text` 四级模型；`/options` 统一下拉入口（租户合并 + 生效过滤 + 本地化 + 缓存）；前端 `useDict`/`DictSelect`/`DictTag` | 7a 详设 §4–§6；`DictItemController.java` | 与元数据字段零连接；7a §11.1 收敛问题开放 |
| 主数据参考数据 | `mdm_reference_set/value/value_tenant` overlay：平台全局值域 + 租户私有值并集 | `ReferenceDataController.java`；`ReferenceDataApplicationService.java` | 与建模零连接 |
| 外部服务 | `bone-integration` 连接器 + 线性同步流；HTTP only（INT-CON-01 红线） | 4 详设 §1.0 | 无「枚举码表消费」形态 |

## 3. 业界最佳实践映射

| 业界 | 分层形态 | Bone 对应 |
|---|---|---|
| SAP | Domain（固定值）→ Value Table（值表）→ Check Table/FK（主数据）→ Search Help（外部检索） | inline → dict → reference → external |
| Dynamics 365 / Dataverse | Local Option Set（焊字段）vs Global Option Set（跨字段共享）+ Lookup（主数据） | 同左；选项集是**列属性**不是视图属性 |
| Salesforce | Restricted picklist + Global Picklist（跨对象共享）+ 依赖筛选 | dict + `hidden`/`labelOverride` |
| Odoo | `selection` 静态 vs `many2one` 关系 | inline/reference；无界记录走 `many2one` ≡ REFERENCE 控件 |
| 低代码（宜搭 / Power Apps） | 选项集 / 关联数据 / 外部数据源 | 三型 + snapshot/live 双模式 |

三条共同纪律（本方案的约束来源）：

1. **选项源是字段属性**：写校验对所有视图/表单生效，不随 UI 配置漂移。
2. **UI 只引用不复制**：共享值域单点维护，界面层只做显示裁剪。
3. **大值域/无界数据走关系查找**：不展开成选项列表。

## 4. 核心设计：选项源（Option Source）

### 4.1 类型谱系与选型

| type | 真源 | 模式 | 适用 | 规模约束（软） |
|---|---|---|---|---|
| `inline` | `meta_field.enum_values` 手编 | snapshot | 字段私有小枚举（性别、是否） | ≤ 50 项，超限提示改 `dict` |
| `dict` | `sys_dict_type.code` | snapshot 默认 / live 可选 | 跨实体共享码表、运营可维护 | ≤ 500 项 |
| `reference` | `mdm_reference_set.code` | snapshot 默认 / live 可选 | 有治理流程的值域（币种、科目、行政区划） | ≤ 1000 项 |
| `external` | integration 连接器 + 接口声明 | **live 强制**（本地快照仅兜底） | 权威在外部（GB/T 2260、ISO 4217、工商照面） | 由接口决定 |

**无界记录型数据**（客户、供应商、员工，持续增长）不纳入选项源，继续用 REFERENCE 控件 + `lookup-options`（G10 已实现）。

### 4.2 声明结构（`meta_field.enum_source`）

```json
{
  "type": "dict",
  "mode": "snapshot",
  "ref": { "typeCode": "invoice_type" },
  "resolvedAt": "2026-10-20T09:30:00",
  "resolvedCount": 12,
  "resolvedBy": "publish"
}
```

| 键 | 说明 |
|---|---|
| `type` | `inline`（缺省，兼容存量）/ `dict` / `reference` / `external` |
| `mode` | `snapshot` / `live`；`external` 强制 `live` |
| `ref` | 按类型的真源定位：`{typeCode}` / `{setCode}` / `{connectorId, path, valuePath, codeField, labelField, refreshSeconds}` |
| `resolvedAt` / `resolvedCount` / `resolvedBy` | 物化元数据（服务端写，建模者不改） |

### 4.3 解析与物化（snapshot 模式）

- **物化时机**：字段保存（`enum_source` 变更时）、实体发布（`MetaEntityApplicationService.publishEntity` 闸门之后、落库之前）、手动刷新。
- **物化动作**：按 `enum_source` 解析选项列表 → 覆写 `meta_field.enum_values`。发布态运行时读 `enum_values`（`CatalogRuntimeEntityProvider` → `RuntimeFieldColumn`），**运行期零改动**。
- **物化失败**：发布阻断（`META_ENUM_SOURCE_RESOLVE_FAILED`，ERROR 级）；手动刷新保留旧快照并报错。
- `inline` 不物化（`enum_values` 即真源）。

> 物化到 `enum_values` 而非新表：发布时把真源「编译」成运行契约，与 uiSchema 发布快照同哲学；写校验（`RuntimeWriteValidator`）与前端渲染（`parseEnumValues`）消费口径不变。

### 4.4 live 模式

| 项 | 设计 |
|---|---|
| 渲染 | 字段 `enum_source.mode=live` 时，ENUM 控件调运行期端点（§9），TTL 缓存：dict 300s / reference 600s / external 60s |
| 降级 | 解析失败 fail-soft 回落物化快照 + 黄条「码表服务不可用，展示上次发布快照」（禁静默） |
| 写校验 | live 解析成功按实时集合校验；失败按快照校验（确定性优先），日志记 `enum_source_live_fallback` |
| 代价 | 写校验集合随时间漂移，故默认 snapshot；live 用于「运营改字典即时生效、不重新发布实体」 |

### 4.5 与 `dictionaries` 覆写的关系

正交：`dictionaries`（`labelOverride` / `hidden`）作用在**解析后的选项集合**上，与来源类型无关。协议 §13.3 结构不变，仅补一句「覆写对全部选项源类型生效」。

## 5. 各来源接线设计

### 5.1 `dict`（系统字典）

| 项 | 设计 |
|---|---|
| 解析 | HTTP GET `{bone-system}/api/v1/system/dict/items/options?type={typeCode}&lang={lang}` |
| 映射 | `DictOptionDto{code,label}` → `OptionItem{code,label}`；其余字段（value/tagType）不进选项集 |
| 层级值域（CASCADE） | 只取 DEFAULT 层级扁平项；树形下拉不在选项源范围（保持 Select 语义） |
| 租户覆盖 / 时效 / i18n | 由 bone-system `/options` 内部完成（平台+租户合并、生效过滤、译文回落），元数据侧无感 |
| 管理端跳转 | 设计器深链 `/system#/dict?type={typeCode}`（qiankun 子应用 `bone-system-app`，路由 `/dict`） |
| 缓存 | metadata-server 侧自持 TTL 缓存（跨服务，不复用 7a 的进程内 `DictOptionsCache`） |

### 5.2 `reference`（主数据参考数据）

| 项 | 设计 |
|---|---|
| 解析 | HTTP GET `{bone-masterdata}/api/v1/masterdata/reference-sets` → 按 `setCode` 定位 id → GET `/{id}/values` → `ReferenceValueView{valueCode,valueName}` |
| 租户并集 | 由 masterdata 侧完成（平台值 + 租户私有值纯并集，无 shadowing） |
| 与 7a §11.1 的关系 | 该开放问题（`mdm_reference_*` 与 `sys_dict` 长期收敛）由本方案回应：**选项源解析是建模/界面侧统一入口**，`/options` 继续服务系统管理页面；两者都是读路径，不冲突 |
| 记录型主数据 | `mdm_entity` + record 不用此路，走 REFERENCE 控件 |

### 5.3 `external`（外部服务）

| 项 | 设计 |
|---|---|
| 出站 | 经 bone-integration HTTP 连接器（INT-CON-01：只走 HTTP；超时 3s、熔断、失败回落快照） |
| 声明 | `connectorId` + `path` + `valuePath`（点分路径 / `$` 前缀 JSONPath 子集）+ `codeField` / `labelField` + `refreshSeconds` |
| 安全 | 凭证在 integration 侧托管，metadata-server 不碰密钥；SSRF 防护走连接器既有出站策略 |
| 物化 | external 的「快照」只是兜底缓存，权威永远在外部；发布不因外部不可用而阻断（用旧快照 + WARNING） |

## 6. 界面设计器改造

### 6.1 字典面板 → 选项源面板（`DictionaryPanel` 扩展）

卡片表头新增信息行：**来源类型 Tag** + 真源定位（typeCode / setCode / 连接器）+ 项数 + 解析时间 + 状态（正常 / 已漂移 / 解析失败）+ 操作（刷新快照 / 跳转管理端 / 漂移详情）。

| 来源 | 面板行为 |
|---|---|
| `inline` | 维持现状（`labelOverride` + `hidden` + 还原）；提示「在字段建模维护」 |
| `dict` | 覆写 UI 不变 + 来源卡 + 「刷新快照」+ 漂移徽标 + 跳转系统字典 |
| `reference` | 同 `dict`（跳转主数据参考数据） |
| `external` | 覆写 UI 不变 + 来源卡 + 最近拉取时间 + 失败降级提示 |

### 6.2 字段建模入口（`FieldWizardModal`）

ENUM 类型时增「选项源」分组：内联枚举（现状编辑器）/ 系统字典（typeCode 选择器，搜索 + 预览前 N 项）/ 主数据参考数据（setCode 选择器）/ 外部服务（P2）。切换来源时若 `enum_values` 已有手编内容 → 二次确认后清空，由物化接管。

### 6.3 发布预览联动（`getPublishPreview`）

| 问题码 | 级别 | 说明 |
|---|---|---|
| `ENUM_SOURCE_DRIFT` | WARNING | 物化快照与真源有差异，列出 added / removed / labelChanged（removed 附「历史数据旧值不受影响」提示） |
| `ENUM_SOURCE_UNRESOLVED` | ERROR | 发布时解析失败（dict/reference 不可达） |

## 7. 运行时与写校验

| 模式 | 写校验 | 渲染取数 |
|---|---|---|
| snapshot | `RuntimeWriteValidator` 不变（`enum_values` 即快照） | 随 catalog 快照下发（现状） |
| live | 实时集合校验，失败回落快照 | 调运行期端点 + TTL 缓存，失败回落快照 |

运行期选项查询端点挂 `RuntimeRelationController`（与 `lookup-options` 同址同模式，同权限口径：读不加 `@PreAuthorize`，理由同 7a §6.2）。

## 8. 数据模型变更（DDL · L3 审批）

`bone-init.sql` `meta_field` 增一列：

```sql
enum_source         JSON            DEFAULT NULL COMMENT '枚举选项源声明（inline/dict/reference/external；缺省 inline）',
```

- 不改 `enum_values`（物化快照落点）；不加新表；不动 `sys_dict_*` / `mdm_reference_*`。
- 存量 ENUM 字段 `enum_source` 为空 = `inline`，行为逐字不变。
- 无增量迁移：改表即改 init（详设 README 约定），开发库重建。

## 10. 分层落地与门禁

```
bone-metadata-server/catalog/domain/service/EnumSourceResolver.java      （端口：按 enum_source 解析 OptionItem 列表）
bone-metadata-server/catalog/infrastructure/enumsource/
  HttpDictEnumSourceResolver.java       （→ bone-system /dict/items/options）
  HttpReferenceEnumSourceResolver.java  （→ bone-masterdata /reference-sets）
  HttpExternalEnumSourceResolver.java   （→ bone-integration 连接器出站）
bone-metadata-server/catalog/application/EnumSourceApplicationService.java  （物化 / 刷新 / 漂移）
```

- Controller 只碰 application；跨服务 HTTP 客户端在 infrastructure；domain 零框架依赖（HC-001 精神）。
- ArchUnit：解析实现不得被 `adapter.web` 直调（同既有 gateway 规则）；`infrastructure.enumsource` 不被 application 反向依赖。
- 前端：`metadataApi.fieldOptions` / `refreshOptions` / `optionDiff`；选项源面板单测；黄金样例跨端（同一 JSON 同时喂 TS 单测与 Java 单测，低代码 PRD §D5 口径）。

## 11. 分期落地

| 批次 | 范围 | 门禁 |
|---|---|---|
| **P0** | `enum_source` 列 + inline 兼容 + dict 接线（snapshot）+ 选项源面板 + 发布闸门 + 漂移检查 | ArchUnit + spotless + 单测；协议零变更、运行时零变更 |
| **P1** | reference 接线 + live 模式 + 运行期 `field-options` 端点 + TTL 缓存/失效 | + 跨端 golden fixtures |
| **P2** | external 接线（integration 连接器）+ 熔断降级 + 监控指标 | + SSRF/超时用例 |

每批独立可交付。P0 落地后系统字典即刻接入（收益最大、风险最小）。

落地前需补：ADR（选项源选型，编号顺延，L3 审批）；DDL 变更（L3 审批）。

## 12. 验收标准

- [ ] `meta_field.enum_source` 落 DDL；存量 ENUM 字段（`enum_source` 为空）行为逐字不变
- [ ] dict 来源：发布物化成功；`/options` 不可达时发布阻断且错误码正确
- [ ] 设计器面板正确显示来源 / 项数 / 解析时间 / 漂移；`hidden` / `labelOverride` 覆写对 dict 来源生效
- [ ] 漂移：真源新增 / 删除 / 改 label 在发布预览 WARNING 列出
- [ ] live：改字典即时生效；解析失败回落快照 + 黄条（禁静默）
- [ ] 写校验：snapshot 与 live 两态均按预期集合校验（含回落路径）
- [ ] ArchUnit / spotless / `scripts/check.sh` 全绿；错误码登记台账与双语语言包

## 13. 非目标

- UI 层新造码表（协议 §3.1 纪律保持）
- 租户专属码表覆盖：跨租户走 dict 租户 overlay，同租户跨场景走 `variants`
- 无界记录型数据（走 REFERENCE 控件）
- 前端直连外部服务（全部经服务端解析）
- 各来源的管理端写入口（仍在 bone-system / bone-masterdata / bone-integration 各自模块）
