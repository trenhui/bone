## 1. 模块概述

### 1.1 模块定位

IAM（Identity and Access Management）账号权限管理模块是 BONE 平台的核心安全组件，负责认证、RBAC 授权与 IAM 域审计。**零信任、五层策略、等保三级**为演进目标（[Vision]），非当前 As-Is 承诺；落地边界见 §1.4。

### 1.2 核心功能

| 功能 | 成熟度 |
|------|--------|
| **账号管理**（`iam_account`） | **As-Is** |
| **角色管理**、角色-权限绑定 | **As-Is** |
| **权限目录**、权限树 | **As-Is** |
| **认证**（JWT + refresh + 黑名单） | **As-Is** |
| **IAM 域审计**（DB，30 天） | **As-Is** |
| **多租户管理**、配额、Schema/库隔离 | **[Target]** / 商业版 |
| **企业 SSO 联邦**（OAuth2/SAML/LDAP） | **[Target]** / 商业版（社区版 PRD ❌） |
| **平台全量审计 + WORM** | **[Vision]** / 商业版 |
| **MFA**、**ABAC/`iam_policy`**、**字段级权限** | **[Vision]** |

### 1.3 设计目标

- **安全性**：采用零信任安全模型，实现细粒度的权限控制
- **可靠性**：确保认证和授权的高可用性
- **可扩展性**：支持大规模用户和权限管理
- **合规性**：满足等保三级要求
- **易用性**：提供简单直观的权限管理界面
- **性能**：确保认证和授权的高性能

### 1.4 能力成熟度矩阵（验收边界）

> 与 PRD §4.8、§3.1.3 社区/商业版边界及 P0 看板 **IAM-*** 项一一对应；**未标 As-Is 不得按已上线验收**。

| 能力 | 层级 | PRD / 看板 | 说明 |
|------|------|------------|------|

| 权限目录 CRUD、权限树 | **As-Is** | IAM-003 | `iam_permission` **无 tenant_id**（平台级目录） |

## 2. 功能设计

### 2.1 账号管理

> **命名约定**：物理表与代码以 **`account`** 为准（`iam_account`、`AccountController`、API `/api/v1/iam/accounts`）；UI/产品文案保留「用户」便于业务理解。

**功能描述**：管理系统账号，包括创建、编辑、禁用账号，管理账号信息。

**核心功能**：
- 创建账号：填写用户名、邮箱、密码，选择角色
- 编辑账号：修改账号信息、角色分配（**As-Is** 经 `AccountRoleBindingService` 写入 `iam_account_role`）
- 禁用账号：禁止账号登录系统
- 重置密码：重置账号密码
- 查询账号：获取账号列表和详情
- 导入/导出账号：批量导入和导出账号信息

**业务规则**：
- `username` 在同一 `tenant_id` 内唯一（DDL 唯一键 `uk_iam_account_username`）
- 密码：**As-Is** 长度 ≥8 + 大小写/数字/符号；**[Target]** 对标 NIST 800-63B（长度 ≥12 + 弱口令字典；不再强制周期轮换）— 见 §7.2.1
- 账号状态：**As-Is** 启用(1)、禁用(0)、**锁定(2)**（连续登录失败，超出 PRD「仅启用/禁用」基线）
- 企业 SSO 联邦：**[Target]** / 商业版（PRD §3.1.3 社区版不含）

### 2.2 角色管理

**功能描述**：管理系统角色，包括创建、编辑角色，分配权限。

**核心功能**：
- 创建角色：填写角色名称、描述
- 编辑角色：修改角色名称、描述
- 分配权限：为角色分配功能权限和数据权限
- 查询角色：获取角色列表和详情
- 角色继承：**[Target]**（`parent_role_id` 已入 DDL，继承求值未实现）

**业务规则**：
- 角色名称/编码必须唯一（同一 `tenant_id` 内）
- 权限包括：功能权限、数据权限（经角色绑定，**As-Is** 无数据权限引擎）
- 角色继承：**[Target]** — 子角色合并父角色权限集（落地前勿按 PRD 验收继承）

### 2.3 权限管理

**功能描述**：定义系统权限，管理权限分配。

**核心功能**：
- 创建权限：填写权限名称、代码、描述
- 编辑权限：修改权限名称、描述
- 分配权限：**As-Is** 仅分配给角色（`iam_role_permission`）；分配给账号直连为 **[Target]**（需 `iam_account_permission` 或回写收敛 PRD）
- 查询权限：获取权限列表和详情
- 权限层级：**As-Is** `parent_id` 树形展示

**业务规则**：
- 权限 `code` 全局唯一（`iam_permission` **无** `tenant_id` — 平台级权限目录，租户通过角色绑定消费）
- 权限类型：**As-Is** 列 `type`（如 `MENU` / `OPERATION`，见 init SQL 默认 `OPERATION`）
- 权限树：**As-Is**；菜单/操作/数据权限的 UI 与引擎校验逐步对齐 **[Target]**

### 2.4 审计日志

**功能描述**：分两层（勿混为单一能力）：

| 层级 | 范围 | 成熟度 |
|------|------|--------|
| **IAM 域审计** | 登录、账号/角色/权限变更等 IAM API | **As-Is** → `iam_audit_log` |
| **平台访问审计** | 元数据/主数据/集成/扩展等全域 API | **[Vision]** — 各服务 AOP + 统一索引/traceId |

**核心功能**：
- 日志记录：**As-Is** IAM 域操作；全平台操作 **[Vision]**
- 日志查询：支持按时间、用户、操作类型等条件查询
- 日志导出：支持导出为Excel、CSV格式
- 日志存储：商业版使用WORM存储，社区版使用数据库存储

**业务规则**：
- 社区版：审计日志存储在关系型数据库，保留30天，支持按日清理
- 商业版：日志实时写入对象存储（MinIO/AWS S3/阿里云OSS），启用WORM锁定180天，之后自动归档到冷存储
- 审计日志包含：租户ID、用户ID、操作类型、资源ID、请求参数（脱敏）、结果、耗时、来源IP、User-Agent

### 2.5 多租户管理（商业版）

**功能描述**：管理多个租户，为每个租户分配独立的资源配额和用户，以实现多组织隔离。

**核心功能**：
- 创建租户：填写租户名称、管理员邮箱、资源配额
- 编辑租户：修改租户信息、资源配额
- 删除租户：删除不再需要的租户
- 查询租户：获取租户列表和详情
- 租户数据隔离：确保租户间数据完全隔离

**业务规则**：
- **As-Is 默认**：共享数据库 + **`tenant_id` 行级隔离**（与 `bone-init.sql`、业务表一致）
- **[Target] / 商业版**：独立 Schema、独立库（§4.5 `isolation_mode` 扩展字段落地后启用）
- 租户内可设置子管理员，管理本租户用户和权限
- 租户配额包括：最大用户数、最大实体数、存储容量（GB）、API调用量（次/天）

## 3. 技术实现

### 3.1 技术栈选型

| 技术 | 版本 | 用途 |
|------|------|------|
| Java | 17+ | 核心开发语言 |
| Spring Boot | 3.2+ | 后端框架 |
| Spring Security | 6.2+ | 安全框架 |
| JWT | 0.11+ | 认证令牌 |
| MySQL | 8.0+ | 关系型数据库 |
| Redis | 7.0+ | 缓存（用于Token存储） |
| MinIO | 2024+ | 对象存储（用于审计日志WORM存储） |
| OAuth2/SAML/LDAP | - | 企业SSO集成 |

### 3.2 架构设计

**架构层次**：
- **前端层**：`bone-iam-app` — 账号/角色/权限/审计管理
- **应用层**：`bone-iam` — 认证、RBAC 编排、IAM 域审计
- **授权（As-Is）**：各业务服务进程内 **Spring Security** + JWT 中的 `authorities`（权限码）；**非**独立 PDE 微服务
- **授权（[Target]）**：进程内 `PolicyEvaluator`（可读 `iam_policy`）
- **授权（[Vision]）**：独立 `authz-service`（总体架构规划示例端口 8082，须 ADR）
- **数据层**：MySQL `iam_*` 表 + Redis（Token 黑名单/权限缓存）

**核心流程（As-Is）**：
1. 登录 → `AuthController` 签发 JWT（含 `tenant_id`、权限码列表）
2. 业务请求 → 网关/服务校验 JWT → `@PreAuthorize` / `hasAuthority('domain:action')`
3. IAM 变更 → 写 `iam_audit_log`；权限变更后 **[Target]** 失效 Redis 权限缓存

### 3.3 Java工程结构

> 与 [`doc/architecture/Bone-DDD-最终实践方案.md`](../../architecture/Bone-DDD-最终实践方案.md) **§14** 对齐：六边形 + **CQRS**（`command`/`query` + Handler）；**bone-metadata-sdk** 持久化。**As-Is** 以 `bone-platform/bone-iam` 源码为真源。

```
bone-iam/src/main/java/com/bone/iam/
├── IamApplication.java
├── adapter/web/
│   ├── controller/        # AuthController / AccountController / RoleController / PermissionController / AuditController / ConsoleController（联调期）/ ExtensionE2eController（联调期）
│   ├── dto/{req|resp}/    # 请求/响应 DTO
│   └── converter/         # Web 装配
├── application/
│   ├── command/{cmd|handler}/    # Login/CreateAccount/CreateRole/AssignPermission...
│   ├── query/{qry|handler|dto}/  # AccountPage/RolePage/AuditLogList...
│   └── event/                    # AccountCreated / RoleCreated / AuditLogCreated handlers
├── domain/
│   ├── model/
│   │   ├── account/       # Account 聚合（对齐 iam_account）；vo：AccountId/Username/Email/AccountStatus
│   │   ├── role/          # Role 聚合（含 parent_role_id 继承字段，继承求值 [Target]）
│   │   ├── permission/    # Permission 聚合（**无 tenant_id**，平台级目录）
│   │   └── audit/         # AuditLog 聚合（对齐 iam_audit_log）
│   ├── repository/        # *Repository 空接口
│   └── service/           # AuthService / AccountService / AuditService 等领域服务
└── infrastructure/
    ├── security/          # JwtAuthenticationFilter / TokenBlacklistService（Redis）
    ├── external/          # SSO/IdP/MinIO Client（OAuth2/SAML/LDAP 实现为 [Target]/商业版）
    └── config/            # SecurityConfig / SwaggerConfig / JwtConfig / RedisConfig
```

**As-Is 与目标态偏差**：

- 源码中聚合根可能仍以 `User` 命名（迁移到 `Account` 进行中）；表已为 `iam_account`，详设统一使用「账号」/`Account` 术语。
- 外部 SSO 实现（`OAuth2SsoClientImpl` / `SamlSsoClientImpl` / `LdapSsoClientImpl`）为 **[Target]/商业版**，社区版仅留 `GET /sso/config` 占位与 `GET /sso/callback` Stub（见 §1.4 与 P0 看板 IAM-08）。
- 通用响应 `ApiResponse` / `PageResult` 与异常基类来自 `bone-core`，本模块**不重复**维护。
- 仓库暂无 `Dockerfile`，部署见 [doc/deployment](../../deployment/) **[Vision]**。

### 3.4 认证机制（**As-Is**）

**认证流程**：
1. `POST /api/v1/iam/login` — 校验 `iam_account`（BCrypt）
2. 签发 access JWT + 持久化 `iam_refresh_token`
3. 客户端 `Authorization: Bearer`；`POST /refresh` 轮换 refresh；`POST /logout` 撤销
4. 各服务 `JwtAuthenticationFilter` 解析 JWT；**`tenant_id` 须来自 JWT claim**，禁止仅用请求体覆盖（总体架构 §8、§10.1）

**认证方式**：
| 方式 | 成熟度 |
|------|--------|
| 用户名/密码 | **As-Is** |
| Refresh + Redis 黑名单 | **As-Is**（无 Redis 时仅撤销 refresh，见 IAM-01） |
| SSO 配置读取 | **As-Is** 占位（`GET /sso/config`） |
| OAuth2 / SAML / LDAP 联邦 | **[Target]** / 商业 |
| MFA | **[Vision]** |

**Token 管理**：access 默认约 2h；refresh 约 7d；黑名单 Redis **[As-Is]**。

### 3.5 授权机制（分层）

#### 3.5.1 As-Is — RBAC + 权限码

- 账号 → `iam_account_role` → 角色 → `iam_role_permission` → `iam_permission.code`（`AccountAuthoritiesQueryHandler`）
- `AssignPermissionHandler` → `RolePermissionBindingService` 维护 `iam_role_permission`；变更后 `AuthorityCacheEvictionService` 失效持有该角色的账号缓存
- 登录/刷新时将权限码写入 JWT claim **`scopes`**；`JwtAuthenticationFilter` 映射为 `GrantedAuthority`
- Redis 可选：`iam:authz:scopes:account:{id}`，TTL 30min（无 Redis 时直查 DB）
- `bone-init.sql` 预置超级管理员角色权限绑定；无绑定的管理员回退 `DefaultPermissionCodes.adminFallback()`
- **无**独立 Policy Decision Engine 进程；**无** `iam_policy` 运行时求值

#### 3.5.2 [Target]

- 进程内策略求值（读 `iam_policy` + RBAC 合并）
- 角色继承闭包计算；权限变更 → Redis 缓存主动失效（**部分落地**：`AuthorityCacheEvictionService`，见 §3.5.1）
- 用户直连权限（若保留 PRD 表述）→ `iam_account_permission` + API

#### 3.5.3 [Vision]

- 五层模型：Owner / Deny(ABAC) / ReBAC / RBAC / Default — **须独立 ADR**（[BONE-总体架构](../../architecture/BONE-总体架构设计方案.md) §10.2）
- 字段级权限、独立 `authz-service`、与元数据字段 ACL 联动

**权限缓存 [Target]**：Redis 缓存用户权限集，TTL 约 30min；与架构 H-008「最终一致 + 对账」对齐。

### 3.6 审计日志实现

**IAM 域（As-Is）**：
- IAM 模块记录登录、账号/角色/权限变更等
- 落库 `iam_audit_log`（列集见 §4.4，**以 init SQL 为准**）
- 社区版保留 30 天、按日清理 **[Target]** 定时任务（`AuditLogCleanupJob`）

**平台域（[Vision]）**：
- 各引擎 AOP → 统一审计管道（含 `traceId`）
- 商业版 WORM 对象存储 180 天 + 冷归档（PRD IAM-004）

### 3.7 跨模块权限码契约

> 命名与 [Bone-API-规范](../../architecture/Bone-API-规范.md) 及 PRD §4.x 对齐；JWT `authorities` 与 DB `iam_permission.code` **字符串一致**。

| 域 | 权限码示例（As-Is / 规划） | 消费方 |
|----|---------------------------|--------|
| IAM | `iam:accounts:read`, `iam:roles:write` … | `bone-iam` |
| 元数据 | `metadata:read`, `metadata:write` | `bone-metadata-server` `@PreAuthorize` |
| 扩展 | `extension:points:read`, `extension:points:write`, `extension:plugins:deploy` | `bone-extension-studio`；admin JWT 种子权限 |
| 主数据 | `masterdata:entities:read` … | **[Target]** `bone-masterdata` |
| 集成 | `integration:flows:write` … | **[Target]** `bone-integration` |

**约定**：`{domain}:{resource}:{action}` 或 `{domain}:{action}`；新增域须登记 init 数据或迁移脚本插入 `iam_permission`，并更新角色绑定、JWT 签发逻辑及 `BonePermissionCodes`（`packages/shared-types/src/bonePermissionCodes.ts`）。

### 4.8 与平台租户字段策略

- 业务表常用 **`tenant_id` + `biz_identity_code`**（`TenantAbstractEntity`）；**IAM 10 表当前仅 `tenant_id`**，不建模 `biz_identity_code`。

## 7. 性能与安全

### 7.1 性能优化

**As-Is 措施**：
- Token 黑名单与（[Target]）权限缓存：Redis（详见 §3.5.2）
- 审计日志：**[Target]** AOP 异步 + 队列削峰；当前为同步落库
- 数据库：`iam_account(tenant_id, username)`、`iam_role(tenant_id, code)` 等唯一索引；`iam_audit_log` 按 `(user_id, created_at)` 与 `(tenant_id)` 二级索引（见 `bone-init.sql`）
- 连接池：HikariCP（`bone-parent` 统一版本 5.1.0）

**性能指标（目标方向，非对外 SLA）**：

| 指标 | 目标值 | 来源 / 备注 |
|------|--------|-------------|
| 认证 P99 | <500ms | PRD §5.1 全平台核心 API SLO |
| 登录链路 P99 | <100ms（**[Target]** 压测基线） | 包含 BCrypt 鉴权与 JWT 签发 |
| 进程内 RBAC 决策 P99 | <50ms | 基于 JWT authorities 内存校验 |
| 最大并发用户 | ≥1000（PRD KR7 基线） | ≥10000 为扩展压测上限，须基准测试 + Runbook |

### 7.2 安全措施（业界最佳实践对标）

> **对标基线**：[OWASP ASVS 4.0](https://owasp.org/www-project-application-security-verification-standard/)、[NIST SP 800-63B](https://pages.nist.gov/800-63-3/sp800-63b.html)（认证）、[NIST SP 800-207](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-207.pdf)（零信任）、[OWASP Top 10 2021](https://owasp.org/Top10/)、CWE Top 25。

#### 7.2.1 身份与凭证（Authentication）

| 控制项 | As-Is | [Target] / [Vision] | 参考 |
|--------|-------|---------------------|------|
| 密码哈希 | BCrypt（cost ≥10） | Argon2id（[Target]） | NIST 800-63B §5.1.1 / OWASP ASVS V2.4 |
| 密码复杂度 | 长度 ≥8，混合字母/数字/符号 | NIST 800-63B 风格：**长度 ≥12** + **常见弱口令字典** 拒绝 | NIST 800-63B §5.1.1.2 |
| 密码轮换 | `password_updated_at` 记录 | **不强制周期轮换**（NIST 800-63B 反对强制），仅在风险事件后强制 | NIST 800-63B Appendix A |
| 账号锁定 | 连续失败计数 + `locked_at` 截止 | + 滑窗 IP/账号双维度限流 | OWASP ASVS V2.2.1 |
| MFA | — | **[Vision]** TOTP / WebAuthn（FIDO2） | NIST 800-63B §5.1.5 / OWASP ASVS V2.8 |
| 凭证存储 | `iam_account.password_hash` | + 字段级 KMS 信封加密（**[Target]**） | OWASP ASVS V2.10 |
| 默认密码 | init SQL 默认 `123456` ⚠️ | **首次启动强制改密**（[Target] CI/启动门禁） | CWE-521 |

#### 7.2.2 会话与令牌（JWT / Session）

| 控制项 | As-Is | [Target] / [Vision] |
|--------|-------|---------------------|
| Access Token TTL | 约 2h | **缩短至 ≤15min**（[Target]，配合 refresh 轮换） |
| Refresh Token | `iam_refresh_token` 持久化 + 撤销 | **轮换机制 As-Is**（`replaced_by` 已建模），需补 **复用检测**（重放即吊销链） |
| 黑名单 | Redis (key=jti)，登出/撤销 | 同 |
| 签名算法 | HS256（共享 secret） | **RS256 / EdDSA**（[Target]，密钥外置 KMS）；JWKS 端点轮换 |
| 密钥轮换 | 重启切换 | **热轮换**（JWKS `kid`，[Target]） |
| Claim 最小化 | `tenant_id` + `authorities` | 避免 PII / 角色名详情；权限码可经 introspection 拉取（[Vision]） |
| 重放防护 | 仅时钟漂移容忍 | + `jti` 单次性 + 关键操作 nonce |

> **参考**：[RFC 8725 — JWT Best Current Practices](https://datatracker.ietf.org/doc/html/rfc8725)、[OWASP JWT Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/JSON_Web_Token_for_Java_Cheat_Sheet.html)。

#### 7.2.3 授权与租户隔离（Authorization）

- **零信任默认拒绝**（NIST 800-207）：默认 `deny`，显式 `allow`；网关 + 服务双层校验
- **`tenant_id` 来源唯一**：JWT claim → `TenantContext`；**拒绝**接受 `?tenantId=` 或 Body 字段覆盖（架构 §8、§10.1）
- **MyBatis/JPA 拦截器** [Target]：自动注入 `tenant_id` WHERE / SET，避免遗漏导致越权
- **CSRF**：JWT Bearer 模式下默认禁用 cookie session（详见 `SecurityConfig` `SessionCreationPolicy.STATELESS`）；如启用 cookie 须 `SameSite=Strict` + CSRF token
- **管理平面 vs 数据平面**：`/iam/*` 与业务域 `/metadata/*`、`/integration/*` 走不同网关路由或独立网关，缩小暴露面（架构 §10.2）

#### 7.2.4 传输与存储

| 控制项 | As-Is | [Target] |
|--------|-------|----------|
| 外部传输 | HTTP（开发）/ HTTPS（部署侧反向代理） | TLS 1.2+（推荐 1.3）；HSTS |
| 服务间通讯 | HTTP | **mTLS**（Service Mesh / Sidecar，架构 §10.1） |
| 敏感字段 | 哈希存 / 明文存 | KMS 信封加密；国密 SM4（信创场景，PRD §5.4） |
| 配置密钥 | `application.yml` / env | **fail-fast** 缺失关键密钥拒启；外置配置中心 |

#### 7.2.5 速率限制与暴力防护

| 控制项 | As-Is | [Target] |
|--------|-------|----------|
| 登录失败计数 | 账号维度（`login_fail_count`） | **+ IP 维度 + 全局阈值**，Redis 令牌桶 |
| API 速率限制 | — | Gateway 限流（`spring-cloud-gateway` redis rate limiter） |

#### 7.2.6 输入与输出

- **输入校验**：JSR-303 / Hibernate Validator + 业务层二次校验（已用）

## 9. 监控与告警（SLO/SLI 对齐）

> 与 [BONE-总体架构](../../architecture/BONE-总体架构设计方案.md) 第二十四部分 NFR/SLO 对齐；遵循 [Google SRE](https://sre.google/sre-book/service-level-objectives/) RED + USE 方法论。

### 9.1 SLI / SLO

| SLI | SLO（目标方向） | 错误预算窗口 |
|-----|------------------|--------------|
| 登录 API 可用性（HTTP 2xx + 4xx 业务失败） | ≥ 99.99% | 30 天 |
| 登录 P95 延迟 | < 300ms | 30 天 |
| 登录 P99 延迟 | < 500ms | 30 天 |
| 鉴权 API（JWT 验签）P99 | < 50ms | 7 天 |
| Refresh 成功率 | ≥ 99.9% | 30 天 |
| 审计日志写入成功率 | ≥ 99.99% | 30 天 |

### 9.2 监控指标（RED + 安全）

| 类别 | 指标 | 实现 |
|------|------|------|
| **Rate（流量）** | `iam_login_requests_total`、`iam_refresh_requests_total` | Micrometer Prometheus（架构 §12） |
| **Errors（错误）** | `iam_login_failures_total{reason=…}`、`iam_jwt_invalid_total` | Counter + label |
| **Duration（时延）** | `iam_login_seconds`、`iam_authorize_seconds` | Histogram（含 P50/95/99） |
| **Saturation** | DB 连接池利用率、Redis 命中率 | Hikari + Redisson 指标 |
| **安全** | 连续失败账号数、单 IP 失败次数、新设备登录 | Counter + Gauge |
| **业务** | 在线会话数（refresh 活跃数）、租户活跃账号数 | Gauge |

### 9.3 告警（多级 + 黄金信号）

**告警规则**：

| 严重等级 | 条件 | 响应 |
|----------|------|------|
| **P1 Critical** | 登录 5xx 错误率 > 5%（5 min）、JWKS 拉取失败 | 立即电话 + 工单 |
| **P2 Warning** | 登录失败率 > 30%（5 min）、单 IP > 100 次失败 | 即时通讯通知 |
| **P3 Info** | 单账号锁定、新设备登录、权限变更高频 | 邮件/审计面板 |
| **安全事件** | 弱口令尝试、Token 重放检测、跨租户越权 | 安全工单 + 触发 IR |

**告警渠道**：邮件 / 企业微信 / 钉钉 / PagerDuty（**[Target]**）

### 9.4 日志管理

**日志分级**：
| 类型 | 内容 | 存储 / 留存 |
|------|------|-------------|
| **业务审计** | IAM 域操作（As-Is） / 平台全量（[Vision]） | `iam_audit_log` 30d；商业版 WORM 180d + 冷归档 |
| **安全日志** | 登录失败、Token 异常、越权 | ELK 90d **[Target]** |
| **应用日志** | INFO/WARN/ERROR、traceId | ELK / Loki 30d **[Target]** |
| **接入日志** | 网关 access log | 7d 滚动 |

**结构化日志**：JSON 格式，强制字段 `traceId / spanId / tenantId / accountId / action / result`，便于 ELK 检索与跨服务关联。

**敏感字段脱敏**：日志中的 `password`、`token`、`secret`、`Authorization`、`身份证`、`手机号` 必须经统一脱敏工具处理。

## 12. 总结

IAM 是 BONE 横切安全基线：

| 阶段 | 交付 |
|------|------|
| **As-Is** | 账号/角色/权限 RBAC、JWT + refresh + Redis 黑名单、IAM 域审计、行级租户隔离 |
| **[Target]** | 租户 REST、角色继承求值、Argon2id / RS256-JWKS、跨域权限码、网关注入 tenant、Gateway 限流、平台审计总线 PoC |
| **[Vision]** | 五层策略（ABAC/ReBAC）、MFA / WebAuthn、独立 authz-service、商业版 WORM + 等保三级交付包、字段级权限 |

详设 v2.3 已对齐 PRD §4.8、总体架构 §8/§10、`bone-init.sql` 以及业界基线（OWASP ASVS / NIST 800-63B / 800-207 / RFC 8725），消除「路线图当现状」与「跨文档契约漂移」两类常见歧义。任何 [Target] / [Vision] 落地前**必须**先出对应 ADR（§10），由架构 + 安全双评审通过。
