## 1. 模块概述

### 1.1 模块定位

IAM（Identity and Access Management）账号权限管理模块是BONE平台的核心安全组件，负责用户认证、授权和审计，确保系统的安全性和合规性。该模块采用零信任安全模型，实现细粒度的权限控制，支持多租户隔离，满足企业级安全合规要求。

### 1.2 核心功能

- **用户管理**：创建、编辑、禁用用户，管理用户信息
- **角色管理**：创建、编辑角色，分配权限
- **权限管理**：定义系统权限，管理权限分配
- **认证管理**：支持JWT认证，集成企业SSO
- **审计日志**：记录用户操作，支持WORM存储（商业版）
- **多租户管理**：支持多组织隔离（商业版）
- **多因素认证**：支持短信、邮箱、TOTP等多因素认证

### 1.3 设计目标

- **安全性**：采用零信任安全模型，实现细粒度的权限控制
- **可靠性**：确保认证和授权的高可用性
- **可扩展性**：支持大规模用户和权限管理
- **合规性**：满足等保三级要求
- **易用性**：提供简单直观的权限管理界面
- **性能**：确保认证和授权的高性能

## 2. 功能设计

### 2.1 用户管理

**功能描述**：管理系统用户，包括创建、编辑、禁用用户，管理用户信息。

**核心功能**：
- 创建用户：填写用户名、邮箱、密码，选择角色
- 编辑用户：修改用户信息、角色分配
- 禁用用户：禁止用户登录系统
- 重置密码：重置用户密码
- 查询用户：获取用户列表和详情
- 导入/导出用户：批量导入和导出用户信息

**业务规则**：
- 用户名必须唯一（同一租户内）
- 密码必须符合强度要求（长度≥8，包含大小写字母、数字、特殊字符）
- 用户状态包括：启用、禁用
- 支持LDAP/OAuth/SAML等企业SSO集成

### 2.2 角色管理

**功能描述**：管理系统角色，包括创建、编辑角色，分配权限。

**核心功能**：
- 创建角色：填写角色名称、描述
- 编辑角色：修改角色名称、描述
- 分配权限：为角色分配功能权限和数据权限
- 查询角色：获取角色列表和详情
- 角色继承：支持角色间的权限继承

**业务规则**：
- 角色名称必须唯一（同一租户内）
- 权限包括：功能权限、数据权限
- 支持角色继承，子角色继承父角色的所有权限

### 2.3 权限管理

**功能描述**：定义系统权限，管理权限分配。

**核心功能**：
- 创建权限：填写权限名称、代码、描述
- 编辑权限：修改权限名称、描述
- 分配权限：将权限分配给角色或用户
- 查询权限：获取权限列表和详情
- 权限层级：支持权限的层级结构

**业务规则**：
- 权限代码必须唯一
- 权限类型包括：菜单权限、操作权限、数据权限
- 支持权限的层级结构，子权限继承父权限的特性

### 2.4 审计日志

**功能描述**：记录用户操作，支持合规导出，并自动归档到冷存储。

**核心功能**：
- 日志记录：记录所有用户操作，包括登录、权限变更、配置修改等
- 日志查询：支持按时间、用户、操作类型等条件查询
- 日志导出：支持导出为Excel、CSV格式
- 日志存储：商业版使用WORM存储，社区版使用数据库存储

**业务规则**：
- 社区版：审计日志存储在关系型数据库，保留30天，支持按日清理
- 商业版：日志实时写入对象存储（MinIO/AWS S3/阿里云OSS），启用WORM锁定180天，之后自动归档到冷存储
- 审计日志包含：租户ID、用户ID、操作类型、资源ID、请求参数（脱敏）、结果、耗时、来源IP、User-Agent

### 2.5 多租户管理（商业版）

**功能描述**：管理多个租户，为每个租户分配独立的资源配额和用户，以实现多组织隔离。

**核心功能**：
- 创建租户：填写租户名称、管理员邮箱、资源配额
- 编辑租户：修改租户信息、资源配额
- 删除租户：删除不再需要的租户
- 查询租户：获取租户列表和详情
- 租户数据隔离：确保租户间数据完全隔离

**业务规则**：
- 支持三种隔离模式：独立数据库（性能最高）、共享数据库独立Schema（中等隔离）、共享Schema行级租户ID（默认）
- 租户内可设置子管理员，管理本租户用户和权限
- 租户配额包括：最大用户数、最大实体数、存储容量（GB）、API调用量（次/天）

## 3. 技术实现

### 3.1 技术栈选型

| 技术 | 版本 | 用途 |
|------|------|------|
| Java | 17+ | 核心开发语言 |
| Spring Boot | 3.2+ | 后端框架 |
| Spring Security | 6.2+ | 安全框架 |
| JWT | 0.11+ | 认证令牌 |
| MySQL | 8.0+ | 关系型数据库 |
| Redis | 7.0+ | 缓存（用于Token存储） |
| MinIO | 2024+ | 对象存储（用于审计日志WORM存储） |
| OAuth2/SAML/LDAP | - | 企业SSO集成 |

### 3.2 架构设计

**架构层次**：
- **前端层**：IAM管理界面，提供用户、角色、权限管理操作
- **应用层**：IAM服务，处理认证、授权和审计逻辑
- **引擎层**：Policy Decision Engine，负责权限决策
- **数据层**：存储用户、角色、权限和审计日志数据

**核心流程**：
1. 用户登录：用户输入用户名和密码，或通过SSO登录
2. 认证处理：IAM服务验证用户身份，生成JWT令牌
3. 授权检查：系统在执行操作前，检查用户是否有相应权限
4. 操作执行：用户执行操作，系统记录审计日志
5. 权限管理：管理员管理用户、角色和权限

### 3.4 认证机制

**认证流程**：
1. 用户发起登录请求
2. IAM服务验证用户身份
3. 生成JWT令牌，包含用户信息和权限
4. 返回JWT令牌给客户端
5. 客户端后续请求携带JWT令牌
6. IAM服务验证JWT令牌的有效性

**认证方式**：
- **用户名/密码认证**：传统的用户名和密码认证
- **SSO集成**：支持OAuth2、SAML、LDAP等企业SSO
- **多因素认证**：支持短信、邮箱、TOTP等多因素认证

**Token管理**：
- 使用JWT作为认证令牌
- Token有效期：默认2小时
- 支持刷新令牌：有效期7天
- Token存储：使用Redis存储Token黑名单

### 3.5 授权机制

**授权模型**：
- 基于RBAC（Role-Based Access Control）的权限控制
- 支持字段级权限
- 五层权限模型：Owner/Deny ABAC/ReBAC/RBAC/Default

**授权流程**：
1. 用户发起操作请求
2. 系统提取用户权限信息
3. Policy Decision Engine进行权限决策
4. 根据决策结果允许或拒绝操作
5. 记录操作审计日志

**权限缓存**：
- 使用Redis缓存用户权限信息
- 权限变更时主动失效缓存
- 缓存过期时间：30分钟

### 3.6 审计日志实现

**日志记录**：
- 使用AOP（面向切面编程）记录用户操作
- 记录操作类型、资源ID、请求参数（脱敏）、结果、耗时、来源IP、User-Agent

**日志存储**：
- **社区版**：存储在MySQL数据库，保留30天
- **商业版**：存储在对象存储（MinIO/AWS S3/阿里云OSS），启用WORM锁定180天

**日志查询**：
- 支持按时间、用户、操作类型、资源类型等条件查询
- 支持分页和排序
- 支持导出为Excel、CSV格式

## 7. 性能与安全

### 7.1 性能优化

**性能优化措施**：
- 权限缓存：使用Redis缓存用户权限信息
- Token管理：使用Redis存储Token黑名单
- 异步处理：审计日志记录异步处理
- 数据库优化：合理索引，优化查询
- 连接池：使用数据库连接池和HTTP连接池

**性能指标**：
- 认证响应时间：<100ms
- 授权检查时间：<50ms
- 系统能支持的最大并发用户数：≥10000
- 系统能支持的最大用户数：≥100000

### 7.2 安全措施

**安全措施**：
- 传输加密：使用TLS 1.3加密所有网络传输
- 存储加密：敏感数据使用AES-256加密存储
- 密码哈希：使用BCrypt对密码进行哈希处理
- 防暴力破解：登录失败次数限制，IP封禁
- 防CSRF攻击：使用CSRF令牌
- 防XSS攻击：输入验证和输出编码
- 权限控制：基于RBAC的细粒度权限控制

**安全策略**：
- 最小权限原则：用户只能访问必要的资源
- 定期密码更换：强制用户定期更换密码
- 多因素认证：敏感操作要求多因素认证
- 权限审计：定期审计权限分配情况

### 7.3 合规性

**合规要求**：
- 等保三级要求：满足信息系统安全等级保护三级要求
- GDPR合规：满足欧盟通用数据保护条例要求
- 行业合规：满足金融、政务等行业的合规要求

**合规措施**：
- 审计日志：记录所有用户操作，支持WORM存储
- 数据脱敏：API返回数据脱敏，日志敏感信息脱敏
- 访问控制：基于角色和权限的细粒度访问控制
- 安全审计：定期进行安全审计和渗透测试
