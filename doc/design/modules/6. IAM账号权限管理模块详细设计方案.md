## 1. 模块概述

### 1.1 模块定位

IAM（Identity and Access Management）账号权限管理模块是 BONE 平台的核心安全组件，负责认证、RBAC 授权与 IAM 域审计。**零信任、五层策略、等保三级**为演进目标（[Vision]），非当前 As-Is 承诺；实现边界见 §1.4。

### 1.2 核心功能

| 功能 | 成熟度 |
|------|--------|
| **账号管理**（`iam_account`） | **As-Is** |
| **角色管理**、角色-权限绑定 | **As-Is** |
| **权限目录**、权限树 | **As-Is** |
| **认证**（JWT + refresh + 黑名单） | **As-Is** |
| **IAM 域审计**（DB，30 天） | **As-Is** |
| **多租户管理**、配额、Schema/库隔离 | **[Target]** / 商业版 |
| **企业 SSO 联邦**（OAuth2/SAML/LDAP） | **[Target]** / 商业版（社区版 PRD ❌） |
| **平台全量审计 + WORM** | **[Vision]** / 商业版 |
| **MFA**、**ABAC/`iam_policy`**、**字段级权限** | **[Vision]** |

### 1.3 设计目标

> **注**：以下「零信任」「等保三级」均为 **演进目标（[Vision]）**，非当前 As-Is 对外承诺；现网 SLO/SLI 仪表化与压测基线见 §9.1 与 §7.1（标 **[Target]**）。

- **安全性**：以 RBAC + JWT scopes 为 As-Is 基线，逐步演进到零信任（NIST SP 800-207）—— 见 §7.2
- **可靠性**：认证与授权的高可用目标与告警仪表为 [Target]（§9）
- **可扩展性**：支持大规模用户和权限管理（数量级与压测产出绑定，§7.1）
- **合规性**：演进目标为等保三级（[Vision]，商业版交付包，§7.3）
- **易用性**：提供权限管理与分配界面
- **性能**：认证与授权的性能目标见 §7.1

## 2. 功能设计

### 2.1 账号管理

> **命名约定**：物理表与代码以 **`account`** 为准（`iam_account`、`AccountController`、API `/api/v1/iam/accounts`）；UI/产品文案保留「用户」便于业务理解。

**功能描述**：管理系统账号，包括创建、编辑、禁用账号，管理账号信息。

**核心功能**：
- 创建账号：填写用户名、邮箱、密码，选择角色
- 编辑账号：修改账号信息、角色分配（**As-Is** 经 `UpdateAccountCommandHandler` 编排，内部由 `AccountRoleBindingService` 写入 `iam_account_role`；`@Transactional` 在 Handler，**非** Controller 直注 Service）
- 禁用账号：禁止账号登录系统
- 重置密码：重置账号密码
- 查询账号：获取账号列表和详情
- 导入/导出账号：批量导入和导出账号信息

**业务规则**：
- `username` 在同一 `tenant_id` 内唯一（DDL 唯一键 `uk_iam_account_username`）
- 密码：**As-Is** 长度 ≥8 + 大小写/数字/符号；**[Target]** 对标 NIST 800-63B（长度 ≥12 + 弱口令字典；不再强制周期轮换）— 见 §7.2.1
- 账号状态：**As-Is** 启用(1)、禁用(0)、**锁定(2)**（连续登录失败，超出 PRD「仅启用/禁用」基线）
- 企业 SSO 联邦：**[Target]** / 商业版（PRD §3.1.3 社区版不含）

### 2.2 角色管理

**功能描述**：管理系统角色，包括创建、编辑角色，分配权限。

**核心功能**：
- 创建角色：填写角色名称、描述
- 编辑角色：修改角色名称、描述
- 分配权限：为角色分配功能权限和数据权限
- 查询角色：获取角色列表和详情
- 角色继承：**[Target]**（`parent_role_id` 已入 DDL，继承求值未实现）

**业务规则**：
- 角色名称/编码必须唯一（同一 `tenant_id` 内）
- 权限：**As-Is** 仅功能权限（权限码字符串）；**数据权限** 经角色绑定为 **[Target]**，需对应数据权限引擎实现（见 §1.5 IAM-16）
- 角色继承：**[Target]** — 子角色合并父角色权限集（实现前勿按 PRD 验收继承）
- **权限绑定闭环（前端契约）**：角色列表接口不返回已绑权限，编辑抽屉须先调 `GET /roles/{id}`（`RoleDetailResp.permissionIds`）预填，保存后调 `POST /roles/{id}/permissions`（replace 语义）提交；编辑时即使清空也须提交以解除全部绑定；权限变更后后端会驱逐相关账号的 authority 缓存

### 2.3 权限管理

**功能描述**：定义系统权限，管理权限分配。

**核心功能**：
- 创建权限：填写权限名称、代码、描述
- 编辑权限：修改权限名称、描述
- 分配权限：**As-Is** 仅分配给角色（`iam_role_permission`）；分配给账号直连为 **[Target]**（需 `iam_account_permission` 或回写收敛 PRD）
- 查询权限：获取权限列表和详情
- 权限层级：**As-Is** `parent_id` 树形展示

**业务规则**：
- 权限 `code` 全局唯一（`iam_permission` **无** `tenant_id` — 平台级权限目录，租户通过角色绑定消费）
- 权限类型：**As-Is** 列 `type`（如 `MENU` / `OPERATION`，见 init SQL 默认 `OPERATION`）
- 权限树：**As-Is**；菜单/操作/数据权限的 UI 与引擎校验逐步对齐 **[Target]**

### 2.4 审计日志

**功能描述**：分两层（勿混为单一能力）：

| 层级 | 范围 | 成熟度 |
|------|------|--------|
| **IAM 域审计** | 登录、账号/角色/权限变更等 IAM API | **As-Is** → `iam_audit_log` |
| **平台访问审计** | 元数据/主数据/集成/扩展等全域 API | **[Vision]** — 各服务 AOP + 统一索引/traceId |

**核心功能**：
- 日志记录：**As-Is** IAM 域操作；全平台操作 **[Vision]**
- 日志查询：支持按时间、用户、操作类型等条件查询
- 日志导出：支持导出为Excel、CSV格式
- 日志存储：商业版使用WORM存储，社区版使用数据库存储

**业务规则**：
- 社区版：审计日志存储在关系型数据库，保留30天，支持按日清理
- 商业版：日志实时写入对象存储（MinIO/AWS S3/阿里云OSS），启用WORM锁定180天，之后自动归档到冷存储
- 审计日志包含：租户ID、用户ID、操作类型、资源ID、请求参数（脱敏）、结果、耗时、来源IP、User-Agent

### 2.5 多租户管理（商业版）

**功能描述**：管理多个租户，为每个租户分配独立的资源配额和用户，以实现多组织隔离。

**核心功能**：
- 创建租户：填写租户名称、管理员邮箱、资源配额
- 编辑租户：修改租户信息、资源配额
- 删除租户：删除不再需要的租户
- 查询租户：获取租户列表和详情
- 租户数据隔离：确保租户间数据完全隔离

**业务规则**：
- **As-Is 默认**：共享数据库 + **`tenant_id` 行级隔离**（与 `bone-init.sql`、业务表一致）
- **[Target] / 商业版**：独立 Schema、独立库（§4.5 `isolation_mode` 扩展字段实现后启用）
- 租户内可设置子管理员，管理本租户用户和权限
- 租户配额包括：最大用户数、最大实体数、存储容量（GB）、API调用量（次/天）

### 2.6 组织机构管理

**功能描述**：以树形结构维护企业部门层级（`/organizations`），作为账号归属与数据权限的组织锚点。页面路径：`/iam#/organizations`。

**页面布局（主从结构，参考 Ant Design Pro / 飞书通讯录）**：

| 区域 | 内容 |
|------|------|
| 顶部统计行 | `StatisticCard.Group`：部门总数 / 启用中 / 根部门 / 最大层级（由树数据派生） |
| 左栏 · 部门结构 | `ProCard` + `Tree`（约 420px 定宽），节点悬停浮现行内操作（添加子部门 / 编辑 / 删除） |
| 右栏 · 部门详情 | `ProCard` + `Descriptions`：部门 ID、状态、上级部门、排序号、子部门数、层级；顶部 `Breadcrumb` 展示从根到当前节点的完整路径 |
| 右上工具栏 | 搜索框（防抖 300ms，走 `/depts/tree?keyword=`）、刷新、展开全部 / 折叠全部、新建根部门 |

**核心交互设计**：
- **富树节点**：图标 + 部门名 + 状态 Tag（启用/禁用）；操作按钮 `stopPropagation`，避免误触选中
- **详情联动**：单击树节点 → 右栏即时渲染详情；未选中时展示 `Empty` 引导态（"从左侧选择一个部门查看详情"）
- **上级部门选择**：新建/编辑抽屉使用 `TreeSelect` 替代旧版手填 `parentId` 数字；编辑时**禁用自身及其全部后代**（防环），顶级节点哨兵值 `'0'`，提交时归一为 `null`
- **删除保护（与后端契约对齐）**：后端 `DELETE /depts/{id}` 仅删除单节点、不级联。有子部门时前端直接拦截（提示"请先删除子部门"），无子部门才弹二次确认"删除后将不可恢复"——避免误删产生孤儿节点
- **ID 精度契约**：后端雪花 ID 以**字符串**序列化返回，前端全链路（树 key / selectedId / TreeSelect value / API path）以 `string` 承载，禁止 `Number()` 转换（超出 `Number.MAX_SAFE_INTEGER` 会精度丢失导致选中失效）

**业务规则**：
- 部门树接口支持 `keyword` 模糊检索（As-Is 已支持，前端已接入）
- **权限码契约**：接口由 `@PreAuthorize` 校验 `iam:depts:read`（树查看）/ `iam:depts:write`（新建/编辑/删除）；权限目录 `iam_permission` 须登记这两个码并绑定角色（否则依赖 admin JWT 回退权限，普通角色无法授权）
- 禁用部门不删除数据，仅标记状态；树中仍可见并标注
- 默认展开前两层，降低大组织下的浏览成本

### 2.7 菜单管理

**功能描述**：维护平台导航菜单与按钮级权限点（`/menus`），是 RBAC 授权的载体与前端路由的元数据源。页面路径：`/iam#/menus`。

**页面布局**：与 §2.6 同构的主从布局，差异点如下：

| 区域 | 内容 |
|------|------|
| 顶部统计行 | 菜单总数 / 菜单项 / 按钮权限 / 顶级菜单 / 最大层级 |
| 左栏 · 菜单结构 | 节点展示 图标 + 名称 + 类型 Tag（菜单=蓝 / 按钮=紫）+ 路径或权限码弱化文本 |
| 右栏 · 菜单详情 | 类型、路由路径、图标、权限码、排序号、子项数、层级 + Breadcrumb |

**核心交互设计**：
- **类型语义**：`type=1` 菜单（页面导航）、`type=2` 按钮（操作权限点），新建抽屉提供类型下拉并在表单内 tooltip 说明二者差异
- **权限码即授权锚点**：按钮型菜单必须填写 `permission`（如 `iam:users:read`），与 §3.7 跨模块权限码契约及 JWT `authorities` 对齐
- **上级菜单选择**：同 §2.6 的 `TreeSelect` + 自身/后代禁用 + `'0'` 哨兵归一策略
- **删除保护（与后端契约对齐）**：同 §2.6，后端仅删单节点不级联；有子项时前端拦截，无子项才二次确认
- **类型条件表单**：`type=按钮` 时隐藏"路由路径"、权限码必填（按钮的授权锚点）；`type=菜单` 时二者均可选
- **检索**：`keyword` 同时匹配名称 / 路径 / 权限码（As-Is 后端能力）

**业务规则**：
- 菜单树深度建议 ≤ 3 层（导航 + 页面 + 按钮），超出时统计卡"最大层级"提供预警信号
- **权限码契约**：菜单管理接口本身由 `@PreAuthorize` 校验 `iam:menus:read` / `iam:menus:write`；这两个码同样须登记 `iam_permission` 并绑定角色（与 §2.6 组织机构同批补齐）
- 删除菜单不影响已签发 JWT，但下一种子刷新后导航与权限同步收窄

### 2.8 前端 UI 设计规范

IAM 模块全部页面（账号 / 角色 / 权限 / 组织机构 / 菜单 / 审计日志 / 审计设置 / 租户）遵循统一设计语言，落地为共享壳组件 `ModulePage`（`bone-iam-app/src/components/ModulePage.tsx`）：

1. **统一页面骨架**：`PageContainer`（标题 + 描述 + 右上操作区）→ 可选统计行 → `ProCard` 正文；列表页搜索/刷新/新建统一放 `extra` 工具栏
2. **仪表化统计行**：`StatisticCard.Group` 顶部横排关键指标（总数、状态分布等），数据由列表接口全量派生（管理台数据规模有限，`pageSize≤500` 一次拉取）
3. **表格最佳实践**：首列实体标识（头像/图标 + 主文本 + 弱化副文本）、状态列用带图标 `Tag`、长文本 `ellipsis`、雪花 ID / 邮箱支持 `copyable`、操作列统一"编辑 / 状态切换 / 删除（Popconfirm 危险确认）"文字链
4. **表单容器选型**：字段较多的创建/编辑表单统一用 `Drawer`（右滑、宽 440–480、底部固定 取消/保存），短表单（重置密码、配额）保留 `Modal`
5. **搜索交互**：关键词搜索统一防抖 300ms、`allowClear`、输入即查（后端 `keyword` 参数），重置按钮一键清空全部筛选
6. **危险操作**：删除一律 `Popconfirm`/`Modal.confirm` 二次确认，并**明示影响范围**（子节点数、关联账号/角色失效等）
7. **一致性**：新建/编辑抽屉标题带上下文（`编辑角色 · 运维管理员`）；成功/失败反馈统一走 `App.useApp()` message；`tsc --noEmit` 保持零错误

### 2.9 平台管理员与租户管理员（双视角模型）

**设计结论**（参考阿里云 RAM / 飞书 / 钉钉 / Salesforce 等业界 SaaS 多租户实践）：

1. **补充两类管理员：建议**。平台管理员（运营方）与租户管理员（企业方）是 SaaS 平台的标配角色分界；实现载体是**角色**而非新账号类型（`is_admin` 仍专指平台超管，租户管理员经角色-权限码授权）。
2. **组织机构按租户隔离：必须，且读侧已隔离**。`iam_dept`/`iam_menu`/`iam_account`/`iam_role` 均带 `tenant_id`，读侧 `resolveTenantFilter` 对租户上下文 >0 强制过滤；写侧 `resolveTenantId` 加固为**租户上下文 >0 时强制本租户**（命令传入其他 tenantId 视为越权企图直接忽略），平台管理员（tenant 0）代操作时可显式指定租户。
3. **双登录页：不建议**。业界主流是**单登录入口 + 登录后按身份分流**（阿里云/飞书/钉钉模式）；双登录页仅在品牌/安全域完全分离时使用。Bone 为 qiankun 单 shell，采用单登录页 + 前端路由守卫 + 后端权限码双层兜底。

**角色定义**：

| 角色 | tenant_id | 职责 | 可授予的权限码域 |
|------|-----------|------|-----------------|
| 平台管理员（`SUPER_ADMIN`） | 0 | 租户全生命周期（创建/配额/禁用/删除）、权限目录维护、平台级菜单、全局审计 | 全部（含平台域 `iam:tenants:*`、`iam:permissions:*`、`iam:sessions:*`） |
| 租户管理员（`TENANT_ADMIN_<code>`） | >0（随租户） | 本租户账号/角色/组织机构/菜单/审计 | 仅租户域（`iam:accounts:*`、`iam:roles:*`、`iam:depts:*`、`iam:menus:*`、`iam:audit:*`） |

**租户创建初始化流程（As-Is 已实现）**：`POST /tenants` 同事务完成 租户落库 → 创建 `TENANT_ADMIN_<code>` 角色 → 绑定租户域权限码 → 创建管理员账号（用户名 `<code>_admin`，随机初始密码）→ 账号-角色绑定。响应返回 `initialPassword` **仅此一次**，由平台管理员转交租户；任一步失败整体回滚（`TenantAdminBootstrapSupport`，`Propagation.MANDATORY`）。

> **⚠ 实现要点（ADR-0029 写侧租户覆写）**：创建租户的是平台管理员（上下文 `tenantId=0`），而 SDK 写路径 `resolveInsertTenantValue` 以可信 `TenantContext` **覆写**实体 `tenantId`——bootstrap 内的角色/账号/账号-角色绑定必须包在 `TenantContextRunner.callAs(tenantId, …)` 中执行（"平台管理员代租户写"的标准入口，ADR-0031 D3），否则三者被静默落到 `tenant_id=0`，租户管理员永远登录不出本租户身份（症状：登录响应 `tenantId=0`/`tenantName=平台`，日志出现 `Entity tenantId … overridden by TenantContext 0` WARN）。权限点与角色-权限绑定表为平台级数据（无 `tenant_id` 列），不受上下文影响，可留在平台上下文读写。

**登录与身份分流（As-Is 已实现）**：
- `POST /login` 响应的 `account` 增加 `tenantId` / `tenantName`；`tenantId=0` 为平台管理员视角，`>0` 为租户管理员视角
- 前端登录后按 `tenantId` 分流存储，`/tenants`、`/permissions` 平台级路由由 `PlatformRoute` 守卫保护——租户管理员访问自动重定向 `/accounts`
- 后端兜底：租户管理员角色不含平台域权限码，`@PreAuthorize` 直接 403（前端守卫仅是体验优化，**安全边界在权限码**）

**隔离矩阵**：

| 资源 | 隔离方式 | 说明 |
|------|---------|------|
| 账号 / 角色 / 组织机构 / 审计日志 | `tenant_id` 行级隔离 | 租户上下文 >0 强制本租户；用户名唯一键为 `(tenant_id, username)`，跨租户允许重名 |
| 菜单 | `tenant_id` 行级隔离 | 租户自管本租户菜单树；`/menus/current` 按登录租户返回 |
| 权限目录（`iam_permission`） | **平台级共享，无 tenant_id** | 租户通过角色绑定消费，不可自行创建权限码 |
| 租户本身（`iam_tenant`） | 平台专属 | 仅平台管理员可 CRUD；`id=0` 为平台租户、禁删 |

**[Target] 演进项**：初始密码改为随机生成 + 邮件下发/首次登录强制改密（当前 `requirePasswordChange` 已对弱口令生效）；租户管理员细粒度授权（按角色拆分组织/菜单/审计管理权）；运营后台独立部署域（仅在合规要求时启用）。

## 3. 技术实现

### 3.1 技术栈选型

| 技术 | 版本 | 用途 |
|------|------|------|
| Java | 17+ | 核心开发语言 |
| Spring Boot | 3.2+ | 后端框架 |
| Spring Security | 6.2+ | 安全框架 |
| JWT | 0.11+ | 认证令牌 |
| MySQL | 8.0+ | 关系型数据库 |
| Redis | 7.0+ | 缓存（用于Token存储） |
| MinIO | 2024+ | 对象存储（用于审计日志WORM存储） |
| OAuth2/SAML/LDAP | - | 企业SSO集成 |

### 3.2 架构设计

**架构层次**：
- **前端层**：`bone-iam-app` — 账号/角色/权限/审计管理
- **应用层**：`bone-iam` — 认证、RBAC 编排、IAM 域审计
- **授权（As-Is）**：各业务服务进程内 **Spring Security** + JWT 中的 `authorities`（权限码）；**非**独立 PDE 微服务
- **授权（[Target]）**：进程内 `PolicyEvaluator`（可读 `iam_policy`）
- **授权（[Vision]）**：独立 `authz-service`（总体架构规划示例端口 8082，须 ADR）
- **数据层**：MySQL `iam_*` 表 + Redis（Token 黑名单/权限缓存）

**核心流程（As-Is）**：
1. 登录 → `AuthController` 签发 JWT（含 `tenant_id`、权限码列表）
2. 业务请求 → 网关/服务校验 JWT → `@PreAuthorize` / `hasAuthority('domain:action')`
3. IAM 变更 → 写 `iam_audit_log`；权限变更后 **[Target]** 失效 Redis 权限缓存

### 3.3 Java工程结构

> 与 [`《Bone-DDD-最终实践方案》`](../../architecture/Bone-DDD-最终实践方案.md) 对齐：六边形 + CQRS，持久化统一使用 **bone-metadata-sdk**。**真源以仓库目录为准**，本节仅描述顶层组成；详细类列表由 Docs-as-Code 收集器扫描（[附录 C](#附录-c-as-is-证据ci-派生)）。

**As-Is 与目标态对齐说明**：

- 聚合根命名已统一为 `Account`（旧 `User*` 已迁移），`iam_account` 与 `Account` 对应；遗留 `CreateUserCommand` 等 DTO 类视为兼容残留，新代码必须使用 `Account` 系。
- 外部 SSO 实现（`OAuth2SsoClient` / `SamlSsoClient` / `LdapSsoClient`）为 **[Target]/商业版**；社区版仅留 `GET /sso/config` 与 `GET /sso/callback` 未配置 501（`IamErrorCodes.SSO_NOT_CONFIGURED`），MFA 同理（`MfaController` enroll/verify 501）。
- 通用响应 `ApiResponse` / `PageResult` 与异常基类来自 `bone-core`，本模块**不重复**维护。
- 仓库暂无 `Dockerfile`，部署见 [doc/deployment](../../deployment/) **[Vision]**。

> 历史 `User*` 全量目录树已删除（保留 `git log` 可查）；任何新增类列表请通过收集器/源码访问，**不要再回写到详设**。

### 3.4 认证机制（**As-Is**）

**认证流程**：
1. `POST /api/v1/iam/login` — 校验 `iam_account`（BCrypt）
2. 签发 access JWT + 持久化 `iam_refresh_token`
3. 客户端 `Authorization: Bearer`；`POST /refresh` 轮换 refresh；`POST /logout` 撤销
4. 各服务 `JwtAuthenticationFilter` 解析 JWT；**`tenant_id` 须来自 JWT claim**，禁止仅用请求体覆盖（总体架构 §8、§10.1）

**认证方式**：
| 方式 | 成熟度 |
|------|--------|
| 用户名/密码 | **As-Is** |
| Refresh + Redis 黑名单 | **As-Is**（无 Redis 时仅撤销 refresh，见 IAM-01） |
| SSO 配置读取 | **As-Is** 占位（`GET /sso/config`） |
| OAuth2 / SAML / LDAP 联邦 | **[Target]** / 商业 |
| MFA | **[Vision]** |

**Token 管理**：access 默认约 2h；refresh 约 7d；黑名单 Redis **[As-Is]**。

### 3.5 授权机制（分层）

#### 3.5.1 As-Is — RBAC + 权限码

> **术语统一**：JWT 载荷使用 claim **`scopes`**（字符串数组）；进入 Spring Security 后才转为 `GrantedAuthority`。下文除特别标注 Spring 内部时统称「权限码 / scopes」。

- 账号 → `iam_account_role` → 角色 → `iam_role_permission` → `iam_permission.code`（`AccountAuthoritiesQueryHandler`）
- `AssignPermissionCommandHandler`（写事务边界）内部调用 `RolePermissionBindingService` 维护 `iam_role_permission`；变更后 `AuthorityCacheEvictionService` 失效持有该角色的账号缓存（两者均为 Handler 内部复用的 S1/S2 service，**禁止 Controller 直接注入**）
- 登录/刷新时将权限码写入 JWT claim **`scopes`**；`JwtAuthenticationFilter` 映射为 `SimpleGrantedAuthority` 注入 `SecurityContext`
- IAM 管理 API 经 `@EnableMethodSecurity` + 方法级 `@PreAuthorize("hasAuthority('iam:…:read|write')")` 校验（**As-Is**，避免「任意有效 JWT 即可调任意管理 API」的越权风险）
- Redis 可选：`iam:authz:scopes:account:{id}`，TTL 30min（无 Redis 时直查 DB）
- `bone-init.sql` 预置超级管理员角色权限绑定；无绑定的管理员回退 `DefaultPermissionCodes.adminFallback()`
- **无**独立 Policy Decision Engine 进程；**无** `iam_policy` 运行时求值

#### 3.5.2 [Target]

- 进程内策略求值（读 `iam_policy` + RBAC 合并）
- 角色继承闭包计算；权限变更 → Redis 缓存主动失效（**部分实现**：`AuthorityCacheEvictionService`，见 §3.5.1）
- 用户直连权限（若保留 PRD 表述）→ `iam_account_permission` + API

#### 3.5.3 [Vision]

- 五层模型：Owner / Deny(ABAC) / ReBAC / RBAC / Default — **须独立 ADR**（[BONE-总体架构](../../architecture/BONE-总体架构设计方案.md) §10.2）
- 字段级权限、独立 `authz-service`、与元数据字段 ACL 联动

**权限缓存 [Target]**：Redis 缓存用户权限集，TTL 约 30min；与架构 H-008「最终一致 + 对账」对齐。

### 3.6 审计日志实现

**IAM 域（As-Is）**：
- IAM 模块记录登录、账号/角色/权限变更等
- 落库 `iam_audit_log`（列集见 §4.4，**以 init SQL 为准**）
- 社区版保留 30 天、按日清理 **As-Is**（`AuditLogCleanupJob`，读取 `iam_audit_settings.retention_days`）

**平台域（[Vision]）**：
- 各引擎 AOP → 统一审计管道（含 `traceId`）
- 商业版 WORM 对象存储 180 天 + 冷归档（PRD IAM-004）

### 3.7 跨模块权限码契约

> 命名与 [Bone-API-规范](../../architecture/Bone-API-规范.md) 及 PRD §4.x 对齐；JWT `authorities` 与 DB `iam_permission.code` **字符串一致**。

| 域 | 权限码示例（As-Is / 规划） | 消费方 |
|----|---------------------------|--------|
| IAM | `iam:accounts:read|write`、`iam:roles:read|write`、`iam:permissions:read|write`、`iam:audit:read|write`、`iam:tenants:read|write`、`iam:depts:read|write`、`iam:menus:read|write` | `bone-iam` 方法级 `@PreAuthorize`（As-Is）|
| 元数据 | `metadata:read`, `metadata:write` | `bone-metadata-server` `@PreAuthorize` |
| 扩展 | `extension:points:read`, `extension:points:write`, `extension:plugins:deploy` | `bone-extension-studio`；admin JWT 种子权限 |
| 主数据 | `masterdata:entities:read` … | **[Target]** `bone-masterdata` |
| 集成 | `integration:flows:write` … | **[Target]** `bone-integration` |

**约定**：`{domain}:{resource}:{action}` 或 `{domain}:{action}`；JWT claim 名固定为 **`scopes`**（与 OAuth2 习惯一致），下游服务统一映射为 `GrantedAuthority`。新增域须登记 init 数据或迁移脚本插入 `iam_permission`，并更新角色绑定、JWT 签发逻辑及 `BonePermissionCodes`（`bone-frontend/packages/shared-types/src/bonePermissionCodes.ts`）。

### 4.8 与平台租户字段策略

- 业务表常用 **`tenant_id` + `biz_identity_code`**（`TenantAbstractEntity`）；**IAM 10 表当前仅 `tenant_id`**，不建模 `biz_identity_code`。

- 若未来同一租户多业务身份：**[Target]** 扩展 JWT claim + IAM 会话上下文，须与元数据/主数据消费链联合 ADR。

|------|--------|-------------|
| 认证 P99 | <500ms | PRD §5.1 全平台核心 API SLO |

### 7.2 安全措施（对标 OWASP / NIST / RFC 8725）

> **对标基线**：[OWASP ASVS 4.0](https://owasp.org/www-project-application-security-verification-standard/)、[NIST SP 800-63B](https://pages.nist.gov/800-63-3/sp800-63b.html)（认证）、[NIST SP 800-207](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-207.pdf)（零信任）、[OWASP Top 10 2021](https://owasp.org/Top10/)、CWE Top 25。

#### 7.2.1 身份与凭证（Authentication）

| 控制项 | As-Is | [Target] / [Vision] | 参考 |
|--------|-------|---------------------|------|
| 密码哈希 | BCrypt（cost ≥10） | Argon2id（[Target]） | NIST 800-63B §5.1.1 / OWASP ASVS V2.4 |
| 密码复杂度 | 长度 ≥8，混合字母/数字/符号 | NIST 800-63B 风格：**长度 ≥12** + **常见弱口令字典** 拒绝 | NIST 800-63B §5.1.1.2 |
| 密码轮换 | `password_updated_at` 记录 | **不强制周期轮换**（NIST 800-63B 反对强制），仅在风险事件后强制 | NIST 800-63B Appendix A |
| 账号锁定 | 连续失败计数 + `locked_at` 截止 | + 滑窗 IP/账号双维度限流 | OWASP ASVS V2.2.1 |
| MFA | — | **[Vision]** TOTP / WebAuthn（FIDO2） | NIST 800-63B §5.1.5 / OWASP ASVS V2.8 |
| 凭证存储 | `iam_account.password_hash` | + 字段级 KMS 信封加密（**[Target]**） | OWASP ASVS V2.10 |
| 默认密码 | init SQL 默认 `123456` ⚠️ | **首次启动强制改密**（[Target] CI/启动门禁） | CWE-521 |

#### 7.2.2 会话与令牌（JWT / Session）

| 控制项 | As-Is | [Target] / [Vision] |
|--------|-------|---------------------|
| Access Token TTL | 约 2h | **缩短至 ≤15min**（[Target]，配合 refresh 轮换） |
| Refresh Token | `iam_refresh_token` 持久化 + 撤销 | **轮换机制 As-Is**（`replaced_by` 已建模），需补 **复用检测**（重放即吊销链） |
| 黑名单 | Redis (key=jti)，登出/撤销 | 同 |
| 签名算法 | HS256（共享 secret） | **RS256 / EdDSA**（[Target]，密钥外置 KMS）；JWKS 端点轮换 |
| 密钥轮换 | 重启切换 | **热轮换**（JWKS `kid`，[Target]） |
| Claim 最小化 | `tenant_id` + `authorities` | 避免 PII / 角色名详情；权限码可经 introspection 拉取（[Vision]） |
| 重放防护 | 仅时钟漂移容忍 | + `jti` 单次性 + 关键操作 nonce |

> **参考**：[RFC 8725 — JWT Best Current Practices](https://datatracker.ietf.org/doc/html/rfc8725)、[OWASP JWT Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/JSON_Web_Token_for_Java_Cheat_Sheet.html)。

#### 7.2.3 授权与租户隔离（Authorization）

- **零信任默认拒绝**（NIST 800-207）：默认 `deny`，显式 `allow`；网关 + 服务双层校验
- **`tenant_id` 来源唯一**：JWT claim → `TenantContext`；**拒绝**接受 `?tenantId=` 或 Body 字段覆盖（架构 §8、§10.1）
- **MyBatis/JPA 拦截器** [Target]：自动注入 `tenant_id` WHERE / SET，避免遗漏导致越权
- **CSRF**：JWT Bearer 模式下默认禁用 cookie session（详见 `SecurityConfig` `SessionCreationPolicy.STATELESS`）；如启用 cookie 须 `SameSite=Strict` + CSRF token
- **管理平面 vs 数据平面**：`/iam/*` 与业务域 `/metadata/*`、`/integration/*` 走不同网关路由或独立网关，缩小暴露面（架构 §10.2）

#### 7.2.4 传输与存储

| 控制项 | As-Is | [Target] |
|--------|-------|----------|
| 外部传输 | HTTP（开发）/ HTTPS（部署侧反向代理） | TLS 1.2+（推荐 1.3）；HSTS |
| 服务间通讯 | HTTP | **mTLS**（Service Mesh / Sidecar，架构 §10.1） |
| 敏感字段 | 哈希存 / 明文存 | KMS 信封加密；国密 SM4（信创场景，PRD §5.4） |
| 配置密钥 | `application.yml` / env | **fail-fast** 缺失关键密钥拒启；外置配置中心 |

#### 7.2.5 速率限制与暴力防护

| 控制项 | As-Is | [Target] |
|--------|-------|----------|
| 登录失败计数 | 账号维度（`login_fail_count`） | **+ IP 维度 + 全局阈值**，Redis 令牌桶 |
| API 速率限制 | — | Gateway 限流（`spring-cloud-gateway` redis rate limiter） |
| 验证码 | — | 失败 ≥ N 次触发 CAPTCHA |
| 异常登录检测 | — | 异地/异常 UA → 风险评分，强制 MFA（[Vision]） |

#### 7.2.6 输入与输出

- **输入校验**：JSR-303 / Hibernate Validator + 业务层二次校验（已用）
- **SQL 注入**：MyBatis 参数化（**禁** `${}` 拼接 SQL，除排序字段白名单）
- **XSS**：前端 React 自动转义；后端响应体不允许返回未转义 HTML
- **日志注入**：`%n` 过滤；审计 `parameters` 字段长度上限 + 脱敏
- **脱敏字段** [Target]：手机号、邮箱、IDCard、token 串均按统一规则脱敏

#### 7.2.7 供应链与构建（DevSecOps）

> 与 [BONE-总体架构](../../architecture/BONE-总体架构设计方案.md) §10.4 对齐。

| 控制项 | As-Is | [Target] |

| **Rate（流量）** | `iam_login_requests_total`、`iam_refresh_requests_total` | Micrometer Prometheus（架构 §12） |
| **Errors（错误）** | `iam_login_failures_total{reason=…}`、`iam_jwt_invalid_total` | Counter + label |
| **Duration（时延）** | `iam_login_seconds`、`iam_authorize_seconds` | Histogram（含 P50/95/99） |
| **Saturation** | DB 连接池利用率、Redis 命中率 | Hikari + Redisson 指标 |
| **安全** | 连续失败账号数、单 IP 失败次数、新设备登录 | Counter + Gauge |
| **业务** | 在线会话数（refresh 活跃数）、租户活跃账号数 | Gauge |

### 9.3 告警（多级 + 黄金信号）

**告警规则**：

| 严重等级 | 条件 | 响应 |
|----------|------|------|
| **P1 Critical** | 登录 5xx 错误率 > 5%（5 min）、JWKS 拉取失败 | 立即电话 + 工单 |
| **P2 Warning** | 登录失败率 > 30%（5 min）、单 IP > 100 次失败 | 即时通讯通知 |
| **P3 Info** | 单账号锁定、新设备登录、权限变更高频 | 邮件/审计面板 |
| **安全事件** | 弱口令尝试、Token 重放检测、跨租户越权 | 安全工单 + 触发 IR |

**告警渠道**：邮件 / 企业微信 / 钉钉 / PagerDuty（**[Target]**）

### 9.4 日志管理

**日志分级**：
| 类型 | 内容 | 存储 / 留存 |
|------|------|-------------|
| **业务审计** | IAM 域操作（As-Is） / 平台全量（[Vision]） | `iam_audit_log` 30d；商业版 WORM 180d + 冷归档 |
| **安全日志** | 登录失败、Token 异常、越权 | ELK 90d **[Target]** |
| **应用日志** | INFO/WARN/ERROR、traceId | ELK / Loki 30d **[Target]** |
| **接入日志** | 网关 access log | 7d 滚动 |

**结构化日志**：JSON 格式，强制字段 `traceId / spanId / tenantId / accountId / action / result`，便于 ELK 检索与跨服务关联。

**敏感字段脱敏**：日志中的 `password`、`token`、`secret`、`Authorization`、`身份证`、`手机号` 必须经统一脱敏工具处理。

## 12. 总结

IAM 是 BONE 横切安全基线：

| 阶段 | 交付 |
|------|------|
| **As-Is** | 账号/角色/权限 RBAC（方法级 `@PreAuthorize`）、JWT + refresh + Redis 黑名单、`TenantContext` 自动注入、IAM 域审计 + `iam_audit_settings`、`TenantController` 基础 CRUD、`MfaController` 状态 + 501 契约、`iam-v1.yaml` 单源 + Gateway IT |
| **[Target]** | `TenantController` DELETE/quota、角色继承求值、Argon2id / RS256-JWKS、跨域权限码注册表、网关注入 tenant、Gateway 限流、平台审计总线 PoC、审计 AOP 异步、IAM-12～18 |
| **[Vision]** | 五层策略（ABAC/ReBAC）、MFA / WebAuthn、独立 authz-service、商业版 WORM + 等保三级交付包、字段级权限 |

详设 v2.4 已对齐 PRD §4.8、总体架构 §8/§10、`bone-init.sql`（**10 张 IAM 表**，含 `iam_audit_settings`）以及 OWASP ASVS / NIST 800-63B / 800-207 / RFC 8725 基线，并通过 Docs-as-Code 收集器在 CI 中校验文档 / 代码漂移，消除「路线图当现状」与「跨文档契约漂移」两类常见歧义。任何 [Target] / [Vision] 实现前**必须**先出对应 ADR（§10），由架构 + 安全双评审通过。
