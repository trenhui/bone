## 0. 数据血缘与 catalog 协同（业界最佳实践）

| 关系 | As-Is | 演进 |
|------|-------|------|
| **业务实体（`meta_*`）→ 主数据实体（`mdm_*`）** | `POST /api/v1/masterdata/entities/convert?businessEntityId=`（`ConvertFromBusinessEntityCommandHandler`） | 决策真源：[ADR-0017](../../architecture/adr/0017-masterdata-catalog-sync.md)（阶段一复制+来源追溯；阶段二事件） |
| **mdm 实体血缘** | 字段 `source_entity_id` 记录来源 | 工具化血缘图（OpenLineage / Marquez 风格）**[Vision]** |
| **质量回写** | `DataQualityController#performCheck` → 报告 | 阈值跌穿写 `bone-platform/bone-integration` 死信 → 通知 **[Target]** |
| **金标准发布** | `PublishMasterDataRecordCommandHandler` | 与 `meta_entity.status=1`（已发布）联动校验 **[Target]** |

> 业界对标：Salesforce MDM、Informatica MDM、Atlan/DataHub 血缘图。Bone 阶段一聚焦 **可追溯**（来源 + 转换 + 消费侧 API），暂不实现可视化血缘 UI。  
> **横切 API 契约**：[Bone-API-规范.md](../../architecture/Bone-API-规范.md) §6–§8 · 本模块 §5.0。

## 1. 模块概述

主数据管理模块是 BONE 平台的核心数据治理模块，负责企业核心业务实体的统一管理、数据质量控制和主数据生命周期管理，为企业提供高质量、一致、可信的主数据服务。

**核心目标**：
- 提供主数据的统一建模和管理能力
- 确保主数据的一致性和完整性
- 实现主数据的质量监控和治理
- 支持主数据的生命周期管理
- 提供主数据的标准化和规范化

## 2. 功能设计

### 2.1 主数据模型管理

**功能描述**：支持主数据模型的创建、编辑、发布和版本管理，定义主数据的结构和属性。

**详细功能**：
- **模型创建**：创建主数据模型，定义模型名称、描述、属性等
- **属性管理**：添加、编辑、删除模型属性，设置属性类型、长度、约束等
- **关系管理**：定义主数据模型之间的关系
- **版本管理**：管理模型的版本历史，支持版本对比和回滚
- **模型发布**：将模型从草稿状态发布为可用状态

**用户故事**：
> 作为数据管理员，我希望创建和管理主数据模型，以便统一管理企业核心数据。

### 2.2 主数据管理

**功能描述**：支持主数据的创建、编辑、审核、发布和生命周期管理。

**详细功能**：
- **数据录入**：手动录入主数据，支持批量导入
- **数据编辑**：修改主数据的属性值
- **数据审核**：审核主数据的变更，确保数据质量
- **数据发布**：将主数据从草稿状态发布为可用状态
- **生命周期管理**：管理主数据的状态，如启用、禁用、归档等
- **数据历史**：记录主数据的变更历史

**用户故事**：
> 作为数据管理员，我希望管理主数据的完整生命周期，确保数据的准确性和一致性。

### 2.3 数据质量监控

**功能描述**：监控主数据的质量，检测和处理数据质量问题。

**详细功能**：
- **质量规则**：定义数据质量规则，如唯一性、完整性、准确性等
- **质量检测**：根据规则检测数据质量问题
- **质量报告**：生成数据质量报告，展示质量指标和问题
- **质量修复**：提供数据质量问题的修复建议和工具
- **质量趋势**：监控数据质量的变化趋势

**用户故事**：
> 作为数据质量分析师，我希望监控主数据的质量，及时发现和解决数据质量问题。

### 2.4 主数据集成

**功能描述**：支持主数据与其他系统的集成，确保数据的一致性和同步。

**详细功能**：
- **集成配置**：配置与其他系统的集成参数
- **数据同步**：同步主数据到其他系统
- **变更通知**：当主数据发生变更时通知相关系统
- **集成监控**：监控集成状态和同步结果
- **错误处理**：处理集成过程中的错误

**用户故事**：
> 作为系统集成专员，我希望配置主数据与其他系统的集成，确保数据的一致性。

### 3.3 关键实现

#### 3.3.1 主数据模型管理

> **命名提示**：以下示例为 To-Be 设计示意；实际代码（As-Is）类名见 §10.3 核心类表。
> `MasterDataModel` → `MasterDataEntity`，`CreateMasterDataModelCommandHandler` → `CreateMasterDataEntityHandler`，
> `MasterDataModelRepository` → `MasterDataEntityRepository`。

```java
package com.bone.masterdata.application.command.handler;

import com.bone.masterdata.application.command.cmd.CreateMasterDataModelCommand;
import com.bone.masterdata.domain.model.MasterDataModel;
import com.bone.masterdata.domain.model.vo.ModelName;
import com.bone.masterdata.domain.repository.MasterDataModelRepository;
import com.bone.core.exception.BizException;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Component;
import org.springframework.transaction.annotation.Transactional;

@Component
@RequiredArgsConstructor
public class CreateMasterDataModelCommandHandler {
    private final MasterDataModelRepository modelRepository;

    @Transactional
    public Long handle(CreateMasterDataModelCommand command) {
        ModelName modelName = new ModelName(command.getName());

        if (modelRepository.existsByName(command.getName())) {
            throw new BizException("MD_MODEL_NAME_DUPLICATED", "模型名称已存在");
        }

        MasterDataModel model = MasterDataModel.create(
            command.getId(),
            command.getTenantId(),
            modelName,
            command.getDescription()
        );

        modelRepository.save(model);

        return model.getId().getValue();
    }
}
```

#### 3.3.2 主数据管理

> **命名提示**：To-Be 示意。As-Is：`MasterData` → `MasterDataRecord`，`CreateMasterDataCommandHandler` → `CreateMasterDataRecordHandler`，
> `MasterDataRepository` → `MasterDataRecordRepository`，`MasterDataModel` → `MasterDataEntity`，`MasterDataModelRepository` → `MasterDataEntityRepository`。

```java
package com.bone.masterdata.application.command.handler;

import com.bone.masterdata.application.command.cmd.CreateMasterDataCommand;
import com.bone.masterdata.domain.model.MasterData;
import com.bone.masterdata.domain.model.MasterDataModel;
import com.bone.masterdata.domain.repository.MasterDataRepository;
import com.bone.masterdata.domain.repository.MasterDataModelRepository;
import com.bone.core.exception.NotFoundException;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Component;
import org.springframework.transaction.annotation.Transactional;

@Component
@RequiredArgsConstructor
public class CreateMasterDataCommandHandler {
    private final MasterDataRepository masterDataRepository;
    private final MasterDataModelRepository modelRepository;

    @Transactional
    public Long handle(CreateMasterDataCommand command) {
        MasterDataModel model = modelRepository.findById(command.getModelId())
                .orElseThrow(() -> new NotFoundException("MD_MODEL_NOT_FOUND", "模型不存在"));

        MasterData masterData = MasterData.create(
            command.getId(),
            command.getTenantId(),
            model.getId(),
            command.getCode(),
            command.getAttributes()
        );

        masterDataRepository.save(masterData);

        return masterData.getId().getValue();
    }
}
```

#### 3.3.3 数据质量监控

> **命名提示**：To-Be 示意。As-Is：`QualityRule` → `DataQualityRule`（`domain/quality/`），
> `CreateQualityRuleCommandHandler` → `CreateDataQualityRuleHandler`，`QualityRuleRepository` → `DataQualityRuleRepository`。

```java
package com.bone.masterdata.application.command.handler;

import com.bone.masterdata.application.command.cmd.CreateQualityRuleCommand;
import com.bone.masterdata.domain.model.QualityRule;
import com.bone.masterdata.domain.model.vo.RuleName;
import com.bone.masterdata.domain.repository.QualityRuleRepository;
import com.bone.core.exception.BizException;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Component;
import org.springframework.transaction.annotation.Transactional;

@Component
@RequiredArgsConstructor
public class CreateQualityRuleCommandHandler {
    private final QualityRuleRepository ruleRepository;

    @Transactional
    public Long handle(CreateQualityRuleCommand command) {
        RuleName ruleName = new RuleName(command.getName());

        if (ruleRepository.existsByName(command.getName())) {
            throw new BizException("MD_QUALITY_RULE_NAME_DUPLICATED", "规则名称已存在");
        }

        QualityRule rule = QualityRule.create(
            command.getId(),
            command.getTenantId(),
            ruleName,
            command.getType(),
            command.getExpression(),
            command.getMessage()
        );

        ruleRepository.save(rule);

        return rule.getId().getValue();
    }
}
```

## 7. 性能与安全

> 通用横切（缓存、TLS、租户隔离、审计、输入验证、数据脱敏）见 [`Bone-API-规范.md`](../../architecture/Bone-API-规范.md)、[`Bone-多租户规范.md`](../../architecture/Bone-多租户规范.md) 与 IAM §7.2。本节仅列主数据特有项。

- **金标准记录缓存**：已发布 `mdm_record`（`status=PUBLISHED`）走 Redis 短 TTL 缓存，命中策略按 `entity_id + record_id`
- **批量导入/导出**：使用 chunk 流式 + Backpressure，避免一次性加载到内存
- **质量检查**：异步执行 + 写 `mdm_qcheck_report`；大批量走 LRO（见 §5.0 横切约定）
- **数据分区**：`mdm_record_version` 历史表与质量报告按月 RANGE 分区（**[Target]**）

### 10.3 核心类设计

> **命名与分层规范**统一参考 [`Bone-DDD v5.1.0`](../../architecture/Bone-DDD-最终实践方案.md)。下表仅列模块特有的关键类。

| 层级 | 关键类（**As-Is** 以 `bone-platform/bone-masterdata` 实际 Controller 为准） | 备注 |
|------|--------------------------------------------------------------------------|------|
| Adapter | `MasterDataEntityController` / `MasterDataFieldController` / `MasterDataRecordController` / `DataQualityController` | 与 §5 API 表一一对应 |
| Application · Command Handler | `CreateMasterDataEntityHandler` / `UpdateMasterDataEntityHandler` / `PublishMasterDataEntityHandler` / `ConvertFromBusinessEntityHandler` / `CreateMasterDataRecordHandler` / `UpdateMasterDataRecordHandler` / `PublishMasterDataRecordHandler` / `ImportMasterDataRecordsHandler` / `CreateMasterDataFieldHandler` / `UpdateMasterDataFieldHandler` / `CreateDataQualityRuleHandler` / `UpdateDataQualityRuleHandler` / `PerformDataQualityCheckHandler` | 命令 `@Transactional`；命名后缀为 `Handler`（非 `CommandHandler`，见 §10.2 目录树标注） |
| Application · Query Handler | `MasterDataEntityPageQueryHandler` / `MasterDataEntityDetailQueryHandler` / `MasterDataFieldListQueryHandler` / `MasterDataRecordPageQueryHandler` / `MasterDataRecordListQueryHandler` / `MasterDataRecordDetailQueryHandler` / `ExportMasterDataRecordsQueryHandler` / `DataQualityRuleListQueryHandler` / `GetQualityReportQueryHandler` | 查询 `@Transactional(readOnly=true)` |
| Domain · 聚合根 | `MasterDataEntity`（`domain/entity/`）/ `MasterDataField`（`domain/entity/`）/ `MasterDataRecord`（`domain/record/`）/ `DataQualityRule`（`domain/quality/`）/ `QualityCheck`（`domain/quality/`）/ `QualityReport`（`domain/quality/`） | 继承 `bone-core` `AggregateRoot`；包路径按子域拆分（`entity`/`record`/`quality`），非 `model/*` |
| Domain · 仓储 | `MasterDataEntityRepository` / `MasterDataFieldRepository` / `MasterDataRecordRepository` / `DataQualityRuleRepository` / `QualityCheckRepository` / `QualityReportRepository` | 继承 `bone-metadata-sdk` `Repository`，空接口；**无** `MasterDataModelRepository` / `MasterDataRepository` / `QualityIssueRepository` |
| Domain · 防腐层 | `MetadataClient`（`domain/gateway/`，查元数据实体）/ `MetaEntityCatalogPort`（catalog 协同）/ `MasterDataExcelImportPort`（导入） | 与外部走 `bone-integration` 协同，**勿在本模块直连外部库**；`ExternalSystemGateway` / `QualityCheckGateway` 为 **[Vision]** |
| Infrastructure | `MetadataClientAdapter` / `MetaEntityCatalogPortAdapter` / `MasterDataExcelImportPortAdapter` / `ExcelUtils` / `DataQualityUtils` | 出站实现统一 `*Adapter` 后缀（E-13.3）；`RestExternalSystemGatewayImpl` / `DefaultQualityCheckGatewayImpl` 为 **[Vision]** |

> **命名差异说明**（To-Be → As-Is）：
> - `MasterDataModel` → `MasterDataEntity`（实体与模型合并为 `MasterDataEntity` 聚合根）
> - `MasterData` → `MasterDataRecord`（主数据记录独立聚合根）
> - `QualityRule` → `DataQualityRule`（加 `Data` 前缀，与 `DataQualityController` 对齐）
> - `QualityIssue` → 拆分为 `QualityCheck`（检查任务）+ `QualityReport`（报告）
> - `CreateMasterDataModelCommandHandler` → `CreateMasterDataEntityHandler`（业务实体转换走 `ConvertFromBusinessEntityHandler`）
> - `CreateMasterDataCommandHandler` → `CreateMasterDataRecordHandler`
> - `CreateQualityRuleCommandHandler` → `CreateDataQualityRuleHandler`
> - Handler 后缀统一为 `*Handler`（非 `*CommandHandler`）

### 10.5 与其他微服务集成

**服务依赖**：
- **bone-iam**：用于权限验证和用户认证（`:8081`）
- **metadata-service**：用于管理主数据模型
- **notification-service**：用于发送主数据变更通知

**集成方式**：
- **Gateway**：通过 `domain/gateway/` 目录下的网关接口调用其他微服务
- **消息队列**：模块内用领域事件（如 `MasterDataPublishedEvent`，过去式）；跨模块解耦用集成事件（如 `MasterDataPublishedIntegrationEvent`）+ MQ/Outbox
- **共享缓存**：通过Redis共享跨服务数据
- **API网关**：通过API网关统一调用其他微服务

**集成流程**：
1. **权限验证**：经网关调用 **bone-iam** 进行用户认证和权限检查
2. **模型管理**：调用metadata-service管理主数据模型
3. **变更通知**：通过notification-service发送主数据变更通知
4. **服务发现**：通过Nacos服务发现机制找到其他微服务

## 11. 总结

主数据管理模块是 BONE 平台的核心数据治理模块，通过提供主数据模型管理、主数据生命周期管理、数据质量监控和主数据集成等功能，为企业提供高质量、一致、可信的主数据服务。该模块采用了先进的技术栈和架构设计，支持复杂的主数据管理需求。

**核心优势**：
- **统一的主数据模型**：支持灵活的主数据模型定义和管理
- **完整的生命周期管理**：从创建到归档的全生命周期管理
- **强大的数据质量监控**：自动检测和修复数据质量问题
- **高效的集成能力**：与外部系统的无缝集成
- **智能的AI辅助**：AI驱动的数据质量分析和修复

**应用场景**：
- 企业核心数据管理：统一管理客户、产品、供应商等核心数据
- 数据质量治理：确保数据的准确性和一致性
- 系统集成：实现不同系统之间的数据同步和一致性
- 业务分析：为业务分析提供高质量的数据基础

主数据管理模块的设计充分考虑了数据治理的复杂性和企业级应用的需求，为 BONE 平台提供了强大的数据治理能力，使企业能够更好地管理和利用其核心数据资产。

**符合规范**：
- 遵循《Bone-DDD》分层与 CQRS Handler 约定
- 应用层默认以 CommandHandler / QueryHandler 为入口；语义化 ApplicationService 也可作为单一用例边界
- 采用六边形架构，依赖方向正确
- 领域层纯净，仅使用 `@Getter` 和私有构造器
- 仓储接口为空接口，继承 `bone-metadata-sdk` 的 `Repository`
- 数据库表结构符合数据库规范，包含完整的中文注释
- 命名规范符合最新标准
- 集成AI能力定义（@Capability）
- 提供扩展点机制（Calculator命名）
