## 1. 背景与目标

### 1.1 业务背景

元数据管理当前实体列表是**扁平结构**，在企业级场景下（100+ 实体、多应用、多租户）存在以下问题：

| 问题 | 场景 | 影响 |
|------|------|------|
| 实体归属不明 | 100+ 实体混在一起 | 找不到、管理混乱 |
| 权限粒度粗 | 有权限就能看所有实体 | 跨应用数据泄露风险 |
| 无法分域治理 | 电商、财务、HR 模型在同一列表 | 领域边界模糊 |
| 多租户无应用视图 | 租户 A 和 B 的实体共用列表 | 数据隔离靠 tenant_id 硬分 |

### 1.2 设计目标

```
应用 (Application)          ← 权限边界、租户可见性
  └── 模块 (Module)         ← 领域边界、分组单元
       ├── 实体 (Entity)    ← 数据建模
       ├── 字段 (Field)     ← 字段建模
       └── 关系 (Relation)  ← 关系建模
```

1. **应用为权限单元**：用户对应用有 admin / developer / viewer 三种角色
2. **模块为分组单元**：实体按模块组织，模块之间实体不交叉
3. **多租户天然支持**：`tenant_id` 区分租户数据，租户间应用隔离
4. **渐进式存量兼容**：存量实体自动归入「未分组」模块

## 2. 数据模型

### 2.1 应用表 `bone_application`

```sql
CREATE TABLE IF NOT EXISTS `bone_application` (
  `id`            BIGINT       NOT NULL COMMENT '主键（Snowflake）',
  `tenant_id`     BIGINT       NOT NULL DEFAULT 0 COMMENT '租户ID',
  `name`          VARCHAR(128) NOT NULL COMMENT '应用名称',
  `code`          VARCHAR(64)  NOT NULL COMMENT '应用编码（租户内唯一）',
  `description`   VARCHAR(512) DEFAULT NULL COMMENT '描述',
  `icon`          VARCHAR(64)  DEFAULT 'appstore' COMMENT '图标',
  `status`        TINYINT      NOT NULL DEFAULT 0 COMMENT '0-启用 1-停用',
  `created_by`    BIGINT       DEFAULT NULL,
  `created_at`    DATETIME(3)  NOT NULL,
  `updated_by`    BIGINT       DEFAULT NULL,
  `updated_at`    DATETIME(3)  DEFAULT NULL,
  `deleted`       TINYINT(1)   NOT NULL DEFAULT 0,
  `version`       INT          NOT NULL DEFAULT 0,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_tenant_code` (`tenant_id`, `code`),
  KEY `idx_tenant_id` (`tenant_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='应用表';
```

### 2.2 模块表 `bone_module`

```sql
CREATE TABLE IF NOT EXISTS `bone_module` (
  `id`            BIGINT       NOT NULL COMMENT '主键（Snowflake）',
  `tenant_id`     BIGINT       NOT NULL DEFAULT 0 COMMENT '租户ID',
  `app_id`        BIGINT       NOT NULL COMMENT '所属应用ID',
  `name`          VARCHAR(128) NOT NULL COMMENT '模块名称',
  `code`          VARCHAR(64)  NOT NULL COMMENT '模块编码（应用内唯一）',
  `description`   VARCHAR(512) DEFAULT NULL COMMENT '描述',
  `status`        TINYINT      NOT NULL DEFAULT 0 COMMENT '0-启用 1-停用 2-归档',
  `sort_order`    INT          NOT NULL DEFAULT 0 COMMENT '排序号',
  `created_by`    BIGINT       DEFAULT NULL,
  `created_at`    DATETIME(3)  NOT NULL,
  `updated_by`    BIGINT       DEFAULT NULL,
  `updated_at`    DATETIME(3)  DEFAULT NULL,
  `deleted`       TINYINT(1)   NOT NULL DEFAULT 0,
  `version`       INT          NOT NULL DEFAULT 0,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_app_code` (`app_id`, `code`),
  KEY `idx_app_id` (`app_id`),
  KEY `idx_tenant_id` (`tenant_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='模块表';
```

### 2.3 实体扩展字段 `meta_entity`

`meta_entity` 表增加 `module_id` 字段（ALTER TABLE 或通过 SDK 扩展字段实现）：

```sql
-- 方案一：ALTER TABLE（推荐，直接关联）
ALTER TABLE `meta_entity` ADD COLUMN `module_id` BIGINT DEFAULT NULL COMMENT '所属模块ID' AFTER `status`;

-- 方案二：SDK 扩展字段·预留列分配（不修改 DDL）
-- 通过 fields:allocate 分配扩展列，将 module_id 作为业务属性存储
```

> **⚠️ 本节尚未决策，开工前须由架构师裁决**（「推荐」≠ 已定）：
>
> | 待决项 | 说明与倾向 |
> |--------|-----------|
> | `module_id` 落地方式 | **倾向方案一 ALTER TABLE**：`module_id` 是结构化关联键，需 JOIN 与索引；SDK 扩展列面向非结构化业务属性，用作关联键无法高效检索。二选一后须同步 `bone-init.sql`。 |
> | 跨模块库边界 | `bone_application` / `bone_module` 声称位于 `bone-platform`，而 `meta_entity` 位于 `bone-metadata-server`——**是否同库、可否建外键**均未定义。 |
> | 跨模块租户策略 | 两侧（`bone_*` 与 `meta_*`）的 `tenant_id` 口径与隔离策略是否一致，未定义。 |
> | 跨模块同步方式 | 若跨库，`module_id` 与模块表的一致性如何保证（领域事件 / 定时对账 / 不保证）未定义；建议参照主数据 ↔ 元数据的 ADR-0017 模式**另立 ADR**。 |
>
> 本模块整体为 **Target（未实现）**。上述未决项解决前不应开工，以免重演「元数据 ↔ 主数据」边界模糊的问题。

### 2.4 应用权限表 `bone_app_permission`

```sql
CREATE TABLE IF NOT EXISTS `bone_app_permission` (
  `id`            BIGINT      NOT NULL COMMENT '主键（Snowflake）',
  `app_id`        BIGINT      NOT NULL COMMENT '应用ID',
  `user_id`       BIGINT      NOT NULL COMMENT '用户ID',
  `role`          VARCHAR(32) NOT NULL COMMENT 'admin / developer / viewer',
  `tenant_id`     BIGINT      NOT NULL DEFAULT 0 COMMENT '租户ID（HC-008 必备）',
  `created_by`    BIGINT      DEFAULT NULL,
  `created_at`    DATETIME(3) NOT NULL,
  `updated_at`    DATETIME(3) DEFAULT NULL,
  `deleted`       TINYINT(1)  NOT NULL DEFAULT 0 COMMENT '逻辑删除（HC-008 必备）',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_tenant_app_user` (`tenant_id`, `app_id`, `user_id`),
  KEY `idx_user_id` (`user_id`),
  KEY `idx_tenant_id` (`tenant_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='应用权限表';
```

## 3. API 设计

### 3.1 应用管理

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| GET | `/api/v1/apps` | 分页查询应用列表（含当前用户权限） | 登录 |
| GET | `/api/v1/apps/{id}` | 应用详情 | 有权限 |
| POST | `/api/v1/apps` | 创建应用 | admin |
| PUT | `/api/v1/apps/{id}` | 更新应用 | admin |
| DELETE | `/api/v1/apps/{id}` | 删除应用（级联删除模块、标注删除实体） | admin |
| GET | `/api/v1/apps/{id}/permissions` | 应用权限列表 | admin |
| POST | `/api/v1/apps/{id}/permissions` | 授予用户权限 | admin |
| DELETE | `/api/v1/apps/{id}/permissions/{userId}` | 移除用户权限 | admin |

### 3.2 模块管理

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| GET | `/api/v1/apps/{appId}/modules` | 查询模块列表（含实体/字段统计） | 登录 |
| GET | `/api/v1/apps/{appId}/modules/{id}` | 模块详情 | 登录 |
| POST | `/api/v1/apps/{appId}/modules` | 创建模块 | developer+ |
| PUT | `/api/v1/apps/{appId}/modules/{id}` | 更新模块 | developer+ |
| DELETE | `/api/v1/apps/{appId}/modules/{id}` | 删除模块 | developer+ |
| PUT | `/api/v1/apps/{appId}/modules/reorder` | 模块排序 | admin |

### 3.3 当前用户 API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/apps/mine` | 获取当前用户有权限的应用列表（含角色） |

## 5. 实体扩展策略（存量兼容）

### 5.1 存量实体迁移

现有 `meta_entity` 表中无 `module_id` 字段的实体，自动归入「未分组」虚拟模块：

```sql
-- 查询未分组的实体
SELECT * FROM meta_entity WHERE module_id IS NULL;

-- 前端展示虚拟模块
{ id: 'uncategorized', name: '未分组', virtual: true }
```

### 5.2 DDL 变更策略

`meta_entity` 新增 `module_id` 列采用 **expand/contract** 模式：

1. **Expand**：`ALTER TABLE meta_entity ADD COLUMN module_id BIGINT DEFAULT NULL`
2. **Migrate**：将存量实体按 code 前缀或手动分组分配到模块
3. **Contract**：确认无 null 后将 `module_id` 设为 `NOT NULL`（下一版本）
