# Studio Generator 详细设计方案（最终完整版 v2.0）

> **仓库对照（As-Is）**：`bone-engine/studio-generator` · 默认 **8086**（`application.yml`）· 前端 `bone-generator-app` **3009** · Gateway **`/api/v1/generator/**` → 8888**  
> **DDL [Hybrid]**：`gen_*` 为目标态；持久化以 **Metadata SDK SqlRepositories** 为主（见 §3.2）；反向工程读取**外部**业务库使用 `HikariDataSource` + 原生 JDBC，非平台库访问，不适用 SDK Repository。  
> **端口**：默认 **8086**（`bone-integration` 为 8085，两者不冲突）；冲突时可改 `server.port` 或 `BONE_GENERATOR_URI`。历史 8084/8082/8085 表述已废止。  
> **与元数据三模块**：本模块承担 **代码生成**；**不**由 `bone-metadata-server` 实现。协作见 [元数据能力-实现映射与竞品对照](./元数据能力-实现映射与竞品对照.md) §3.3。  
> **HTTP 真源**：OpenAPI [generator-v1.yaml](../../architecture/openapi/generator-v1.yaml) · Controller `bone-engine/studio-generator/src/main/java/com/bone/studio/generator/adapter/web/controller/*` · 路径常量 `GeneratorApiPaths`。  
> **错误码前缀**：`GEN_` · 登记规则 [Bone-错误码登记.md](../../architecture/Bone-错误码登记.md)。

| 术语 | 本文档含义 | **不同于** |

## 1. 模块概述

Studio Generator 是 BONE 平台的核心代码生成模块。它基于数据库表结构（元数据）与可定制的 Freemarker 模板，自动生成对齐 **[《Bone-DDD》](../../architecture/Bone-DDD-最终实践方案.md)** 与 **bone-blueprint** 示例、可直接编译运行的 Java 代码。通过自动化重复性编码工作，让开发者聚焦于核心业务逻辑，实现开发效率与架构一致性的双重提升。

**核心目标**：
- **多数据源支持**：连接 MySQL、PostgreSQL、Oracle、SQL Server，反向解析表结构。
- **模板驱动生成**：提供符合架构规范的内置标准模板，并支持在线自定义与版本化管理。
- **生成即正确**：内建编译校验、代码格式化、静态分析三层质量门禁。
- **深度平台集成**：与 BONE IAM、**meta_* / metadata-sdk**（建模数据）、Nacos、MinIO 协作；扩展字段走 **metadata-server**（选配）。
- **AI 原生**：通过 `@Capability` 注册原子能力，支持 AI 助手发现、编排和调用。
- **优秀开发者体验**：向导式 UI、异步任务进度反馈、一键下载 ZIP、增量生成保护手写代码。

## 2. 功能设计

### 2.1 数据源管理
管理代码生成所依赖的数据库连接。

**详细功能**：
- **多类型支持**：MySQL、PostgreSQL、Oracle、SQL Server。
- **连接池**：为每个启用的数据源建立 HikariCP 连接池，支持验证、超时、重连。
- **密码安全**：AES‑256 加密存储，密钥从 K8s Secret 或 Vault 注入。
- **健康检查**：手动测试连接 + 后台定时探活，自动禁用不可用数据源。
- **生命周期**：增、删、改、查、启用/禁用。禁用的数据源不可用于代码生成。

**用户故事**：
- 作为**开发者**，我希望能够配置并验证数据库连接，以便系统能读取表结构。
- 作为**安全管理员**，我要求所有数据源密码加密存储，且操作可审计。
- 作为**团队 TL**，我希望能管理团队共享的数据源，统一环境配置。

### 2.2 表结构管理
将原始数据库表结构，转换为平台可理解的标准化元数据。

**详细功能**：
- **元数据同步**：从指定数据源同步最新表结构到 `gen_table_metadata` 和 `gen_column_metadata`。
- **智能类型映射**：通过 `gen_type_mapping` 表自动将数据库类型映射为 Java 类型。
- **元数据增强**：允许开发者修改实体名、字段名、业务注释等，不影响数据库原始定义。
- **结构化预览**：以树形/表格形式展示表、列、主键、注释等信息。
- **批量操作**：支持多表批量同步、批量生成代码。

**用户故事**：
- 作为**开发者**，我希望能从数据库同步表结构，并重命名含义不清的字段。
- 作为**DBA**，我希望能查看到表的完整结构，确保生成代码准确反映数据库设计。
- 作为**项目负责人**，我希望能批量选择相关表一次性生成整个模块的代码。

### 2.3 代码模板管理
管理生成代码的逻辑蓝图，实现“模型-视图”分离。

**详细功能**：
- **模板引擎**：Freemarker。
- **内置模板库**：提供符合 Bone‑Blueprint 规范的 `Entity`、`Repository`（空接口）、`*CommandHandler`、`*QueryHandler`、`Controller`、`Assembler`、`*Req`/`*Resp` 等模板；**不**内置 `Service`/`ServiceImpl` 直注 Controller 的反模式模板。
- **版本化**：语义化版本管理，生成历史会记录所使用的模板版本。
- **在线编辑器**：基于 Monaco Editor 的 Web IDE，支持语法高亮、变量提示。
- **预览与校验**：选择测试表后，实时预览渲染效果，并进行语法验证。

**用户故事**：
- 作为**架构师**，我希望能自定义 Repository 模板，注入团队特有的数据访问逻辑。
- 作为**开发者**，我希望能选择模板后立即预览生成出的代码，以确认其符合预期。

### 2.4 代码生成
编排元数据与模板，执行最终生成任务。

**详细功能**：
- **生成配置**：
  - `projectName`、`basePackage`、`moduleName`、`author`、`tablePrefix`（需移除的表前缀，如 `t_`）。
  - 选择数据源及其下的表。
  - 为每个表选择要应用的模板组。
- **差异化生成**：覆盖模式 vs 增量模式。增量模式仅生成新表/新字段的代码，保护已手写的业务逻辑。
- **异步任务**：采用 `@Async` + WebSocket 实时反馈进度。
- **产物下载**：按包路径组织代码文件，打包成 ZIP，上传至 MinIO，返回临时下载链接。
- **生成历史**：详细记录每次生成操作的输入、产物列表、模板版本、任务状态，支持追溯和重新下载。

**用户故事**：
- 作为**新入职开发者**，我想通过几步配置快速搭建新模块的基础代码，然后直接上手业务开发。
- 作为**代码审查员**，我可以在生成历史中回溯任何一次代码生成的上下文。

### 3.3 关键实现细节

#### 3.3.1 应用层编排策略

> **真源**：[《Bone-DDD-最终实践方案》](../../architecture/Bone-DDD-最终实践方案.md)。
> **兼容约束**：现有 `application/usecase/**`、`*UseCase`、自造 `@UseCase` / `UseCaseExecutor` 不新增；合法语义化 ApplicationService 可直接作为用例边界，但不得与同义 Handler 套娃。当前 ArchUnit 对 ApplicationService 的旧限制属于待调整规则。

**生成物（对外交付的 Java 工程）**：默认 CQRS — 写用例生成 `*CommandHandler`，读用例生成 `*QueryHandler` + application `*QueryPort`；一个用例只生成一种应用边界。

**Studio 服务自身（`bone-engine/studio-generator`）**：

| 场景 | 做法 |
|------|------|
| 单用例 CRUD / 查询 | `*CommandHandler` / `*QueryHandler`，`@Transactional` 在写 Handler |
| 单一业务流程需要共享应用级策略 | 语义化 `*ApplicationService` 直接作为用例边界，不再外包同义 Handler |
| 跨步骤且需要重试/补偿 | `application/orchestration/*Orchestrator` |
| AI 可发现能力 | 在 Handler 上标注 `@Capability`（§3.3.2），**禁止**为发现性新建 UseCase 门面 |

**使用 Orchestrator 的判定**：流程跨多个独立步骤，并且需要显式重试、超时或补偿。暴露给 AI、使用扩展点或调用 Gateway 本身都不是引入 Orchestrator 的理由。

#### 3.3.3 数据库元数据获取（Gateway 防腐层）

涉及外部数据库连接的操作定义为 Gateway（防腐层），接口在 `domain/gateway/`，实现在 `infrastructure/gateway/`。

```java
// domain/gateway/DatabaseMetadataGateway.java
public interface DatabaseMetadataGateway {
    
    /**
     * 测试数据源连接是否可用
     */
    boolean testConnection(DataSourceConfig config);
    
    /**
     * 从数据源加载所有表的元数据
     */
    List<DatabaseTable> loadTables(DataSource dataSource);
    
    /**
     * 从数据源加载指定表的列元数据
     */
    List<TableColumn> loadTableColumns(DataSource dataSource, String tableName);
}

// infrastructure/gateway/DatabaseMetadataGatewayAdapter.java
@Component
@RequiredArgsConstructor
public class DatabaseMetadataGatewayAdapter implements DatabaseMetadataGateway {
    
    private final ConcurrentHashMap<Long, HikariDataSource> poolCache = new ConcurrentHashMap<>();
    
    @Value("${generator.encryption.key}")
    private String encKey;
    
    @Override
    public boolean testConnection(DataSourceConfig config) {
        try (HikariDataSource ds = buildTempPool(config)) {
            try (Connection conn = ds.getConnection()) {
                return conn.isValid(5);
            }
        }
    }
    
    @Override
    public List<DatabaseTable> loadTables(DataSource dataSource) {
        HikariDataSource ds = getOrCreatePool(dataSource);
        try (Connection conn = ds.getConnection()) {
            DatabaseMetaData metaData = conn.getMetaData();
            ResultSet rs = metaData.getTables(dataSource.getDbName(), null, "%", new String[] {"TABLE"});
            List<DatabaseTable> tables = new ArrayList<>();
            while (rs.next()) {
                String tableName = rs.getString("TABLE_NAME");
                String comment = rs.getString("REMARKS");
                List<TableColumn> columns = loadTableColumns(dataSource, tableName);
                tables.add(DatabaseTable.of(tableName, comment, columns));
            }
            return tables;
        } catch (SQLException e) {
            throw new InfrastructureException("Failed to load tables from data source", e);
        }
    }
    
    @Override
    public List<TableColumn> loadTableColumns(DataSource dataSource, String tableName) {
        HikariDataSource ds = getOrCreatePool(dataSource);
        try (Connection conn = ds.getConnection()) {
            DatabaseMetaData metaData = conn.getMetaData();
            ResultSet rs = metaData.getColumns(dataSource.getDbName(), null, tableName, null);
            List<TableColumn> columns = new ArrayList<>();
            while (rs.next()) {
                columns.add(TableColumn.builder()
                    .columnName(rs.getString("COLUMN_NAME"))
                    .jdbcType(rs.getInt("DATA_TYPE"))
                    .columnType(rs.getString("TYPE_NAME"))
                    .columnSize(rs.getInt("COLUMN_SIZE"))
                    .decimalDigits(rs.getInt("DECIMAL_DIGITS"))
                    .nullable(rs.getInt("NULLABLE") == DatabaseMetaData.columnNullable)
                    .remarks(rs.getString("REMARKS"))
                    .build());
            }
            return columns;
        } catch (SQLException e) {
            throw new InfrastructureException("Failed to load columns for table " + tableName, e);
        }
    }
    
    private HikariDataSource buildTempPool(DataSourceConfig config) {
        HikariConfig hc = new HikariConfig();
        hc.setJdbcUrl(buildUrl(config));
        hc.setUsername(config.getUsername());
        hc.setPassword(AESUtils.decrypt(config.getPasswordEncrypted(), encKey));
        hc.setMaximumPoolSize(2);
        hc.setConnectionTimeout(5000);
        return new HikariDataSource(hc);
    }
    
    private HikariDataSource getOrCreatePool(DataSource ds) {
        return poolCache.computeIfAbsent(ds.getId(), id -> {
            HikariConfig hc = new HikariConfig();
            hc.setJdbcUrl(buildUrl(ds.toConfig()));
            hc.setUsername(ds.getUsername());
            hc.setPassword(AESUtils.decrypt(ds.getPasswordEncrypted(), encKey));
            hc.setMaximumPoolSize(5);
            hc.setIdleTimeout(600000);
            hc.setMaxLifetime(1800000);
            return new HikariDataSource(hc);
        });
    }
    
    private String buildUrl(DataSourceConfig config) {
        String host = config.getHost();
        int port = config.getPort();
        String dbName = config.getDbName();
        String params = config.getParams() != null ? config.getParams() : "";
        switch (config.getType()) {
            case MYSQL:
                return String.format("jdbc:mysql://%s:%d/%s?useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&%s", host, port, dbName, params);
            case POSTGRESQL:
                return String.format("jdbc:postgresql://%s:%d/%s?%s", host, port, dbName, params);
            case ORACLE:
                return String.format("jdbc:oracle:thin:@%s:%d:%s", host, port, dbName);
            case SQLSERVER:
                return String.format("jdbc:sqlserver://%s:%d;databaseName=%s;%s", host, port, dbName, params);
            default:
                throw new DomainException("Unsupported database type: " + config.getType());
        }
    }
}
```

#### 3.3.4 表结构同步（编排示例）

> 生成物不新增 `*UseCase` 薄门面。Controller 依赖生成的应用用例边界；跨步骤且需要重试/补偿的流程使用 `*Orchestrator`，普通复用不创建编排器（见 [Bone-DDD 应用用例边界](../../architecture/Bone-DDD-最终实践方案.md#application-use-case-boundary)）。

```java
// Handler 负责编排 + 事务（或拆为 Orchestrator + 子 Handler）
@Component
@RequiredArgsConstructor
public class SyncTableMetadataCommandHandler {
    
    private final GenTableMetadataRepository tableMetadataRepo;
    private final GenColumnMetadataRepository columnMetadataRepo;
    private final GenTypeMappingRepository typeMappingRepo;

    @Transactional
    public void handle(Long dataSourceId, List<DatabaseTable> dbTables) {
        for (DatabaseTable dbTable : dbTables) {
            // 使用 Criteria 查询现有元数据
            GenTableMetadata metadata = tableMetadataRepo.findOneByCriteria(
                Criteria.<GenTableMetadata>builder()
                    .eq(GenTableMetadata::getDataSourceId, dataSourceId)
                    .eq(GenTableMetadata::getOriginalTableName, dbTable.getTableName())
                    .eq(GenTableMetadata::getDeleted, false)
                    .build()
            ).orElseGet(() -> {
                long id = DistributedIdGenerator.generateLongId();
                return GenTableMetadata.create(id, SecurityUtils.getTenantId(), dataSourceId, dbTable);
            });
            
            // 同步列信息
            metadata.syncColumns(dbTable.getColumns(), typeMappingRepo);
            tableMetadataRepo.save(metadata);
        }
    }
}
```

#### 3.3.5 代码生成（异步 + 策略模式）

```java
// Controller 直注 GenerateCodeCommandHandler；异步提交见 CodeGenerationAsyncService
// Handler 是 @Capability 标记的 AI 可见能力
@Capability(
    name = "studio.generator.generateCode",
    description = "根据指定的表和模板生成代码包",
    inputSchema = "...",  // 同前
    outputSchema = "...",
    category = "开发工具",
    riskLevel = "LOW"
)
@Component
@RequiredArgsConstructor
public class GenerateCodeCommandHandler {

    private final List<FileGenerator> fileGenerators;  // 策略集合
    private final GenerationTaskRepository taskRepository;
    private final GenTableMetadataRepository tableMetadataRepo;
    private final CodeTemplateRepository templateRepo;
    private final MinioStorageGateway storageGateway;

    @Transactional
    public void createAndRun(long id, String taskTraceId, GenerateCodeCommand command) {
        GenerationTask task = GenerationTask.create(
            id,
            SecurityUtils.getTenantId(),
            taskTraceId,
            command.getProjectName(),
            command.getBasePackage(),
            command.getModuleName(),
            command.getDataSourceId(),
            command.getTableNames(),
            command.getTemplateIds(),
            command.getGenConfig()
        );
        taskRepository.save(task);
        asyncGenerate(task);
    }

    @Async
    public void asyncGenerate(GenerationTask task) {
        try {
            task.markProcessing();
            taskRepository.save(task);

            List<GeneratedFile> files = new ArrayList<>();
            for (String tableName : task.getTableNames()) {
                // 使用 Criteria 查询表元数据
                GenTableMetadata table = tableMetadataRepo.findOneByCriteria(
                    Criteria.<GenTableMetadata>builder()
                        .eq(GenTableMetadata::getOriginalTableName, tableName)
                        .eq(GenTableMetadata::getDeleted, false)
                        .build()
                ).orElseThrow(() -> new NotFoundException("Table metadata not found: " + tableName));

                for (Long templateId : task.getTemplateIds()) {
                    CodeTemplate template = templateRepo.findById(templateId)
                            .orElseThrow(() -> new NotFoundException("Template not found: " + templateId));
                    
                    // 选择匹配的策略生成文件
                    FileGenerator gen = fileGenerators.stream()
                            .filter(g -> g.supports(template.getType()))
                            .findFirst()
                            .orElseThrow(() -> new DomainException("No generator for type: " + template.getType()));
                    
                    files.add(gen.generate(table, template, task.getBasePackage(), task.getModuleName()));
                }
            }

            byte[] zipBytes = ZipUtils.streamZip(files);
            String zipUrl = storageGateway.upload(task.getTaskId() + ".zip", zipBytes);
            task.markCompleted(files, zipUrl);
            taskRepository.save(task);
        } catch (Exception e) {
            log.error("Code generation failed for task {}", task.getTaskId(), e);
            task.markFailed(e.getMessage());
            taskRepository.save(task);
        }
    }
}
```

## 6. Controller 示例（严格遵循规范）

> 与 《Bone-DDD-最终实践方案》 对齐：Controller 依赖单一应用用例边界；本示例选择 `*CommandHandler` / `*QueryHandler`。现有 `*UseCase` 薄门面不新增；命名风格见 [Bone-DDD E-13](../../architecture/Bone-DDD-最终实践方案.md#naming-style)。

> **示例说明**：下列代码中的 `DataSourceAssembler` 为示意写法——生成器当前**没有** `assembler/` 包，`*Req` / `*Resp` 与 DTO 的转换在 Controller 内直接完成；入口构件以 `*ApplicationService` 为准（ADR-0028）。
```java
// adapter/web/controller/DataSourceController.java
@RestController
@RequestMapping("/api/v1/generator/data-sources")
@RequiredArgsConstructor
public class DataSourceController {

    private final DataSourceQueryHandler dataSourceQueryHandler;
    private final DataSourceCommandHandler dataSourceCommandHandler;

    // adapter 层入参用 *Req/*Qry，经 Assembler 转为 application 层 *Query
    @GetMapping
    public ApiResponse<PageResult<DataSourceResp>> list(@Valid DataSourcePageReq req) {
        PageResult<DataSourceDTO> page = dataSourceQueryHandler.page(DataSourceAssembler.toQuery(req));
        return ApiResponse.success(page.map(DataSourceAssembler::toResp));
    }

    @GetMapping("/{id}")
    public ApiResponse<DataSourceResp> detail(@PathVariable Long id) {
        DataSourceDTO dto = dataSourceQueryHandler.findById(new DataSourceByIdQuery(id));
        return ApiResponse.success(DataSourceAssembler.toResp(dto));
    }

    @PostMapping
    public ApiResponse<Long> create(@Valid @RequestBody CreateDataSourceReq req) {
        CreateDataSourceCommand command = DataSourceAssembler.toCommand(req);
        return ApiResponse.success(dataSourceCommandHandler.create(command));
    }

    @PutMapping("/{id}")
    public ApiResponse<Void> update(@PathVariable Long id, @Valid @RequestBody UpdateDataSourceReq req) {
        dataSourceCommandHandler.update(DataSourceAssembler.toCommand(id, req));
        return ApiResponse.success();
    }

    @DeleteMapping("/{id}")
    public ApiResponse<Void> delete(@PathVariable Long id) {
        dataSourceCommandHandler.delete(new DeleteDataSourceCommand(id));
        return ApiResponse.success();
    }

    @PostMapping("/{id}:test-connection")
    public ApiResponse<TestConnectionResp> testConnection(@PathVariable Long id) {
        return ApiResponse.success(dataSourceCommandHandler.testConnection(new TestConnectionCommand(id)));
    }
}
```

- **组件适配**：根据屏幕尺寸调整组件大小、布局和交互方式

```
│       ├── SyncTableMetadataCommandHandler        # 编排：读 DB → 落 gen_table/column_metadata（含类型映射）
│       ├── GenerateCodeCommandHandler  @Capability # AI 可见：编排生成
│       └── PublishTemplateCommandHandler
├── query/
│   ├── qry/          # DataSourcePageQuery, TemplatePageQuery, HistoryPageQuery, TableMetadataDetailQuery
│   ├── handler/      # *QueryHandler（@Transactional(readOnly)）
│   ├── port/         # *QueryPort
│   └── dto/          # DataSourceDTO / TemplateDTO / GenerationTaskDTO
└── orchestration/
    └── CodeGenerationOrchestrator   # 跨步骤：生成→质量门禁→打包→上传 MinIO→写历史；含重试/补偿
```

**关键改造项（按优先级）**：

1. **B1/B2 — 应用层重构 + Capability**：把 `GenerateCodeCommandHandler` 标 `@Capability(name="studio.generator.generateCode", ...)`（JSON Schema 见 §3.3.2），Controller 直注该 Handler；跨步骤流程下沉到 `CodeGenerationOrchestrator`（生成→门禁→打包→上传→历史）。
2. **B3 — 收敛入口**：删除 `GeneratorShortcutController`（`/generate`）与 `GenerationTaskController`（`/generation-tasks`）；统一只保留 `CodeGenerationController` 的 `POST /code-generation`（LRO 202 + `operations/{id}`）+ `?sync=true`。`CATALOG_SNAPSHOT` 与 `PHYSICAL_DB` 仅作为 `GenerateCodeCommand.sourceType` 枚举差异，请求体统一。
3. **B4 — 模板版本化**：`CodeTemplate` 增加 `version`(SemVer) + `published` 状态；`POST /templates/{id}:publish` 真正落库发布版本；生成历史记录所用 `templateId+version`。
4. **B5 — 产物上 MinIO**：`CodeGenerationOrchestrator` 生成后 `ZipUtils.streamZip(files)` → `MinioStorageGateway.upload(taskId+".zip")` → `task.markCompleted(files, zipUrl)`；`GET /tasks/{id}/download` 改为返回 **MinIO 签名 URL 302**（或流式代理），不再内联读 JSON。
5. **B6 — 增量模式**：`GenerateCodeCommand.mode ∈ {OVERWRITE, INCREMENTAL}`；INCREMENTAL 对比已落盘/已存在文件，跳过手写文件（以 `@Generated` 标记或 `.bone-generated` 清单判定）。
6. **B7 — 质量门禁**：`infrastructure/generator/QualityGate`（编译用临时 Maven/Gradle；格式化走 Spotless；静态走 Checkstyle/PMD/SpotBugs），失败则 `task.markFailed` 并阻断下载。
7. **B8 — Freemarker 沙箱**：`GeneratorConfiguration` 设置 `Configuration.setNewBuiltinClassResolver(TemplateClassResolver.SAFER_RESOLVER)` 并禁 `?api`/`?new`。
8. **B9 — 值对象持久化**：将 `GeneratedFile` 作为独立 `gen_generated_file` 行（或列表型 JSON 列配自定义 TypeHandler 映射回 `GeneratedFile`），消除 `LinkedHashMap` 取字段的架构异味。
