# 建模工作台功能与用例设计方案

> **文档性质**：建模工作台（Modeling Workspace）功能与用例设计——[2a 核心场景及用例](2a.%20元数据管理模块核心场景及用例设计方案.md) 的落点篇（2a 定能力链与治理骨架，本文把「②建模」这一段做成可用的产品）
> **适用产品**：BONE 企业级全栈开源快速开发平台
> **版本**：v1.4 | **发布日期**：2026-09-26 | **文档状态**：🟡 设计中（待拍板）| **密级**：内部机密
> **对标参考**：Power Apps Maker Portal（任务导向工作台首页）、Salesforce Object Manager + Schema Builder（对象管理器 / 可视化画布）、OutSystems TrueChange + Mendix Studio Pro 一致性面板（校验即门禁、点错误跳转）、Salesforce New Field 向导 / 简道云·宜搭字段面板（字段快速建模）、Mendix 复制实体 / SAP DDIC Copy（模型复用）、Dataverse 安全角色（只读 Maker 形态）、Airtable / NocoDB（网格行内编辑）
> **分层约定**：沿用 ✅ **As-Is** / ⏳ **[Target]** / 💡 **[Vision]** 标记；未标 As-Is 不得按已上线验收。
> **边界**：本文只设计**建模工作台前端形态与用例**；能力链、权限码、DDL、发布包后端见 2a 与 [ADR-0039](../../architecture/adr/0039-release-package-with-approval-and-rollback.md)，本文引用不复制。

## 1. 结论先行

### 1.1 一句话定位

> **建模工作台 = 应用建模者的驾驶舱：以「应用 → 模块 → 实体 → 字段/关系」为主线，把选基线、建模、校验、发布四件事串在一个界面里，权限与状态驱动每一个按钮。**

对标 Power Apps Maker Portal 的核心理念：**工作台按「用户要办的事」组织，而不是按「系统有什么对象」组织**。这正是 2a G10 断点（「入口是功能，不是场景」）在前端的解法。

### 1.2 As-Is 现状快照（2026-09-26）

| 页面 | 现状 | 已具备 | 主要缺口 |
|------|------|--------|---------|
| `ModelingWorkspace`（/apps） | 应用卡片选择入口 | ✅ `/apps/mine` 真过滤（G15）、角色标签、模块/实体计数 | 只读罗列，无「最近编辑」「待发布」「从模板新建」等任务入口 |
| `ModuleManagement` | 模块列表 | ✅ 模块 CRUD（IAM） | 无模块级统计与发布状态聚合 |
| `EntityManagement` | 树 + 实体表 | ✅ 树接 IAM 真数据、moduleId 服务端过滤（G2）、关键词/类型/交付模式/状态筛选、单发/批量发布、新建 Modal 模块下拉接 IAM | 发布=裸 Popconfirm（无 dry-run）；无静态校验反馈；无实体复制 |
| `EntityDetail` | 实体信息 + 字段表 | ✅ 字段 CRUD、编辑 Modal | 无「已发布受限编辑」的引导文案；无校验问题面板；无字段向导/行内编辑 |
| `FieldManagement` / `RelationManagement` | 独立页面 | ✅ 基础 CRUD | 与实体上下文割裂（按对象排菜单位置，2a G10 同源问题） |
| `RuntimeDataManagement` | 运行时记录 CRUD | ✅ 按字段动态渲染 | — |

**后端已就绪但前端无入口的能力（重要）**：

| 后端能力 | 状态 | 前端入口 |
|---------|------|---------|
| 平台模板目录 + 实例化（G3 / ADR-0038） | ✅ 已联调（模板 9101 客户模板实例化实测通过） | ❌ 无任何 UI——**建模者根本不知道有模板** |
| moduleId 服务端过滤（G2） | ✅ | ✅ 已接线 |
| 发布期漂移校验（409） | ✅ | ⚠️ 仅发布失败时报错，发布前不可见 |
| 六权限码（G5：`metadata:model:read\|write` 等） | ✅ 已落库 | ⚠️ 前端未按码区分只读/可写形态 |
| 应用角色（G1②：ADMIN/DEVELOPER 可建模） | ✅ 后端强制 403 | ❌ 前端不感知，用户点了才报错 |

### 1.3 设计总纲（五条原则）

| # | 原则 | 业界出处 |
|---|------|---------|
| P-1 | **任务导向入口**：首页给「继续上次建模 / 从模板新建 / 待发布变更」，应用卡片只是次级入口 | Power Apps Maker Portal 首页 |
| P-2 | **校验即门禁**：发布前必过静态校验面板；错误可点击跳转到问题字段；有错时发布按钮禁用并给出原因 | OutSystems TrueChange / Mendix 一致性面板 |
| P-3 | **权限与状态驱动 UI**：VIEWER 只读形态；无应用角色禁建；已发布实体只开放「加字段/改非破坏属性」，禁用项带原因提示——**前端禁用永远只是体验，后端 403 才是真门禁**（G1② 已落地） | Dataverse 安全角色 / Salesforce 页面布局 |
| P-4 | **复用优先**：新建实体第一入口是「从模板实例化」，全新建模退居第二选项（2a UC-MT2 主流程 A/B/C 的前端化） | Salesforce AppExchange / Mendix Marketplace |
| P-5 | **破坏性操作显式化**：删字段=归档、发布前 DDL 预览、破坏性变更二次确认——不依赖用户记忆 | ADR-0039 三道闸 / SAP 传输请求 |

## 2. 工作台信息架构（IA）

### 2.1 页面结构（目标态）

```
建模工作台首页（/apps）
├─ ① 概览条：我的应用 N · 实体总数 N · 草稿(待发布) N · 校验问题 N        ⏳ [Target]
├─ ② 快捷入口区：                                                        ⏳ [Target]
│     「继续建模」（最近编辑实体 Top5，点击直达 EntityDetail）
│     「从模板新建」（打开模板选择向导 → UC-W2）
│     「全新建模」（选应用+模块 → 打开新建 Modal → UC-W3 流程 C）
├─ ③ 我的应用卡片（As-Is 保留）＋ 每卡新增「待发布 N」徽标                 ✅+⏳
│
└─ /apps/:appId/modules ── 模块列表（补实体数/草稿数列）
     └─ /entities ── EntityManagement：左树（应用→模块，带计数与状态图标）+ 右表
          ├─ EntityDetail：Tab 化「字段 / 关系 / 基本信息 / 校验问题」      ⏳ [Target]
          │     └─ 发布按钮 → 发布预览 Modal（DDL/dry-run，随 ADR-0039 R1）⏳ [Target]
          ├─ FieldManagement / RelationManagement 能力并入 Detail Tab      ⏳ [Target]（独立页保留为兼容路由）
          └─ RuntimeDataManagement（运营录数据，权限码 metadata:runtime:write）
```

### 2.2 导航与 2a G10 的关系

G10（导航重组为「建模工作台 / 发布中心 / 模型资产 / 运行时数据」）是**shell 菜单层**的重组；本文是**工作台内部**的 IA。二者衔接：shell「建模工作台」菜单 → 本文首页；「发布中心」等其余三块由 ADR-0039 实现时另行设计，不在本文范围。

## 3. 功能设计（F1~F10）

> 优先级：**P0** = 本轮可做（纯前端或复用既有后端，无 DDL）；**P1** = 需少量后端配合或依赖 ADR-0039 R1；**P2/Vision** = 高投入或远期。

| ID | 功能 | 内容 | 对应用例 | 优先级 |
|----|------|------|---------|--------|
| **F1** | 工作台首页任务化 | 概览条 + 「继续建模」（最近编辑实体）+「从模板新建」+「全新建模」三个快捷入口；应用卡片补「待发布 N」徽标 | UC-W1 | **P0** |
| **F2** | 权限驱动界面形态 | 读 `metadata:model:write` + 应用角色：VIEWER/只读码 → 表格无操作列、新建/发布按钮隐藏并提示原因；前端仅做体验，后端 403 兜底 | UC-W8 | **P0** |
| **F3** | 已发布实体受限编辑引导 | 状态=已发布：字段区只开放「加字段」，改动弹窗内禁用破坏属性并给文案「已发布实体仅允许加字段/改非破坏属性，结构性变更请走发布包」 | UC-W6 | **P0** |
| **F4** | 前端即时校验 | 新建/编辑实体与字段时：编码正则 `^[a-zA-Z][a-zA-Z0-9_]*$`、必填、实体内字段编码重复、表名合法性——即时红字，不等提交 | UC-W5 | **P0** |
| **F5** | 脏状态守卫 | 编辑态切换路由/关页前确认（「有未保存的修改」）；Modal 关闭前脏检查 | UC-W3 | **P0** | ✅ 已落地（v1.3：编辑字段/关系 Modal 关闭前 `isFieldsTouched` 二次确认） |
| **F6** | 模板实例化向导 | 选模板 → 看（模板字段预览）→ 填编码/表名/选模块 → 实例化；成功后直达 EntityDetail；模板目录 API 已就绪（G3） | UC-W2 | **P0** |
| **F7** | 校验问题面板 | EntityDetail 增「校验」Tab：静态校验结果列表（错误/警告分级），**点击跳转问题字段**；后端需新增 `POST /entities/{id}/validate` 静态校验 API（无 DDL） | UC-W5 | **P1** |
| **F8** | 发布预览（dry-run） | 发布按钮 → 预览 Modal：将执行的 DDL、变更摘要、破坏性变更清单；确认后调发布接口。随 ADR-0039 R1（隐式建包） | UC-W7 | **P1** |
| **F9** | 实体复制 | EntityManagement 行操作「复制」：复制实体定义+字段到同/跨模块（跨应用需目标应用角色），新编码自动生成，默认草稿态 | UC-W2 流程 B | **P1** |
| **F10** | 字段建模升级 | a) 加字段向导（类型面板：常用类型置顶 + 说明，Salesforce New Field 式）；b) 字段网格行内编辑（Airtable 式，先做非破坏属性）；c) 枚举/字典集中管理入口（2a UC-MT3 缺口③） | UC-W4 | **P1**（a 先行） | ✅ a)/b) 已落地（v1.2/v1.3）；c) 待后端枚举/字典模型（见 §13.3，另立 Change） |
| F11 | ER 可视化画布 | Schema Builder / Mendix 域模型画布：拖拽建实体/关系，画布即导航 | — | 💡 [Vision]（投入重，依赖 F10/关系物理策略 G7） |
| F12 | 全局搜索与命令面板 | Ctrl+K 跨应用搜实体/字段/表名；「最近查看」 | — | 💡 [Vision] |
| F13 | 模型导入导出 ✅ v1.4 | 实体定义导出 JSON / 导入校验后创建（对标 Salesforce Metadata API 的文件化形态，衔接 Docs-as-Code） | — | P2 |
| F14 | 影响提示 | 实体/字段页展示消费方计数（「被 2 个应用 + 1 条集成流引用」）；随 2a G8 消费登记落地 | — | P2（依赖 G8/G9） |

## 4. 核心用例（UC-W）

> 用例卡格式沿用 2a。参与者为 2a §4.1 角色：应用建模者（主）、租户建模负责人、发布审批人、运行时数据运维。

### UC-W1 进入工作台并定位建模目标 ✅ 部分作为 / ⏳ F1

| 项 | 内容 |
|----|------|
| 参与者 | 应用建模者 |
| 主流程 | ① 打开工作台：先看「继续建模」最近实体（若有）→ ② 或从应用卡片进入 → ③ 树内选中模块 → ④ 实体表定位目标 |
| As-Is | 应用卡片 + 树 + moduleId 过滤 ✅；最近编辑/概览条/待发布徽标 ❌ |
| 异常 | 无可建模应用 → 空态引导去 IAM 建应用（As-Is 已有 Alert）；无应用角色 → 卡片呈只读态（F2） |
| 权限码 | `metadata:model:read` |

### UC-W2 选基线：模板实例化 / 复制 / 全新 ⏳ F6/F9（后端 As-Is / Target）

| 项 | 内容 |
|----|------|
| 参与者 | 应用建模者 |
| 主流程 A（模板） | 「从模板新建」→ 模板目录（名称/领域/字段数）→ 选中看字段预览 → 填编码/表名 + 选模块 → 实例化 → 直达详情补租户扩展字段 |
| 主流程 B（复制） | 实体行「复制」→ 选目标模块（跨应用校验目标应用角色）→ 生成草稿副本 |
| 主流程 C（全新） | 「全新建模」→ 新建 Modal（As-Is 保留） |
| 关键约束 | 实例化成功后 `scope=PLATFORM_INSTANCE`、模板字段默认锁定态（2a §3.1 规则 1 前端呈现：模板字段标「平台模板」Tag，禁删） |
| 权限码 | `metadata:model:write` + `metadata:template:read` |
| 串联出口 | → UC-W3 |

### UC-W3 实体与字段一站式成型 ✅ 部分作为 / ⏳ F5、F10

| 项 | 内容 |
|----|------|
| 参与者 | 应用建模者 |
| 主流程 | ① 建实体（Modal，即时校验 F4）→ ② 进入详情加字段（向导式 F10a / 现有 Modal）→ ③ 定义关系（关系 Tab）→ ④ 不离开详情页完成一次成型 |
| As-Is | Modal CRUD ✅；即时校验 ❌、向导 ❌、行内编辑 ❌、脏状态守卫 ❌ |
| 异常 | 编码重复/非法 → 即时红字；离开未保存 → 脏状态确认（F5） |
| 权限码 | `metadata:model:write`（+ 应用角色 G1②） |
| 串联出口 | → UC-W5 校验 → UC-W7 发布 |

### UC-W4 字段快速建模 ⏳ F10

| 项 | 内容 |
|----|------|
| 参与者 | 应用建模者 |
| 主流程 | 加字段向导：选类型（常用置顶：文本/整数/小数/布尔/日期/枚举；每个类型带一句用途说明）→ 填编码/名称/必填/唯一/默认值 →（枚举类型：选字典或内联定义枚举项）→ 保存 |
| 业界出处 | Salesforce New Custom Field 向导（选型→明细两步式）；简道云/宜搭字段面板的「类型+说明」卡选 |
| 关键约束 | 已发布实体加字段后须重新发布生效（提示条）；唯一+必填组合给风险提示（影响存量数据） |
| 权限码 | `metadata:model:write` |

### UC-W5 校验与发布前自检 ⏳ F4/F7

| 项 | 内容 |
|----|------|
| 参与者 | 应用建模者（触发）/ 系统（执行） |
| 主流程 | ① 录入期即时校验（F4，前端规则）→ ② 详情页「校验」Tab 拉取静态校验结果（F7，后端 API）→ ③ 错误/警告分级展示，点击跳转问题字段 → ④ 存在错误级问题时发布按钮禁用 + Tooltip 原因 |
| 业界出处 | OutSystems TrueChange：常驻问题面板 + 双击跳转；Mendix：一致性错误阻断发布 |
| 异常 | 校验 API 不可用 → 发布按钮保持可用但给警告（降级不误伤，后端发布期仍兜底） |
| 权限码 | `metadata:model:read` |
| 串联出口 | → UC-W7 |

### UC-W6 已发布模型的受限编辑 ✅ 域校验 As-Is / ⏳ F3

| 项 | 内容 |
|----|------|
| 参与者 | 应用建模者 |
| 主流程 | 已发布实体详情：结构性改动项禁用 + 原因文案；「加字段」开放；顶部提示「当前为已发布态，变更将进入下次发布」 |
| As-Is | 后端 `META_ENTITY_PUBLISHED` 拦截 ✅（点保存才报错）；前端无预先引导 ❌ |
| 关键约束 | 删字段永远不可用（归档语义归 2a UC-MT7 / ADR-0017） |
| 权限码 | `metadata:model:write` |

### UC-W7 发布：预览 → 确认 → 结果 ⏳ F8（后端：As-Is 单发 / Target ADR-0039）

| 项 | 内容 |
|----|------|
| 参与者 | 应用建模者（提交）→ 发布审批人（审批，SoD） |
| 主流程 | ① 点「发布」→ 预览 Modal：变更摘要 + 将执行 DDL + 破坏性变更清单（红）→ ② 确认提交 → ③ （Target）走发布包审批 → ④ 结果页：成功/失败 + 失败原因（漂移 409 文案前置到发布前校验尽量拦住） |
| As-Is | Popconfirm「发布后实体将不可编辑」→ 直接裸发布 ❌ |
| 关键约束 | 预览数据在 R1 前可先做**变更摘要级**（实体+字段 diff），R1 后升级为真实 DDL——**两阶段交付，不被 ADR-0039 阻塞** |
| 权限码 | `metadata:release:create`（Target）/ 旧 `metadata:publish` 兼容 |
| 串联出口 | → 2a UC-MT6 交付 |

### UC-W8 权限形态：只读者与无角色者 ⏳ F2（后端 As-Is）

| 项 | 内容 |
|----|------|
| 参与者 | 消费方/查看者（`metadata:model:read`）、无应用角色用户 |
| 主流程 | 只读形态：全页无写按钮、操作列消失、字段值只读渲染；无应用角色 + 有 `model:write`：列表可见但新建/发布禁用 + 「需要 OMS 应用 DEVELOPER 角色」文案（申请入口指引去 IAM） |
| 业界出处 | Dataverse maker 安全角色；Salesforce「按钮可见但被权限拦截」反模式——Bone 显式禁用优于静默报错 |
| 关键约束 | 前端形态由权限码 + `/apps/mine` 的 `myRole` 共同决定；后端 403 兜底不变 |

### UC-W9 运营录数据分流 ✅ As-Is

运行时数据运维从工作台首直达 `RuntimeDataManagement`（或 2a G10 后的「运行时数据」菜单），**不经过建模界面**——权限码 `metadata:runtime:write` 与 `model:write` 已拆分（G5），前端确保录数入口不出现建模按钮。

### UC-W10 建模负责人视角 ⏳（随 G4 R2）

租户建模负责人在工作台看模块级「待发布/审批中」聚合；审批动作归「发布中心」（ADR-0039 落地时设计），工作台仅展示计数与跳转。本文不做审批 UI。

## 5. 实施批次

| 批次 | 内容 | 依赖 | 自证口径 |
|------|------|------|---------|
