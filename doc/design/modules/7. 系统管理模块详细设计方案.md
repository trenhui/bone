## 1. 模块概述

### 1.1 模块定位

系统管理模块是BONE平台的支撑模块，负责系统的配置管理、监控告警、日志管理和部署支持，确保系统的稳定运行和可维护性。该模块提供了全面的系统管理功能，包括系统配置的管理、监控指标的收集和分析、告警的配置和处理、日志的管理和分析，以及Kubernetes部署的支持。

### 1.2 核心功能

- **系统配置**：管理系统全局配置，调整系统参数，控制功能开关
- **监控告警**：查看系统监控指标，配置告警规则，接收告警通知
- **日志管理**：查看系统运行日志，支持日志搜索和分析
- **Kubernetes部署支持**：通过Helm Chart在Kubernetes集群中一键部署BONE平台
- **系统健康检查**：监控系统各组件的健康状态
- **系统指标收集**：收集系统运行的关键指标

### 1.3 设计目标

- **可靠性**：确保系统的稳定运行和高可用性
- **可观测性**：提供全面的系统监控和日志管理能力
- **可维护性**：简化系统管理和维护流程
- **安全性**：确保系统配置和管理操作的安全性
- **易用性**：提供简单直观的系统管理界面
- **可扩展性**：支持系统的水平扩展和功能扩展

## 2. 功能设计

### 2.1 系统配置

**功能描述**：管理系统全局配置，调整系统参数，控制功能开关。

**核心功能**：
- 修改系统配置：修改配置项（如服务端口、缓存大小、日志级别）
- 管理功能开关：开启或关闭功能开关（如代码生成、主数据管理）
- 查看配置历史：查看配置变更历史
- 导入/导出配置：批量导入和导出配置

**业务规则**：
- 配置项分为：系统级、服务级、功能级
- 敏感配置项（如数据库密码）支持加密存储
- 配置变更支持版本管理
- 配置变更需要记录审计日志

### 2.2 监控告警

**功能描述**：查看系统监控指标，配置告警规则，接收告警通知。

**核心功能**：
- 查看监控指标：查看系统指标（CPU、内存、磁盘使用率）、服务指标（API响应时间、错误率、QPS）、数据库指标（连接数、查询响应时间）
- 配置告警规则：添加、编辑、删除告警规则
- 接收告警通知：通过邮件、短信、企业微信、钉钉等方式接收告警通知
- 查看告警历史：查看历史告警记录

**业务规则**：
- 支持的告警级别包括：严重、警告、信息
- 支持的通知方式包括：邮件、短信、企业微信、钉钉
- 告警规则支持按时间范围设置
- 告警通知需要记录审计日志

### 2.3 日志管理

**功能描述**：查看系统运行日志，支持日志搜索和分析。

**核心功能**：
- 查看系统日志：查看系统运行日志，包括时间、级别、服务、内容
- 搜索系统日志：按时间范围、级别、服务、关键词等条件搜索日志
- 分析系统日志：生成日志分析报告，包括错误分布、趋势分析、热点服务等
- 导出系统日志：导出日志为Excel、CSV格式

**业务规则**：
- 日志级别包括：ERROR、WARN、INFO、DEBUG、TRACE
- 支持按多条件组合搜索
- 日志支持导出为Excel、CSV格式
- 日志保留期：180天

### 2.4 Kubernetes部署支持

**功能描述**：通过Helm Chart在Kubernetes集群中一键部署BONE平台，并自动配置监控和告警。

**核心功能**：
- Helm Chart管理：提供官方Helm Chart，支持配置MySQL、Redis、RocketMQ等外部依赖
- 自动水平伸缩：基于CPU和内存阈值自动调整Pod副本数
- 监控集成：自动配置Prometheus监控和Grafana仪表盘
- 高可用配置：提供PodDisruptionBudget保证可用性
- 滚动更新：支持滚动更新策略，确保服务不中断

**业务规则**：
- 支持Kubernetes 1.24+版本
- 支持自动水平伸缩（HPA）：基于CPU和内存阈值
- 提供PodDisruptionBudget保证可用性（minAvailable: 2）
- 支持滚动更新策略（maxSurge: 25%，maxUnavailable: 0）

## 3. 技术实现

### 3.1 技术栈选型

| 技术 | 版本 | 用途 |
|------|------|------|
| Java | 17+ | 核心开发语言 |
| Spring Boot | 3.2+ | 后端框架 |
| Prometheus | 2.45+ | 监控系统 |
| Grafana | 10.0+ | 监控面板 |
| ELK Stack | 8.0+ | 日志管理 |
| Kubernetes | 1.24+ | 容器编排 |
| Helm | 3.0+ | 应用管理 |
| Redis | 7.0+ | 缓存 |
| MySQL | 8.0+ | 关系型数据库 |

### 3.2 架构设计

**架构层次**：
- **前端层**：系统管理界面，提供系统配置、监控告警、日志管理等操作
- **应用层**：系统服务，处理系统管理的业务逻辑
- **引擎层**：监控引擎、日志引擎、部署引擎
- **数据层**：存储系统配置、告警规则、系统日志等数据

**核心流程**：
1. 用户通过前端界面管理系统配置
2. 系统服务处理配置变更，更新配置存储
3. 监控引擎收集系统指标，触发告警
4. 日志引擎收集和分析系统日志
5. 部署引擎管理Kubernetes部署

### 3.3 核心组件

| 组件 | 职责 | 技术实现 |
|------|------|----------|
| 系统服务 | 处理系统管理的业务逻辑 | Spring Boot 3.2 |
| 监控引擎 | 收集和分析系统指标 | Prometheus + Grafana |
| 日志引擎 | 收集和分析系统日志 | ELK Stack |
| 部署引擎 | 管理Kubernetes部署 | Helm + Kubernetes API |
| 配置管理器 | 管理系统配置 | Spring Boot 组件 |
| 告警管理器 | 管理告警规则和通知 | 自定义组件 |

### 3.4 监控实现

**监控体系**：
- **基础设施监控**：CPU、内存、磁盘、网络
- **应用监控**：API响应时间、错误率、QPS
- **业务监控**：实体创建数、代码生成数、流程执行数

**监控工具**：
- **Prometheus**：收集和存储监控指标
- **Grafana**：可视化监控指标
- **Alertmanager**：处理告警通知

**监控指标**：
- JVM指标：堆内存使用、GC次数、线程数
- 应用指标：请求数、响应时间、错误率
- 数据库指标：连接数、查询响应时间
- 系统指标：CPU使用率、内存使用率、磁盘使用率

### 3.5 部署实现（**[Vision]**）

> **As-Is**：仓库内**无** `bone-chart/` Helm 目录，部署形态以 Spring Boot 可执行 Jar + 环境变量为主（见 [wiki/03-本地开发与构建.md](../../wiki/03-本地开发与构建.md)）。下列 Helm/K8s 内容为路线图示例，落地见 `doc/deployment/`。

**[Vision] Helm Chart结构**：
```
bone-chart/
├── Chart.yaml
├── values.yaml
├── templates/
│   ├── deployment.yaml / service.yaml / ingress.yaml
│   ├── configmap.yaml / secret.yaml
│   ├── hpa.yaml / poddisruptionbudget.yaml
│   └── serviceaccount.yaml
```

**[Vision] 部署命令**：
```bash
helm install bone ./bone-chart \
  --set database.host=mysql \
  --set redis.host=redis \
  --set nacos.host=nacos
```

**部署配置（规划）**：
- **开发**：单节点 K8s，内嵌中间件
- **测试 / 预生产 / 生产**：多节点 K8s + 独立 MySQL/Redis；生产高可用 + 多 AZ

## 4. 数据模型

### 4.0 表清单（已实现）

见 [`bone-init.sql`](../../../bone-init.sql) §2 · [数据库开发规范.md](../../architecture/数据库开发规范.md) §2.2：

| 表 | 说明 |
|----|------|
| `sys_config` | 配置（`tenant_id` + `config_key` 唯一，`encrypted`，标准审计） |
| `sys_log` | 日志（`level`，`service`，`content`，`trace_id`，`created_at`） |
| `sys_alert_rule` | 告警规则（`metric_name`，`threshold_value`，`alert_level`，`enabled`） |
| `sys_alert_event` | 告警事件（`rule_id`，`current_value`，`status` OPEN/ACK/RESOLVED） |

代码模块：`bone-platform/bone-system`。

### 4.1 字段说明（与 init 对齐）

- **时间与操作人**：`created_by`、`updated_by`、`created_at`、`updated_at`。
- **配置**：列名 `encrypted`（对应领域 `encrypted`），`config_type` 为 SYSTEM/SERVICE/FEATURE。
- **告警规则**：列名 `name`、`metric_name`、`threshold_value`、`alert_level`、`enabled`。

### 4.2 规划扩展（未入 init）

`sys_config_history`（配置变更历史）、`sys_system_log`（增强日志/分区）、敏感配置 `is_sensitive` 等 — 落地时追加 `bone-init.sql`，勿维护详设 SQL 副本。

## 6. 部署与集成

### 6.1 部署架构

> **As-Is**：`bone-platform/bone-system` 默认 :8083（Spring Boot 可执行 Jar）；不强依赖 Prometheus/Grafana/ELK 等外置组件。下列 K8s/Prometheus 全栈为 **[Vision]**。

**[Vision] 部署方式**：
- 与 BONE 平台其他服务一起部署在 Kubernetes 集群中
- 使用 Helm Chart 进行应用管理（见 §3.5）
- 支持水平扩展，根据系统负载自动调整实例数

**[Vision] 资源配置（参考值，落地前先压测）**：
- 每个系统服务实例：2 核 CPU / 4GB 内存
- Prometheus：4 核 CPU / 8GB 内存 / 50GB 存储
- Grafana：2 核 CPU / 4GB 内存
- ELK Stack：按日志量调整

### 6.2 集成方式

**与其他模块的集成**：
- 与管理服务集成：提供统一的管理界面
- 与IAM服务集成：控制系统管理权限
- 与监控系统集成：收集和分析系统指标
- 与日志系统集成：收集和分析系统日志

**集成接口**：
- 提供系统配置的API
- 提供监控指标的API
- 提供日志管理的API

### 6.3 配置管理

**配置项**：
- 系统配置：服务端口、缓存大小、日志级别
- 监控配置：监控指标、告警规则
- 日志配置：日志级别、日志存储
- 部署配置：Kubernetes部署参数

**配置管理**：
- 使用Nacos作为配置中心
- 支持配置热更新
- 配置变更记录和审计

## 7. 性能与安全

### 7.1 性能优化

**性能优化措施**：
- 缓存策略：使用Redis缓存系统配置和监控指标
- 异步处理：日志收集和分析异步处理
- 批量处理：批量处理配置变更和告警通知
- 数据库优化：合理索引，优化查询
- 连接池：使用数据库连接池和HTTP连接池

**性能指标**：
- 系统配置响应时间：<100ms
- 监控指标查询时间：<500ms
- 日志搜索响应时间：<2000ms
- 系统能支持的最大并发请求数：≥1000

### 7.2 安全措施

**安全措施**：
- 权限控制：基于RBAC的细粒度权限控制
- 传输加密：使用TLS 1.3加密所有网络传输
- 存储加密：敏感配置使用AES-256加密存储
- 访问控制：限制系统管理API的访问
- 审计日志：记录系统管理操作

**安全策略**：
- 最小权限原则：用户只能访问必要的系统管理功能
- 定期安全审计：定期审计系统配置和权限
- 安全备份：定期备份系统配置和监控数据

## 9. 监控与告警

> 通用 SLI/SLO、Prometheus 指标命名、ELK 日志规范统一参考 [`doc/architecture/Bone-可观测性规范.md`](../../architecture/Bone-可观测性规范.md)（若未单列，则以 IAM §9 模板为基线）。

系统管理特有指标与告警：

| 类别 | 关键指标 | 数据来源 |
|------|----------|----------|
| 配置 | `sys_config_change_total{by_user}` / `sys_config_encrypted_total` | `ConfigController` AOP |
| 告警 | `sys_alert_event_open_total` / `sys_alert_rule_evaluations_total` | `AlertController` |
| 日志 | `sys_log_write_qps` / `sys_log_level_distribution` | `LogController` |
| 平台资源 | CPU / 内存 / 磁盘 / DB 连接池 / Redis 命中率 | Micrometer（**[Vision]** 经 Prometheus 上报） |

**告警规则示例（[Vision]，配 Prometheus）**：CPU >80% / 内存 >85% / 磁盘 >90% / API 错误率 >5% / DB 连接 >80% 池容量。
**告警通道**：邮件 · 短信 · 企业微信 · 钉钉（**[Vision]**，As-Is 仅 `sys_alert_event` 落库 + 前端展示）。

**日志**：内容、ELK 收集与保留策略统一参考可观测性规范。当前 As-Is `sys_log` 默认保留 **180 天**（含 trace_id），见 §2.3；ELK / 可视化为 **[Vision]**。

## 10. 总结

系统管理模块是BONE平台的支撑模块，提供了全面的系统管理功能，包括系统配置管理、监控告警、日志管理和Kubernetes部署支持。该模块确保了系统的稳定运行和可维护性，为平台的其他模块提供了可靠的基础设施支持。

**核心优势**：
- **全面的监控能力**：提供系统、应用、业务等多维度的监控指标
- **灵活的告警机制**：支持多种告警级别和通知方式
- **强大的日志管理**：支持日志搜索、分析和导出
- **便捷的部署支持**：通过Helm Chart一键部署BONE平台
- **高可用性**：支持系统的高可用配置和自动伸缩
- **安全性**：提供细粒度的权限控制和安全措施

**应用场景**：
- 系统运维：监控系统运行状态，及时发现和解决问题
- 系统配置：管理系统参数，优化系统性能
- 故障排查：通过日志分析定位和解决故障
- 系统部署：快速部署和升级BONE平台
- 性能优化：通过监控指标分析系统性能，进行优化

系统管理模块的设计充分考虑了可靠性、可观测性和可维护性，为BONE平台提供了强大的系统管理能力，使平台能够稳定运行并快速响应业务需求的变化。
