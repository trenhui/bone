## 1. 最佳方案的"取各家之长"取舍

### 1.1 模型设计（入口页）—— 串联"冷启动零前置 + hero + rail"
- 取 act1 的 **模板起盘冷启动**：模板 Modal 内左侧模板列表 + 右侧字段与真实形态（明细子表/类别引用/5 态状态机）同屏亮出，"实例化并进入结构"一步落位；无应用也能起盘（个人草稿箱暂存，发布前补归属）。
- 取 v3 的 **磁贴 hero（Action-first）** + **双栏 rail**：首屏零滚动掌握全部状态；待发布草稿用行列表而非网格（避免"第二份列表"观感）。
- 取 v3 的 **无应用空状态 / 内联建应用模块（O1/O2）**：缺容器时同页建，不踢去 IAM。
- 新增 **步骤引导条（选起点→定义结构→发布）** 与 **⌘K 命令面板提示**：降低首屏认知负荷，显式提示快捷入口。

### 1.2 业务对象（清单真源）—— 单表 + 状态驱动操作
- 取 v3 的 **左树 + 单表**（模块列/更新时间列替代 N 张分组卡片，解 B3/B4/B5）。
- 取方案的 **操作列收敛**：按状态呈现 —— 已发布 `[打开][数据][更多▾]`、草稿 `[打开][发布][更多▾]`；`更多`含 复制/导出/**删除（Modal.confirm 安全，规避 Popconfirm-in-Dropdown 竞态）**，列宽收敛不再换行（解 B1）。
- 取 v3 的 **导入合并 `[导入▾]`**（解 B2）+ **左树选中模块自动带入**（O3）+ **⌘K 提示**。
- 新增 **批量发布**（选中草稿行→顶部浮现操作条）：高频运营动作的批处理，贴合"工作台该给待办一键动作"的 IE 原则。

### 1.3 业务数据（跨实体运营台）—— 状态驱动闭环
- 取 v2 的 **最近操作实体 chips**（避免每次重选数百候选）。
- 取 v2 的 **报销单录入抽屉**：申请人/部门自动带、金额 min 实时校验（对应 RC-007）、明细子表逐行、附件清单。
- 取 v2 的 **状态驱动操作**：草稿=编辑/提交/删除；待审批=查看/撤回；已通过=查看/打款；已打款=查看。与流程串联一致。

### 1.4 串联 —— 深链衔接，不复制数据
- 取 expense-flow 的 7 步动线：模型设计"发布"→ 业务对象自动出现实体 → 行内"数据"经 `#/entities/{id}/data` 直跳业务数据并锁定实体；三页职责不重叠，单实体录入走实体详情"数据"Tab（带上下文不会看错对象）。

## 2. 最佳方案的关键交互决策（为什么）

| 决策 | 采用自 | 为什么（对标） |
|------|--------|----------------|
| 入口页首屏 = 磁贴 hero，而非指标/列表 | v3 (D1) | 飞书/钉钉/NocoBase 首页把主行动放最顶；入口页核心是教用户"怎么开始" |
| 待发布=行列表，非卡片网格 | v3 (D3) | 待办应紧凑+一键动作；网格会像"第二份对象列表"，与"业务对象=唯一真源"冲突 |
| 无应用时空状态替代禁用按钮 | v3 (O1) | NocoBase/宜搭：零容器同页建，不踢去别处，消除首次激活断层 |
| 创建向导内联建应用/模块 | v3 (O2) | Salesforce 内联上下文创建；跨微应用跳转成本高、用户未必有 IAM 入口感知 |
| 业务对象操作列 ≤3 inline + 更多 | v3 (B1) | Ant Design Pro 行操作"主动作+更多"；主路径突出、视觉噪音降 |
| 删除用 Modal.confirm 置于"更多" | 诊断补充 | 规避 Dropdown 内嵌 Popconfirm 的菜单关闭竞态（已踩坑） |
| 左树+单表，不双表 | v3 (B3) | 单表+模块列即可，不必 N 张嵌套表；降冗余与横向滚动 |
| 补"最近更新"列 | v3 (B4) | 运营型列表普遍带时间/操作人，支撑巡检 |
| 最近操作实体 chips | v2 | 飞书/Notion"最近打开"；高频巡检用户每次重选是重复摩擦 |
| 录入抽屉 + 金额 min 实时校验 | v2 | 对应 RC-007 规则引擎；提交前拦截，错误不进库 |
| 状态驱动行操作 | v2 | 不同生命周期阶段只暴露合法动作，防误操作（草稿才提交、已通过才打款） |

## 3. 不做的事（约束）
- 不搬 IAM 完整应用管理进元数据应用（仅内联最常用的"建应用/建模块"，完整授权仍归 IAM，无权限回退提示）。
- 不复制数据：模型设计不管清单、业务对象不管录入、业务数据只做跨实体/运营。
- 不新增"审批台"独立页（审批在业务数据页内按状态驱动动作完成，保持 MVP 闭环）。
