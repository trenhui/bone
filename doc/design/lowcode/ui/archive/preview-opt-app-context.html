模型设计
本图聚焦「应用选择 / 创建」动线优化对照 Salesforce（对象与 app 解耦）/ Airtable·宜搭（容器内联自助建）。优化点 ①②③④⑤。

① 模型设计 · 新建不再被「无应用」挡死

＋ 新建模型 一步进编辑器
草稿可暂不带归属；归属（应用/模块）在编辑器头部随时改，或选「稍后分配」。
归属 可在编辑器内改
📦 从模板
实例化行业模型，归属在实例化时选（可后补）。
①原版无可写应用时「空白建模/导入」磁贴直接 disabled（L292/299），用户被推出门。优化：主 CTA 永远可按，归属用上次使用预填 + 「稍后分配」可选——结构归属是进阶决策，不该挡住"先画个模型"（渐进披露）。对标 Salesforce 对象创建与 app 解耦。

③ 无应用？就地「创建 / 申请」，而非跳 IAM 死路

现状：无应用时仅显示 Alert「还没有可建模的应用，请去 IAM 创建」——死路，本应用内无任何创建入口。
优化：两条自助路径
⚡ 快速创建应用
若你有平台/租户级权限，内联建应用（或一键深链 IAM，建完带回并预填）。
🔑 申请应用权限
无创建权限时，提交申请给应用管理员；状态可见（待审/已批），批后自动进入。
③原版把用户弹到 IAM 是典型"摩擦悬崖"。Airtable/宜搭 把容器创建做成自助；治理仍可在 IAM（应用 CRUD 归 IAM 不变），但**前门不 dead-end**：有平台权限→内联/深链建完带回；无权限→提交申请（状态可见），而不是 Alert 一句"去 IAM"。
