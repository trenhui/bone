# 界面设计器字典打通设计方案

> 问题来源：界面设计器（`/metadata#/entities/{id}?tab=uischema`）的字典配置是否应与系统管理字典、主数据、外部服务接口打通。
> 结论：**建议打通，但不是三方合并成一个字典库，而是「分层真源 + 单向引用 + 统一解析」**。
> 状态：v1.1 已实施并通过联调，2026-10-21 全量终验通过后归档（#1–#4、#6、#7、#9、#10 已落地，见下方实现状态表；#5 为文档论证项、#8 为 P2 后续范围；DDL 部分走 L3 审批）。

## 1. 现状核实（代码证据，非转述）

| 面 | 现状 | 证据 |
|---|---|---|

| 事件机制 | bone-system 已有进程内领域事件（`SpringDomainEventPublisher` + `@TransactionalEventListener(AFTER_COMMIT)`），但**无跨服务 MQ** | `infrastructure/event/SpringDomainEventPublisher.java`；integration 的 outbox 仅服务自身 |
| 主数据参考值域 | `mdm_reference_set/value`，平台只写、多方只读、租户可扩展私有值，配套 steward/血缘/质量 | `ReferenceSet.java`、`TenantReferenceValue.java` |
| 外部接口 | `int_connector` + `int_flow` 已具备外部服务注册、编排、执行日志、outbox 重试 | `Connector.java`、`IntegrationFlow.java` |
| 断裂点 | `MetaField` 无值域绑定字段，枚举只能手抄进 `enumValues` JSON 文本 | `MetaField.java`（字段清单无 `dictTypeCode`） |

**三个具体断裂**：

1. **重复建设**：平台字典体系已成熟，但界面设计器完全绕开它，枚举走无治理、无版本、无多语言、无审计的 JSON 文本。
2. **口径分裂**：同一个「性别 / 状态 / 币种」在系统字典、主数据值域、`enumValues` 三处各存一份，改一处不生效另两处——「配了不生效」正是当前最高发的正确性债务类型。
3. **外部值域无入口**：组织架构、供应商、客户等来自外部系统的动态码表，现在只能手工抄录，无法同步、无法感知过期。

不打通还会有两个后果：字典本是主数据「数据标准」的落地基座（系统字典立项提案原话），界面侧绕开它等于数据标准在 UI 层落空；`enumValues` + UI 覆写已允许改名/隐藏，若为图方便再放开「UI 层新建选项」，协议 S7 防线即失守，参照完整性无从保证。

## 2. 业界最佳实践对标

| 平台/规范 | 机制 | 借鉴点 |
|---|---|---|
| SAP S/4（Domain / Data Element） | 字段的数据元素绑定值域（Domain），数据类型 + 固定值 + 格式约束集中在值域定义，屏幕只引用不定义 | 「字段 → 值域」单向绑定；值域自带格式校验（本平台 `valueType/valueRegex` 已有） |
| SAP value table | Domain 可绑 check table，落库时做外键检查 | 反例参考：物理外键不适合动态/跨租户值域，见 §4.6 |
| Salesforce Global Picklist | 全局选项集一处定义、多字段引用；字段可限本地取值子集；修改全局集时提示影响范围 | 全局集 + 字段级子集，恰是本方案「绑定 + UI 覆写 hidden」的产品化；变更影响提示 → 引用方清单 + 变更预览 |
| Dynamics 365 Global Option Set | 全局选项集与本地选项集分层；解决方案分层（managed / unmanaged） | 平台内置（`builtin=1`）+ 租户私有两级治理，与 `tenantId=0` 语义同构 |
| OpenAPI / 公共 API 演进 | enum 只增不改不删；下线走 deprecate 过渡期：新消费方不可见、旧消费方仍可用 | §4.5 三态生命周期的直接来源 |
| Confluent Schema Registry | 变更按兼容性分级（BACKWARD / FORWARD / FULL），不兼容变更显式拒绝或走新版本 | §4.4 兼容性矩阵的直接来源 |
| HTTP 缓存（RFC 5861 stale-while-revalidate） | 缓存过期后先返旧值、后台异步刷新，配版本协商避免不一致放大 | §4.3 一致性策略的直接来源 |
| OutSystems Static Entity | 低代码平台把枚举建模为「静态实体」，表单绑定实体而非内联选项 | 「值域即一等公民」的产品形态验证 |
| MDM（Informatic/SEM 实践） | 参考数据 steward + 质量 + 血缘；迁移用 match/merge 规则；外部系统标识映射（external ID） | 主数据值域治理框架 + §5.3 迁移向导 + §6 externalCode 对账 |

**共同结论**：业界没有「UI 层自建字典」的实践，全部是「集中值域 + 字段绑定 + 局部覆写」。本平台协议 S7 与业界一致，缺的是把「引用」从「只能引用 enumValues」扩展为「可以引用各级真源」，并把「值域变更怎么办」从空白补齐为分级策略（§4.4/§4.5）——后者恰恰是评审最可能被挑战的部分。

## 3. 目标架构：四层真源 + 单向引用 + 统一解析

```
┌──────────────────────────────────────────────────────────────┐
│ 界面设计器（UiSchemaTab → DictionaryPanel）                    │
│   只引用值域 code；覆写仅限 labelOverride / hidden              │
└──────────────────────────┬───────────────────────────────────┘
                           │ 单向引用（UI → 真源）
                           ▼
┌──────────────────────────────────────────────────────────────┐
│ 统一解析层 OptionsProvider（metadata-server 投影层落点）        │
│   ① 绑定解析  ② 真源取值（/options + 版本协商）                 │
│   ③ 快照比对  ④ UI 覆写  ⑤ 写校验（双口径）                    │
└──────┬──────────────┬──────────────┬──────────────────────────┘
       ▼              ▼              ▼
┌────────────┐ ┌────────────┐ ┌───────────────┐ ┌──────────────┐
│ L1 平台字典 │ │ L2 主数据   │ │ L3 外部同步    │ │ L0 实体私有  │
│ sys_dict   │ │ 参考值域    │ │ Connector/Flow│ │ enumValues  │
│ 三态生命周期│ │ steward治理 │ │ 定期同步物化   │ │ 元数据维护   │
└────────────┘ └────────────┘ └───────────────┘ └──────────────┘
       │              │              │
       └──────────────┴──────────────┘
              回流：漂移检测 → 设计器徽标（真源变更不静默）
```

### 3.1 四层真源（按治理强度分层，各层职责唯一）

| 层 | 真源 | 适用值域 | 维护入口 | 治理能力 |
|---|---|---|---|---|
| L1 | bone-system `sys_dict_type / sys_dict_item` | 跨模块通用：性别、状态、币种、地区、行业、UOM | 系统管理 → 字典配置 | 内置禁删、租户覆盖、多语言、层级、值格式校验、生效窗口、**三态生命周期**（§4.5）、漂移检测（均已具备或零 DDL 扩展） |
| L2 | bone-masterdata `mdm_reference_set / value` | 需治理的参考数据：客户分级、供应商等级 | 主数据模块 | steward、质量规则、血缘、订阅（均已具备） |
| L3 | bone-integration `Connector / Flow` 同步通道 | 外部系统动态码表：组织架构、外部主数据 | 集成模块 | 连接器、执行日志、outbox、健康度 |
| L0 | `meta_field.enumValues`（保留不动） | 实体本地小码表：发票类型、单据状态 | 元数据建模 | 元数据版本（随实体发布） |

**「打通」的准确含义**：设计器字典面板从「只能读 enumValues」扩展为「可引用 L1/L2/L3 真源」，引用是单向的（UI → 真源），真源变更通过漂移检测回流为设计器内的可见告警，绝不变更静默生效。

**打通前先回答两个问题**（沿用权限迁移的决策法，每个枚举字段归模时过一遍）：
1. 这个值域的治理者是谁？（平台 / 租户 / 主数据 steward / 外部系统）——决定归到哪一层。
2. 变更应该影响谁？（全部引用方 / 仅本实体 / 仅本场景）——决定用绑定（全局生效）还是 variants（场景差异），避免把场景差异错误地做成值域分裂。

## 4. 模型与协议增量

### 4.1 元数据模型（DDL 走 L3 审批）

`MetaField` 新增两个字段，**不替换、不迁移存量 `enumValues`**：

| 字段 | 类型 | 语义 |
|---|---|---|
| `dict_type_code` | VARCHAR(64) 可空 | 绑定值域编码（L1/L2 统一用 code 寻址，L3 通道 code 另行注册表）。为空 = L0 本地枚举，行为与现状完全一致 |
| `dict_snapshot` | JSON 可空 | 发布时点的选项快照（code + label + state + 生效窗口 + 字典版本号），见 §4.3 |

`SysDictItem.status` **不新增列**（Integer 列语义扩展，零 DDL）：`1 = ACTIVE`，`2 = DEPRECATED`，`0 = DISABLED`（§4.5）。

### 4.2 UI 协议增量（v1.3，向后兼容）

```json
"dictionaries": {
  "gender": {
    "source": { "kind": "dict", "code": "GENDER", "snapshotVersion": 3 },
    "labelOverride": { "M": "男" },
    "hidden": ["U"]
  }
}
```

不变量在 S7 基础上新增两条，由发布门禁强制：

| # | 不变量 | 强制点 |
|---|---|---|
| S8 | `source.code` 必须存在于对应真源注册表，否则 schema 校验 ERROR（禁止悬空绑定） | metadata-server validate + 发布预检 |
| S9 | 写校验按快照口径执行，且区分 DEPRECATED / DISABLED：DISABLED 拒绝、DEPRECATED 放行（存量兼容）；渲染集 = 实时选项（仅 ACTIVE）∩ 快照 | 运行时引擎 + 后端写校验 |

### 4.3 一致性策略：快照 + 版本协商 + stale-while-revalidate

v1.0 的「纯快照 + 重新发布刷新」有两个弱点：刷新不及时（要等发布）、以及跨服务没有刷新通道。v1.1 改用三层混合，**不引入跨服务 MQ**（现网只有进程内事件总线，新建消息基础设施超出本方案范围纪律）：

| 层 | 机制 | 职责 |
|---|---|---|
| 快照（兜底） | 发布时固化选项进 `dict_snapshot` | 确定性渲染、写校验口径、字典服务宕机时降级 |
| 版本协商（日常） | `/options` 响应新增 `version`（值域版本号，任何变更递增）；metadata-server 投影缓存带 TTL，TTL 内先返缓存（stale），同时后台带版本号比对，不一致则刷新 | 字典变更在分钟级到达绑定字段，无需人工重新发布 |
| 进程内事件（同服务） | 复用 `SpringDomainEventPublisher`：字典项变更后发 `DictItemChangedEvent`，bone-system 自身 `DictOptionsCache` 立即失效（对齐 config 模块 `ConfigHistoryProjector` 先例） | 同服务内零延迟；跨服务分钟级（TTL + 版本比对） |

**为什么不让「实时覆盖快照」**：渲染取「实时 ∩ 快照」而非「实时全量」——快照是发布口径，实时是运营态；取交集保证「发布时不可见的 code，不会因运营态加了个值就悄悄进新表单」。字典服务不可用时渲染与写校验双双降级到快照，与 blueprint `DictGateway` 的 `Optional.empty + 本地兜底 + TTL` 降级范式一致。

### 4.4 值域变更兼容性矩阵（Schema Registry 模式）

值域变更不是「都能实时生效」的一锅粥，按兼容性分级处置：

| 变更 | 兼容性 | 系统行为 |
|---|---|---|
| 新增 value | BACKWARD compatible | 版本递增 → 投影缓存后台刷新 → 进入新表单；不影响已发布 schema |
| 修改 label | compatible | 实时生效（渲染取实时 label），快照在下次刷新时跟进 |
| 停用 value | breaking for new writes | 转入 DEPRECATED（§4.5）：新表单不可见，存量写仍放行 |
| 删除 value | breaking | 必须先 DEPRECATED 过渡（观察期由 steward 定），历史数据处理方案（归档/迁移）就绪后才可 DISABLED |
| 修改 value code | breaking | 禁止（与 `SysDictType.code` 禁改同构——编码是跨系统业务键，改了等于让所有引用方失效）；确需修改走「新建 + 废弃 + 数据迁移」 |

「breaking 变更必须先过渡」由管理面强制：直接 DELETE 字典项返回 4xx 并提示先停用，从产品上堵住「删了再说」。

### 4.5 字典项三态生命周期（deprecated 过渡态）

```
        ┌──────────────┐  停用请求 / effectiveTo 到期   ┌──────────────┐
        │   ACTIVE     │ ────────────────────────────▶ │  DEPRECATED  │
        │    生效      │ ◄──────────────────────────── │   已废弃     │
        └──────────────┘        撤销弃用（恢复）        └──────┬───────┘
                                                              │ 强制停用（过渡期满）
                                                              ▼
                                                    ┌──────────────┐
                                                    │   DISABLED   │
                                                    │    停用      │
                                                    └──────────────┘
```

| 状态 | 新表单渲染 | 写校验 | 说明 |
|---|---|---|---|
| ACTIVE | 出现 | 接受 | 正常态 |
| DEPRECATED | 不出现 | 接受 | 过渡态：新数据不再产生，存量单据仍可保存/回显（迁移期窗口由 steward 定） |
| DISABLED | 不出现 | 拒绝 | 终态：存量数据只读展示 |

与已有 `effectiveFrom/effectiveTo` 配合实现**定时切换**：如「下季度起停用某币种」= 提前置 DEPRECATED + `effectiveTo` 设为下季度初，到期由定时任务转 DISABLED——停用从「运营人员手动点」变成「可计划的变更」，这正是业界 change window 的轻量落地。

判定口诀：**渲染只看 ACTIVE，写校验放行 ACTIVE + DEPRECATED，只有 DISABLED 拦写**。

### 4.6 补一个反例论证：为什么不学 SAP 的物理外键

SAP Domain 可绑 check table，在数据库层做外键检查，写入不合领域外码直接报错。本方案**不采用**物理外键，三个理由：值域是跨租户动态数据（平台级 + 租户覆盖），外键无法表达「按租户裁剪」；字典项随运营持续增删，外键会让删项变成级联灾难；多副本部署下行锁/外键检查的代价与收益不成比例。替代方案是应用层快照口径校验（S9）——把「数据库完整性」上移为「发布口径内的应用完整性」，代价是需自证校验存在（负向探针，见 §8）。

## 5. 界面设计器改造

### 5.1 DictionaryPanel 三态（按字段绑定来源分流）

| 状态 | 判定 | 面板行为 |
|---|---|---|
| 本地枚举（L0） | `dictTypeCode` 为空 | 现状不变（覆写 label/hidden）；新增「升级为平台字典」入口（§5.3） |
| 平台字典（L1） | 绑定存在且归属 L1 | 选项只读展示；真源提示「由系统字典维护」+ 跳转深链；**漂移徽标**（快照 vs 真源：`missingInDict` / `missingInEnum`，复用已有 enum-diff 端点）；覆写仍允许 |
| 主数据 / 外部（L2/L3） | 绑定存在且归属 L2/L3 | 只读 + 新鲜度（最后同步时间、通道健康态）+ 降级说明 |

DEPRECATED 项在面板中以弃用样式展示（置灰 + 「废弃中」标签），让设计者提前感知「这个选项正在下线」，而不是某天突然消失。

### 5.2 控件绑定配置（BasePanel 的 ENUM 控件）

数据源四选一：本地枚举 / 平台字典（带搜索与选项预览的选择器）/ 主数据值域 / 外部同步通道。后两项只列**已注册的白名单 code**，与协议 §13.6 `ATTACHMENT.uploadApi`、S4 同一纪律——禁任意 URL 槽位。

### 5.3 升级迁移向导（L0 → L1，MDM match/merge 规则）

本地 `enumValues` → 与系统字典做 code 集合 diff → 按匹配度分流处理：

| 匹配情形 | 处理 |
|---|---|
| code 集合完全一致 | 直接绑定，零冲突 |
| 字典多出 value | 直接绑定（additive，BACKWARD 兼容，§4.4） |
| 本地多出 value | 引导并入字典（创建缺失项）或保留为本地覆写，二选一明示 |
| **同 code 不同 label** | **告警不阻断**（疑似同码不同义），由建模者确认后绑定——MDM 匹配的标准姿态：机器报疑，人做裁决 |
| **同 label 不同 code** | 告警不阻断，提示确认编码口径 |

绑定成功后原覆写（labelOverride/hidden）自动迁移。

### 5.4 字典管理页反向增强（Salesforce 式变更预览）

- **变更影响预览**：提交字典项变更前，先展示 diff（新增/停用/删除几项）+ 受影响引用方清单（哪些实体/字段/已发布 schema 的快照会过期）——把「改完才发现炸了」前置为「改前就看到影响」。
- **被引用情况**：某值域被哪些实体/字段绑定（引用方清单本体）。
- **漂移告警入口**：从字典侧看到「哪些绑定字段的快照已过期、待刷新」。

## 6. 外部服务接口打通（受控同步 + 对账回流）

**不做设计器直连外部 HTTP**（违反 S4 白名单纪律，且把凭据/超时/重试散进 UI 层）。走平台已有集成能力：

1. 外部值域注册为 `Connector` + `Flow`（拉取型），执行结果物化到 `sys_dict_item`（L1 承接）或 `mdm_reference_value`（L2 承接）。
2. 同步项利用已有 `externalCode` 字段回写外部系统编码——这是双向对账的基础：下次同步按 externalCode 比对外部侧增删，本地停用项也能回推外部（避免「外部还以为生效」）。
3. 设计器只引用「同步通道 code」——通道即白名单，与上传通道同构。
4. **新鲜度与降级**：每次同步记录 `executedAt` 与健康态；运行时 `/options` 拉取失败 → 降级到发布快照（§4.3）；漂移超阈值 → 设计器告警。
5. **灰度开关**：`dictBinding` 特性开关按租户灰度开放，P0 上线默认关、逐租户开——绑定功能本身不打破任何存量租户。

## 7. 运行时统一解析链

```
字段渲染 / 写校验
 ① 绑定解析：dictTypeCode 有值 → 真源寻址（L1/L2/L3 统一 OptionsProvider）
              为空 → parseEnumValues(enumValues)（L0，现状路径）
 ② 真源取值：GET /api/v1/system/dict/items/options（平台+租户覆盖合并、生效过滤、lang）
             响应带 version；投影缓存 stale-while-revalidate
 ③ 快照比对：渲染集 = 实时（仅 ACTIVE）∩ 发布快照（S9）
 ④ UI 覆写：dictionaries[code].labelOverride / hidden（最后生效）
 ⑤ 写校验：值 ∈ 快照口径，DISABLED 拒绝 / DEPRECATED 放行 / ACTIVE 接受（不依赖字典服务在线）
```

服务端落点：metadata-server 投影层（与 N7 字段级可见性同位置）在 ui-schema 投影时完成绑定解析、code 存在性校验、快照注入；前端引擎在 `uiSchemaEngine` 解析控件 options 时消费同一结构。**同一份绑定声明，渲染与写校验共用，杜绝「显示能选、提交报错」两套口径。**

## 8. 验收口径（每期可验证）

| 分期 | 范围 | 验收判据 |
|---|---|---|
| P0 读通 | `dictTypeCode` + 快照 + 设计器三态展示 + 深链 + 运行时解析 + 灰度开关 | E2E 探针：绑定字段的选项来自系统字典而非 enumValues；字典停用某项后新表单不再出现、历史数据回显正常；变异验证（移除绑定解析 → 探针转红）；开关关闭时全部行为与现状逐字节一致 |
| P1 治理回流 | enum-diff 复用 + 漂移徽标 + 引用方清单 + 变更预览 + 三态生命周期 + 兼容性矩阵 + 升级向导 | 改字典项 → 设计器出现漂移徽标；直接 DELETE 字典项被拒（breaking 必须先过渡，负向探针）；DEPRECATED 项新表单不可见但存量写放行（双口径断言）；向导产物通过发布门禁（悬空绑定被拒） |
| P2 主数据 + 外部 | L2 值域接入统一 OptionsProvider；外部同步通道 + externalCode 对账 + 健康度 | 同步通道断网 → 运行时降级到快照且告警可见；恢复后按版本协商自动刷新；写校验在字典服务宕机时仍按快照放行/拦截 |

**三个可观测指标**（上线后持续度量，支撑量化验收）：

| 指标 | 定义 | 健康方向 |
|---|---|---|
| 绑定覆盖率 | 已绑定真源的 ENUM 字段 / 全部 ENUM 字段 | 逐季上升（L0 长尾自然存在，不追求 100%） |
| 降级率 | 快照兜底渲染次数 / 总渲染次数 | 趋近于 0；突增 = 字典服务故障信号 |
| 漂移待刷新数 | 快照版本落后于真源版本的绑定数 | 趋近于 0（版本协商生效的证明；持续走高说明刷新链路坏） |

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 字典变更影响全部引用方（改一个标签，N 个表单变） | 引用方清单 + 变更预览 + 快照版本化；重新发布才改口径，无静默变更 |
| 字典服务不可用拖垮表单 | 渲染降级到发布快照；写校验用快照口径；沿用 `DictGateway` 的 Optional + TTL 降级范式 |
| 版本协商的最终一致性窗口（分钟级内新旧并存） | 快照永远可用（兜底）；DEPRECATED 过渡态天然容忍窗口期（新旧都不炸）；窗口长度 = TTL，可配置 |
| `status` 语义扩展（1/2/0）的存量兼容 | 存量只有 1/0，2 为新增语义；读侧按 `==1` 判 ACTIVE 的逻辑改为 `>=1`？——不，正确做法：渲染/写校验统一走新的 `state()` 判别函数，一次改全，测试断言三态行为 |
| 存量迁移成本 | 向导式 code 集合 diff + match/merge 冲突规则 + 双轨并存，不强制 |
| 覆写与真源漂移（覆写了已删除的 code） | 发布门禁校验「覆写 code ∈ 快照」；漂移徽标 |
| 多租户口径 | 复用 `tenantId=0` 平台级 + 租户覆盖合并语义（`/options` 已实现） |
| 范围蔓延（想着手做「字典引擎」或「消息总线」） | 只做绑定、解析、快照、告警四件事；一致性用 HTTP 缓存标准实践而非新建 MQ；值域治理复用现有模块 |

## 11. 复用资产清单（不造重复轮子）

| 需求 | 复用 |
|---|---|
| 取数契约与缓存 | `GET /dict/items/options` + `DictOptionsCache` + `useDict` |
| 跨服务消费与降级范式 | `bone-blueprint DictGateway`（Optional + 兜底 + TTL） |
| 漂移检测 | `GET /dict/types/{code}/enum-diff`（missingInDict / missingInEnum / valueDrift） |
| 同服务事件失效 | `SpringDomainEventPublisher` + `@TransactionalEventListener(AFTER_COMMIT)`（对齐 `ConfigHistoryProjector` 先例） |
| 定时切换 / 生效窗口 | `SysDictItem.effectiveFrom / effectiveTo` + bone-system 定时任务能力 |
| 外部编码对账 | `SysDictItem.externalCode` |
| 参考值域治理 | `ReferenceSet` + Steward + Lineage + 质量规则 |
| 外部同步 | `Connector` + `Flow` + outbox + 执行日志 |
| 投影层落点 | N7 字段级可见性同一投影位置（ui-schema 三表面交集） |
| 场景差异 | `variants[]`（同租户跨场景走变体，不做值域分裂） |

**新增只有四件**：`dictTypeCode` 绑定字段、发布快照、设计器三态面板、统一 OptionsProvider 抽象。其余全部是语义扩展（status 三态、/options 加 version/state）与流程增强（预览、向导、对账）。
