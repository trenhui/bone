## 1. 执行摘要

### 1.1 产品定位

Synap Equity 是面向**价值投资研究场景**的智能估值研究系统：输入一只股票，输出**数据来源、财务质量、估值区间、核心假设、风险因素与后续跟踪条件**。它不是"问股聊天机器人"，而是**把大模型的表达力压进一个有纪律、可复算、可验证的估值研究框架**。

### 1.2 核心判断与解法

2026 年券商 AI 产品已普遍把行情、基本面、行业研究和智能体结合起来，"自然语言问股票 + 生成分析报告"的同质化能力**没有护城河**。竞争壁垒不在 Agent 编排，而在于：

- **可复算的估值模型**：同一标的、同一输入，任意时刻重跑得到一致结论；
- **财务数据质量校验**：口径统一、异常识别、非经常性损益剥离；
- **估值与实际业绩的持续跟踪**：结论发布后进入跟踪队列，用真实业绩对账；
- **有明确假设和风险边界的决策流程**：估值区间 + 情景分析 + 触发条件，而非单一目标价；
- **对历史结论的前瞻性验证**：回测只使用当时可得数据，主动避免幸存者偏差与未来数据泄漏。

**Synap Equity 解法**：沿用 Synap 的确定性分层思想（与 ClaimSphere 同构），把系统拆为四层——**数据校验层（确定性）→ 估值计算层（确定性）→ 分析增强层（LLM，引用可溯源）→ 跟踪验证层（确定性）**。模型只负责"读和写"，估值数字全部来自确定性计算。

### 1.3 关键指标承诺（MVP）

| **指标** | **目标值** | **阶段** | **说明** |
|---|---|---|---|
| 估值可复算率 | 100% | MVP 可测 | 同一标的+同一时点数据重跑，结论一致（引擎幂等） |
| 报告数字可追溯率 | 100% | MVP 可测 | 报告中每个财务/估值数字均可回溯到数据源与计算过程 |
| 关键假设显式化率 | 100% | MVP 可测 | 每个估值输出必须附带假设清单，缺假设不产出 |
| 估值输出区间化 | 100% | MVP 可测 | 不输出单一目标价，输出区间 + 情景 |
| 数据无未来泄漏 | 100% | MVP 可测 | 时点快照数据架构，快照时间戳审计可查 |
| 估值方向准确率（低估/高估判断） | ≥60% | MVP 后 3 个月 | 区间命中率的前置指标，样本口径见 §13 |
| 研究档案跟踪闭环率 | ≥80% | MVP 后 3 个月 | 已发结论完成对账的比例 |

### 1.4 MVP 范围一句话

**10 只 A 股种子标的，跑通「数据 → 估值 → 报告 → 跟踪」单标的垂直闭环**：PE/PB 估值为主（DCF 为实验性模块）、五维财务体检、数字注入式研究报告、研究档案与手动对账跟踪；不做自动交易、不做实时量化、不做多市场全覆盖、不做行业分位回测自动化（P1 延后）。

### 1.5 战略衔接与资源（可落地性前提）

**定位**：Synap Equity 是创业体系内的**第三条探索线**，不与主攻赛道（Claim）和造血赛道（Bid）抢资源。

| **项** | **口径** |
|---|---|
| 人力 | MVP 期间 **1 人主导**（架构师/CEO 在 Claim 商务等待期切入，或指定 1 人 50%–100% 投入），其余成员按需支援（数据核对、财报领域知识） |
| 资源占比 | 不计入 Claim(50%)/Bid(20%)/Core(30%) 的既定配比，作为探索投入单独核算，上限 ≤1 人全职等价 |
| 进入决策 | 复用创业方案「客户付费意愿/数据可获得性/技术可行性/团队匹配度」打分机制，Equity 得分达阈值（如数据可获得性 ≥7/10）才启动 |
| 继续/暂停 | **继续条件**：数据合规分级达 A 级可用、且 2 周内跑通单标的闭环；**暂停条件**：数据源卡死、或种子用户 2 周内无正反馈、或 Claim 商务突破需回填人力 |
| 与主线的边界 | Equity 所有成果（证据链、确定性分层、档案机制）可回流 Claim/Core，避免重复造轮子 |

## 2. 市场与用户分析

### 2.1 行业背景与痛点

| **痛点** | **表现** | **量化影响** |
|---|---|---|
| AI 报告不可复算 | 同一问题两次回答结论漂移，数字来源不明 | 用户无法对结论做任何验证，只能"感觉" |
| 估值结论被当"预测" | 单一目标价 + 无假设边界，误导决策 | 决策质量无法评估，结论无沉淀价值 |
| 数据口径混乱 | 报告期、币种、复权、母公司/合并报表混用 | 估值计算失真，跨期不可比 |
| 未来数据泄漏 | 用后发的财报"解释"当时的估值决策 | 回测"成功"是幻觉，幸存者偏差被放大 |
| 研究不可持续 | 每次分析都是"一次性报告"，无跟踪 | 无法积累"估值 vs 实际"的长期证据库 |

### 2.2 竞品对标（定性）

| **竞品类型** | **代表形态** | **弱点** | **Synap Equity 切入点** |
|---|---|---|---|
| 券商 AI（智能投研） | 行情+研报+问答 | 结论不可复算、无个人化跟踪、模型即能力 | 可复算估值 + 档案化跟踪 |
| 传统数据终端（Wind/同花顺 iFind 类） | 数据+工具 | 只给数据不给决策框架，学习成本高 | 开箱即用的研究闭环 |
| 通用大模型问答 | 问股、生成报告 | 幻觉、无数据源、无一致性 | 数字全部来自确定性计算与引用 |
| 量化平台（掘金/聚宽类） | 策略回测 | 面向策略编写，非估值研究 | 面向"研究助理"而非"程序员" |

**结论**：Synap Equity 不卖"更聪明的 AI"，卖**"有纪律的估值研究基础设施"**——先证明体系一致、可解释、可验证，再谈长期研究价值。

### 2.3 用户角色与核心场景

| **角色** | **核心场景** | **使用频率** | **关键痛点** |
|---|---|---|---|
| 新手投资者（免费层漏斗） | 看估值卡片学"怎么估值"，被提醒样例引导 | 偶发 | 免费 App 内容不可验证、不知何谓"合理估值" |
| 个人价值投资者 | 输入股票 → 获取带证据的估值研究卡片 | 每周数次 | 研报良莠不齐、无法验证、无跟踪 |
| 独立研究员/工作室 | 批量维护自选池、跟踪估值变化 | 每日 | 手工维护 Excel，口径不一致 |
| 券商/财富机构投顾（后期） | 研究辅助、合规留痕 | 每日 | 结论需可追溯、可审计 |
| 产品运营 | 管理标的池、监控数据质量与跟踪闭环 | 每周 | 数据源漂移、结论过期无人知 |

### 2.4 付费群体与变现路径分析（业界对标）

> 结论先行：**个人订阅（C 端 Freemium）做市场认知与漏斗，券商投顾工作台（B 端）做真收入**；开户导流模式因监管封堵明确不做。

| **对标产品** | **模式** | **定价** | **付费钩子** | **对 Synap Equity 的启示** |
|---|---|---|---|---|
| Simply Wall St（800 万用户） | Freemium 订阅 | Free / Premium $120/年 / Unlimited $240/年 | 报告额度、组合跟踪、提醒、券商同步、导出 | **付费点是"持续跟踪+提醒+组合"，不是一次性报告**；免费层给足价值（5 份报告/月） |

**国内 B 端时机（2026 年窗口）**：

- 2025 年末全行业证券投资顾问 9.60 万人，但投资咨询业务净收入仅占行业营收 1.42%（约 76.94 亿元）——**投顾产能与变现机制严重错配，"合规留痕+投研准备"工具是供给缺口**；

- 监管鼓励人机协同：**AI 承担信息准备，决策与责任在人**——Synap Equity 的研究卡片/证据链正对应"机构统一观点库 + 受控内容生成"的合规要求。

## 3. 产品定位与价值主张

### 3.1 一句话定位

> **Synap Equity：把"估值判断"变成"可复算、可追踪、可验证的研究资产"。**

### 3.2 差异化主张（对"问股+报告"路线的明确否定）

| **主张** | **市场常见做法** | **Synap Equity 做法** |
|---|---|---|
| 估值方式 | 模型生成"目标价" | 确定性引擎输出**合理估值区间**（悲观/基准/乐观三情景） |
| 数字来源 | 模型记忆或编造 | 每个数字带**数据源 + 计算过程链接**，可点开核对 |
| 假设管理 | 隐含、无边界 | **显式假设清单**，改一个假设立即重算并提示影响 |
| 结论生命周期 | 一次性报告 | **研究档案 + 跟踪队列**，到点自动对账实际业绩 |
| 回测纪律 | 事后"解释" | **时点快照**，只用当时可得数据，防未来数据泄漏 |
| 质量评测 | 无 | 有正确答案的评测集：字段提取率、引用正确率、估值误差分布 |

### 3.3 让用户"能挣钱"的价值主张（付费钩子设计）

> 对标 Simply Wall St/Seeking Alpha 的付费结构：**用户为"持续跟踪+提醒+验证"付费，而不是为一次性报告付费**。Synap Equity 的付费钩子按"帮用户拿得住、拿得对、看得清"设计：

| **钩子** | **对用户的价值（能挣钱的机制）** | **付费理由** |
|---|---|---|
| 估值区间 + 当前价格位置 | 避免追高（价格已远高于区间顶部时不追）与杀跌（价格跌入区间底部时有依据地评估） | 免费 |
| **跟踪提醒（价格边界/财报季）** | 到点提醒"该重新评估了"，把"研究"变成持续动作 | **付费（高频使用）** |
| 假设面板（改假设即重算） | 用自己认可的假设检验结论，不被"标准化假设"误导（Simply Wall St 的批评点即此） | **付费（专业用户）** |
| 组合跟踪（估值区间 vs 实际走势） | 长期验证自己的持仓逻辑，形成可复盘的投资纪律 | **付费（高粘性）** |
| 研究档案/胜率记录 | 沉淀"我说过什么、后来对不对"，建立可信任的个人投研资产 | 免费（数据资产在用户侧） |

### 3.4 对 Synap 体系的承接

- **方法论同构**：复用决策图/证据链思想（每个结论附带证据链）、确定性分层、人工复核回流；这些机制与 ClaimSphere 一致，便于团队复用与后续成果回流；
- **技术实现独立**：MVP 阶段 Equity 使用 **Python 技术栈**（FastAPI + pandas + SQLite），估值引擎为**无 LLM 依赖的确定性纯函数模块**；与 ClaimSphere 的 Java 内核不共享运行时，只共享方法论（详见 §6.1）；
- **可选的 Core 承接**：Synap Core 的财报 PDF 解析能力列为 P2 增强，**不作为 MVP 前置依赖**（语料源先用公告原文文本，见 FR-R1）。

### 3.5 技术壁垒：为什么难以复制（诚实版）

> **智识诚实的前提**：纯估值计算（PE/PB/DCF）在业界**没有壁垒**——方法是教科书内容，Simply Wall St 的公平价值算法公开在 GitHub、Seeking Alpha 的 Quant 打分也可复制。Synap Equity 的壁垒不在算法，在**三样需要时间积累的资产**：

| **壁垒层** | **资产** | **为什么难以复制** | **形成时间** |
|---|---|---|---|
| **数据资产（壁垒一）** | ① 历史时点快照库（as-of 数据：财报披露时点可得的真实数据，非"最新值"回溯）；② 黄金标注集（财报-指标映射的人工核对答案）；③ 预测-实际对账误差库（每次研究结论的"考试成绩"） | 竞争者需要同样长时间的采集与标注；**时间差就是壁垒**。快照库尤其稀缺——多数玩家用"当前数据+复权"，而验证需要"当时可得的真实数据" | MVP 启动即积累，1–2 年成形 |
| **信任资产（壁垒二）** | ① 可复算品牌（每个结论可一键复算验证）；② 胜率记录（历史估值判断的方向命中率，对标 Seeking Alpha Quant Ratings 的跑赢记录）；③ 误差透明（不掩盖错误，把误差库做成产品） | 信任只能靠时间与真实记录积累，无法购买或赶工；**它是 C 端付费与 B 端采购的决策依据** | 6 个月起有统计意义，持续复利 |
| **合规流程资产（壁垒三）** | 证据链留痕、内容三态口径（公域认知/私域讲解/账户服务）、私有化部署能力 | 券商投顾合规是强监管场景，"可留痕、可回溯、责任在人"是采购硬门槛；**监管门槛本身就是壁垒**，新进入者需要同样合规周期 | P2 起，随 B 端签约固化 |
| LLM 工程能力（入场券） | 数字注入式生成（LLM 不编数字）、结构化输出、评测体系 | 有工程价值但不是壁垒：模型 API 人人可得，防幻觉是基本盘 | MVP 即具备 |

**双飞轮正循环**：

```plaintext
数据飞轮：时点快照库 → 对账误差库 → 假设校准 → 更准的估值 → 更多用户 → 更多对账数据（自增强）
信任飞轮：可复算 → 胜率记录 → 品牌信任 → B 端采购 → 收入 + 数据反哺 → 更厚的信任（自增强）
```

**对竞争者的意义**：算法可以被抄，但**快照库的历史深度、标注集的规模、误差库的记录长度**在相同时间尺度上无法追赶——这就是"为什么是我们"的回答。

### 3.6 如何帮用户投资挣钱（行为改善机制）

> **合规与智识诚实**：任何工具都不能承诺收益（违规定性即"荐股"）。Synap Equity 帮用户挣钱的机制是**行为改善**——业界研究证明投资者最大的损失来自行为损耗，而非选股能力：

| **业界证据** | **结论** | **Synap Equity 对应机制** |
|---|---|---|
| 投顾行为研究（2026 券商 AI 投顾研究）：持仓不足 3 个月的投资者平均收益率与盈利占比明显低于长期持有者 | **"拿得住、拿得对"比"选得好"更值钱** | 跟踪提醒（价格边界/财报季）把"研究"变成持续动作，避免情绪化卖出/买入 |
| Seeking Alpha Quant Ratings：Strong Buy 组合 2024 年 +37.14% vs 市场 +12.75%（回测口径，仅供参考） | **纪律化低估值策略长期有效**，但反人性、需工具辅助 | 估值区间=纪律锚点：价格高于区间顶部时不追，跌入底部时有依据地评估 |
| 追高杀跌是散户亏损主因（行为金融学共识） | 决策需要"外部锚点"而非情绪 | 当前价 vs 区间位置可视化，每个决策带假设与风险边界 |
| 过度自信与自我归因偏差 | 判断需要"对账验证"来纠偏 | 预测-实际对账 + 胜率记录，让历史判断可复盘、可修正 |

**结论（可对外传达的话术）**：Synap Equity 帮用户**避免明显的亏钱**（追高杀跌、无依据决策、发完即忘），**提升决策效率与纪律**（拿得住、拿得对），并**验证自己的判断**（可复算、可对账）——不承诺收益，承诺"每一步都有依据"。（策略落地的具体规则见 §7.6 模块 S：策略模板库/分档买卖纪律/组合建议/策略回测）

### 3.7 核心卖点（可直接用于市场话术）

| **客群** | **卖点** | **一句话话术** | **对应壁垒/钩子** |
|---|---|---|---|
| C 端 | 敢复算的估值 | "每个结论都能一键复算，假设写在明处" | 信任资产（回应 Simply Wall St 标准化假设批评点） |
| C 端 | 跟踪不缺席 | "价格到边界、财报季到点，系统主动提醒你重新评估" | 跟踪提醒付费钩子（FR-T5） |
| C 端 | 胜率看得见 | "你的判断历史有记录，后来对不对，系统帮你对账" | 对账误差库 + 胜率记录 |
| B 端 | 合规留痕开箱即用 | "每个投顾建议稿带证据链与时间戳，可审计可回溯" | 合规流程资产（监管内容三态/集中决策/全程回溯） |
| B 端 | 投研产能放大器 | "研究卡片替代手工整理，投顾专注判断与客户沟通" | 数据资产（回应投顾 9.6 万人的产能缺口） |
| B 端 | 数据不出机构 | "私有化部署，券商客户数据本地化，品牌化模板" | 合规流程资产（采购硬门槛） |

## 4. 产品范围与约束

### 4.1 MVP 范围（In Scope）

> **垂直切片原则**：MVP 验证的是「单标的闭环能否走通、结论能否可复算可追踪」，不是「覆盖多少标的」。广度功能一律延后。

| **模块** | **MVP 范围** | **延后（P1+）** |
|---|---|---|
| 数据接入 | A 级合规数据源（公开披露/巨潮/交易所，见 FR-D1）+ 10 只种子标的×最近 2 期财报 | 数据商 API、行业分位、历史估值分位 |
| 估值引擎 | **PE/PB 主方法**（确定性计算 + 估值区间）；DCF 为实验性模块（仅手动输入假设时计算，带强警告） | DCF 自动假设、敏感性矩阵 |
| 基本面分析 | 五维体检·简化版（8–10 个核心指标，确定性规则评分） | 五维全量指标、行业对比 |
| 报告生成 | 单模板数字注入式报告 + 引用溯源（语料=公告原文文本 + 结构化数据） | 多模板、RAG 增强、Synap Core PDF 解析 |
| 跟踪验证 | 研究档案（版本链）+ 手动触发的对账跟踪 | 跟踪提醒（价格边界/财报季，C 端付费钩子）、自动跟踪队列、回测自动化 |
| **投资策略（纪律引擎）** | 区间三分档提示（低估/合理/高估）+ 价格位置映射 + 触发提示（MVP 轻量版，见 FR-S2） | 策略模板库（价值/质量成长/红利）、分档买卖纪律、组合建议、策略回测 |
| 前端 | 研究卡片单页 + 自选池 + 反馈入口 | 跟踪看板、多页面 |
| **数据资产（壁垒启动）** | 时点快照库 schema 落地（10 标的×2 期）+ 黄金标注集启动（40 份财报答案）+ 对账误差库首条记录 | 快照自动采集、误差库自动沉淀（见 §3.5 壁垒） |

### 4.2 MVP 明确不做（Out of Scope，且不验证核心价值）

- ❌ 自动交易 / 交易下单
- ❌ 多市场全覆盖（先只做 A 股）
- ❌ 复杂的多 Agent 辩论/研究兵团
- ❌ 实时量化策略平台
- ❌ 面向公众的"荐股/投资建议"输出（合规边界，见 §14）
- ❌ 行业分位/历史分位回测自动化（MVP 后 1–2 周补）
- ❌ 众包社区/UGC（对标 Seeking Alpha 的作者体系不做：内容质量不可控、运营成本高，Synap Equity 走"确定性引擎 + 受控生成"路线）

### 4.3 硬约束

1. **数字纪律**：报告中任何财务/估值数字必须可回溯到数据源与计算过程；LLM 禁止直接产出未经引擎计算的数字。
2. **区间纪律**：所有估值输出为区间 + 情景 + 假设，禁止单一目标价。
3. **时点纪律**：所有计算基于时点快照（as-of），禁止未来数据参与；回测禁用全样本筛选。
4. **跟踪纪律**：已发布结论进入档案，不允许"发完即忘"（MVP 阶段对账可手动触发，到点必须留痕）。
5. **合规纪律**：产品定位为研究辅助工具，输出"研究性内容"，不做投资建议导向的推送（详见 §14 风险）。
6. **数据合规分级**：数据来源按 A/B/C 分级管理（A 级公开披露可直接用，B 级数据商需授权，C 级禁止），详见 FR-D1。

### 4.4 产品载体决策：优先 Web（响应式），MVP 不做小程序

> **结论**：MVP 采用**响应式 Web**（PC + 移动浏览器自适应），**微信小程序列为 P1 条件性选项**。核心判断：Synap Equity 是**重研究工具**（可复算/假设面板/档案/回测/导出），不是轻浏览工具（行情/快讯）；业界对标 Simply Wall St 以纯 Web 验证了研究工具的主载体形态（全球 800 万用户、无 App 优先）。

| **维度** | **Web（响应式）** | **微信小程序** | **结论** |
|---|---|---|---|
| 产品形态匹配 | 复算/假设面板/敏感性/导出等重交互在桌面与移动浏览器均可完成 | 轻浏览友好，重交互受限（表格/图表/导出弱） | Web ✅ |
| B 端路径（收入主线） | 券商投顾工作台私有化部署天然 Web（机构内网/桌面场景） | 无法私有化，机构不使用小程序 | Web ✅ |
| 合规资质 | 自建站内容口径自控，无平台类目限制 | **金融类目需持牌资质**（行情类目审核风险），可能卡 MVP | Web ✅ |
| 开发效率 | 一次开发跨 PC/移动，迭代无审核周期 | 需适配微信框架 + 类目审核排期（金融类更严） | Web ✅ |
| C 端触达 | 微信内 H5 链接可分享、邮件/站内提醒 | 微信生态裂变/订阅消息强 | 小程序（P1 条件） |
| 付费 | Web 聚合支付（微信/支付宝） | 微信支付便捷，但虚拟支付受平台抽成与规则约束 | 平手 |

**小程序上线的触发条件（P1，三条件齐备才立项）**：
1. 类目资质验证通过（或产品定位论证为非行情展示，规避持牌类目）；
2. C 端免费→付费转化率 ≥3% 且移动端访问占比 >50%（证明轻量触达有价值）；
3. 提醒需要微信订阅消息通道（Web 邮件/站内信触达率不足时）。

**配套原则**：Web 端从一开始就做响应式布局（移动浏览器可看卡片/加自选/反馈），保证种子用户在手机上也能完成核心动作，为未来小程序迁移保留最小成本。

**微信生态触达的折中路径（推荐，MVP 即用）**：小程序的真正价值在"触达与提醒"，而非"研究"——而这两点不必依赖小程序即可实现。更优解是用**微信内 H5（复用 Web 代码）承接微信生态**：

| 能力 | 小程序方案 | H5 折中方案（推荐） |
|---|---|---|
| 分享 | 小程序卡片 | 研究卡片 H5 链接（微信内直接打开） |
| 提醒 | 订阅消息（需授权、受限） | 服务号模板消息 / 企业微信消息推送 |
| 支付 | 微信支付（虚拟支付受平台规则约束） | 微信支付 H5 / JSAPI |
| 审核 | **金融类目需持牌，有卡审风险** | 无需类目审核，内容口径自控 |
| 成本 | 需独立开发适配 + 审核排期 | **近乎为零**（响应式 Web 已覆盖） |

→ 结论：**先用 H5 承接微信触达，规避类目审核风险**；只有当 H5 数据验证"微信是主要获客/转化渠道"、且资质到位时，才值得投入原生小程序换取体验增益（流畅度、订阅消息、微信内支付闭环）。

**什么情况下应反转（小程序优先）**——作为决策边界：
1. 产品定位改为"行情快讯 + 社区 + 推送"的**轻场景**（而非深度研究）；
2. 目标用户几乎全为移动端散户，且**不做 B 端私有化**；
3. **已持有证券投资咨询牌照**（类目风险解除）。

三者需同时成立才反转；当前定位下均不成立（重研究工具 / B 端收入主线 / 无持牌），故结论不变。

### 4.5 低门槛体验设计原则（面向普通投资者）

> **核心判断**：目标用户是**非专业投资者**，不是分析师。产品必须"一进来就能看懂、不用填任何东西就能看到结论"。但降门槛**不等于做向导**——不用分步弹窗/引导遮罩（那会打断自主探索），而是用"结论先行 + 白话表达 + 渐进式披露"降低认知负担。

| 原则 | 做法 | 避免 |
|---|---|---|
| **结论先行** | 进入个股页第一屏给一句话结论（便宜/合理/偏贵 + 我们估的区间 + 现价），并随之可见 | 一上来就是 PE Band / 敏感性矩阵等专业图表 |
| **白话优先** | 面向用户的主标签用"便宜 / 合理 / 偏贵"、"最差情况 / 中性判断 / 最好情况" | 主界面堆 PE、PB、分位、WACC 等术语 |
| **术语熔断** | 保留专业术语但提供常驻"看不懂？"浮层白解（估值区间/PE/分位/假设/五维体检） | 术语无解释、用户看到就流失 |
| **渐进式披露** | 高级筛选、DCF、敏感性矩阵折叠或置于"进阶分析"Tab，默认视图不含专业参数 | 默认视图全是专业控件 |
| **零前置** | 默认假设已填好，不改任何参数即可得到完整结论 | 必须先填表单/选参数才能看结果 |
| **不做向导** | 用"大搜索框 + 三个一键入口（便宜的/更稳的/增长快的）"引导 | 分步弹窗、强引导遮罩、进度式流程 |
| **移动优先触控** | 移动端底部导航；按钮触控区 ≥44px；表格横向滚动 | 小按钮、悬浮交互、仅 hover 可用 |
| **友好空状态与容错** | 搜索无结果给推荐词；筛选无结果给"恢复默认"一键；搜索兼容名称/代码/行业 | 空白页或无反馈 |
| **即时反馈** | 滑杆拖动实时重算，结论卡同步更新；操作有 toast 反馈 | 改完参数需要点"提交"才刷新 |
| **合规常驻** | 结论卡下方常驻"这是研究参考，不是买卖建议" | 结论毫无风险提示 |

**落地状态**：以上原则已在《产品DEMO.html》中实现（结论卡、白话档位、术语浮层、进阶 Tab 提示、折叠筛选、移动端底导、友好空状态、实时重算）。凡新增功能均须对照本表验收。

## 6. 核心架构与设计原则

### 6.1 确定性分层架构

```plaintext
┌─────────────────────────────────────────────────────┐
│  跟踪验证层（确定性）                                  │
│  研究档案 · 跟踪队列 · 预期vs实际对账 · 回测评测        │
├─────────────────────────────────────────────────────┤
│  策略纪律层（确定性规则，基于估值输出）                  │
│  策略模板库 · 分档买卖纪律 · 组合建议 · 触发提示         │
│  规则：只输出"规则解释+标的状态匹配度"，不输出交易指令    │
├─────────────────────────────────────────────────────┤
│  分析增强层（LLM，受控）                               │
│  RAG检索(财报/公告/资料) · 报告生成 · 引用溯源          │
│  规则：LLM只读数字、只写文字，禁止生成未经验证的数字      │
├─────────────────────────────────────────────────────┤
│  估值计算层（100%确定性，Python 纯函数模块）            │
│  PE/PB（MVP 主法） · DCF（实验性） · 估值区间 · 敏感性  │
├─────────────────────────────────────────────────────┤
│  数据校验层（确定性）                                  │
│  A/B/C 数据合规分级 · 口径统一 · 质量校验 · 时点快照     │
└─────────────────────────────────────────────────────┘
```

> **技术栈口径（务实调整）**：MVP 采用 **Python（FastAPI + pandas + SQLite）**，估值引擎为无 LLM 依赖的确定性纯函数模块（单元测试可独立验证）；与 ClaimSphere 的 Java 内核**方法论同构、运行时独立**。若后续进入机构场景需统一运行时，再评估估值引擎服务化/Java 化，不在 MVP 范围内。

### 6.2 设计原则

| **原则** | **含义** | **落地机制** |
|---|---|---|
| 数字与文字分离 | 模型不产生任何估值数字 | 报告中数字全部由计算层注入，模型只负责组织语言与引用 |
| 计算与解释分离 | 计算内核可脱离 LLM 独立运行与测试 | 估值引擎为无 LLM 依赖的独立模块 |
| 时点即真相 | 一切计算基于 as-of 快照 | 数据层按报告期/交易日打快照，计算仅消费快照 |
| 假设显式化 | 没有假设就没有估值 | 输出模板强制三情景假设清单，缺项拒绝产出 |
| 结论资产化 | 发布即入库、即跟踪 | 研究档案为主存储，报告只是档案的"视图" |
| 一致性优先 | 方法不随时间漂移 | 同一标的估值方法族登记于档案，变更需显式记录原因 |
| 复杂度驱动 | 不因"AI"过度设计 | MVP 用确定性工作流 + 单模型，确需自主决策再引入多 Agent |
| 垂直切片优先 | 先跑通单标的闭环，再谈广度 | MVP 验收以单标的全流程为准，标的池与功能广度均延后 |

### 6.3 与 ClaimSphere 的技术同构

| **ClaimSphere 组件** | **Synap Equity 对应** |
|---|---|
| 决策图（规则+LLM 收敛） | 估值图（计算引擎 + LLM 解释，数字注入） |
| 证据链（病历/条款引用） | 证据链（财报页/公告/数据源引用） |
| 理算规则引擎 | 估值模型引擎（PE/PB/DCF + 敏感性） |
| 风控时间轴矛盾检测 | 数据口径一致性校验 + 时点泄漏检测 |
| 人工复核回流 | 用户对假设的修正回流 + 对账反馈 |

## 7. 功能需求

> 编号规则：FR-模块-序号。标注 [As-Is]（存量能力，仅适配）与 [Gap]（新增能力，MVP 主战场）。

### 7.1 数据与估值（模块 D，对应 §12.1 第 1–2 周）

#### FR-D1 数据合规分级接入 [Gap] P0

- **用户故事**：作为系统，我需要明确每个数据来源的合规等级，确保 MVP 不被数据授权商务谈判卡死。
- **业务规则**：
  1. **A 级（公开披露，可直接用）**：交易所官网/巨潮资讯披露的财报与公告原文、交易所公开行情（日线收盘价）；授权范围公开明确，MVP 主数据源；
  2. **B 级（数据商授权）**：Wind/聚源/同花顺等 API——需商务谈判，**不作为 MVP 前置依赖**，P1 再引入；
  3. **C 级（禁止）**：爬取商用数据站点（如抓取东财/雪球页面数据）参与计算，仅允许人工摘录并标注来源；
  4. 数据按 `(标的, 报告期/交易日, 数据源, 合规等级)` 唯一标识；种子标的入库前必须人工核对一次（见 FR-Q1 评测集联动）。
- **BDD 验收**：Given 配置某标的；When 入库；Then 生成含合规等级的数据资产记录；若数据源为 C 级爬取则拒绝入库。

#### FR-D2 财务口径统一 [Gap] P0

- **用户故事**：作为研究员，我需要系统统一财务指标、报告期、币种与数据时点，避免跨期不可比。
- **业务规则**：
  1. 统一口径：合并报表为主、母公司报表为辅并显式标注；
  2. 报告期归一化：年报/中报/季报按会计期间对齐，重复覆盖时取最新且标注；
  3. 币种统一为人民币，历史外币科目按当时汇率折算并留痕；
  4. 复权方式显式记录（前复权/后复权/不复权），估值计算默认不复权、分红再投另算。
- **BDD 验收**：Given 某标的存在多口径财务数据；When 进入计算；Then 引擎使用统一口径快照，且口径元数据可查。

#### FR-D3 财务数据质量校验 [Gap] P0

- **用户故事**：作为研究员，我需要系统自动识别异常与缺漏（如毛利率突变、商誉占比过高、非经常性损益扰动），而不是直接拿原始数计算。
- **业务规则**：
  1. 校验项：科目一致性（资产负债表勾稽）、跨期异常波动（阈值告警）、非经常性损益剥离（扣非口径）、数据缺失标注；
  2. 校验结果分三档：通过 / 警告（可计算但需标注）/ 阻断（禁止参与计算）；
  3. 人工修正必须留痕（修正人、理由、时间）。
- **BDD 验收**：Given 一份含异常的财报数据；When 数据入库；Then 输出质量报告（异常项、档位、建议），阻断项不进入估值引擎。

#### FR-D4 基础估值模型（PE/PB 主法 + DCF 实验性） [Gap] P0

- **用户故事**：作为研究员，我需要 PE、PB 两种主方法的确定性计算与估值区间输出；DCF 在无分析师数据源的情况下仅作为实验性模块。
- **业务规则**：
  1. **PE/PB（MVP 主法）**：基于统一口径的 EPS/BVPS（扣非口径优先），输出当前 PE/PB 与合理区间（由行业可比区间 + 自身历史区间共同锚定，MVP 用简单规则：行业中位数 ±30% 与自身 3 年分位区间取交集）；
  2. **DCF（实验性）**：因 MVP 无分析师一致预期数据源，**仅当用户手动输入增长率/WACC/永续增长率时计算**，输出必须带强警告（"假设为手动输入，非市场一致预期"）；三情景（悲观/基准/乐观）默认规则：基准=历史 3 年营收 CAGR，悲观=基准×0.5，乐观=基准×1.3（规则可配，参数显式记录）；
  3. 输出形态：**合理估值区间**（三情景并集），禁止单一目标价；
  4. 敏感性分析（增长率/WACC 矩阵）列为 P1。
- **BDD 验收**：Given 已通过质量校验的标的；When 运行估值引擎；Then 输出估值区间 + 假设清单；PE/PB 路径无需人工输入即可完成，DCF 路径缺手动假设时拒绝计算。

#### FR-D5 行业对比与历史估值分位 [Gap] P1

- **用户故事**：作为研究员，我需要看到标的在行业内的估值位置与自身历史分位。
- **业务规则**：
  1. 行业划分采用申万一级/二级（或所选数据源口径）并记录口径；
  2. 分位计算基于时点快照，剔除缺失期；
  3. 输出当前 PE/PB 分位、行业中位数对比、与历史区间偏离度。
- **BDD 验收**：Given 标的已入池；When 生成研究卡片；Then 卡片含行业对比与历史分位区块，数据来源可溯源。
- **备注**：本需求依赖行业对照样本库，**MVP 延后**（10 只种子标的不足以支撑分位统计），P1 阶段标的池扩至 50+ 后启用。

### 7.2 基本面分析引擎（模块 F，对应 §12.1 第 3 周）

#### FR-F1 财务质量与风险分析（简化版） [Gap] P0

- **用户故事**：作为研究员，我需要系统输出财务质量、盈利能力、成长性、现金流与负债风险的体检结论。
- **业务规则**：
  1. 五维体检·**MVP 简化版**：每维选取 1–2 个核心指标（共 8–10 个：如 ROE、毛利率、营收 CAGR、经营现金流/净利润、资产负债率、商誉/净资产、应收账款/营收、有息负债率），全量指标 P1 扩充；
  2. 每维输出评分（1–5 星）+ 依据指标 + 行业中位数对比（无行业样本时标注"行业对比暂缺"，不阻断）；
  3. 评分由确定性规则产出（阈值表配置化），LLM 只能解释不能改分；
  4. 负值/异常指标（如净利润为负、净资产为负）直接标红并跳过相应评分维度，不硬算。
- **BDD 验收**：Given 标的财报快照；When 运行体检；Then 输出五维评分 + 依据指标，评分可复算；数据缺失时标注不阻断。

- **业务规则**：
  1. 结论模板强制包含：估值区间、假设清单、关键风险、跟踪条件；
  2. 跟踪条件示例：财报季验证点、假设触发点（如实际增速偏离假设 ±20%）、价格进入/离开区间；

- **BDD 验收**：Given 研究卡片生成完成；When 用户点击发布；Then 校验模板要素完整性，缺项则拦截并提示补齐。

### 7.3 LLM 研究报告（模块 R，对应 §12.1 第 3 周）

#### FR-R1 引用溯源（MVP 语料=公告原文文本） [Gap] P0

- **用户故事**：作为研究员，我需要报告引用财报、公告与资料时，每个引用都能点开溯源。
- **业务规则**：
  1. **MVP 语料源**：公告原文文本（巨潮披露的 PDF 转文本/公告正文）+ 入库的结构化财务数据；**不依赖 Synap Core PDF 表格解析**（其为 P2 增强，未成型前不阻塞 MVP）；
  2. 引用必须携带来源定位（文档名、段落/页码）；
  3. 引用正确性纳入评测（见 FR-Q1），错误引用计入缺陷。
- **BDD 验收**：Given 一份生成报告；When 点击任一引用；Then 打开来源原文定位，且引用定位命中率纳入评测指标。

#### FR-R2 报告生成（数字注入式，MVP 单模板） [Gap] P0

- **用户故事**：作为研究员，我需要系统生成可读的研究报告，且其中所有数字来自引擎计算结果，不允许模型编造。
- **业务规则**：
  1. **MVP 报告模板（单模板）**：业务概览 → 财务体检 → 估值区间与假设 → 风险因素 → 跟踪建议；多模板 P1；
  2. 数字注入机制：报告中所有财务/估值数字由计算层以结构化数据注入（引擎输出 → 模板槽位），模型仅组织文字；
  3. 检测规则：报告发布前做数字一致性校验（文中数字 vs 引擎输出），不一致拒绝发布；

- **BDD 验收**：Given 引擎输出 + 语料；When 生成报告；Then 校验全部数字来自注入清单，含模型自造数字时拦截。

#### FR-R3 假设解释与边界提示 [Gap] P1

- **用户故事**：作为研究员，我需要报告明确写出关键假设及其影响边界（乐观/悲观情形），避免把区间当预测。
- **业务规则**：
  1. 每个假设标注：来源依据（历史均值/管理层指引/研究员输入）与影响幅度；

- **BDD 验收**：Given 研究报告生成；When 查看假设章节；Then 每项假设含依据、影响幅度与失效信号。

### 7.4 决策跟踪与质量验证（模块 T，对应 §12.1 第 4–5 周）

#### FR-T1 研究档案与估值变化跟踪 [Gap] P0

- **用户故事**：作为研究员，我需要系统以档案形式沉淀每次研究结论，并跟踪估值随时间的演变。
- **业务规则**：
  1. 档案为不可变快照 + 变更链：每次估值发布生成版本，后续修正追加版本并记录原因；
  2. 展示估值区间随时间的变化曲线（预期区间 vs 后续实际）；
  3. 估值方法变更（如从 PE 主法切换 DCF）必须显式记录，保证方法一致性可审计。
- **BDD 验收**：Given 标的已发布多期结论；When 查看档案；Then 展示版本链、区间演变曲线与方法变更记录。

#### FR-T2 跟踪与预期-实际对账（MVP 手动触发） [Gap] P0

- **用户故事**：作为研究员，我需要到点核对"当时估值假设 vs 实际业绩"，形成长期验证证据。
- **业务规则**：
  1. **MVP 触发方式**：对账任务由研究员手动触发（财报披露后 1 周内），自动提醒（日历提示）P1；触发后生成对账任务，未完成时档案标记"待对账"；
  2. 对账内容：实际营收/净利 vs 当时假设、实际股价区间 vs 估值区间；
  3. 对账结果归档进档案，形成"预测-实际"误差库；
  4. 长期沉淀：误差库用于评测估值体系的系统性偏差（乐观/悲观倾向）。
- **BDD 验收**：Given 已发布结论到跟踪时点；When 执行对账；Then 生成对账记录并归档，误差数据进入评测库。

#### FR-T3 无泄漏数据架构与评测（MVP 简化回测） [Gap] P1

- **用户故事**：作为产品运营，我需要确保系统只用"当时可得数据"，并对历史结论做前瞻性验证。
- **业务规则**：
  1. **数据架构（MVP 必做）**：一切计算基于时点快照（as-of），快照含数据披露时间戳；禁止使用披露时间晚于计算时点的数据；
  2. **回测（MVP 简化版）**：先做"事后回放"——对已入库标的按历史快照重跑估值，人工核验无泄漏（抽查披露时间戳）；自动化回测与含退市标的池 P1；
  3. 评测指标：字段提取准确率、引用正确率、估值方向准确率、区间命中率（区间命中率需样本≥20 期×3 个月才统计，见 §13）；
  4. 评测集有"正确答案"（后续实际数据），每季度滚动更新。
- **BDD 验收**：Given 评测集与快照数据；When 运行评测；Then 输出指标，且快照时间戳审计证明无未来数据参与。

#### FR-T4 研究卡片与用户反馈（Web 端） [Gap] P1

- **用户故事**：作为个人投资者，我需要简单易用的 Web 页面查看研究卡片、管理自选池并反馈意见。
- **业务规则**：
  1. 页面：研究卡片（六要素）、自选池、跟踪看板、反馈入口；
  2. **响应式布局（MVP 必做）**：PC 与移动浏览器均可完成核心动作（看卡片/加自选/反馈）；移动端优先保证这三个动作，重交互（假设面板/导出）桌面端完整；
  3. 反馈（"数据不对""假设不合理"等）进入质量工单，回流数据/假设修正。
- **BDD 验收**：Given 登录 Web 端（PC 或移动浏览器）；When 输入股票；Then 展示研究卡片并支持加入自选池、提交反馈；移动端布局无横向滚动（核心三动作可完成）。

#### FR-T5 跟踪提醒（价格边界/财报季） [Gap] P1（C 端付费钩子）

- **用户故事**：作为付费订阅者，我需要系统在"价格进入/离开估值区间"或"财报季对账时点"主动提醒我，把研究变成持续动作。
- **业务规则**：
  1. 提醒类型：价格进入估值区间上/下边界、价格偏离区间 ±20%、财报季对账提醒、假设触发点；
  2. 提醒通道：邮件 + Web 站内通知（P1 移动端推送）；
  3. **免费层策略**：免费用户可预览"提醒样例"（历史触发实例），创建提醒为付费能力；
  4. 提醒可静默/可配置频次，避免噪音；提醒触达链路纳入评测（漏报率 ≤5%）。
- **BDD 验收**：Given 已发布档案的自选标的；When 价格触及区间边界；Then 生成提醒（含当前价、区间、偏离度），免费用户仅见样例。

#### FR-B1 投顾工作台（B 端，合规留痕） [Gap] P2（真收入）

- **用户故事**：作为券商投顾，我需要把研究卡片一键生成为带证据链的投顾服务素材，全程留痕可审计。
- **业务规则**：
  1. 能力：研究卡片 → 投顾建议稿（含证据链引用）→ 合规留痕导出（时间戳、假设、数据源）；
  2. 机构模式：私有化部署、品牌化模板（券商 logo）、观点库受控（机构统一观点，投顾不自行生成建议）；
  3. 留痕要求：建议稿每个结论可回溯至研究卡片与原始数据，满足"内部集中统一决策 + 全程可回溯"监管导向；
  4. 该模块为 B 端商务 POC 后的增量开发，不进入 C 端 MVP 范围。
- **BDD 验收**：Given 机构模式启用；When 生成投顾建议稿；Then 导出含证据链+时间戳+假设清单的留痕档案，无来源结论被拒绝导出。

### 7.5 质量评测（模块 Q）

#### FR-Q1 评测体系（落地口径：样本量 + 标注分工） [Gap] P1

- **用户故事**：作为团队，我需要有正确答案的评测集持续度量系统质量，而不是"感觉变好了"。
- **业务规则**：
  1. **评测集规模（MVP）**：
     - 字段提取：10 只种子标的 × 最近 4 期财报（40 份），**答案由人工从巨潮原始 PDF 核对**（一次性建集，约 2–3 人天）；
     - 估值计算：引擎单元测试（数学正确性验证，无需人工标注）；
     - 引用正确率：每期抽样 20 条引用人工核验；
  2. 指标：字段提取准确率（≥95%）、引用正确率（≥98%）、异常处理通过率；估值方向/区间命中率按 §13 时间窗统计；
  3. 每次发布前运行评测门禁，低于阈值的版本禁止发布；
  4. 标注变更留痕（标注人、时间、修订理由）；
  5. **商业功能评测（P1 起随付费功能启用）**：提醒准确性（漏报率 ≤5%、误报率 ≤10%，人工抽检触发实例）、建议稿留痕完整性（B 端 POC 时抽检导出档案，无来源结论计数为 0）。
- **BDD 验收**：Given 评测集；When 运行评测；Then 输出各项指标与达标状态，门禁结果入发布流水线。

### 7.6 投资策略与纪律引擎（模块 S，对应 §12.1 第 2 周起）

> **定位**：把 §3.6 的"行为改善"落到可执行的策略规则。**合规边界（硬约束）**：策略引擎只输出"规则解释 + 标的状态匹配度"（如"当前价格处于低估档 1，按模板 A 的规则提示"），**不输出"买入/卖出"交易指令**；页面常驻"研究性内容，非投资建议"声明（见 §14）。

#### FR-S1 策略模板库（内置三模板，规则可配置） [Gap] P1

- **用户故事**：作为投资者，我需要选择适合自己的策略模板（价值型/质量成长型/红利型），系统按模板规则评估标的状态。
- **业务规则**（业界经典策略产品化，参数显式记录、可配置）：

| **模板** | **筛选条件（确定性规则）** | **估值锚点** | **买卖纪律** | **跟踪规则** |
|---|---|---|---|---|
| 价值型（格雷厄姆-巴菲特式） | PE 行业分位 <40%、PB <1.5 或分位 <50%、ROE ≥10%、负债率 <60%、经营现金流为正 | PE/PB 区间（主法） | 低估档 1 分档买入；高估档提示不追 | 财报季对账 + 假设失效复核 |
| 质量成长型（PEG 式） | 营收 CAGR ≥10%、净利 CAGR ≥10%、PEG <1、ROE ≥15% | PE 区间 + 成长假设（DCF 实验性） | 区间中下部加仓；成长假设被证伪即退出提示 | 每季验证成长假设 |
| 红利型（防守） | 股息率 ≥3%、连续分红 ≥3 年、低波动（β<0.9） | 股息率阈值 + 区间 | 股息率跌破阈值提示；估值非主约束 | 分红/股息率变动跟踪 |

  1. 模板参数全部配置化，改参数即重算匹配度（与估值重算联动）；
  2. 模板仅作研究辅助，不做自动交易（Out of Scope）。
- **BDD 验收**：Given 标的已入池且模板已配置；When 运行策略引擎；Then 输出标的状态匹配度与对应规则解释，参数可溯源。

#### FR-S2 分档买入与退出纪律提示（MVP 轻量版：区间三分档） [Gap] P0（MVP 只做三分档）

- **用户故事**：作为投资者，我需要知道"当前价格在估值区间的哪个档位、规则上该怎么做"，避免情绪化追高杀跌。
- **业务规则**：
  1. **MVP 轻量版（必做）**：将估值区间划分为**低估档（区间底部以下）/ 合理档（区间内）/ 高估档（区间顶部以上）**三档，研究卡片展示"当前价位置 + 档位 + 偏离度"（已有 FR-F3 卡片布局中"当前价位置"即此能力）；触发提示：价格进入低估档（免费层见样例）或离开高估档时提醒（复用 FR-T5 提醒链路）；
  2. **分档买入纪律（P1 完整版）**：低估档内再分 3 档（区间底部 → 档 1 试探仓 1/3 目标仓位；再跌 15–20% → 档 2 加至 2/3；再跌 30% 且基本面未恶化 → 档 3 达目标仓位）；
  3. **退出纪律（P1 完整版）**：① 价格 ≥ 乐观情景上沿 → 提示"进入高估区，可考虑减持"；② 对账偏差 >20% 且质量评分下降 → 触发"重新评估，必要时退出"；③ 假设失效信号（增长假设被证伪/护城河事件，见 FR-R3）→ 退出提示；
  4. 输出均为"规则提示 + 依据"，不构成交易指令（合规边界）。
- **BDD 验收（MVP）**：Given 标的估值区间；When 卡片生成；Then 展示三档位置与偏离度；价格穿越档位边界时触发提醒（复用 FR-T5）。

#### FR-S3 组合构建建议（仓位与分散，研究辅助） [Gap] P2

- **用户故事**：作为进阶投资者，我需要组合层面的纪律建议（单标的仓位、行业分散），而不是单票看估值。
- **业务规则**：
  1. 单标的仓位上限建议：高确定性标的 ≤10%、一般标的 ≤5%（确定性=质量评分×估值置信度，规则可配）；
  2. 行业分散建议：单一行业合计 ≤30%；
  3. 输出"组合健康度"（集中度/相关性提示），仅建议不强制，不替代投资者判断。
- **BDD 验收**：Given 用户自选池；When 组合分析；Then 输出仓位上限/行业分布/集中度提示。

#### FR-S4 策略回测（快照库驱动，防幸存者偏差） [Gap] P1

- **用户故事**：作为产品运营，我需要验证"内置策略过去执行会怎样"，用真实记录而不是事后解释。
- **业务规则**：
  1. 用时点快照库回放策略规则（模板 A/B/C），统计方向命中率、区间命中率、最大回撤；
  2. 标的池含退市标的（防幸存者偏差）；仅用当时可得数据（防未来函数，FR-T3 架构保障）；
  3. 启动条件：快照库覆盖 ≥50 标的×≥2 年（MVP 仅 10 标的×2 期，**P1 启动**）；
  4. 回测结果展示带"历史回测不代表未来收益"声明。
- **BDD 验收**：Given 快照库达到启动条件；When 运行策略回测；Then 输出策略统计与回撤曲线，快照时间戳审计证明无泄漏。

## 8. 业务流程

### 8.1 核心流程：从输入到跟踪闭环

```plaintext
输入股票代码
   ↓
[数据校验层] 拉取行情/财报/公司信息 → 口径统一 → 质量校验
   ↓ 阻断项拦截，警告项标注
[估值计算层] 财务体检(5维) → PE/PB（主法）/DCF（实验性）→ 估值区间
   ↓ 输出：假设清单 + 估值区间（结构化）
[分析增强层] 检索语料(公告原文/结构化数据) → 数字注入 → 报告生成 → 数字一致性校验
   ↓ 引用溯源全部就绪
[跟踪验证层] 生成研究档案(版本v1) → 发布 → 进入跟踪队列
   ↓ 财报季 / 假设触发 / 价格边界（手动对账 MVP / 自动提醒 P1）
对账：预期假设 vs 实际业绩 → 归档 → 误差入评测库
```

### 8.2 支线 A：跟踪提醒（C 端付费钩子，P1）

```plaintext
用户订阅标的（Pro 用户可创建提醒）
   ↓
[规则引擎] 检查价格 vs 估值区间边界 / 财报季临近 / 假设触发点
   ↓ 触发条件满足
生成提醒（当前价、区间、偏离度、数据源）→ 邮件/站内信送达
   ↓
用户回访研究卡片 → 更新假设或确认对账 → 进入档案版本链
```

### 8.3 支线 B：投顾建议稿（B 端工作台，P2）

```plaintext
机构模式下的投顾选择标的
   ↓
[研究卡片] 估值区间 + 证据链 + 假设清单（机构统一观点库）
   ↓ 一键生成
投顾建议稿（含证据链引用、时间戳、合规声明）
   ↓ 留痕校验：每个结论可回溯至研究卡片与原始数据
导出留痕档案（供内部审核备案 / 客户沟通）
```

### 8.4 关键决策点

| **决策点** | **判断依据** | **处置** |
|---|---|---|
| 数据质量阻断 | 校验结果=阻断 | 拒绝进入估值引擎，输出原因 |
| 报告数字不一致 | 文中数字 ≠ 引擎输出 | 拦截发布，回到报告生成 |
| 假设缺失 | 模板要素不全 | 拒绝发布结论 |
| 对账偏差超阈值 | 实际 vs 预期偏离 > 20% | 提示研究员复核，触发档案修订版本 |
| 提醒漏报 | 触发条件满足但未送达 | 计入评测缺陷（漏报率 ≤5%），回查规则与通道 |
| 建议稿无来源结论 | 结论无法回溯至卡片/数据 | 拒绝导出（合规留痕硬约束） |

## 9. 领域模型

```plaintext
Stock（股票标的）
 ├── SecurityProfile（公司基本信息：行业、股本、流通股）
 ├── FinancialReport（财报：报告期、口径、币种、快照时点）
 │     ├── BalanceSheet / IncomeStatement / CashFlow
 │     └── QualityCheck（质量校验结果：通过/警告/阻断）
 ├── PriceSeries（行情：复权方式、交易日快照）
 ├── ValuationModel（估值模型：PE/PB/DCF 参数与情景）
 │     ├── Scenario（悲观/基准/乐观：假设集合）
 │     └── SensitivityMatrix（敏感性分析结果）
 ├── ValuationOutput（估值输出：区间、假设清单、触发条件）
 ├── ResearchReport（研究报告：正文 + 数字注入清单 + 引用集合）
 ├── ResearchArchive（研究档案：不可变版本链 + 方法变更记录）
 ├── TrackingTask（跟踪任务：触发时点、对账结果）
 ├── TrackingAlert（跟踪提醒：规则、触发、送达、确认）
 ├── AdviceDraft（投顾建议稿：证据链、留痕、导出，B 端）
 ├── Subscription（订阅：层级、额度、用量、续费状态）
 └── EvaluationRecord（评测记录：误差、命中率、引用正确率）
```

### 9.1 聚合边界说明

- `ResearchArchive` 为聚合根：研究卡片、报告、跟踪任务、提醒、建议稿均为档案的视图/衍生，保证"结论资产化"；
- `ValuationOutput` 不可变：重算生成新版本，不覆盖旧结论（可复算、可审计）；
- `FinancialReport` 以快照形态消费：计算只读当时快照，禁止动态取"最新值"参与历史计算；
- `Subscription` 独立于研究域：额度（免费/Pro）只约束功能边界（提醒数量、报告额度），不参与估值计算，避免订阅逻辑污染确定性内核。

## 12. 产品路线图

### 12.1 MVP（6 周，1 人主导 + 按需支援）

> **原则**：每周围绕「单标的垂直闭环」推进，先保证 1 只标的全流程跑通，再横向复制到 10 只。

| **周** | **里程碑** | **产出物** | **验收标准** |
|---|---|---|---|
| 第 1 周 | 数据底座（先做数据和估值，不先做 Agent） | 数据模型 + A 级数据源接入（巨潮/交易所）+ 口径统一 + 质量校验（三档）+ 种子标的清单（10 只，覆盖 2–3 个行业）+ **时点快照库 schema 落地（数据资产启动，见 §3.5）** | 2 只标的×最近 2 期财报入库并通过人工核对；估值引擎框架就绪；快照库首条记录写入 |
| 第 2 周 | 估值引擎 | **PE/PB 确定性计算**（区间输出 + 假设清单）+ 引擎幂等测试 + **价格-区间三分档映射（策略 MVP 版，FR-S2）** | 1 只标的全流程估值跑通；同输入重跑逐位一致；DCF 实验模块（手动假设）可用；三分档与档位展示正确 |
| 第 3 周 | 基本面分析 + 报告生成 | 五维体检简化版（8–10 指标）+ 数字注入式报告（单模板）+ 引用溯源 | 报告数字 100% 来自引擎注入；自造数字被拦截；引用可点开溯源 |
| 第 4 周 | 研究档案 + 跟踪 | 研究档案（版本链）+ 手动对账流程 + 档案视图 | 发布结论即入档；对账触发后留痕；误差进入评测库 |
| 第 5 周 | Web 与种子验证 | 研究卡片单页 + 自选池 + 反馈入口（**响应式，移动浏览器可用**）；10–20 位种子用户内测 | 种子用户可自服务生成研究卡片并提交反馈（PC/手机均可完成核心动作） |
| 第 6 周 | 评测与打磨 | 评测集（40 份财报答案）+ 评测门禁 + 缺陷修复 | 字段提取 ≥95%、引用正确率 ≥98%；可复算/可追溯审计通过 |

### 12.2 MVP 之后（规划，非承诺）

- **P1（+2–4 周）**：① C 端 Freemium 上线（免费层 + Pro 订阅，付费钩子=跟踪提醒 FR-T5/假设面板/组合跟踪）；② 标的池扩至 50+（行业分位/历史分位启用）；③ DCF 自动假设（引入数据商后）、敏感性矩阵；④ 对账提醒自动化；
- **P2（+1–2 月）**：① **B 端投顾工作台 POC（FR-B1）**——接触 1–2 家券商投顾/财富机构，私有化或订阅试点；② 港股/美股扩展（多市场）、估值方法扩展（EV/EBITDA、股息折现）；③ Synap Core PDF 表格解析接入；
- **P3（视数据而定）**：财务预测模型（基于历史与指引的预测报表）、宏观/行业因子视角、数据/API 输出（估值引擎 + 档案能力封装）。

### 12.3 明确不纳入近期路线

自动交易、多 Agent 辩论、实时量化平台、面向公众的荐股服务。

| **LLM 幻觉污染报告**（模型编数字/错误引用） | 中 | 违反核心承诺 | 数字注入机制 + 发布前一致性校验 + 引用溯源评测 |
| **Synap Core 未成型阻塞报告** | 中 | 报告质量受限 | MVP 语料源不依赖 Core（公告原文文本 + 结构化数据），Core 解析列为 P2 增强 |
| **幸存者偏差/数据泄漏**（回测虚高） | 中 | 长期研究价值归零 | 时点快照 + 快照时间戳审计；含退市标的池列为 P1 |

| **团队能力缺口**（财务会计/估值方法不熟） | 中 | 质量不达标 | 按 §16 学习路径投入 2–3 周建立基础，边开发边深化；种子标的财务答案由懂财报的成员核对 |
| **B 端商务周期长**（券商采购流程慢，POC→签约 3–6 个月） | 高 | 收入延迟、资源耗散 | 先用低门槛"总部订阅/按席年费"切入试点，降低决策层级；B 端触点多线并行（2–3 家）而非单点押注 |
| **免费层成本侵蚀**（用户增长 → LLM token 成本线性放大） | 中 | 毛利率下降 | 免费层硬限额（5 份报告/月）；低成本模型分层（免费层用小模型、付费层用强模型）；监控单用户边际成本 |
| **监管细则变化**（证券基金投资咨询办法征求意见稿、AI 内容标识办法） | 中 | 合规口径漂移 | 合规顾问常驻；按"内容三态"（公域认知/私域讲解/账户服务）口径设计产品边界；AI 生成内容显式+隐式标识从 MVP 就内置 |
| **竞品跟进**（券商自研 AI 投研工具、大厂估值产品） | 中 | 同质化竞争 | 不打参数规模，打"可复算 + 显式假设 + 留痕档案"的确定性差异；B 端以私有化和合规留痕锁定 |
| **壁垒被复制**（竞品跟进时点快照/对账体系） | 中-高 | 差异化窗口缩小 | 数据资产时间差（快照库/标注集/误差库需 1–2 年积累，无法追赶）；B 端先发锁定（签约绑定 + 私有化粘性）；合规流程门槛 |

### 14.2 关键依赖

- **A 级数据源可用性**：巨潮/交易所披露接口或人工下载渠道可用（公开、免费）；
- **公告原文文本**：财报/公告 PDF 可转换为文本（MVP 用公开转换工具，不依赖 Synap Core）；
- **LLM 供应商**：结构化输出与工具调用能力（报告生成单模板）。

### 14.3 关键假设

- A 级公开披露数据（巨潮/交易所）足以支撑 MVP 的 10 只种子标的估值计算；
- MVP 阶段验证的是"研究价值与留存"，付费转化留到 MVP 之后（不假设 MVP 期内有收入）；
- 财务数据以公开披露为准，不依赖内幕/付费预测数据。

## 15. 商业模式

### 15.1 变现路径总览

> **双路径模型**：C 端 Freemium 做市场认知与漏斗（个人投资者），B 端券商投顾工作台做真收入（机构预算）；**开户导流模式不做**（金融产品网络营销新规封堵第三方变相营销，见 §2.4）。

| **路径** | **客户** | **模式** | **收入角色** | **启动阶段** |
|---|---|---|---|---|
| C 端 Freemium | 个人投资者/独立研究员 | 免费研究卡片 + 付费跟踪提醒/假设面板/组合跟踪 | 市场认知 + 早期收入 | MVP 后 1–2 月 |
| B 端投顾工作台 | 券商投顾/财富机构 | 私有化部署或订阅年费（工具输出给持牌机构） | **真收入** | MVP 后 2–3 月 POC |

### 15.2 C 端 Freemium（对标 Simply Wall St $120/年）

| **层级** | **功能边界** | **参考定价** | **转化设计** |

### 15.3 B 端券商投顾工作台（真收入）

**核心场景**：券商投顾的"投研准备 + 合规留痕"工作台——AI 承担信息准备（研究卡片、证据链、估值档案），投顾负责判断与客户沟通，全程留痕可审计。

| **能力** | **对应券商痛点（业界现状）** | **Synap Equity 能力** |

|---|---|---|

### 15.4 商业验证节奏（分阶段，保持务实）

| **阶段** | **动作** | **验证口径（达标才进入下一阶段）** |
|---|---|---|
| MVP 内（第 5–6 周） | 种子用户共创（10–20 位），不收费 | 周留存 ≥40%；≥30% 种子用户表示愿付费（≥50 元/月） |

### 15.7 单位经济学（CAC / LTV / LTV:CAC）

> **口径说明（修正版）**：SaaS 健康基准为月流失率 <5–10%（对应年留存 54–87%）；此前"月续费率 60%"等价于月流失 40%（年留存仅 2%）——不可持续，已修正。

**C 端（Pro ¥69/月 或 ¥499/年，取年付为主）**：

| **参数** | **取值** | **依据** |
|---|---|---|
| ARPU（月） | ¥69（月付）/ ¥41.6（年付折算） | 定价见 §15.2 |
| 月流失率（目标） | ≤10% | SaaS 健康基准；跟踪提醒高频使用支撑留存 |
| 平均生命周期 | 1/流失率 ≈ 10 个月（年付用户因预付锁定更长，取 12 个月） | 流失率倒数 |
| **LTV（毛利）** | 年付口径 ≈ ¥500（¥41.6×12）；月付口径 ≈ ¥690 | — |
| **CAC（目标）** | ≤¥166–230（LTV:CAC ≥ 3） | 内容营销可实现 ¥0–150 |
| **LTV:CAC** | 内容获客 3–5（健康）；付费投放 2–3（边界） | ≥3 为 SaaS 健康基准 |

**B 端（私有化/按席订阅）**：

| **参数** | **取值** | **依据** |
|---|---|---|
| 客单价（年） | 20–50 万（私有化）/ 500–2000 元/席（订阅） | 定价见 §15.3 |
| 销售周期 | 3–6 个月（POC→签约） | 券商采购现实 |
| CAC（含销售人力） | 5–10 万/单 | 直客销售 + 商务投入 |
| LTV（按 2–3 年续费） | 40–150 万 | 私有化粘性 + 实施服务追加 |
| **LTV:CAC** | 4–15（健康） | 显著优于 C 端，印证"B 端为真收入" |

**结论**：C 端依赖低 CAC 内容获客（LTV:CAC ≥3 才成立，付费投放仅作边界补充）；B 端单位经济学天然健康（LTV:CAC 4–15），**但销售周期长**——两者组合构成"C 端漏斗 + B 端变现"的稳健结构。

### 15.8 定价包装与梯子设计（业界最佳实践）

> 定价遵循"梯子"逻辑：免费层获客 → 主力档承接 → 专业档收割长尾；年付锚定引导现金流与留存。

| **层级** | **定价** | **锚定/促销设计** | **目的** |
|---|---|---|---|
| 免费层 | ¥0 | 研究卡片 5 份/月，提醒仅样例 | 获客 + 展示"敢复算" |
| Pro | ¥69/月 或 **¥499/年**（≈7.2 折） | 月付/年付并列展示，默认高亮年付；首年促销 ¥399（限种子用户） | **主力收入**，年付锁留存与现金流 |
| Pro+ | ¥199/月 | 无限报告 + API 访问 | 长尾专业用户，拉高 ARPU |
| B 端 | 按席 ¥500–2000/席/年 → 私有化 20–50 万/年 | 先按席试点再升私有化；实施服务单独计价（2–5 万/次） | 低门槛切入，高价值锁定 |

**定价心理学要点**：① 年付锚定（¥499 vs ¥828 月付合计）引导年付；② 免费层额度用尽（5 份/月）制造"用完感"促转化；③ B 端"按席→私有化"升级路径，避免一上来谈大额商务吓退中小券商。

## 16. 附录：领域知识与技术学习路径

### 16.1 共同技术基础（两个项目通用，优先级高）

1. **LLM 应用工程**：模型 API、结构化输出、工具调用、上下文管理、异常重试、成本控制；

4. **评测体系**：有正确答案的测试集，评估事实准确性、字段提取率、引用正确性、异常处理与业务效果；
5. **安全与合规**：数据授权、最小权限、敏感数据保护、日志审计、模型供应商数据处理约定。

## 17. 成本测算（MVP 6 周）

> 口径：1 人主导（50%–100% 投入）+ 按需支援；以免费/低成本 A 级数据源为前提。

| **成本项** | **估算** | **说明** |
|---|---|---|
| 人力 | 6 周 × 1 人全职等价 ≈ 30 人天（按团队机会成本计，机会成本由三条探索线优先级承担） | 如 Claim 商务突破需回填，按 §1.5 暂停条件处理 |
| 数据源 | ≈0 元（MVP） | A 级公开披露免费；数据商授权（B 级）费用留到 P1 预算，届时再评估 |
| LLM API | 单份报告约 5–15 万 token（含检索上下文），按 0.5–2 元/份估算；10 标的×每季 1 次 ≈ 20–80 元/季 | 结构化输出 + 单模板控制上下文长度；成本不作为 MVP 瓶颈 |

| **MVP 总现金支出** | **≈ 600–1800 元**（基础设施 + LLM 试算，不含人力机会成本） | 数据资产与代码均为内部投入 |

### 17.1 收入模型与盈亏平衡（三档情景）

> 口径：年度运营成本 ≈ 基础设施（100–300 元/月）+ LLM API（种子规模下 200–800 元/月）+ 人工（1 人 30% 投入，机会成本另计）≈ **3–5 万元/年现金**；人力机会成本单列。

| **情景** | **假设** | **年度收入估算** | **结论** |
|---|---|---|---|
| 悲观 | C 端 100 付费用户（¥499/年）+ B 端 0 | ≈5 万元/年 | 覆盖现金成本，人力机会成本不cover |
| 中性 | C 端 300 用户（¥499/年）+ B 端 1 家（20 万/年） | ≈35 万元/年 | 覆盖现金+部分人力，验证模型成立 |
| 乐观 | C 端 1000 用户 + B 端 3 家（20–50 万/年） | ≈100–200 万元/年 | 可作为独立业务线投入 |

**关键结论**：
1. **B 端 1 单 ≈ C 端 400 个年费用户**——B 端是盈亏平衡的决定变量，C 端是品牌与漏斗；
2. 中性情景（C 端 300 + B 端 1）即达"可继续投入"线，验证门槛不高；
3. 若 MVP 后 3 个月 C 端转化率 <3% 且 B 端无 POC 意向，按 §1.5 暂停条件处置。

**三个最急的缺口（为什么）**：
1. **数据源验证**——时间最急：第 1 周就要"2 只标的入库"，但 A 级数据源具体路径未验证，这是唯一可能阻塞第 1 周周产出的缺口；
