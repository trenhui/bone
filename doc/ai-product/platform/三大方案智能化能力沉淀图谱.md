## 1. 结论（TL;DR）

三套方案（采购审查 / 智能理赔 / 智能估值）领域完全不同，但 **10 项底层智能能力中 8 项在三方案独立同构设计、2 项在两方案同构**——包括具体选型都高度重复（pgvector 混合检索、QLExpress 规则热更、快照+引擎版本三元组、HITL 三态、评测集+Kappa、适配器模板）。这些是**可沉淀项**；领域知识（规则库/医学图谱/估值引擎/快照库）是**不可沉淀项**——它们是壁垒，不是基础设施。

| 优先级 | 能力 | 同构度 | 一句话理由 |
|---|---|---|---|
| **P0** | C1 文档解析与 IR 服务 | 3/3 | 条款级引用/证据链/锚点高亮的公共地基，三处各建一套 L1 |
| **P0** | C2 双引擎与流程编排 | 3/3 | 规则确定性兜底 + LLM 开放推理 + 状态机 + fallback，三方案共同的核心架构决策 |
| **P0** | C3 HITL 确认与反馈回流 | 3/3 | "AI 提议、人审批"是政企/金融合规硬门槛，交互模式完全同构 |
| **P0** | C4 结论快照与审计追溯 | 3/3 | 可复现/可回放是采购准入资格，三处独立设计同一机制 |
| **P1** | C5 LLM 网关（路由/配额/审计） | 3/3 | 多产品多模型治理标配，直连 vLLM/API 必然成本与灰度失控 |
| **P1** | C6 受控 RAG（引用强制） | 3/3 | 检索栈同构（混合检索+rerank+出处），差异只在语料 |
| **P1** | C7 评测体系与质量门禁 | 3/3 | "你怎么证明它准"是必答题；评测汇聚才能形成数据飞轮 |
| **P1** | C8 LLM 安全基线 | 3/3 | 提示注入/数据分级是私有化准入前置，防御模式跨方案同构 |
| **P1** | C9 提醒与预警引擎 | 2/3 | 规则触发 + 多级触达 + 消警闭环，procuraAI 与 Equity 同构 |
| **P2** | C10 集成适配与三态灰度交付（FDE） | 2/3 | 两套 FDE 方案写出几乎相同的集成原则，平台化避免第二套 |

## 3. 可沉淀能力详表

### P0 —— 产品地基 + 合规准入硬门槛（每个产品都要，且 Bone 可直接承接）

| 能力 | 沉淀内容 | 为什么可沉淀（同构证据） | 为什么值得沉淀（平台价值） |
|---|---|---|---|
| **C1 文档解析与 IR** | 统一 IR schema（章节树/段落/表格/条款引用索引/span 定位）；OCR/表格抽取管线；语义切片；**脱敏 + 受控回填** | 三方案各自实现 L1：同样的解析栈选型、同样的"引用必须定位到原文"设计、同样的脱敏后进 LLM | 条款级引用率 100%、证据链、前端锚点高亮全部依赖 IR；平台一份实现，三个产品自动获得；解析质量（表格抽取/切片召回）有统一评测基线 |
| **C2 双引擎与编排** | 规则 DSL（JSON+表达式+沙箱热更）；规则版本化/灰度/shadow；显式状态机（排队→解析→规则→LLM→确认→归档）；AI 节点 fallback 与降级矩阵 | procuraAI ADR-01、ClaimSphere 决策图、Equity 数字注入是同一架构决策的三种表述；均验证"纯 LLM 漏检 12.7% vs 混合 0.3%" | 这是三方案共同的**核心架构决策与主要壁垒**（B1）；平台化后新智能体直接继承"确定性兜底"，不必从零论证评审 |
| **C3 HITL 与反馈回流** | 条目化建议（原文引用+依据+建议）；置信度分级（≥0.85 直出/0.7–0.85 复核/<0.7 提示）；分派路由；三态决策 + reason_type 分类回流 | 三方案的 HITL 交互完全同构：确认不阻塞流水线、驳回必须给理由、反馈进评测集 | 对齐 195 号文"辅助性定位"、金融监管"人责归属"、保险法"拒赔必答"——**一次建设 = 全部产品获得合规人格**；反馈数据跨产品汇聚成飞轮 |
| **C4 快照与审计追溯** | 输入哈希 + 中间表示 + 引擎版本三元组；不可变档案/版本链；操作全量留痕；回放复现 | 三处独立设计同一机制：review_snapshot / decision_trace+funding_events / research_dossier+as-of | 政企金融采购的**准入资格**（审计可回放、责任可追溯）；日志留存口径（≥7 年/≥6 个月）平台统一执行 |

## 4. 不沉淀：领域资产与边界原则

| 产品 | 领域资产（留在产品侧） |
|---|---|
| procuraAI | 法规规则库 R01–R25 + 企业源 ER01+、三一致校验（条例57条阴阳合同）、条款库与智能起草、供应商信用画像 |
| ClaimSphere | 简化资金状态机（两段式）、理算引擎、医学知识图谱（诊断-条款映射）、多智能体风控、决策图模板 |
| Synap Equity | PE/PB/DCF 估值引擎、五维财务体检、时点快照库、策略纪律引擎、研究档案与对账误差库 |

**边界原则**（三条，回答"为什么这些不能沉淀"）：

1. **它们是壁垒，不是基础设施。** Synap 创业方案壁垒分层说得很清楚：模型可买、数据难买——规则资产/授权数据/知识图谱需要 2–3 年积累，吞进平台会模糊产品归属、拖慢领域迭代。
2. **平台只沉淀"机制与治理"，不吞并"内容与领域逻辑"。** 版本化、灰度、回流、留痕、评测的**机制**进平台；法规三元组、诊断映射、估值公式的**内容**留产品。
3. **Clean Core 一致。** procuraAI README 已明确"独立智能体不修改 Bone 核心"——平台能力以契约化服务暴露，领域智能体外置隔离、独立部署。

## 5. 为什么沉淀（五条论证）

1. **重复建设有实证**：10 项能力 8 项三方案同构、2 项两方案同构，连选型都重复（QLExpress、pgvector+BM25+rerank、快照+引擎版本、HITL 三态、Kappa 标注、适配器模板）——继续各建一套是确定的浪费。
2. **合规准入一次建设、多产品复用**：可复现/可回放/人工终审/数据不出域是政企金融采购硬门槛（195 号文辅助性定位、金融日志≥7 年、等保三级），平台级实现让每个产品默认拿到准入资格。
3. **质量证明体系统一，反馈跨产品汇聚**：指标字典 + 评测门禁 + 反馈回流平台化后，误报/漏检/采纳数据成为跨产品复利的数据飞轮（Synap 壁垒一"时间差就是壁垒"）。
4. **成本治理必须平台强制**：LLM 网关的模型分流/配额/语义缓存直接决定毛利；"规则命中不调 LLM"这类红线靠产品自觉必然失控。
5. **交付提速**：FDE 适配器模板化（70–90% 复用）+ 三态开关，把客户接入从项目制变配置制——这是 procuraAI/ClaimSphere 两个产品已经写出来的诉求，只是还没共享。

## 6. Bone 落地路径

**已有可复用资产**（2026-10-13 仓库实证，修正 v1.0 的误判：Bone **没有** QLExpress，实际已有 Aviator 5.4.1 且为 LGPL-2.1+；但上游已迁址并换许可——`io.github.aviatorscript:aviator 5.9.0` 为 **Apache-2.0**（包名兼容），存量升级 GAV 即解决许可，QLExpress 4.1.3（Apache-2.0）作为 bone-ai-rules 规则 DSL 默认实现（表达式追踪服务证据链回放），详见《BONE-AI能力中台最佳方案》v3.4 §3.3）：元数据建模与低代码 Runtime（规则/表单配置化）、`bone-extension-sdk` 表达式 SPI（`AviatorExpressionEvaluator`）、Apache POI 5.3.0、Apache Camel 4.18.2（`bone-integration` Flow/Connector/Outbox 底座）、`bone-notification` alert 域、`bone-file`、多租户与审计字段规范、check.sh + ArchUnit 门禁体系。

**新增能力层（v1.1 指针化）**：落点**以《BONE-AI能力中台最佳方案》v3.4 §2 的 `bone-ai/` 七模块聚合为准**（gateway / orchestration(内嵌 HITL 子域) / trace / rules / document / rag / eval；C4 独立为 bone-ai-trace，一期不引 Spring AI）。v1.0 本节旧落点表（bone-ai-doc/rule/hitl 命名、gateway“唯一持 Spring AI”、C4 落 bone-framework 横切）**已被其 v2.0+ 裁决推翻，不再维护**；入站边界等治理约束（ADR-0028 `*ApplicationService`、`ApiResponse`/`PageResult`、全表租户隔离）继续有效，模块规划细节见 `BONE-AI能力沉淀模块规划与框架选型建议.md`（v1.2）。

**治理机制**：每能力指定 owner + 语义化版本 + 评测基线门禁（指标口径沿用 procuraAI §10.1 指标字典）；平台 API 稳定封箱、领域产品经契约消费；平台能力变更走 L3 审批（对齐 AGENTS.md 自主权分级）。

**风险与权衡**：
- 平台化不能拖慢产品——契约先行、实现可替换；P0 四项可用"平台默认实现 + 产品可覆盖"落地。
- 防过度设计：MVP 阶段确定性工作流优先，确需自主决策再上多 Agent（Equity §6.2"复杂度驱动"与 Bone 方法论一致）。
- 许可排雷前置（2026-10-13 经官方来源实证，结论已按最佳方案 v2.0 精细化）：pg_search AGPL-3.0（用 pgvector）；Aviator LGPL-2.1+（升级 GAV 至 `io.github.aviatorscript:aviator 5.9.0` Apache-2.0 或换 QLExpress 4.1.3）；MinerU ≥3.1.0 为基于 Apache-2.0 的自定义许可（>100M MAU 或 >$20M/月营收需商业授权 + 在线服务署名——私有化内部部署基本不触发，需法务确认版本与权重许可，对外 SaaS 不建议）；PyMuPDF AGPL、Marker 权重 OpenRAIL-M（换 PaddleOCR/Docling/PDFBox）；Dify 多租户许可红线（LICENSE 原文实证：tenant=workspace，无书面授权不得运营多租户环境，不引内核）；Qwen 按档位分层——Qwen3.8-27B 为 Apache-2.0，Max/Flash-Next 等档位有 MAU/营收/MaaS 条款（纯内部使用豁免，选型锁定 Apache-2.0 档位）；**Spring AI 官方 1.1.x 止于 1.1.8 且有 4 个未修复 CVE（2 high，含 CVE-2026-59318 工具调用越权）——一期不默认引入，改用自建 OpenAI 兼容客户端**。均需在 POC 签前完成法务 SBOM 评估。

## 7. 一页纸总结

> **能沉淀的是"机制"**：解析、双引擎、人环、留痕、网关、检索、评测、安全、预警、交付——10 项中 8 项三方案同构，是产品地基与合规门槛，平台一次建设全部复用。
> **不能沉淀的是"资产"**：法规规则库、医学图谱、估值引擎、时点快照库——它们是 2–3 年积累的数据飞轮与 know-how，是壁垒，必须留在产品侧。
> **判断标准一句话**：跨域同构的工程机制进平台；领域知识与数据资产留产品；平台只做"证明与治理"，不做"判断与决策"。
