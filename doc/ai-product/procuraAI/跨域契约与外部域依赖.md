# 跨域契约与外部域依赖（Item / Inventory / Warehouse）

> **版本**：v0.3（2026-11-09）
> **状态**：**Proposal（设计提案，待架构评审冻结）**
> **定位**：JD 职责 4 / 要求 5 点名的 7 个域中，此前**无契约**的 Item、Inventory、Warehouse 三域的最小可执行契约；Supplier / Cost / Contract / Finance 四域契约见 `采购总体架构方案.md §7.1` 与 `采购领域架构设计方案.md §6.2`。
> **依据**：诊断 P1-11 / 建议 R8（二选一中的「明示边界 + 最小契约」分支）。
> **门禁**：`tools/check_procura_alignment.py` **A10**（三域章节齐全 / 边界声明 / OpenAPI 端点登记）。

## 1. 边界声明（先说清不定义什么）

> **采购域不生产、不裁决、不写入 Item / Inventory / Warehouse 三域的数据。** 这三类主档与库存事实的**系统真源在各自域**，采购域是**只读消费者 + 事件订阅者**。因此 `contracts/asyncapi.yaml` 的 29 个 channel **100% 为 `domain.procurement.*`**（采购域自产事件全集），本文件登记的是**入站依赖**而非采购域事件；这不构成「跨域契约只有单侧」——单侧指的是「不定义生产方契约」，而四要素（API / Event / 主数据 / 状态同步）在**消费侧**均有可执行定义。

**为什么不新增 `domain.item.*` 等 channel**：`总纲 §16.8` 已把「INBOUND 事件 topic 的 domain 段与事件规范 §2『domain = 生产方上下文』不一致」登记为 **P0 偏差 + L31 待裁决**。在 L31 关闭前新增第三套命名，只会用新争议替换旧争议。裁决前的统一纪律：**只以 `eventType + eventId + HMAC 验签` 做识别与授权，禁止用 topic 的 domain 段做路由/权限判断**。

**若架构评审选择 R8 的另一分支**（采购域为三域定义生产方契约），须先关闭 L31、在总纲附录 B 登记新 topic、重跑生成器并扩 A8 白名单——本文件不预先做此决定。

## 2. 三域统一消费模型

| 要素 | 约定 |
|------|------|
| 同步读 | 业务侧 `*QueryPort`（框架无该接口，按 CORE-05 自定义；`能力基线 §1.4`），经 ACL 适配器 |
| 异步入站 | 外部域事件 → Webhook/消息队列 → `t_proc_processed_event` 幂等 → 采购域**只读投影表** |
| 一致性 | 请求级（同步读）/ 最终一致（投影）；**禁止跨域强一致事务** |
| 隔离 | `tenant_id + legal_entity_id + org_id` 三维谓词（`总体 §8.5`）；投影表同样带必备列（`总纲 §18.1`） |
| 失败 | 外部域不可用 → 只读投影 + 明确 `staleness` 标记 + 阻断需新鲜数据的操作（如 PO 提交），**不得静默用陈旧值** |
| 授权 | `@PreAuthorize("hasAuthority('procurement:<resource>:read')")`；权限码取自 `总纲 附录 C` 白名单，不新增 |
| 错误 | 复用 `总纲 附录 A` 的 31xxx 与 RFC 9457 通用 HTTP 语义；**不新增错误码**（A8 守护 43 条目录不变） |

## 3. Item（物料 / 商品主数据）域

### 3.1 同步只读端口

```
ItemQueryPort.findByIds(tenantId, itemIds[]) -> List<ItemSnapshot>
  ItemSnapshot { item_id, sku, name, uom_base, uom_purchasing,
                 conversion_factor, tax_code, hazard_flag,
                 lifecycle_state, version, source_domain, as_of }
```

- **UOM 换算快照**（`总纲 §14`）：PO 行必须落 `uom_purchasing`、`conversion_factor` 与 `as_of`；**不得在事后用当前主档重算历史金额**。
- `tax_code` 与 `hazard_flag` 决定采购可行性与审批链；`lifecycle_state != ACTIVE` 的物料禁止进入新 PO（负向探针 §6 IT-1）。
- 缓存：仅缓存 `ItemSnapshot`，key 含 `tenant_id + item_id + version`；**失效靠版本号变化 + TTL 双保险**，不做跨库双写（避免缓存一致性伪命题，回应诊断 JD 职责 5「缓存无设计」）。

### 3.2 INBOUND 事件（订阅，不生产）

| eventType | 生产方 | 触发 | 采购域动作 | 幂等键 |
|-----------|--------|------|------------|--------|
| `ItemMasterChanged` | Item 域 | 主档新增/变更/停用 | 失效本地快照缓存 + 更新只读投影；**不改写已有 PO 行快照** | `item_id + version` |
| `ItemUomConversionChanged` | Item 域 | 换算率调整 | 标记受影响未结 PO 需人工复核（不自动重算价） | `item_id + effective_from` |

### 3.3 主数据映射与状态同步

| 采购域概念 | Item 域来源 | 同步语义 |
|------------|-------------|----------|
| `SupplierItem`（`01 卷 §3`） | `item_id` + 供应商特定编码 | 采购域持有**供应关系**，不持有物料主档；Golden Record survivorship 见 `01 卷 §13.1` |
| PO 行 `item_ref` | `item_id` 快照 | 下单时冻结；主档后续变更只影响新单 |
| 价格条件 `PriceCondition`（`04 卷 §3`） | 品类 / 税码 | 条件技术访问序列按**下单时快照**求值（`04 卷 §13.1`） |

## 4. Inventory（库存）域

### 4.1 同步只读端口

```
InventoryQueryPort.available(tenantId, itemIds[], siteIds[]) -> List<StockSnapshot>
  StockSnapshot { item_id, site_id, qty_available, qty_reserved,
                  uom_base, version, as_of }
```

- 用于 PR 转 PO 前的**可用性提示**，不是库存锁定；预留动作须由 Inventory 域自身 API 完成并回传 `reservation_id`。
- `as_of` 超过 `总纲 §23.7` 的 staleness 阈值时，PO 提交必须阻断并提示刷新（负向探针 §6 IV-2）。

### 4.2 INBOUND 事件

| eventType | 生产方 | 触发 | 采购域动作 | 幂等键 |
|-----------|--------|------|------------|--------|
| `GoodsReceived`（**已冻结**，`总体 §7.1`） | Inventory(ACL) | 收货过账 | 推进 PO 行收货状态、三单匹配输入（`04/05 卷`） | `gr_no` |
| `StockReservationChanged` | Inventory 域 | 预留创建/释放/过期 | 更新 PR 可行性与 `reservation_id` 投影 | `reservation_id + version` |
| `InventoryAdjustmentPosted` | Inventory 域 | 盘盈盘亏 | 触发已收数量差异例外台账（`05 卷 §13.1` 例外分类） | `adjustment_no` |

> `GoodsReceived` 已在 `总纲 附录 B.1` 登记为 Frozen + INBOUND + domain 段偏差（L31），**沿用冻结值不改**；此处只补齐生产方与消费侧契约说明。

### 4.3 状态同步

| 采购域状态 | 依赖事实 | 不允许的做法 |
|------------|----------|--------------|
| PO 行 `RECEIVED` | `gr_no` 与累计收货数量 | 不得由 ASN（856）直接推定收货（X12 语义，`05 卷 §13.1`） |
| RTV 库存回冲（`04 卷 §13.1`） | Inventory 域红冲回执 | 不得在采购域直接改库存表 |
| Transfer 在途（`04 卷 §5`） | 调出/调入两笔库存移动 | 不得用单个本地事务跨库提交 |

## 5. Warehouse（仓储）域

### 5.1 同步只读端口

```
WarehouseQueryPort.sites(tenantId, legalEntityId) -> List<SiteSnapshot>
  SiteSnapshot { site_id, warehouse_code, legal_entity_id,
                 receiving_calendar, dock_capacity, version, as_of }
```

- 多法人场景：`site_id` 必须属于 PO 的 `legal_entity_id`，否则拒单（负向探针 §6 WH-1）。
- `receiving_calendar` 用于 ASN 预约与 SLA 计算（`05 卷 §13.3`）。

### 5.2 INBOUND 事件

| eventType | 生产方 | 触发 | 采购域动作 | 幂等键 |
|-----------|--------|------|------------|--------|
| `AsnAcknowledged` | Warehouse 域 | ASN 预约确认/拒收 | 更新 ASN 状态与供应商协同视图 | `asn_no + version` |
| `ReceivingDiscrepancyRaised` | Warehouse 域 | 实收与 ASN 不符 | 生成收货差异例外，进 aging 升级链（`05 卷 §13.1`） | `discrepancy_no` |

### 5.3 主数据映射与状态同步

| 采购域概念 | Warehouse 域来源 | 同步语义 |
|------------|------------------|----------|
| `Site`（`01 卷 §3`） | `site_id` | 采购域存**供应商地点**与 `site_id` 的关联，不复制仓库主档 |
| ASN 预约 | `receiving_calendar` + `dock_capacity` | 预约成功才允许发运；不做双写 |

## 6. 负向探针与验收

| # | 注入 | 期望 |
|---|------|------|
| IT-1 | `lifecycle_state=DISCONTINUED` 的物料进入新 PO 行 | 拒绝 + 具名错误；`openapi` 契约测试转红 |
| IT-2 | 主档换算率变更后，用当前值重算历史 PO 金额 | 金额不变（用下单快照）；回归用例转红 |
| IV-1 | 缺 `gr_no` 的 ASN 被当作收货凭证推进 PO 至 `RECEIVED` | 状态不变 + 告警 |
| IV-2 | `StockSnapshot.as_of` 超 staleness 阈值仍允许 PO 提交 | 阻断 + 提示刷新 |
| WH-1 | PO 法人与 `site_id` 法人不一致 | 拒单 + 审计留痕 |
| WH-2 | Warehouse 事件重放两次 | 只产生 1 条例外台账（`t_proc_processed_event` 幂等） |
| XD-1 | 三域任一 ACL 超时且无 `staleness` 标记 | 读接口 fail-closed，不得静默返回陈旧值 |

> 探针为**契约级验收**（可写成 WireMock/契约测试）；本族当前仍是 Proposal，尚无测试代码，见 `质量属性场景与ATAM.md` 对「可自动化程度」的诚实标注。
