## 1. 模块定位与边界

**拥有的业务结果**：从请购到 PO 下达、价格快照冻结、收货推进、退供与调拨的交易闭环；以及可复现的**采购成本真源**（价格链 / PPV / Savings / 价格合规率）。

| 在范围内 | **非目标（Non-goals）** |
|----------|------------------------|
| Requisition / PurchaseOrder(+Line) / PurchaseCost / PriceCondition / PriceSnapshot | ❌ **不裁决发票匹配与付款**（Finance 执行 2-way/3-way + 容差 + 冻结放行，PA-04） |
| Transfer / RTV 及其跨域补偿编排 | ❌ 不维护库存台账（Inventory/Warehouse 经 ACL 协作） |
| 预算占用/释放、Blanket PO 累计核销、GR 累计投影 | ❌ 不定义标准成本归集口径（Finance 共同确认，领域 §5.3） |
| 产出匹配输入数据与 `PaymentRequested` | ❌ 不直连/改写 ERP 核心（Clean Core / ACL，PA-03） |

**裁决边界（总体 §3.1、领域 §5.2）**：采购域产出 PO / GR / 发票数据；`InvoiceMatched` 由 **Finance(ACL)** 回传；采购域据此发 `PaymentRequested`，ERP 付款后 `PaymentRecorded` 回传。**三者跨系统，只有最终一致 + 对账，不设跨域强一致不变量**。

## 3. 领域模型与不变量

| 聚合根 | 关键实体/值对象 | 强一致不变量 |
|--------|----------------|--------------|
| `Requisition` | PR Line、预算占用引用 | **INV-01** 审批通过才可转 PO；**INV-02** 转换后 `CONVERTED` 终态；预算占用/释放成对 |
| `PurchaseOrder` | `PurchaseOrderLine`（子实体，随根） | **INV-03** `po_amount = Σ line_amount`（单聚合强一致）；**INV-04** `(tenant_id,po_no,po_version)` 唯一；**INV-05** 创建时 `vendor_id` 必须 `ACTIVE_VENDOR` 且 `legal_entity_id` 匹配（负向探针）；**INV-06** `CLOSED/CANCELLED` 终态不可回写 |
| `PurchaseCost` | `PriceCondition`（随根）、`PriceSnapshot`（值对象） | **INV-07** `(vendor_id,item_id,org_id,valid_from,version)` 唯一；**INV-08** 同一生效期不得两个有效价（条件更新互斥）；**INV-09** PO 引用快照后成本版本变更**不回滚已下 PO** |
| `Transfer` | 跨仓/跨组织/跨法人明细 | **INV-10** 跨法人须带 `legal_entity_from/to` 并触发双边账务事件 |
| `RTV` | `RtvLine`、原 GR/发票引用、RMA | **INV-11** 冲销幂等（`eventId` 去重）；**INV-12** 应付红冲 + 库存回冲 + RMA 质检三步补偿成对 |

> **跨域只最终一致**：GR 累计 ≤ PO 承诺量是**本域投影**校验（最终一致），不是跨系统强一致不变量（领域 §5.2）。

## 4. 数据库设计

> **v0.2（总纲 §14 / §18）**：金额列一律 `DECIMAL(19,4)` + `currency CHAR(3)`、汇率 `DECIMAL(19,8)`、数量 `DECIMAL(19,6)`、时间 UTC `DATETIME(3)`，**禁用 float/double**（D-01–D-09）；唯一键须处理软删与同码重建冲突（§18.3）；索引须给出 access pattern 理由（§18.2）。下表只列业务列，类型基线不重复抄写。

> 必备列见总纲 §4；一期已列 `t_proc_po` / `t_proc_po_line` / `t_proc_price_condition`（能力基线 §3.4），下表补全并新增。DDL 手写 `bone-init.sql` 后补列级对账。

| 表 | 业务列 | 唯一键 / 索引 | 冲突处理 |
|----|--------|---------------|----------|
| `t_proc_requisition` | `pr_no, requester_id, org_id, budget_ref, budget_amount, status, workflow_instance_id` | `uk(tenant_id,pr_no)`；`idx(org_id,status)` | `@Version` |
| `t_proc_po` | `po_no, po_version, vendor_id, supplier_id, legal_entity_id, org_id, contract_no, price_snapshot_ref, currency, total_amount, status, workflow_instance_id, sent_at` | `uk(tenant_id,po_no,po_version)`；`idx(vendor_id,status)` | `po_no+po_version` CAS |
| `t_proc_po_line` | `po_id, line_no, item_id, qty, uom, net_price, tax_rate, line_amount, site_id, received_qty, price_snapshot_ref` | `uk(tenant_id,po_id,line_no)` | 随根 `@Cascade`；金额校验在 domain |
| `t_proc_purchase_cost` | `vendor_id, item_id, org_id, valid_from, valid_to, version, standard_cost_ref, currency, status` | `uk(tenant_id,vendor_id,item_id,org_id,valid_from,version)`；**有效期互斥条件更新** | `31401` |
| `t_proc_price_condition` | `cost_id, cond_type, seq, base_type, rate, tier_json, rebate_json, freight_json, tax_rate, currency` | `uk(tenant_id,cost_id,cond_type,seq)` | 优先级不可重叠 |
| `t_proc_price_snapshot` | `po_no, po_version, computed_net_price, condition_result_json, fx_rate, fx_as_of, fx_source, rounding_mode, tax_code_version, tax_amount, computed_hash, computed_at`（`computed_hash` 覆盖 fx_as_of/fx_source/rounding_mode/tax_code_version，对齐总纲 §14；金额 DECIMAL(19,4)+currency CHAR(3)） | `uk(tenant_id,po_no,po_version)` | **只追加、不可变** |
| `t_proc_transfer` | `transfer_no, from_wh, to_wh, legal_entity_from, legal_entity_to, status, shipped_at, received_at` | `uk(tenant_id,transfer_no)` | 在途丢失补偿 |
| `t_proc_rtv` | `rtv_no, po_no, gr_no, invoice_no, rma_no, reason, status, total_amount` | `uk(tenant_id,rtv_no)`；`idx(po_no)` | 冲销幂等 |
| `t_proc_rtv_line` | `rtv_id, line_no, item_id, qty, amount` | `uk(tenant_id,rtv_id,line_no)` | 随根 |

**价格链与价值度量**（领域 §5.3）：Quotation(Sourcing) → PriceCondition(Contract/SupplierItem) → 标准成本(Finance 只读) → **PO 价快照** → 发票价(Finance)。`PPV = 实际 PO/发票价 − 标准成本`；`Savings = 基线价 − 实际成交价`（标注 `avoidance/realized`）；`价格合规率 = PO 价落在允许区间的行占比`。三者经 `*QueryPort` 只投影，不回写交易表。

## 5. 状态机

> **v0.2（总纲 §21.1–§21.3）**：本节状态须落为枚举 + **显式迁移表** `Map<State, Map<Event, Transition>>`，守卫集中在 domain 层；**迁移表未列出即拒绝**（fail-closed），非法迁移返回 §17.2 的 `invalid_transition`（带 `current_state/attempted/allowed[]`）；状态迁移与 `@Version` CAS 同事务；终态不可回写由 domain 守卫 + 唯一约束双保险。本节小写领域事件（如 `supplier.activated`）属**领域内部事件**，不落 Outbox、不进注册表（总纲 §16.1）。

**Requisition**：`DRAFT → SUBMITTED → APPROVED → CONVERTED → CLOSED`（`CANCELLED` 终态）。

**PurchaseOrder**（领域 §5.1）：`DRAFT → SUBMITTED → APPROVED → SENT → ACKNOWLEDGED → PARTIAL_RECEIVED → FULLY_RECEIVED → CLOSED`；`CANCELLED` 终态。

| From | Event | Guard | To | 补偿 |
|------|-------|-------|----|------|
| `DRAFT` | `submit` | 行金额合计一致 + Vendor `ACTIVE_VENDOR` + LE 匹配 | `SUBMITTED` | — |
| `SUBMITTED` | `approve` | WF 审批（金额阈值条件分支） | `APPROVED` | 驳回 `rejectToNode` |
| `APPROVED` | `send` | 价格快照已冻结 + 合同引用有效 | `SENT` | 发送失败重投 |
| `SENT` | `acknowledge` | 门户 `po_acknowledged`，`po_no+po_version` CAS | `ACKNOWLEDGED` | 超时催办 |
| `ACKNOWLEDGED` | `goods_received` | `GoodsReceived` 幂等；累计 GR ≤ 承诺量（本域投影） | `PARTIAL_RECEIVED` / `FULLY_RECEIVED` | 超量进例外台账 |
| `FULLY_RECEIVED` | `close` | 无未结 IR 例外 + 对账通过 | `CLOSED` | — |
| 非终态 | `cancel` | 审批 + 预留释放 | `CANCELLED` | 预算/库存预留回滚 |

**PurchaseCost**：`DRAFT → PENDING_APPROVAL → EFFECTIVE → SUPERSEDED → EXPIRED`；新版本不影响已下 PO（INV-09）。
**Transfer**：`CREATED → IN_TRANSIT → RECEIVED → CLOSED`；在途丢失 → 冲销 + 重发。
**RTV**：`OPEN → APPROVED → RETURNED → SETTLED`；`SETTLED` 终态。

**禁止迁移**：任何终态回写；`DRAFT → SENT` 跳步；未审批 PO 下发；`Vendor` 非 `ACTIVE_VENDOR` 建 PO。

```json

  "vendor_id": 9901,
```

## 7. 事件契约

> **v0.2 契约校准（总纲 §16 / 附录 B）**：本表 `eventType` 的 **topic / partition_key / owner / consumers / schemaVersion 一律以总纲附录 B 事件契约注册表为准**，payload 字段**唯一真源 = `contracts/asyncapi.yaml`**；本表仅为字段速查，**不重复定义 topic**（避免双真源）。所有事件已按事件规范 §4「先登记注册表 → 再写 Producer」登记；门禁 **A8** 校验本表 eventType 均在注册表内、且注册表 topic 与 AsyncAPI channel 一一对应。顺序敏感链路 `partition_key = tenant_id + <aggregate_key>`（总纲 §6 双轨）且 payload 带 `aggregate_version` 供乱序丢弃；消费侧为 tolerant reader（§16.5）+ Inbox 幂等（§6），delivery 为 at-least-once。**`INBOUND`** 事件由外部上下文生产、沿用上游冻结 topic（L31 待裁决），采购域只读、不裁决。

| 方向 | eventType（topic / partition_key / owner 见总纲附录 B） | payload 字段速查（真源 `contracts/asyncapi.yaml`） | 幂等 / 顺序 / 失败 |
|------|-------------------|------------------|--------------------|
| 生产 | `PurchaseOrderCreated`（已冻结） | `po_no, tenant_id, supplier_id, total_amount, currency, po_version, created_at, requisition_no?, legal_entity_id, lines[], contract_no?, price_snapshot_ref?`（字段名真源 D3-v2 §2.1） | `po_no+po_version`；同 `po_no` 保序 |
| 生产 | `PoLineReceived`（LLD 新增） | `po_no, line_no, received_qty, gr_no` | 同 `po_no` 保序；重放须新 `eventId` |
| 生产 | `PaymentRequested`（已冻结） | `po_no, invoice_no, vendor_id, legal_entity_id, amount(Money)`（字段名真源 D3-v2 §2.1；金额与币种同行） | `Idempotency-Key`；**不裁决** |
| 生产 | `RtvSettled` / `TransferShipped`（LLD 新增） | `rtv_no/transfer_no, legal_entity_from/to, amount` | 业务单号唯一 |
| 消费 | `PurchaseOrderAcknowledged`（05 卷） | `po_no, po_version, ack_lines[]` | `po_no+po_version` CAS；不得确认已关闭 PO |
| 消费 | `GoodsReceived`（**INBOUND** / Inventory ACL；依赖跨域 ACL 交付（F-A），未交付前接口预留、运行期不触发） | `gr_no, po_no, po_line_no, received_qty, uom, received_at, site_id, tenant_id, supplier_id?, asn_no?`（字段名真源 D3-v2 §2.1） | `gr_no` 幂等；推进 PO 状态 |
| 消费 | `InvoiceMatched`（**INBOUND / Finance ACL**；依赖跨域 ACL 交付（F-A），未交付前接口预留、运行期不触发） | `match_id, invoice_no, po_no, match_status(enum MATCHED/EXCEPTION/REVIEW), matched_amount, exception_code?, matched_at`（**字段级真源 D3-v2 §2.1**） | `invoice_no+revision`；采购域**只读** |
| 消费 | `PaymentRecorded`（**INBOUND** / Finance ACL；依赖跨域 ACL 交付（F-A），未交付前接口预留、运行期不触发） | `payment_id, invoice_no, paid_amount, payment_date, payment_method?, payer_legal_entity`（**字段级真源 D3-v2 §2.1**） | `payment_id`；对账 |
| 消费 | `VendorActivated` / `SupplierChanged`（01 卷） | `vendor_id, vendor_status, supplier_version` | 更新只读投影 |

## 13. 本卷专题深化（v0.3）

> **一期状态（R6 / B20，A10 守护）**：T6（Saga 拆分后启用）；一期只做 PR→PO 最小闭环。本章全部规格**保留为设计储备**，触发条件与逐项映射见 [一期边界与机制触发条件.md](../一期边界与机制触发条件.md) §2；不得把本章机制默认解读为「一期必须实现」。

> **定位**：把总纲 §23 八项要素实例化到采购交易与成本；本章**不新增事件 / 错误码 / 权限码**，不动 v0.1 已冻结的「采购域不裁决匹配与付款」结论。数值均为草案（L38）。
> **依据**：B15（SAP 条件技术与 PPV / Savings 口径），总纲 §23.9 → 04 卷。

**13.1 差异化核心算法：条件技术、逐行舍入、PPV 双基线与预算承诺**

1. **条件技术（价格决定过程）**：条件类型固定为 基价 / 折扣 / 附加费 / 运费 / 税；**访问序列按优先级自上而下，首个命中即停**（`exclusive` 标记），同一条件类型多条记录按 `valid_from ≤ 业务日 ≤ valid_to` 与「供应商 + 物料 + 组织」维度取最具体者；命中记录全量写入价格快照，保证 `computed_hash` 可复现（M4-8 / M4-14）。
2. **逐行定价与舍入**（§14）：`net_i = round(base_i × (1 − discount_i) + surcharge_i, minor_unit(currency))`，**逐行舍入后再汇总**，舍入模式显式冻结在快照中；含税场景先按税率做价税分离再定价，禁止先汇总后反算税。跨币种按 §14 锁一次 `fx_rate + fx_as_of + fx_source`，红冲复用原汇率，FX 损益单列，不并入价差。
3. **PPV 符号与双基线隔离**：`PPV = (实际净价 − 标准成本) × 采购量`，**正值 = 不利差异**；采购节约口径 `Savings = 采购基线 − 实际净价` 为反向，**两者不可混用、不得相减合并**。会计基线 = 财年冻结标准成本；采购基线 = 上次成交价 / 合同价 / 指数价（三选一，按品类配置，L42）。**移动平均价法不产生 PPV**，命中即跳过归集并标注口径。
4. **归因分项**：汇率 / 运费 / Incoterms / 规格变更 / 陈旧标准成本 / 量差六类**单列**，不得塞进 PPV 主项；标准成本超过刷新周期未更新时，PPV 标「基线陈旧」并降权展示，不静默当真实价差。
5. **预算承诺**：PO 下达按行占用预算（`commitment`），收货 / 取消 / RTV 按比例释放，PO 变更按「变更前后差额」增量占用；变更金额或关键条款越过阈值 → **重审批**（阈值 L42），已发 PO 版本不回写。
6. **决策表**：

| 条件 | 判定 | 动作 |
|------|------|------|
| 条件记录 `valid_to` < 业务日 | 过期条件 | 跳过并在快照记「已排除」，不得参与定价（M4-14） |
| 多个条件类型同时命中且标 `exclusive` | 访问序列首个命中 | 截断后续，快照记录截断原因 |
| 缺 `fx_rate` / `fx_as_of` | 无法确定金额 | 定价失败，禁止用当日牌价兜底（§14） |
| 混用会计基线与采购基线 | 口径污染 | 拒绝计算 + 归因分项单列（M4-13） |
| 标准成本陈旧 | 基线不可信 | PPV 打标降权，不阻断入账 |
| PO 变更超阈值 | 需重审批 | 冻结发送，回原审批链，原版本只读 |
| 收货数量 < PO 数量 | 部分释放 | 按未收差额释放剩余承诺，避免虚占 |

7. **失败语义与反例**：价格服务不可用 → **不降级为「沿用上次价格」**，PO 保持 `DRAFT`；反例：把「上次成交价」当标准成本算 PPV，会把市场波动误记成生产效率差异，必须被 M4-13 拦截。

**13.5 上线四闸门与回滚（总纲 §22.1 / 总体 §8.4）**

- **feature flag 粒度**：`tenant_id × company_code × flow(CONDITION_V2 / PPV_SPLIT / COMMITMENT_V2)`，默认全关；金额相关开关**不按用户灰度**，只按法人整体切换，避免同单双口径。

- **灰度维度与观测窗**：按法人 1 家 → 3 家 → 全量，每级 ≥ 1 个完整月结周期，观测 `ppv_baseline_mix_total` / 承诺泄漏 / 快照可复现率 / 月结差异。
- **回滚触发**：基线混算 ≥ 1、快照哈希不可复现、承诺泄漏、月结与总账差异超阈值。
- **本卷回滚代价（诚实登记）**：**已下达并已对供应商生效的 PO 不可删除、不可改写原版本**，只能发变更单；已入账 PPV 需财务红冲而非程序回滚；已发事件按 §23.5 不撤回，用补偿事件与差异台账处理。

**13.7 只读投影与新鲜度（总纲 §16.7 / §19.6）**

- **投影表**：`t_proc_cost_dashboard_projection`（成本看板 / PPV 汇总 / 价格合规率 / 采购节约），跨聚合列表一次取齐 JOIN，禁止 N+1（§18.4）。
- **更新触发**：本卷 §7 已登记的 OUTBOUND 与 INBOUND 事件 + 月结批作业；**月结口径以账套表为准，投影只做展示**。
- **staleness 上界**：P99 30s（月结期间放宽至 5min 并显式标注）；超界自动读回源并告警 P2。
