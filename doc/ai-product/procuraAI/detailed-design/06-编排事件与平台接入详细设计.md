## 1. 模块定位与边界

**拥有的业务结果**：把跨部署单元的写协作做成**可靠、幂等、可重放、可对账**的事件通道；把长流程按步推进（E-3.3）；把 BONE 平台能力按三轨接入；保留并约束存量低代码适配层。

| 在范围内 | **非目标（Non-goals）** |
|----------|------------------------|
| `ProcurementOrchestrator`（跨聚合长流程按步推进） | ❌ **同库同进程内不引入 Outbox/MQ/Saga**（总体 §8.1、PA-08，避免为不存在的边界付复杂度） |
| `t_proc_outbox` / `t_proc_processed_event` / 中继 / DLQ 转投 | ❌ 不跨上下文直写 `bp_processed_event` / `bp_outbox`（能力基线 §1.4） |
| `IdempotencyStore`、`AclGateway`（HMAC）、审计事件、对账作业 | ❌ 不把 `scripts/check.sh` 当 CI 门禁；**ship-ready 判据 = CI blocking**（总体 §13） |
| WF 状态回写统一经 `WorkflowStatusPort`；存量适配层保留 | ❌ 不由低代码 Runtime 动作直接触发付款（PA-04，`PaymentRequested` 为唯一生产链路） |

**一期事实（能力基线 §7）**：仓库已有 `bone-apps/bone-app-purchase`（12 个主代码类，无 `@Table` 实体 / 无 Repository），是低代码 Runtime 动作 + 工作流适配器；决策为**保留为适配层**，新模块统一 `bone-procurement-*` 命名。

                   FinanceWebhookController · InventoryWebhookController
adapter/web        OpsController（重放 / DLQ / 对账作业，admin）
     │
     ▼

             OutboxWriter              （业务事务内写 outbox）

             AuditEventPublisher       （统一审计事件 schema）

     │            PlatformEventPort · QueryPort(读)
     ▼

             OrchestrationStep / ReconResult / AuditEvent
     ▼

|------|------|-----------|------|

## 3. 领域模型与不变量

| 聚合根 | 关键实体 | 强一致不变量 |

## 5. 状态机

> **v0.2（总纲 §21.1–§21.3）**：本节状态须落为枚举 + **显式迁移表** `Map<State, Map<Event, Transition>>`，守卫集中在 domain 层；**迁移表未列出即拒绝**（fail-closed），非法迁移返回 §17.2 的 `invalid_transition`（带 `current_state/attempted/allowed[]`）；状态迁移与 `@Version` CAS 同事务；终态不可回写由 domain 守卫 + 唯一约束双保险。本节小写领域事件（如 `supplier.activated`）属**领域内部事件**，不落 Outbox、不进注册表（总纲 §16.1）。

**OutboxMessage**：`PENDING → PUBLISHED`；`PENDING → FAILED → PENDING`（**L3 中继投递重试预算 ≤8 次 / 累计 ≤10min**，见 `一期边界与机制触发条件.md §3`；Saga 补偿 L1 与批量单条 L2 才用 ≤3，二者对象不同，不得混用）；`FAILED → DEAD_LETTER`（转投 `platform.dead_letter.v1`）。

| From | Event | Guard | To |
|------|-------|-------|----|
| `PENDING` | `publish_ok` | 事件总线确认 | `PUBLISHED` |
| `PENDING` | `publish_fail` | 可重试异常 + `retry_count < 3` | `FAILED`（退避重投） |
| `FAILED` | `replay` | 人工/自动重放，新 `eventId` 或标 `replayOf` | `PENDING` |
| `FAILED` | `exhausted` | `retry_count ≥ 3` | `DEAD_LETTER` + 转投 + 告警 |

**OrchestrationStep**：`PENDING → RUNNING → COMPLETED / FAILED → COMPENSATING → COMPENSATED`。

**ReconciliationJob**：`SCHEDULED(01:00 日终) → RUNNING → COMPLETED / DIFF_FOUND`；`DIFF_FOUND` 生成例外台账 + 告警，**不自动修数**。

**禁止迁移**：`PUBLISHED → PENDING`；`DEAD_LETTER → PENDING` 未经人工确认；步骤反向跳跃；终态回写。

> 平台 `IntegrationOutboxRelay` 超限只 `markFailed()`（能力基线 §5.2），**DLQ 转投必须由本卷中继自建**；仅 blueprint `OrderOutboxRelayPortAdapter:339-347` 有真实转投可参考。

## 6. API 契约（内部运维，非业务端点）

> **v0.2（总纲 §17 / 附录 A）**：错误码以总纲附录 A 为唯一真源（含新增 `317xx` 段）；错误体采用 RFC 9457 `application/problem+json` 并与 HC-003 `ApiResponse<T>` 兼容（§17.2）；大表 / 流水 / 审计 / DLQ 列表用 cursor 分页 + 服务端 `max_page_size`（§17.4）；状态码与可重试性见 §17.3；契约工件 `contracts/openapi.yaml`。

| 方法 | 路径 | 权限码 | 幂等键 | 说明 |
|------|------|--------|--------|------|
| `POST` | `/api/v1/procurement/ops/events/{eventId}/replay` | `procurement:ops:admin` | `Idempotency-Key` | 重放（新 `eventId` 或 `replayOf`） |
| `GET` | `/api/v1/procurement/ops/dead-letters` | `procurement:ops:admin` | — | DLQ 列表（分页） |
| `POST` | `/api/v1/procurement/ops/dead-letters/{id}/redeliver` | `procurement:ops:admin` | `Idempotency-Key` | 人工确认后转投 |
| `POST` | `/api/v1/procurement/ops/reconciliation/run` | `procurement:recon:admin` | `Idempotency-Key` | 触发三通道对账 |
| `GET` | `/api/v1/procurement/ops/readiness` | `procurement:ops:read` | — | 事件/ACL/门禁就绪状态（部署态/配置态/运行期三层分离） |
| `POST` | `/api/v1/procurement/webhooks/{system}` | 服务间 scoped credential | `eventId` + HMAC | Finance / Inventory / OA / ERP 入站 |

请求示例（重放）：`{"event_id":"evt-01J...","reason":"Finance 消费超时","replay_of":true}`

响应 `202`：`{"code":"OK","data":{"new_event_id":"evt-01J...","status":"PENDING"},"trace_id":"..."}`

**错误码**（总纲附录 A）：`31601` Outbox 投递超限、`31602` HMAC 验签失败、`31603` 跨上下文写 `bp_*` 表、`31604` 无补偿动作的步骤启动、`31605` 未授权重放。非法迁移 `409 invalid_transition`。

> `/ops/readiness` 借鉴 synap-claim `ai-readiness` 设计：端口默认 `UNKNOWN` fail-closed；部署态/配置态/运行期三层分离；**就绪 ≠ 放行许可**。**v0.2**：重放与转投端点须带 `mode=REBUILD|REDELIVER`，默认 `REBUILD` 并抑制不可逆副作用（总纲 §16.7）；liveness 与 readiness 分离（§19.5）。

## 7. 事件契约（中继不改写 payload）

> **v0.2 契约校准（总纲 §16 / 附录 B）**：本表 `eventType` 的 **topic / partition_key / owner / consumers / schemaVersion 一律以总纲附录 B 事件契约注册表为准**，payload 字段**唯一真源 = `contracts/asyncapi.yaml`**；本表仅为字段速查，**不重复定义 topic**（避免双真源）。所有事件已按事件规范 §4「先登记注册表 → 再写 Producer」登记；门禁 **A8** 校验本表 eventType 均在注册表内、且注册表 topic 与 AsyncAPI channel 一一对应。顺序敏感链路 `partition_key = tenant_id + <aggregate_key>`（总纲 §6 双轨）且 payload 带 `aggregate_version` 供乱序丢弃；消费侧为 tolerant reader（§16.5）+ Inbox 幂等（§6），delivery 为 at-least-once。**`INBOUND`** 事件由外部上下文生产、沿用上游冻结 topic（L31 待裁决），采购域只读、不裁决。

| 方向 | eventType（topic / partition_key / owner 见总纲附录 B） | payload 字段速查（真源 `contracts/asyncapi.yaml`） | 幂等 / 顺序 / 失败 |
|------|-------------------|------------------|--------------------|
| 中继 | 全量 `domain.procurement.*` | 原样 8 字段信封，**中继只改投递状态不改 payload** | `event_id` 唯一；同 `partition_key` 保序 |

## 9. 工程治理

> **v0.2（总纲 §14 / §15 / §19）**：金额与汇率语义见 §14（D-01–D-09）；长流程步骤按 `COMPENSATABLE / PIVOT / RETRIABLE` 三分类并登记补偿（§15），编排状态持久化 + 语义锁 / 可交换更新 / 重读值；Outbox 运行纪律见 §19.6（**broker confirm 后才置 `PUBLISHED`**、`FOR UPDATE SKIP LOCKED`、最老未发件年龄告警、Claim Check）；重放 `mode=REBUILD` 抑制不可逆副作用（§16.7）；指标与告警见 §19.3–§19.4。

## 13. 本卷专题深化（v0.3）

> **一期状态（R6 / B20，A10 守护）**：T2 / T3 / T6 / T7 / T10 / T11（Outbox·Inbox·DLQ 一期启用；Saga / schema registry / Replay / 双轨分区键为拆分后启用）。本章全部规格**保留为设计储备**，触发条件与逐项映射见 [一期边界与机制触发条件.md](../一期边界与机制触发条件.md) §2；不得把本章机制默认解读为「一期必须实现」。

> **定位**：把总纲 §23 八项要素实例化到编排、Outbox / Inbox / DLQ 与平台接入；本章**不新增事件 / 错误码 / 权限码**，不动 v0.1 已冻结的「at-least-once 而非 exactly-once」「采购域自建 `t_proc_processed_event`」结论。数值均为草案（L38）。
> **依据**：B17（Outbox / 重试 / DLQ 生产运行纪律），总纲 §23.9 → 06 卷。

**13.1 差异化核心算法：有界退避 + full jitter、失败分类与限流分批 redrive**

1. **退避公式**（唯一允许的重试策略）：`delay = min(cap, base × 2^attempt) × (0.5 + rand())`；草案 `base = 200ms`、`cap = 30s`、`rand() ∈ [0, 0.5)`，即 full jitter 变体。**L3（Outbox 中继投递）retry budget = 单条消息最多 8 次 / 累计 ≤10min**，超出即转 DLQ，不再无限重试。**L1/L2（Saga 补偿 / 批量单条）仍为 ≤3 次**——按 B17 分层而非全族统一数字，见 `一期边界与机制触发条件.md §3`；禁止 L3 与 L4（HTTP 客户端 / SDK）叠加。
2. **禁止多层重试叠加**（M6-12）：中继层 / HTTP 客户端 / SDK 三层**只允许一层开启重试**，其余层 `maxAttempts = 1`；配置加载时做预算校验，检测到多层重试即拒绝启动。
3. **失败分类**：

| 类别 | 判定 | 动作 |
|------|------|------|
| 瞬时 | 5xx / 超时 / 429 / 连接重置 | 按退避公式重试，消耗 retry budget |
| 永久 | 4xx（401/403/404/409/422）/ schema 校验失败 | **不重试**，直接转 DLQ 并标 `PERMANENT` |
| 毒丸 | 同一 `error_class` 连续 N 次（草案 N=5）或反序列化持续失败 | 立即隔离到 DLQ，**停止该 consumer group 的同构消费**并告警 P1 |

4. **DLQ 诊断上下文（缺一不可）**：原 `event_id` / `event_type` / `error_class` / `trace_id` / `tenant_id` / `consumer_version` / `attempt 历史` / `last_error_digest` / `first_failed_at` / **owner** / **响应时限**（L43）。禁止只存异常堆栈。
5. **禁止整队自动 redrive**（M6-13）：修复后必须 ① 人工确认根因已消除 → ② 按限流分批（草案 50 条/min，上限 L43）→ ③ **保留原幂等键与原 `event_id`** → ④ 先小批观察 Inbox 去重与副作用幂等 → ⑤ 再逐批扩量；任何一批出现新毒丸立即停批。
6. **监控主指标**：`oldest_pending_age_seconds`（**最老未发件年龄**）而非仅 backlog 行数；配套 `outbox_relay_lag_seconds` / `dlq_depth` / `poison_isolated_total` / `redrive_inflight`。队列积压但年龄不涨属可接受，年龄持续增长即 P1。
7. **中继与停机**：`FOR UPDATE SKIP LOCKED` + lease（草案 30s，续约需 version 校验）保证多实例不重复取件；worker 优雅停机先停取件、再 drain 在途、最后释放 lease；按 queue age 而非 CPU 扩缩容（草案 age > 60s 扩容，< 10s 缩容）。
8. **清理与反例**：`PUBLISHED` 行按恢复窗口（草案 7 天）分批清理（每批 1,000 行，避免长事务）；反例：整队 redrive 且重发时生成新 `event_id`，会让 Inbox 去重失效并重复触发不可逆副作用，必须由 M6-13 拦截。**Outbox delivery 是 at-least-once，不是 exactly-once**，消费侧幂等由 Inbox 与业务唯一键共同保证。

**13.5 上线四闸门与回滚（总纲 §22.1 / 总体 §8.4）**

- **feature flag 粒度**：`tenant_id × topic_group × flow(RELAY_V2 / JITTER / DLQ_REDRIVE_CONSOLE)`；**`RELAY_V2` 全局唯一开关，不按租户灰度**（同一 Outbox 表不能双策略并存），默认全关。
- **历史数据回填**：存量 `PENDING` 补 `next_attempt_at / attempt_count / partition_key`；**回填不重发任何消息**，只补调度元数据。
- **灰度维度与观测窗**：先影子中继（只观测不投递）→ 单 topic_group → 全量，每级 ≥ 1 周，观测最老年龄 / 毒丸数 / Inbox 去重命中 / drain 时长。
- **回滚触发**：重复投递造成重复副作用、顺序链路乱序、最老年龄 > 10min、`RELAY_V2` 与旧中继同时取件。
- **本卷回滚代价（诚实登记）**：**已投递并被下游消费的事件不可撤回**（§23.5），回滚中继只能防新增；重复副作用须按业务唯一键补偿、`REBUILD` 修投影；已入 DLQ 的消息不因回滚而删除。存量 `bone-app-purchase` 适配层 12 类行为零改写（总体 §12.2）。

**13.7 只读投影与新鲜度（总纲 §16.7 / §19.6）**

- **投影表**：`t_proc_ops_board_projection`（投递看板 / DLQ 分派 / 编排步骤进度 / 对账例外聚合）；**运维判「是否积压」必须回源 `t_proc_outbox` 取最老未发件年龄，禁止用投影行数替代**（§13.1）。
- **更新触发**：中继状态变更 + 定时聚合（不新增事件）；投影只服务展示。
- **staleness 上界**：P99 15s；> 60s 自动读回源并告警 P2。
- **新鲜度证据**：`projection_version` + `last_event_occurred_at` + `relay_as_of` 展示「数据截至」，禁止把投影当权威强一致数据（§23.7）。
- **重建入口**：replay `mode=REBUILD` 默认抑制不可逆副作用（§16.7）；**重建绝不触发真实投递、付款请求或 redrive**，`REDELIVER` 必须显式二次确认。
