## 1. 模块定位与边界

**拥有的业务结果**：把 PO 之后的协同链路（确认 → 发货通知 → 收货 → 自助开票 → 匹配结果回传 → 付款通知）标准化为**可核对的文档链**，并提供供应商侧 B2B 自助入口。

| 在范围内 | **非目标（Non-goals）** |
|----------|------------------------|
| PO Ack / ASN / GR 投影 / InvoiceSubmission / IRException / 对账例外 | ❌ **不裁决发票匹配与付款**（Finance 执行 2-way/3-way + 容差 + 冻结放行，PA-04） |
| 供应商门户：PO 查看、确认、ASN、自助开票、IR 补料、绩效查看 | ❌ 不维护库存/仓库台账（Inventory/Warehouse 经 ACL） |
| 独立前端 + BFF、外部用户隔离、Webhook/HMAC | ❌ 不直连业务库（Separate Ways，总体 §8.1） |
| 门户协同动作落哪个聚合、发什么事件（领域 §4.4） | ❌ 不把 **997 语法回执**当成业务接受（X12 实践，总纲 §13 B3） |

**业界依据（ANSI X12）**：850 PO → 855 行级确认 → 856 ASN（含 SSCC-18 / 包装层级）→ 810 发票；997/999 仅语法层回执，业务接受由买方匹配决定；820 汇款通知闭环；BEG03 + 交易伙伴标识做重传去重；前端校验（item master、UOM、ship-to、价格）在传输前拦截（总纲 §13 B3）。

## 3. 领域模型与不变量

| 聚合根 | 关键实体 | 强一致不变量 |
|--------|----------|--------------|
| `PoAck` | 行级确认结果（接受/改期/拒收） | **INV-01** 幂等 `po_no+po_version` + CAS；**INV-02** 不得确认已关闭 PO |
| `ASN` | `AsnLine`、包装层级、SSCC-18、承运商 | **INV-03** `asn_no` 唯一；**INV-04** 发货行必须引用已确认 PO 行；**INV-05** ASN 数量与后续 GR 差异进例外台账，不静默改写 |
| `GoodsReceipt`（投影） | `gr_no, po_no, line_no, qty, asn_no` | **INV-06** 只追加；权威在 Inventory，本域为最终一致投影 |
| `InvoiceSubmission` | 发票号、税、币种、行、PO 引用 | **INV-07** `(tenant_id,invoice_no,vendor_id)` 去重；**INV-08** 金额须 ≤ PO 未开票余额（本域投影）；**INV-09** 发票只提交，不裁决匹配结果 |
| `IRException` | 例外码、补料、申诉、状态 | **INV-10** 状态由 `InvoiceMatched` 回写，采购域**不可自行放行**；**INV-11** 重复 `exception_code` 幂等 |
| `ReconException` | 通道、差异、处置 | **INV-12** 预付/红冲/部分付款/RTV/汇兑差异**单列台账**，不得并入净额等式（领域 §6.4） |

## 5. 状态机

> **v0.2（总纲 §21.1–§21.3）**：本节状态须落为枚举 + **显式迁移表** `Map<State, Map<Event, Transition>>`，守卫集中在 domain 层；**迁移表未列出即拒绝**（fail-closed），非法迁移返回 §17.2 的 `invalid_transition`（带 `current_state/attempted/allowed[]`）；状态迁移与 `@Version` CAS 同事务；终态不可回写由 domain 守卫 + 唯一约束双保险。本节小写领域事件（如 `supplier.activated`）属**领域内部事件**，不落 Outbox、不进注册表（总纲 §16.1）。

**ASN**：`CREATED → TRANSMITTED → RECEIVING_MATCHED → RECONCILED`；`CANCELLED` 终态。

| From | Event | Guard | To |
|------|-------|-------|----|
| `CREATED` | `transmit` | PO 已 `ACKNOWLEDGED` + 行引用有效 + 包装层级完整 | `TRANSMITTED` |
| `TRANSMITTED` | `goods_received` | `GoodsReceived` 幂等消费 | `RECEIVING_MATCHED` |
| `RECEIVING_MATCHED` | `reconciled` | ASN 与 GR 差异已进例外台账 | `RECONCILED` |

**InvoiceSubmission**：`DRAFT → SUBMITTED → MATCH_PENDING → MATCHED / BLOCKED / REJECTED`。

| From | Event | Guard | To |
|------|-------|-------|----|
| `DRAFT` | `submit` | 发票号唯一 + 金额 ≤ PO 未开票余额 | `SUBMITTED` |
| `SUBMITTED` | `finance_ack`（997 类比：仅语法回执） | 仅标记收到，**不等于业务接受** | `MATCH_PENDING` |
| `MATCH_PENDING` | `invoice_matched` | `InvoiceMatched` 由 Finance 回传 | `MATCHED` / `BLOCKED` |
| `BLOCKED` | `exception_raised` | 生成 IR 例外 + 补料 | `BLOCKED`（补料） |
| `BLOCKED` | `released` | **仅 Finance 放行事件** | `MATCHED` |

**IRException**：`OPEN → SUPPLEMENTED → UNDER_REVIEW → RESOLVED / REJECTED`；`RESOLVED` 只能由 Finance 事件置位。

**禁止迁移**：未确认 PO 直接发 ASN；997 回执直接置 `MATCHED`；采购域把 `BLOCKED` 改为 `MATCHED`；终态回写。

## 6. API 契约

> **v0.2（总纲 §17 / 附录 A）**：错误码以总纲附录 A 为唯一真源（含新增 `317xx` 段）；错误体采用 RFC 9457 `application/problem+json` 并与 HC-003 `ApiResponse<T>` 兼容（§17.2）；大表 / 流水 / 审计 / DLQ 列表用 cursor 分页 + 服务端 `max_page_size`（§17.4）；状态码与可重试性见 §17.3；契约工件 `contracts/openapi.yaml`。

> 门户路径 `/api/v1/portal/...`（外部用户，BFF 转发）；内部履约路径 `/api/v1/procurement/...`。

| 方法 | 路径 | 权限码 | 幂等键 | 说明 |
|------|------|--------|--------|------|
| `GET` | `/api/v1/portal/purchase-orders` | `portal:purchase-order:read` | — | 仅本供应商可见（可见性矩阵） |
| `POST` | `/api/v1/portal/purchase-orders/{no}/ack` | `portal:po-ack:write` | `po_no+po_version` | 行级确认（855 类比） |
| `POST` | `/api/v1/portal/asns` | `portal:asn:write` | `asn_no` | 发货通知（856 类比，含 SSCC） |
| `POST` | `/api/v1/portal/invoices` | `portal:invoice-submission:write` | `invoice_no+supplier_id` | 自助开票（810 类比） |
| `POST` | `/api/v1/portal/ir-exceptions/{no}/supplement` | `portal:ir-exception:write` | `Idempotency-Key` | 例外补料/申诉 |
| `GET` | `/api/v1/portal/performance-scores` | `portal:performance-score:read` | — | 绩效只读投影 |
| `GET` | `/api/v1/portal/payments` | `portal:payment:read` | — | 付款通知（820 类比，只读） |
| `POST` | `/api/v1/procurement/webhooks/finance` | 服务间 scoped credential | `eventId` | **HMAC 验签** + `InvoiceMatched`/`PaymentRecorded` 入站 |
| `POST` | `/api/v1/procurement/ops/reconciliation/run` | `procurement:recon:admin` | `Idempotency-Key` | **复用 06 卷 §6 端点**（日终三通道对账；同一作业不另设路径，见裁决 R8-a） |

请求示例（`POST /portal/asns`）：

```json
{
  "asn_no": "ASN-2026-0917-01",
  "po_no": "PO-2026-0917",
  "ship_date": "2026-11-08",
  "carrier": "SF",
  "tracking_no": "SF1234567890",
  "sscc": ["SSCC-18-0001", "SSCC-18-0002"],
  "lines": [{"po_line_no": 1, "item_id": 50021, "qty": 100, "uom": "EA", "pack_ref": "SSCC-18-0001"}]
}
```

响应 `201`：`{"code":"OK","data":{"asn_no":"ASN-2026-0917-01","status":"CREATED"},"trace_id":"..."}`；未确认 PO → `31503`；ASN 与 GR 不符 → `31501`。

**错误码**（总纲附录 A）：`31001` 匹配数据不完整；`31501` ASN 与 GR 不符、`31502` 发票号重复、`31503` PO 未确认、`31504` 发票超未开票余额、`31505` 采购域越权放行 IR、`31506` 997 回执被当作业务接受。非法迁移 `409 invalid_transition`；越权 `403`；限流 `429` 带 `retry_after`。

## 7. 事件契约

> **v0.2 契约校准（总纲 §16 / 附录 B）**：本表 `eventType` 的 **topic / partition_key / owner / consumers / schemaVersion 一律以总纲附录 B 事件契约注册表为准**，payload 字段**唯一真源 = `contracts/asyncapi.yaml`**；本表仅为字段速查，**不重复定义 topic**（避免双真源）。所有事件已按事件规范 §4「先登记注册表 → 再写 Producer」登记；门禁 **A8** 校验本表 eventType 均在注册表内、且注册表 topic 与 AsyncAPI channel 一一对应。顺序敏感链路 `partition_key = tenant_id + <aggregate_key>`（总纲 §6 双轨）且 payload 带 `aggregate_version` 供乱序丢弃；消费侧为 tolerant reader（§16.5）+ Inbox 幂等（§6），delivery 为 at-least-once。**`INBOUND`** 事件由外部上下文生产、沿用上游冻结 topic（L31 待裁决），采购域只读、不裁决。

| 方向 | eventType（topic / partition_key / owner 见总纲附录 B） | payload 字段速查（真源 `contracts/asyncapi.yaml`） | 幂等 / 顺序 / 失败 |
|------|-------------------|------------------|--------------------|
| 生产 | `PurchaseOrderAcknowledged`（已冻结） | `po_no, po_version, vendor_id, ack_lines[]` | `po_no+po_version`；同 `po_no` 保序 |
| 生产 | `AsnSubmitted`（已冻结） | `asn_no, po_no, ship_date, lines[], sscc[]` | `asn_no` 唯一；投递失败 DLQ |
| 生产 | `InvoiceSubmitted`（已冻结） | `invoice_no, po_no?, supplier_id, invoice_amount, tax_amount?, invoice_date, due_date?, currency`（字段名真源 D3-v2 §2.1；金额一律 Money，Supplier↔Vendor 分离） | `invoice_no+supplier_id` 去重 |
| 生产 | `IrExceptionRaised`（LLD 新增） | `exception_no, invoice_no, exception_code, match_status` | `exception_no`；同 `invoice_no` 保序 |
| 消费 | `GoodsReceived`（**INBOUND** / Inventory ACL，已冻结；依赖跨域 ACL 交付（F-A），未交付前接口预留、运行期不触发） | `gr_no, po_no, po_line_no, received_qty, uom, received_at, site_id, tenant_id, supplier_id?, asn_no?`（字段名真源 D3-v2 §2.1） | `gr_no` 幂等；更新投影 |
| 消费 | `InvoiceMatched`（**INBOUND / Finance ACL**，已冻结；依赖跨域 ACL 交付（F-A），未交付前接口预留、运行期不触发） | `match_id, invoice_no, po_no, match_status(enum MATCHED/EXCEPTION/REVIEW), matched_amount, exception_code?, matched_at`（**字段级真源 D3-v2 §2.1**） | `invoice_no+revision`；**只回写，不裁决** |
| 消费 | `PaymentRecorded`（**INBOUND** / Finance ACL，已冻结；依赖跨域 ACL 交付（F-A），未交付前接口预留、运行期不触发） | `payment_id, invoice_no, paid_amount, payment_date, payment_method?, payer_legal_entity`（**字段级真源 D3-v2 §2.1**） | `payment_id`；对账 + 门户通知 |
| 消费 | `PurchaseOrderCreated`（04 卷） | `po_no, po_version, supplier_id, lines[]`（本域只消费投影子集，字段名真源 D3-v2 §2.1） | 门户 PO 视图投影（最终一致） |

```json
{
  "eventId": "evt-01J...",
  "eventType": "InvoiceMatched",
  "topic": "domain.procurement.invoice_matched.v1",
  "occurredAt": "2026-11-08T12:00:00Z",
  "tenantId": "t-1001",
  "traceId": "tr-...",
  "schemaVersion": "1.0",
  "payload": {
    "match_id": "MATCH-2026-0917",
    "invoice_no": "INV-2026-0917",
    "po_no": "PO-2026-0917",
    "match_status": "EXCEPTION",
    "matched_amount": {"amount": "4250.00", "currency": "CNY"},
    "exception_code": "PRICE_VARIANCE",
    "matched_at": "2026-11-08T12:00:00Z"
  }
}
```

> 采购域收到 `match_status=EXCEPTION` / `REVIEW` 只生成/更新 `IRException` 并通知供应商补料；**放行权在 Finance**（总体 §3.1、PA-04）。事件字段以 D3-v2 §2.1 为唯一真源。

## 9. 工程治理

| 幂等 | Ack `po_no+po_version`、ASN `asn_no`、发票 `invoice_no+supplier_id`、事件 `(consumer_group,event_id)`；X12 重传类比以业务键去重，不以 `eventId` 替代业务键 |

## 13. 本卷专题深化（v0.3）

> **一期状态（R6 / B20，A10 守护）**：T2 / T12（跨单元 Outbox 与分期事件中继）。本章全部规格**保留为设计储备**，触发条件与逐项映射见 [一期边界与机制触发条件.md](../一期边界与机制触发条件.md) §2；不得把本章机制默认解读为「一期必须实现」。

> **定位**：把总纲 §23 八项要素实例化到履约协同与供应商门户；本章**不新增事件 / 错误码 / 权限码**，不动 v0.1 已冻结的「Finance 裁决三单匹配」结论。数值均为草案（L38）。
> **依据**：B16（ANSI X12 850/855/856/810/997/820 与 AP 三单匹配例外运营），总纲 §23.9 → 05 卷。

**13.1 差异化核心算法：X12 字段映射、TDS 校验、例外分类法与门户安全**

1. **链路语义映射**（本设计为 REST + JSON 语义类比，是否接真实 EDI 网关见 L21）：850 = PO 下达 / 855 = PO Ack / 856 = ASN / 810 = 供应商发票 / 997·999 = **语法回执** / 820 = 汇款通知。`997` 到达**只置「语法已确认」，绝不置 `MATCHED`**（M5-7）；**ASN 不是收货凭证**，GR 只由 Warehouse / Inventory 回传的 `GoodsReceived` 投影生成。
2. **`TDS` 校验**：`TDS = Σ IT1 ± SAC`（逐行金额 + 折扣 / 费用调整），**逐行舍入后汇总**（§14）；`|810.TDS − 计算值| > tolerance(category, supplier)` 即拒收并生成例外单（M5-12）；容差按供应商 / 品类配置且变更留痕，**禁止硬编码阈值**。
3. **例外分类法 → owner → 时限 → aging 升级**（具体矩阵与时限由 L43 冻结，下表为结构草案）：

| 例外类型 | 判定信号 | owner | 时限（草案） | aging 分桶与升级 |
|----------|----------|-------|--------------|------------------|
| 价格差异 | 发票单价 ≠ PO 单价且超容差 | 采购 | 2 工作日 | 0–2 / 3–5 / 6–10 / >10 天，逐桶升级至采购经理 → 财务总监 |
| 数量差异 | 发票数量 ≠ GR 数量 | 收货 / Warehouse | 1 工作日 | 同上，超 5 天升级运营负责人 |
| 重复发票 | 同 `vendor_id + invoice_no + 金额` 命中 | AP | 1 工作日 | 立即冻结重复件，>2 天升级内控 |
| 税 / 税率差异 | 税额或税率与 PO 快照不符 | 税务 | 2 工作日 | >5 天升级税务负责人 |
| 容差豁免 | 差额在容差内但需放行 | controller | 3 工作日 | 超期自动回到 `MATCH_PENDING`，**不自动放行** |
| 未匹配到 PO / GR | 关联键缺失 | AP + 采购 | 2 工作日 | >10 天进月结差异台账 |

4. **三通道对账归因**：`SUPPLY`（PO/GR 事实）/ `INVOICE`（发票与例外）/ `PAYMENT`（Finance 回传）三通道各自独立成账；预付 / 红冲 / 部分付款 / RTV / 汇兑损益**单列例外台账**，禁止并入「净额等式」（M5-10）。
5. **门户安全**：附件类型白名单 + 大小上限 + 隔离桶病毒扫描 + 下载审计（M5-13）；外部账号按 `tenant_id × supplier_id × legal_entity_id` 三重隔离，邀请 / 冻结走 IAM（L23）；HMAC 四类注入全拒（M5-8）；**门户任何接口都不得提供发票放行能力**（PA-04）。
6. **失败语义与反例**：Finance 不可用 → 保持 `MATCH_PENDING`，**不降级为推断匹配通过**（M5-11）；反例：把 `997` 当业务接受并置 `MATCHED`，会绕过三单匹配，必须由 M5-7 拦截。

**13.5 上线四闸门与回滚（总纲 §22.1 / 总体 §8.4）**

- **feature flag 粒度**：`tenant_id × supplier_id × flow(PORTAL_V2 / TDS_STRICT / EXCEPTION_ROUTING_V2)`，默认全关；`TDS_STRICT` 单独开关，便于按品类逐步收紧容差。
- **历史数据回填**：存量发票与例外单补 `exception_type / owner / age_bucket / tolerance_version`；**回填不自动改变任何匹配状态**，不触发付款请求。
- **灰度维度与观测窗**：按供应商 5% → 25% → 100%，每级 ≥ 2 个结算周期，观测 `tds_mismatch_total` / 例外 aging / 越权拦截 / 匹配结果 lag。
- **回滚触发**：越权读取 ≥ 1、`TDS` 校验被绕过、匹配结果重复回传、例外被自动关闭。
- **本卷回滚代价（诚实登记）**：**已向供应商展示的匹配状态、已发出的例外通知不可撤回**，只能发更正；已回传 Finance 的发票数据不删改，用红冲 / 更正单补偿（§23.5）；门户附件一旦被合法下载不可「收回」，只能作废对象键。
