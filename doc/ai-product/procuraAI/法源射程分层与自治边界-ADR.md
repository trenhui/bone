# ADR：法源射程分层与自治边界（2026-11-11）

> **版本**：v0.3　**状态**：真源（**Proposal 设计态**，待法务出具主体适用性与场景射程结论后方可转为生效）

## 1. 问题陈述

`D3-v2 §3.3` 第七轮裁决已实证：发改法规〔2026〕195 号文总体目标限定「围绕招标投标交易全过程和管理重点环节」，三（十一）主体为招标人 / 招标代理机构 / 投标人 / 评标专家，故 B-1–B-5 标 `conditionalBiddingScope`，**不覆盖**企业非招标采购的合同审查 / 供应商画像 / 智慧问答 / 发票与履约绩效；《生成式人工智能服务管理暂行办法》第 2 条第三款更明文排除未向境内公众提供服务的企业内部应用（B-13，`excludedByScope`）。

但 `D3-v2 §3` 的「AI 仅辅助 / 人工最终决策 / 自动结案：禁止」仍是**全域不可稀释红线**，`蓝图 §4.3.1` 明确以「195 号文辅助性定位」为由「本族不设 Level 4 式自主执行档」，`总体 §5.1` 的 fail-closed 亦全域适用。结果是：**把「招标 / 评标 / 授标」（法定辅助性定位，必须严守）与「企业内部目录采购 / 协议内补货 / 例行执行」（可有界自治）一刀切锁死在 `ADVISORY_ONLY`**。射程校准只用在法规核对表，没有反哺治理分层。

这不是「要不要放开自动放款」的争论，而是**法源射程与治理档位是否匹配**的逻辑自洽问题：用一个只覆盖招标投标活动的文件，给全域治理做背书，与 §3.3 自己的裁决冲突。

## 2. 决策（两档，按法源射程而非按能力编号切分）

| 档 | 适用场景 | 治理档位 | 法源依据 | 可否有界自治执行 |
|----|----------|----------|----------|------------------|
| **档 A：招标射程内（法定辅助性定位）** | 招标文件检测 / 投标合规自查 / 辅助评标 / 围串标线索 / 授标相关环节（M1 / M3 / M4） | `ADVISORY_ONLY`，**不可稀释** | 195 号文三（十一）「坚持技术的辅助性定位，模型生成的结论不替代招标人、招标代理机构、投标人、评标专家等的自主判断」；`D3-v2 §3.3` B-1–B-5 `conditionalBiddingScope` | **否**。AI 只出线索 / 清单 / 对比摘要，不得授标、不得作准入或违法定性 |
| **档 B：非招标域（企业自主治理）** | 内部目录采购、协议内补货、例行单据流转、文档预处理、结构化抽取、对账线索、供应商画像更新（非招标场景） | 在**预授权白名单 + 金额阈值 + 可回滚 + 全量留痕 + Kill switch** 下允许**有界自治执行动作**；**授标 / 结案 / 放款 / 风险条目终态仍 100% 人工终决** | 企业内部治理契约（`D3-v2 §3`、`总体 §5.1`、`资产登记 §5`）；195 号文**不作本档依据**（射程外） | **仅限动作层**，且须先过 F1–F4 地基层 + 本 ADR 升级审批 |

> **裁决要点**：195 号文既不能给「全域禁止自治」背书（射程外推），也不能给「全域放开自治」背书（它根本不覆盖非招标域）。非招标域的自治边界**由企业自身治理契约与风险偏好决定**，与法定辅助性定位无关。

## 3. 不可稀释红线（两档共同适用，写入本 ADR 即为硬约束）

1. **AI 不碰钱**：金额与税额计算、付款许可、放款、对账裁决一律确定性规则 / 工作流，不接 AI。
2. **授标归人**：任何场景的授标、准入定性、围串标违法定性由人作出，AI 不得出终态结论。
3. **结案归人**：自动结案禁止，`confirmed_by` 为空不得置 `FINALIZED` / `ARCHIVED` / `CLOSED`；`ADR-06` 已撤销，不得复活。
4. **三态 fail-closed**：`ai_available` = AVAILABLE / UNAVAILABLE / UNKNOWN，`UNKNOWN` 不得压成「AI 未参与」；不可用降级 `rules_only`，不得静默放行。
5. **可解释与留痕**：证据不回传 `output` 原文（PII 禁入）、版本溯源、生成内容显式 + 隐式双标识、人工确认人/时间与 override 记录按 `03 卷 §13.6` 留存。
6. **公平护栏**：供应商筛选 / 推荐不得对所有制 / 地域 / 规模产生系统性偏见，命中即 fail-closed 回滚。

> 上述 6 条是 `D3-v2 §3` 与 `资产登记 §5` 既有红线的**重述而非放宽**；本 ADR 不新增任何自动决策许可。

## 5. 升级审批与附加护栏（档 B 才适用）

任一档 B 能力要从「建议态」升到「有界自治执行」，须**全部**满足：① F1–F4 地基层验收通过（`蓝图 §4.2`）；② 能力码已登记 + 自带关键负向用例 + 过 CI blocking；③ 预授权白名单（品类 / 金额 / 法人 / 供应商池）与日护栏（重复单率 / override 率 / 成本）经采购域 TL + 风控 + 平台组会签；④ 全量留痕、可回滚、Kill switch 与定期复评；⑤ **主体适用性与场景射程的法务结论**已出具。缺任一项一律退回 `ADVISORY_ONLY`。

## 6. 业界校准（说明「为何分层」而非「为何放开」）

Gartner 2026-05-26 主张按自治等级与信任边界**比例化**施加护栏，警告统一治理会导致 agent 项目失败；其四级自治模型（Observe / Advise / Act with Approval / Act Autonomously）是治理分级框架，不是「放开终决权」。已产品化的 Oracle `Autonomous Sourcing Agent`（2026-02 GA，限 low-dollar / high-volume / 按公司政策）、Coupa Navi agents、Levelpath Ranger 有界自治**均保留 human final award decision**——即「授标归人、执行可有界自治」，与本 ADR 两档一致。Gartner 2026-05 供应链专场同时明确 agentic AI in procurement 仍 nascent、近期机会是 targeted use cases、须防 agent-washing，故本 ADR **不扩张能力清单**，只为已论证的 G16 等场景解除「用错法源」造成的自我设限。
