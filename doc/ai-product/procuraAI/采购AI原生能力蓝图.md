# 采购 AI 原生能力蓝图（Proposal）

> **版本**：v0.2（2026-11-10，草案，待架构评审冻结；新增 G14/G16 能力卡片与 §5 战略选项 ADR 草案）
> **状态**：**Proposal（设计提案，不进冻结，不在本期实现范围）**
> **上游**：`procuraAI-方案逻辑自洽与AI原生诊断-2026-11-09.md` §4（G1–G10 缺口）+ 本报告 §4.1（编排层）
> **治理铁律**：本蓝图所有新增 AI 能力**必须同样受 `D3-v2 §3` 约束**（三态 `ai_available`、fail-closed、人工终决、PII 禁入、评测集回归、证据不回传 output、版本溯源）。未经 D3-v2 冻结的能力码（C-F）不得标「① 复用 S」。
> **定位**：把当前「点状挂载」的 AI（仅 02 评标 / 03 审查）升级为「AI 原生」——AI 作为贯穿采购全链路的**一等公民能力**。本文是能力地图与编排骨架，**不是模块详设**，落地需逐能力立项、过评测集、owner 排期。

---

## 1. 为什么需要「AI 原生」而不是「加几个 AI 功能」

诊断确认：当前 AI 仅挂在 02（评标辅助 M1/M4）、03（审查/起草/问答/抽取/风控/绩效 M2/M5/M7）两卷，且严格限定在「人工决策前的辅助位」。**01 主数据 / 04 交易 / 05 履约 / 06 编排 四个模块完全没有 AI 设计**，M10 是独立 runtime，各模块各自接散点端口。

业界共识（Ariba / Coupa / SAP Ariba Category Management / Gartner 采购 AI 成熟度 / 中物联《人工智能+采购供应链应用指南》10 大领域）：AI 原生的价值不在「单点智能」，而在**贯穿源（需求）→ 寻源 → 合同 → 交易 → 履约 → 支付 → 续约**的连续智能与数据飞轮。散点接入会重复造评测集 / 降级 / cost-quota / trace / HITL，**稀释现有合规红线**（D3-v2 §3）。因此本蓝图在 M10 runtime 之上补一层**统一的采购域 AI 编排层**（§3），让 G1–G16 共享治理基座。

| **G16** | 低风险自治采购执行车道（有界自治） | 现全域「人工终决」，连目录内标准请购转 PO 也全靠人工。Gartner 2026 指出自治 AI 代理采购可降本增效，但到 2027 年 40% 企业因治理失败降级/退役自治代理——**对所有代理套用统一治理会导致失败，必须按自治等级分层**。业界模型是 bounded autonomy（有界自治）：自动化例行执行，人保留授标 / 例外 / 谈判 / 承诺支出的责任 | M04 交易 + 编排层 | 预授权规则引擎（非 LLM 决策）+ `AutonomyEscalated` 事件 | P4（须先以 ADR 划定边界，见 §5.2） |

> **阶段说明**：P2 = 紧接本期二期（补齐风险/对账/寻源智能 + G11/G12/G13，复用现有 M10 runtime 与 D3-v2 §3）；P3 = 三期（预测/对话/Copilot，需数据飞轮与前端）；P4 = 远期战略层。**所有阶段的能力立项前必须先把对应能力码登记进 D3-v2 §1.1 映射表并过评测集（参照 §3.2）**。
> **G15 治理前置说明**：G15 不按 P2/P3/P4 排期，它是 G2 / G4 / G5 / M1 / M4 等一切「影响供应商机会」的 AI 能力的**上线准入条件**——能力码登记、评测集偏见用例、公平性复跑与伦理审查缺一，该能力不得上线（fail-closed）。
> **战略选项（P4）**：G14（N-tier + 控制塔）与 G16（低风险自治车道）已形成可评审 ADR 草案（§5），但**不进本期、不自动立项**——须 owner + 监管 / 法务评审边界与阈值后方可启动。

## 3. 统一的采购域 AI 编排层（架构级，必建）

> 不建这层，G1–G10 继续散点接 `procuraai-runtime`，会重复造评测集 / 降级 / cost-quota / trace / HITL，并稀释 D3-v2 §3 红线。

```
                ┌─────────────────────────────────────────────┐
                │   采购域 AI 编排层（Proposal，新增抽象）        │
                │  ── 统一治理基座（D3-v2 §3 的执行面）          │
                │  • 能力注册表（capability registry）          │
                │  • 评测集复跑（每个能力自带评测集 + 关键负向） │
                │  • 降级 rules_only（AI 不可用 → 纯规则）       │
                │  • cost / quota 限额（按能力 + 租户）          │
                │  • trace_id 贯穿 + 证据链（不回传 output）     │
                │  • human_in_loop 路由（建议 → 人工终决）       │
                └───────────────┬─────────────────────────────┘
                                │ 统一端口 ProcurementAiOrchestrationPort
        ┌───────────────┬───────┴────────┬───────────────────┐
        ▼               ▼                ▼                   ▼
   G1-G3 (M01/02/04)  G4-G5 (M05/07)   G6 (Copilot 适配层)  G7-G10 (跨域)
        │               │                │                   │
        └───────────────┴────────────────┴───────────────────┘
                                │
                        ┌───────▼────────┐
                        │ M10 procuraai- │
                        │ runtime（LLM/  │
                        │ RAG/规则/评测） │
                        └────────────────┘
```

**职责边界**：
- 编排层不持有 LLM，只负责**治理与路由**；推理仍在 M10 runtime。
- 每个 Gx 能力在注册表登记：能力码（D3-v2 §1.1）、评测集路径、降级策略、quota、HITL 路由规则。
- 编排层对模块暴露**唯一端口** `ProcurementAiOrchestrationPort`（替代当前 02/03 各自 `AiReviewPort` 散点），模块只看到「建议 + 三态 `ai_available` + 证据引用」。
- **知识图谱基座（G13）** 作为编排层的关系数据底座（供应商网络 / 条款本体 / 品类树 / 法规关联），供 G12 反舞弊、G14 N-tier 透明度、G2 推荐复用；图谱构建与更新走发布流程，禁在线直改（同 RAG 语料纪律）。

## 4. 增量落地阶段（建议）

> **顺序修正（2026-11-10 复诊 P1-⑧ / P2-⑨）**：能力分期表之前必须先建 **§4.2 地基层**（F1–F4，P0 治理前置）；**G10 品类智能分类由 P4 前移为 P2 前置**（原顺序颠倒，它是 G1/G2/G3 的共同输入）。

|------|------|------|----------|

### 4.2 地基层（P0 治理前置，优先于一切 Gx 能力卡片）

| # | 地基层能力 | why（依据） | 可验收动作 | Owner / 估工 | 验收判据 |

| **F1** | 高质量数据集 + 标注治理 + 数据分类分级 | 《指南》§四(二)：高质量数据集与标注规范是模型效果前提。现 19 例 seed 的 `groundTruthRef` 指向**文档锚点**而非源码，无数据飞轮，G1 / G5 / G8 无可训练 / 可验证输入 | ① 采购域数据分级目录（公开 / 内部 / 敏感 / 机密）；② 标注规范 + 双人复核 + 标注者一致性指标；③ 训练 / 验证 / 冻结集三分离（冻结集不进训练与提示词调优）；④ override 回流闭环 | 数据 owner + 采购域 TL；**人月待估，须在 WBS 单列，不并入 96 人月** | 数据集版本可追溯、冻结集零污染、标注一致性达 owner 设定阈值；`groundTruthRef` 逐步从文档锚点重定向到源码契约 |

## 5. 战略选项 ADR 草案（G14 / G16，待评审，不进本期）

> 本节是 **Proposal 设计态的可评审草案**，不是已冻结决策。两条 ADR 均标注「待 owner + 监管/法务确认」的决策点；在决策点闭合前，**不得立项、不得实现、不得稀释 D3-v2 §3 治理铁律**。业界对标来源见 §5.3。

### 5.1 ADR-G14：多层级（N-tier）供应商透明度 + 采购控制塔

- **决策（待定）**：是否在 P4 建设采购域统一控制塔，并将供应商可视性从 tier-1 扩展到 N-tier（至少 sub-tier）。当前状态：**仅直达供应商快照，无控制塔，无 N-tier**。
- **上下文**：静态供应商计分卡滞后于快速变化的风险与绩效信号，领先实践已转向实时、预测性的「活控制系统」[cite:g14-1]；McKinsey 预测到 2030 年采购将拥有覆盖 sub-tier 原材料供应商 → tier-1 → 内部制造 → 客户 → 物流渠道的供应链数字孪生 [cite:g14-2]；Gartner 预测到 2029 年 40% 组织需实现第三级供应商可视性 [cite:g14-3]。EUDR / CBAM 要求追溯原材料来源与毁林/排放，N-tier 盲区是合规硬风险。
- **能力边界（控制塔 = 统一只读视图 + 异常管理 + 场景分析，不持写入权）**：
  - 统一实时视图：支出 / 供应商绩效 / 风险 / 在途 / 合同状态一屏聚合（取代各模块散点报表）
  - 异常管理：阈值突破 / 中断信号 / 绩效劣化自动预警与工单派发（复用现有 `RiskAlertRaised` 事件，不新增并行告警通道）
  - 场景分析 / what-if：模拟「某 sub-tier 中断」对 tier-1 交付与库存的影响，推荐替代来源
  - N-tier 透明度：sub-tier 供应商画像、上下游关系、风险传导（依赖 G13 知识图谱的供应商网络关系）
- **不做的事（边界）**：控制塔是**只读视图 + 预警**，不直接下推采购动作；不替代各模块的领域写入；N-tier 数据来源受供应商协作意愿与外部数据合规约束，不强制采集。
- **依赖与前置**：
  - G13 知识图谱（供应商网络 / sub-tier 关系底座，P2 前置）
  - 外部数据源接入（第三方风险数据 / 供应商协作平台 / 在途可视性数据）——**外部数据合规与采购成本属 owner 边界**
  - 与 Inventory / 物流域的跨域只读端口（F-A 同类跨域 ACL 前置）
  - M01 `vendor_profile` 从快照升级为动态（与 G5 风险画像协同）
- **待 owner + 监管决策点**：① 是否建设控制塔（P4 优先级 vs 其他 P4 项）；② N-tier 数据采集的合规边界（是否触及供应商商业秘密 / 数据出境）；③ 外部数据源采购预算。
- **验收基线（若立项）**：控制塔首屏覆盖支出 + 风险 + 在途 + 合同 4 类指标；至少 1 个 sub-tier 风险传导 demo 端到端跑通；异常预警 100% 走 `RiskAlertRaised` 单一通道（不造并行告警）。

### 5.2 ADR-G16：低风险自治采购执行车道（有界自治 bounded autonomy）

- **决策（待定）**：是否在 P4 开放「低风险、预授权边界内」的采购执行自动化（自治车道）。当前状态：**全域人工终决，无自治车道**。
- **上下文**：Gartner 指出自治 AI 代理采购可降本增效、获得运营优势，但**强治理至关重要** [cite:g16-1]；更关键的是，Gartner 2026-05 警告：到 2027 年 **40% 企业将因治理失败降级或退役自治 AI 代理**，且「对所有代理套用统一治理会导致失败」——治理必须按自治等级分层 [cite:g16-2]。业界成熟模型是 **bounded autonomy（有界自治）**：自动化例行执行，人保留授标 / 例外 / 谈判 / 承诺支出的责任 [cite:g16-3]。
- **与 D3-v2 §3 的兼容性声明（关键，不得稀释红线）**：
  - G16 自治的是**执行动作**（如目录内请购→PO、框架协议内补货、标准续约发起），**不是风险结论终态**；不触发 D3-v2 §3「自动结案：禁止」条款（风险结案仍须 `confirmed_by` 人工）。
  - G16 不授权 AI 授标 / 评标 / 合同审查 / 付款指令（资金状态机仍走 Finance 防腐层）。
  - 自治路径仍走三态 `ai_available` + fail-closed + 全量审计留痕；AI 不可用时降级纯规则或转人工。
  - **决策权仍在人**：人在策略层定义自治边界（白名单 + 阈值），人处理所有越界与异常。这与「AI 仅辅助、人工最终决策」的精神兼容——AI 是在人预授权的规则边界内执行，不是替人决策。
- **自治边界（白名单制，默认不自治；四重 AND 条件全部满足才放行）**：
  1. **任务类型白名单**：仅限低风险执行类（目录内 / 框架协议内请购转 PO、协议内补货、标准续约**发起**）；排除授标、评标、合同审查、风险结案、付款指令
  2. **金额阈值**：单笔 ≤ owner 设定阈值（阈值具体值待 owner 定，本文不写死）；超限一律转人工
  3. **品类白名单**：仅限品类经理明确放行的品类
  4. **供应商白名单**：仅限已验证合格供应商池（复用 M01 准入结果）
  > 任一条件不满足 → fail-closed → 转人工 HITL，不得降级放行。
- **治理护栏（四层控制，业界对标 [cite:g16-4]）**：
  1. 硬自治边界（上述四重白名单，规则引擎强制，非 LLM 自由裁量）
  2. 金额阈值强制升级（超阈值必经人工审批）
  3. 未明确放行的一律人工审批（默认 fail-closed，品类经理主动清单项才能自治）
  4. 全量审计可追溯（每笔自治决策可重构：输入 / 命中规则 / 版本 / 时间 / 结果），留存期对齐 03 卷 §13.6
- **渐进扩边纪律（业界对标 [cite:g16-5]）**：先单一场景（如一个品类 + 一个供应商集）试点，设日护栏指标——重复单率、人工 override 率（阈值待 owner 定）；任一指标超限 → **立即暂停自治 + 审计 + 调参**；连续稳定 N 天后再扩下一个品类 / 供应商集；**反对一次性全域放开**。
- **Kill switch**：全局一键关闭自治开关，回退全人工；开关状态进审计。
- **不做的事（边界）**：自治不涉及支出承诺的最终审批（超阈值 / 白名单外仍人工）；不自动结案、不得触发已撤销的 ADR-06 自动归档路径；LLM 不参与自治放行决策（自治靠预授权规则引擎，LLM 仅可生成建议，不做放行终判）。
- **依赖与前置**：
  - §5.2 ADR 经 owner + 监管 / 法务评审通过（阈值、白名单、适用性）
  - 预授权规则引擎（可基于现有规则引擎扩展，不新建独立库）
  - `AutonomyEscalated` 越界升级事件登记进 D3-v2 / 附录 B
  - 全量审计留痕对接统一审计 schema
- **待 owner + 监管决策点**：① 是否开放自治车道（受监管行业可能禁止）；② 金额阈值、品类白名单、供应商白名单的具体值；③ 日护栏指标阈值与扩边节奏；④ 法务确认自治执行的合规责任归属。
- **验收基线（若立项）**：单一场景试点连续 N 天日护栏不超限；越界 100% 升级人工（无遗漏）；Kill switch 端到端验证；全量审计可重构每笔决策。
