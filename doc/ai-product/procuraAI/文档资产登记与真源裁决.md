## 1. 为什么需要这一层

本目录同时存在两代方案：2026-10 的 `采购AI-*` POC 族（9 份 md + 5 张 SVG，已到 POC 实现依据）与 2026-11 的 Procura SRM/PMS 架构族（3 份真源 + README + 7 卷 LLD + 契约工件 + 4 张 SVG）。二者对「AI 能否自动结案」「字段是否已冻结」「procuraAI 是子模块还是独立产品」「部署范式」给出过互斥答案。**在没有资产状态登记之前，任何新真源都会被旧族反向污染**（诊断 P0-1/2/3/6 的总根源）。

本文档不删除、不重写历史资产，只做**状态裁决 + 可执行裁决链**。

## 4. 冲突裁决链（可执行，无自指环）

### 4.1 计数口径统一

诊断 P0-5 指出「四份 / 5 类 / 3 份」三处计数不一致。本文统一为：

> **三份域内真源**（领域 / 技术架构 / 框架能力实证） + **一份治理真源**（本文） = **四份文档**；
> 另有 **平台约束真源**（`doc/architecture/` 下的 DDD 方案、事件规范、workflow README）与 **AI 契约真源**（D3-v2），二者是**外部/专项真源**，不计入「四份」。
> `门禁:SOURCE_DOCS` 的 3 份是「A1 版本头校验范围」，是**实现范围**不是**真源总数**，二者语义不同，不再混用「四份」表述。

### 4.2 裁决优先级（自上而下，命中即止）

| 序 | 冲突类型 | 裁决者 | 回改对象 |
|----|----------|--------|----------|
| 1 | 资产状态 / 文档是否已作废 | 本文 §3 | 引用方 |
| 2 | 平台规范条文（CORE/HC/E、事件信封/幂等/DLQ） | `doc/architecture/` 平台约束真源 | 域内文档 |
| 3 | 平台能力「是否真的已实现」 | 能力基线的 `file:line` 源码实证 | 任何自述（含平台 README） |
| 4 | 领域语义（聚合 / 状态机 / 事件语义 / 边界） | `采购领域架构设计方案.md` | 技术文档与 LLD |
| 5 | 技术约束 / 部署 / NFR / 事件 payload / WBS | `采购总体架构方案.md` §7.1 | LLD 与工件 |
| 6 | AI 子能力契约（端点 / payload / 合规 / 错误码映射） | `采购AI-接口契约与数据字典-v2.md` | 03 卷与 AI 接入层 |
| 7 | 实现级概念（表 / 字段 / 端点 / 事件注册表） | `detailed-design/00-总纲与统一约定.md` 附录 A–F | 各卷与契约工件；**冻结后回填上游** |
| 8 | 事件契约工件 | **总纲附录 B 是生成源（唯一真源）**；`asyncapi.yaml` 是**派生物** | 冲突时回改**工件或消费方**，重跑 `generate_asyncapi.py`；**禁止反向改附录 B 以迁就工件** |

> **第 8 条拆解了诊断 P0-5 的「文档 → 工件 → 文档」自指环**：派生物不再高于生成源。A8 的零漂移判据因此是「工件是否忠实于真源」，而非「真源是否忠实于工件」。
>
> **第 5 条取代诊断 P0-3 的「下游反向改上游」**：`总体 §12.1` 原写「给 D3 补关联说明 / 新增 31xxx 段」，本轮改写为**适配层映射表**（D3-v2 §1/§4），不再在下游文档里修改上游契约。

### 4.3 新增概念的流程

新增事件 → 先改总纲附录 B → 重跑生成器 → A8/A10 校验 → 才写 Producer（事件规范 §4）。
新增错误码 / 权限码 → 先改总纲附录 A / C 与 `openapi.yaml` catalog → A8 校验 → 才写业务代码。
新增端点 → 先改各卷 §6 与 `openapi.yaml`（含 Path Item 级 `parameters`）→ **A10.9 双向覆盖校验** → 才写 Controller；仅跨域只读投影端点可不在六卷 §6 出现，但须登记进门禁 `EXTRA_OPENAPI_ENDPOINTS` 白名单。

> **R8-a 端点裁决（2026-11-09）**：`05 卷 §6` 原 `/procurement/reconciliation/run` 与 `06 卷 §6` `/procurement/ops/reconciliation/run` 指向同一日终对账作业、同一权限码 `procurement:recon:admin`，判为跨卷重复而非两个端点。按 `06 卷 §6`「内部运维端点」的分工，统一收敛到 ops 路径，`05 卷 §6` 改为显式复用；`openapi.yaml` 不新增第二个端点，裁决写入 `x-endpoint-adjudication`。**R8-b**：字面量 `/procurement/webhooks/finance` 与模板 `/procurement/webhooks/{system}` 并存，路由字面量优先、模板承接其余系统，共用 HMAC + Inbox 幂等，不判重复。
