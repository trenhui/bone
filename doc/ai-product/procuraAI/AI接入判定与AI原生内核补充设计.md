## 1. AI 接入判定准则

四条**同时满足**才接 AI；任一不满足即回退纯规则 / 工作流 / 状态机：

| # | 判据 | 反例（不满足即不接） |
|---|------|----------------------|
| ① | 输入是自然语言 / 非结构化文档或高维模式，规则无法穷举 | 结构化金额字段、固定枚举状态 |
| ② | 输出是**建议 / 摘要 / 线索 / 草稿**，不是资金、授标或终态结论 | 付款指令、授标决定、`FINALIZED` |
| ③ | 有可构造的 ground truth、可写负向用例、可字段级评测 | 无标注、无通过线的主观判断 |
| ④ | 失败能 fail-closed 到纯规则或人工，**不阻断业务主链路** | AI 不可用即主链路停摆 |

**明确不接 AI**（用确定性规则 / 工作流 / 状态机）：

| 环节 | 替代机制 |
|------|----------|
| 金额与税额计算 | 确定性算术 + Money 类型校验 |
| 状态机迁移 | 迁移表 guard（`总纲 §21.1`「迁移表未列出即拒绝」） |
| 三单匹配裁决 | 规则容差 + 三通道台账 |
| 付款许可 | Finance 防腐层 / 资金状态机 |
| 幂等与对账 | 幂等键 + 确定性重放 |
| 授标 / 准入定性 | 人工终决 + 三方会签 |
| 围串标违法定性 | 监管侧职责，企业侧只出线索（G12） |

> **「AI 不碰钱」是本族合规基线**：与 `采购AI-接口契约与数据字典-v2.md §3`「AI 仅辅助 / 人工最终决策 / 自动结案：禁止」、`采购领域架构设计方案.md §2.1` Finance 裁决边界一致。旧 ADR-06「低风险自动归档」**已撤销、禁止复活**（`文档资产登记与真源裁决.md §5`），本文件任何条款不得把它作为有效决策。

### 1.1 四条件与现行真源的对应

| 条件 | 真源锚点 | 不满足时的处置 |
|------|----------|----------------|
| ① 非结构化输入 | `D3-v2 §1.1` 八码均为文档 / 文本 / 信号输入 | 落 `detailed-design/04-采购交易与成本模块详细设计.md` 确定性规则 |
| ② 建议态输出 | `D3-v2 §3.2` E-2 结果枚举（无 `AUTO` 档）、`蓝图 §4.3.1` T1 `ADVISORY_ONLY` | 不得进入付款 / 授标 / 状态迁移链路 |
| ③ 可评测 | `check_procura_evalset.py` A14 / A17（能力码 ↔ 用例双向覆盖、每码 ≥1 正 + 1 负） | 无 ground truth 的能力一律不立项 |
| ④ fail-closed | `D3-v2 §3` 三态 / 降级 `rules_only` / `总体 §5.1` | AI 不可用切纯规则，主链路不停 |

> 判定顺序：先过「不接 AI」清单，再逐条核四条件；任一档能力升级（C→B→A 反向）都须重新过本表，**不得因模型效果提升而跳过 ②/④**。

## 4. AI 原生内核 N1–N8

> 证据均为 `诊断 §5` 已核实的 `file:line` 转引。简称：`蓝图`=`采购AI原生能力蓝图.md`、`06 卷`=`detailed-design/06-编排事件与平台接入详细设计.md`、`03 卷`=`detailed-design/03-合同风险绩效与AI模块详细设计.md`、`总体`=`采购总体架构方案.md`、`领域`=`采购领域架构设计方案.md`、`技术方案`=旧族受限引用 `采购AI-智能风险审查与合同智能处理-技术方案.md`。每项六要素：缺口证据 / 结构性判定 / 业界依据 / 最小可验收动作 / 契约落点 / 优先级与前置。

### 4.1 N1 Intake Orchestration（最大结构性缺口）

- **缺口证据**：`蓝图:13`「当前 AI 仅挂在 02 评标 / 03 审查…01/04/05/06 完全没有 AI 设计」；`Guided Buying` 只是 `领域:126` 一句说明、`总体:89` 一个流程节点；G6 Copilot 排 P3（`诊断 §5` N1）。
- **结构性判定**：这是「AI 从哪进系统」的入口问题，不是再加一张能力卡片——现有 Gx 全挂既有模块，缺统一自然语言入口；加 G17 只会放大 WBS 死锁。
- **业界依据**：IDC MarketScape **#US54663526 (2026-07)** 把 **AI-Enabled Spend Orchestration** 立为独立评估品类；Zip / Levelpath / SAP / Oracle 的 **AI front door + guided buying** 把「填单」变「说需求」。
- **最小可验收动作**：定义 `ProcurementIntakePort`：自然语言 / 邮件 / 表单统一入口 → 结构化请购意图 + 引用政策条款 + 置信度 + 人工确认点；带「**政策冲突不自动生成 PR**」负向用例（用例 id **待登记**，以 evalset 登记为准）。
- **契约落点**：端口 `ProcurementIntakePort`（新端口，登记口径以 D3-v2 §1.1 为准）；能力码 **待登记**；评测集负向 **待登记**；门禁 **待登记**（见 §5）。
- **优先级与前置**：第 4 位（N1+N2）；前置 F1 数据分级、§3 统一端口裁决。

### 4.2 N2 可执行 agent 运行时 + MCP/A2A

- **缺口证据**：`蓝图:78`「编排层不持有 LLM，只负责治理与路由」；`06 卷:189` 统一端口「一期不实现、仅占位」；`S7`（`蓝图:122`）agentId / 最小权限 / auditRef 仅草案一行；新族真源零 MCP/A2A 落点（`诊断 §5` N2）。
- **结构性判定**：缺的是运行时形态（生命周期 / 检查点 / 工具治理），不是能力数量；只读互操作是治理边界，不是功能卡片。
- **业界依据**：Coupa Navi Connect MCP / Levelpath MCP / Oracle AI Agent Studio / Ivalua MCP 为**业界产品化动向**（标注为动向，不虚构具体数字）；agent registry / 长时任务与中断恢复 / 多 agent 协作是 2026 新标配。
- **最小可验收动作**：编排层补 **agent 生命周期状态机 + 工具白名单 + 任务检查点**；`ProcurementAiOrchestrationPort` 升为契约真源（§3）；MCP/A2A **只读工具先行**（权限继承 + 全量审计），不开放写工具。
- **契约落点**：端口 `ProcurementAiOrchestrationPort`；能力码 `ORCHESTRATION`（D3-v2 §1.1 真实登记）；agent 状态机 / 工具白名单契约 **待登记**；门禁 **待登记**。
- **优先级与前置**：第 4 位（N1+N2）；前置 §3 端口裁决、F3 kill switch 扩到全域。

### 4.3 N3 数据飞轮闭环

- **缺口证据**：`03 卷 §13.1:302` override 回流、`:303` 固定集复跑、`:315` 评测集增补、M3-12 发布阻断、`§13.5` 灰度「每一点都有，但没有连成带 owner/SLA/版本的状态机」；`evalset:874` `scalePlan.status=notStarted`（`诊断 §5` N3）。
- **结构性判定**：散点已齐全，缺的是编排与可验收状态机；这是 F1/F2 永不验收的根因，不是能力缺失。
- **业界依据**：`蓝图 §4.2` F1/F2 地基层 + Gartner 2026 Decision Governance（`诊断 §6` P2）。
- **最小可验收动作**：把 override 回流 → 重标 → **冻结集** → 模型 / 提示词升版 → 固定集复跑（M3-12）→ 灰度 → 自动回滚串成带 **owner / SLA / 版本**的状态机；冻结集与训练 / 提示词调优隔离可校验；「**升版未复跑**」注入必红。
- **契约落点**：`M3-12` 发布阻断（真实编号）；`check_procura_evalset.py` A15 `scalePlan` / A17 正负用例；冻结集隔离判据 **待登记**（见 §5）。
- **优先级与前置**：第 2 位（N3+N7）；前置 F1/F2 立项。

### 4.4 N4 不可信输入隔离（提示注入）

- **缺口证据**：**诊断时点（2026-11-11 上午）**：旧族 `技术方案 §6.3.1:677-690` 已有 OWASP **LLM01/02/07** + ASI 2026（GoalTheft / RecursiveHijacking / ToolOrchestrationAbuse）防御，但按 `文档资产登记与真源裁决.md §3.2` 属**受限引用**；新族 AI 契约真源 `D3-v2 §3` 当时**无注入防御条款**、25 例评测集 **0 条注入 / 越狱用例**（唯一相关 `ANOMALY-02` 属摄入层标注管控，非推理期防护）（`诊断 §5` N4）。**本轮已闭合**：`D3-v2 §3` 增「不可信输入隔离」条款、评测集增 `PROMPT-INJ-01/02`、门禁增 A18 + A10.23；下文按落地后口径描述。
- **结构性判定**：合同 / 投标文件 / 发票是**攻击者可控的不受信任输入**；间接注入可让 AI 忽略风险条款，是高后果攻击面。这是「把旧族防御**升进新族真源链 + 评测集 + CI**」的治理动作，不是补一张能力卡片。
- **业界依据**：OWASP LLM01/02/07 + ASI 2026 防御（旧族 `技术方案 §6.3.1`，受限引用升进真源）。
- **最小可验收动作**：D3-v2 §3 增「不可信输入隔离 / 工具最小权限 / 系统提示保护」条款；登记能力码与 **≥1 正 + 1 负**用例（隐藏指令让 AI 把 `FORBIDDEN` 条款判为无风险 → 必红；用例 id = `PROMPT-INJ-01` 负向 / `PROMPT-INJ-02` 正向）；接 CI blocking；**区分两层**：「摄入层拒收污染样本」（`ANOMALY-02` / D3-v2 §3.2 E-3）与「**推理期防御**」（本项新增）互不替代。
- **契约落点（已落地）**：`D3-v2 §3` 已增「不可信输入隔离」条款；能力码挂 `ORCHESTRATION`（`D3-v2 §1.1` 真实登记，不新增 Mxx 码以免破坏 A10.18 分层集合）；评测集已增 `PROMPT-INJ-01/02` 并纳入 `CRITICAL_NEGATIVE_IDS`；门禁 `check_procura_evalset.py` **A18**（1 正 + 1 负 + 检出期望 + 2 条注入反证）与 `check_procura_alignment.py` **A10.23**（D3-v2 §3 条款不可删）。
- **优先级与前置**：**第 1 位（合规硬前置）**；前置无，先于一切 Gx。

### 4.5 N5 IDP 质量契约

- **缺口证据**：`技术方案:175` 有 PaddleOCR + 版面分析并诚实标注「识别准确率无官方统一口径」，但**新族真源没有** IDP 质量指标（版面还原率 / 跨页表格 / 印章签章 / 手写 / 扫描退化）、无「解析失败 → 人工」fail-closed 分级，OCR 置信度未传进 `ContractReviewed` evidence 链（`诊断 §5` N5）。
- **结构性判定**：**AI 审查 recall 上限由解析质量决定**，解析错误在下游不可见；这是输入质量契约，不是审查能力卡片。
- **业界依据**：`领域 §2.2.2` 证照 / 发票结构化；`技术方案:175`（受限引用，仅作技术背景）。
- **最小可验收动作**：定义 `DocumentParsingQuality` 契约（版面还原率 / 跨页表格 / 印章签章 / 手写 / 扫描退化 / **字段级置信度随快照落库**）、低置信转人工阈值、跨页条款关联负向用例；纳入 `03 卷 §13.3` 告警。
- **契约落点**：`DocumentParsingQuality` 契约字段 / 阈值 **待登记**（阈值属 owner，见 §6）；`ContractReviewed` evidence（D3-v2 §2 真实）；`03 卷 §13.3` 告警；评测集跨页负向 **待登记**；门禁 **待登记**。
- **优先级与前置**：第 5 位；前置 N4（摄入层隔离）、F1 数据分级。

### 4.6 N6 Human-AI 确认工作台（ROI 的真正解法）

- **缺口证据**：`商业化:286` B≈A×(0.2~0.3)、`:56,274,326` 人工降 80%+；但 `资产登记:114,116` 已撤销 ADR-06、`PRD:253` 改「人工确认后归档」、`D3-v2:183-184` 全量人工终决；`技术方案:334`「人工处理时长不计入 P95」、`POC:50` 基线只测 5 份、`POC:72` 采纳率 ≥60% 意味着 ≤40% 需返工；`原型交互设计` 已归档、`05 卷` 承接门户业务而非 AI 确认工作台（`诊断 §5` N6 / `§3.1` P0-D）。
- **结构性判定**：100% 人工终决下「**人如何仍比原来快**」才是 ROI 的真正解法；没有确认工作台，人工终决会吃掉全部 AI 提速。这是交互与可观测契约，不是模型能力。
- **业界依据**：`诊断 §3.3` 三段时间分离（`T_machine` / `T_human_confirm` / `T_e2e`）；CLM 真实提效来自确认工作台而非模型本身。
- **最小可验收动作**：逐条采纳 / 驳回、批量确认、原文锚点一键定位、置信度校准、**结论条数上限**；把「单条确认耗时」「批量采纳率」「`T_human_confirm`」列为可观测指标；A/B 用**同批样本 + 同职级法务**测「收到文件 → 签发结论」全流程。
- **契约落点**：确认工作台规格 **待登记**；指标口径挂 `诊断 §3.3` 三段时间；门禁落点 **待登记**（见 §5）。
- **优先级与前置**：第 3 位；前置 N3 飞轮（采纳 / 驳回数据回流）。

### 4.7 N7 LLM 可观测与成本治理

- **缺口证据**：`总体 §5.1` 只有「Token 成本按租户 / 场景配额与限流」一句、`蓝图:59` 只列 `cost/quota` 一项；缺按「能力 × 租户 × 模型」的 token / latency / cost 归因、语义缓存、模型降级链、灰度流量比、跨 trace span、成本异常告警（`诊断 §5` N7）。

- **业界依据**：`蓝图 §3` 统一治理基座（cost / quota / trace_id）；`总体 §5.1` 配额条款。
- **最小可验收动作**：每笔 AI 调用落 `capabilityCode / model_version / prompt_version / token_in_out / cost / trace_id`；按能力 × 租户 × 模型出**日成本与 P95**；语义缓存、模型降级链、灰度流量比、跨「业务→AI→事件」trace span；「**cost 超配额未降级**」注入必红。
- **契约落点**：调用日志字段契约 **待登记**；能力码 `ORCHESTRATION`（归因维度含各 Gx 码）；门禁「cost 超配额未降级」注入 **待登记**（见 §5）。
- **优先级与前置**：第 2 位（N3+N7）；前置 §3 统一端口（trace 贯穿）。
