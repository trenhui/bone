# 平台能力共建 RFC：统一待办聚合与跨域接入契约

> **RFC 编号**：PLAT-RFC-001　|　**版本**：v0.3（2026-11-09）　|　**状态**：**Proposed（待平台组评审）**
> **Owner（待填）**：平台组 ____________　|　**共建方（待填）**：采购域 TL ____________、财务域 ____________
> **定位**：把 `能力基线 §4.4` 已冻结的「统一待办聚合 schema + 接入规范 + 负向用例」从一段设计说明提升为**独立的平台契约**，使「复用 / 共建」可被答辩为「定义了平台契约并推动跨领域复用」。
> **依据**：诊断 P1-12 / 建议 R9；JD 职责 6「建设 Workflow / Task Center / Audit 等通用平台能力，并推动跨领域复用」。
> **门禁**：`tools/check_procura_alignment.py` **A10**（RFC 存在 / schema 六要素 / 跨域接入清单 / 待办 owner 字段）。

---

## 1. 问题陈述与决策边界

BONE 已有 `bone-workflow-engine`（退回/改派/转办/加签/抄送均已实现，源码实证见 `能力基线 §2`），但**统一任务中心 = D 态（仅规范承诺）**、审计总线 = **N 态（不存在）**、通用 Outbox starter = **N 态**。

`能力基线 §4.4/§9.2` 的决策是「**不自建第二套引擎 / 任务中心 / 审计总线**，缺口回灌平台」。**这是正确的架构决策**（避免重复造轮子、符合 Clean Core 与 golden path），本 RFC 不推翻它；但从 JD 答辩角度，「复用/共建排三期」无法回答「你建了什么、推动了哪几个域复用」。本 RFC 的作用是把**共建的产出物契约化、署名化、可验证化**。

| 不做 | 做 |
|------|-----|
| 不新建第二套工作流引擎 | 定义**统一待办聚合 schema**（跨域唯一契约） |
| 不新建独立任务中心服务 | 定义**接入规范 + 负向用例**，任何域按契约接入 |
| 不新建审计总线 | 定义**审计事件最小字段集**，复用现有 IAM 审计落库 |
| 不把 D/N 态写成「已复用」 | 逐项标 S/D/N 与接入排期（诚实标注） |

## 2. 统一待办聚合 schema（平台契约，六要素）

任何域接入任务中心，须提供下列字段；平台侧负责聚合、分页、权限过滤与状态回写，**不解析业务 payload**。

| # | 字段 | 类型 | 约束 | 来源 |
|---|------|------|------|------|
| 1 | `task_id` | string | 全局唯一，`<domain>:<biz_type>:<ulid>` | 接入域生成 |
| 2 | `tenant_id` / `legal_entity_id` / `org_id` | string ×3 | 三维隔离谓词，缺一即拒绝（对应 `总体 §8.5`） | 接入域 |
| 3 | `assignee_ref` / `candidate_groups[]` | string / array | 与 IAM 主体/组对齐；**不得内嵌业务角色名** | 接入域 |
| 4 | `biz_type` / `biz_key` / `biz_state` | string ×3 | `biz_state` 只作展示，**真实状态以业务域聚合为准**（单向投影） | 接入域 |
| 5 | `sla_due_at` / `priority` / `created_at` | UTC / enum / UTC | 时间统一 UTC ISO-8601（`总纲 §14`）；`priority` 枚举白名单 | 接入域 |
| 6 | `trace_id` / `source_event_id` | string ×2 | 全链路追踪 + 幂等；重复 `source_event_id` 必须幂等 | 接入域 / 平台 |

**平台侧保证**：① 聚合查询按租户/法人/组织强制过滤；② cursor/keyset 分页，禁止精确 `COUNT(*)`（`总纲 §17.4`）；③ `t_platform_processed_event` 幂等；④ 任务动作（改派/转办/加签/抄送/退回）经 `WorkflowStatusPort` 回写业务域，**不直接改业务表**。

**接入域保证**：① 不向任务中心写业务结论；② 状态变更由业务域发事件，任务中心只消费投影；③ 不得绕过 IAM 自建权限判定。

## 3. 接入规范与负向用例

| 步骤 | 动作 | 验收 |
|------|------|------|
| S1 | 接入域提交 `biz_type` 注册表项 + schema 样例 | 平台评审，六要素齐全 |
| S2 | 实现 `TaskCenterPort` 适配器（只读投影 + 动作回写） | 契约测试通过 |
| S3 | 跑负向用例集（下表） | 全部转红后还原必绿 |
| S4 | 灰度 1 个业务域 → 观察 2 周 → 扩域 | 跨域接入清单更新 |

| # | 负向注入 | 期望 |
|---|----------|------|
| PT-1 | 缺 `legal_entity_id` 的待办写入 | 拒绝 + 具名错误（越权防护） |
| PT-2 | 同一 `source_event_id` 重复上报 | 只生成 1 条待办（幂等） |
| PT-3 | 平台侧直接改业务域 `biz_state` | 架构守卫拒绝（单向投影） |
| PT-4 | 任务动作回写时无 `trace_id` | 拒绝并告警 |
| PT-5 | 用业务角色名替代 `candidate_groups` | schema 校验失败 |
| PT-6 | 分页用 `COUNT(*)` 精确总数 | 契约测试失败（必须 cursor） |

> 负向用例**方向正确但当前仍是文本规格**（诊断 P1-8「无测试代码」）：本 RFC 不谎称已自动化；S3 要求接入时提交可执行的契约测试代码，否则不予接入。

## 4. 审计事件最小字段集（复用 IAM 审计，不建总线）

`actor, action, resource_type, resource_id, tenant_id, legal_entity_id, org_id, occurred_at(UTC), trace_id, outcome, reason_code`。

- 落库复用平台 IAM 审计表（能力基线 S 态能力）；**不新建 `AuditBus`**（该词已被 A4 判废，A10 会扫描 SVG `<text>` 拦截）。
- AI 相关决策另需 `ai_available / model_version_snapshot / confirmed_by`（`D3-v2 §3`），三态 `UNKNOWN` 不得压成「AI 未参与」。

## 5. 跨域接入证据清单（JD「推动跨领域复用」的可验证锚点）

> **诚实状态栏**：以下均为**排期 / 待接入**，不是已完成记录。答辩时必须按此状态陈述，不得写成「已推动 N 个域复用」。

| 域 | 接入内容 | 状态 | 排期 | 证据形式（待产出） |
|----|----------|------|------|--------------------|
| 采购域 | 准入审批 / CAPA / 合同用印待办 | **一期首批（待接入）** | 一期 T0+0~12 周 | 契约测试报告 + 灰度记录 |
| 财务域 | 三单匹配例外 / 付款放行待办 | **待接入** | 二期 | 接入评审纪要 + `TaskCenterPort` 实现 |
| 主数据域 | Golden Record 变更请求双人复核 | **待接入** | 二期 | 同上 |
| 平台自身 | `WorkflowStatusPort` 动作回写回归 | **已具备（S 态）** | — | `能力基线 §2` `file:line` 实证 |

**验收线（R9）**：至少 **1 个非采购域**完成 S1–S4 并提交可执行的契约测试代码，才把「共建」表述升级为「定义了平台契约并推动落地」。在此之前，JD 职责 6 的判定维持「决策合理，但无建设成果证据」。

## 6. 三态与排期（禁止把规范承诺写成已复用）

| 能力 | 三态 | 一期动作 | 实现排期 |
|------|------|----------|----------|
| `bone-workflow-engine` 主干 | **S** 已实现 | 直接复用，不改动 | — |
| 统一待办聚合 schema / 接入规范 | **D** 规范承诺 | **本 RFC 定义契约**（本轮产出） | 一期冻结 schema |
| 统一任务中心实现 | **D** | 不自建，按契约共建 | 三期（`能力基线 §4.4`） |
| 审计最小字段集 | **D** | 本 RFC 定义 | 一期随业务模块落地 |
| 审计总线 / 通用 Outbox starter | **N** 不存在 | **明确不实现**，等平台 D2 立项 | 待决 |

## 7. 待决与署名

- **P-RFC-1**：Owner 署名与跨域共建的排期承诺（需平台组 + 各域 TL 会签）——**本轮不代填**。
- **P-RFC-2**：`t_platform_processed_event` 是新建还是复用平台统一幂等表（并入 `能力基线 §9.2 D3`）。
- **P-RFC-3**：`biz_type` 注册表由谁维护、枚举扩容是否按破坏性变更处理（`总纲 §16.4` 枚举扩容按破坏性）。
- 本 RFC 状态 `Proposed`；评审通过后改 `Accepted` 并回填 §5 证据清单。
