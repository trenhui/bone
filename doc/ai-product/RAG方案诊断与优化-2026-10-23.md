# BONE-AI RAG（bone-ai-rag）方案诊断报告

> **诊断对象**：`bone-ai/bone-ai-rag` 模块源码 + 方案四件套中 RAG 相关断言（详设 §2.6/§3.1、总案 §4.5、接入指南、`bone-init.sql` §12.1 `ai_rag_chunk`）
> **诊断日期**：2026-10-23　**方法**：源码走查实证（grep 消费方 + 装配链追溯 + 测试反推）+ 业界最佳实践对标（Modular RAG / TEI / 混合检索工业界惯例）
> **诊断问题**：RAG 方案质量如何？哪些是名实不符？基于业界最佳实践怎么优化、为什么？

---

## 0. 总体结论（三段论）

1. **域模型与算法内核是真落地**：`RrfFuser`（k=60 加权、末位钳制防溢出）、`Bm25Scorer`（语料统计一次计算 O(N²)→O(N)）、`CosineSimilarity`、引用强制 fail-closed（无 `clauseRef`/非法 span 即丢弃）——全部有实现有单测，DDD 分层干净（domain 无外层依赖，ArchUnit 7 规则全过）。**「无出处不得生成」这条红线在代码里是真的**。
2. **但检索链的关键两环是纸面的**：详设/总案把「向量(bge-m3) + BM25 双路 → RRF → **rerank top-30→top-5**」写成已落地最小全链，实际 **rerank 从未被调用**（`RagApplicationService` 无 `RerankPort` 依赖）、**HTTP 推理客户端零消费方**（`HttpBgeEmbeddingClient`/`HttpBgeRerankClient` 无任何装配代码引用）、**`RagInferenceProperties` 从未注册**（无 `@EnableConfigurationProperties`，配了 `bone.ai.rag.*` 也读不到）。即：生产形态恒为「过渡哈希 + 无精排」，而文档描述的是「bge-m3 + cross-encoder」。
3. **写入侧幂等机制缺一半**：DDL 有 `doc_version`（注释明写「增量更新幂等批键」），实体 `RagChunk` **无该字段**、`of(...)` 无该参数、ingest 不写版本——「文档版本事件 → 失效旧 chunk → 重切重嵌（幂等）」在代码中不存在，重复 ingest 会无限追加重复切片。

**总体判定：算法内核优秀、装配层断链、幂等半成品。属于「差最后一段接线」而非「方向错误」——按业界最佳实践补齐装配与护栏后即可达生产态。**

## 2. 稳健性与可落地性诊断（业界最佳实践对标）

| # | 问题 | 证据 | 业界惯例 / 危害 |
|---|---|---|---|
| S1 | **容量护栏缺失**：`findByTenantAndDocScope` 把租户全部 chunk（含 CSV 向量文本）一次性载入内存，无上限 | `RagApplicationService.java:46`；`ChunkRepository.java:14` | 过渡态（MySQL 全表 + 内存打分）下，租户语料增长即 OOM/GC 抖动/超时。业界：检索必须有扫描上限或索引下推。**绝不能静默截断**——「我以为检了全集」的假设不成立时，引用完整性失真 |
| S2 | **无分数阈值（无依据拒答）**：低分结果照样进 topK 喂生成 | `RagQuery(query, docScope, topK)` 无 minScore | 业界混合检索标配 top-k + score-threshold 双闸；无阈值时弱相关切片会被生成器「硬凑」成答案，正是「无出处不得生成」想防的场景 |
| S3 | **provider 故障无降级**：嵌入服务挂 ⇒ 整个检索 502；rerank 挂 ⇒ 502 | `embeddingPort.embed()` 异常直上抛 | 双路架构的意义就是单路可用；读路径业界惯例 = 降级 + WARN + 保持语义（引用强制不丢）。注意红线不变：降级仅限**本域内已实现路径**（BM25 单路），严禁切云端辅路 |
| S4 | **引用强制位置靠后**：失效切片仍参与 BM25/向量/RRF 计算后才在组装期丢弃 | `retrieve()` L61-104 | 浪费算力且污染 BM25 语料统计；一旦按 R1 补上 rerank，topK 截断点后置会使失效切片挤占精排名额（返回有效数 < topK 且无回填） |
| S5 | **无查询改写**（multi-query / HyDE / step-back） | 无 | recall 提升的标准手段，用户口语化查询与条款书面语 gap 明显时收益大。记 backlog |
| S6 | **无多样性控制**（MMR） | 无 | top-5 可能全来自同一条款/同一章节，引用集中、视角单一。记 backlog |
| S7 | **ingest 无失败恢复语义**：中途失败留半截切片，无幂等重建 | `ingest()` 循环 `save`，无版本批键 | 崩溃后重试 ⇒ 重复切片叠加。幂等批键（R3 修复）同时解决此问题：重入时校验版本 + 切片数，不一致即重建 |

## 3. 优化建议清单（按优先级；★ = 本次已执行）

### P0——不修则生产形态与方案描述不符

1. ★ **接线 rerank（R1）**：`RagApplicationService` 增 `RerankPort` 依赖；链路改为 RRF 粗序 → 取前 `candidatePool`（默认 30，`bone.ai.rag.candidate-pool`）→ rerank → topK。rerank provider 故障：WARN + 回落 `NoOpReranker` 序（RRF 粗序），**引用强制语义不变**；同步订正 `HttpBgeRerankClient` javadoc 中「不静默降级」的旧口径（与实现决策对齐，消灭双口径）。
   *为什么*：rerank 是「引用正确率 ≥98%」门禁的关键一环；降级而非 502 是因为读路径可用性优先，且 WARN + 错误码使降级可观测（非「假装已精排」）。
2. ★ **接线 embedding 并按配置装配（R2）**：`RagAutoConfiguration` 补 `@EnableConfigurationProperties(RagInferenceProperties.class)`；`embeddingPort()` 按 `bone.ai.rag.embedding.base-url` 条件装配 `HttpBgeEmbeddingClient`，空则回落 `TransitionalHashEmbedding`；`rerankPort()` 同构（空则 `NoOpReranker`）。嵌入 provider 故障：WARN + **回落 BM25 单路**（复用 `RrfFuser` 空路语义：该路全体记末位，BM25 序主导）。
   *为什么*：配置面不注册 = 运维配了不生效，比没有配置更坏；BM25 单路降级让「双路」真正具备冗余价值。
3. ★ **补齐 docVersion 幂等（R3/R5/R7）**：`RagChunk` 补 `docVersion` 字段（对齐 DDL）+ `of(...)` 增参；`ChunkRepository` 补 `findByTenantAndDoc`；`ingest(tenantId, docId, docVersion, segments)` 幂等判定 = **同版本且切片数一致 ⇒ 跳过**（文档版本事件语义：同版本内容不变；崩溃半截场景切片数不符 ⇒ 自动重建自愈），否则软删该文档全部旧切片后重嵌。`RagController`/`RagIngestRequest` 补 `docVersion` 入参。
   *为什么*：DDL 注释已承诺「同版本不重复入库」；无此机制时重复入库直接污染 BM25 语料与向量路（同文本多副本抬升 IDF/重复命中）。
4. ★ **容量护栏 + 分数阈值（S1/S2）**：`RagQuery` 补 `minScore` + `maxScan`（3 参构造保留，默认 minScore=0 不启用、maxScan=10000）；`maxScan` 超限 **fail-closed** 抛 `AI_RAG_SCOPE_OVER_LIMIT`（422，提示收窄 `doc_scope` 或调大 `bone.ai.rag.max-scan`），绝不静默截断；`minScore` 在精排后按最终分过滤（宁缺毋滥，返回数可 < topK）。错误码补入 `AiRagErrorCodes` + 台账 + 详设 §3.1 表。
   *为什么*：护栏的取值哲学与本模块一致——容量问题显式失败（调用方知道发生了什么），阈值问题按实测分布校准（默认不误杀）。
5. ★ **引用强制前置（S4）**：失效切片（无 `clauseRef`/span 非法）在打分前剔除并聚合 WARN，候选池只含有效切片——rerank 名额不被浪费，返回有效数稳定达 topK（语料允许时）。
6. ★ **minScore/maxScan 应用层配置贯通**：`BoneAiProperties` 补 `ragMinScore`/`ragMaxScan`，`application.yml` 补 `bone.ai.rag.*` 示例块（embedding/rerank base-url 注释态 + candidate-pool/max-scan/min-score），`RagRetrieveRequest` 支持请求级覆盖。

### P1——安全与质量（2026-10-23 晚二次执行：ACL / MMR / 降级可观测三项已落地；查询改写记决策）

7. ★ **文档级 ACL（R4）**：新增 `RagAclPort`（domain 端口，契约 = 返回调用方可见 `doc_id` 集合）+ 默认 `NoDocAcl`（仅租户硬隔离兜底）+ `RagAutoConfiguration` `@ConditionalOnMissingBean` 条件装配。检索链第一环接入：显式 `doc_scope` 不在可见集合 ⇒ **403 `AI_RAG_DOC_FORBIDDEN` fail-closed**（绝不静默回落全租户检索），无作用域时按可见集过滤候选切片。调用方身份由实现自行从上下文解析（端口不接收 user 入参——防伪造身份参数绕权，与 `TenantProvider` 同构）。**为何是端口而非 rag 自建 ACL 表**：文档权限模型归属文档中心，rag 不重复建设权限存储；L3 私有化交付前接入方适配为硬依赖（当前兜底形态仍有同租户内跨文档越权面）。
   *落地形态*：seam + fail-closed 语义 + 负向探针测试（越权 403 / 可见集过滤），**接入方 ACL 适配**列 L3。
8. **查询改写（S5）——决策：暂不落地 machinery**。multi-query 合并机制本身零风险，但**无 producer 的 machinery 即死代码**（正是本轮 P0 修掉的反模式：`HttpBge*Client` / `RerankPort` 零消费方前车之鉴）；改写收益须按评测集回流数据标定（报告原建议「批二定」）。接线点预留：orchestration 侧生成多查询 → rag 多查询合并，批二启动。
9. ★ **多样性 MMR（S6）**：`MmrSelector`（domain/service）选取式实现——从精排后候选迭代挑 topK，每步选 `λ·相关性 − (1−λ)·与已选的最大相似度` 最大者；相似度用切片入库嵌入（仅同模型版本可用，否则按 0、MMR 自然退化为相关性原序）。`bone.ai.rag.mmr-lambda` 默认 **0 = 关闭**（λ=0 约定为关闭而非数学上的纯多样性——防运维误配乱序；λ=1 纯相关性等价关闭；阈值按评测集回流校准，批二启用，与 minScore 同哲学）。开启时精排候选按 3 倍扩样（选取式 MMR 需要比 topK 更大的候选面才能「换掉」同质项；关闭时不多要，避免白付 cross-encoder 成本）。
10. ★ **降级可观测性**：`RagEventSink` 端口 + `RagEvent(type, detail)` + 默认 `LoggingRagEventSink`（结构化 WARN，保持既有可观测性不降级）；降级 / 数据卫生事件（`EMBEDDING_DEGRADED` / `RERANK_DEGRADED` / `DROP_INVALID_CHUNKS`）经端口下沉；**响应体 `degradations` 透出降级痕迹码**（`retrieve` 返回 `RagRetrieveOutcome(results, degradations)`）——接入方 / 评测管线可观测，而非只翻服务端日志。目标态 trace 落库 + 告警适配：端口已就位，接入方 `@Bean` 覆盖即可，检索链零改动（L3）。

### P2——完善性

11. 终局检索形态（pgvector / ANN 索引 + BM25 下推 DB）维持总案批二计划；过渡态以 maxScan fail-closed 护栏兜底，两者语义连续（护栏阈值即索引化迁移的触发信号）。
12. `RagResult.score` 量纲双轨（rerank 分 vs RRF 分）写入接口文档：接入方不得跨模式比较 score 绝对值，只可用于同次结果内排序。
