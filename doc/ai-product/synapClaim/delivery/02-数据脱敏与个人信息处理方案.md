# 02 数据脱敏与个人信息处理方案

> 用途：满足 PIPL 与金融数据安全要求，把"授权脱敏样本"从一句口号变成可执行、可验证、可审计的工程流程。适用于试点数据交接与后续生产数据（员工福利险场景）。

---

## 一、数据分级（先分级、再脱敏）

|**级别**|**数据**|**处理要求**|
|---|---|---|
|S（敏感个人信息）|姓名、身份证号、手机号、地址、病历号、诊断、药品/检查项目、费用明细|默认不出域；本地 vLLM；脱敏后可入评测集|
|A（个人信息）|保单号（可识别个人的业务标识）、医疗机构名称|脱敏/假名化|
|B（一般数据）|疾病分类（ICD-10 代码）、药品目录代码、金额统计、日期（脱敏后）|可入库；**用于模型训练须按金发〔2026〕8号数据条款与保司授权约定另行取得许可**，评测回归可用|
|C（公开/脱敏后）|完全匿名化聚合数据（如准确率统计）|自由使用（需确认不可重识别）|

## 二、脱敏字段清单与算法（逐字段映射）

|**字段**|**示例值**|**脱敏算法**|**脱敏后示例**|**保留信息**|
|---|---|---|---|---|
|姓名|张三|遮蔽（保留姓）|张*|姓氏+长度（用于同名重复检测）|
|身份证号|110101199001011234|假名化（HMAC-SHA256+盐）|f3a9…8b|对评测/开发角色不可逆，一致性哈希可关联|
|手机号|138****1234|遮蔽|138****1234|前3后4（用于重复报案检测）|
|地址|北京市朝阳区XX路1号|泛化（到区级）|北京市朝阳区|区级（用于地域分布）|
|病历号|20250101001|假名化|h7k2…9m|可关联同一人多次就诊|
|诊断|急性上呼吸道感染|保留（医学研究价值）|急性上呼吸道感染|疾病名称（ICD-10 编码）|
|用药明细|阿莫西林胶囊 0.25g×24|保留|阿莫西林胶囊 0.25g×24|药品+剂量（理算必须）|
|金额|¥356.80|保留|¥356.80|金额（理算必须）|
|就诊日期|2026-03-12|**禁用抖动**（时序风控字段，R-FRAUD-03 时间轴规则依赖）|2026-03-12|日期（时间轴风控需要）|
|医院名称|北京协和医院|泛化（保留等级+城市）；需具体医院的规则（定点/观察名单）经**受控映射表**回查原值|三甲医院·北京市|医院等级+城市（责任范围判断）|

**原则**：
1. **可逆性**：可识别字段对评测/开发角色一律不可逆（假名化+盐，盐存 KMS/HSM 双人分片托管 + 定期轮换（工程落地版 §11.3））；密钥管理员持受控映射表，仅供撤回删除执行、泄露追溯与受控规则回查（如医院定点判断），映射表按个人信息管理（加密存储、访问入审计日志）；“一致性”靠假名化后的稳定 ID 保证（同一人多次就诊可关联，但对业务/评测角色无法反推真实身份）
2. **最小保留**：只保留理算、核责、风控、评测真正需要的字段；不相关字段直接删除
3. **宁缺勿猜**：无法确认脱敏方式的字段不进入数据集

## 三、脱敏验证方法（防"脱了个寂寞"）

|**验证项**|**方法**|**通过标准**|
|---|---|---|
|字段覆盖检查|脚本比对源数据与脱敏后数据的字段映射完整性|100% 覆盖清单字段|
|重识别风险评估|模拟攻击：脱敏后数据尝试关联外部公开数据（姓名+身份证+病历号组合查询）|重识别率 <5% 且无法定位到具体个人|
|一致性验证|同一人多次记录假名化后 ID 一致（关联查询通过）|一致率 100%|
|业务可用性验证|评测集抽取 20 条，核赔员人工核验"脱敏后数据能否正常理算"|20/20 可用|

## 四、数据流转链路（获取→使用→删除）

```plaintext
甲方提供（加密通道+交接清单）
  ↓
乙方接收（加密存储，落地即标记）
  ↓ 7 日内完成脱敏（脱敏脚本+人工抽检）
脱敏后数据集（评测集/训练集分离，权限隔离）
  ↓
使用（仅限试点目的；访问留痕）
  ↓
试点终止后 30 日内删除或返还（销毁证书/日志按审计要求保留）
```

## 五、访问控制与审计

- 角色：数据管理员（仅 1 人，负责密钥与脱敏脚本）、评测工程师（仅可读脱敏数据集）、业务专家（标注任务，无导出权限）
- 审计：所有数据集访问、导出、删除操作记录（谁/何时/何目的/何范围），日志保留 ≥7 年
- 存储：加密（AES-256 静态加密）；传输：TLS 1.2+；脱敏脚本与盐分离保管

## 六、PIPL 合规要点（试点操作检查表）

- [ ] 甲方确认个人信息主体授权链路（员工福利险：保单条款 + 员工知情同意/授权书）
- [ ] 数据处理目的告知甲方（仅试点验证，非商业化使用）
- [ ] 最小必要：只收集试点必需的字段（对照本方案字段清单）
- [ ] DPA 已签署（delivery/01）
- [ ] 云端 API 仅限非敏感数据；病历/身份类不出域（本地 vLLM）
- [ ] 如涉及个人信息出境：单独做出境安全评估（本项目默认不触发）
- [ ] 数据安全事件应急预案（泄露 24h 内通知甲方）

> **红线提醒**：医疗健康数据属"敏感个人信息"，处理需单独同意（PIPL 第 29 条）；"脱敏后即自由"是常见误区——假名化数据仍属个人信息，需持续按本方案管理；只有通过重识别风险评估的匿名化数据才可自由使用。

## 七、脱敏技术实现（开发规格）

### 7.1 工具选型

- **假名化**：自研 Python 脚本，HMAC-SHA256 + 每字段独立盐（盐存 KMS/HSM 双人分片托管，不入代码库、不入数据集）
- **遮蔽/泛化/删除**：自研规则脚本（Python，config 驱动）
- **影像遮蔽**：对 PDF/图片中的敏感区域（姓名、身份证号、地址栏）做 OCR 定位 + 涂黑/遮挡，保留票据金额与明细区域
- **校验**：单元测试 + 样例比对（每个规则至少 3 条正反例）

### 7.2 脚本接口规范

```bash
mask_dataset \
  --input ./raw_data \          # 原始数据（落地即隔离）
  --output ./masked_data \      # 脱敏后数据（评测/训练分离）
  --config config.yaml          # 字段-算法映射（见下表）
  --salt-key id-salt-2026       # 盐引用（密钥库）
```

config.yaml 结构（节选）：

```yaml
fields:
  - name: name
    algorithm: mask_middle
    keep_prefix: 1            # 保留姓
  - name: id_card
    algorithm: pseudonym
    salt_key: id_salt
  - name: address
    algorithm: generalize
    level: district           # 泛化到区级
  - name: hospital
    algorithm: generalize
    level: level+city          # 等级+城市
  - name: diagnosis
    algorithm: keep            # 医学研究价值，保留
  - name: amount
    algorithm: keep
  - name: created_at
    algorithm: jitter
    days: 7                   # ±7天抖动（仅限非时序风控字段）
  - name: invoice_date
    algorithm: keep           # 时序风控字段禁抖动（R-FRAUD-03 时间轴规则依赖）
```

### 7.3 密钥管理

- 盐文件：存 **KMS/HSM**，**双人分片托管 + 定期轮换**，禁导出明文盐（对齐工程落地版 §11.3；单人托管有 bus-factor 与合谋风险）；每字段独立盐
- 轮换：定期轮换（对齐工程落地版 §11.3）；轮换后旧盐仅限密钥管理员受控解密映射（映射表加密存储、访问入审计日志，用途限定撤回删除/泄露追溯/受控规则回查）
- 审计：盐访问记录入审计日志（谁/何时/为何）

## 八、脱敏样例（输入 → 输出）

**示例 1：员工信息（假名化）**

```json
// 输入
{"name": "张三", "id_card": "110101199001011234", "mobile": "13812345678"}
// 输出
{"name": "张*", "id_card_hash": "f3a9c21d…8b", "mobile": "138****5678",
 "person_key": "p-7f2k9d"}   // person_key 用于同一人多案关联（不可反推）
```

**示例 2：案件主数据（保留业务字段）**

```json
// 输入
{"policy_no": "EG20260001", "hospital": "北京协和医院",
 "date": "2026-03-12", "amount": 356.80,
 "diagnosis": "急性上呼吸道感染", "drugs": [{"name": "阿莫西林胶囊", "amount": 35.80}]}
// 输出
{"policy_no": "POL_a91f7c3e", "hospital": "三甲医院·北京市",
 "date": "2026-03-12", "amount": 356.80,
 "diagnosis": "急性上呼吸道感染", "drugs": [{"name": "阿莫西林胶囊", "amount": 35.80}]}
```

**示例 3：材料影像（区域遮蔽）**

```text
发票影像：姓名/身份证号/住址区域 → 涂黑；金额/明细/医院/日期 → 保留
病历影像：患者标识/家属信息 → 涂黑；诊断/用药/检查 → 保留
```

> 脱敏后样例每季度抽 20 条人工核验（对照 §三 验证方法），确保业务可用性不回退。

## 九、数据接收与交接 SOP（操作步骤）

|**步骤**|**动作**|**责任人**|**产出/记录**|
|---|---|---|---|
|1|交接前核对（附件A 清单：字段/条数/格式）|双方数据接口人|交接清单确认单|
|2|传输（SFTP/加密网盘，TLS 1.2+，密文）|甲方导出、乙方接收|传输日志|
|3|接收校验（条数、格式、字段完整性、文件可读）|乙方数据管理员|校验报告|
|4|落地即隔离（原始数据加密存储，仅管理员可读）|乙方数据管理员|访问记录|
|5|7 日内完成脱敏（脚本 + 人工抽检 5%）|乙方数据管理员|脱敏脚本日志|
|6|出具脱敏说明（字段覆盖 100% + 重识别风险报告）|乙方数据管理员|脱敏报告|
|7|甲方确认（24h 内）|甲方数据接口人|确认回执|
|8|归档：交接记录、脱敏报告存档 7 年；原始数据按 DPA 处理|乙方|档案索引|

### 9.1 撤回同意后的去标识化擦除字段清单（PIPL 29 条，与工程落地版 §11.3/§11.9 同源）

撤回（`consent_withdrawn_flag=1`）触发**去标识化擦除**（不物理删除——资金/决策记录受 ≥7 年监管留存约束），擦除字段清单如下，**未列入字段为不可回溯到个人的去标识化业务/审计事实，保留**：

| 表 | 擦除字段 | 处理方式 |
|---|---|---|
| `claim_case` | `insured_id_hash` | 置擦除标记值（不可逆映射），历史 hash 不回填 |
| `claim_stakeholder` | `person_id_hash`/`name_masked`/`phone_masked`/`bank_ref` | 同上；`bank_ref` 同步销毁密钥引用 |
| `quota_account` | `insured_id_hash` | 同上（额度账务事实保留，仅断开个人关联） |
| `claim_medical_fact` | `fact_value` 中可识别个人部分（姓名/证件片段） | 泛化或置空，`source_span` 保留指向 |
| `claim_evidence` | `extracted_json` 中个人字段 | 置空（文件本体按 DPA 约定处理） |
| `claim_appeal` | `applicant_hash`/`reason_text` 中个人部分 | 同上 |

> 擦除作业经 `domain_event_outbox` 异步执行并留痕（`erased_at`/`erased_by`/`erased_fields`，工程落地版 §11.9）；已归档冷存介质中的上述字段同样在擦除范围（归档时 S 级字段单独加密，擦除 = 销毁密钥/密文块）；WORM 审计通道日志不受擦除影响。

## 十、泄露应急响应（流程）

|**步骤**|**动作**|**时限**|
|---|---|---|
|1|发现（监控告警 / 审计异常 / 外部通报）|—|
|2|隔离（断开受影响系统/账号，冻结访问）|立即|
|3|通知甲方（DPA 第 9 条：书面通知 + 初步影响说明）|24 小时内|
|4|取证（日志、访问记录、数据快照，只读保全）|48 小时内|
|5|影响评估（重识别风险、涉及数据范围、受影响个人）|72 小时内|
|6|整改（根因修复、密钥轮换、脱敏加强）|一周内|
|7|复盘报告（原因、影响、整改、预防措施）与监管报告（如需）|两周内|

> 应急联系人与 24h 值班电话随 DPA 附件确认；演练频率：每半年一次桌面演练。
