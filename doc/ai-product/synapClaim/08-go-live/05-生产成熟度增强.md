## 5.1 AI 置信度阈值校准方法论（P2-1）

> 现状：0.7 / 0.85 三档（Shadow/Assisted/Automated）已定（§7.3、AI 技术方案 §2.1），但**缺"基于数据校准"的方法论**。Phase C 放开自动通过前，阈值误标 = 资损或零价值。

### 5.1.1 校准流程（对齐 MRM champion-challenger，§1.4）

| 步骤 | 动作 | 产出 |
|---|---|---|
| 0. 概率校准 | 模型原始置信度普遍**过自信**，先用留存集画可靠性曲线（Reliability Diagram）、算 **ECE**，用温度缩放（Temperature Scaling）或 Isotonic 回归校准；**校准后 ECE ≤ 0.05 才允许进入阈值调参**，否则 0.7/0.85 的切分无效 | 校准后的置信度输出 + ECE 报告 |
| 1. 历史回放 | 用 Shadow 态积累的真实案件（含人工最终结论）回放决策图，记录各置信度档的**精确率/召回率/误拒率/误付率** | 校准数据集（带标签） |
| 2. 代价矩阵 | 定义误拒赔代价（用户求偿权损害 + 合规）/ 误付代价（资损）权重 | 阈值优化目标函数 |
| 3. 定标 | 以"误付资损 ≤ 预算 + 误拒率 ≤ 监管/体验上限"为约束，反推各档最优阈值（未必是 0.7/0.85） | 校准后阈值 + 置信区间 |
| 4. champion-challenger | 新阈值先在 Shadow 与现阈值双跑比对，一致率 ≥ 阈值且 challenger 不劣化再升 Assisted | 升阶证据 |
| 5.  registrar 审批 | 阈值变更经风险管理委员会审批（金发 8 号第 16 条），写入 §7.3 映射表 | 审批回执 |

### 5.1.2 阈值漂移监控（复用 MRM）

- 线上各档**实际精确率/误拒率周环比**下滑 > 5% → 暂停自动建议，退回人工（MRM §1.4 概念漂移动作）。
- 阈值与模型卡 `driftPolicy` 联动：模型重训后须重新走 5.1.1 校准，禁止"换模型不换阈值"。

### 5.1.3 验收

- Phase C 放开前：5.1.1 校准报告 + registrar 审批回执在 §12.2；阈值非硬编码、经 `feature_toggle` 外置（MRM §1.4 灰度比例不发版）。

## 5.2 审计完整性增强（P2-2，对齐等保三级）

> 现状（§11.3）：双层审计——① 业务事实落 append-only 表（禁 UPDATE/DELETE，应用账号仅 INSERT/SELECT）；② 审计通道日志入对象存储 **WORM/Object Lock（合规模式）≥7 年**。已扎实。增强点：

| 增强项 | 内容 | 等保三级依据 |
|---|---|---|
| **hash 链** | 每条审计记录含 `prev_hash` → 本记录 hash，形成不可篡改链；任意中间篡改导致后续 hash 断裂，可检测 | 审计完整性（数据完整性） |
| **数字签名** | 审计写入方用私钥对记录签名，验签失败 = 被篡改/伪造 | 抗抵赖 + 完整性 |
| **审计库与业务库物理分离** | 审计实例独立部署 + 独立账号（与业务库不同实例/不同 KMS 密钥）；应用对审计库仅 INSERT，无 SELECT 管理权限 | 等保"集中审计"+"审计与业务隔离" |
| **留存与导出** | ≥7 年介质明确（§11.3 已定 WORM）；补"可审计导出"接口（监管调阅）+ 导出留痕 | PIPL 留存 + 监管调阅 |

> **不破坏既有**：append-only 表禁改 + WORM 保留；hash 链/签名是**叠加**在既有双层之上，不改变"应用账号仅 INSERT"的硬约束（§2799 禁授权后门同源）。

## 5.3 错误预算 / SLO burn-rate 告警政策（P2-3）

> 现状：告警 35 处、混沌回归 CI、季度 RTO/RPO 演练齐备（诊断已纠偏），但**错误预算消耗告警政策未单独成文**。

### 5.3.1 SLO 文档（建议基线）

| SLO | 目标 | 错误预算（月度） |
|---|---|---|
| 决策初筛时延 | P95 ≤ 30s（单案 ≤5 份材料，§11.8） | 0.5%（约 3.6h/月） |
| 平台可用性 | 99.9%（一期）/ 99.99%（V2） | 43.8min / 4.38min |
| 资金差错率 | **0**（§11.7 目标） | 0（无预算，硬零） |

### 5.3.2 burn-rate 多窗口告警

| 窗口 | 消耗速率 | 动作 |
|---|---|---|
| 1h 快速耗尽（≥14.4x，1h 烧完全月预算） | 立即 P1 + 值班介入 | 降流量/切降级 |
| 6h 慢速耗尽（≥6x） | P2 + 复盘 | 排查趋势 |
| 资金差错（任何一笔） | 立即 P0（无预算） | 按 §11.7 差异处置 SLA（15min 告警/1h 介入） |

> **政策成文**：把上表固化为 `SLO-burn-rate-policy.md`，与现有告警矩阵（§11.6）、演练（季度 RTO/RPO）联动；错误预算耗尽时触发"冻结自动通过 / 转人工"的显式降级（与 §11.4 三态开关衔接）。
