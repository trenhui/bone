# 10 · 备份恢复实测与演练证据

> **定位**：补齐 `outputs/synapClaim-生产就绪独立诊断.md` 盲区 **B5**。原独立诊断声明"RTO/RPO 季度演练"，但文档族**无真实 restore test 可验证 artifact**。等保与金融监管要求的是"**可恢复**"而非"**有备份**"——备份存在 ≠ 备份可用。
>
> **业界基准**：等保 2.0 8.1.2（数据备份恢复）要求**定期恢复演练**；金融行业（如《商业银行数据中心监管指引》）要求备份可用性验证；ISO 27031（业务连续性 ICT 就绪）。

---

## 一、为什么"有备份"不够

| 常见失效 | 仅靠"有备份"发现不了 |
|---|---|
| 备份静默损坏（bitrot / 加密密钥丢失） | 恢复时才发现备份打不开 |
| 增量链断裂 | 全量 OK 但中间增量缺失 → 只能恢复到旧点 |
| 恢复后数据不一致（跨库/跨表） | 单库恢复成功，但业务事务跨表不一致 |
| 恢复耗时超 RTO | 演练才暴露，平时无数据 |
| 权限/配置未备份 | 数据恢复但系统起不来 |

---

## 二、须建设的内容（可证伪）

| 项 | 内容 | 验收（可证伪） |
|---|---|---|
| **定期真实恢复演练** | 每季度从**生产备份**恢复到**隔离环境**，校验数据完整性/跨表一致性/业务可起 | 演练报告含：日期、恢复范围、校验结果、实际恢复耗时 |
| **恢复耗时 vs RTO/RPO** | 报告明确实际恢复耗时，对照 §11.8 的 RTO/RPO 目标 | 实际耗时 ≤ 声明 RTO；数据丢失 ≤ 声明 RPO |
| **备份完整性** | 备份加密 + 异地 + 保留周期满足合规；备份清单与恢复对象对账 | 备份清单可回溯，密钥托管可验证 |
| **演练报告归档** | 报告入 WORM 审计（§11.3），作为 Go-Live 与年度复审证据 | 最近一次演练报告在 §12.2 |

> 关键：演练必须基于**真实生产备份**，而非"用测试数据假装恢复"。这是金融审计的高频检查项。

---

## 三、与现有 §11.8 的衔接

- §11.8 已声明 RTO/RPO 与备份策略；本册要求把"**声明**"升级为"**实测证据**"——折叠时把 RTO/RPO 从"目标值"改为"目标值 + 最近实测值"双列。
- 演练应与混沌 CI（韧性验证）合并排期，避免重复停机窗口。
