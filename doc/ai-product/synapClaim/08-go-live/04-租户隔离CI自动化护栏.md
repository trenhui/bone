## 4.2 ArchUnit 规则（✅ 已落地：`src/test/java/com/bone/claim/ArchitectureTest.java`）

> 与既有 24 条 ArchUnit **同文件同跑**（`mvn test` 触发）。本次新增 2 条，计数 24 → **26**，全绿。

```java
// P1-5：租户身份读取收敛到唯一权威 TenantPortAdapter（OWASP A01 fail-closed 结构锁）。
// tenant_context_via_provider 已禁 domain/application/adapter 直读 TenantContext；本规则收口
// 「基础设施层其余类（含未来新增的 adapter/security/config）也不得读 TenantContext.get*」，
// 仅 ..infrastructure.tenant..（TenantPortAdapter）可读——杜绝从线程本地/请求头旁路绕过租户隔离。
@ArchTest
static final ArchRule tenant_context_read_only_by_tenant_port_adapter =
    noClasses().that().resideOutsideOfPackage("..infrastructure.tenant..")
        .should().callMethod(TenantContext.class, "getTenantId")
        .allowEmptyShould(true)
        .because("OWASP A01：租户身份唯一权威是 TenantPortAdapter（读 TenantContext），"
            + "基础设施层其余类不得直读 TenantContext.getTenantId，防止绕过租户隔离");

@ArchTest
static final ArchRule tenant_context_aslong_read_only_by_tenant_port_adapter =
    noClasses().that().resideOutsideOfPackage("..infrastructure.tenant..")
        .should().callMethod(TenantContext.class, "getTenantIdAsLong")
        .allowEmptyShould(true)
        .because("OWASP A01：租户身份唯一权威是 TenantPortAdapter（读 TenantContext），"
            + "基础设施层其余类不得直读 TenantContext.getTenantIdAsLong，防止绕过租户隔离");
```

> **为何不做原草图的 R-TENANT-01/02（repository 方法签名断言）**：原草图的"所有 Repository 查询必须带 `tenant_id`"已被现有共享规则覆盖——`all_tenant_entry_points_must_be_named_all_tenants`（全租户入口须命名 `*AllTenants`）+ `schedule_only_calls_all_tenants_repository_methods` + `tenant_context_via_provider`（业务层禁直读 TenantContext，统一经 `TenantPort`）。再叠方法签名断言属重复且脆弱（易误报），故改为更精准的**读取边界锁**：只有 `TenantPortAdapter` 可读 `TenantContext.get*`。当日即绿（全模块仅 `TenantPortAdapter` 读 `get*`），锁住未来新增类绕过。

## 4.3 运行时反例测试（✅ 已落地：`src/test/java/com/bone/claim/infrastructure/security/TenantIsolationGuardrailTest.java`）

> 5 例，随 `mvn test` 跑（与 26 条 ArchUnit 同批）。纯过滤器/端口单元，**不启动 Spring 上下文**，毫秒级。证明两条 OWASP A01 fail-closed 不变量：

| 用例 | 断言 | 锁住的不变量 |
|---|---|---|
| `forgedTenantHeaderIsOverriddenBySignedClaim` | 持租户 A token + 伪造 `X-Tenant-Id:B` → 下游头被改写为 A | 伪造头被签名 claim 覆盖，下游读到的只能是 A |
| `platformTenantClaimOverridesForgedHeader` | 平台租户(0) token + 伪造头 → 头=0 | 平台租户同样不信任伪造头 |
| `tenantTokenWithActingHeaderIsRejected` | 租户 token + 伪造 `X-Acting-Tenant-Id` → 头=自身 claim | ADR-0029 切换头不被租户 token 采信 |
| `tenantPortAdapterReadsOnlyTenantContext` | `TenantContext=B` → `currentTenantId()==B` | 租户权威只认 TenantContext（签名 claim 播种），不读原始请求头 |
| `tenantPortAdapterFailsClosedWhenContextMissing` | 上下文缺失 → 抛 `IllegalStateException("租户上下文缺失")` | fail-closed：绝不回落默认值 |

> **回归防护**：若有人去掉过滤器归一化或让别的类直读 `TenantContext.get*` 旁路租户隔离，测试/ArchUnit 立即转红，CI 阻断。与 §3.3"认证主体为权威"设计形成"设计 + 结构锁 + 反例"三保险。

## 4.3.1 链路级集成测试（✅ 已落地：`.../security/TenantIsolationChainTest.java`，2026-10-28）

> 4 例，随 `mvn test` 跑。不启动 Spring 上下文，但**直接编排生产中 Spring 实际装配的两个真实组件**——`JwtAuthenticationFilter`（归一化头）与 `TenantInterceptor`（播种上下文）——复刻生产装配顺序（过滤器先、拦截器后，且拦截器看到的是过滤器包装后的请求 `TenantHeaderOverridingRequest`），断言伪造头在"过滤器→拦截器→端口"全链路被签名租户彻底覆盖。

| 用例 | 构造 | 断言（锁住的不变量） |
|---|---|---|
| `forgedHeaderNeverReachesDataLayer_chainResolvesToSignedTenant` | token(A) + 伪造 `X-Tenant-Id:B` | `TenantContext` 与 `TenantPortAdapter#currentTenantId()` 均解析为 A，且 `≠B`——伪造头**永不到达数据层** |
| `normalRequestWithoutForgedHeader_chainResolvesToTokenTenant` | token(A)、无伪造头 | 解析为 A |
| `missingHeaderChainFailsClosed_notDefaultTenant` | 无 token、无头（畸形入站） | `TenantContext` 为空、端口 `IllegalStateException`（fail-closed，不回落 0） |
| （辅助）下游请求捕获 | 过滤器交下游的请求对象 | 拦截器只校验该包装请求，与生产一致 |

> **关键实证发现（写进测试注释）**：`AbstractJwtAuthenticationFilter` 对带 token 请求把 `X-Tenant-Id` 归一化为签名 claim，是通过 `HttpServletRequestWrapper`（`TenantHeaderOverridingRequest`）**包装透传下游**，而非改写原始请求的 header。因此测试必须把过滤器实际交给下游的请求对象喂给拦截器，才与生产行为一致——这也反向确认了设计是 OWASP A01 fail-closed（源头改头，对所有下游消费者同时生效、与执行顺序无关）。
