# 02 · 外部依赖 SLA 与降级责任矩阵（含支付实时对账契约）

> **目标态**：填补全库 0 命中的"外部依赖 SLA 矩阵"，并补完 Phase C 自动出款前的**支付实时对账与未知态处置契约**。
> 依据：《工程落地版》§11.6（韧性与熔断）、§11.7（四向对账）、§11.8（部署与高可用，99.9% 对外承诺档）、§7.5（资金状态机）、待评审清单 #6（bone-ai 端口）。
>
> **核心约束**：对外承诺 99.9%（一期）/ 99.99%（V2 同城双活）的前提是**每个上游依赖的 SLA 必须严于本平台承诺档**，否则数学上不可达。

## 2.1 外部依赖清单（synapClaim 直接依赖）

| 依赖 | 一期形态 | 生产形态 | 对资金/核定的影响 |
|---|---|---|---|
| 支付网关 | mock（`PaymentGatewayPort` 一期 mock） | 保司/银联/支付宝/微信支付直连或经 TPA 内部账户 | **直接出金，资损高风险** |
| TPA / 保司核心 | pk-tpa-saas `AdjustEngine` 复用 | 同左 + 直付/垫付通道（C10） | 理算/额度权威 |
| LLM 厂商 | 经 `bone-ai-gateway` 底层（vLLM/云端分层） | 同左 | AI 建议质量；降级→纯规则 |
| 医保 / 税务通道 | 一期不接（§1.2 非目标，发票验真走 `bone-ai-document`） | V2 深度直连 | 票据真实性 |
| **bone-ai 中台** | **六端口零实现**（待评审清单 #6） | C1–C11 能力（T6 依赖图谱） | **AI 能力层整体不可用（P0-1）** |
| OCR / 文档解析 | `bone-ai-document`（可复用快瞳） | 同左 / Docling sidecar | 材料解析；降级→拒收转人工 |

## 2.2 依赖 SLA 与降级责任矩阵（SLA 值须签署，不得留空）

> 每格必须填写**签署值**与**责任归属**。空白 = 门禁 G8 未过（总纲 §二）。

| 依赖 | 承诺 SLA（对本平台） | 故障模式 | 本平台降级动作 | 对客户责任归属 | 验收项（接入前） |
|---|---|---|---|---|---|
| 支付网关 | 目标 ≥ **99.95%**（严于本平台 99.9%） | 超时/503/未知态 | 落 DLQ + P1 告警 + 案件转人工；不重复出金（§11.7） | 平台兜底通知客户，按 SLA 赔偿条款 | 网关支持 `idempotency_key` 去重 + 超时语义明确（§2.3） |
| TPA / 保司核心 | ≥ 99.9% | 接口超时/数据不一致 | 重试退避（1s/2s/4s≤3）+ 补偿；额度不一致转人工 | 平台 + TPA 按合同 | 额度余额查询契约 + 请款/回款对账文件 |
| LLM 厂商（经网关） | ≥ 99.5%（AI 非资金路径） | 超时/限流/内容安全拦截 | **纯规则降级**（§7.3）+ 超时转人工 | 平台（AI 仅建议，不出金） | 网关熔断配置 + 降级开关（§11.4） |
| 医保/税务 | V2 起 ≥ 99.5% | 通道不可用 | 票据真实性转人工核验 | 平台通知客户延后 | V2 接入验收 |
| **bone-ai 中台** | **未定（P0-1 阻断）** | 六端口未接线 | 域内规则引擎 + 决策图兜底（不调用中台） | 平台（AI 能力降级） | **G1：端口 SDK 交付或豁免延期评审** |
| OCR / 文档解析 | ≥ 99.5% | 队列积压/解析失败 | 拒收材料转人工（§7.2） | 平台通知客户补件 | OCR 并发 ≤5 背压（§3 容量包） |

> **责任边界铁律**：外部依赖故障导致客户损失时，**责任归属字段**决定谁通知、谁赔偿、谁复盘——禁止"事故时扯皮"。本平台承诺 99.9% 的内部 SLA 文档（§11.8）须与上游 SLA 矩阵联动修订，上游未达标则本平台对外承诺须同步下调。

## 2.3 支付实时对账契约（Phase C 自动出款前必须落地）

> 现状（§11.7）：一期"进程内事件总线 + `afterCommit` + Outbox"已正确；对账为 CDC 监听 `funding_events` + `ReconciliationJob` 每日 01:00（T+1）。**问题**：T+1 对 Phase C 自动出款过慢，资金差错当晚才发现；且**外部网关"未知态"处置未定义**。

### 2.3.1 支付指令三态机（新增）

| 状态 | 含义 | 进入条件 | 离场动作 |
|---|---|---|---|
| `INSTRUCTED`（已指令） | Outbox 已发支付命令，待网关回执 | `PaymentGatewayPort.pay()` 返回受理 | 启动未知态计时器 |
| `PAID`（已支付） | 网关回执成功，`gateway_trade_no` 落 `settle_funding_event` | 回执成功/对账确认 | 进入 §11.7 四向对账 |
| `FAILED`（失败） | 网关明确拒绝 | 回执失败 | 补偿 `RELEASED`/`FAILED` 回冲额度（§7.5 补偿矩阵） |
| `UNKNOWN`（未知态） | 超时未回执（网络分区/网关无响应） | 超时阈值（建议 ≤ 30s 指令级 + ≤ 5min 查单级）触发 | **定时查单 + 二段确认（见下）** |

### 2.3.2 未知态处置（补偿路径）

```
INSTRUCTED --超时(30s)--> UNKNOWN
UNKNOWN --主动查单(gateway query, 指数退避≤5次)--> PAID / FAILED / 仍UNKNOWN
仍UNKNOWN --T+0 准实时对账(分钟级, 非仅T+1)--> 确认 PAID/FAILED
确认 FAILED --> 回冲额度(RELEASED) + 案件转人工
确认 PAID  --> 四向对账闭合; 若本地未收到回执, 补登 gateway_trade_no
UNKNOWN 超阈值(如 2h) --> 人工介入 + P0 资金告警(§11.7 差异处置 SLA: 15min告警/1h介入)
```

### 2.3.3 实时对账契约（替代/增强 T+1）

| 项 | 要求 |
|---|---|
| 频率 | Phase C 前：**准实时（分钟级，建议 ≤5min 拉取网关对账文件/接口）**；T+1 批量作为兜底与凭证 |
| 匹配键 | `gateway_trade_no`（§9.5 `settle_funding_event.gateway_trade_no`，PAID/FAILED/REFUNDED 必填） |
| 差异处置 | 单边账（本地 PAID / 网关无）/ 金额不符 / 重复指令 → 入 `reconciliation_diff` + P0 告警 + 人工 |
| 幂等保证 | 网关必须支持 `idempotency_key`（`{claimNo}:{stage}:{attempt}`）去重；**同键同参返回首次结果**（§10.3 已约定）；接入验收须验证该语义 |
| 未知态兜底 | 网关须提供"查询单笔"接口；否则本平台无法收敛 `UNKNOWN`，Phase C 不得放开 |

> **门禁 G7**：§2.3 状态机实现 + 网关 `idempotency_key` 去重与查单能力验收单，是 Phase C 自动出款放开的硬前置。

## 2.4 与韧性与熔断的衔接（§11.6）

- 依赖 SLA 矩阵（§2.2）每项降级动作须有对应熔断/降级配置，纳入 §11.6 韧性清单（现有：支付网关 1s/2s/4s≤3 退避 + DLQ + P1 告警 + 转人工）。
- bone-ai 中台降级：六端口未接线时，域内规则引擎 + 决策图必须可独立运行（不依赖中台），验证"AI 中台全宕，理赔主链路仍可 Assisted 运行"。
