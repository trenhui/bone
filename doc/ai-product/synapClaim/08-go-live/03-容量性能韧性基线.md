# 03 · 容量 · 性能 · 韧性基线（连接池 · 网关WAF · 背压 · 压测）

> **目标态**：把《工程落地版》§11.8 容量阈值表"已定义，待压测实测"回填为**带判据的实测基线**；填补全库 0 命中的"连接池"与"WAF"；定稿 API 网关选型（§11.8 选型表已登记 Higress 待验证）。
>
> **约束**：30s SLO（单案材料 ≤5 份不计入，§11.8/PRD）、OCR 并发 ≤5 队列背压、对外承诺 99.9% 不得超卖（FDE §四）。

## 3.1 DB 连接池基线（HikariCP，填补 0 命中）

| 参数 | 建议值（单实例） | 推导 | 风险 |
|---|---|---|---|
| `maximumPoolSize` | `min(CPU_core*2 + 磁盘数, DB_max_connections/实例数 - 余量)` | 经验公式，避免超过 MySQL `max_connections` | 过大→DB 连接耗尽；过小→请求排队 |
| `minimumIdle` | = `maximumPoolSize` 的 1/3，或固定 10 | 防冷启动建连抖动 | — |
| `connectionTimeout` | 3s | 超过即失败转降级，不无限阻塞 | 默认 30s 过长 |
| `idleTimeout` | 10min | 回收空闲连接 | — |
| `maxLifetime` | 30min（< DB `wait_timeout`） | 防 DB 侧主动断连导致幽灵连接 | 须 < 网关/LB 空闲超时 |
| 租户作用域批处理 | 全租户扫描须限流（ADR-0034），禁无差别全表扫 | §11.8 / 待评审清单 ADR-0034 | 单租户风暴打爆 DB |

> **与现有衔接**：连接池上限须与 §11.8 容量阈值（并发连接数预警 80%）联动；`ReconciliationJob`/`RefreshLimitHourJob` 等全租户调度（待评审清单 #2）已用 `TenantContextRunner.runAs` 逐租户，须补**批处理限流**防止峰值击穿 DB。

## 3.2 OCR / 文档解析队列背压（OCR 并发 ≤5）

| 项 | 建议 | 说明 |
|---|---|---|
| 并发解析数 | ≤5（既定语义） | 超出入队列，深度阈值触发拒绝 |
| 队列深度阈值 | 单租户 ≤ N（按容量表，建议 50） | 超限→新任务转人工/延后，返回 `429-style` 业务码 |
| 拒绝策略 | 排队超时（建议 ≤ SLA 余量）转人工 | 不阻塞主链路，fail-safe |
| 退避 | 1s/2s/4s≤3（与支付网关同《工程落地版》§2014） | 复用既有退避 |

> 折叠进 §11.8：把"OCR 并发 ≤5"从散落口径固化为"队列深度 + 拒绝策略 + 超时转人工"三件套。

## 3.3 API 网关 + WAF 选型（定稿，填补 WAF 0 命中）

| 层 | 选型 | 职责 | 状态 |
|---|---|---|---|
| API 网关（一期） | **沿用 BONE 平台网关**（限流/鉴权/租户路由由平台承担） | 入口限流 + 鉴权 + 租户路由 | 已定（§11.8 选型表） |
| API 网关（候选） | Higress | 待验证选型，**不得作为既定架构写入下游**（§11.8 已登记"待验证"） | 待 PoC |
| **WAF（边缘）** | **必须新增**：云 WAF / 网关层 WAF 模块 | 防 CC / SQL 注入 / 越权补充 / 防爬 | **Go-Live 前门禁 G9（原 0 命中）** |
| 内部 mTLS | 服务间 mTLS（既有 §11.3） | 内部零信任 | 已落地 |

> **WAF 门禁**：金融系统对外暴露面（员工端/工作台/对接）必须过 WAF；WAF 规则须覆盖"伪造 `X-Tenant-Id` 越权"类攻击（与 §4 租户护栏互补）。G9 验收 = WAF 在 §12.2 + 规则集评审通过。

## 3.4 水平扩展模型

| 维度 | 建议 | 依据 |
|---|---|---|
| 服务形态 | 无状态（会话/上下文外置，租户上下文经 `TenantContextRunner`） | 便于水平扩缩 |
| 会话亲和 | 非必需（无状态）；若有本地缓存亲和，须可降级为无亲和 | 避免扩缩漂移 |
| DB 扩展 | 单集群主从（一期 99.9%）→ 同城双活（V2 99.99%，§11.8） | 档位↔拓扑绑定 |
| 队列/异步 | 一期进程内事件总线 + Outbox；二期 RocketMQ（§11.1.1） | 一期无 MQ 必要 |
| 租户批处理 | 限流 + 显式租户作用域（ADR-0034） | 防全表扫风暴 |

## 3.5 压测计划模板（回填容量阈值表）

> 目标：在 Phase C 前出压测报告，把 §11.8"待压测实测"列填为实测值。

| 压测场景 | 目标指标 | 工具 | 判据（通过标准） |
|---|---|---|---|
| 报案受理 QPS 峰值 | 峰值 QPS 下 P95 ≤ 30s（≤5 份材料） | JMeter / k6 | 容量阈值 80% 预警不触发 |
| OCR 队列深度 | 峰值并发下队列 ≤ 阈值、无拒绝风暴 | 同上 + 队列监控 | 拒绝转人工率 ≤ X% |
| 决策图并发 | 自动通过/人工态混合并发 | 同上 | 决策图 P95 ≤ SLO；AI 降级不破资损 |
| 支付 TPS | 出款峰值 TPS | 同上 + 支付网关影子 | 资金差错率 = 0（§11.7） |
| 全租户调度 | `ReconciliationJob` 等全租户扫描 | 生产影子 | DB 连接池不耗尽、单租户不风暴 |

**压测报告必含**：实测峰值、容量阈值回填值、瓶颈点、扩容建议、与 99.9% 承诺的达成度。
**折叠动作**：将 §11.8 容量阈值表"目标值 + 预警阈值 80% + 压测判据"三列从"待压测"改为实测值 + 报告链接。
