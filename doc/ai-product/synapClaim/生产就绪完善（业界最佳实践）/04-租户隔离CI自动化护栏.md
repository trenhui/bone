# 04 · 租户隔离 CI 自动化护栏（ArchUnit + 反例测试）

> **目标态**：把《工程落地版》§3.3 已强的租户隔离**设计**（认证主体为权威 + 强制 `tenant_id` + OWASP A01 越权返回 403）从"靠人守"升级为"CI 直接失败"的自动化护栏，与既有 24 条 ArchUnit 同口径。
>
> **问题**：设计正确但无 CI 护栏——新增实体/端点时易回归（漏带 `tenant_id`、伪造 `X-Tenant-Id` 越权未被持续验证）。这是 P1-5。

| 控制 | 落地位置 | 说明 |

## 4.2 ArchUnit 规则（目标态，新增到 `com.bone.claim.archunit`）

> 与现有 24 条 ArchUnit 同包同跑（`mvn test` 触发）。以下为**草图（目标态）**，折叠进代码时须随包结构微调并通过编译。

```java
package com.bone.claim.archunit;

import com.tngtech.archunit.core.importer.ImportOption;
import com.tngtech.archunit.junit.AnalyzeClasses;
import com.tngtech.archunit.junit.ArchTest;
import com.tngtech.archunit.lang.ArchRule;

import static com.tngtech.archunit.lang.syntax.ArchRuleDefinition.noClasses;

@AnalyzeClasses(
    packages = "com.bone.claim",
    importOptions = ImportOption.DoNotIncludeTests.class)
class TenantIsolationRules {

    // R-TENANT-01：持久化层禁止绕过租户过滤器直出查询
    // 所有 *Repository / *Dao 的公开查询方法，必须位于受租户过滤器托管的包，
    // 或方法签名显式携带 tenantId / 经 TenantContextRunner 注入。
    @ArchTest
    static final ArchRule repository_must_not_expose_tenant_unscoped_query =
        noClasses().that().resideInAPackage("..adapter..persistence..")
            .should().haveOnlyMethodsWithoutTenantScope(); // 伪代码：实际用 methodName/annotation 断言

    // R-TENANT-02：禁止业务代码直接 new 跨租户查询（防隐式 CurrentTenant）
    @ArchTest
    static final ArchRule no_implicit_current_tenant_in_batch =
        noClasses().that().resideInAPackage("..application..")
            .should().callMethodWhere(
                m -> m.getName().contains("findAll") && !m.getOwner().isAnnotatedWith(TenantScoped.class));
}
```

> **务实替代（推荐先落地，零误报）**：与其做脆弱的方法签名断言，不如用**标记注解 + 强制**——所有 Repository 查询方法标注 `@TenantScoped`（或由基类 `AbstractTenantRepository` 统一实现），ArchUnit 仅校验"无 `@TenantScoped` 的公开查询方法不存在于 persistence 层"。误报可控，且与"认证主体为权威"同源。

## 4.3 集成反例测试（伪造租户头必 403，目标态）

> 落 `src/test/java/com/bone/claim/security/TenantIsolationAntiTest.java`，随 `delivery/07` 安全测试 + 24 条 ArchUnit 同跑。这是"关掉即红"的护栏（参考理算引擎防假绿思路）。

```java
@SpringBootTest(webEnvironment = RANDOM_PORT)
class TenantIsolationAntiTest {

    @Autowired TestRestTemplate rest;
    @Autowired TenantCredentialFactory cred; // 测试夹具：签发两租户 token

    @Test
    @DisplayName("伪造 X-Tenant-Id 访问他人案件 -> 403 (OWASP A01)")
    void forgedTenantHeader_mustBeRejected() {
        // 租户 A 的合法 token，但请求头伪装成租户 B
        var tokenA = cred.issueToken(tenantA, userA);
        var headers = new HttpHeaders();
        headers.setBearerAuth(tokenA);
        headers.set("X-Tenant-Id", String.valueOf(tenantB)); // 伪造

        var resp = rest.exchange(
            "/api/v1/claims/{id}", GET, new HttpEntity<>(headers),
            String.class, caseBelongingToB);

        assertThat(resp.getStatusCode()).isEqualTo(FORBIDDEN); // 403，非 200/404
    }

    @Test
    @DisplayName("同租户越权读他人案件 -> 按数据权限拒 (非 404 枚举)")
    void crossUserWithinTenant_mustBeDenied() {
        var tokenA = cred.issueToken(tenantA, userA);
        var headers = new HttpHeaders();
        headers.setBearerAuth(tokenA);
        var resp = rest.exchange(
            "/api/v1/claims/{id}", GET, new HttpEntity<>(headers),
            String.class, caseBelongingToOtherUserInA);
        assertThat(resp.getStatusCode()).isIn(FORBIDDEN, NOT_FOUND);
    }
}
```

> **回归防护**：该测试作为"反例必红"护栏——若有人去掉租户过滤器或放宽 `X-Tenant-Id` 校验，测试立即转红，CI 阻断。与 §3.3"认证主体为权威"设计形成"设计 + 测试"双保险。
