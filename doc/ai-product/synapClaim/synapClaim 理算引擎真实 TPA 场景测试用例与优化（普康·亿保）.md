## 0. TL;DR

- 基于普康（普康宝内置医保三大目录 + 医保分割信息自动理算）、亿保（智慧E保即时结算 / 直付预授权 / 鹰感风控）、泰康（甲乙丙类差异比例、年免赔累计抵扣、有社保未结算降比、等待期/责任免除拒赔）的真实条款，设计了 **14 个确定性场景用例**（已落 `ScenarioSuite.java`，全部可编译运行、带期望值断言）。
- 用例**实际跑出 1 个真实引擎缺陷**：年度限额原实现误用"相减"而非"封顶"，导致年限额内首案即被扣为 0 赔付。已修复为封顶语义，并用 S6b/S10 固化回归。
- 基于场景补全两类 proven 基线缺失能力：**商保直付预授权 `preAuthorize`**（亿保核心）、**拒赔建模 `status`/`rejectType`/`denyReasons`**（亿保前置核验 + 泰康责任免除）。
- 防假绿纪律延续：原有 `ProbeSuite`（11 变异探针 + 5 变异对照）与新 `ScenarioSuite`（14 场景）**全部绿色**；文档三机检（numbers/xref/contract_drift）保持绿色。

## 3. 用例倒逼的引擎优化

### 3.1 修复：年度限额"封顶"语义缺陷（真实缺陷）
**现象**：原 `settle()` 对年度限额采用 `net = net − limApplied`，使"年限额"被当成"免赔额"相减。例：年限额 1 万、单案 6000，正确应付 6000（≤限额），原实现却扣为 0。
**修复**：年度限额是**封顶**语义——
```java
limApplied = net.min(remainingLim);   // 本次占用 = 实际应付（取交）
net = limApplied;                     // 封顶，而非相减
```
免赔额仍保持相减语义（被保险人先自担）。该缺陷被 **S6b / S10** 用例捕获，`ProbeSuite.P11` 同步修正期望值（首案实付 900、次案实付 100）。

### 3.2 新增：商保直付预授权 `preAuthorize`（亿保核心能力）
对应亿保"就诊前核验 + 预算授权"。直付场景必须在就诊时给出"本次最多可直付多少"，结算时再真实占额。
```java
PreAuthResult preAuthorize(ctx, snap, estimatedTotal) {
    remainingDed  = max(0, annualDeductible − usedDed);
    remainingLim  = max(0, annualLimit      − usedLim);
    authByDed     = max(0, estimatedTotal − remainingDed);
    authorized    = min(authByDed, remainingLim, liabilityLimit, planRemaining);
    // 仅计算，不 commit 累计（预授权不占额）
}
```
S9 验证：预估 15000 − 年免赔 1 万 = 授权 **5000**；S10 验证授权额度 ≥ 实际结算净额（一致性护栏）。

### 3.3 新增：拒赔建模（亿保前置核验 + 泰康责任免除）
真实 TPA 必须有"拒赔"结论，而非永远付一点。新增：
- **整案拒赔**：`ClaimContext.denyReasons`（等待期/免责/指定医院外）→ `status=REJECT`，net=0，**不提交跨案累计**、占额 0，outbox 发 `REJECTED:`。
- **费用级拒赔**：`FeeConfig.rejectType`（目录外/免责项目）→ 该行 payout=0 并登记 `rejectType`，`ruleTrace` 记录拒赔原因。
- `IndemnityCalculation.status ∈ {PAY, PARTIAL, REJECT}`、`denied`、`denyReasons`、`AdjustmentLine.rejectType`。
- S11（等待期整案 REJECT）、S12（免责项目费用级拒赔）、S5（丙类目录外拒赔）共同固化。

### 3.4 可解释性升级
`explain()` 增加 `status` 行与拒赔原因行，满足监管告知 / 客户沟通（对应 P9 规则溯源）。
