建议判定实证原因与后续条件
P1-3 反洗钱 9 要素不支持新后端全仓无 AML/9要素实现：干系人实体 ClaimStakeholder 仅 person_id_hash / name_masked / phone_masked / bank_ref，无身份证明/常驻地址/职业字段；10000 阈值仅用于双人复核门；拒赔码字典无反洗钱项。且明文证件依 PIPL 不落库。后续条件：需先做 L3 评审（字段/存储/写入期校验/驳回码/阈值配置），不得前端单侧伪造校验。
P1-4 OCR 字段→影像 bbox 画框不支持理赔侧 OCR 结果仅 code/value/confidence/evidenceRef（文本偏移 text@12:8 或 image@code），pageNo/lineNo 恒 null；全仓 bbox 零命中。真实 bbox 能力在独立模块 bone-ai-document（BoundingBox{x1,y1,x2,y2}）但 synap-claim 的 pom 未依赖、端口注释明确列「二期」。后续条件：跨模块集成改造（加依赖 + 改 DocumentParsePort 契约 + 改落库 extracted_json + 改响应 DTO）。现有 evidenceLocatorsOf 无坐标返回空数组的诚实行为保持不变——补默认页就是幻觉。
P0-3 保存视图升级后端落库范围收口useSavedViews 的 localStorage 方案有明确设计理由（个人偏好、与权限无关、无消费方不建服务端表）。凭空造后端接口会违反「新增字段先找消费方」。本次把能真实交付的 URL 真源铺开到保单页，保存视图后端化留待有真实消费方时迁移。
P2-3 页面文案全量 i18n范围收口现状「错误码双语随 shell 切换 + 页面主体文案硬编码中文」。全量改造涉及 23 页数百处文案与双语翻译校验，且需要与业务术语表同步——不是本次增量能完成的，且错误码三处必齐门禁已在保护合规口径。保留半国际化现状，如实披露。
本次对暂缓项的重新取证（维持不做，不做≠遗漏）：曾重新评估「AML 只校验齐备性、不落明文」与「OCR 基于 evidenceRef 做字段→证据定位」是否有合规轻量路径，逐条核实后仍判定不可实施：① synap-claim 模块全仓 AML 关键字仅命中无关子串（如 YamlPropertySourceLoader），无任何字段 / 校验 / 驳回码 / 阈值配置，前端单侧校验没有消费方即假功能；② 前端 EvidenceResp 不返回 extractedJson，拿不到 OCR 文本原文，而 evidenceRef 是 text@offset 文本偏移；后端 AiAssessNodeHandler.locatorsOf 仅在 pageNo 非 null 时产坐标（解析层实测恒 null），现有 decisionExplain.ts 已消费 evidenceLocators 且有防幻觉测试。把文本偏移当影像页码展示即为坐标幻觉。两项的后续条件不变：AML 需 L3 评审，OCR 需跨模块接入真实 bbox。
