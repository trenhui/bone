## #2 双保单号命名（policy_no 平台号 + insurer_policy_no 保司号）

> ✅ **已落地（2026-11-03 续轮，用户授权越 L3/DDL 门禁）**：采用**方案 B 冗余列**，迁移 `0117_synap_claim_policy_insurer_no.sql`（幂等加列 insurer_policy_no + sp_verify_0117 终态断言）；`ClaimPolicy` 加 `insurerPolicyNo` 字段 + `assignInsurerPolicyNo()` 方法（**不改 open() 签名**以控爆炸半径）；`ClaimPolicyRepository.findByInsurerPolicyNo`；`ClaimConfigRequests.CreatePolicyReq` / `ClaimConfigApplicationService` / `ClaimConfigController` 透传；`bone-init.sql` 同批加列。方案 A（改锚）未采用（迁移面数倍）。

### 裁定
policy_no 保留为平台号；新增 insurer_policy_no 承载保司侧保单号。依据 §2.3 缺口 4：子表外键全锚在 policy_no 上，反向（以保司号为主键）迁移面是数倍。

### 现状锚点（grep 结论）
- `t_claim_policy.policy_no`（ClaimPolicy，line 64）
- `t_claim_case.policy_no`（ClaimCase，line 50）
- `t_quota_account.policy_no`（QuotaAccount，line 43）
- `t_quota_change_log.policy_no`（QuotaChangeLog，line 41）
- 查询侧：`ClaimPolicyRepository` 按 policy_no LIKE/等值检索；`QuotaAccountRepository` 行键含 policy_no。

### 改动面（待架构裁定两种方案）
- **方案 A（改锚）**：子表外键从 policy_no 改为 insurer_policy_no，policy_no 退为冗余/展示字段。
  - 优点：语义干净，保司号为主键。
  - 风险：**迁移面数倍**（所有子表外键 + 索引 + 既有查询改写 + 活库回填 insurer_policy_no 自 policy_no 映射），须配回归证据。
- **方案 B（冗余列）**：仅新增 insurer_policy_no 列，查询/匹配优先用 insurer_policy_no，policy_no 保留不动。
  - 优点：迁移面小，不破坏既有外键。
  - 风险：双号并存，须防不一致（写入期双写校验）。

### 迁移草稿（幂等，方案 B 视角）

  ADD COLUMN insurer_policy_no VARCHAR(64) NOT NULL DEFAULT '' COMMENT '保司侧保单号（§16-2）；policy_no 保留平台号';

### 实体草稿

- 即映射域已实质偏离软删约定——本裁定是把"既成事实"转正。
