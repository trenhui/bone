## 1 一句话结论

旧内核是「一个基数 → 扣免赔 → 乘比例 → 截断」的**标量四步**，只能表达「单责任单比例」。本次按 V1 重建为**分层管线**：
费用池（三池 × 医保内外）→ 比例多维查表 → 免赔六维 → 控额七层 → 次限额分组 → 不变量自证。
聚合 `Adjustment` 退化为外壳（状态机 + 快照 + 持久化），**金额计算零重复实现**。

同时把 V1 明确标注为〔缺〕的能力（定额/津贴给付、共享保额、先赔后赔、日限额、外部控额）改为
**装载期显式拒绝 + 受控原因码**——配置里出现了，系统会告诉你「这条责任不能自动理算」，而不是安静地照算一遍。

## 3 五个关键设计决策

### 3.1 费用池三池，而不是一个 base

旧内核 `base = Σ valid_amount`。这在单责任单比例下碰巧对；一旦「合理金额 90% / 自付二 80% / 总自费 70%」，
标量模型连正确的**输入**都表达不出来。故按 §3.6 拆三池，且每池再拆医保内外（§3.5）——
后者是 §4.3「范围内/外各自 min 后求和，再用责任额度截断」的前提；不分内外，某一类额度用尽会吞掉另一类的可用额。

### 3.2 旧配置映射为「免赔对象 = 发票费用」，而非 V1 默认

`t_adj_liability` 的 `pay_percent / liability_deduct` 是**历史配置模型**，它在原系统（reference-impl P16「免赔先于比例」）
里的语义就是「先减免赔再乘比例」。发票 1000、比例 80%、免赔 200：旧 640，V1 默认 600。

改这个数就是**改变所有存续保单的赔付金额**，属资金口径变更，须走条款报批，不能由代码升级顺手完成。因此：

- `LiabilityRule.fromLegacy(...)` → `Target.INVOICE_AMOUNT`（旧语义，`Adjustment` 走这条）；
- `LiabilityRule.simple(...)` → `Target.CALCULATED_AMOUNT`（V1 §6.3 默认，新配置走这条）。

两者是**同一引擎的两种配置取值**，不是两套算法——`DeductibleEngine.apply` 只有一份，
顺序由 `AdjustmentEngine.applyDeductible` 按 `Target` 分支编排。

### 3.3 控额只有一份实现

第一版实现里 `AdjustmentEngine.MutableQuotaPool` 自己写了一遍 min + pro-rata，`QuotaStack` 成了死代码。
这正是「两套实现」的典型形态——**测试全绿也发现不了**，因为两条路径在单费用池场景下结果相同。

已收敛：`MutableQuotaPool` 只做两件事——把费用池翻译成控额分组、把本次消耗回写到跨组共享的额度账本；
分层截断与分摊全部委托 `QuotaStack.cap`。变异验证见 §6。

### 3.4 相对免赔的 `deducted` 记 0，不记满额

I5 的语义是「够了就**一分不减**」。若跳档时仍把「已用免赔」记成满额，账面会虚增一笔从未抵扣的钱。
相对免赔下 `deducted = 0`、`remainingAfter = 0`（门槛已达成）：次案的判断结果一致（仍然跳档），但账面不撒谎。

### 3.5 不变量写在引擎里，不只写在测试里

`InvariantGuard` 在**每一个真实赔案**上校验：Σ 明细实付 ≡ 总额（I1）、赔付 ≤ 责任剩余（I2）、
免赔消抵 ≤ 剩余可抵扣（I4，含 0.01 × 行数的取整容差）、各成分非负。
抛 `IllegalStateException`（程序缺陷）而不是 `RuleGap`（配置缺失）——混用会让真实缺陷被当成业务数据问题降级处理。

## 4 语义变更与影响面

| 项 | 变更前 | 变更后 | 影响 |
|---|---|---|---|
| 计算基准 | 单标量 Σ valid | 三池 × 医保内外 | 多费用类型可按各自比例赔 |
| 免赔类型 | 仅绝对 | 绝对 + **相对**（跳档） | 达门槛客户不再被白扣（I5） |
| 免赔对象 | 固定「先免赔后比例」 | 两种可选，旧配置保持原口径 | 旧数据零变更；新配置可用 V1 默认 |
| 免赔粒度 | 仅责任级 | 责任级 / **费用类型级** | §5.5 示例 A(3) 可配 |
| 免赔方式 | 仅年度 | 年度 / 次（天数显式拒绝） | 按次免赔可用 |
| 免赔抵扣 | 未建模 | 三口径（`effectiveUsed` 收口） | 医保/三方是否填满免赔可配 |
| 赔付比例 | 单百分数 | 多维查表（费用类型 × 医保赔付 × 累计区间 × 票额 × 医院等级 × 病种） | 条款里「1000 元以上赔 70%」可表达 |
| 控额层数 | 2 层（个人/责任） | **7 层**（项目/类型/次/共保/责任/险种/计划） | 团体保单不再穿透计划总额 |
| 次限额 | 无 | 六档分组（先分组、各组独立理算） | 多日门诊不再被总额 min 少赔 |
| 归因 | 1 条汇总行 | 每费用池 1 行 + 六成分金额 + 分支/命中键 | 拒赔五要素可举证 |
| 缺口处理 | 静默按默认值 | 装载期 `RuleGap` + 原因码 | 配置缺失不再变成错金额 |

零赔付归因新增 `ZERO_LIMIT_EXHAUSTED` 与 `ZERO_NOT_COVERED`，并修正一处错判：
免赔（对象=发票费用）把基数扣到 0 时，比例后金额也是 0，旧判断会先命中「比例为 0」而误报 `ZERO_REASONABLE`。
现按「免赔吃光 → 比例 0 → 合理费用 0」的顺序判定。
