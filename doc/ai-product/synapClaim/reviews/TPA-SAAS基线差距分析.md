**结论：这是一套"把人工流程搬进可配置系统"的扎实底座**，不是智能系统。

- **已有（要在 synapClaim 保留的部分）**：`保单 → 计划 → 险种 → 责任` 四级要素化配置；免赔 / 赔付比例（含赔案累计区间）/ 控额（个账·公账·直付）均可配；流程各环节可开关；数据字典覆盖理赔主链路；选项集支持版本与映射。
- **缺失**：全流程（签收/初审/录入/质检/审核/复核）仍以人工为主；理算逻辑硬编码、公式仅展示不驱动；无独立规则引擎、流程引擎、反欺诈、大模型审核与直通处理（STP）；主数据（医院库/疾病库）映射未完成。

## 2. 差距分析（现状 → 最佳实践 → 落点）

| 维度 | TPA-SAAS 现状（文档实证） | 业界最佳实践 | 目标态落点（真源） |
|---|---|---|---|
| 录入 | 纯人工 DTO 逐字录入 | OCR + 多模态自动填充，低置信转人工 | PRD §7 / 工程落地版 §7.2 |
| 签收 / 初审 | 影像人工分类、Excel 区分、医保模板未统一 | 视觉自动分类 + 完整性预检、渠道归一化 | 工程落地版 §7.1 / §7.2 |
| 理算 | 硬编码、公式仅展示不驱动；多责任/跨保单累计算法缺失 | 规则引擎驱动、聚合累计 + 回滚全闭环 | 工程落地版 §5.1 / §7.4；《理算引擎设计》 |
| 责任配置 | 四级模型完善但规则非机读 | 规则 DSL 化、热更 + 回归门禁 | 工程落地版 §5.2 / §8 |
| 流程 | 环节可开关但无智能路由 | 风险分层 STP 路由 + HITL | 工程落地版 §7.3 |
| 自动结案 | 固定阈值（≤3000 / 单保单 / 非住院） | 风险分层 STP，动态扩面 | 工程落地版 §7.5 |
| 反欺诈 | 7 条规则，无图 / 视觉 / 多模态 | 图 + 视觉 + 多模态 + 100% 质检 | 《风控与支付通道设计》§1–2 |
| 审核 | 21 条硬编码校验 + 人工决策 | 规则引擎 + AI 秒级建议 + 人工确认 | 工程落地版 §7.3 / §7.6 |
| 推送支付 | 渠道 / 重试 / 幂等未定义 | 状态机 + 四向对账 + 直付通道 + 未知态补偿 | 工程落地版 §7.5 / §11.7；《风控与支付通道设计》§4 |
| 数据模型 | 无独立责任 / 理算实体、治理粒度粗 | 独立责任 / 理算实体 + 字段级治理 | 工程落地版 §9.1 / §9.5 |
| 多租户选项集 | 前五排序、缺租户级自定义 | 租户级自定义 + 独立版本 + 字段级扩展 | 工程落地版 §9.2 |
| 主数据 | 医院库 / 疾病库映射待确认 | 内置三大目录 + ICD-10 + 医疗机构库底座 | `delivery/06-医学目录库建设方案` |
| 合规治理 | 无 AI 治理、无算法备案 | NAIC / 金发 8 号 + MRM + 审计链 | 工程落地版 §11.3；《生产就绪完善》01/05 |

## 3. 保留的护城河（与《业界对标整改台账》一致，不重复论证）

确定性分层（AI 不碰钱）· 拒赔人工确认 + 五要素通知书 · 规则热更 + 评测回归门禁 · 私有化信创 + 数据不出域 · 双阈值熔断独立字段 · 资金两段式幂等 + 四向对账 + 乐观锁 · 发票唯一性硬约束 · 排期自欺防火墙。后续所有新增能力均须遵守上述纪律。
