# synapClaim 业界对标整改台账（业界最佳实践）

> 本文档基于业界领先智能理赔系统（平安产险、众安、泰康在线、普康宝/普康 TPA、太保、国寿）的实践，对 `synapClaim` 现有方案（PRD / AI 技术方案 / 工程落地版 / Rulebook / 创业方案）做**对标诊断 + 已落地整改**的固化。
>
> **核心结论先行**：本方案的"工程纪律"已属上乘、是护城河，**保留不动**；问题集中在**产品范式与若干能力域落后于 2026 年行业前沿**——而这两点恰是理赔 ROI 与资金风险的核心。本方案的执行口径是：**把最高 ROI 的能力从 V2/V3 提前到 V1.0（Phase B），且不破坏 MVP 的排期纪律（不把图数据库/视觉反诈塞进 I0–I4）**。

---

## 一、保留项（护城河，明确不改）

以下能力是 `synapClaim` 相对行业通病的**差异化优势**，已与 IBM Business Automation、金发〔2026〕8 号、暖哇×华为实践方向一致，**全部保留**：

|**保留项**|**出处**|**为什么是护城河**|
|---|---|---|
|确定性分层：AI 只出 `AiSuggestion`，金额/资金全在确定性代码|工程落地版 §2 硬约束"AI 不碰钱"|可审计、零资金差错；大模型幻觉不传导到钱|
|拒赔必须人工确认 + 五要素结构化通知书|Rulebook R-MAN-03 / PRD §7.3|合规可解释，避免监管风险|
|规则热更 + 评测集回归门禁（30 秒生效，字段/规则/复核率不下降才可发布）|Rulebook §一 / 工程落地版 §8.2|业务敏捷且不破确定性|
|私有化信创 + 敏感数据不出域（本地 vLLM）|PRD §13 / MVP §六|金融合规刚需|
|双阈值熔断相互独立（`ocr_confidence` / `ai_confidence` 独立字段）|Rulebook R-MAN-01 / 工程落地版 §2|防"假绿"——单一阈值掩盖另一路失效|
|资金两段式幂等状态机 + 四向对账 + 乐观锁（`@Version`，禁 `FOR UPDATE`）|工程落地版 §5/§7.5/§11.7|资金零差错硬保障|
|发票唯一性硬约束 `uk(tenant_id, invoice_code, invoice_no)` + 防枚举 409|Rulebook R-FRAUD-07 / 工程落地版 §8.2|反欺诈第一道不可绕过硬墙|
|排期自欺防火墙（§3.3 容量校验矩阵：超载必须落到增人/延期/砍范围）|MVP §3.3|防止"靠并行消化"式虚假排期|

> **纪律一致性要求**：本次所有整改均遵守上述纪律——新增能力走"确定性规则 + AI 建议"分层，不碰资金；新增评测样本入回归集；不把超 MVP 容量的工作伪装进 I0–I4。

## 三、整改项（已落地到文档）

> 标注 **[已落地]** 的条目已完成文档改动（含 file:line 指针）；未标者为本方案建议、待排期。

### P0-1　范式升级：数据直连 + 院端直付提至 V1.0 主路径

**现状证据**
- `PRD §14` V1.0 行原为"住院理赔扩展、医院端直付对接（HIS/医保通道）…"；`PRD §14（直付演进注）` 原注"MVP 为报销模式快赔；医院端直付列为 V3+ 演进"。
- `MVP §1.2` 原列"医院端直付、医保通道对接（V3+ 演进）"。
- `工程落地版 §10.4（与 pk-tpa-saas 集成）` 原注"一期不接医保局与银行网关"。

**问题**：OCR 报销是成本中心不是价值中心；"垫付-等待-报销 3–7 天"是体验痛点根源。原设计把普康宝式老 TPA 外包范式照搬，未继承其"医保三大目录 + ICD-10 + 医疗机构库 + 直付"底座，等于用最重链路做最薄增值。

**业界证据**：泰康一站式结算 1000+ 医院签字即走；众安医疗数据直连 70% 自动化理算、15 秒结案；普康宝本身即带直付。

**整改（已落地）**
- `PRD §14` V1.0 行改为："① 院端直付试点（**经保司/TPA 通道，非自建医保局网关**）+ 医保/医院数据直连探索；…"；新增反欺诈升级、100% 质检、MRM、临床合理性底座。
- `PRD §14（直付演进注）` 重写为"直付演进（2026-10-26 修正）"：MVP 保留报销兜底，院端直付**从 V3+ 提前为 V1.0 试点主线**，经保司/TPA 通道接入，V2 再做 HIS/医保规模化；一期即内置普康宝式三大目录+ICD-10+医疗机构库底座。
- `MVP §1.2` 重分类：医院端直付由"V3+ 演进"改为"V1.0 经保司/TPA 通道试点；HIS/医保局深度直连留 V2"。
- `工程落地版 §1.2` + `§2048` 增加 V1.0 通道演进注：MVP 维持报销+mock 网关兜底，V1.0 经保司/TPA 通道做直付试点，不要求自建医保局/银行网关。

**落地 delta（V1.0）**
- 一期（MVP）必建**知识底座**：医保三大目录（甲/乙/丙）+ ICD-10 + 全国医疗机构库（见 delivery/06，已标 V1.0）。
- V1.0 直付试点：对接保司/TPA 既有直结能力，复用普康宝式内部账户；直付成功率/时效纳入 KPI。

### P0-2　反欺诈体系升级：图 + 视觉 + 多模态（最大资金风险敞口）

**现状证据**
- `Rulebook §九` 仅 R-FRAUD-01~07 共 7 条（同人同日同院同额、3σ、时间轴、发票-清单差额、团伙 V2 单维、验真、唯一性）；无团伙网络、无设备指纹、无关系图谱、无影像相似度、无跨案件关联。
- `AI 技术方案 §13` 把反欺诈当"验真失败/重复报销转人工"。

**问题**：理赔是欺诈重灾区（IAIS：全球 20–30% 赔款涉欺诈；车险占 90%+）。单证上传范式恰是 PS 发票、重复报销、搭车收费温床，而原防线最薄（7 条 vs 平安 208 条）。

**业界证据**：平安财险 13 模型+208 规则；太保知识图谱+图计算（团伙>60%）；泰康关系图谱+影像特征检索；众安图像+语音+关系图谱联合破案；国寿"识图"影像相似度百万级。

**整改（已落地，Rulebook）**
- 新增 **R-FRAUD-08 影像相似度检索**（对标国寿"识图"）：pHash/aHash + 特征向量跨案件检索，相似≥0.92 且非同案件→标记重复/PS/翻拍。
- 新增 **R-FRAUD-09 关系图谱 + 设备指纹团伙识别**（对标太保/泰康/众安）：人-案件-机构-设备-代理人-受益人图谱 + 图计算社区发现 + 设备指纹；与 R-FRAUD-05 融合输出团伙风险分。
- 新增 **R-FRAUD-10 知识图谱一致性推理**：诊断-用药-诊疗-时间轴矛盾推理（与 R-DIR-06 互补）。
- 新增 **R-FRAUD-11 跨案件关联网络**：同被保险人/证件/手机/收款账户/地址聚合，识别化整为零、一人多赔。
- **R-FRAUD-05 由 V2 单维标记升格为 V1.0 图计算团伙识别**（多维权）。
- `Rulebook §十` 评测清单同步要求 R-FRAUD-08~11 每类 ≥3 正/反例。
- `PRD §14` V1.0 行、delivery/06 §七 均引用上述规则作为反欺诈底座。

**落地 delta（V1.0）**
- 引入图数据库（轻量 NebulaGraph/TuGraph，或 TiDB 图计算）+ 设备指纹服务 + 影像指纹向量库（TiDB Vector / Milvus）。
- 团伙高置信→P0 强制转人工并进入风控专项（沿用 §七 P0 裁决优先级，已覆盖 `R-FRAUD-*`）。

### P1-1　医学目录 / 临床合理性底座提至 V1.0（原 V2）

**现状证据**
- `Rulebook §三` R-DIR-01~05 依赖"医保目录库"，但库本身 V2 才建（`delivery/06` 原标"持续维护资产"）。
- `MVP §1.1` 仅做责任范围规则匹配，无临床合理性。

**问题**：门诊小额渗漏主因是搭车收费、过度医疗、诊断-用药不匹配。无目录则理算只能判"责任内按比例"，无法判"该不该赔"。

**整改（已落地）**
- `Rulebook §三` 新增 **R-DIR-06 诊断-用药-诊疗合理性**：适应症矛盾、超量、时间轴倒置、搭车收费→标记人工复核档（不自动拒赔）。
- `delivery/06` 升格为 V1.0 必建，新增 §七"临床合理性与反欺诈数据底座"，强制纳入全国医疗机构库 + 诊断-用药适应症映射 + 用药剂量常识表。
- `工程落地版 §1.2` 注：临床合理性（R-DIR-06）前置到 V1.0。

### P1-3　后督质检：5% 抽检 → 100% AI 质检

**现状证据**
- `PRD §7.3（后督巡检）` 原"每日抽检比例≥5%"；`MVP §4.3` 后督抽检任务"结案案件抽检 ≥5%"。

**整改（已落地）**
- `PRD §7.3（后督巡检）` 改为"**V1.0 升格：自动通过/系统建议拒赔结论 100% AI 后督质检（高风险全量）；人工抽检作补充（≥5%）**"，理由：众安已落地全量 100% AI 质检动态风险屏障。
- `MVP §4.3` 维持 MVP 口径（≥5% 抽检闭环），V1.0 升格在 PRD §14 已声明——**不挤占 MVP I0–I4 排期**。

### P1-5　模型风险管理（MRM）治理闭环（原缺失）

**现状证据**：方案仅 300 条评测集 + 提及合规，缺 model cards、漂移监控、champion/challenger、公平性/偏差监测、可解释报告自动化。监管要求：金融监管总局《银行业保险业人工智能安全开发应用指导意见》32 项 + 金发〔2026〕8 号。

**整改（已落地 PRD §14 声明，详细见本节）**
V1.0 建立 MRM 闭环，最小集：
1. **模型卡片（Model Card）**：每个 OCR/NLP/风控模型登记用途、训练数据来源、已知偏差、适用边界。
2. **在线漂移监控**：输入分布漂移（PSI）、输出置信度分布、拒赔/通过率异常波动 → P1 告警。
3. **Champion/Challenger**：新模型影子运行（Shadow）对比冠军模型指标，达标才切流（复用三态开关 Shadow/Assisted/Automated）。
4. **偏差/公平性监测**：按机构等级、性别、年龄维度监控理算/拒赔差异，防歧视性偏差。
5. **可解释报告自动化**：每次自动决策附带五要素证据链 + 模型贡献度说明（复用决策 trace §7.3）。
6. **评测集飞轮**：难例自动挖掘 + 影子学习回流（见 P2-2），评测集从 300 条滚动扩充。

## 五、自动化率口径校准（防"假绿"）

原目标 80%（POC60/MVP70）偏保守但务实。务必区分三口径，避免对外承诺虚高（贴合文档一贯"防假绿"纪律）：

|**口径**|**定义**|**适用阶段**|
|---|---|---|
|自动决策率|AI 给出建议结论（含人工确认后生效）占比|Phase B 起可报|
|自动支付率|无需人工介入直接打款/直付占比|Phase C 放量后测量|
|零人工介入结案率|端到端无人工触碰结案占比|规模化稳定期测量|

> 不把"自动决策率"等同于"自动化率"对外承诺；生产口径与评测集口径（离线）分列，Phase A/B 仅报评测集口径（PRD §15 已定）。

## 六、风险与回退

|**风险**|**缓解**|**回退**|
|---|---|---|
|V1.0 直付试点保司/TPA 通道不稳|多通道备用 + 本地缓存 + 熔断降级为垫付转人工（PRD §16.1（主要风险））|退回报销快赔兜底主路径|
|图/视觉反诈引入新依赖（图库/向量库）超容|轻量起步（TiDB 图计算/Vector），超限切 NebulaGraph/Milvus；独立 `bone-ai-*` 扩容不拖主链路|相关结论转人工，不阻断 MVP 链路|
|临床合理性误标导致复核率上升|R-DIR-06 仅标记不自动拒赔；评测集覆盖常见变体|调低灵敏度或回退纯目录判定|
|MRM 监控误报扰民|漂移告警设缓冲窗口 + 人工确认|关停自动切流，维持冠军模型|
