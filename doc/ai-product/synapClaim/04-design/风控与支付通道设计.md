# synapClaim 风控与支付通道设计（视觉反诈 · 图计算 · MRM · 直付）

> **定位**：决策图 `FraudScreen` 与 `Adjust` 直付分支的**横向能力设计**。本文合并原先两份文档——《反欺诈增强设计（视觉 E1 + 图计算 E2）》与《MRM 与直付通道增强设计（E4 + C10）》。合并理由：它们都是"接入平台横向能力、最终都收敛到同一条治理闭环（模型过门禁 → 反诈命中 → 额度熔断 → 降级转人工）"，分列会导致同一条闭环被写两遍且口径不一致。两篇原在文档族内**零引用**，合并后才能被设计层正常索引进评审。
>
> **对齐**：`platform/`《BONE-AI 能力中台整体方案》C12-visual / C12-graph / C7 / C10；规则 ID 见 `07-delivery/04-业务规则书` R-FRAUD-05/08/09/10/11。
> **定位与节奏**：V1.0 Phase B 增量，不挤占 MVP I0–I4 容量矩阵；所有命中走"系统建议 + 人工确认"（`SUGGEST_REJECT`），**AI 不碰钱、不自动拒赔、不自动放款**。
> **铁律**：synapClaim domain 仅经 `VisualForensicsPort` / `GraphFraudPort` / `EvaluationPort` / `IntegrationPort` 消费能力，禁止直接 import `bone-ai-visual` / `bone-ai-graph` 任何类。

---

## 0. 范围与契约落点

| 增强项 | 平台能力 | 承载规则 | 决策图节点 | 端口 |
|---|---|---|---|---|
| E1 视觉反诈 | C12-visual（平台新增） | R-FRAUD-08 | `EvidenceLoad`(视觉) + `FraudScreen` | `VisualForensicsPort` |
| E2 图计算反欺诈 | C12-graph（平台新增） | R-FRAUD-05(升格)/09/10/11 | `FraudScreen` | `GraphFraudPort` |
| E2 预警闭环 | C9 提醒预警 | 命中即预警 | `FraudScreen` | `NotificationPort` |
| E4 模型风险管理 | C7 评测门禁（增强） | — | 全 AI 节点 | `EvaluationPort` + `TracePort` |
| C10 直付三态灰度 | C10 集成三态灰度 | R-FAST-02 | `Adjust` 直付分支 | `IntegrationPort` + `LedgerPort` |

> **为什么先做 E1/E2**：理赔欺诈损失中"重复报案 / PS 翻拍 / 团伙聚集"占比最高，且二者是 Net-new 能力（既有 R-FRAUD-01~07 仅覆盖单案规则）。行业实证：平安财险以 13 模型 + 208 规则构建反诈体系；太保/泰康用关系图谱做团伙识别；国寿"识图"以影像相似拦截重复报案；众安以"图像 + 关系图谱"联合反诈。本设计对齐该范式，把最成熟的两条能力从 V2 提前到 V1.0 Phase B。

## 1. E1 视觉反诈（R-FRAUD-08）

### 1.1 能力分解

| 子能力 | 方法 | 输出 |
|---|---|---|
| 感知哈希 | pHash（DCT 低频）/ aHash / dHash 三路，对关键区域（发票代码区、金额区、印章区）分别取哈希 | 64-bit ×3 指纹 |
| 特征向量 | 轻量 CNN（私有化部署）提取全局 + 区域特征，维度 512 | 向量 `feature_vec` |
| 篡改检测 | ELA 高残差区、噪声一致性、JPEG 8×8 网格边界不连续、EXIF 与内容矛盾 | `tamper_score` 0–1 |
| 跨案相似检索 | 指纹库（按 `tenant_id` 隔离）pHash 汉明距离 Top-K + 向量库余弦 Top-K，融合排序 | 相似源案件清单 + 相似度 |

**业界锚点**：国寿"识图"（票据/病历影像指纹跨案检索，拦"一票多赔"）；众安（ELA + 噪声一致性 + 跨案检索）；平安（JPEG 网格、EXIF 异常、生成式修补痕迹）。
**经验区间**（以本平台标注集实测校准，非承诺值）：医疗理赔中翻拍/PS 类可疑影像行业经验占比约 3%–8%，团伙案中跨案复用影像比例显著更高——故"跨案相似度"是最高 ROI 信号。

### 1.2 端口契约

```
VisualForensicsPort
  入参 ImageForensicQuery { tenantId, caseId, docType, imageRef, regionHints? }
  出参 ForensicHit {
         phashA/phashD/phashH, featureVecRef,
         tamperScore,                       // 0–1，≥阈值标记疑似篡改
         similarCases: List<SimilarCase{ caseId, similarity, sameInvoice? }>,
         hitRules: Set<R_FRAUD>,            // 如 R-FRAUD-08
         confidence, evidenceRef            // 落 C4 trace 的引用
       }
  失败语义：不可达 → 抛 VisualForensicsUnavailable，调用方降级（§1.5）
```

### 1.3 数据模型与索引

```
forensic_image_hash (
  tenant_id BIGINT, case_id VARCHAR, evidence_id VARCHAR,
  doc_type VARCHAR,            -- INVOICE / LIST / MEDICAL_RECORD
  phash_a / phash_d / phash_h VARCHAR(16),
  feature_ref VARCHAR,         -- 向量库外部键
  created_at DATETIME,
  PRIMARY KEY (tenant_id, evidence_id),
  INDEX idx_tenant_doctype (tenant_id, doc_type)
)
```
向量索引建在外部向量库，按 `tenant_id` 分片保证隔离与不出域；影像仅在租户私有存储与私有化模型内处理，指纹/向量不跨租户。

### 1.4 SLA / 容量 / 成本

| 项 | 参数 | 理由 |
|---|---|---|
| 单份感知哈希 | < 5ms（CPU） | 三路哈希纯计算，可批处理 |
| 向量抽取 | < 300ms/份（GPU 轻量模型，无 GPU 退 CPU 约 1s） | 仅在 `EvidenceLoad` 后异步触发 |
| 跨案检索 | < 200ms（Top-K=20） | 限 K 防规模爆炸 |
| 触发时机 | 锁定证据后**异步**批量送视觉，不阻塞主链路；`FraudScreen` 取已算结果 | 不拖垮理赔主链路 |
| 容量上限 | 单案 ≤20 份、单份 ≤10MB | 与 `ATTACHMENT` 纪律一致 |

### 1.5 评估与降级

- **标注集**：每类正例 ≥50（重复报案 / PS 翻拍 / 篡改），反例 ≥200（真实不同案件的不同发票）。
- **指标**：`@阈值0.92` 的 P/R/F1 + 阈值扫描曲线（0.85–0.97）。
- **负向探针（证明"测到"而非"跑通"）**：① 同一张真实发票重新上传（同案）→ 相似度 1.0 但 `sameInvoice=true`，**不**误标重复报案；② 换一张完全不同真实发票 → 相似度 <0.5，不命中；③ 随机高斯噪声图 → `tamper_score` 高但 `similarCases` 空，仅标疑似篡改转人工。
- **门禁**：F1 ≥ 0.85 且误伤率 ≤1%，否则规则不启用、退回阈值从严。
- **降级**：端口超时（>1.5s）→ 跳过视觉分支，降级单案规则路径（R-FRAUD-01~07）转人工；视觉**仅产建议**，命中一律 `MANUAL_REQUIRED` + 升级风控岗，**绝不自动拒赔**。阈值取保守值（0.92）：宁可漏过（转人工）不可误伤客户。

## 2. E2 图计算反欺诈（R-FRAUD-05 升格 / 09 / 10 / 11）

### 2.1 图模型（租户隔离为核心约束）

- **节点**：`Person`（被保险人/受益人/代理人）、`ClaimCase`、`Institution`（医院/药店）、`Device`（上传终端指纹）、`Account`（收款账户）、`Address`、`IP`。
- **边**：`PERSON-申报->CLAIM`、`CLAIM-收款->ACCOUNT`、`PERSON-就诊->INSTITUTION`、`CLAIM-使用设备->DEVICE`、`DEVICE-同指纹->DEVICE`、`PERSON-同地址->ADDRESS`、`ACCOUNT-聚集->ACCOUNT`。
- **隔离**：`tenant_id` 作为图分区键（NebulaGraph `tag partition` / TuGraph 属性过滤），所有查询带 `tenant_id` 谓词。

### 2.2 能力分解

| 子能力 | 方法 | 承载规则 |
|---|---|---|
| 设备指纹 | 终端特征（UA/分辨率/Canvas/时区）+ IP + 设备绑定历史 | R-FRAUD-09 |
| 社区发现 | Louvain / 连通分量，对"人-案-机构-设备-账户"子图聚类，输出社区 ID 与模块度 | R-FRAUD-09 / 05（升格） |
| 中心性 | PageRank / 度中心性识别枢纽人物/机构 | R-FRAUD-09 |
| 跨案关联 | 同被保人/证件/手机/收款账户/地址的多案聚合，识别"化整为零""一人多投多赔" | R-FRAUD-11 |
| 知识图谱一致性 | 医学目录底座 + 理赔知识图谱，推理"诊断-用药-诊疗-时间轴"矛盾 | R-FRAUD-10（与 R-DIR-06 互补） |

**业界锚点**：太保/泰康关系图谱团伙识别；众安关系图谱 + 设备指纹；蚂蚁"蚁盾"设备指纹 + 关系网络评分；银行图计算反洗钱（子图同构/PageRank 识别资金回路，理赔可借鉴"收款账户聚集"）。

### 2.3 端口契约与选型

```
GraphFraudPort
  入参 GraphFraudQuery { tenantId, caseId, personIds, accountIds, deviceFingerprint?, institutionIds? }
  出参 GraphFraudHit {
         communityId?, riskScore,            // 0–1 团伙风险分
         relatedCaseIds: List<caseId>,
         hitRules: Set<R_FRAUD>,             // R-FRAUD-05/09/10/11
         deviceCluster?, consistencyConflicts?, evidenceRef
       }
  失败语义：图库不可达 → 抛 GraphFraudUnavailable，降级单案规则路径
```

| 选型 | 适用 | 备注 |
|---|---|---|
| **NebulaGraph** | 大规模、高并发、分布式 | 国产开源，信创友好，**生产主选** |
| **TuGraph** | 中小规模、单机/轻量 | 国产，事务图，适合试点 |
| 轻量兜底 | Neo4j 社区版 / TiDB 图计算 | 仅试点期或无法署 Nebula 时；不推荐长期（栈分裂） |

- 部署：私有化、数据不出域；图库与向量库同可用区。
- **不为想象规模预付**：Phase B 先以单租户子集 + 近 90 天窗口构图，跑通再扩全量。

### 2.4 实时 vs 离线

- **实时**（案件提交时）：增量写节点/边 → 局部邻域查询（该人/账户/设备的 Top-K 邻居、同设备账号数）→ 输出 `riskScore` + `relatedCaseIds`，延迟预算 <500ms。
- **离线**（每日）：全量社区发现、团伙聚类、PageRank 重算，结果写回供实时参考；离线失败不影响实时降级路径。

### 2.5 评估与降级

- **标注团伙集**：运营沉淀的已知骗保团伙（≥10 簇）为正例，随机无关案件簇为反例。
- **指标**：社区发现 NMI / ARI、团伙召回率、设备聚集识别准确率。
- **负向探针**：① 随机编造无关案件 → 不应成团（`riskScore` <0.3）；② 同一人正常多案（逐年续保不同疾病）→ 不误判（靠"高额聚集 + 材料相似 + 设备聚集"多维权，而非单纯多案）；③ 注入 10% 噪声边 → 模块度下降但核心团伙仍召回（证明鲁棒）。
- **降级**：超时（>2s）→ 跳图分支转人工；高置信团伙（`riskScore ≥0.8` 且社区规模 ≥3）→ **P0 强制转人工** + 风控专项，`FRAUD` 挂起**不设自动恢复**；命中经 `NotificationPort`(C9) 多级预警。

## 3. E4 模型风险管理（MRM，增强 C7）

### 3.1 模型卡（唯一准入门槛）

```
ModelCard {
  modelId, version, owner,                  // 责任人，非"AI 团队"泛称
  purpose,                                  // 预期用途与边界（如"仅门诊小额快赔 AiAssess 建议"）
  dataLineage,                              // 训练/标注数据源、时间窗、脱敏方式
  inputOutputSpec, metrics: { precision, recall, f1, falseRejectRate, falseApproveCost },
  biasAssessment,                           // 分群（年龄/地区/产品）差异与告警阈值
  limitations,                              // 不适用场景（高额、非门诊）
  driftPolicy, signoff                      // 风控 + 合规 + 技术三方签字
}
```
- 所有进入 `AiAssess` / `FraudScreen` 的模型（含视觉 E1、图 E2、LLM 评测）**必须有模型卡方可启用**。
- 模型卡存 `bone-ai`(C7)，synapClaim 仅持 `modelId`，经 `EvaluationPort` 取评测态。

**业界锚点**：银保监/央行模型风险管理（SR 11-7 类，模型须"卡 + 验证 + 持续监测 + 退出"全生命周期）；金发〔2026〕8 号（可解释、可人工复核、可审计）；Google Model Cards / EU AI Act 高风险（元数据与偏差评估强制登记）；平安/招行"上线前评测门禁 + 上线后月度漂移 + champion-challenger"。

### 3.2 评测门禁（CI 不可绕过）

- **负向探针**：每个模型门禁须含"删掉实现哪一行会红"的对抗用例；RAG 检索须**真实执行断言**，而非仅比对生成 SQL 文本。
- **门禁项**：精度/召回达标（F1 ≥0.85）、误伤率 ≤1%、内容安全（复用 C8）零高危漏检、可解释字段完整。
- **失败即阻塞**：门禁不过 → 端口返回 `ModelNotCleared`，调用方降级转人工。

### 3.3 漂移与 champion-challenger

| 漂移类型 | 监测 | 动作 |
|---|---|---|
| 数据漂移 | PSI >0.2 告警、>0.25 阻塞 | 触发重训评审 |
| 概念漂移 | 线上精度周环比下滑 >5% | 暂停自动建议，退回人工 |
| 性能漂移 | 端到端 P95 超 SLA | 告警 + 降级 |
| 偏差 | 分群指标差异超阈值 | 合规复核 |

- **champion-challenger**：新模型先在 `Shadow` 与现模型双跑，一致率 ≥ 阈值且不劣化，再升 `Assisted`；灰度比例经 `feature_toggle` 外置，改比例不发版。
- 监测数据来自 `TracePort`(C4) 决策轨迹 + `EvaluationPort`(C7) 评测回流。

### 3.4 治理工作流与退出

模型登记（卡）→ 评测门禁（CI 阻塞）→ Shadow 双跑 → Assisted 灰度 → 全量（仍保留人工确认护栏）→ 漂移触发退出/重训。
退出机制：弃用须在 `ModelCard.signoff` 记录，端口返回 `ModelDeprecated`，调用方降级。

> **与阈值的关系**：模型重训后**必须重新校准阈值**，禁止"换模型不换阈值"。置信度校准（ECE ≤0.05 才允许调参）与三档阈值映射见 `08-go-live/05-生产成熟度增强` §5.1。

## 4. C10 直付通道（三态灰度）

### 4.1 三态灰度

| 态 | 行为 | 资金动作 | 升阶条件 |
|---|---|---|---|
| `Shadow` | 仅旁路计算直付建议，不实际出款 | 无 | 建议与人工结论一致率 ≥99% 且零资损样例 |
| `Assisted` | 出款前需人工确认（类型护栏 `Confirmed`） | 出款 | 误拒/误付率 ≤ 阈值且 MRM 漂移达标 |
| `Automated` | 高信任客户免单证直赔，系统直出 | 出款（仍受 C11 额度 + 反诈熔断） | 任何异常 → 回退 `Assisted` |

三态经 `feature_toggle` 外置，**改态不发版**；默认 `Shadow`，**禁止默认 `Automated`**（合规前置，ADR-1 / 金发 8 号）。

> **本平台约束**：V1.0 **经保司/TPA 既有通道**做院端直付试点，复用普康宝式内部账户与直结能力，**不要求自建医保局/银行网关**；HIS/医保局深度直连留 V2。行业参照：泰康/众安/平安"数据直连 + 院端直付"经既有通道对接，客户"零垫付"。

### 4.2 接入契约与三件套（防 SSRF / 重放 / 重复出款）

```
IntegrationPort
  入参 ChannelCommand {
         tenantId, channelType,          // TPA / INSURER
         command,                        // PRE_AUTHORIZE / SETTLE / REFUND
         payloadEncrypted,               // 密文，不出明文 PII
         hmac, timestamp, nonce,         // 防重放三件套
         idempotencyKey                  // {claimNo}:{stage}:{attempt}（口径见《工程落地版》§7.5）
       }
  出参 ChannelResult { status, settlementRef, ledgerReservationId? }
```

- **SSRF 防御**：通道域名/IP 走平台注册白名单，禁止前端传入任意 URL；内网 endpoint 拉取，外网仅预览。
- **HMAC + timestamp + nonce**：nonce 窗口内唯一，超时拒绝；密钥进程内缓存，遇 `401` 自动重取重试一次。
- **幂等**：重复 `SETTLE` 返回首次 `settlementRef`，杜绝双付。
- **失败降级**：通道不可用 → 退回"报销快赔 + mock 支付网关"兜底主路径，案件不卡死。

### 4.3 与额度、反诈的联动

- 高信任客户免单证直赔前，先经 `LedgerPort`(C11) 做两阶段 reserve/commit/release。
- 反诈命中（`FraudScreen` 挂起 `FRAUD`）→ 信任额度自动 `release`，并熔断该客户 `Automated` 态降为 `Assisted`。
- 额度仅预授权，最终出款仍受 `SUGGEST_REJECT` 人工确认护栏（AI 不碰钱）。
- 直付全程经 `TracePort`(C4) 留痕（channel 命令、HMAC 校验态、出款 ref、人工确认）；对外内容复用 C8 `ContentSafetyGuard`；资金事件走 `OutboxPort` 事务性发件箱。

## 5. 串联：一条治理闭环

```
AiAssess / FraudScreen(模型)
   ├─ EvaluationPort(C7) → 评测门禁 + 漂移监控 + 模型卡
   ├─ VisualForensicsPort(E1) → R-FRAUD-08 命中 → 标记 + 附相似源案
   ├─ GraphFraudPort(E2) → R-FRAUD-05/09/10/11 → riskScore + 关联簇
   ├─ NotificationPort(C9) → 命中即多级预警 + 挂起 FRAUD
   └─ TracePort(C4) → ForensicHit/GraphFraudHit 全量入 claim_decision_trace
        ↓
Arbitrate(DECISION+C3) → Adjust(RULE+C2+C11)
        ↓                    ↓
   SUGGEST_REJECT     IntegrationPort(C10) 三态灰度
                             ↓
                     LedgerPort(C11) 信任额度 ── 反诈命中即熔断 ──→ NotificationPort(C9)
                             ↓
                     OutboxPort + TracePort(C4) → 资金零丢失 + 全链路可回放
```

- **MRM 守门**：未过评测门禁的模型不进 `AiAssess`/`FraudScreen`；直付通道未达 `Shadow` 一致率不升 `Assisted`。
- **证据闭环**：所有反诈命中必须可回放——`evidenceRef` 写入 `claim_decision_trace`，满足金发 8 号"可解释 + 可人工复核"。
- **类型护栏**：`FraudScreen` 输出 `AiSuggestion` 型建议，最终 `Confirmed` 由人工在 `Arbitrate` 落定。
- **后督**：自动通过 / 建议拒赔结论 100% 经 AI 质检，反诈命中列为高优先级抽检。

## 6. 企业场景契合

| 约束 | 落点 |
|---|---|
| 信创 | 图库 Nebula/TuGraph；向量 TiDB Vector/Milvus；视觉模型私有化（PaddleOCR 系 / ResNet 轻量头）；直付经保司/TPA 既有设施 |
| 数据不出域 | 影像/图/向量均租户私有存储 + 私有化推理；指纹按 `tenant_id` 隔离；PII 不入 trace |
| 多租户 | 图分区键 + 向量分片；所有查询带 `tenant_id` 谓词；通道请求带 `tenantId` |
| 合规 | 金发 8 号（可解释 + 可人工复核）、195 号文（AI 辅助性定位）、TC260/GB-T 45654（内容安全复用 C8）；反诈仅建议不决断 |

## 7. 风险与回退

- **引入运维税**：图库/视觉模型带来新依赖，先以 MVP 单案规则兜底，Phase B 再接；**不为想象规模预付**。
- **规模硬顶**：图/向量均须先做 90 天窗口 + 限 K 检索，否则成业务瓶颈。
- **直付资损**：`Automated` 仅开放高信任客户，受额度 + 反诈熔断三重约束；任一异常回退 `Assisted`。
- **通道供应商风险**：保司/TPA 通道故障 → 退回报销兜底，不阻塞主链路。
- **模型漂移**：challenger 不劣化才升阶；漂移超阈值自动退回人工。
- **统一回退纪律**：任一增强项故障 → fail-safe 转人工（安全兜底优先于 R-FAST 快赔）。
