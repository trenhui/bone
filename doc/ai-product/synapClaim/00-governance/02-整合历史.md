## 三、P10 结构治理（2026-10-30，本轮）

**动因（实测，不是感觉）**：

1. **层号与位置脱钩**：9 份核心文档平铺在根目录，`L1 战略` 与 `L3 契约` 的邻居关系靠 100 行的表来描述——路径本身推不出权威性。
2. **规范与记录混放**：`08-go-live/` 里 `01`–`13` 是**规范草案**（"须建设"），`14`–`18` 是**变更记录**（"本次已完成三项 P0"）。同一目录里两套权威性，AI 与新人都会读成"现在就是这样"。
3. **一份文件六个主题**：`文档地图.md` 同时装着品牌约定、层表、治理规则、引用约定、机检说明、整合历史，读一份索引要 108 行。
4. **同一事实四份拷贝**：`DOC_MAP`(16 条) / `MAIN`(5 条) / `RULEBOOK·CONTRACT·LANDING` / `DOC` 分散在 4 个脚本里，外加符号基线的 13 条路径——**移动文件必漏改**，而漏改的后果是机检"仍在跑但校验的不是真源"（静默失焦）。
5. **目录名带全角括号**：`08-go-live/` 在 URL、shell、CI 参数里都要转义。

**动作**：

| 动作 | 前 | 后 |
|---|---|---|
| 目录按层编号 | 根平铺 9 份 + `04-design/`、`06-verification/`、`07-delivery/`、`09-records/reviews/`、`10-archive/`、`08-go-live/` | `00-governance/` … `10-archive/`（**目录号=层号**，机检锁死） |
| 规范 vs 记录分离 | 上线包 19 分册同目录 | `08-go-live/` 规范 14 份（`00`–`13`）+ `09-records/impl-log/` 记录 5 份（`14`–`18`） |
| 索引拆分 | `文档地图.md`（108 行，6 主题） | `00-文档地图`（层与真源）/ `01-文档治理规约`（规则）/ `02-整合历史`（本文） |
| 机读索引 | 无 | `docs.manifest.json`（52 条，含 `summary` / `authority` / `shortNames`），**四道机检从此读取** |
| 新增机检 | 无 | `_check_manifest.py`：manifest ↔ 磁盘双向、目录号=层号、短名唯一、正文路径 token 存在 |
