# 文档治理规约

> 本文是**强制规则**，不是建议。规则的作用是防住同类事故复发：本目录曾在 7 天内从 13 份涨到 45 份，原因就是"没有登记与收敛的强制点"。
>
> 机检脚本按本文实现；若发现规则与脚本行为不一致，**以脚本为准并立刻修本文**（规则写在空中等于没有）。

## 一、命名约定

| 对象 | 规则 | 理由 |
|---|---|---|
| 目录 | `NN-<英文语义>`，两位序号 = 层号 | 目录号=层号，路径即能推出权威性 |
| L1–L3、L5 的核心文档 | `synapClaim 智能理赔平台-<类型>（<修饰>）.md` | 全仓统一品牌；修饰符进括号 |
| L4、L6、L7、L8、L9 内文档 | **短名**（目录已含分类，不再套长前缀） | 避免 `synapClaim 智能理赔平台-` 重复占宽 |
| 交付包 / 上线分册 | `NN-<主题>.md`，编号连续且**必须在索引表登记** | 编号即对外编号，缺号=交付物缺失 |
| 品牌 | **Synap（思纳普）** = 公司；**synapClaim** = 产品 | 两者不混用 |
| 设计原则 | `synapClaim Pn`（P1–P6），定义见 `AI 技术方案` §1.2 | 引用须带编号与出处 |

**禁止**：中英文混排目录名、全角括号目录名（已清理 `08-go-live/` → `08-go-live/`，因为全角括号在 URL / shell / 工具链里都要转义）、文件名错别字（已修 `智理理算` → `智能理算`）。

## 二、登记即 SSOT

1. **新建文档必须先登记** `docs.manifest.json`，否则 `_check_manifest.py` 判红（未登记 = 不计入 SSOT）。
2. 登记字段的最低要求：`id`（稳定标识，不随文件名变）、`path`、`layer`、`diataxis`、`summary`（一句话"什么时候该读它"）、`authority`（它拥有哪些主题）。
3. **7 天内被引用 < 2 次**的文档，下一轮整合时归档或合并——这条是针对上一轮膨胀的直接对策。
4. 删除文档时同步删 manifest 条目；**不要留"指向不存在路径"的条目**（符号基线里已有 1 条 `ClaimSphere …` 的历史欠账，属反面教材）。

## 三、一篇一主题，一主题一真源

1. **一份文档只占一个 Diátaxis 象限**：Reference（契约/设计）不写叙事；Explanation（愿景/诊断）不定义口径；How-to 不复述设计。
2. **同一主题只允许一个 authority 命中**。理算类现在是三份、职责不重叠：`04-design/理算引擎设计`（结构）+ `03-contract/…V1`（业务口径）+ `06-verification/…验证套件`（验证）。
3. **新结论优先回写，不新建文档**。动手写之前先回答："这条结论的真源章节是谁？"能回写就回写。

## 四、交叉引用约定

- 引用格式：**`《文档短名》 §X（标题）`**。短名取自 manifest 的 `shortNames`。
- 禁止裸产品名代指章节（形如「产品名 + §章节号」的写法无效）——机检会报"遗留裸引用"。
- **短名一旦登记就进入 § 校验**：新增短名等价于给全仓加了新断言，先在本地跑 `_check_xref.py` 再提交。
- 正文里提到文件路径时，**必须用真实相对路径**（如 `../03-contract/…md`）；`_check_manifest.py` 会校验带已知前缀的路径 token 是否真实存在，防止"文中链接指向已删除文件"这种静默腐化。

## 五、机检（本目录自带，6 道）

| 脚本 | 作用 | 扫描范围 |
|---|---|---|
| `_check_manifest.py` | **新增**。manifest ↔ 磁盘双向一致；目录号=层号；`shortNames` 唯一；正文路径 token 存在性 | 全族 |
| `_check_xref.py` | 《短名》§X 引用完整性 + 契约-设计一致性 + 交付/上线库存双向 | L0–L7（不含 L8–L10） |
| `_check_contract_drift.py` | 规则 ID ⊆ Rulebook、对外枚举双向、错误码集合、表清单对位、L4/L6 分层真源 | L3 / L4 / L6 / L7 |
| `_check_ddl.py` | DDL 可执行性：单 id 主键 / 列名唯一 / 索引列已声明 / append-only 无变更列 / 建表数 = 35 | L3 |
| `_check_numbers.py` | FORBIDDEN（已定性错误表述零命中）+ REQUIRED（关键口径在位）+ ADR 可追溯 | 见下 |

**扫描范围的原则**：L9 / L10 **不纳入语义机检**——它们是冻结的证据，纳入会导致"改历史文档才能过 CI"。但 L9/L10 的**路径存在性**受 `_check_manifest.py` 保护（防止证据文件被误删）。

**路径不再硬编码**：四个脚本的文档路径全部从 `docs.manifest.json` 读取。此前同一事实在 4 个脚本里有 4 份拷贝（`DOC_MAP` / `MAIN` / `RULEBOOK`…），与本仓前端"双导航漂移"事故同构——移动文件时必然漏改一处，而漏改的后果是**机检静默失焦**（脚本仍在跑，但校验的不是真源）。

## 六、新增 / 移动文档的检查清单

1. 选层 → 放对目录（目录号=层号）。
2. 在 `docs.manifest.json` 登记条目（含 `summary` 与 `authority`）。
3. 若新增短名，跑 `_check_xref.py`：新断言可能立刻变红，这是**发现旧引用写错**的机会，不是障碍。
4. 正文里的路径引用同步改（用真实相对路径）。
5. 跑全套：`python3 _check_manifest.py && python3 _check_xref.py && python3 _check_contract_drift.py && python3 _check_ddl.py && python3 _check_numbers.py`。
6. 交付包新增/删除须同步 `07-delivery/README.md` 索引；上线分册须同步 `08-go-live/00-总纲` 映射表（两者都有库存双向校验）。
