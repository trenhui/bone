# 文档治理规约

> 本文是**强制规则**，不是建议。规则的作用是防住同类事故复发：本目录曾在 7 天内从 13 份涨到 45 份，原因就是"没有登记与收敛的强制点"。
>
> 机检脚本按本文实现；若发现规则与脚本行为不一致，**以脚本为准并立刻修本文**（规则写在空中等于没有）。

## 一、命名约定

| 对象 | 规则 | 理由 |
|---|---|---|
| 目录 | `NN-<英文语义>`，两位序号 = 层号 | 目录号=层号，路径即能推出权威性 |
| L1–L3、L5 的核心文档 | `synapClaim 智能理赔平台-<类型>（<修饰>）.md` | 全仓统一品牌；修饰符进括号 |
| L4、L6、L7、L8、L9 内文档 | **短名**（目录已含分类，不再套长前缀） | 避免 `synapClaim 智能理赔平台-` 重复占宽 |
| 交付包 / 上线分册 | `NN-<主题>.md`，编号连续且**必须在索引表登记** | 编号即对外编号，缺号=交付物缺失 |
| 品牌 | **Synap（思纳普）** = 公司；**synapClaim** = 产品 | 两者不混用 |
| 设计原则 | `synapClaim Pn`（P1–P6），定义见 `AI 技术方案` §1.2 | 引用须带编号与出处 |

**禁止**：中英文混排目录名、全角括号目录名（已清理 `08-go-live/` → `08-go-live/`，因为全角括号在 URL / shell / 工具链里都要转义）、文件名错别字（已修 `智理理算` → `智能理算`）。

## 二、登记即 SSOT

1. **新建文档必须先登记** `docs.manifest.json`，否则 `tools/_check_manifest.py` 判红（未登记 = 不计入 SSOT）。
2. 登记字段的最低要求：`id`（稳定标识，不随文件名变）、`path`、`layer`、`diataxis`、`summary`（一句话"什么时候该读它"）、`authority`（它拥有哪些主题）、**`role`**、**`currency`**（见 §三之二）。
3. **7 天内被引用 < 2 次**的文档，下一轮整合时归档或合并——这条是针对上一轮膨胀的直接对策。
4. 删除文档时同步删 manifest 条目；**不要留"指向不存在路径"的条目**（符号基线里已有 1 条 `ClaimSphere …` 的历史欠账，属反面教材）。

## 三、权威与时效：让 AI 判得准

### 三之一、一篇一主题，一主题一真源

1. **一份文档只占一个 Diátaxis 象限**：Reference（契约/设计）不写叙事；Explanation（愿景/诊断）不定义口径；How-to 不复述设计。
2. **同一主题只允许一个 authority 命中**。理算类现在是三份、职责不重叠：`04-design/理算引擎设计`（结构）+ `03-contract/…V1`（业务口径）+ `06-verification/…验证套件`（验证）。
3. **新结论优先回写，不新建文档**。动手写之前先回答："这条结论的真源章节是谁？"能回写就回写。

### 三之二、`role` / `currency`：写进工件本身，而不是只写在地图里

**为什么需要**：人类会先读 README 再决定读哪份；**AI 不会**——AI 靠相似度检索，容易把"过程证据"和"待合入草案"当成"当前设计"。若权威与时效只存在于一份人读的地图里，AI 检索到的片段就没有任何信号区分"现行契约"与"某时点的取证"。

因此这两组字段必须写在**可被检索的工件本身**（manifest 条目 + 文档 front-matter 两处）。

| 字段 | 取值 | 含义 | AI 应当如何处理 |
|---|---|---|---|
| `role` | `ssot` | 当前权威真源 | 可引用为事实 |
| `role` | `navigation` | 导航/治理元文档 | 用于路由，不含业务口径 |
| `role` | `draft` | 待合入草案（如 go-live 01–13） | 仅作计划/提案，不当现行契约 |
| `role` | `evidence` | 冻结的过程证据（L9/L10） | 仅回答"为什么/历史" |
| `role` | `tooling` | 工具/参考实现（oracle） | 非产品代码，不当设计引用 |
| `role` | `guide` | 操作指南（可执行步骤 / 逐项裁定台账，不含现行契约） | 按步骤执行；其中的状态与数值以对应 `ssot` 为准，不据此宣称能力已具备 |
| `currency` | `current` | 现行 | 默认可引用 |
| `currency` | `draft` | 草案 | 仅在明确询问规划时引用 |
| `currency` | `frozen` | 冻结 | 只作历史取证，**禁止当作现状** |
| `superseded_by` | 目标文档路径 | 本文档已被哪份撤销/修正 | 读到它 ⇒ 必须去读取代者 |

**填写规则**：

- `role` 由**文档承担什么职责**决定，不由它在哪一层决定（L8 的总纲是 `ssot`，同层分册是 `draft`）。
- `currency=frozen` 必配 `role=evidence`（或 `tooling`）；有 `superseded_by` 时必须同时写 `supersede_note`（一句话说清被撤销的**具体结论**，而不只是"已被取代"）。
- **每份文档的 front-matter 必须与 manifest 逐字段一致**（`doc_id` / `role` / `currency`），由 `tools/_check_manifest.py` 的 M9 强制——front-matter 是绕过 manifest 直读单文件时 AI 判断"证据还是现状"的唯一依据。

### 三之三、AI-INDEX.md 是生成物，不是手写文件

- `AI-INDEX.md` 由 `tools/_gen_ai_index.py` **从 manifest 派生**，禁止手工编辑；改了 manifest 必须重跑生成器。
- **路由表（`aiRouting`）的真源在 manifest 里**，不在生成器代码里，也不在 AI-INDEX 里——否则"路由"会变成第二处需要手工同步的地方。
- 门禁 M7 校验 AI-INDEX 与 manifest 派生结果**逐字节一致**；不一致即红，提示 `python3 tools/_gen_ai_index.py` 修复。

## 四、交叉引用约定

- 引用格式：**`《文档短名》 §X（标题）`**。短名取自 manifest 的 `shortNames`。
- 禁止裸产品名代指章节（形如「产品名 + §章节号」的写法无效）——机检会报"遗留裸引用"。
- **短名一旦登记就进入 § 校验**：新增短名等价于给全仓加了新断言，先在本地跑 `tools/_check_xref.py` 再提交。
- 正文里提到文件路径时，**必须用真实相对路径**（如 `../03-contract/…md`）；`tools/_check_manifest.py` 会校验带已知前缀的路径 token 是否真实存在，防止"文中链接指向已删除文件"这种静默腐化。

## 五、机检（本目录自带，6 道脚本 / 9 条不变量）

`tools/_check_manifest.py` 承担 9 条不变量（M1–M9），其余 5 道脚本各管一类语义漂移：

| 脚本 | 作用 | 扫描范围 |
|---|---|---|
| `tools/_check_manifest.py` | **M1–M9**：manifest ↔ 磁盘双向一致；目录号=层号；`shortNames` 唯一；正文路径 token 存在性；**AI 索引不漂移（M7）**；**AI 路由 id 有效（M8）**；**front-matter 与 manifest 一致（M9）** | 全族 |
| `tools/_check_xref.py` | 《短名》§X 引用完整性 + 契约-设计一致性 + 交付/上线库存双向 | L0–L7（不含 L8–L10） |
| `tools/_check_contract_drift.py` | 规则 ID ⊆ Rulebook、对外枚举双向、错误码集合、表清单对位、L4/L6 分层真源 | L3 / L4 / L6 / L7 |
| `tools/_check_ddl.py` | DDL 可执行性：单 id 主键 / 列名唯一 / 索引列已声明 / append-only 无变更列 / 建表数 = 36 | L3 |
| `tools/_check_numbers.py` | FORBIDDEN（已定性错误表述零命中）+ REQUIRED（关键口径在位）+ ADR 可追溯 | 见下 |
| `tools/_check_ai_native_calibration.py` | 飞轮下游**强判据**：校准/模型治理实现类含全部判据符号、单测用例数下界、防反馈环锚点、纯领域零框架依赖；`--self-test` 用 4 个负向探针证明判据不恒真 | 码侧内核 |

第 6 道机检的**定位边界**：它只证明「内核真实、可证伪」，**不判定飞轮是否已接线到生产链路**，也不判定 L3 达标。配套判据是 `tools/_ai_native_readiness.py` 的 `FLYWHEEL_DOWNSTREAM` 三要素强校验：校准实现类存在、盲标样本源有生产调用、校准计算有生产调用，三者同时成立才判 SATISFIED；`import` / 注释 / 单测均不算接线，脚本自带「摘除校准计算生产调用（import 假绿回归钉子）」等负向探针。三要素齐备只能代表「可编码消费方与调用链已就位」；真实闭环仍须由独立盲标样本、冻结集回归与运行期覆盖证据给出，静态事实给不出，绝不因文件存在就宣称达标。

**自身接线**（避免第 6 道机检变成新的孤儿门禁）：`scripts/tests/test_check_ai_native_calibration.py` 11 例通过 `[42/59] 门禁脚本自身单元测试` 被 pre-commit 自动发现，逐条验证 C1–C5 精确归因、合规正例、扫描失效闸与负向探针有效性；判据被改成恒绿/恒红、锚点被删、扫描路径漂移都会在那一步判红。注意区分两层：`check.sh` 主流程**并未调用**该机检本体（本目录自带脚本一贯不进 `check.sh`，`R4` 也只扫 `scripts/check-*.py`）；被守护的是**机检自身的判据**，不是「每次提交都扫一遍校准内核」。人工跑全套仍按 §六 第 7 条。

**治理端点接线（6 个只读端点）**：`/api/v1/claim-ops/` 下为 `ai-readiness` / `ai-runtime-health` / `ai-calibration/report` / `ai-rollout` / `ai-rollout/drill` / `ai-provider-probe`（第 6 个为本轮新增）。三条口径在此登记，避免下游文档各自复述：

- 证据窗口单一真源：前端 `governanceWindow()` 与 E2E `EVIDENCE_WINDOW` 同算法——`to = ceil(now / 86400000) * 86400000`、`from = to - 30 * 86400000`（UTC 日界 30 天，同日恒定、长度恰 30 天且小于端点 31 天上限）；字符串统一为秒级 ISO（`...Z`，无毫秒），与后端 `Instant` 回显逐字一致——逐字一致靠同一份规范串，不靠比较时再归一化。E2E A 组断言后端回显窗口逐字一致，B 组断言治理面板声明窗口逐字一致。
- `ai-provider-probe` 每次真实消耗一次 provider 用量，只允许用户在治理面板显式点击触发；默认加载、刷新与轮询均不得发起请求（E2E 用 `page.on('request')` 断言进入页面 0 次、点击后 1 次）。
- `tools/_ai_native_readiness.py` 的 `RUNTIME_MODEL_COVERAGE` 为**四条件**：`provider_env` 已配 **且** `runtime.probeVerdict == REACHABLE` **且** `runtime.probeEvidence` 证据束自洽 **且** `nodes>0 / rate>0 / participated>0`。第二条件对应 `AI技术方案 §11.7` 记录的「探活绿灯、业务全量降级」事故——配了环境变量 ≠ 上游通了 ≠ 输出契约对；判词由 E2E 同一次手动探活响应写入产物，缺失或非 `REACHABLE` 一律 fail-closed，绝不把「没测过」当成「通了」。第三条件堵住第 11 轮 GAP 的「三要素同源可伪造」：环境变量、裸判词、参与率都能手写，故证据束须含 `httpStatus=200`、`model` 非空、`provenance=PROVIDER`、`promptTokens>0`、`completionTokens>0` 与合法 `requestId`，且由 E2E 从同一次探活响应透传；采集侧尚未产出这些字段时产物为 `null`，按 `PROBE_EVIDENCE_*` 阻断，绝不回落到裸判词或编造 token / requestId。reason 按 `PROVIDER_NOT_CONFIGURED` > `PROBE_NOT_REACHABLE` > `PROBE_EVIDENCE_*` > `MODEL_PARTICIPATION_ZERO` > `ADMITTED` 归因，detail 附 `providerConfigured=` / `probeVerdict=` / `probeEvidence=`；`--self-test` 的 stay 类与伪造鲁棒性探针、`scripts/tests/` 下表征测试（含「摘除任一条件须被自测判红」与证据束源码变异）守护该判据；条数以脚本为准，文档不写死计数。窗口统一、参与率非零或伪造判词都不改变 `l3Claimable=false`。

**成熟度档位（第 11 轮收敛）**：`tools/_ai_native_readiness.py` 的 `current_level()` 描述**运行态**，不再只看两个配置态判据。`PROVIDER_CONFIGURED` 与 `PERCEPTION_MODEL_DRIVEN` 全齐、但 `RUNTIME_MODEL_COVERAGE` 非 SATISFIED 时，一律回落 `L0（配置态就绪但运行期未达标：<reason>）`；四条件齐备且感知由模型驱动才判 L2（三要素伪造但缺证据束须回落 L0）。`scripts/tests/test_ai_native_readiness_flywheel.py` 的 `MaturityLevelTest`（含「退化成只看配置态」变异）与 `--self-test` 第四类「成熟度档位」探针共同守护该约束；条数以脚本为准。E2E 在最终产物落盘后**再跑一次复核器做终态对账**，堵住 C 组中途快照之后产物被污染无人复核的盲点；产物新增 `runtime.probeVerdictCapturedAt` 与 `runtime.finalReadinessSnapshot`。

另有 1 个**生成器**（不参与判红，但产物被 M7 校验）：

| 脚本 | 作用 |
|---|---|
| `tools/_gen_ai_index.py` | 从 manifest 生成 `AI-INDEX.md`；`--check` 模式只校验不写入 |

**M1–M9 速查**（细节见各脚本 docstring）：

| 规则 | 一句话 | 典型触发场景 |
|---|---|---|
| M1 | manifest 可解析，id/path 唯一，必填字段齐全 | 登记条目缺 `summary` |
| M2 | 登记即存在 | 改了路径但没挪文件 |
| M3 | 存在即登记 | 新建文档没登记 |
| M4 | 目录号 = 层号 | 把 L3 文档放进 L4 目录 |
| M5 | 短名唯一 | 两个文档用了同一个《短名》 |
| M6 | 正文路径不悬空 | 文中链接指向已删文件 |
| M7 | AI 索引不漂移 | 改了 manifest 没重跑生成器 |
| M8 | AI 路由 id 有效 | 路由指向不存在的文档 |
| M9 | front-matter 与 manifest 一致 | 手工改了文档头的 `role`/`currency` |

**扫描范围的原则**：L9 / L10 **不纳入语义机检**——它们是冻结的证据，纳入会导致"改历史文档才能过 CI"。但 L9/L10 的**路径存在性**受 `tools/_check_manifest.py` 保护（防止证据文件被误删）。

**路径不再硬编码**：四个脚本的文档路径全部从 `docs.manifest.json` 读取。此前同一事实在 4 个脚本里有 4 份拷贝（`DOC_MAP` / `MAIN` / `RULEBOOK`…），与本仓前端"双导航漂移"事故同构——移动文件时必然漏改一处，而漏改的后果是**机检静默失焦**（脚本仍在跑，但校验的不是真源）。

## 六、新增 / 移动文档的检查清单

1. 选层 → 放对目录（目录号=层号）。
2. 在 `docs.manifest.json` 登记条目（含 `summary`、`authority`、`role`、`currency`）。
3. 文档头部写 front-matter（`doc_id` / `role` / `currency`，须与 manifest 一致）。
4. 若新增短名，跑 `tools/_check_xref.py`：新断言可能立刻变红，这是**发现旧引用写错**的机会，不是障碍。
5. 正文里的路径引用同步改（用真实相对路径）。
6. **重跑生成器**：`python3 tools/_gen_ai_index.py`（改了 manifest 必做，否则 M7 判红）。
7. 跑全套：`python3 tools/_check_manifest.py && python3 tools/_check_xref.py && python3 tools/_check_contract_drift.py && python3 tools/_check_ddl.py && python3 tools/_check_numbers.py && python3 tools/_check_ai_native_calibration.py --check && python3 tools/_check_ai_native_calibration.py --self-test && python3 tools/_gen_ai_index.py --check`。
8. 交付包新增/删除须同步 `07-delivery/README.md` 索引；上线分册须同步 `08-go-live/00-总纲` 映射表（两者都有库存双向校验）。
