| 缺口 | 实证 |

## 三、配置真实 provider（须采购/密钥托管完成后执行）

```bash
export BONE_AI_GATEWAY_BASE_URL=https://api.deepseek.com   # OpenAI 兼容地址
export BONE_AI_GATEWAY_API_KEY=<从密钥托管注入，禁止明文入库>
export BONE_AI_GATEWAY_MODEL=deepseek-chat                 # 必须是该 provider 真实模型名
export BONE_AI_GATEWAY_TIMEOUT=60s                        # 可选

# 感知层模型驱动（PERCEPTION_MODEL_DRIVEN 的第二个必要条件，文档此前 0 命中）
export BONE_CLAIM_DOCUMENT_PARSE_MODE=llm
```

四个 `BONE_AI_GATEWAY_*` 变量对应 `application.yml:92-95`。注意事项：

- 密钥留未解析的 `${...}` 占位符会让 `LlmGatewayProperties` **启动即失败**（不允许带字面量去鉴权）；
- `PERCEPTION_MODEL_DRIVEN` 判据要求 `BONE_CLAIM_DOCUMENT_PARSE_MODE=llm` **且**
  `BONE_AI_GATEWAY_BASE_URL` 非空，两者缺一即 `TEXT_LAYER_ONLY`；
- `llm` 模式未配 provider 时网关回落 `MockLlmClient`，适配器显式拒绝并转人工，
  **绝不伪造解析产物**；
- 图像解析另有独立门控 `BONE_CLAIM_DOCUMENT_PARSE_IMAGE_ENABLED`（默认 `false`），
  受控 RAG 另有 `BONE_CLAIM_KNOWLEDGE_RAG_ENABLED`（默认 `false`）——两者都是
  「配了不生效」的既定设计，本手册不擅自打开。

## 四、探活（唯一允许的连通性判据）

```bash
curl --noproxy '*' -H "Authorization: Bearer <JWT>" \
  "http://127.0.0.1:8888/api/v1/claim-ops/ai-provider-probe"
```

`verdict` 必须是 `REACHABLE`。非 `REACHABLE` 时**只按响应里的 `action` 处置**，
不要自行改配置猜原因。权限复用 `claim:claims:read`；端点每次真实消耗一次
provider 用量（场景标签 `claim-ai-provider-probe`），刻意不缓存——缓存会让
「现在通不通」退化成「上次通不通」。端点契约与受控原因码见 `AI技术方案.md §11.7`。

`configured` / `reachable` / `model` / `provenance` / `latencyMs` 五个字段都要看：
`provenance` 按 `AiModelProvenance` 切 `PROVIDER` / `STUB`，与参与率判据同源。

产物：`outputs/claims-e2e-result.json`（被 `.gitignore:290` 整目录忽略，属本机
未跟踪产物，**不可复现、不可审计**；若需版本化须另建 `doc/evidence/` 并登记）。

### 窗口口径（最容易误判的一处）

`runtime` 段是 `GET /claim-ops/ai-runtime-health` 响应的原样拷贝，但窗口
**被硬编码在 `synap-claim-e2e.cjs:77-78`**：

```js
const from = '2026-10-06T00:00:00Z';
const to   = '2026-11-05T00:00:00Z';
```

因此 `runtime.participationRate=0` 是**这个 31 天历史窗口**的读数（含 v1.6 之前
88 条 `UNATTRIBUTED` 存量，历史回填不可能），**不代表当下完全没有模型参与**：
同一产物的 `ui.aiGovernance` 段用近 7 天滚动窗口，曾实测 `8 / 91 ≈ 8.79%`。

重跑时若窗口已过期，必须修改脚本的 `from`/`to`（或参数化）再跑，否则拿到的是
陈旧证据。`RUNTIME_MODEL_COVERAGE` 判据消费的正是 `runtime` 段的 0，故无 provider
时判 `BLOCKED / MODEL_PARTICIPATION_ZERO` 是正确读数。

> **防漂移提示**：仓库已有一个进行中的 `evidence-window-contract` 变更，目标是把
> E2E 产物与治理面板统一到「UTC 日界单一真源」。该变更落地后，本节的硬编码常量
> 与行号即失效，须同批回写本手册；在此之前请以脚本实际取值为准，不要照抄常量。

## 七、红线（本手册反复要防的事）

1. **不得为观感刷绿**：无 provider 时 `participationRate=0` 是正确读数；
   不得改配置默认值、不得把 `draft` 批量改成 `current`、不得把 `declared`
   改成 `wired`、不得给冻结集塞一个任意 `payloadHash`、不得把 `BLOCKED`
   洗成 `SATISFIED`。`AI技术方案.md §1.7 ⑤(457)` 明确：把任何 BLOCKED 改成
   SATISFIED 的唯一合法路径是**闭环其对应的外部条件**。
2. **2026-11-07 判据硬化后**，上述刷绿动作在复核器里已一律判红（见
   `scripts/tests/test_ai_native_readiness_evidence_gates.py` 的 21 条表征钉子），
   且 `--self-test` 有 10 条「刷绿不得翻绿」反向探针。
3. **模型跑通 ≠ 能自动放款**：`aiParticipated>0` 但案件仍 `MANUAL_REQUIRED`
   属正常——知识层对纯票据案件恒 `INSUFFICIENT_CLINICAL_FACTS`，这是 fail-closed
   的正确表现。把它改成「放行」才是事故。
4. **不得先改文档宣告完成**：13 个 go-live 分册的 `currency: draft` 是准确状态；
   `00-总纲` L97 明文要求「一律标注目标态/待落地」，逐册升 current 必须与某一
   G 门禁的验收证据一一对应。
5. 本手册**不修改** `application.yml` 默认值、`baseline-metrics.json` 状态、
   迁移脚本、13 分册 frontmatter 或 `check.sh`（L3，需架构师审批）。
