# 04 业务规则书（Rulebook）—— 门诊小额快赔 MVP 全集

> 用途：把"示例口径"升级为**可开发、可配置、可评测的规则全集**。本规则书是理算引擎、评测集、保司配置三者的共同输入；客户现场可逐条核对。**规则版本号 R1.0（MVP 一期）**
>
> **契约地位**：本规则书为 MVP **规则真源**（规则 ID 如 `R-MAN-01` / `R-FRAUD-*`），被《synapClaim 智能理赔平台-工程详细设计（落地版）》§8.2 / §10.6 引用对齐；规则变更须经业务评审 + 评测集回归方可发布。
> >
> **ID 命名空间警告（2026-11-07 实测，必读）**：本规则书的 `R-XXX-nn` 是**对外业务条款**，`claim-ruleset.json` 里同名的 `R-XXX-nn` 是**引擎执行期判定项**，两者共享前缀但**有 10 个 ID 语义完全不同**（例：本书 `R-FRAUD-02` = 金额异常检测，资产 `R-FRAUD-02` = 无证据）。引用规则 ID 必须写明是哪一层，**不得互相解释**。完整对照与处置见 §十一；由 `tools/_check_ruleset_alignment.py` 守护。
>
> **版本修订（2026-10-26 业界对标优化）**：在 R1.0 基础上，将反欺诈由 7 条规则升级为 11 条（新增 R-FRAUD-08~11：影像相似度、关系图谱+设备指纹、知识图谱一致性、跨案件关联），R-FRAUD-05 由 V2 单维标记升格为 V1.0 图计算团伙识别；目录规则新增 R-DIR-06 诊断-用药-诊疗合理性（原 V2 临床知识图谱前置）。依据：平安财险 13 模型+208 规则、太保/泰康关系图谱团伙识别、国寿"识图"影像相似度、众安图像+关系图谱联合反诈。
>
> **版本修订（2026-11-07 契约补齐）**：补齐 7 条**已在代码生效、但本规则书未登记**的规则——`R-FRAUD-13/14`（目录映射缺失，实现侧 `category=CATALOG`）、`R-FRAUD-21`（渠道来源未知）、`R-FRAUD-22`（跨案重复索赔，`risk=true`）、`R-ANOM-01~03`（异常行为，`risk=false` 仅留痕，新增 §九之二）。定义来源：`bone-apps/synap-claim/src/main/resources/claim-ruleset.json` v4（33 条），非据文档推测。
>
> **为什么现在补**：`AI技术方案` 由 L3 移入 L4 后，`tools/_check_contract_drift.py` 的 C7（分层真源规则 ID 覆盖）才把它纳入扫描，当场抓到 `R-FRAUD-22` / `R-ANOM-03` 悬空——本规则书没有这两条的定义行。这是**已有的契约缺口，不是移层造成的**：代码与规则资产里它们已生效，客户却按一本没写它们的规则书理解赔付逻辑。同一轮逐条核对另发现 `R-FRAUD-13/14/21` 与 `R-ANOM-01/02` 同样缺登记，本次一并补齐 7 条。

## 一、规则管理规范

|**项**|**约定**|
|---|---|
|版本管理|每条规则含 version、effective_date、expire_date；生效规则唯一|
|变更流程|规则变更 → 业务评审（理赔负责人+客户业务专家）→ 审批 → 入评测集回归 → 发布（30 秒热生效）|
|冲突裁决|多规则命中冲突时按"优先级裁决表"（见 §七）；裁决过程留痕显示|
|评测联动|每次规则变更跑一次基准测试集回归（字段/规则/复核率不下降才可发布）|

## 九、风控标记规则（R-FRAUD）

|**规则ID**|**规则内容**|**触发条件示例**|
|---|---|---|
|R-FRAUD-01|重复报销检测|同人同日同院同额（假名化关联）|
|R-FRAUD-02|金额异常检测|单案金额超同类案件 3σ 或超保额 80%|
|R-FRAUD-03|时间轴矛盾|用药日期早于就诊日期/诊断日期晚于就诊日期等|
|R-FRAUD-04|材料一致性|发票金额与清单合计不一致（差额 >1 元）|
|R-FRAUD-05|团伙关联（**V1.0 升格，由单维标记升级为图计算**）|同医院/同科室/同代理人/同设备多人同类高额案件聚集，多维权关联（就诊时间聚集、金额聚集、材料相似度、关系图谱邻接度）；输出团伙风险分（0–1）与关联案件清单，供 R-FRAUD-09 图计算复核|关系图谱 + 设备指纹（V1.0 启用，详见 R-FRAUD-09）|
|R-FRAUD-06|票据验真（票面查验）|发票代码/号码/金额等票面要素核验（税局/电子票据平台通道，通道接入前按“查验不通过或无法查验一律转人工”从严处置）；查验不通过禁止进入自动通过路径|
|R-FRAUD-07|发票唯一性（硬约束）|同一发票在同一租户内只允许一笔赔案；由数据库唯一约束 uk(tenant_id, invoice_code, invoice_no) 强制（规则判定为辅），命中返回 409 且不回传已存在案件引用（防枚举）|
|R-FRAUD-08|影像相似度检索（**V1.0 新增，对标国寿"识图"**）|对上传发票/清单/病历影像提取感知哈希（pHash/aHash）+ 关键区域特征向量，跨租户历史案件库检索 Top-K 相似影像；相似度 ≥阈值（如 ≥0.92）且非同一案件 → 标记"疑似重复报案/PS 翻拍"，转人工并附相似源案件；支持同一张发票被不同人/不同案复用检测|影像指纹库（按 tenant_id 隔离）+ 向量检索（TiDB Vector / Milvus）|
|R-FRAUD-09|关系图谱 + 设备指纹团伙识别（**V1.0 新增，对标太保/泰康/众安**）|构建"人-案件-机构-设备-代理人-受益人"关系图谱，基于图计算（社区发现/PageRank/子图同构）识别团伙网络；设备指纹（上传终端特征、IP、账号设备绑定）识别同设备多账号、设备聚集；与 R-FRAUD-05 多维权融合输出团伙风险分；命中高置信团伙 → P0 强制转人工并进入风控专项|图数据库（如 NebulaGraph/TuGraph，轻量可用 Neo4j 或 TiDB 图计算）+ 设备指纹服务|
|R-FRAUD-10|知识图谱一致性推理（**V1.0 新增**）|基于医学目录底座 + 理赔知识图谱，推理"诊断-用药-诊疗-时间轴"内部矛盾（如诊断与用药无适应症关联、诊疗项目与诊断不匹配、时间轴倒置）；与 R-DIR-06 临床合理性互补（R-DIR-06 做确定性规则标记，本规则做图谱推理增强）|医学目录底座 + 理赔知识图谱（V1.0 最小集）|
|R-FRAUD-11|跨案件关联网络（**V1.0 新增**）|同被保险人/同证件/同手机号/同收款账户/同邮寄地址的多案件关联分析，识别"化整为零"（单案均 ≤阈值但聚合超保额）、"一人多投多赔"、收款账户聚集；输出关联案件簇与风险标签|案件关联索引 + 关系图谱（复用 R-FRAUD-09 底座）|

|R-FRAUD-13|目录映射版本缺失（实现侧 `category=CATALOG`）|规则执行时 `mappingVersionBlank == true`（该案件未绑定任何目录映射版本）→ 结论 `MAPPING_MISSING`；**risk=false**，只进审计与补件提示，不拉高风险闸。编号沿用实现侧标识（`claim-ruleset.json`）以保持回放可追溯，不与风控族同源|目录映射版本索引（`std_*` 映射未被引用即命中）|
|R-FRAUD-14|医院编码未映射到标准码（实现侧 `category=CATALOG`）|`hospitalCodeBlank == false && stdHospitalCodeBlank == true`（原始医院编码存在但未解析出标准码）→ 结论 `HOSPITAL_UNMAPPED`；**risk=false**，进未命中队列等映射补录，不阻断自动通过|保司码表 + 权威桥（见《多保司保单配置面与主数据映射设计》§6）|
|R-FRAUD-21|渠道来源未知|`sourceChannel` 为空或 `UNKNOWN` → 结论 `CHANNEL_UNKNOWN`；**risk=false**，仅审计留痕——渠道是灰度放量的分桶键，缺失渠道一律不放量（放量闸排在 100% 全放捷径之前，顺序反了会静默变全量）|渠道标识由接入方透传；缺失即命中|
|R-FRAUD-22|跨案重复索赔|排除本案自身后，同一被保险人历史案件数 `priorClaimCount >= 1` → 结论 `PRIOR_CLAIM_DUPLICATE`；**risk=true**，命中即拉高 `riskHit`、收紧硬闸（R-FAST-01 的"无风险标记"条件不成立）。**必须剔除本案自身**：否则新报案把自身算进历史、必然命中，造成 100% 误报|`ClaimCaseRepository.findByInsuredIdHash` 取同被保人全部赔案 |

## 九之二、异常行为标记（R-ANOM，仅审计留痕）

> **本族 `risk` 全为 false**：命中只落审计与人工提示，**不改变硬闸、不阻断自动通过**。与 §九 的区别就在这一点——§九 命中是"收紧"，本族命中是"留痕"。设计意图：避免对正常高频小额报案（如慢病复诊、企业批量报销）过度拒付。

|**规则ID**|**规则内容**|**触发条件**|
|---|---|---|
|R-ANOM-01|批量渠道大额异常|`sourceChannel == "BATCH" && claimAmount >= 50000` → `BATCH_LARGE_ANOMALY`；`risk=false`，提示人工抽检|批量导入通道 + 单案金额 ≥5 万|
|R-ANOM-02|批量渠道无票据|`sourceChannel == "BATCH" && invoiceEvidenceCount == 0` → `BATCH_NO_INVOICE`；`risk=false`，进补件提示|批量导入通道 + 无发票证据|
|R-ANOM-03|近 90 天高频报案|排除本案自身后 `recentClaims90d >= 3` → `FREQUENCY_ANOMALY`；`risk=false`，仅审计留痕。窗口与取证口径见《工程详细设计（落地版）》§8.2|同被保人近 90 天（UTC 日界）新增案件数 ≥3|

## 十、评测集联动清单（每条规则至少 3 条评测样本）

|**规则类别**|**覆盖样本要求**|
|---|---|
|责任范围|超范围医院/超范围诊疗/等待期内 各 ≥3 条|
|目录自费|目录外药品/保健品/超处方限额/诊断-用药不合理（R-DIR-06） 各 ≥3 条|
|免赔比例|免赔累计中/跨案件共享/社区上浮 各 ≥3 条|
|封顶|未达/已达/重置 各 ≥3 条|
|风险标记|`R-FRAUD-01~11`、`R-FRAUD-13/14/21/22` 与 `R-ANOM-01~03` 每类 ≥3 条（正/反例成对，与 §十 每规则 ≥3 统一）；其中 R-FRAUD-08/09/10/11 须含：① 跨案件影像重复/PS 正例、② 团伙子图正例、③ 诊断-用药矛盾正例、④ 化整为零聚合超保额正例，每类配反例；**R-FRAUD-22 须含"仅本案、无历史 ⇒ 零命中"反例**（缺此反例则新报案把自己算进历史，100% 误报）|

## 十一、执行资产 ID 命名空间对照（2026-11-07 实测登记）

> **本节是缺陷登记，不是新设计。** 2026-11-07 把 `bone-apps/synap-claim/src/main/resources/claim-ruleset.json`（v4，33 条 QLExpress 执行规则）与本规则书逐 ID 对账，发现两类 ID 空间**共享前缀但语义独立**：本规则书的 `R-XXX-nn` 是**对外业务条款**（客户逐条核对），资产的 `R-XXX-nn` 是**引擎执行期判定项**（有 `expression` / `conclusion` / `risk`）。C7 门禁只查「ID 是否在本书定义」，两边都定义就放行，**查不出同名不同义**。

**命名空间规则（即日起生效）**：

1. 引用规则 ID 必须写明是哪一层：本规则书写「条款 `R-FRAUD-02`」，代码侧写「执行项 `R-FRAUD-02`（资产）」，**禁止互相引用当作同一条规则**。
2. **不重命名任何已生效 ID**——代码侧日志/评测集/客户交付都在用，重命名会造成不可逆的口径断裂。用对照表登记差异，而不是改名字。
3. 新增 ID 时若复用已有前缀编号，必须在本节登记；`tools/_check_ruleset_alignment.py` 会把「共有 ID 集合 / conclusion / risk / 关系」锁成可判定判据。

> **A7** §11.1 每行**必须声明落点**，`端口:X`/`端口待接:X`/`引擎:X` 声明的类必须真实存在于源码树，`无落点` 集合锁基线（新增或静默消除都判红）；
> **A8** 表达式引用的变量必须**全部有事实提供方**（`QlExpressRuleEnginePortAdapter` 的 `facts.put` 集合），先剥字符串字面量再取标识符——缺一个变量，该执行项就是**静默不命中**：不报错、不告警，客户以为查了、其实没查。
> **A9** 端口落点必须**有实现者**（`implements` 零命中就不许写 `端口:X`，只能写 `端口待接:X`），且端口除实现者外**必须有调用方**（类存在≠接线）；`端口待接` 集合锁基线，接线后基线未同步也判红。
>
> **A7 是 2026-11-08 新增的**，起因是 A1–A3 都只守 ID 与 conclusion，**没有任何判据在问「这条条款到底由哪段代码承载」**。加它的当天就抓出 2 条空挂条款（Q4）。判据落地前先对全量取了一次证（手工 10 条），避免又造出「判据只覆盖样例、真实仓库全红/恒绿」的假象。
>
> **A8 是同一轮顺着「A7 只校类存在、不校接线」再往下钻的一层**：变量级比类级更细——类可能被接线了，但规则引用的变量没人给，执行项照样静默失效。实测结论是**这一层没有缺陷**：2026-11-08 补齐 7 条执行项后，40 条执行项共引用 **31 个变量**、事实提供方 **37 个**，无提供方 0。之所以固化成判据：这类缺陷**不报错**，只靠人工 grep 不可能长期守住。
>
> **A9 是再下一层，抓的是「端口在、但没人实现它」**：A7 只问「类名存不存在」，而 `端口:X` 这个措辞会被读成"这条在判"。2026-11-08 实测：4 个端口里 `ItemCatalogPort` 全仓 `implements` 零命中（`ItemCatalogGateway` 用 `ObjectProvider` 调用时解析，无实现即全 `UNKNOWN`），于是 `R-DIR-01` 写成 `端口:X` 属**过度声明**——一期它不判定，只退补件。修正为 `端口待接:X` 并锁基线。**同一轮还固化了「端口必须有调用方」**：`GraphFraudPort`/`VisualForensicsPort`/`ItemCatalogPort` 各有 3 个调用方，一旦哪天只剩实现者、没有调用方（本项目出现过"类在、零调用方"），A9 立刻判红。
>
> **已知判据边界（诚实说明）**：§11.3 的「为什么不要求出现在 QLExpress 资产」列是**自由文本**，A6 只校验条数、**不校验该列声明的载体是否真实存在/被引用**——本次是人工复核（3 个具名类 + 引用点数）。之所以不把它改成受控枚举 + 机检：这一列的语义混着「由某类实现」「由流程承载」「待接线」三种，强行结构化会把产品口径塞进代码常量，收益低于维护成本。**若日后再度出现「族级载体声明腐化」，再上判据**。

**Q4 裁定与实现（2026-11-08 已结案）**

下表是裁定前取证的成本证据，保留以便追溯「为什么这么定」。

| 选项 | 需要什么 | 现成程度 | 主要风险 |
|---|---|---|---|
| ① 补金额异常 | 同类样本 + 样本量下限；保额事实 | 历史样本查询**已存在**：`enrichPriorClaimFacts` 用 `findByInsuredIdHash` 取该被保险人全部历史案件，已排除本案、已算 90 天窗口，加「金额集合 → 均值/σ」即可；但**保额不在** `ClaimContextView`（仅 8 个字段）里，在责任额度 `LiabilityRule` / `LimitSet` 中 | 小样本 σ 不可靠（n<30 时三次异常就能把阈值撑爆）；「同类」定义未定（同诊断？同医院？同渠道？口径不同结论完全不同） |
| ①′ 只补时间轴 | 日期字段抽取 + 三元比较 | `EvidenceFact` 只有 `(docType, code, value, evidenceRef)`，日期是**字符串**；`EvidenceFieldReader` 无日期解析，需先做抽取 | OCR 日期格式歧义（`2026-03-12` vs `12/03/2026`）会误判；须先定格式白名单与不可解析时的 fail-closed 口径 |
| ② 降级二期 | 无 | 文档改动即完成 | 客户按现行规则书核对时预期落空——必须在客户版显式写「二期」，不能只改内部文档 |
| ③ 阈值显式替代 | 无（`R-AMOUNT-01/02` 已在跑） | 现成 | 口径差异必须写进客户版：绝对阈值 ≠ 3σ ≠ 保额 80%，替而不说等于换口径交付 |

> **裁定结果（2026-11-08，业务方）**：`R-FRAUD-03` 取 **①′ 补实现**；`R-FRAUD-02` 取 **① 两个子面都补**（而不是工程侧建议的 ③ 显式替代）。**裁定优先于工程建议**，实现时把工程侧担心的两条风险用闸门挡住，而不是用「不做」挡住：
>
> | 子项 | 实现落点 | 挡住风险的方式 |
> |---|---|---|
> | 时间轴（`R-FRAUD-03`） | 资产 `R-TIMELINE-01/02/03` + `EvidenceDateParser` | 只认 `uuuu-MM-dd` / `uuuu/MM/dd` 两种白名单格式；认不出 → `TIMELINE_DATE_UNRESOLVED` 转人工，**不猜**。发票日期早于就诊日即矛盾（药先开票）；晚于就诊日 >30 天才算「事后补票」，避免把跨周末补录全部打成风险 |
> | 超保额 80%（`R-FRAUD-02` 子面一） | 资产 `R-AMOUNT-07` | 保额取**计划下生效责任 `liability_limit` 的最大值**（计划级上限）。方向只会漏报不会误报；责任级精确判定需案件携带责任标识，属接线项。全部责任限额为 0 / 读不到 → `coverageLimitKnown=false` 不判，**绝不把「没配」当「限额为 0」** |
> | 同类 3σ（`R-FRAUD-02` 子面二） | 资产 `R-AMOUNT-08` | 三条闸门缺一不可：样本量 `n≥30`、标准差 `σ>0`、诊断码非空。任一不满足 → `amountSigmaReady=false` 不判。**小样本不可靠时宁可不判，也不拿不可靠统计误杀正常大额赔付** |
>
> 「同类」口径在这里取**同被保人 + 同诊断码**（可复现、不依赖外部主数据）；换成同医院/同渠道需要另立条款，不属本次范围。
