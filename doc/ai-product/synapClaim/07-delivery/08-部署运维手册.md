# 08 部署运维手册（MVP → 试点）

> 用途：试点/客户环境部署与运维的可执行手册（FDE §五"部署包+运维手册"产物的成文版）。分三部分：部署、日常运维、应急。

---

## 一、部署

### 1.1 部署形态（两档）

|**档位**|**适用**|**拓扑**|**资源要求**|
|---|---|---|---|
|轻量（试点/Demo）|Shadow 旁路、单客户试点|Docker Compose 单机：Gateway+Core+TiDB+vLLM(可选)|8C16G + 显存 ≥16G（vLLM 本地推理）|
|标准（生产）|Phase B/C|K8s 集群：Gateway×2 / Core×2 / TiDB×3 / vLLM 独立节点|按案件量横向扩展|

### 1.2 部署步骤（轻量档）

```bash
# 1. 环境准备：Docker 24+；检查端口 8080(API)/2379(TiDB)/8000(vLLM)
# 2. 拉取部署包
git clone <repo> deploy && cd deploy
# 3. 配置（config.yaml）：租户、目录库版本、规则版本、三态开关
#    密钥经 KMS/环境变量注入，config.yaml 仅持 KMS 引用（禁明文写入 application*.yaml，工程落地版 §11.3）
vi config.yaml
# 3.1 上线门禁：明文密钥扫描（git grep），未通过不得发布（工程落地版 §11.3）
./scripts/scan-secrets.sh
# 4. 启动
docker compose up -d
# 5. 验证
curl -s http://localhost:8080/api/v1/health   # 期望 {"status":"ok","mode":"shadow"}
# 6. 数据初始化：目录库导入 + 规则导入 + 评测集导入
./scripts/init-data.sh
```

### 1.3 三态开关（Shadow / Assisted / Automated）

|**模式**|**行为**|**切换方式**|**回退**|
|---|---|---|---|
|shadow|只读同步+旁路出建议+对照评测|config.yaml `mode: shadow`|关同步即可|
|assisted|工作台嵌入，人工终审|`mode: assisted`|关闭建议开关|
|automated|低风险自动通过+支付|`mode: automated` + `autoRatio: 0.05` 灰度|按比例回退|

**切换纪律**：一次只切一个开关；灰度从 5% 开始；切换后 24h 观察三指标（自动化完成率/介入率/结案时效）。

**发布纪律（工程落地版 §11.8）**：

- 禁周五 16:00 后与节假日前一日发版（无人值守窗口风险）。
- 每次变更绑定**回滚剧本**（步骤 + 判定条件 + 执行人），无剧本不予发布；剧本编号 RB-ROLLBACK-<场景>，变更记录（内容/窗口/剧本编号）入审计。
- RTO/RPO 演练每季度一次，编号 **RB-DR-<场景>**（应用无状态 RTO<5min、RPO≈0）。
- 混沌回归纳入 CI：支付 / LLM / Redis / MQ 四类故障注入 runbook，注入后对外响应码与降级动作须符合工程落地版 §11.6 依赖降级矩阵。
- 信创环境适配检查表：麒麟 OS + 鲲鹏/海光 CPU（镜像架构、JDK/依赖原生库、容器 base、vLLM 推理），对齐 FDE §四承诺；适配未通过则降级云端推理（仅非敏感数据）或关闭 AI 建议仅保留规则路径。
- 测试/生产环境隔离：测试用专属 tenant_id；生产数据须脱敏 + 假名化后方可入测试库，严禁明文个人医疗/金融数据进测试库（工程落地版 §11.11）。

## 二、日常运维

### 2.1 监控与告警（SLO）

|**SLO**|**指标**|**告警阈值**|**告警通道**|
|---|---|---|---|
|可用性 99.9%（工程门禁档；对外承诺 99.99% 须同城双活部署形态，工程落地版 §11.8 档位映射）|探活/错误率|5 分钟错误率 >1%|钉钉+邮件|
|决策 P95 ≤30s|决策链路耗时|P95 >30s 连续 10 分钟|钉钉|
|资金零差错|对账差异（对平键 `gateway_trade_no`，§11.7）|任一差异订单|紧急电话+邮件|
|评测回归|五指标|任一指标下降 >1pp|钉钉|
|数据同步（Shadow）|同步延迟 + 双跑差异可归因率|延迟 >15 分钟（自定阈值；双轨退出判据见工程落地版 §12.3，容量阈值见 §11.2）；可归因率 <95%|钉钉|
|决策图并发|并发执行数|>100（预警 >80）|钉钉|
|OCR 队列深度|积压件数|>200（>160 持续 15min）|钉钉|
|支付吞吐|TPS|<10 TPS|紧急电话+邮件|
|提交/上传限流|租户令牌桶 QPS|>10 QPS（429 带 Retry-After）|钉钉|
|待办列表 P95|工作台接口耗时|>500ms|钉钉|
|端到端（自动通过）|全链路耗时|P95 >60s|钉钉|
|决策图成功率|成功执行占比（含 FALLBACK）|<99% 连续 3 日|钉钉|
|发件箱 PENDING 积压|中继积压事件数|>10000（预警 >8000）|钉钉|

> 阈值锚定工程落地版 §11.2 容量阈值表（决策图并发≤100 / OCR 队列≤200 / 支付 TPS≥10 / 发件箱积压≤10000 / 限流 10QPS / 待办 P95<500ms / 端到端 60s / 决策图成功率≥99%）。

#### 2.1.1 四向对账调度与差异派单（工程落地版 §11.7）

| 对账 | 调度（T+1） | 对平对象 | 落库 |
|---|---|---|---|
| 支付对账 | 03:00 | 支付网关 T 日流水 ↔ settle_funding_event | reconciliation_report(PAYMENT) |
| TPA 回写对账 | 03:30 | pk-tpa 回写金额/状态 | reconciliation_report(TPA) |
| 额度对账 | 03:45 | quota_account = Σ quota_transaction | reconciliation_report(QUOTA) |
| 请款/回款对账 | 04:00 | 医院请款单 settle_claim_request、保司/公账回款 settle_receipt | reconciliation_report(CLAIM_SETTLE) |

差异派单：金额差异→资金岗；状态差异→理赔运营；额度断裂→风控；处置落 RESOLVED/ADJUSTED/WAIVED 并记 resolved_by/at，金额调账走双人复核并同步写 settle_funding_event 补偿事件。P0 资金差异 15min 内告警、1h 内人工介入，违例即 P0。

#### 2.1.2 实时不变量每小时校验清单（5 项，违例即 P0 告警）

| # | 不变量 | 判据 |
|---|---|---|
| 1 | 额度守恒 | quota_account.{deductible_used, cap_used} = Σ quota_transaction；quota_available = initial − claimed − frozen |
| 2 | 资金金额守恒 | 单结算单 PAID = HARD_RESERVED；RELEASED/REFUNDED 一一冲抵 |
| 3 | 阶段单调 | SOFT→HARD→(REVIEW_FREEZE)→PAID 无逆向 |
| 4 | 幂等唯一 | uk(tenant_id, idempotency_key) 无重复、同键金额一致 |
| 5 | 案件-结算一致 | claim_case.approved_amount = 关联结算单 PAID 金额 |

#### 2.1.3 Saga 补偿与 DLQ / 发件箱积压处置

- 补偿矩阵（工程落地版 §7.5）：支付投递失败→回冲占用（RELEASED）；回执失败/拒付→释放冻结（RELEASED）；已 PAID 退票→反向退款 + 回冲额度（REFUNDED）；请款退回/回款冲销→反向冲销并回冲额度（REFUNDED）。
- 补偿与正向操作同为发件箱事件（至少一次 + 消费幂等）；补偿失败同样入 DLQ，不允许静默丢弃。
- DLQ 处置：退避 >6 次入 DLQ → 值班排查 → 修复后重投；PENDING 积压 >10000（>8000 预警）P1 告警，中继停摆先保业务（发件箱兜底），恢复后补投。

#### 2.1.4 状态机卡单 / 退回 / 补推运维操作

| 场景 | 操作 | 入口 |
|---|---|---|
| 外部退回 | 校验来源角色 + 记 BACK_NODE + 累计回退 ≤3 | POST /api/v1/integration/claims/{id}/back |
| 推送重推 | 查 integration_sync_log → 重推 | POST /api/v1/integration/claims/{id}/repush |
| 同步失败排查 | 分页查失败记录 → 定位 → 重推 | GET /api/v1/integration/sync-failures |
| 卡单（挂起 >72h） | 人工恢复入口 | POST /api/v1/claims/{id}/hangup |

### 2.2 备份与恢复

|**对象**|**策略**|**RPO/RTO**|
|---|---|---|
|TiDB（业务数据）|每日全量 + binlog 实时|RPO ≤5min / RTO ≤1h（备份恢复/灾难恢复级；系统级高可用切换口径 RTO <5min / RPO ≈0（同步复制），见 PRD §13.2）|
|目录库/规则库（资产）|版本库（Git）|即取即用|
|评测集/标注|版本库 + 对象存储双份|—|
|审计日志|追加式独立存储（7 年）|—|

**恢复演练**：季度一次恢复演练（备份→恢复→校验数据完整性），演练记录存档。

### 2.3 数据保留与删除 SOP（合规）

|**数据**|**保留期**|**到期处理**|
|---|---|---|
|资金/决策日志|≥7 年（监管）|归档存储，只增不改|
|普通操作日志|≥180 天|自动清理|
|案件业务数据|监管归档 ≥7 年（工程落地版 §12.3 撤站矩阵；不得默认全删或全留）|归档存储；可删类（幂等记录/缓存/评测集）终止后 30 日内删除并出具销毁证明|
|评测集脱敏数据|项目存续期|删除脚本+审计留痕|

## 三、应急手册

### 3.1 故障分级与响应

|**级别**|**场景**|**响应**|**目标**|
|---|---|---|---|
|P0|资金异常/全站不可用|立即响应（值班+CEO）|5 分钟内自动恢复或降级（US-09：RTO<5min、RPO≈0）|
|P1|决策 P95 超时/数据同步中断|30 分钟内响应|4 小时内恢复|
|P2|功能缺陷/告警噪声|48 小时内修复|—|

### 3.2 典型故障处置

|**故障**|**判断**|**处置**|
|---|---|---|
|决策超时|vLLM 卡顿/OCR 慢|切规则兜底路径（AI 降级）；扩 vLLM 并发|
|资金重复支付风险|对账差异单|立即冻结该案件支付 → 查幂等键 → 人工核对 → 冲正|
|数据同步中断|Shadow 同步延迟告警|检查源系统接口/文件通道 → 断点续传恢复 → 补齐期间数据|
|评测指标下滑|发布后回归失败|回滚最近规则/模型版本（版本绑定记录）→ 复盘失败案例|
|安全事件|泄露/越权告警|按 02 方案：24h 内通知客户 → 隔离 → 取证 → 整改|

### 3.3 值班与交接

- 值班表：CEO/底座/理赔轮值（试点期 7×12 覆盖）
- 交接：值班日志（事件、处理、遗留项）每日同步
- 演练：季度 RTO/RPO 演练（编号 RB-DR-<场景>）+ 三态回退演练 + 备份恢复演练；支付/LLM/Redis/MQ 四类故障注入回归纳入 CI
