- **现状**：`AppealController.submit` 功能本就存在，但映射在单数 `/api/v1/claims/{claimId}/appeal`；契约（05 #16 / §10.1 #4 / §10.4 `claim-api.yaml`）规定复数 `/appeals`。缺口为资源名单复数未对齐，非功能缺失。

- **验证**：`mvn -o -pl bone-apps/synap-claim test` → 113/0/0；四机检全绿（详见 §12.2.1 戳记与记忆第八批）。

## 2. adapter/schedule 调度包

- **现状**：领域能力已备（`ClaimCase.closeExpired` 21→45 超期关单、`limit_hour` 刷新、对账触发、SLA 物化触发），但 `adapter/schedule` 包整体未建，无调度 Bean（§12.2.1 登记「触发入口一期未建」）。当前这些能力只能手动触发，无自动化入口。
- **改动范围**：
  - 新建 `com.bone.claim.adapter.schedule` 包（镜像 `adapter/web` 分层）。
  - **单一调度仓储（ADR-0030）**：禁散落 `@Scheduled`；统一注册/暂停/租户作用域。
  - **租户作用域声明（ADR-0031）**：每个调度入口显式声明租户作用域，禁隐式 `CurrentTenant`。
  - **全租户入口判据 + 限流（ADR-0034）**：遍历全租户的批处理须有显式全租户判据与限流，禁无差别全表扫。
  - 调度 Bean 调用既有 `*ApplicationService`（ADR-0028 入站边界不变）。
  - 可能新增 `t_schedule_lock` / `t_job_state` 状态表（落点待架构确认）。
- **影响面 / 风险**：多租户下必须显式租户作用域，避免串租户越权；全租户批处理须限流避免打爆 DB 与单租户风暴；调度须可暂停、可观测、可灰度。
- **工作量**：M（约 3–5 人日，含单测）。
- **架构关注点**：遵循 ADR-0030/0031/0034；ArchUnit 须放行新包（应用层构件白名单 ADR-0035：`adapter/schedule` 属于 adapter 层，非 application 角色包）；可能需扩 `scripts/check-application-constructs.py` 或 `ArchitectureTest` 的白名单。
- **进度（2026-10-24）**：~~已落地 `CloseExpiredClaimJob`~~ —— **该进度登记已于 2026-10-25 实机核码后撤销**：在当前工作区中，**不存在** `com.bone.claim.adapter.schedule` 包、`CloseExpiredClaimJob` 类与 `StaleClaimProjection`；全仓 grep 无命中。原 「113/0/0 + ArchUnit 23/0/0」结论在当前状态下不可复现（连 `mvn compile` 都因 `ClaimTenantRef` 缺失而失败，见事项 8）。原因判定为并发进程导致的工作区产物被抹/半丢失，而非代码回归。
- **当前真实状态（2026-10-25）**：领域能力（`ClaimCase.closeForStale`）+ 应用服务方法（`ClaimCaseApplicationService.closeForStale`）+ 全租户仓储方法声明（`findStaleEvidenceClaimsAllTenants` / `findFinishedForInspectionAllTenants`，依赖的 `ClaimTenantRef` 投影已补回）**三者齐备**；缺的是 `adapter/schedule` 包本体、Job 类与 SQL 模板。
- **落地宣称纪律（本仓已确立）**：任何「已落地」登记**必须先 `mvn clean test` 实机验证再写进文档**，且验证命令与结果摘要（如 114/0/0）须一并记录；文档不得先于代码宣告完成。库模块不自含调度器，依赖宿主应用 `@EnableScheduling`（bone-system 已开启）。
- **2026-10-25 实机基线**：`mvn -o -pl bone-apps/synap-claim clean test` → **114/0/0**（90 JUnit + 24 ArchUnit），BUILD SUCCESS。本基线可作为后续事项 2/3/6/7 落地后的对照。
- 待建：`limit_hour` 刷新 / 对账调度 / SLA 物化三个 Job 依赖各自对应的应用服务方法，目前尚未存在，待补。

- **现状**：`t_claim_inspection` 表未建；§10.1 #13（发起抽检）/ #14（抽检结论）端点代码 0 落地；抽样调度未建（§7.6 / §12.2.1 登记）。一期目标 = 三件齐备 + diff 回流闭环（案件状态回流 30/31/32 为 V2）。
- **改动范围**：
  - **建表**：`t_claim_inspection`（DDL 迁移，V 版本递增），含抽检单号、案件、抽检维度、结论、diff 字段。
  - **聚合**：`InspectionRecord`（镜像 `AppealRecord` 的 `@Table/@Column/@Version` 风格），状态机 `待抽检 → 抽检中 → 已结论`。
  - **仓储 + SQL**：`InspectionRepository` + `resources/sql/.../InspectionRepository/<method>.sql`（遵循既有文件名约定绑定）。
  - **应用服务**：`InspectionApplicationService`（创建抽检、结论、diff 回流），经 `ClaimCaseApplicationService` 推进案件状态。

## 4. V3–V5 五张表补 `t_` 前缀

- **现状**：`settle_order` / `settle_funding_event` / `appeal_record` / `claim_decision_execution` / `claim_decision_trace` 五张表缺 `t_` 前缀（V1/V2 规定业务表须 `t_` 前缀），DDL 属 L3（§12.2.1 登记「待整改」）。
- **改动范围**：在线 DDL（TiDB）rename + expand-contract 四步（加新名表/双写/切读/删旧）；存量数据迁移；代码实体 `@Table` 映射同步；既有迁移脚本 `V4__synap_claim_appeal.sql` 中 `appeal_record` 亦须一并处理。
- **影响面 / 风险**：**生产表改名高风险**，须零停机的 expand-contract（ADR-0001），双写期长；任何遗漏字段导致数据错位；回滚预案必备。
- **工作量**：S 代码改动 / 高协调成本（需 DBA + 灰度窗口）。
- **架构关注点**：L3 **须架构师审批**；严格走 ADR-0001 迁移纪律（禁 Flyway 自动迁移、增量 DDL 与代码版本强绑定）。
- **有效性复核（2026-10-24）**：模块表名**本身不一致**——V1/V2 表（`t_claim_case`/`t_claim_evidence`/`t_quota_*`/`t_adj_*`）带 `t_` 前缀，而 V3–V5（`appeal_record`/`claim_decision_execution`/`claim_decision_trace`/`settle_order`/`settle_funding_event`）不带。故本项**真实有效**（非文档误判）；探查子代理曾误判为“全模块无前缀”，已纠正。

## 5. `/review/tasks` 任务中心 vs `/claims/{id}` 案件中心 路径收敛

- **现状**：契约（05 / §10.1）按**任务中心**（`/review/tasks/*`），代码按**案件中心**（`GET /api/v1/claims` 分页待办、`POST /claims/{id}/decision`、`/allocate`）；决策图 execute/trace 路径双方一致。§10.6 #6 登记为有意偏离。
- **改动范围（推荐方案①）**：代码补 `/review/tasks` 门面适配（对外契约不变、05 无需回改），由门面路由到既有案件中心能力；或方案②改契约须同步 05 + integration-out 下游。
- **影响面 / 风险**：方案①新增门面层、不改既有路径，风险低但引入一层转发；方案②改契约波及下游，协调成本高。
- **工作量**：M（方案①约 2–3 人日）。
- **架构关注点**：未定前勿双轨维护两套路径（§10.6 #6）；与事项 3 的 #13/#14 路径决策联动。

## 6. bone-ai 能力端口接线（ADR-002 一期豁免）

- **现状**：§3.2.1 登记的六个能力端口（`AiGatewayPort` / `RuleEnginePort` / `OrchestrationPort` / `DocumentParsePort` / `TracePort` / `KnowledgeRetrievalPort`）及其 `infrastructure.client` 实现**零实现**；模块内只有 `PolicyQueryPort` / `TenantPort` / `DecisionNodeHandler`。
- **影响**：决策图（`DecisionGraphExecutor`）与 AI 安全三件套（`domain.security`）均为**域内自建**，ADR-002「禁止场景自建 AI」当前不以「复用中台」的形态成立。
- **一期处置**：登记为 **ADR-002 一期豁免**（落地版 §14 ADR 生效状态表）；对外不得宣称「已复用 AI 中台」。
- **撤销条件**：Phase C 前完成 `bone-ai-orchestration` / `gateway` / `trace` 接线，或提交豁免延期评审。
- **工作量**：L（≈8–12 人日，含契约测试 CDC）。
- **架构关注点**：已新增 ArchUnit 守护 `no_direct_bone_ai_dependency_outside_infrastructure`（当日转绿），确保**未来接线只能落在 `infrastructure`**，不得让 domain/application/adapter 出现 `com.bone.ai*` 直接依赖（即「偷接」）；撤销豁免时该规则仍须保持绿。
