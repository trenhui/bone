| 项 | 规范 |

## 4. 字段命名与类型

### 4.1 时间字段（方案 C：统一 `*_at`）

**所有时间点列**（含行创建/修改、业务事件）均使用 **`{动词或语义}_at`**，类型 **`DATETIME(3)`**。

| 用途 | 列名 | 说明 |
|------|------|------|
| 行创建时刻 | `created_at` | 默认 `CURRENT_TIMESTAMP(3)` |
| 行最后修改时刻 | `updated_at` | 默认 `ON UPDATE CURRENT_TIMESTAMP(3)` |
| 业务事件 | `last_login_at`、`expires_at`、`started_at`、`published_at`… | 由领域显式赋值，通常允许 NULL 直至事件发生 |

**行级四件套（推荐，聚合根表）**：`created_by`、`updated_by`、`created_at`、`updated_at`。

**例外（须在 COMMENT 说明）**：

| 场景 | 处理 |
|------|------|
| 只追加、永不 UPDATE 的表（如 `iam_audit_log`） | 仅 `created_at`，无 `updated_at` |
| 令牌/会话 | `expires_at`、`revoked_at` 等业务列 + 可选 `created_at` |

**禁止**：`create_time` / `update_time`、`created_at` 与 `row_created_at` 并存、`TIMESTAMP` 无时区策略的混用。

**Java 映射**：`createdAt` / `updatedAt`（`LocalDateTime` 或 `Date`），与列名蛇形转换一致；API JSON 建议 ISO-8601。

### 4.2 其它类型

- **布尔**：`is_xxx TINYINT(1)`；枚举态用 `status` + COMMENT。
- **关联列**：`{实体}_id`。
- **金额**：`DECIMAL(18,2)`（报表类可用 `DECIMAL(20,4)`，模块内统一）。
- **配置**：`JSON`（结构由契约/模块定义）。

### 4.3 布尔与 JDBC

- `TINYINT(1)` ↔ `boolean` / `Boolean`。
- 三态用包装类型 + 列 `NULL`。

## 5. 索引规范

| 类型 | 命名 | 示例 |
|------|------|------|
| 唯一索引 | `uk_{表缩写}_{字段}` | `uk_iam_tenant_code` |
| 普通索引 | `idx_{表缩写}_{字段}` | `idx_iam_account_tenant` |

- 多租户表组合索引：**`tenant_id` 置前**，如 `idx_xxx_tenant_status (tenant_id, status)`。
- 组合索引：区分度高的列在前；等值在前、范围在后。
- **不对 `deleted` 单独建索引**；按查询模式并入组合索引。
- 软删 + 业务唯一：采用 `(tenant_id, code)` 唯一 + 应用层保证已删行释放编码，或唯一索引包含 `deleted`（团队择一并在模块注明）。

## 6. 时区与默认值（业界实践）

| 项 | 建议 |
|----|------|
| **库内存储** | 统一 **UTC**（推荐）或与运维约定一致的单一时区；禁止混用 |
| **应用层** | `Instant` / `OffsetDateTime` 转换后写入；展示层按用户时区格式化 |
| **默认值** | `created_at` / `updated_at` 可用 DB 默认；**业务 `xxx_at`** 默认 `NULL`，事件发生时写入 |
| **API** | 对外 ISO-8601（含偏移或 `Z`） |

---

## 7. 分区与大表

- 日志/流水类可按 **`created_at` 或业务 `started_at`** 做 RANGE 分区（年/月）。
- 分区键须包含在**主键与所有唯一索引**中。
- 约定保留周期与归档脚本（运维）。

---

## 8. 安全与敏感数据

- 密码、密钥、Token：**哈希或 KMS**，列如 `password_hash`、`token_hash`；禁止明文落库。
- `encrypted` / 敏感配置：生产通过环境变量或配置中心注入，禁止写死在仓库。
- 日志表不得写入完整密钥、身份证号等（见日志规范）。
