# Bone 数据库开发规范

> **设计对齐**：与 [`Bone-DDD-最终实践方案.md`](./Bone-DDD-最终实践方案.md) 中的持久化与多租户约定一致；应用层主键生成、审计与租户上下文以代码与契约为准。  
> **目标数据库**：MySQL 8.0+  
> **库名**：`bone`  
> **字符集 / 排序规则**：`utf8mb4`；排序规则**默认** `utf8mb4_unicode_ci`（与根目录 `bone-init.sql` 一致）。`utf8mb4_bin` 仅用于需区分大小写的专用场景，须在表/列 COMMENT 中说明。  
> **存储引擎**：InnoDB  

---

## 文档与脚本关系

| 产物 | 路径 | 说明 |
|------|------|------|
| **全量 DDL（文档化）** | [初始脚本.sql](./初始脚本.sql) | 约 58 张表的结构定义，供评审、对照与离线建库 |
| **仓库运行时初始化** | 仓库根目录 `bone-init.sql` | 当前仓库常用的库表 + 种子数据；若与本目录 DDL 不一致，**以 `bone-init.sql`、Flyway/Liquibase 等迁移与线上一致性为准** |

执行示例（仅结构，无种子数据）：

```bash
mysql -u root -p < doc/architecture/初始脚本.sql
```

## 1. 通用约定

| 项目 | 规范 |
|------|------|
| **数据库名** | `bone` |
| **存储引擎** | 强制 InnoDB |
| **字符集 / 排序规则** | `utf8mb4` / `utf8mb4_unicode_ci`（默认）；敏感排序场景可用 `utf8mb4_bin` |
| **表命名** | 单数名词，全小写 + 下划线，格式 `{模块前缀}_{业务名}` |
| **主键** | `id BIGINT NOT NULL`，应用层 Snowflake（或项目统一 ID 策略）生成，**默认不使用数据库自增** |
| **租户** | `tenant_id BIGINT NOT NULL DEFAULT 0`（0 表示平台 / 系统级，与 `TenantContext` 一致） |
| **软删除** | `deleted TINYINT(1) NOT NULL DEFAULT 0` |
| **乐观锁** | 需要并发控制的表增加 `version INT NOT NULL DEFAULT 0` |
| **审计字段** | 与 `bone-core` 的 `AbstractEntity` 对齐：`create_by`、`update_by`、`create_time`、`update_time`（`BIGINT` / `DATETIME(3)`）；遗留表若仍为 `created_*` 命名，迁移时统一，新建表禁止混用两套命名 |
| **注释** | 表、字段、索引须有 **中文 COMMENT** |
| **外键** | **不创建物理外键**；参照完整性由应用层保证；关联列建索引 |

## 2. 模块前缀

| 模块 | 前缀 | 说明 |
|------|------|------|
| 统一 IAM | **iam** | 租户、账户、角色、权限、审计 |
| 架构治理 | **arch** | 模板、模块、聚合、扩展点、规则等 |
| 元数据 | **meta** | 实体、字段、关系、模板、质量规则 |
| 系统集成 | **int**（运行时 `bone-init.sql`）/ **integ**（文档化 DDL `初始脚本.sql`） | 连接器、流程、执行、死信、模板；**新表以 `bone-init.sql` 的 `int_` 为准**，勿在同一环境混用两套前缀 |
| 事件存储 | **evt** | 事件、快照、投递 |
| 控制台 | **cnsl** | 仪表盘、通知、最近访问 |

| 系统管理 | **sys** | 配置、告警、日志 |
| 扩展 | **ext** | 扩展点、插件、实现、脚本 |
| 主数据 | **mdm** | 实体配置、记录、版本、分类、质量检查 |

## 3. 字段命名与类型

- **布尔**：`is_xxx TINYINT(1)`；语义非「是否」时可用 `status`、`passed` 等 + 注释说明取值。
- **时间**：`xxx_at DATETIME(3)`，毫秒精度。
- **关联外键列**：`{关联实体}_id`。
- **金额**：`DECIMAL(18,2)`。
- **半结构化配置**：`JSON`。

### 3.1 布尔字段与 Java / JDBC

- **MySQL**：`TINYINT(1)` 在常用 JDBC 驱动中可映射为 `boolean` / `Boolean`；与 JavaBean `isXxx()` 习惯兼容。
- **JSON**：序列化取决于 Java 类型（如 Jackson 输出 `true` / `false`），与列类型无冲突。
- **三态**：需要 `null` 时使用包装类型 `Boolean`；列允许 `NULL` 即可。

## 4. 索引规范

| 类型 | 命名格式 | 示例 |
|------|----------|------|
| 唯一索引 | `uk_{表缩写}_{字段}` | `uk_iam_tenant_code` |
| 普通索引 | `idx_{表缩写}_{字段}` | `idx_iam_account_tenant` |

- 组合索引：区分度高的列在前，等值在前、范围在后。
- 为常用关联列、筛选列建索引；**不对 `deleted` 单独建索引**，可放入组合索引前缀（若查询模式需要）。

---

## 5. 分区与大表

- 日志类、流水类大表可按时间 **RANGE** 分区（年 / 月）。
- 分区键须包含在**主键与所有唯一索引**中。
- 通过运维脚本扩展新分区、归档或删除历史分区。

---

## 6. 变更与评审

- 新表、新列、索引变更应经过 **Code Review**，并与对应模块设计文档（[`../design/modules/`](../design/modules/)）或契约一致。
- 生产变更优先走 **版本化迁移**（与 `bone-init.sql` / 各服务迁移脚本策略对齐），避免仅手工执行文档 DDL 造成漂移。

---

## 7. 小结

本规范统一 **命名、类型、租户、软删、审计、索引与分区原则**；完整 **CREATE TABLE** 定义见同目录 **[初始脚本.sql](./初始脚本.sql)**（表数量随演进变化，以文件为准）。种子数据与线上一致的结构以 **`bone-init.sql`** 及正式迁移为准。
