# 🏗️ Bone 企业级开发平台：Java 工程规范

## 🎯 **核心命名原则**

### 1.1 包命名核心原则
```java
/**
 * BONE 包命名原则
 * B - Business Domain First (业务领域优先)
 * O - Organized Hierarchy (组织化层次)
 * N - Naming Consistency (命名一致性) 
 * E - Explicit Meaning (明确含义)
 */
```

### 1.2 标准包命名格式
```java
// 标准格式：com.company.platform.layer[.domain].component
com.bone.framework.common.util                    // 框架通用工具
com.bone.engine.metadata.domain.model            // 引擎元数据领域模型
com.bone.platform.iam.application.service        // 平台IAM应用服务
com.bone.business.order.interfaces.rest          // 业务订单接口层
```

## 🎯 **包命名最佳实践总结**

### 11.1 核心命名规则
| 规则 | 说明 | 示例 |
|------|------|------|
| **域名反转** | com.company.platform | com.bone.framework |
| **层次清晰** | layer.domain.component | com.bone.business.order.domain |
| **职责单一** | 每个包聚焦单一功能 | .service, .repository, .model |
| **命名一致** | 相同概念使用相同命名 | *Repository, *Service, *Controller |

### 11.2 包依赖规范
```java
// 允许的依赖方向
framework → engine → platform → business
    ↓          ↓         ↓         ↓
  starter → client ← gateway ← interfaces
```

### 11.3 特殊包命名约定
```java
// 内部实现包
.internal.*              // 内部实现，不对外暴露
.impl.*                  // 接口实现类

// 特定技术包
.jdbc.*                  // JDBC相关
.redis.*                 // Redis相关
.kafka.*                 // Kafka相关

// 适配器包
.adapter.*               // 适配器模式
```

### 11.4 包大小控制原则
- **适中规模**：每个包包含5-15个类文件
- **功能内聚**：相关功能放在同一包内
- **避免过大**：超过20个类考虑拆分
- **避免过小**：少于3个类考虑合并

> **"优秀的包命名是系统架构的蓝图，清晰的包结构是团队协作的基石。"**
