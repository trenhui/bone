# 📁 Bone 前端根目录命名最终方案

## 🎯 优化目标

基于用户反馈，我们需要提供一个更理想、更符合业界最佳实践的前端根目录命名方案，同时保持与后端架构的一致性和协调。

## 🔍 当前命名问题分析

"bone-web-client"存在的不足：
- 命名过长，不符合简洁原则
- "web-client"组合略显冗余
- 在大型项目中可能不够灵活
- 与后端的命名风格有一定差异

## 💡 全新命名方案推荐

### 🥇 最佳推荐：`bone-ui`

**核心优势**：
1. **简洁明了**：简短有力，易于记忆和使用
2. **职责明确**：直接表达用户界面层的核心职责
3. **架构一致性**：保持"bone-"前缀，与后端模块命名风格统一
4. **技术无关性**：不绑定特定技术栈，支持未来技术升级
5. **业界认可**：符合Angular、React等主流前端框架的命名惯例

### 🥈 备选方案：`bone-portal`

**优势**：
- 强调其作为平台入口的门户性质
- 简洁有力，易于记忆
- 符合微前端架构中主应用作为门户的定位
- 无技术栈耦合，支持未来技术升级

### 🥉 备选方案：`bone-app`

**优势**：
- 极致简洁，表达核心应用概念
- 与后端命名风格保持一致
- 为未来扩展预留空间（如bone-mobile-app）
- 符合现代应用开发的命名趋势

## 🏢 与后端架构协调性分析

从后端工程结构文档分析，后端使用了清晰的分层架构：
- framework: 技术基础设施
- engine: 平台核心能力
- platform: 企业级共享服务
- business: 领域业务实现

**`bone-ui`与后端架构的协调优势**：

1. **命名风格一致**：
   - 后端模块以功能/职责命名（如bone-framework、bone-engine）
   - `bone-ui`同样以职责命名，表达用户界面层

2. **分层概念对应**：
   - 后端有清晰的职责分层
   - `bone-ui`明确对应前端展示层，与后端架构理念一致

3. **命名空间统一**：
   - 保持"bone-"前缀，与后端模块命名保持统一性

## 💼 业界最佳实践参考

### 知名项目命名案例

1. **Angular Material**：
   - 使用`angular-material`而非`angular-ui-components`
   - 简洁直接，专注于UI组件库

2. **React Admin**：
   - 使用`react-admin`而非`react-web-admin-client`
   - 简短有力，表达核心功能

3. **Vue CLI UI**：
   - 使用`@vue/cli-ui`而非`@vue/cli-web-client`
   - 简洁明了，直接表达UI工具的性质

### 企业级应用命名趋势

- **职责优先**：优先使用表达职责的名称而非技术描述
- **简洁为王**：在明确性和简洁性之间取得平衡
- **一致风格**：保持与整体项目架构的命名风格一致

## 🔄 实施建议

如采用`bone-ui`命名方案，建议：

1. **更新所有引用**：
   - 架构文档中的目录结构描述
   - 配置文件中的路径引用
   - CI/CD流程中的路径配置

2. **命名空间协调**：
   - 内部模块命名空间可使用`@bone/`前缀保持一致
   - 应用名称可使用`bone-{domain}-app`格式

3. **迁移策略**：
   - 使用Git的`git mv`命令保留文件历史
   - 创建迁移文档，确保团队成员了解变更
   - 分阶段更新，避免大规模同时变更

## 📝 结论

`bone-ui`是最符合Bone平台设计理念和业界最佳实践的前端根目录命名方案。它简洁明了，直接表达用户界面层的核心职责，与后端架构保持一致，同时避免了过长命名带来的不便。这个命名方案既符合现代前端工程的命名趋势，也为未来的扩展预留了空间。
