# ADR-0003：五层权限模型分阶段交付（ADR-IAM-002）

| 项 | 内容 |
|----|------|
| **状态** | 提议 |
| **日期** | 2026-05-20 |
| **决策者** | 架构组 + 安全组（待评审） |
| **关联** | [BONE-总体架构 §10.2](../BONE-总体架构设计方案.md)、IAM 详设 §3.5.3 |

---

## 背景

PRD / 总体架构提出 **Owner / Deny(ABAC) / ReBAC / RBAC / Default** 五层模型；`iam_policy` 表已存在但无运行时求值。需避免将 Vision 写入 As-Is 验收。

## 决策

1. **MVP**：仅 **RBAC + Default deny**（显式 allow）。
2. **阶段 2**：进程内读取 `iam_policy`（SpEL），实现 **Deny 优先 + ABAC**。
3. **阶段 3**：ReBAC（资源关系图）、Owner 语义与字段级 ACL。
4. 每层上线前单独评审与压测；**禁止**跳过 RBAC 直接全量 ABAC。

## 理由

- 对齐 NIST 800-207 零信任「默认拒绝」。
- `iam_policy` DDL 已预留，分阶段降低迁移风险。

## 后果

### 正面

- 金融/政务客户可规划合规路线图。

### 负面 / 风险

- 策略引擎复杂度高；须专职测试与策略审计工具。

## 备选方案

| 方案 | 未采纳原因 |
|------|------------|
| 一次性上线 OPA | 运维与学习成本高 |
| 永久仅 RBAC | 无法满足 PRD 字段级/数据权限愿景 |

## 合规与迁移

- [Target] 引入 `PolicyEvaluator` 接口于 `bone-iam` application 层。
- 与 ADR-0004（独立 authz）决策联动。
