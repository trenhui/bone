## 背景

ADR-0024 通过拆分正文、Context Map、应用与一致性、门禁、迁移台账和版本历史，解决了旧主文档内容过长与重复漂移的问题。后续实践表明，分册同时带来了新的治理成本：

1. 同一规则的原则、工程口径和实施状态分散，阅读者需要跨文件拼接完整语义。
2. 仓库文档、源码 Javadoc 和校验脚本持续引用不同分册，链接和规则真源容易漂移。
3. 分册与主文档之间的“规范入口”和“实施状态真源”边界不够直观。
4. 删除或迁移章节时，缺少稳定的主文档锚点承接现有引用。

## 决策

### 1. 单一、自包含的规范真源

`doc/architecture/Bone-DDD-最终实践方案.md` 是 Bone DDD 原则、工程决策、门禁口径、实施状态、迁移台账、示例与版本历史的唯一真源。主文档必须能够脱离旧分册独立阅读和执行。

本决定取代 ADR-0024 中“正文与分册并存”的文档结构决定。ADR-0024 的其他战略、应用、CQRS、可靠性和门禁语义继续有效。

### 2. 内容按职责整合

旧分册的独有内容按“速览 → 原则 P → 工程决策 E → 门禁 G → 附录”并入主文档，不做简单拼接，不删除仍有效的规则、迁移记录、示例或版本历史。重复内容在主文档只保留一份规范定义。

### 3. 稳定锚点承接引用

主文档维护旧分册章节到内部锚点的唯一映射。源码、现行文档和校验脚本必须改为引用主文档锚点；后续调整章节位置时保留锚点名称。

### 4. 历史快照与实时状态分离

带日期的 ACL、ArchUnit 或模块实施状态作为历史快照并入附录，保留原日期，并明确其不代表当前 CI 或实时门禁状态。实时结论只能由当前主文档状态表、模块规则和实际校验结果共同证明。

### 5. 分阶段迁移

整合期间旧分册仅作为待迁移材料保留，不再作为新增引用目标或独立规则真源。确认内容完整并同步更新源码、现行文档和脚本引用后，删除旧分册。历史记录不追溯改写。

## 理由

- 单一文档能在一次评审中呈现规则语义、实施状态和迁移约束。
- 稳定锚点比文件路径更适合承接仓内长期引用。
- 附录可以保留完整历史和样板，同时避免与核心规范重复。
- 明确历史快照属性，可以防止过期状态被误解为当前门禁证明。

## 后果

### 正面

- 主文档可独立回答边界、建模、应用、事务、事件、门禁、迁移和示例问题。
- 规则修改只需维护一个规范真源。
- 现行引用统一落到稳定的主文档锚点。

### 成本与风险

- 整合阶段主文档会增长，需要依靠内部导航和附录维持可读性。
- 删除分册前必须完成内容指纹核对和生效引用迁移，避免信息或链接丢失。
- 历史 ADR-0024 保留原文，因此读取者需通过本 ADR 理解决策演进。

## 验收

1. 主文档版本为 5.1.0，并引用本 ADR。
2. 主文档提供旧分册章节到稳定内部锚点的映射。
3. 旧分册独有内容完整并入主文档，历史快照带日期和免责声明。
4. 源码、现行文档和校验脚本不再依赖旧分册路径。
5. 内容核对完成后删除旧分册，主文档可自包含使用。
