# BONE 前端 UI 规范

> **文档分工**：Monorepo 目录、Qiankun 集成、端口与工程约定以同目录 [`bone-前端架构.md`](../bone-前端架构.md) 为准；本文定义 **设计令牌、布局、组件、交互与无障碍** 等 UI 标准。

## 1. 概述

本规范基于 BONE 产品需求文档、前端架构设计方案和优化方案，定义了 BONE 平台前端的 UI 设计标准和实现规范，用于统一界面风格、视觉质量与交互一致性。

**工程实现以 §1.1、§1.2 为准**；下文各章中的视觉与交互要求为设计标准，与实现冲突时以 §1.1 分层策略为准。

### 1.1 实现策略（与仓库对齐，强制）

| 层级 | 选型 | 说明 |
|------|------|------|
| **运行时组件库** | **Ant Design 5** + **@ant-design/pro-components**（按需） | 所有业务页面（`bone-*-app`、Shell）的 Button、Form、Table、Modal 等**必须**使用 Ant Design API，禁止在业务代码中再引入第二套平行组件库。 |
| **语义设计源** | `bone-frontend/packages/ui/design-system` | BONE 设计令牌（色彩、排版、间距等）的**唯一语义来源**；通过 `applyTheme` 写 CSS 变量，并映射到 Ant Design `ConfigProvider` 的 `theme.token`（见 §1.2）。 |
| **实验性 headless** | `packages/ui/components`（如 `@bone/ui/components`） | 仅用于无 Ant Design 覆盖的特殊场景；**不得**在正式微应用业务页替代 Ant Design 基础组件。 |
| **跨应用主题** | Shell `applyTheme` + Qiankun `props` | 主题切换在 Shell 统一处理，经 `props.themeMode` 下发子应用；子应用在 `mount` 时同步 `ConfigProvider`（详见 [`bone-前端架构.md`](../bone-前端架构.md) §5.1）。 |

**禁止事项**

- 业务页混用自建 `<Button variant="...">` 与 `<Button type="primary">`（Ant Design）两套 API。
- 各子应用私自定义主色板、字号阶梯（须从 `design-system` 或 §1.2 映射表取值）。
- 经 Qiankun 加载的子应用忽略 Shell 下发的主题模式。

### 1.2 BONE 设计令牌 → Ant Design 映射

子应用与 Shell 应通过共享工具函数（建议置于 `packages/shared-utils` 或 `design-system` 导出）将下表注入 `ConfigProvider`：

```tsx
import { ConfigProvider, theme } from 'antd';
import { designTokens, applyTheme, type Theme } from '@bone/ui/design-system'; // 路径以 workspace 为准

function toAntdTheme(mode: Theme) {
  applyTheme(mode); // 同步 --primary 等 CSS 变量，供非 Ant 样式使用
  const t = designTokens;
  const isDark = mode === 'dark';
  return {
    algorithm: isDark ? theme.darkAlgorithm : theme.defaultAlgorithm,
    token: {
      colorPrimary: t.colors.primary[500],
      colorSuccess: t.colors.semantic.success,
      colorWarning: t.colors.semantic.warning,
      colorError: t.colors.semantic.error,
      colorInfo: t.colors.semantic.info,
      fontFamily: t.typography.fonts.primary,
      fontSize: 16, // 对应 typography.scales.md
      borderRadius: 6,
    },
  };
}

// 微应用 mount(props) 内：ConfigProvider theme={toAntdTheme(props.themeMode ?? 'light')}
```

| BONE 令牌 | Ant Design `theme.token` / 组件 | 备注 |
|-----------|----------------------------------|------|
| `colors.primary.500` | `colorPrimary` | 主按钮、链接、选中态 |
| `colors.semantic.success` | `colorSuccess` | 成功提示、Tag |
| `colors.semantic.warning` | `colorWarning` | 警告 |
| `colors.semantic.error` | `colorError` | 错误、危险操作 |
| `colors.semantic.info` | `colorInfo` | 信息提示 |
| `colors.gray.50`～`900` | `colorBgContainer`、`colorText` 等（按亮/暗主题选取） | 暗色背景推荐 `#121212` / surface `#1e1e1e`（与 `darkTheme` 一致） |
| `typography.fonts.primary` | `fontFamily` | 与 Ant Design 默认字体栈二选一时**以本表为准** |
| `typography.scales.md.fontSize` | `fontSize` | 正文基准 16px |
| `spacing.md` | 布局间距（`padding`/`margin` 或 Pro Layout `token`） | 非全部有 Ant Design 一等令牌，页面级样式可用 CSS 变量 |
| `breakpoints.*` | Grid `screens` 或自定义媒体查询 | 与 §9.1 断点一致 |

源码对照：`bone-frontend/packages/ui/design-system/src/tokens/`、`theme/index.ts`。

## 2. 设计原则

### 2.1 核心原则

- **一致性**：统一的设计语言和交互模式，确保用户体验的连贯性
- **简洁性**：清晰、简洁的界面，减少视觉干扰，突出核心功能
- **可访问性**：符合 WCAG 2.1 AA 级标准，确保所有用户都能使用
- **响应式**：适配不同屏幕尺寸，提供一致的跨设备体验
- **性能优先**：优化加载速度和交互响应，提升用户体验
- **可扩展性**：支持主题定制和功能扩展，满足不同业务需求

### 2.2 设计价值观

- **专业**：错误、空状态与边界情况都有明确文案，操作可预期
- **现代**：沿用 Ant Design 5 的设计语言与组件，不自建风格
- **高效**：常用操作路径不超过三步，重复动作可复用
- **可靠**：加载、失败、成功三种状态都有明确视觉反馈
- **一致**：交互模式在各页面保持一致，新增页面可直接沿用

### 3.2 主题系统

BONE 设计系统支持多种主题，包括：

- **亮色主题**：默认主题，适合日常使用
- **暗色主题**：适合夜间使用，减少眼睛疲劳
- **高对比度主题**：适合视力障碍用户，提高可访问性

主题切换通过 `applyTheme` 写入根节点 CSS 变量，并**同时**经 §1.2 映射更新各应用 `ConfigProvider` 的 `theme.token`（仅改 `body.className` 不足以保证 Ant Design 组件一致）。

高对比度主题为**目标态**（见 §13），实现前须在 `design-system` 中扩展令牌集。

## 4. 布局系统

### 4.1 整体布局

- **标准布局**：左侧固定导航 + 右侧内容区 + 顶部状态栏
- **紧凑布局**：左侧可折叠导航 + 右侧内容区 + 顶部状态栏
- **全屏布局**：无导航，适合数据可视化等场景
- **自定义布局**：支持根据业务需求定制布局

### 4.2 栅格系统

- 使用 24 栅格系统，提供灵活的布局能力
- 支持响应式断点：xs(0)、sm(640px)、md(768px)、lg(1024px)、xl(1280px)、2xl(1536px)
- 支持嵌套栅格，实现复杂布局
- 支持偏移、排序等高级功能

### 4.3 布局组件

- **Layout**：整体布局容器
- **Header**：顶部导航栏
- **Sider**：侧边导航栏
- **Content**：内容区域
- **Footer**：页脚

## 5. 组件规范

### 5.1 基础组件

#### 5.1.1 按钮

- **类型**：主要按钮、次要按钮、文本按钮、链接按钮、危险按钮
- **尺寸**：大、中、小、迷你
- **状态**：默认、悬停、点击、禁用、加载
- **形状**：圆角、方形、圆形
- **图标**：支持前后图标

```tsx
import { Button } from 'antd';

<Button type="primary" size="middle">
  主要按钮

```

#### 5.1.4 表格

#### 5.1.5 表单

- **布局**：水平、垂直、内联

#### 5.1.6 弹窗

#### 5.1.8 加载

## 6. 图标系统

### 6.1 图标库

- **Ant Design Icons**：默认图标库，提供丰富的图标资源
- **自定义图标**：支持 SVG 图标和字体图标
- **图标分类**：操作图标、状态图标、导航图标、业务图标

### 6.2 图标尺寸

| 尺寸 | 用途 |
|------|------|
| 12px | 小文本旁边的图标 |
| 16px | 按钮、输入框等组件中的图标 |
| 20px | 导航菜单、标题旁边的图标 |
| 24px | 独立显示的图标、图表中的图标 |
| 32px | 大按钮、重要操作的图标 |

### 6.3 图标使用规范

- 保持图标风格一致

- 避免过度使用图标，保持界面简洁

## 7. 交互规范

### 7.1 操作反馈

- **视觉反馈**：按钮点击、表单提交等操作有明确的视觉反馈
- **加载状态**：数据加载过程中显示加载动画
- **操作结果**：操作成功或失败时给出明确提示
- **错误提示**：表单验证、网络错误等给出清晰的错误提示

### 7.2 微交互

- **悬停效果**：按钮、卡片等元素有悬停效果
- **滚动效果**：平滑滚动、滚动到底部提示
- **拖拽效果**：拖拽元素时有视觉反馈
- **输入反馈**：输入框输入时有实时验证和反馈

### 7.3 加载状态

- **页面加载**：使用骨架屏，减少用户等待感
- **数据加载**：使用加载动画，明确指示加载状态
- **按钮加载**：按钮内加载动画，保持界面上下文
- **图片加载**：图片懒加载，提高页面加载速度

### 7.4 错误处理

- **表单验证错误**：实时提示，清晰指明错误原因
- **网络错误**：友好提示，提供重试选项
- **业务错误**：详细说明，指导用户如何解决
- **系统错误**：通用错误提示，记录错误信息供开发人员排查

### 7.5 响应速度

- **页面切换**：响应时间 < 300ms
- **表单提交**：响应时间 < 1s
- **数据加载**：响应时间 < 2s
- **交互反馈**：响应时间 < 100ms

## 8. 微前端相关（UI 侧）

**框架、生命周期、应用注册、路由衔接、主题下发**见 [`bone-前端架构.md`](../bone-前端架构.md)（含 **§5.1 主题与跨应用样式**）。本节仅约束与 **视觉与样式** 相关的微前端协作：

- **样式隔离**：优先 CSS Modules 或各应用约定的 scoped 方案；避免污染全局；若使用 CSS-in-JS，须与构建配置一致。
- **主题与设计令牌**：Shell 调用 `applyTheme` 并经由 Qiankun `props.themeMode` 下发；子应用以本文 **§3 设计令牌** 与 **§1.2 映射表** 配置 `ConfigProvider`，禁止各子应用私自分叉色板与字号阶梯。
- **事件与跨应用通信**：事件命名须带业务前缀或命名空间；敏感数据不得经前端事件总线明文传递（见平台安全基线）。

## 9. 响应式设计

### 9.1 断点设置

| 断点 | 屏幕宽度 | 布局调整 |
|------|----------|----------|
| xs | < 640px | 单栏布局，导航折叠，内容垂直排列 |
| sm | 640px-767px | 双栏布局，导航可折叠，内容开始横向排列 |
| md | 768px-1023px | 双栏布局，导航展开，内容充分利用空间 |
| lg | 1024px-1279px | 三栏布局，完整功能展示 |
| xl | 1280px-1535px | 三栏布局，内容区最大化 |
| 2xl | ≥ 1536px | 三栏布局，充分利用大屏幕空间 |

### 9.2 适配策略

- **移动优先**：优先设计移动设备体验，再逐步扩展到更大屏幕
- **内容优先**：确保核心功能在所有设备上都可用
- **弹性布局**：使用弹性布局和网格系统，适应不同屏幕尺寸
- **组件适配**：根据屏幕尺寸调整组件大小、布局和交互方式
- **性能优化**：针对移动设备进行性能优化，减少资源消耗

### 9.3 响应式组件

- **导航**：在小屏幕上自动折叠为汉堡菜单

- **组成**：图标 + 提示文字 + 操作按钮（如适用）
- **位置**：在内容区域居中显示
- **交互**：提供明确的操作入口引导用户创建数据
- **样式**：使用中性色，不抢夺用户注意力

## 20. 新增规范：分页

### 20.1 分页设计

- **默认选项**：提供 `10` / `20` / `50` / `100` 每页条数选项
- **显示位置**：表格底部右侧
- **显示内容**：显示「共 X 条」，当前页 / 总页数
- **快捷跳转**：支持输入页码直接跳转
- **更多数据**：滚动加载（无限滚动）vs 分页，根据场景选择：
  - 无限滚动：信息流、feed 流场景
  - 传统分页：管理后台、数据列表场景

## 21. 新增规范：深色模式

### 21.1 实现机制

- 基于 CSS Variables 实现，切换主题时替换根节点设计令牌
- 支持三种模式：**跟随系统**（默认）、**浅色**、**深色**
- 用户手动切换偏好存储到 localStorage

### 21.2 设计要求

- 所有组件都必须支持深色模式
- 深色模式下对比度同样需要满足 WCAG 2.1 AA 标准
  - 文本对比度 ≥ 4.5:1
  - 按钮对比度 ≥ 3:1
- 背景层次：用不同灰度区分层次，避免纯黑（#121212 推荐）

## 22. 新增规范：移动端适配

### 22.1 iOS 安全区域

- viewport meta 标签添加 `viewport-fit=cover`
- 顶部使用 `env(safe-area-inset-top)` 留出刘海区域
- 底部使用 `env(safe-area-inset-bottom)` 留出指示条区域

### 22.2 点击目标

- 最小点击尺寸 ≥ 44x44px
- 点击间距 ≥ 8px
- 避免过小的点击目标
