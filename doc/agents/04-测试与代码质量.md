## 6. 测试策略

> 平台级测试分层与总体策略（测试金字塔、各层配比）见
> [`doc/architecture/Bone-测试策略.md`](../architecture/Bone-测试策略.md)（触发才读）；本文件只承载执行侧约定。

### 6.1 后端测试

| 工具 | 版本 | 用途 |
|---|---|---|
| JUnit 5（Jupiter） | Spring Boot 自带 | 单元与集成测试 |
| Mockito | 5.11.0 | Mock |
| Maven Surefire | 3.2.5 | 测试执行 |
| ArchUnit | 1.2.1 | **架构规则静态校验**（重点） |

- 测试类命名：`*Test.java`、`*Tests.java`
- 排除：`Abstract*.java`
- 已发现使用 ArchUnit 的模块（共 20 个，代表性示例）：`bone-blueprint`、`bone-iam`、`bone-masterdata`、`bone-metadata-server`、`studio-generator`、`bone-extension-studio`、`bone-integration`、`bone-system` 等，通过 `ArchitectureTest.java` + `FreezingArchRule` 强制校验分层依赖。
- 其他测试覆盖：扩展引擎（PromotionServiceTest 等）、SmartMeta 引擎（ExpressionEngineTest、BusinessRuleEngineTest 等）。
- **现状**：多数模块已建立 `src/test/java` 目录，但覆盖率总体偏稀疏。实测覆盖率门槛的**唯一真源**见 [Bone-DDD G-1.7 的 HC-005](<../architecture/Bone-DDD-最终实践方案.md#hc-hard-constraints>)（此处**不**复述数值，避免与真源漂移）。

### 6.3 端到端测试（`scripts/e2e` · e2e_lib 公共层）

跨服务链路、建模→发布→业务全生命周期的验收能力沉淀在 `scripts/e2e/`，
公共层 `scripts/e2e/e2e_lib/` 是**唯一真源**（模块职责与 API 约定见其
`__init__.py` 模块 docstring），操作手册与脚本清单见
[`scripts/e2e/README.md`](../../scripts/e2e/README.md)。

任何 agent 在此目录新增/改动测试时的硬约定（违反即重构）：

1. **基础设施只从 `e2e_lib` 取**：登录、HTTP、建模、断言、清理一律 `import e2e_lib`，
   禁止在脚本内再复制 login/call/check/teardown 样板；配置只走 `BONE_E2E_*` 环境变量，
   不硬编码端口与口令（gitleaks 门禁会拦 `password="…"` 字面量）。
2. **断言必须有牙**：每条断言要能回答「删掉对应实现它会不会变红」；
   只断 HTTP 200 不算数，负向探针（400/409/412/422）必须与正向成对存在。
3. **退出码即信号**：登录失败立即退出、`report.finish()` 按失败数定退出码，
   禁止吞 `SystemExit` 造成假绿/假红。
4. **残留必须回收**：运行级产物带 `config.run_suffix()` 后缀并 `teardown.register()`，
   `BONE_E2E_KEEP_RESIDUE=1` 保留现场、`cleanup-residue.py --suffix … --apply` 定点补清。
5. **提交前自检**：`py_compile`（Python）/ `node --check`（探针）+ 真跑基线全绿，
   断言数与语义在重构中保持不变（基线以脚本 `汇总` 输出为准）。
6. **测试数据要生产化**：业务值一律走 `e2e_lib/fixtures`——可读单号（`BX-20261028-0706`）、
   非圆整金额、守恒拆分（`split` 的 Σ 恒等于总额）、受控中文词表、运行日倒推的业务日期；
   主表/子表/动作引用同一数据集身份（`ds.customer`/`ds.supplier`）串成链。
   **禁止**圆整数、test123、裸随机串当显示名；每个值只生成一次存变量，创建与断言共用。
   规范细节与反例对照见 [`scripts/e2e/README.md` §3](../../scripts/e2e/README.md)。
7. **造数只走唯一入口，禁止各 agent 各造一套**：先 `./run.sh datagen list` 看现有场景
   （`e2e_lib/scenarios.py`：订单→理赔 / 采购三单 / 租户 IAM / 主数据 overlay / AI 建议回流），
   能覆盖就复用；覆盖不了就**先给 `scenarios.py` 加场景并补机器可校验不变量**
   （金额守恒、日期单调、职责分离 SoD、引用完整），再写用例消费。原子值用
   `fixtures.py`（Python）/ `fixtures.cjs`（Node）；零代码取数用
   `./run.sh datagen <场景> --format json|env|md`。
8. **场景必须模拟企业真实业务**：E2E 造数要能讲通一笔业务（谁下给谁、多少钱、何时审批、
   怎么理赔），而非互不相干的随机值；`scenarios.build(...)` 返回的 `invariants.all_ok`
   必须为真，用例可直接断言它，防止「数据自相矛盾但接口 200」。
9. **接口变更必须同步用例（同一次提交内）**：Controller 新增/修改/删除端点后执行
   `./run.sh impact --status`，零覆盖端点按输出的脚手架命令补用例；
   `./run.sh impact --staged --strict` 会在 pre-commit 阻断，`--print-case-files` 供 pre-push 实跑。
   确属纯重构无法补用例时，提交信息说明并用 `BONE_E2E_IMPACT=off` 显式跳过。
10. **提交 / 推送自动校验已接线**：`./scripts/setup-hooks.sh` 安装 pre-commit
    （接口影响分析 + 造数真实性 + 功能变更↔造数资产同步 + `check.sh`）与 pre-push
    （影响分析 + 造数不变量 + 受影响用例实跑；栈不可达告警跳过，`BONE_E2E_PREPUSH=require` 强制）。
    hook 自动刷新派生映射并 `git add`；业务用例与断言不自动生成。行为细节见
    [`scripts/e2e/README.md` §2 / §3.4](../../scripts/e2e/README.md)。
11. **造数能力唯一清单**：AI 造数前执行 `python3 scripts/bone.py data list`，按
    `scripts/registry/data-assets.json` 复用资产，禁止各造一套。后端功能新增 / 修改 / 删除时按
    [`scripts/e2e/README.md` §3.4](../../scripts/e2e/README.md) 的变更矩阵同批同步造数资产与用例；
    清单损坏、场景不变量不成立、数据契约未同步由 `check-feature-data-impact.py` 阻断。

分层与单测门禁仍按 §6.1/§6.2/§7 执行；UAT 数据不变量门禁是
`scripts/seed/uat/95_validate.py`，与 e2e 互补（e2e 验行为、95_validate 验数据）。

## 7. 代码质量

### 7.1 格式化

- **Spotless** 2.43.0 + **Google Java Format** 1.17.0
- 执行：`mvn spotless:apply`（格式化）/ `mvn spotless:check`（校验）
- 在 `bone-parent/pom.xml` 中绑定到 `validate` 阶段（`spotless:check`），所有继承 bone-parent 的模块构建时自动执行格式校验；CI（`.github/workflows/ci.yml`）亦显式调用 `mvn spotless:check`。

### 7.2 静态分析（全局 + 按模块配置）

**全局**（`bone-parent/pom.xml` 继承生效，覆盖所有模块）：

| 能力 | 生效方式 | 说明 |
|---|---|---|
| JaCoCo 覆盖率门禁 | `build/plugins` 全局激活 | `prepare-agent` + `report` + `check`（verify 阶段）；阈值属性（`jacoco.minimum.coverage` 等）与版本真源在 `bone-parent/pom.xml`，门禁实测状态见 [HC-005](<../architecture/Bone-DDD-最终实践方案.md#hc-hard-constraints>)，此处不复述数值 |
| 质量插件版本集中管理 | `pluginManagement` | Checkstyle 3.3.0 / SpotBugs 4.10.4.1 / OWASP dependency-check 8.4.0——子模块**只声明插件、不写版本**，统一在此维护（4.10.x 才能解析 Java 21 字节码，旧 4.7.3 会 "No classes found to analyze"） |

**按模块显式配置**（仅以下两个 SDK；平台模块 `bone-iam`、`bone-system`、`bone-masterdata`、`bone-integration` 等**未配置**）：

| 模块 | 工具 | 触发方式 | 说明 |
|---|---|---|---|
| `bone-metadata-sdk` | Checkstyle | 显式调用 | `google_checks.xml`，`failsOnError=false` |
| `bone-metadata-sdk` | SpotBugs | 显式调用 | `effort=Max`，`threshold=Low`，`failOnError=false` |
| `bone-metadata-sdk` | OWASP dependency-check | 显式调用 | `failBuildOnCVSS=7` |
| `bone-extension-sdk` | Checkstyle | **绑定 `validate`，随构建执行** | 自定义 `checkstyle.xml`，`failsOnError=false` |
| `bone-extension-sdk` | SpotBugs | **绑定 `verify`，随构建执行** | `effort=Max`，`threshold=Low` + `spotbugs-exclude.xml` |

**注意**：
- 上述 Checkstyle / SpotBugs 均 `failsOnError=false` / `failOnError=false`，发现问题只输出报告、**不阻断构建**；JaCoCo `check` 是否阻断取决于全局阈值（真源见上表）。
- 平台模块除 Spotless 格式校验与 ArchUnit 架构校验外，还受**全局 JaCoCo 覆盖率门禁**约束（不是「什么都不配」）。
- 已过时的历史条目勿再引用：「JaCoCo 0.8.10 / PACKAGE 线 ≥80% 仅 metadata-sdk」（已改全局 BUNDLE 门禁）、「PMD 3.21.0」（已从工程移除）。
