## 后端架构规范

- **DDD + CQRS**：写模型 `command` + `*CommandHandler`（事务边界）；读模型 `query` + `*QueryHandler`（只读）。
- **六边形 / 整洁架构**：适配器（Web）→ 应用 → 领域；基础设施实现领域仓储接口。
- **统一 API 包装**：优先使用 `ApiResponse<T>`、`PageResult<T>`（定义于 `bone-core`）。
- **可选与空值**：业务代码倾向使用 `Optional<T>`，避免无意义的 `null` 传播（与团队约定、静态检查一致）。

命名约定示例：

| 类型 | 示例 |
|------|------|
| 命令 | `CreateXxxCommand` |
| 查询 | `XxxByIdQuery` |
| 处理器 | `CreateXxxCommandHandler`、`XxxByIdQueryHandler` |

权威文档（唯一）：[doc/architecture/Bone-DDD-最终实践方案.md](../architecture/Bone-DDD-最终实践方案.md)。

**持久化 P0**：新业务模块禁止以 JPA 实体 / MyBatis-Plus 默认栈为主路径；须使用 Bone Metadata SDK + `bone-datasource`（与 [AGENTS.md §5.1.1](../../AGENTS.md) 一致）。

## 架构静态检查

部分模块使用 **ArchUnit**（如 `ArchitectureTest`）校验包依赖与分层，提交前应在对应模块执行 `mvn test`。

## 代码质量工具

- **格式化**：Spotless + Google Java Format 已在 **`bone-parent`** 子树启用；CI 对 **framework / platform / business / sdk / tool、metadata-sdk / metadata-server、metadata-engine-*、integration / extension** 等模块执行 `check`。命令见 [CONTRIBUTING.md](../../CONTRIBUTING.md)。
- **密钥扫描**：本地 `bash scripts/scan-secrets.sh`（见 [09-密钥与Git历史.md](./09-密钥与Git历史.md)）；根仓 CI 当前以 [ci.yml](../../.github/workflows/ci.yml) 的 `backend-security`（OWASP）为主，**未**单独跑 Gitleaks job。
- **蓝图校验**：根 CI **未**含 `bone-blueprint`；发布前建议 `mvn -f bone-blueprint/pom.xml test`（见 [08-blueprint与主工程对齐](./08-blueprint与主工程对齐.md)）。
- **分析**：Checkstyle、PMD、SpotBugs、JaCoCo 等可在部分子模块的 Maven 配置中绑定；并非所有子模块默认开启同一套规则，以各模块 `pom.xml` 为准。

详见 [CODE_WIKI.md §8–9](../../CODE_WIKI.md)、[CONTRIBUTING.md](../../CONTRIBUTING.md)。

## 安全红线（摘要）

1. 不在代码库中提交真实密钥、Token、生产密码。
2. 对外接口注意鉴权与输入校验，避免 SQL 注入、越权访问。
3. 默认账号与弱密码仅用于本地开发，上线前必须治理。
4. 生产关闭或保护 Swagger / OpenAPI 控制台。
