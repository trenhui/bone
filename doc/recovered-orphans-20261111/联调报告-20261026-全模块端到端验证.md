# 全模块前后端联调测试报告（2026-10-26）

## 一、联调范围与方法

**拓扑**：网关 `bone-gateway(:8888)` 为南北向唯一入口；后端 11 个服务全部经健康检查确认在位；前端 10 个微应用全部起服并返回 200。

| 服务 | 端口 | 服务 | 端口 |
|------|------|------|------|
| bone-gateway | 8888 | bone-extension-studio | 8088 |
| bone-iam | 8081 | bone-ai-server | 8091 |
| bone-blueprint | 8082 | bone-file | 8107 |
| bone-system | 8083 | bone-metadata-server | 9001 |
| bone-masterdata | 8084 | synap-claim | 8087 |
| bone-integration | 8085 | bone-studio-generator | 8086 |
| 依赖：Nacos(:8848) / MySQL(:3306) / Redis(:6379) | | | |

**方法**：admin 令牌统一走网关模拟人工操作，Python 用例按「创建 → 查询 → 更新 → 状态流转 → 副作用核对」顺序驱动全链路；测试数据一律带时间戳后缀或自建一次性夹具，避免与历史数据撞名造成假失败；写端点另做「全仓端点枚举 → 缺口补测」，逐个发真实请求断言落库成功。前端除起服外，另跑 `tsc --noEmit` 全量类型检查。

## 三、本轮修复的缺陷（11 项）

### 3.1 后端代码缺陷（3 项）

| # | 缺陷 | 根因 | 修复 | 验证 |
|---|------|------|------|------|
| 1 | `bone-system` 起不来，`mvn spring-boot:run` 直接编译失败 | 告警通知端口接线（`AlertNotifierPort`）后构造器多一个参数，`AlertEvaluationTest` 未同步 ⇒ testCompile 失败 ⇒ 整个模块（含运行）构建中断 | 测试补 `@Mock AlertNotifierPort` 并补入参 | `bone-platform` 全模块 test-compile BUILD SUCCESS；system(:8083) 起来 |
| 2 | `synap-claim` 主源码编译失败，jar 无法构建 | 并行实现合入时丢了整个 `com.bone.claim.domain.port.out` 包（`OutboxPort` / `OutboxRecord`），而 `OutboxApplicationService` 与 `SpringOutboxDispatcher` 都在引用 | 补两个类型（接口 + 不可变 record，含非空校验与「失败即抛」契约注释） | `mvn package` BUILD SUCCESS；claim(:8087) 起来，35/35 + 25/25 |
| 3 | 质量规则更新把裸 SQL 泄漏到响应里 | `PUT /quality/rules/{id}` 只校验 `severity`，`name/type/expression` 缺失时直接进聚合 `update()` ⇒ UPDATE 把 NOT NULL 列写成 null ⇒ 数据库抛完整性约束，响应体是 `Column 'type' cannot be null` | 进入领域前按业务码拒绝：新增 `MD_RULE_TYPE_INVALID`，复用 `MD_RULE_EXPRESSION_INVALID`；用例改按 PUT 语义传全字段 | 由 400+裸 SQL 转为可读业务码；`mdm-rule-update` 转 PASS |

### 3.2 前端缺陷（3 项）

## 五、已知非问题 / 遗留待办（均已定位，不阻塞）

| 项 | 结论 |
|----|------|
| `api-sweep` 6 项 400 | 裸 GET 未带必填查询参数（`by-code` 需 code、`dict/items/tree|options` 需 typeCode、`open-count` 需实体、`sso/callback` 需票据、`dict-bindings` 需字段上下文），属扫描夹具，非接口缺陷 |
| `/runtime/approval/tasks/pending|decided` 403 | metadata-server 默认 `security.enabled=false`（匿名主体 + 全权限），而待办按**办理人**检索，匿名主体被业务码 `META_RUNTIME_FORBIDDEN_ACTION` 明确拒绝；接入 JWT 主体后应返回 2xx |
| `ext-exec-log-ingest` 503 | 数据面上报令牌未注入，fail-closed 设计行为（安全基线），注入 `BONE_EXTENSION_REPORTER_TOKEN` 后回归 |
| `sys-dict-enum-sync` | 需字典先绑定 enumClass（默认字典未绑定 ⇒ `SYS_DICT_ENUM_CLASS_INVALID`） |
| `mdm-instantiate` | 模板实例化的前置是模板已发布（`MD_TEMPLATE_NOT_PUBLISHED`） |
| `mdm-reconcile` | 对账只针对「由元数据转换而来」的实体，租户自建返回 `MD_MODEL_DRIFT_NO_SOURCE`（正确拒绝） |
| `iam-enroll` 501 | MFA 未在商业版/IdP 启用，fail-closed |
| `POST /apps/{appId}/permissions` | 全仓无此路由（IAM 只有 `/apps/{appId}/modules` 与 `/iam/permissions`），属端点清单误报 |
| **待修**：`meta-fields-allocate` 500 | 夹具不足时服务端 NPE 被兜成 500；入参不合法应按 400 收敛（已登记，未在本轮改动） |
