## 一、本轮根因：运行期 classpath 停在新 jar 之前

上一轮修完 SDK（`bone-metadata-sdk` 就在仓内 `bone-engine/bone-metadata-sdk`）后，
**只在 `.m2` 里装了新 jar，却没重启任何服务**，于是所有在跑的进程 ClassLoader 里仍是旧 jar。
症状链（全部由这一个原因派生）：

| 表象 | 真实根因 |
|---|---|
| `POST /api/v1/iam/accounts` → 500 / `IAM_DEPT_NOT_FOUND` | 旧 jar 的 `findById` 缺陷（缺 `m.id` 条件）仍在工作 |
| `NoClassDefFoundError: com/bone/metadata/sdk/query/context/DeleteContext` | 服务进程（02:37 起）早于 jar 落盘（02:41），内存里是旧 jar |
| C4/C7/C8 一片「分页信封 total/page/size 缺失」「返回 array 实为 dict」 | 端点其实返回 500，错误体自然没有分页信封——**不是契约漂移** |

**处置**：整体重启 10 个服务（脚本 `/private/tmp/bone-e2e/up_rest.sh`），重启后 C4/C7/C8 全部转绿。

> 教训（可复用）：**改了仓内 SDK 必须 `mvn -o -pl bone-engine/bone-metadata-sdk clean install`，
> 然后重启全部下游服务**；只 install 不重启等于没改。

## 五、环境纪律（本轮新增，写进 MEMORY）

- **后台起进程必须 `</dev/null`**：否则后台任务继承父 shell 的 stdin，父 shell 不退出，
  拉起它的调用方永远等不到返回（实测 python 脚本卡死 6 分钟）。
- **health 探测别把 401 当 DOWN**：generator/extension 的 actuator 需鉴权，判定要用端口探测
  （`lsof -nP -iTCP:<port> -sTCP:LISTEN`）而非只看 `/actuator/health` 的 200。
- **admin 账号密码是 `123456`**（`bone-init.sql` 里那个 BCrypt 对得上），不是 `admin123`；
  `chains.py` 的 `ADMIN` 常量本来就是对的，手工复现链路时别写错。
- **`/api/v1/iam/depts` 与 `/api/v1/iam/menus` 是 405**，只有 `/depts/tree`、`/menus/tree` 可用；
  前端两页也只用 `/tree`，别照着 405 的接口去"修"页面。
