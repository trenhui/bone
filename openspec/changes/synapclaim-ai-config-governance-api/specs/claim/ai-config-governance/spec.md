## Purpose

把 AI 自动初审的三层配置从静态、只读、不可审计的状态，升级为有权限边界、只收紧不放开、可随时关闭回落的配置治理能力；同时把 AI 建议的曝光与人工裁决变成服务端可计量的事实，使采纳率有真实分母且不会被重放污染。

## ADDED Requirements

### Requirement: 配置写入只能收紧阈值

系统 SHALL 对 L1/L2/L3 配置写请求逐字段比较当前生效值，凡使阈值更宽松（降低门槛、扩大自动放行范围）的写入 MUST 被拒绝并返回可辨认的错误码；相等或更严格的写入方可通过，且每次写入 MUST 留审计记录。

#### Scenario: 放宽阈值被拒

- **WHEN** 治理页提交一个低于当前生效值的自动初审阈值
- **THEN** 写入 MUST 被拒、库中值不变、审计记录标注拒绝原因

#### Scenario: 收紧阈值生效

- **WHEN** 提交一个更严格的阈值
- **THEN** 写入成功、读回值等于新值、审计记录含旧值与新值

### Requirement: 写 API 可关闭并回落只读

系统 SHALL 提供写 API 开关；关闭后所有配置写请求 MUST 被拒，治理页 MUST 回到只读且仍能查看当前配置，不得出现「页面可编辑但提交失败」的暗示。

#### Scenario: 开关关闭后提交

- **WHEN** 开关关闭时治理页提交任一配置变更
- **THEN** 返回明确的只读错误，页面不展示可提交控件，库中值不变

### Requirement: AI 建议曝光与裁决回流

系统 SHALL 记录 AI 建议曝光事件作为采纳率分母，并 SHALL 记录人工裁决（含 `traceId`、AI 参与四态、`ReasonType` 四值）；仅 `AI_ASSISTED` 且非 `blind_label` 场景允许裁决，端点 MUST NOT 改案件状态或写资金。

#### Scenario: 曝光计入分母

- **WHEN** 初审页展示一条 AI 建议并上报曝光事件
- **THEN** 事件落库，采纳率统计的分母 +1，且事件不带姓名/证件/金额

#### Scenario: 盲标场景拒绝裁决

- **WHEN** 对 `blind_label` 场景或非 `AI_ASSISTED` 参与态提交裁决
- **THEN** 请求 MUST 被拒，不产生裁决事实

### Requirement: 事件重放幂等

系统 SHALL 以租户内 `event_id` 为唯一幂等键：相同键相同载荷重放 MUST 返回首次结果；相同键不同载荷 MUST 返回 409，不得覆盖首次事实。

#### Scenario: 同键重放

- **WHEN** 用同一 `event_id` 与相同载荷重复上报
- **THEN** 返回首次结果，库中仅一条事件

#### Scenario: 同键不同载荷

- **WHEN** 用同一 `event_id` 上报不同载荷
- **THEN** 返回 409，首次事件内容不变
