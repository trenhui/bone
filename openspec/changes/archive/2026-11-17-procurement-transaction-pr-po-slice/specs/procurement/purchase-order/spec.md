# Spec Delta

## Purpose

定义采购订单从创建到下达的行为契约，覆盖供应商交易资格闸门、法人实体隔离、订单金额一致性、下达时价格快照冻结与不可变、终态保护与非法迁移拒绝，使下游履约与财务能够据此判断一张订单是否具备被执行的前提。

## ADDED Requirements

### Requirement: 采购订单创建与供应商交易资格闸门

系统必须在创建采购订单时校验供应商是否已开通交易与付款资格。未开通交易资格的供应商不得用于下单，校验不通过时必须拒绝建单且不产生订单记录。

#### Scenario: 已开通交易资格的供应商可以下单

- **WHEN** 使用交易状态为 `ACTIVE_VENDOR` 的供应商创建采购订单
- **THEN** 系统创建订单并返回订单号与初始状态 `DRAFT`

#### Scenario: 待开通供应商被拒绝

- **WHEN** 使用交易状态为 `PENDING_VENDOR` 的供应商创建采购订单
- **THEN** 系统拒绝建单并返回错误码 `31003`，不产生订单记录

#### Scenario: 付款冻结的供应商被拒绝

- **WHEN** 使用交易状态为 `PAYMENT_BLOCKED` 的供应商创建采购订单
- **THEN** 系统拒绝建单并返回错误码 `31003`，错误信息说明该供应商当前不具备交易资格

#### Scenario: 已停用的供应商被拒绝

- **WHEN** 使用交易状态为 `INACTIVE_VENDOR` 的供应商创建采购订单
- **THEN** 系统拒绝建单并返回错误码 `31003`

#### Scenario: 供应商不存在时拒绝建单

- **WHEN** 请求引用的供应商在供应商主数据中不存在
- **THEN** 系统拒绝建单并返回供应商不存在或未开通的明确错误，不静默创建订单

### Requirement: 法人实体隔离

采购订单必须携带法人实体标识，且该标识必须与供应商在该法人下的归属一致。跨法人下单必须被拒绝，不得以「供应商存在」为由放行。

#### Scenario: 法人实体不匹配被拒绝

- **WHEN** 创建采购订单时提交的法人实体标识与供应商归属的法人实体不一致
- **THEN** 系统拒绝建单并返回错误码 `31004`

#### Scenario: 法人实体匹配时通过

- **WHEN** 创建采购订单时提交的法人实体标识与供应商归属一致，且供应商交易资格为 `ACTIVE_VENDOR`
- **THEN** 系统通过闸门校验并创建订单

### Requirement: 订单金额与行金额一致性

采购订单总额必须等于全部明细行金额之和，该一致性必须在同一订单内强一致成立。不一致时不得创建或提交订单。

#### Scenario: 总额与行金额合计不一致被拒绝

- **WHEN** 创建或提交采购订单时，声明的订单总额与各明细行金额合计不相等
- **THEN** 系统拒绝该操作并返回错误码 `31402`，订单状态不发生变化

#### Scenario: 总额按行金额合计自动成立

- **WHEN** 创建采购订单时提供若干明细行及其单价、数量、税率
- **THEN** 系统按行计算金额并汇总为订单总额，查询返回的总额与行金额合计一致

#### Scenario: 金额精度满足四位小数

- **WHEN** 订单行的单价形如 `42.5`、数量形如 `100`、税率形如 `0.13`
- **THEN** 系统按四位小数保存行金额与订单总额，不出现浮点舍入漂移，币种随订单保存

### Requirement: 订单提交与审批

采购订单必须经提交才能进入审批。提交时必须同时满足行金额合计一致、供应商交易资格有效、法人实体匹配三项条件，任一不满足即拒绝提交。

#### Scenario: 草稿提交成功

- **WHEN** 对处于 `DRAFT` 状态且满足金额一致性、供应商资格、法人匹配三项条件的订单执行提交
- **THEN** 状态变为 `SUBMITTED`

#### Scenario: 审批通过后进入已批准

- **WHEN** 审批人对处于 `SUBMITTED` 状态的订单给出通过结论
- **THEN** 状态变为 `APPROVED`

### Requirement: 下达与价格快照冻结

订单下达必须在同一操作内冻结价格快照，快照一经生成不可修改。缺少价格快照时不得下达。

#### Scenario: 缺少价格快照时下达被拒绝

- **WHEN** 对处于 `APPROVED` 状态但尚未生成价格快照的订单执行下达
- **THEN** 系统拒绝下达并返回错误码 `31405`，订单状态保持 `APPROVED`

#### Scenario: 下达成功并冻结快照

- **WHEN** 对处于 `APPROVED` 状态且价格快照可生成的订单执行下达
- **THEN** 订单状态变为 `SENT`，同时生成一条不可变的价格快照，快照包含订单号、版本号、逐行净价、税额、币种与计算哈希，并返回快照引用

#### Scenario: 快照在重复计算后保持不变

- **WHEN** 同一订单版本已存在价格快照，再次触发快照计算
- **THEN** 已冻结快照的净价与计算哈希均不发生改变，不产生第二条同版本快照

#### Scenario: 未下达订单查询不到快照

- **WHEN** 查询处于 `DRAFT` 或 `SUBMITTED` 状态的订单详情
- **THEN** 返回的快照引用为空，且不暴露任何未冻结的价格快照内容

### Requirement: 终态保护与非法迁移拒绝

订单状态迁移必须按显式迁移表裁决，未列出的迁移一律拒绝并返回可读的非法迁移错误，错误中必须包含当前状态、被拒绝的事件与当前允许的事件集合。已取消与已关闭的订单一律不接受状态回写。

#### Scenario: 已关闭订单回写被拒绝

- **WHEN** 对处于 `CLOSED` 状态的订单执行任意状态推进
- **THEN** 系统拒绝并返回错误码 `31403`

#### Scenario: 已取消订单回写被拒绝

- **WHEN** 对处于 `CANCELLED` 状态的订单执行任意状态推进
- **THEN** 系统拒绝并返回错误码 `31403`

#### Scenario: 跳步迁移被拒绝

- **WHEN** 对处于 `DRAFT` 状态的订单直接执行下达
- **THEN** 系统拒绝并返回非法迁移错误，错误中同时给出当前状态、被拒绝的事件与当前允许的事件集合

#### Scenario: 并发状态推进只有一个成功

- **WHEN** 同一订单在相同版本上被并发提交两个不同的状态推进请求
- **THEN** 只有一个请求成功，另一个返回版本冲突或非法迁移错误，订单不会被写入两个状态

### Requirement: 订单详情查询

系统必须提供按订单号查询详情的能力，返回订单头、全部明细行与价格快照引用。查询必须受读权限约束，且不得返回超出订单范围的供应商敏感字段。

#### Scenario: 查询返回订单头与明细行

- **WHEN** 具备 `procurement:purchase-order:read` 权限的用户按订单号查询已存在的订单
- **THEN** 系统返回订单头信息、全部明细行与快照引用，金额与币种完整

#### Scenario: 查询不存在的订单

- **WHEN** 按一个不存在的订单号查询
- **THEN** 系统返回未找到类错误，不返回空壳订单对象

#### Scenario: 无读权限时拒绝查询

- **WHEN** 不具备 `procurement:purchase-order:read` 权限的调用方发起查询
- **THEN** 系统拒绝并返回无权限错误，不泄露订单是否存在

### Requirement: 采购域不裁决发票与付款

采购订单能力不得提供任何发票匹配、放行或付款触发接口。订单下达只产生可被履约引用的交易数据，付款裁决属于财务域。

#### Scenario: 不存在付款或放行接口

- **WHEN** 调用方尝试通过采购订单端点触发付款或发票放行
- **THEN** 系统不存在此类端点，请求返回未找到，不执行任何付款相关副作用
