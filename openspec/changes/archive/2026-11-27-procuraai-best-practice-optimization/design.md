# Design

## Context

本次是文档族内的纯登记与建议产出，不修改任何生产代码或机器判据。当前族内已存在 27 轮台账与 D-19～D-22 开口项（见 `decisions/DECISION-REGISTER.md`）；自查发现的 N1（配置化交付）、N2（内控体检规则集）、N3（体验三层）、N4（审批流自助 playbook）四项漏项中，N1 与 N2 尚无登记落点，N3 需并入 S4 采集口径。工作区另有 8 个上一轮 D-19～D-22 的未提交文档改动（同主题基线）与一个无关 change `procuraai-business-aggregates-completion`（业务聚合代码，open 阶段），两者均需保护。

## Goals / Non-Goals

**Goals:**
- 在 `outputs/` 生成一份可执行的分级优化建议方案，逐条给出证据、落点、红线与 owner 边界。
- 登记 D-23、D-24 两个开口项，保持决策表六列连续。
- 把六条内控规则挂到 03 卷既有 R/ER 规则编号，把三项体验指标补上可采集口径。
- 全程不新增能力码、不改契约工件与 CI 三入口判据集合。

**Non-Goals:**
- 不实现任何规则引擎代码、不接真实模型、不声明效果达标。
- 不改可见性矩阵、八码集合、人工终决红线、DDL、evalset、门禁常量。
- 不合并/删除历史过程记录，不回改历史台账数字。

## Decisions

1. **用 tweak 而非 full**：改动局限于单一文档族、无 spec 级行为变化、无跨模块架构协调 → Runtime 路由 `tweak`（`requires_confirmation: false`），`skip_specs: true`。备选 full 会引入 brainstorming 与完整计划，对纯登记项边际收益为负。
2. **隔离方式 current**：用户长期约束「只在 dev 分支工作、不自建/切分支」排除 branch 与 worktree，唯一合法选项是 `current`。
3. **D-23/D-24 只登记为 `Proposed`**：沿用 D-19～D-22 的「只登记开口项、不改现行结论」纪律，避免制造已落地的假象；D-24 明确「纯规则、不涉模型、不自动定性」。
4. **内控规则挂既有 R/ER 号而非新编号**：03 卷已有 R/ER 规则体系，复用可避免编号漂移与自检探针误伤；新增子节可能触碰 A10 章节守护，故采用既有行内补充。
5. **建议方案落 `outputs/`**：符合项目「评估报告落 outputs、不进文档族」约定；新增报告会触发 A10.27 索引守护（L3），因此本轮以独立路径交付并在台账诚实标注，不擅自改 `indexCount` 与门禁常量。
6. **不重复修 D-19～D-22 空行**：该修复已在上一轮工作区改动中完成，本轮仅核对表连续性，不重复编辑同一处。
7. **验证中发现并修复 F1 探针假阴（本 change 内完成）**：Build 末尾跑 self-test 发现 `m_foundation_drop_column`（F1 验收判据列删掉）注入后仍绿——根因是上一轮 D-19 把「四类结构化资产结构化率 ≥ owner 阈值（…）；」插入 F1 验收判据列中间，切断了探针的精确文本锚点。修复不改门禁脚本与判据集合，只把该判据句移入 F1 可验收动作列 ⑤，使验收判据列恢复探针锚点原文；语义完整保留。验收：主门禁 10/10 + self-test 157/157（F1 探针重新转红）。这印证了项目铁律「改真源文本须同步探针」。

## Risks / Trade-offs

- [新增口径无机器守护] → 诚实标注「不在 CI 三入口判据集合内」，纳判据须走 D-11 四入口一致流程（L3），留 owner。
- [A10.16 黑名单误伤] → 新文案避开「未接 CI」「本轮未改 CI」「三条 ProcuraAI* blocking」精确串，统一用「不在 CI 三入口判据集合内」表述。
- [A10.27 新增 outputs 报告转红] → 报告以独立路径交付，不改 `indexCount`/门禁常量；在台账标注该暴露面。
- [轮次索引不一致] → 同步 README / llms.txt / 资产登记 / 决策登记的轮次串为 28 轮（若这些文件已有独立改动则不覆盖，仅追加必要行）。
- [并行会话碰撞] → 编辑前对目标文件做 mtime 双采样，发现变化即停；不触碰无关 change。

## Migration Plan

无代码迁移。文档编辑逐文件落盘，每批后跑主门禁静态核对；全部完成后跑对齐门禁与 OpenSpec 校验，记录真实结果（不声称未实际执行的绿）。

## Open Questions

无可在不改变方案或任务拆分前提下推迟的问题。D-16 八码冻结、D-15 评测扩容、D-02 四角色会签属 owner 裁决，已在决策登记保持 `Proposed`，不在本 change 范围内。
