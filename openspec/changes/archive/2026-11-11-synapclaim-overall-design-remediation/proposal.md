## Why

《04-design/总体技术方案.md》是 `role: ssot / currency: current` 的架构真源。2026-11-11 的独立诊断发现：§13.1 里程碑 A 的判据「引擎按 JSON 取值算钱」依赖被同一行明确排除的 M2 ②③④，逻辑不可达；两个已知 P0 资金缺陷（复算取当期 ACTIVE 责任、幂等契约违约）只登记在诊断报告交人清单，未进任何里程碑或 §13 台账；决定上线的 M2.5 在 §9.1 / §11 均无工程定义；另有 4 处数字与口径漂移（台账条数 10 vs 11、文档总数 63 vs 68、Port 判据与实测相反）。读者按本文排期或写 ArchUnit 断言会直接踩坑。本次在**纯文档层**收口全部「合理且可自主执行」的整改，不改代码 / DDL / CI。

## What Changes

- 修正 §13.1 里程碑 A / B 依赖划分：把 ② 写侧双写与 ③ 3a 键级回落随判据移入 A（二者已落地且零行为变更），③ 3b 读侧切主与 ④ 写入期解锁仍归 B，使 A 判据可达；同步重写末段论证与变更隔离窗口。
- §13 台账新增 **O-12 / O-13** 登记两个已知 P0 资金缺陷，并设为里程碑 A 的**准入门槛**（先止血再扩能力）；修复动作本身仍属 L3，保持交人清单登记、不改代码。
- §9.1 五步表补 **M2.5 正式一行**、§11 补 **R11**、O-10 补指针，给这项资金行为变更完整的前置 / 验收 / 回滚 / 触发定义。
- 修正 §4.1 规约 2：把已被实测推翻的「每个 Port 有且仅有一个适配器」改为真实判据（至多一个无条件实现 + 至多一个 `@Primary`、扫描排除匿名 / 局部类），统一「20 个 `*Port.java` 文件 / 23 个出站接口」两个口径；同步 §2 读图要点与 §3 架构图。
- 按业界实践强化 §9.1.1 ④ 读兼容层语义（未知键保留并回写，AWS Builders' Library）与三格兼容矩阵（跨版本自动化验证为 ④ 解锁硬前置，而非可延后目标态）。
- 澄清 §1.1 G3 一期验收口径：G3a 已达成，G3b / G3c 属能力储备（免 DDL 不免发版）、决策表外置为二期选型，不计入一期已达成承诺。
- 消除数字漂移：§0 / §12 的「10 条登记」与四处「文档总数保持 63」改为指向台账末位 O-xx 编号与 `docs.manifest.json`，不再写死。
- §0 增「当前态快照」评审入口，并声明带日期批注属过程记录、机检只锁判据不锁批注。

明确不做（非目标）：不改 Java / SQL / 前端 / DDL / 迁移 / `scripts/check.sh` / CI；不修复 O-12 / O-13 的代码缺陷本身（L3 需架构师评审凭据）；不新建设计文档（D2）；不把目标态写成已生效；不改 §4 归属表与基线行的实测数字；不新建或外置过程记录文档。
