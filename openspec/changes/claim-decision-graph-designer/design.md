## Context

决策图由 `claim-ruleset.json` 配置驱动，执行引擎规格明确「只提供允许跳过的节点集合，不得改变节点顺序或注入新节点」。前端已有只读元数据视图 `adjust-attribution.ui-schema.json`（displayModes: view）。详见 proposal.md。

## Goals / Non-Goals

**Goals:**
- 把只读视图升级为可编辑编排，仅限既有配置维度
- 非法配置 fail-closed，灰度可回滚
- 不改执行引擎语义

**Non-Goals:**
- 不引入图定义 DDL、不改资金路径、不做低代码表单设计器

## Decisions

**决策 1：沿用配置文件，不建图定义表。**
编排结果仍写 `claim_flow_config`（外部文件）而非数据库表。备选是新增图定义表——否决，因引入 DDL 属 L3 且本轮范围要求规避。

**决策 2：编辑权限收敛到「允许跳过集合」。**
编辑器只暴露执行引擎允许的配置维度。备选是开放完整 DAG 编辑——否决，因会突破引擎「顺序不可变」约束，需改引擎与资金语义。

**决策 3：校验前置 + 灰度。**
保存前校验（节点存在性/必需节点/跳过集合合法性），通过后灰度发布并支持秒级回滚。

## Risks / Trade-offs

- [编辑器被误认为可改流程顺序] → UI 明确只读节点顺序，只开放跳过集合；规格钉死
- [坏配置影响执行] → 校验前置 + 灰度 + 秒级回滚 + fail-closed
- [配置变更影响决策结果] → 灰度门禁与变异测试覆盖

## Migration Plan

无数据迁移。部署后现有配置不变；编辑器为增量入口。回滚为恢复上一版配置文件。
