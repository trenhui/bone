# claim/liability-rule-json-dual-read Specification

## Purpose
定义责任规则聚合 JSON 在读侧的按键回落语义、默认关闭的读开关，以及新旧两条路径的双轨比对契约。目的是在「写入已影子化」与「读侧切主」之间建立一个零行为变更、可逐笔验证、可随时回退的中间态，使后续是否允许切主由实测差异率决定，而不是由设计稿的乐观假设决定。

## Requirements

### Requirement: 按键回落，禁止整列判断

系统 SHALL 按**单个规则键**解析责任规则：聚合 JSON 中存在该键时取 JSON 值，缺失时取对应旧标量列。系统 MUST NOT 因聚合 JSON 非空而把全部键一次性切到 JSON 源，也不得因聚合 JSON 为空而拒绝读取旧标量列。

#### Scenario: 只配一个键的 JSON

- **WHEN** 某责任行的聚合 JSON 仅含 `pay_percent`，而 `liability_deduct` / `liability_limit` 有旧标量值
- **THEN** `pay_percent` 取自 JSON，另外两键取自旧标量列，三个结果与各自真源数值相等

#### Scenario: 整列判断写法必被拒绝

- **WHEN** 把实现改成「聚合 JSON 非空则全部键走 JSON」并运行双轨比对用例
- **THEN** 单键场景的用例 MUST 失败（变异验证转红），且失败信息能定位到被错误丢弃的键

#### Scenario: 历史行 JSON 为空

- **WHEN** 读取 M2 之前创建的责任版本行（聚合 JSON 为 NULL）
- **THEN** 三个可映射键全部取自旧标量列，复算结果与迁移前逐笔相等，且不需要任何存量回填

### Requirement: 键分类的缺省语义

系统 SHALL 对两类键区别处理：A 类三个可映射计算键缺键时回落旧标量，且 JSON 与旧标量**同时为空** MUST 拒绝并给出字段级错误；B 类六个可选限定维度缺键表示「不施加该约束」，MUST NOT 被当作 0，也 MUST NOT 因缺键拒绝读取。

#### Scenario: A 类键双空必拒

- **WHEN** 某 A 类键在聚合 JSON 中缺失，且对应旧标量列也为 NULL
- **THEN** 系统拒绝该次读取并报出具体键名，不得静默按 0 计算

#### Scenario: 只配一个 B 类键

- **WHEN** 聚合 JSON 只含一个 B 类维度，其余五个 B 类维度均缺失
- **THEN** 只施加该维度，其余维度不被当作 0、不被当作必填、不产生拒绝，赔付结果与「不施加任何 B 类约束」的基线在其余维度上一致

#### Scenario: 历史行不施加 B 类约束

- **WHEN** 历史责任版本行的聚合 JSON 为 NULL
- **THEN** 六个 B 类维度全部按「不施加约束」处理，不得把 B 类键判为 fail-closed

### Requirement: 未知版本、未知键与非法 JSON 必须 fail-closed

系统 SHALL 在读取期拒绝语义版本不在已知集合内、含未知键、或无法解析的聚合 JSON；拒绝 MUST 带字段级或键级错误，且 MUST NOT 静默回落到旧标量路径后继续计算赔付金额。

#### Scenario: 未知语义版本

- **WHEN** 聚合 JSON 的 `schemaVersion` 为未知值（例如未来版本 2）
- **THEN** 读取被拒绝并报出版本号，不得按版本 1 的语义解释

#### Scenario: 未知键

- **WHEN** 聚合 JSON 含拼写错误或不属于已知集合的键
- **THEN** 读取被拒绝并报出该键名，不得忽略该键后继续

#### Scenario: 非法 JSON 文本

- **WHEN** 聚合 JSON 列存有不可解析的文本
- **THEN** 读取被拒绝并报出解析错误位置，不得当作「整列为空」走旧路径

### Requirement: 读开关默认关闭且零行为变更

系统 SHALL 提供读侧开关，**默认值必须为关闭**。开关关闭时，赔付计算 MUST 与 M2 ② 落地后的行为逐笔一致，且 MUST NOT 解析聚合 JSON。开关打开时，系统 SHALL 同时计算旧标量路径与按键回落路径并逐笔比对；差异 MUST 只被记录（日志/计数），MUST NOT 阻断请求，也 MUST NOT 改变本次请求返回的赔付金额。

#### Scenario: 开关关闭时走旧路径

- **WHEN** 使用默认配置读取任意责任行（含已有合法聚合 JSON 的新行）
- **THEN** 赔付金额与关闭 JSON 分支的实现逐笔相等，且聚合 JSON 解析次数为零

#### Scenario: 开关打开时双轨比对不阻断

- **WHEN** 打开读开关并注入一条两条路径结果不同的责任行
- **THEN** 系统记录差异（含责任 ID 与差异键），本次请求仍按旧标量路径返回金额，不抛异常、不改写金额

#### Scenario: 删除 JSON 分支的变异必须转红

- **WHEN** 从回落实现中删掉 JSON 分支并运行比对用例集
- **THEN** 至少一个用例失败，证明用例集对实现有判别力

### Requirement: 双轨比对按数值相等判定

系统 SHALL 以数值相等（而非字符串逐字相等）比对金额类规则值。聚合 JSON 在 MySQL 中会被规范化（例如 `90.00` 变 `90.0`、键序重排），逐字比对 MUST NOT 被用作等价判据。

#### Scenario: 小数规范化不产生误报

- **WHEN** 写入聚合 JSON 的金额为 `90.00`，存储层规范化为 `90.0`
- **THEN** 双轨比对判定为相等，不产生差异记录

#### Scenario: 真实数值差异必须被发现

- **WHEN** 聚合 JSON 的金额为 `90`，旧标量列金额为 `80`
- **THEN** 双轨比对判定为不相等并记录差异键与两侧数值

### Requirement: 阻塞项必须以可判定条件登记，不得制造假绿

系统 SHALL 对「消费方为零的新字段」与「离线制品缺失的门禁」给出明确的触发条件与验证命令，且 MUST NOT 落一个无人消费的实体/DDL，也 MUST NOT 接入一个从未成功运行过的检查作为门禁。登记内容必须能被机检或命令复核。

#### Scenario: 消费方为零的新字段

- **WHEN** 检索 `engine_version` 在理赔模块源码中的读取点结果为零
- **THEN** 不新增实体与 DDL，台账中写明触发条件（消费方落地时同批入库）与复核命令

#### Scenario: 离线制品缺失的门禁

- **WHEN** 本地依赖仓库中不存在变异测试制品、`mvn -o` 无法解析
- **THEN** 不接入构建门禁，台账中写明触发条件（CI 联网 + 路由开关生产启用评审前）与复核命令；不得把它写成已生效的门禁

#### Scenario: 等待期间不会静默过期

- **WHEN** 时间流逝而触发条件未发生
- **THEN** 台账条目仍带有可判定的触发事件与复核命令，可被文档门禁持续校验，不依赖人工记忆
