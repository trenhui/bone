# claim/case360-embedded-workflow Specification

## Purpose
把围绕同一赔案的多类作业内聚到单一案件视图，让作业人员进入案件后不再重复输入 18 位案件 ID，也不必在侧栏菜单与独立页面之间来回跳转；同时保留所有既有深链入口与逐案人工终审的安全下限。

## Requirements

### Requirement: 案件上下文在全部单案作业视图中唯一且驻留

系统 SHALL 以 URL 中的 `claimId` 作为案件上下文的唯一数据源。作业人员进入案件后，在「材料与 OCR / 理算归因 / 资金与结算 / 申诉复议 / 挂起恢复 / 后督质检」六类作业视图之间切换时，不得要求再次输入案件 ID，不得跳离案件视图，且目标视图展示的数据必须属于同一 `claimId`。

#### Scenario: 从工作台进入案件后切换作业视图
- **WHEN** 作业人员从待办队列进入某案件，随后依次切换六个作业视图
- **THEN** 每次切换都停留在同一案件视图内，不出现案件 ID 输入框，各视图读取的数据均属于该 `claimId`

#### Scenario: 深链分享后直接落在指定视图
- **WHEN** 用户打开带有 `claimId` 与 `tab` 参数的分享链接
- **THEN** 页面直接渲染该案件对应视图，且案件号、状态等事实与从工作台进入时一致

#### Scenario: 浏览器前进与后退恢复视图状态
- **WHEN** 用户切换视图后使用浏览器后退或前进
- **THEN** 当前视图随 URL 参数一同回退或恢复，不出现视图与 URL 不一致

### Requirement: 既有作业深链保持可达且不产生重复上下文入口

系统 SHALL 保留既有作业 URL 带 `claimId` 直接进入的形态，且这类入口不得返回 404。当作业内容以案件内嵌视图呈现时，页面不得同时出现两套页面标题或两套案件 ID 输入控件；从既有作业页返回案件视图时，必须回到同一 `claimId` 及其对应视图。

#### Scenario: 旧链接直达作业页
- **WHEN** 用户打开既有的带 `claimId` 作业 URL
- **THEN** 页面正常渲染该案件内容，不出现白屏、404 或重复的页面标题与 ID 输入控件

#### Scenario: 从既有作业页回到案件视图
- **WHEN** 用户在既有作业页点击返回案件视图的动作
- **THEN** 落到同一 `claimId` 的案件视图，并定位到该作业对应的视图标签

### Requirement: 非法上下文与未知视图一律安全回退

系统 SHALL 对非法 `claimId` 与未登记的视图标识回退到明确的安全态并给出可见提示；不得把未登记值拼进跳转目标，不得向后端发起带非法 ID 的请求。

#### Scenario: 链接中的视图标识未登记
- **WHEN** 用户打开 `tab` 为未登记值或包含路径穿越字符的案件链接
- **THEN** 页面回退到概览视图并显示可见提示，不跳转到链接指定的未知目标

#### Scenario: 案件 ID 非法
- **WHEN** 案件链接中的 `claimId` 含空格、斜杠或其他非法字符
- **THEN** 页面显示尚未选择案件的安全空态，不发起案件详情请求

### Requirement: 受保护动作维持逐案人工终审

资金结算、FRAUD 挂起恢复、后督 DIFF 等受保护动作 SHALL 继续逐案人工确认；内嵌作业视图不得引入批量执行或自动采纳入口。AI 参与事实非 `AI_ASSISTED` 的案件不得出现采纳、驳回或修改动作。

#### Scenario: 内嵌资金视图的操作边界
- **WHEN** 作业人员在案件内嵌的资金与结算视图中操作
- **THEN** 界面不提供批量执行入口，动作按单案逐次确认

#### Scenario: 非 AI_ASSISTED 案件的裁决动作
- **WHEN** 案件的 AI 参与事实为 `AI_UNAVAILABLE` 或其他非 `AI_ASSISTED` 取值
- **THEN** AI 结论卡明确呈现不可裁决的解释文案，且不出现采纳、驳回、修改按钮

### Requirement: 雪花案件 ID 全链路不截断

系统 SHALL 以字符串处理案件 ID；在 URL、深链、列表项、请求参数与页面展示中，18 位雪花 ID 的每一位都保持不变。

#### Scenario: 长 ID 往返
- **WHEN** 用户以 `776102367333449728` 进入案件、复制深链、再由该深链返回
- **THEN** URL、页面展示与后端请求参数中的 ID 均为完整的 18 位原文，无科学计数法与末位丢失
