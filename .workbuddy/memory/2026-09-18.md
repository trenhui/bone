## 第二轮：E-13.0「包表达边界，类名表达语义」+ bean 名唯一性门禁（2026-09-18，v5.5.9）

### 用户给的这条原则（直接采纳为总则）
> 协议类型通过 package 表达边界，业务类型通过 class name 表达语义；避免使用 Rpc、Http、Domain、App 等技术后缀重复表达已经由 package 明确的信息。

### ⚠ 它**推翻了上一轮的结论**
上一轮写的是「类名里的协议标记是例外，不是默认，**不能删**」，理由是「两个 `OrderController` → 启动期 `ConflictingBeanDefinitionException`」。**该推理把「类名合法」与「bean 名唯一」混为一谈**：类名同名合法（DTO 更是完全无所谓），需要唯一的只是 **bean 名**，而 bean 名可以用显式标识消解。
- 手写组件：`@RestController("rpcOrderController")`（`AnnotationBeanNameGenerator` 显式 `value` 优先）。
- MapStruct：`@Mapper(componentModel = "spring", implementationName = "RpcOrderAssemblerImpl")`（1.5.5 实测确有 `implementationName`，占位符 `<CLASS_NAME>`）。
- DTO 不是 bean，同名无需任何处理。
⇒ 标记**不是被删，而是下沉到 DI 标识**。上一轮的「必须保留」是错的。

### 判据（写进 E-13.0）
**把技术后缀去掉，语义是否由包路径无损承载？** 能 → 冗余，删；不能 → 保留。两个必须保留的反例已写进文档：
- `HttpProbeServiceHealthGateway`（`bone-system/infrastructure/gateway/`）的 `Http` 指**传输机制**，包路径没声明它。
- IAM 的 `App` 是**通用语言名词**（应用实体），不是层次标记。

### 三条「不得反推」（文档里明写，防用歪）
1. 不得推出「所有 RPC 类都要加 Rpc」/「所有入站类都要加 Web」。
2. 不得推出「类名可以随便重复」——同名只在**同一领域概念、不同协议**时合法。
3. 不得把「标记下沉」读成「标记消失」：`OrderRpcController` 的问题是**标记放错了层**，不是多了 `Rpc`。

### 新门禁 `springComponentBeanNamesMustBeUnique`（正确性门禁，非命名风格）
- 实现：`ArchCondition` 的**集合级**判定——`init(Collection<JavaClass>)` 按有效 bean 名分组，`check(JavaClass, events)` 逐类报告同组冲突（ArchUnit 1.0.1 的 `ArchCondition` **没有**集合版 `check`，只有 `init` + `finish`，故用 `init` 建索引）。**注意 `ArchCondition.check` 是单参版 `check(T item, ConditionEvents)`，不是 `check(Collection, ...)`**。
- 有效 bean 名口径：`isMetaAnnotatedWith(Component)` 的具体类（排除接口/抽象/内部类），注解显式 `value` 优先，否则类短名 `decapitalize`（前两位都大写则原样）。
- 分级理由：它守护**正确性**（bean 名撞了容器起不来），所以是 **Hard gate**；E-13 其余仍是 **Advisory**。这一点必须在文档与 gate-state 里写清，否则违反「E-13 默认 Advisory」。
- 实测**18 模块 553 个 Spring 组件当前零冲突** ⇒ 可全模块接线不破基线（先只在 blueprint 启用）。
- **负向对照必做**：临时去掉 `@RestController("rpcOrderController")` → `blueprint ArchitectureTest` 红并精确点名两个类（rpc + web 的 `OrderController`）；加回 → 绿。**不做负向对照就等于没验证门禁**。
