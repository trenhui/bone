### 一、404→500 语义失真修复（平台级）
- 根因：Spring Boot 3 / Spring 6 未匹配路由抛 `NoResourceFoundException`，但框架 `bone-web` 的
  `GlobalExceptionHandler` 只 catch 了旧版 `NoHandlerFoundException`（死代码），各模块 catch-all
  `@ExceptionHandler(Exception.class)` 把真 404 兜成 500。
- 修复（5 处）：
  - `bone-framework/bone-web`：`GlobalExceptionHandler` 换 `NoHandlerFoundException` → `NoResourceFoundException`（`AutoConfiguration.imports` 注册，覆盖 iam/integration/extension）。
  - `bone-platform/bone-system`、`bone-platform/bone-masterdata`、`bone-engine/bone-metadata-server`：各自 `GlobalExceptionHandler` 补 `NoResourceFoundException→404`。
  - `bone-engine/studio-generator`：`GeneratorExceptionHandler` 补同款（该模块只依赖 `bone-core`，拿不到 bone-web 的 advice）。
  - metadata-server 另加 `MetaErrorCodes.META_NOT_FOUND`。
- 验证：7 个模块用「保证不存在的顶层路径」探测，全部返回 404（此前 500）。
- 副作用（良性）：修复前 OPTIONS 探测把「真缺失」与「500」都归为 inconclusive，掩盖了缺口；修复后契约对账从
  「12 缺失」暴露为 **23 缺失**。这是本次修复的最大价值。

### 五、关键坑与结论（可复用）
1. ⚠ **bone-iam 架构门禁在本机 clean build 下「既有红」**：`FreezingArchRule` 基线是按 violation 标识串
   （含行号 + 方法名）冻结的；当前工具链重编译后 lambda 归属从 `lambda$N(...)` 漂移到外层方法 `handle(...)`，
   基线无法匹配 ⇒ 报「新违规」。失败项全在**既有类**：`ApplicationPageQueryHandler`
   （E-4.2 读侧 DSL，4 条）、`AccountDetailQueryHandler`/`RoleDetailQueryHandler`（E-2 TenantContext，2 条）。
   **已用「HEAD 干净 worktree 跑同一命令」自证：结果逐条一致** ⇒ 与本次改动无关。
   另：跑挂的 ArchUnit 会**删除**基线中「不再出现」的条目（本次 2 个 store 文件各被删 7 行），
   已 `git checkout --` 还原，未把基线改动混进本次提交。增量编译会掩盖该漂移，`mvn clean` 才暴露。
2. **IAM「本聚合读」的规矩**：可在 `domain/repository` 用 `default` 方法就地构造 `Criteria`
   （先例 `AccountRepository`），**但前提是该仓储位于 `..domain.repository..`（扁平包）**——模块内联规则
   `domain_no_query_builder` 只豁免 `..domain.repository..`，`domain.app.repository` **不在豁免内**。
   且 `..application..` 一律不得出现读侧 DSL（E-4.2）。故本次把 `AppPermissionRepository` 放在
   `com.bone.iam.domain.repository`（与无 DSL 的 `BoneApplicationRepository` 分居两处属预期）。
3. **SDK 不做 DDL 自动建表**：`generateCreateTableStatement` 只有声明与实现、**无调用方**；
   表实际来自仓库根 `bone-init.sql`。新增 `@Table` 聚合必须同步补 DDL 并手工执行。
4. 枚举持久化：`SqlUtil.toJdbcParameter` 优先反射 `getCode()`（有则存其返回值为参数），否则存 `name()`；
   读回由 `SmartRowMapper` 兜底 `Enum.valueOf` / `of(int)`。⇒ **新枚举若把访问器命名成 `getCode()`，
   会走进「code 落库、name 读回」的错配**。本次 `AppRole.externalName()` 刻意避开 `getCode()` 命名，
   库里存 `ADMIN/DEVELOPER/VIEWER`，API 输出小写。
5. `mvn clean` 与删除/移动类：非 clean 构建会留 `target/**/*.class` 残骸，ArchUnit 按旧类报**假违规**
   （本次移动 `AppPermissionRepository` 后先报 4 条假红，`clean` 后消失）。
6. `PIPESTATUS` 是 bash 专有：zsh 下 `${PIPESTATUS[0]}` 恒空，别据此判断退出码（用 `$pipestatus` 或直接看 BUILD 行）。
7. 沙箱无 `seq`/`basename`/`sleep`；`nohup ... &` 起的进程会随 Bash 工具返回而被回收 ⇒ 长驻服务必须用
   工具的 `run_in_background`。`grep` 的 `\|` 交替在 BSD grep 下静默返回空（踩了 5 次）。

### 九、bone-iam 错误码收口为单一真源（Q7-③）

**落地形态**（与 `blueprint/BlueprintErrors`、`system/SystemErrors` 同构，三处现已一致）：
`common/IamErrorCodes`（只承载稳定码字符串 + 语义）+ `common/IamErrors`（**「码 → HTTP 状态」唯一真源**
`DEFAULT_HTTP_STATUS` 表 + `of(码[,上下文[,根因]])` / `supplier(...)` 工厂）。**类加载时反射校验**每个
public String 常量都已登记状态，漏登记即 `IllegalStateException`（fail fast，不给「被兜底成 400」留机会）。

**迁移手法（可复用）**：① 先写**声明**文件（码 + 状态表）；② 用 Python 脚本做**精确字符串替换**批量改抛出点
（`BizException.of(404, CODE + ": 文案")` → `IamErrors.of(CODE, "文案")`），顺带删私藏状态常量、清理不再用的 import；
③ 脚本跑完**必须逐条回读 diff 核对状态码是否原值保留**（脚本只做机械替换，码的归属判定需人工复核）；
④ 测试断言按消息格式变更同步（**顺手加强**：原只断言 `isInstanceOf(NotFoundException.class)`，改为
`BizException` + `code==404` + `hasMessageContaining(码)`）。

**⚠ 本轮踩到的新坑**：
1. **脚本补 import 会漏**：原文件用裸字符串时从未 import `{Module}ErrorCodes`，脚本只补了 `IamErrors` ⇒
   4 个文件编译报「找不到符号 IamErrorCodes」。**迁移脚本必须同时补码类与工厂两个 import**。
2. **删常量会留双空行**：脚本删 `private static final int NOT_FOUND = 404;` 后留下连续两个空行，spotless 会打回。
   手工先修，别指望 apply（apply 会重排）。
3. **`git add -A <module>` 会扫入他人在途文件**：本轮 `bone-platform/bone-iam/README.md` 被另一会话
   **同时在改**（mtime 落在本会话进行中，引用我未接触的 ADR-0033），被 `-A` 一并暂存。改用
   **`git commit -F <msg> --only -- <显式路径列表>`**；提交前用 `git diff --cached --name-only` 逐条核对清单。
   教训：**在共享工作树里永远不用 `-A`**，用显式路径（哪怕要写 20 行）。
4. **状态码失真比无码更隐蔽**：`throw new RuntimeException("账户不存在")` 会落到
   `@ExceptionHandler(Exception.class)` 兜底 ⇒ **404 报成 500**（污染 5xx 告警/SLO）。IAM `IamExceptionHandler`
   **没有** `IllegalArgumentException` handler ⇒ 这类裸异常全部 500。用
   「扫全部 `throw new (RuntimeException|IllegalStateException|IllegalArgumentException)`」一次找齐。
   但 **domain 层裸异常是正确形态**（app 层 catch 后翻译，如 `Account.enable()` 抛 `IllegalStateException`
   → `IAM_ACCOUNT_STATUS_CONFLICT`），别一刀切改。
