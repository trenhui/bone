## #4 深入调查结论（本轮回退了一版错误实现）
- **关键发现**：Order/Payment 的 DB 级乐观锁在 blueprint 层**无法合法实现**。原因有二：
  1. 架构硬门禁 P0-5（`domainMustNotUseQueryBuilder`）+ E-9.3（`readSideDslOnlyInQueryLayer`）禁止 `domain` 与 `application` 依赖 `@ReadSideOnly`（即 `com.bone.metadata.sdk.query.criteria.Criteria`）。而 `updateByCriteria(Criteria)` 是构造"WHERE version=?"条件的唯一 SDK 入口，只能落在 `infrastructure`。
  2. Bone 元数据 SDK 写路径（BaseRepository.update → DynamicUpdateBuilder / ConditionalUpdateBuilder）**不消费 version 列**：`TableMetadataResolver` 仅检测 `@Version` 并缓存 versionColumn，`ColumnAllocation` 仅建模，所有 UPDATE/INSERT 构造器都未用它。已 grep 全 SDK 确认仅有检测、无写侧使用。
- **结论**：蓝图无法在自身门禁内做乐观锁；真实修复点是 **SDK 启用原生 `@Version`**（在通用写路径追加 `WHERE version=?` + 自增）。已回退本轮回退前误加的 `Order.setVersion/getVersion`、`Payment.setVersion`、`OptimisticLockException`（死代码），保持 22 条架构门禁 + 154 测试全绿。
- **当前真实护栏（写入 README 第 64 行）**：① 支付回调并发靠 `channel_trade_no` 唯一索引幂等去重；② 钱货不一致由 `OrderPaymentInconsistencyJob` 周期对账（仅告警不改单）补偿"支付成功但订单确认丢失"窗口；③ 状态机防非法跃迁。SDK 乐观锁就绪前高并发写同聚合的丢失更新风险为已知登记项。
- **给用户的下一步建议**：向 SDK 团队提需求——在 `BaseRepository.update`/`DynamicUpdateBuilder` 消费 `versionColumn` 实现原生乐观锁；blueprint 侧届时把 `version` 标 `@Version` 即自动生效。
- **#5/#7 仍全部保持**（上一轮已落地的端口归位 + 回归门禁 + README 锚点净化）。

- **E-13.3**：`*Adapter` 独占语义 =「infrastructure 对 application/domain 出站端口的技术实现」。
- **E-13.4**：`*Service` 只允许出现在 `domain/service`（纯规则、无 IO）；`*ApplicationService` 只允许 `application/service`。
- **E-13.1**：`application/command/cmd/` 唯一语义 = `*Command`（写用例输入）；`*PO` 位于 `infrastructure/persistence/`。
- **E-10.3 L1323 明文**：`infrastructure/query/OrderQueryAdapter  # = application/query/port 的实现`；L1322 `infrastructure/persistence/OrderRepositoryImpl`。
- **E-10 L946/L957**：`application/query/port/*QueryPort`、`infrastructure/query/*QueryAdapter`，示例 `public interface OrderQueryPort`。
- **E-10 L1259-1260**：`QueryPort` 固定在 `application/query/port`，实现固定在 `infrastructure/query`。
- **⚠️ L890 硬约束**：「渐进重构（Boy Scout）…**禁止全仓重构、批量重命名、批量格式化**」→ 直接决定优化方式：不能批量改名。

### 发现的偏差（P0→P2）
- **P0 · 读侧端口名沿用 v4 遗留 `*ReadPort`**：`OrderReadPort`/`PaymentReadPort` 应为 `*QueryPort`；`OrderReadPortImpl`/`PaymentReadPortImpl` 应为 `*QueryAdapter`（E-10.3 L1323 明文）。成因：**半程迁移**——位置已迁到 `application/query/port`，名字没跟着改；README/Javadoc 引的 `§18.5 *ReadPort` 是 v4 遗留锚点。影响面：4 个文件 + 约 30 处引用（含 Javadoc/测试）。因 L951 已将 blueprint 列为「读侧目标形态范例」，此名会误导照抄的模块。
- **P1 · 出站端口实现类后缀不统一**：13 个实现仅 3 个用规定的 `*Adapter`；其余 10 个用了 `*Impl`(5)/`*Sender`(2)/`*Verifier`/`*Relay`/`*Publisher` 共 5 种形态。其中 `OrderOutboxRelay` 与 `adapter/schedule/OrderOutboxRelayJob` 几乎同名，是阅读隐患。`SpringDomainEventPublisher` 还把实现技术写进类名（L993「端口按使用者拥有，不按实现技术命名」）。
- **P1 · `application/service/BlueprintIdempotencyService` 用 `*Service`**（E-13.4 只许 `*ApplicationService`）。但**Javadoc 自陈是为对齐平台既有 `StudioIdempotencyService`/`CatalogIdempotencyService`**（"其他模块照抄时不会遇到第二种形态"）→ 属**平台级命名债**，单改 blueprint 反而新造第二种形态。同 Javadoc 还自陈分层折中：应用层用了 `ResponseEntity`/`ApiResponse` 等 HTTP 类型（E-10.1）。
- **P2 · `application/command/cmd/InitiatePaymentResult`**：record 结果对象放进了只允许 `*Command` 的 cmd 包；且 E-13 **未定义** `*Result` 后缀 → 是**规范空白**，非单纯改名可解。
- **P2 · infra 持久化对象命名**：`IdempotencyRecord`/`OrderOutboxRecord`/`ConsumedEventRecord` 均 `extends AggregateRoot<Long>` 且被 `*Repository` 持久化，但 E-13.1 规定持久化对象用 `*PO` 且位于 `infrastructure/persistence/`（该目录尚不存在）。同包 `IdempotencyRepository`/`OrderOutboxRepository`/`ConsumedEventRepository` 占用了 E-13.3 中 `*Repository` 的「domain 写侧聚合仓储」独占语义。
- **P2 · 同包内后缀并存**：`infrastructure/config/` 的 `SecurityConfig` vs `OrderOutboxConfiguration`/`WebMvcConfiguration`；`application/query/dto/` 的 `*Dto` vs `*Row`。
- **包结构（附带）**：`adapter/mq/listener/` 应为 E-10 参考的 `adapter/messaging/`；`infrastructure/gateway/` 按 E-10.2 应为 `infrastructure/integration/`；`application/query/support/`、`application/event/` 不在 E-10 参考结构中；README 未按 E-10 L1252 登记 domain 分组形态。

### 合规面（应主动说明，避免误判为违规）
`*Command`(8)/`*Query`(3)/`*CommandHandler`(4)/`*QueryHandler`(3) 全部合规且未用 `*Cmd`/`*Qry` 类名；adapter DTO `*Req`(4)/`*Qry`(1)/`*Resp`(5) 合规；`*Event`/`*IntegrationEvent` 合规；聚合/实体/值对象用通用语言名词无类目后缀；`*Job`(4)/`*Listener`/`*HealthIndicator` 合规；**无 domain/service**（规避了 L1410 警告的 `OrderService` 贫血堆积）；`domain/gateway` 只放业务网关。
