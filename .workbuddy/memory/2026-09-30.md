## 缺陷修复：数据库中文乱码（cp1252 误读，用户发现于 final-runtime.png）
- **根因**：`scripts/dev/db-init.sh` 导入 bone-init.sql 未带 `--default-character-set`，mysql CLI 以 latin1/cp1252 会话导入，全部中文（种子+建表注释）的 UTF-8 字节被按 cp1252 误读入库（特征码点：U+201D/U+02DC/U+2021/U+017D，非纯 latin1）。init.sql 源文件本身是好的。"从存量表导入"又把坏 COLUMN_COMMENT 抄进 meta_field → UI 列头乱码。
- **无损还原法**：存储串 → cp1252 反向映射（Node Buffer 不支持 cp1252，用托管 Python 做文本还原；Node mysql2 管 DB，JSON 文件中转）→ 原 UTF-8 字节 → 解码校验无 U+FFFD。脚本流程：dump(cjs) → recover(py) → apply(cjs)。
- **已修**：27 处列注释/5 表（仅改 COMMENT 的 ALTER）、meta_field 16 值、数据值 9 处（bone_application/bone_module/gen_column_metadata/gen_table_metadata）；`db-init.sh` 已补 `--default-character-set=utf8mb4` 防复发。全库扫描 0 残留，浏览器 e2e 重跑全通过。
- **教训**：任何 mysql CLI 导入 SQL 文件必须显式 `--default-character-set=utf8mb4`；修复类 DDL 先用 information_schema 重建列定义（含 CHAR SET/COLLATE/DEFAULT/EXTRA），只动要动的部分。
