2. **extension 全部列表页空（No data）**：`extensionApi.assertSuccess` 按 `AxiosResponse` 再取一次 `.data`，而 `createApiClient` 拦截器已是 `(r)=>r.data` ⇒ **双重解包**恒得 undefined（26 处调用点全受影响）。改 `assertSuccess(body)` 直接吃 ApiResponse 本体，一处改动覆盖全部。
   - 同源死代码：`deployPlugin` 用 `res.status===202` 判定异步，但拦截器丢弃 HTTP status ⇒ 202 分支永不触发；改为以 payload 是否含 `operationId` 判定。
   - **单测假绿**：`extensionApi.test.ts` 把拦截器 mock 成 no-op、传原始 axios 响应，与运行时形状不一致 ⇒ 掩盖该缺陷。已让 mock 真正执行注册的响应拦截器（`vi.hoisted` 里收集 handlers 并 reduce 应用）；21 测试仍绿且现在能捕获该 bug。注意：`vi.mock` 工厂被提升，辅助函数必须也放进 `vi.hoisted`，否则 TDZ `Cannot access ... before initialization`。
3. **masterdata#/records 横向溢出 67px**：动态列无 `scroll` ⇒ 整页横向滚动。加 `scroll={{x:'max-content'}}` 改为表格内部滚动。
4. **masterdata 记录动态列全显示 `-`**：后端 `MasterDataRecordDTO.data` 是 **JSON 字符串**且键为字段 **code**，而共享类型声明为对象、dataIndex 用 `data.<字段name>` ⇒ 取不到值。加 `parseRecordData()` 归一化（字符串 JSON.parse / 对象直通），并按 code→name 兼容取值。
5. **masterdata 记录缺 `data` 时返回 500**：`md_record.data` 为 NOT NULL，`checkDataSize(null)` 静默放过 ⇒ 落库违反约束变 500。给 `Create/UpdateMasterDataRecordReq.data` 加 `@NotEmpty` + 控制器 `@Valid` ⇒ 正确返回 400。
6. **system 不支持的 HTTP 方法返回 500**：`HttpRequestMethodNotSupportedException` 被 catch-all 兜底。按该文件既有 404 处理的同一理由补 405 映射（与项目"404 不许兜成 500"约定一致）。
7. **metadata 已删实体仍显示在列表**：SDK `deleteById` 对 meta_entity 走逻辑删除（deleted=1），但 `MetaEntityRepository.pageEntities` 未过滤 ⇒ 用户看到已删数据。`MetaEntity extends AbstractEntity` **已自带 `@Deleted deleted`**（勿重复加字段，否则 Lombok getter 冲突），直接 `.and(MetaEntity::getDeleted).eq(false)` 即可。total 50→45 验证通过。
