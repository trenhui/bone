已闭环P1-5 大 schema 性能 —— 先度量后优化：原诊断的性能归因是错的

原诊断纠正

原报告断言瓶颈在「无虚拟滚动 + undo/redo 全量快照栈」，属未度量即归因。实测证伪：bench/ui-schema-large-schema.bench.test.ts 显示 400 控件的纯函数 lintSchema 仅 ~0.11ms —— 引擎层完全不是瓶颈，虚拟滚动与差量历史栈都不必上（若照原文直接开工，属于优化错对象）。

真实根因

结构面板每个控件行都渲染一个 antd <Select>，而 options 写成 options={KIND_GROUPS.map(...)} 位于 JSX 内 —— 这份数组内容完全由静态常量决定，却在「每控件行 × 每帧」被重建。antd Select 每次收到新引用即重建内部 flatten 结果与缓存，于是 N 个控件 = 每帧 N 份选项树重建。jsdom 挂载中位数对照：40/80/160 行下静态引用快 2.08x / 3.11x / 2.37x。

改动（仅引用口径，零行为变更）

constants.ts：新增 7 个模块级静态 options 单例（CONTROL_KIND_OPTIONS / SECTION_KIND_OPTIONS / SECTION_LAYOUT_OPTIONS / DISPLAY_MODE_OPTIONS / FUNCTION_OPTIONS / OPERATOR_OPTIONS / VERIFY_TYPE_OPTIONS），并把判据写成注释随码保管：静态元数据 ⇒ 提升模块单例；依赖 props/state ⇒ 组件内 useMemo。

StructurePanel.tsx（4 处）、RulesPanel.tsx（3 处）、ListPanel.tsx（列固定 Segmented）改引用单例；ConditionEditor 的运算符下拉依赖 fieldType（真动态，模块单例不适用）⇒ 按 type 用 useMemo 缓存。

N7字段级角色可见性

为何

当前权限模型是「行级 RLS（数据谁能看哪些行）」+「变体（按角色换布局）」。但「同一布局里某个字段仅对特定角色可见」是一等需求（如薪酬字段仅 HR 可见）。目前只能：①为每个受限角色建一个变体（维护爆炸）；②用静态 visible=false（对所有角色隐藏，非按角色）。缺少字段级 ACL 概念。

对标

Salesforce FLS（Field-Level Security）、钉钉宜搭的「字段权限」均为角色 × 字段的可见/可编辑矩阵。

建议

在 schema 增加 control.roles（可见角色白名单）或复用变体的 match.roles 做字段级裁决；运行时 fieldVisible 接入。属协议 + 引擎 + 创作侧三端改动，工作量 2-3 人日，建议作为独立专项评估，勿与前轮变体特性混淆。

已闭环N4 控件级校验规则编辑器 —— 原诊断不实，已修正并扩大范围

原诊断纠正

原报告称「协议 props 已支持 max/min/maxLength/pattern」，实测不成立：pattern 在协议真源与 PROP_WHITELIST 均不存在；而已有的 min/max/maxLength 只被 Java 侧当元数据字段级约束，UI 引擎与运行时一行都不消费。若照原文只做编辑器，会造出第 4 个「配了不生效」。

实际范围

五层同补：①协议（真源 + runtime 副本加 control.required、props.pattern）；②白名单（PROP_WHITELIST 加 pattern，否则 lint/后端拒越界键）；③引擎（新增 validateControlValues：必填覆盖 / 数值 min·max / 文本 maxLength·pattern，非法正则 fail-closed）；④双渲染器接线（SchemaPreview 与 BoneDynamicForm 同源消费，避免双轨漂移）；⑤创作侧（ControlInspector 按控件类型显示校验卡：数值型出 min/max，文本型出 maxLength/pattern）。

关键设计

必填不双报：control.required 仅在「控件要求必填 且 元数据未要求」时才由 validateControlValues 报；元数据必填仍归 runSubmit，避免同一字段弹两条错。非法正则按配置错误 fail-closed，不静默放行（与 runSubmit 同口径）。

验证

单测 validateControlValues 12 例 + lint props 格式 13 例；变异验证 10/10 全部被捕获（逐条删实现行，对应用例必红）；活体探针 ui-designer-n4-n5-probe.mjs 24/24（注入 → 预览拦截 → 恢复草稿的完整闭环）。

已闭环N5 样例数据预览

为何

预览渲染空字段，建模者看不出「这个字段实际填了会多长、会不会挤爆排版」，只能等上线才发现。对标 Retool / Appsmith / 宜搭的「样例数据」开关。

实现口径
